# 13. Основной путь в приложении и порядок сборки (04.11.2026)

> Брейншторм основателя + разбор архитектора. Сверено с `docs/03-prd/*`, `docs/04-domain-model.md`, кодом и базой.
> Решения со звёздочкой (*) — предложения по умолчанию, ждут подтверждения основателя (раздел 6).

## 1. Путь целиком
1. **Регистрация → компания → мастер настройки** (любой шаг можно пропустить; пропущенное — чек-лист «Настройка» на «Сегодня», «3 из 8»).
2. **Первые шаги**: подсказка «что дальше» на «Сегодня» (создать лид → смету → отправить).
3. **Лид** (вручную; позже сам из Thumbtack/почты/веб-формы) → **смета из лида** → отправка ссылкой → видно «открыл N раз» → **подпись**.
4. **Лид → клиент**: автоматически при подписи; вручную — с причиной («подписал на бумаге»).
5. **Клиент**: правка контактов, объекта, заметки.
6. **Подписал → уведомление «назначьте дату»** → подрядчик выбирает дату, время, длительность, мастера → только тогда работа в «Плане» (автоматически на завтра 9:00 — нет, решение основателя).
7. **Договор → счета → квитанции**: депозит → (этапы) → финальный счёт на остаток; каждая оплата = квитанция.

## 2. Компания: что настраивается
| Блок | Поля | Сущность |
|---|---|---|
| Юр. данные | Название для клиентов (DBA), юр. название, форма (LLC / Corp / Sole prop), EIN (шифруется) | `companies` |

| Связь | Основной email, сайт | `companies` |
| Люди и телефоны | Имя, должность, телефон, email, «основной», «печатать на документах»; может быть связан с сотрудником приложения | **новая** `company_contacts` |
| Лицензии | Тип (CSLB, городская, HIS…), номер, классы, срок, «печатать на документах» | **новая** `company_licenses` |
| Страховка | CGL и workers' comp (или освобождение) — обязательны в договоре CA; bond — позже | `companies.contract_settings` |

| Время | Часовой пояс, рабочие часы, зона работ | `companies` |

Позже: проверка лицензии в CSLB, W-9, seller's permit, SMS-номер (A2P 10DLC требует точные юр. название, EIN и адрес — поэтому заполнять правильно уже сейчас), Stripe Connect, публичная страница и отзывы.

Отличие «Люди компании» от «Сотрудников»: сотрудник входит в приложение (роль); контакт компании — кто печатается в документах и кому звонит клиент. Один человек может быть и тем и другим.

## 3. Лид → смета → клиент
- Смета создаётся **из карточки лида** (`estimates.lead_id`); при этом заводятся карточка клиента со статусом **«потенциальный»*** (не в основном списке) и объект.
- Статусы лида видны полностью: новый → ответили → осмотр → смета отправлена → выигран / потерян (сейчас в приложении 4 статуса из 8).
- **Клиентом становится при подписи*** (депозит не нужен). Ручной перевод разрешён с причиной (`won_via = manual`) — это меняет правило PRD 02 «вручную won нельзя».
- **Сколько живёт лид***: 14 дней без действий — задача «связаться или закрыть», 30 дней без ответа — предложить «потерян: не отвечает», через 90 дней после won/lost — архив.

## 4. Заметки
Одна сущность `notes` для лида, клиента, объекта, работы: видимость **«команда»** или **«только я»***; закрепление. Клиенту видны только примечания в смете и счёте (меньше риск показать внутреннее).

## 5. Договор, счета, квитанции
- **Договор** = подписанная смета, полная сумма. Это не счёт.
- **Счёт** = требование оплатить часть: депозит (создаётся **сразу при подписи***) → этапы (по желанию) → финальный на остаток. Частичные оплаты по любому счёту.
- **Квитанция** на каждую оплату: номер RCT, PDF, отправка клиенту.
- **Выписка по договору** на экране работы и на странице клиента: «Договор $3,400 · выставлено $340 · оплачено $340 · осталось $3,060» + список счетов и квитанций.
- Почему не один счёт на 100% при подписи: в CA депозит ≤ min(10%, $1,000), платежи не могут опережать работу (B&P §7159.5); счёт на этап — место для отметки «работа выполнена»; lien release по каждой оплате; так же устроено в QuickBooks. Для мелкого ремонта (Service & Repair) — один финальный счёт с частичными оплатами.

## 6. Решения основателя (* — по умолчанию)
1. Клиент — при подписи; ручной перевод с причиной.
2. Лид: 14 / 30 / 90 дней.
3. Счета по этапам + выписка по договору.
4. Счёт на депозит — сразу при подписи.
5. Личные заметки видит только автор; клиенту — только примечания в документах.
6. На документах: основной телефон + до двух отмеченных.
7. Печатаются все действующие лицензии; истёкшая лицензия CSLB блокирует отправку договора в CA.
8. Нумерация документов продолжает вашу текущую; направлений несколько, модули включаются отдельно.

## 7. Порядок сборки
Сначала данные, потом экраны.
1. **Миграция** `company_profile_crm`: поля компании, `trades[]`, `company_licenses`, `company_contacts`, `notes` (+RLS: «только я» видит автор), `customers.status = prospect`, `leads.won_via`; `portal_accept` переводит лид в won, клиента в active и создаёт счёт на депозит.
2. **Типы и загрузка** (`types.ts`, `repo.ts`, `seed.ts`) — все новые сущности сразу, чтобы следующие волны их не трогали.
3. Дальше 4 трека, параллельно:

| Трек | Что | Зависит от |
|---|---|---|
| A. Компания и онбординг | Мастер после создания компании, «Ещё → Компания», чек-лист «Настройка», шапка документов | 1–2 |
| B. Лид → смета → клиент | Смета из лида, воронка, «открыл N раз», перевод в клиента | 1–2 |
| C. Заметки | Блок заметок у лида/клиента/объекта/работы | 1–2 |
| D. Счета и квитанции | Выписка по договору, «выставить остаток», квитанции PDF | B; шапка из A |

### Волны
- **Волна 7 «Профиль компании и первые шаги»**: шаги 1–2 + трек A. Приёмка: миграция на чистой и текущей базе, тесты базы зелёные, `gutters` по умолчанию нет; мастер из 6 шагов с пропуском и чек-листом; редактирование в «Ещё» офлайн; название, лицензии, телефон, логотип — в смете, PDF и на `/p/<token>`; предупреждение без лицензии CSLB; RU/EN/ES, 2 темы × 3 ширины.
- **Волна 8**: B + C (лид → смета → клиент, заметки).
- **Волна 9**: D (счета, квитанции, выписка), затем Stripe.
