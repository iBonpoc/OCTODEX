# Проверки OCTODEX: что, когда и кто запускает

Решение основателя 06.11.2026: все проверки записаны здесь, с этапом, на котором их гонять. Источники: правила проекта (`CLAUDE.md` 1–17), `docs/08-security.md`, разбор внешних наборов навыков (addyosmani/agent-skills — безопасность и удаление устаревшего; supabase/agent-skills; expo/skills; devsemih/appstore-review-skill), 06.11.2026.

## 1. Каждый PR (исполнитель, до отчёта руководителю)
| Проверка | Как | Правило |
|---|---|---|
| Типы, тесты приложения, сторож дизайн-системы, движок денег, токены, тесты базы | `npm run check` | 13 |
| Сквозные прогоны своих спек на 6 видах | `npm run check:e2e -- --all-layouts <спека> …` | 4, 13 |
| Новая функция = новый тест; исправленная ошибка = тест, который падал до исправления | e2e / unit / тест базы | 15 |
| Грепнуть все спеки на маршруты и тексты, которые меняешь | `grep -rn "<текст>" apps/mobile/e2e/specs` | BOARD, 06.11 |
| e2e идут с reduced motion: каждый `browser.newContext` с `reducedMotion: "reduce"` (анимации «Наряда» ставят значения сразу, снимки и размеры стабильны; сторож — `test/e2eMotion.test.ts`) | `e2e/run.cjs`, свой `newContext` в спеке — так же | 13, 07.11 |
| Даты в тестах — только через `e2e/companyTime.cjs`; не ставить событие «N минут назад» без проверки полуночи компании | см. §5 | BOARD, 06.11 |

## 2. По содержанию PR (исполнитель зовёт помощника, руководитель проверяет, что звал)
| Если PR меняет… | Помощник | Что смотрит |
|---|---|---|
| миграции, права, серверные функции, приём данных извне | агент `security-check` | список в `.claude/agents/security-check.md` |
| статусы, сущности, переходы | агент `map-keeper` | `docs/15-story-map.md` §4–§5 |
| большой или денежный код | агент `code-reviewer` | правила 1–15, спецификация |
| стыки между шагами | агент `handoff-tester` | тест на обе стороны стыка |
| схему базы: переименование или удаление колонки, таблицы, функции | правило 16 (два шага) | старая версия приложения на телефоне не ломается |
| зависимости (`package.json`, lockfile) | правило 17 | §4 ниже |

## 3. Сборный PR (руководитель)
- Прогон GitHub (`checks.yml`): типы, тесты, база, e2e всех спек на 3 видах (390 тёмная, 820 светлая, 1280 тёмная — каждая ширина и обе темы; 08-layouts сам проверяет все экраны на 6 видах), каждый вид в 2 части параллельно.
- Конфликты только в `version.ts`, i18n, списках — обе стороны; `BUILD` = номер сборного PR.
- Красное: сначала понять, не время ли (§5). Перезапуск упавших заданий — один раз, после окна.

## 4. Новая зависимость (правило 17)
- Ставить только `npx expo install <pkg>`; один lockfile в корне, CI его не переписывает.
- Перед добавлением: кто автор, жив ли проект (последний релиз, issues), нет ли похожего имени-подделки, сколько тянет за собой.
- `npm audit fix --force` и автоматические «починки» — никогда. Критичные и высокие уязвимости разбирать по одной: достижима ли в приложении; отложенные — в BOARD с причиной и датой.
- Пакеты со скриптами установки — смотреть скрипт до первой установки.

## 5. Окна времени, когда тесты ложно краснеют (до исправления самих тестов)
| Окно (UTC, зима, LA = UTC−8) | Что падает | Причина | Статус |
|---|---|---|---|
| 07:00–08:00 | тест базы T21/T22 «визит 15 дней назад» | перевод часов | исправлено #186 |
| 08:00–08:31 | e2e 49-late-visit, 54-schedule-settings | выезд до полуночи компании пропадал из «опаздывает» (ошибка приложения) | исправляет #197 |
| ~07:59–08:00 | любая спека, идущая через полночь компании (видели 65-job-done) | демо пересевается при смене дня (store.tsx); посаженные спекой данные пропадают | исправлено #201: раннер ждёт полночь, если до неё < 3 мин; 08-layouts (> 3 мин) — известный остаток |
Летом (LA = UTC−7) окна на час раньше. Проверить окно заранее: `E2E_NOW=<ISO> npm run check:e2e -- <спека>` (после #197).

## 8. Как пользоваться внешними навыками
- Не ставить в репозиторий и не всем чатам сразу. Чат читает навык с GitHub как список проверок или ставит его у себя (не в `.claude/` проекта).
- Находки — отчётом руководителю; правки — обычными задачами исполнителям по правилам проекта.
- Наши правила важнее: при расхождении действует `CLAUDE.md`.

## 9. Частые ошибки, из-за которых краснеют проверки (сбор 07.11.2026)
Источник: все 59 упавших прогонов на GitHub за 05–07.11 и журнал `LOG.md`. Каждая ошибка ниже стоила хотя бы одного повторного прогона пачки. Исполнитель сверяет свой PR с этим списком **до** PR; руководитель — при приёмке.

| № | Ошибка | Сколько раз | Примеры | Как не допускать |
|---|---|---|---|---|
| 1 | **Тест зависит от настоящего часа.** Проверки идут около полуночи компании (LA) — это 08:00 UTC, утро основателя. Тест видит «вчера», «12:00 AM», пропавший выезд или перевод часов | 22 прогона, больше трети всех падений | e2e 107 «12:00 AM», 116 «к вчерашнему дню», 49, 54, 65, 04; база T21/T22 «визит 15 дней назад» | Часы браузера в e2e — на полдень дня компании (`page.clock.install` + `companyTime.cjs`), даты — только через `companyTime.cjs`. Перед PR прогнать свою спеку с `E2E_NOW` в 00:20 по LA (08:20 UTC). Проверять узко — свою карточку, а не весь текст экрана |
| 2 | **Две правки не знают друг о друге.** Один PR переименовал пункт, перенёс экран или поменял роль, а тест другого PR (или старый тест) ищет прежнее. Видно только в пачке или в main | 14 прогонов | e2e 134 ищет «Мои настройки» после #289; 87/89 «роль Мастер» в приглашении; 23/79/82 «ожидает оплаты»; 51 «суммы на Сегодня»; 38, 36 нижняя панель; 07 вкладки | Кто меняет видимый текст, путь или экран — ищет старое слово во всех `e2e/specs` и `e2e/cloud` и правит их в том же PR. Новый тест ищет элемент по `testID`, а не по надписи. Руководитель при сборке пачки сверяет: PR А переименовал, PR Б в тестах ищет старое → правка до пачки |
| 3 | **Тест не дождался.** Проверяет раньше, чем экран дорисовал, или ждёт не тот признак | 10 прогонов | облачная 114 (ждала заголовок, а не обе карточки) — 5 прогонов; 05, 22, 04, 64 — «Timeout 30000ms» | Ждать именно то, что проверяешь (обе карточки, нужную строку), а не соседний заголовок. После нажатия — ждать результат, а не фиксированные секунды. Анимации: проверять и с «Уменьшить движение» |
| 4 | **Правило поменяли, модульный тест — нет** | 1 прогон | `attentionSign.test.ts` ждал `estimateExpired` | Меняешь правило — сначала правишь его тест; `npm run check` перед каждым PR (правило 13) |
| 5 | **Не наш код: секреты, GitHub, npm** | 11 прогонов | Release без `SUPABASE_ACCESS_TOKEN` — 5 раз; GitHub 503/504; npm 404 при установке eas-cli; сбой загрузки скриншотов | Не чинить кодом. Секреты заводит основатель (`11-setup-guide`); сбой GitHub/npm — перезапуск один раз; версии внешних утилит закреплены (#pin-eas-cli) |

Главное, что исправить в самом раннере (задача руководителя исполнителю): №1 — часы на полдень дня компании для всех спек сразу, а не по одной; спека, которой нужен настоящий час, просит его явно.
