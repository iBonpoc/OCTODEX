| схему базы: переименование или удаление колонки, таблицы, функции | правило 16 (два шага) | старая версия приложения на телефоне не ломается |
| зависимости (`package.json`, lockfile) | правило 17 | §4 ниже |

## 3. Прогон на GitHub (руководитель)
- Прогон GitHub (`checks.yml`): типы, тесты, база, e2e всех спек на 3 видах (390 тёмная, 820 светлая, 1280 тёмная — каждая ширина и обе темы; 08-layouts сам проверяет все экраны на 6 видах), каждый вид в 2 части параллельно.
- Конфликты только в `version.ts`, i18n, списках — обе стороны; `BUILD` = 0.
- Красное: сначала понять, не время ли (§5). Перезапуск упавших заданий — один раз, после окна.

## 4. Новая зависимость (правило 17)
- Ставить только `npx expo install <pkg>`; один lockfile в корне, CI его не переписывает.
- Перед добавлением: кто автор, жив ли проект (последний релиз, issues), нет ли похожего имени-подделки, сколько тянет за собой.
- `npm audit fix --force` и автоматические «починки» — никогда. Критичные и высокие уязвимости разбирать по одной: достижима ли в приложении; отложенные — в BOARD с причиной и датой.
- Пакеты со скриптами установки — смотреть скрипт до первой установки.

| Окно (UTC, зима, LA = UTC−8) | Что падает | Причина | Статус |
|---|---|---|---|
| 07:00–08:00 | тест базы T21/T22 «визит 15 дней назад» | перевод часов | исправлено #186 |

Летом (LA = UTC−7) окна на час раньше. Проверить окно заранее: `E2E_NOW=<ISO> npm run check:e2e -- <спека>` (после #197).
**Для обычных e2e окна закрыты** (PR «часы раннера», 07.11.2026): раннер начинает каждую спеку в полдень дня компании, полночь в спеке не наступает (§9 п.1). Окна остаются для тестов базы, облачных спек (`e2e/cloud`) и спек с `exports.clock = "real"`; проверка опасного часа — та же, `E2E_NOW`.

## 9. Частые ошибки, из-за которых краснеют проверки (сбор 07.11.2026)
Источник: все 59 упавших прогонов на GitHub за 05–07.11 и журнал `LOG.md`. Каждая ошибка ниже стоила хотя бы одного повторного прогона пачки. Исполнитель сверяет свой PR с этим списком **до** PR; руководитель — при приёмке.

| № | Ошибка | Сколько раз | Примеры | Как не допускать |
|---|---|---|---|---|
| 1 | **Тест зависит от настоящего часа.** Проверки идут около полуночи компании (LA) — это 08:00 UTC, утро основателя. Тест видит «вчера», «12:00 AM», пропавший выезд или перевод часов | около 20 прогонов — больше трети всех падений | e2e 107 «12:00 AM», 116 «к вчерашнему дню», 49, 54, 65, 04; база T21/T22 «визит 15 дней назад» | Часы e2e ставит раннер: каждая спека начинается в полдень дня компании (`e2e/clock.cjs`, сторож `test/e2eClock.test.ts`); своя минута — `exports.clock = { minute }`, настоящее время — `exports.clock = "real"`; свой контекст — `installClock(ctx)`. ## 10. Правило «с первого раза» (решение основателя 09.11.2026: «чтобы не гонять тесты по 10 раз, а сразу всё вливалось»)
Разбор 700 прогонов `checks.yml` за 07.11 01:35 – 09.11 06:30 UTC (руководитель №6): 388 зелёных, **270 отменены** (новый пуш в PR обрывает прежний прогон — 39 % всех запусков), **41 упал**. **Исполнитель перед сдачей PR (по порядку, ничего не пропускать):**
1. `git merge origin/main` **последним шагом** перед прогонами — и снова, если main сдвинулся до сдачи. PR поверх невлитого PR не сдавать: держать черновиком, сдавать после влития нижнего и merge main.
2. Пока main красный — не сливать его в свою ветку и не сдавать; написать руководителю.
3. `npm run check` — зелёный.
4. E2E: свои спеки **и затронутые** (спеки, которые открывают изменённые экраны/маршруты или ищут изменённые надписи и `testID`) — `--all-layouts`, **3 процесса параллельно** (нагрузка как на GitHub). Новые и изменённые спеки — **3 раза подряд** зелёные. Своя спека — ещё раз с `E2E_NOW` в 00:20 LA (08:20 UTC).
5. Шторка: перед жестом, кликом по холсту или Esc — дождаться, что шторка ушла (`sheetGone`/`waitFor hidden`) и в точке холст (`canvasAt`); Esc — до закрытия, не один раз; ожидания не глотать `.catch(() => {})`.
6. Переименовал надпись, правило, право или пункт меню — найти старое во всех `e2e/specs` и `e2e/cloud` (и проверки «пункта нет» `count() === 0`) и поправить в этом же PR.
7. Тест базы: дата — по `timezone` компании, не `current_date`.
8. **Один пуш на сдачу**: копить коммиты локально, пушить, когда п.1–7 зелёные. Мелкие правки после сдачи — одним пушем, не по одному.
9. В сообщении руководителю — строка «с первого раза: п.1–8 ✅» и какие спеки прогнаны.

**Руководитель:** не вливает, пока main красный (сначала одна правка или откат); вливает по одному, после каждого влития — merge main в следующий PR очереди; PR без строки п.9 не принимает. Новая мигалка → строка в §9 в тот же день.
