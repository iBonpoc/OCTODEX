# Проверки OCTODEX: что, когда и кто запускает

Решение основателя 06.11.2026: все проверки записаны здесь, с этапом, на котором их гонять. Источники: правила проекта (`CLAUDE.md` 1–17), `docs/08-security.md`, разбор внешних наборов навыков (addyosmani/agent-skills — безопасность и удаление устаревшего; supabase/agent-skills; expo/skills; devsemih/appstore-review-skill), 06.11.2026.

## 1. Каждый PR (исполнитель, до отчёта руководителю)
| Проверка | Как | Правило |
|---|---|---|
| Типы, тесты приложения, сторож дизайн-системы, движок денег, токены, тесты базы | `npm run check` | 13 |
| Сквозные прогоны своих спек на 6 видах | `npm run check:e2e -- --all-layouts <спека> …` | 4, 13 |
| Новая функция = новый тест; исправленная ошибка = тест, который падал до исправления | e2e / unit / тест базы | 15 |
| Грепнуть все спеки на маршруты и тексты, которые меняешь | `grep -rn "<текст>" apps/mobile/e2e/specs` | BOARD, 06.11 |
| Даты в тестах — только через `e2e/companyTime.cjs`; не ставить событие «N минут назад» без проверки полуночи компании | см. §5 | BOARD, 06.11 |

## 2. По содержанию PR (исполнитель зовёт помощника, руководитель проверяет, что звал)
| Если PR меняет… | Помощник | Что смотрит |
|---|---|---|
| миграции, права, серверные функции, приём данных извне | агент `security-check` | список в `.claude/agents/security-check.md` |
| статусы, сущности, переходы | агент `map-keeper` | `docs/15-story-map.md` §4–§5 |
| большой или денежный код | агент `code-reviewer` | правила 1–15, спецификация |
| стыки между шагами | агент `handoff-tester` | тест на обе стороны стыка |
| схему базы: переименование или удаление колонки, таблицы, функции | правило 16 (два шага) | старая версия приложения на телефоне не ломается |
| зависимости (`package.json`, lockfile) | правило 17 | §4 ниже |

## 3. Сборный PR (руководитель)
- Полный прогон GitHub (`checks.yml`): типы, тесты, база, e2e 3 ширины × 2 темы.
- Конфликты только в `version.ts`, i18n, списках — обе стороны; `BUILD` = номер сборного PR.
- Красное: сначала понять, не время ли (§5). Перезапуск упавших заданий — один раз, после окна.

## 4. Новая зависимость (правило 17)
- Ставить только `npx expo install <pkg>`; один lockfile в корне, CI его не переписывает.
- Перед добавлением: кто автор, жив ли проект (последний релиз, issues), нет ли похожего имени-подделки, сколько тянет за собой.
- `npm audit fix --force` и автоматические «починки» — никогда. Критичные и высокие уязвимости разбирать по одной: достижима ли в приложении; отложенные — в BOARD с причиной и датой.
- Пакеты со скриптами установки — смотреть скрипт до первой установки.

## 5. Окна времени, когда тесты ложно краснеют (до исправления самих тестов)
| Окно (UTC, зима, LA = UTC−8) | Что падает | Причина | Статус |
|---|---|---|---|
| 07:00–08:00 | тест базы T21/T22 «визит 15 дней назад» | перевод часов | исправлено #186 |
| 08:00–08:31 | e2e 49-late-visit, 54-schedule-settings | выезд до полуночи компании пропадал из «опаздывает» (ошибка приложения) | исправляет #197 |
| ~07:59–08:00 | любая спека, идущая через полночь компании (видели 65-job-done) | демо пересевается при смене дня (store.tsx); посаженные спекой данные пропадают | PR «Работ» №3: раннер ждёт полночь, если до неё < 3 мин; 08-layouts (> 3 мин) — остаток |
Летом (LA = UTC−7) окна на час раньше. Проверить окно заранее: `E2E_NOW=<ISO> npm run check:e2e -- <спека>` (после #197).

## 6. Регулярно (руководитель ставит чат)
| Когда | Проверка | Кто |
|---|---|---|
| Сейчас, затем раз в месяц и перед каждым выпуском в магазин | **Аудит базы** по `supabase-postgres-best-practices` и `supabase` (RLS, `security definer`, индексы, доступ API к таблицам): только находки, без правок | разовый чат «Аудит базы» |
| Раз в месяц и перед выпуском | `npm audit` по lockfile, разбор по §4 | чат «Каркас» |
| Перед выпуском | Скорость на телефоне (запуск, списки, память) по `callstackincubator/agent-skills` react-native-best-practices | по находкам |

## 7. Перед первой подачей в App Store и Google Play
| Проверка | Как |
|---|---|
| Правила App Store / Google Play: файл приватности (`PrivacyInfo`), удаление аккаунта, тексты запросов разрешений, «Войти через Apple» (нужен, только если появится вход через Google/Facebook), покупки, секреты в коде | навык `devsemih/appstore-review-skill` (`/appstore-review`, `/playstore-review`), отчёт; вторым мнением — `cruisediary/apple-app-review-skills` (privacy, Sign in with Apple) |
| Удаление аккаунта и данных по-настоящему (вход, данные компании/человека, файлы, кэши, копии), выгрузка данных по запросу (CCPA) | e2e + тест базы; не «пометка», а удаление |
| Сборка и подача: EAS Build / Submit, TestFlight, версии, описание в магазине | навыки `expo/skills` (`eas-app-stores`, `expo-upgrade`) |
| Проход сценариев на симуляторе (вход, удаление аккаунта, разрешения) со скриншотами | `callstack/agent-device`; нужен Mac с Xcode — делает основатель или чат на его компьютере |

## 8. Как пользоваться внешними навыками
- Не ставить в репозиторий и не всем чатам сразу. Чат читает навык с GitHub как список проверок или ставит его у себя (не в `.claude/` проекта).
- Находки — отчётом руководителю; правки — обычными задачами исполнителям по правилам проекта.
- Наши правила важнее: при расхождении действует `CLAUDE.md`.
