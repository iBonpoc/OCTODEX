Источники: правила проекта (`CLAUDE.md` 1–17), `docs/08-security.md`, разбор внешних наборов навыков (addyosmani/agent-skills — безопасность и удаление устаревшего; supabase/agent-skills; expo/skills; devsemih/appstore-review-skill), 06.11.2026.

## 2. По содержанию PR (исполнитель зовёт помощника, руководитель проверяет, что звал)
| Если PR меняет… | Помощник | Что смотрит |
|---|---|---|
| миграции, права, серверные функции, приём данных извне | агент `security-check` | список в `.claude/agents/security-check.md` |
| статусы, сущности, переходы | агент `map-keeper` | `docs/15-story-map.md` §4–§5 |
| большой или денежный код | агент `code-reviewer` | правила 1–15, спецификация |
| стыки между шагами | агент `handoff-tester` | тест на обе стороны стыка |
| схему базы: переименование или удаление колонки, таблицы, функции | правило 16 (два шага) | старая версия приложения на телефоне не ломается |
| зависимости (`package.json`, lockfile) | правило 17 | §4 ниже |

## 3. Прогон на GitHub (руководитель)
- Прогон GitHub (`checks.yml`): типы, тесты, база, e2e всех спек на 3 видах (390 тёмная, 820 светлая, 1280 тёмная — каждая ширина и обе темы; 08-layouts сам проверяет все экраны на 6 видах), каждый вид в 2 части параллельно.
- Конфликты только в `version.ts`, i18n, списках — обе стороны; `BUILD` = 0.
- Красное: сначала понять, не время ли (§5). Перезапуск упавших заданий — один раз, после окна.

## 4. Новая зависимость (правило 17)
- Ставить только `npx expo install <pkg>`; один lockfile в корне, CI его не переписывает.
- Перед добавлением: кто автор, жив ли проект (последний релиз, issues), нет ли похожего имени-подделки, сколько тянет за собой.
- `npm audit fix --force` и автоматические «починки» — никогда. Критичные и высокие уязвимости разбирать по одной: достижима ли в приложении; отложенные — в BOARD с причиной и датой.
- Пакеты со скриптами установки — смотреть скрипт до первой установки.

## 9. Частые ошибки, из-за которых краснеют проверки (сбор 07.11.2026)
Источник: все 59 упавших прогонов на GitHub за 05–07.11 и журнал `LOG.md`. Каждая ошибка ниже стоила хотя бы одного повторного прогона пачки. Исполнитель сверяет свой PR с этим списком **до** PR; руководитель — при приёмке.

| № | Ошибка | Сколько раз | Примеры | Как не допускать |
|---|---|---|---|---|
| 1 | **Тест зависит от настоящего часа.** Проверки идут около полуночи компании (LA) — это 08:00 UTC, утро основателя. Тест видит «вчера», «12:00 AM», пропавший выезд или перевод часов | около 20 прогонов — больше трети всех падений | e2e 107 «12:00 AM», 116 «к вчерашнему дню», 49, 54, 65, 04; база T21/T22 «визит 15 дней назад» | Часы e2e ставит раннер: каждая спека начинается в полдень дня компании (`e2e/clock.cjs`, сторож `test/e2eClock.test.ts`); своя минута — `exports.clock = { minute }`, настоящее время — `exports.clock = "real"`; свой контекст — `installClock(ctx)`. Исключение — облачные спеки (`e2e/cloud`): там настоящее время, now() сервера не сдвинуть. Даты — только через `companyTime.cjs`. Перед PR прогнать свою спеку с `E2E_NOW` в 00:20 по LA (08:20 UTC). Проверять узко — свою карточку, а не весь текст экрана |
| 2 | **Две правки не знают друг о друге.** Один PR переименовал пункт, перенёс экран или поменял роль, а тест другого PR (или старый тест) ищет прежнее. Видно только в пачке или в main | около 15 прогонов | e2e 134 ищет «Мои настройки» после #289; 87/89 «роль Мастер» в приглашении; 23/79/82 «ожидает оплаты»; 51 «суммы на Сегодня»; 38, 36 нижняя панель; 07 вкладки | Кто меняет видимый текст, путь или экран — ищет старое слово во всех `e2e/specs` и `e2e/cloud` и правит их в том же PR. Новый тест ищет элемент по `testID`, а не по надписи. Руководитель при сборке пачки сверяет: PR А переименовал, PR Б в тестах ищет старое → правка до пачки Добавил пункт или право (было «нет» → стало «есть») — ищи и тесты, которые проверяют, что его **нет** (`count() === 0`, «no row/tile»): #327 открыл мастеру «Лиды», а e2e 119 и 61 ждали отсутствия (сборка #332). Новая страница ходит в сеть — тесты других PR, которые её открывают, тоже подменяют этот запрос: e2e 181 (#424) открывал `/f/`, а `/f/` из #421 начал звать функцию (сборка #427) |
| 3 | **Тест не дождался.** Проверяет раньше, чем экран дорисовал, или ждёт не тот признак | около 10 прогонов | облачная 114 (ждала заголовок, а не обе карточки) — 5 прогонов; 05, 22, 04, 64 — «Timeout 30000ms» | Ждать именно то, что проверяешь (обе карточки, нужную строку), а не соседний заголовок. ## 10. Правило «с первого раза» (решение основателя 09.11.2026: «чтобы не гонять тесты по 10 раз, а сразу всё вливалось»)
Разбор 700 прогонов `checks.yml` за 07.11 01:35 – 09.11 06:30 UTC (руководитель №6): 388 зелёных, **270 отменены** (новый пуш в PR обрывает прежний прогон — 39 % всех запусков), **41 упал**. Мигалки: 163 (7), 157 (5), 180 (4), 107 (4), 173 (3). Значит, почти все падения — в тестах и в порядке сдачи, а не в приложении.

**Исполнитель перед сдачей PR (по порядку, ничего не пропускать):**
1. `git merge origin/main` **последним шагом** перед прогонами — и снова, если main сдвинулся до сдачи. PR поверх невлитого PR не сдавать: держать черновиком, сдавать после влития нижнего и merge main.
2. Пока main красный — не сливать его в свою ветку и не сдавать; написать руководителю.
3. `npm run check` — зелёный.
4. E2E: свои спеки **и затронутые** (спеки, которые открывают изменённые экраны/маршруты или ищут изменённые надписи и `testID`) — `--all-layouts`, **3 процесса параллельно** (нагрузка как на GitHub). Новые и изменённые спеки — **3 раза подряд** зелёные. Своя спека — ещё раз с `E2E_NOW` в 00:20 LA (08:20 UTC).
5. Шторка: перед жестом, кликом по холсту или Esc — дождаться, что шторка ушла (`sheetGone`/`waitFor hidden`) и в точке холст (`canvasAt`); Esc — до закрытия, не один раз; ожидания не глотать `.catch(() => {})`.
6. Переименовал надпись, правило, право или пункт меню — найти старое во всех `e2e/specs` и `e2e/cloud` (и проверки «пункта нет» `count() === 0`) и поправить в этом же PR.
7. Тест базы: дата — по `timezone` компании, не `current_date`.
8. **Один пуш на сдачу**: копить коммиты локально, пушить, когда п.1–7 зелёные. Мелкие правки после сдачи — одним пушем, не по одному.
8а. **Снимки «было» и «стало» в описании PR** (решение аудита №2, 16.11.2026: «из 16 последних у 8 нет «было»… основатель не может решить «оставить/откатить»»). Экранная правка К2/К3 вида — пара снимков **«было» и «стало» на 390 в светлой теме**, одним и тем же состоянием экрана, обязательно (остальные виды — по К2). «Было» снимается с `origin/main` до правки. Без пары руководитель PR не вливает.
9. В сообщении руководителю — строка «с первого раза: п.1–8а ✅» и какие спеки прогнаны.

## 11. Визуальный сторож — снимок против эталона (21.11.2026, вопрос основателя «чтобы при вёрстке всё переносилось без ошибок»)

Пиксель изменён, если канал сдвинулся больше чем на 24 из 255. Кадр красный, если изменённых больше **0,5 %**. Сдвиг кнопки на 4 pt даёт 4–10 %.

- **Браузер.** Сторож берёт Chromium самого Playwright. Если он не скачан, берёт установленный Google Chrome. С каким браузером сняты эталоны, записано в `ref/BROWSER.txt`. Другой браузер — предупреждение в выводе: текст рисуется чуть иначе.

**Когда эталон обновляется.** Только когда основатель одобрил новый вид, в том же PR. Команда — `cd apps/mobile && node e2e/visual/visual.cjs --update [экран]`. - Руководитель не вливает PR с изменёнными `e2e/visual/ref/*.png` без этой строки.

**Почему пока не в CI и что для этого нужно.**
1. **Шрифты на Linux.** Приложение грузит свои шрифты (Jost, Manrope, Onest через `@expo-google-fonts`), но системные запасные, эмодзи и сглаживание на Linux другие. Нужен второй набор эталонов, снятый на том же образе, что CI (`ref-linux/`), или запуск в контейнере `mcr.microsoft.com/playwright:v1.63.0-jammy` и локально, и в CI.
2. Браузер в CI — `npx playwright install --with-deps chromium` той же версии, что `playwright` в `package.json`, плюс шрифты `fonts-noto-color-emoji`, `fonts-liberation`.
3. Задание `visual` в `checks.yml` после сборки сайта. Отчёт `e2e/visual/out/` выгружать артефактом при красном.
4. Сначала 2 недели «только сообщает» (`continue-on-error`) и разбор мигалок по §9, потом обязательное.

## 12. Снимки экранов не снимаем сами (21.11.2026, #2360)
Разбор и сверка вида идут по снимкам службы-фотографа, а не по собственному серверу: `npm run shot:find` → `npm run shot` (правила и флаги — `docs/ai/WORKER.md` «Снимки экранов»). Снимок без штампа под кадром или со штампом старого коммита как доказательство не принимается. Свой сервер и свой Chrome ради снимка не поднимать (порты 8094–8099 заняты службой). Автотест формата — `apps/mobile/test/shotService.test.ts`; живая проверка службы — `npm run shot:selftest`.
