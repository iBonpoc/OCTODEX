# Исполнитель OCTODEX

Руководитель проекта один — см. `CLAUDE.md` и `docs/ai/DIRECTOR.md`. Он ставит задачи, принимает PR и вливает их в `main`.

## Правила исполнителя
1. В начале чата прочитать `CLAUDE.md` и `docs/ai/BOARD.md`. **До первой правки** сообщить руководителю (`send_message` на `session_015CqH68Vr1GBAvYuJQpTZzq`): задачу, ветку и файлы, которые будешь менять. Если тема или файлы уже у другого чата (доска, «Кто что держит»), не начинать: ждать ответа руководителя.
1а. Если по ходу работы нужен файл, которого не было в списке, сначала сообщить руководителю.
2. Работать в своей ветке и только в файлах своего направления (таблица в `CLAUDE.md`). Чужой или общий файл — сначала сообщение руководителю.
3. В `main` не пушить и PR не вливать. Это делает руководитель.
4. Перед PR: `git merge origin/main`, `npm run check`, `npm run check:e2e`; `BUILD` = номер PR.
5. После PR — отчёт руководителю (шаблон ниже). Вопросы о продукте можно задавать основателю напрямую; технические — руководителю.
6. Правки от руководителя — в ту же ветку, затем снова отчёт.

## Шаблон заявки (исполнитель → руководитель, до начала)
```
Чат: <название>, ветка <имя>
Задача: <1–2 строки>
Файлы: <список или маски>
Общие файлы: <нет / какие>
```

## Шаблон задания (руководитель → исполнитель)
```
Задача: <что сделать, 1–3 строки>

Твои файлы: <список>
Нельзя трогать: <список>
Тесты: <какие e2e / модульные / движок / база>
Готово, когда: <проверяемое условие>
```

## Шаблон отчёта (исполнитель → руководитель)

```
Тесты: <какие добавлены>

```
