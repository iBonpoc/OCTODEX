# Mac: почему не идёт `npm run check` (24.11, зона «Проверки»)

Проверено на чистом main (74b34c8bf) в ~/GoRix/wt-envcheck со своими node_modules.

## Что не работало и почему
1. tsc: 16 ошибок — 8 TS1149 + 8 следствий (TS2305/TS2724/TS1261). Причина одна: пять пар `X.tsx` + `x.ts`
   (ClosedCompany, NotesTerms, DemoBadge, SignOutAsk, BackSwipe). На Mac (ФС без учёта регистра) импорт `@/nav/BackSwipe`
   находит `backSwipe.ts`, а не компонент. Починено PR #2479 (компоненты -> `*View.tsx`, сторож `caseNamesGuard.test.ts`).
   После: 0 ошибок.
2. vitest: на чистом main 1 красный файл из 523 — `aptRetry.test.ts` (2 теста): скрипт `scripts/aptRetries.sh` использует
   GNU sed, на macOS BSD sed. Только Mac; на CI зелёно. Кодом чинится (sed без -i/-r-различий), отдельной задачей, здесь не трогал.
   `brandGuard`, `fontScale`, `gutter*` — зелёные на свежих node_modules: прошлые красные были от устаревших зависимостей.
3. Тесты базы (`supabase/tests/run.sh`): нужен Postgres 17 (`initdb` из `PGBIN`, по умолчанию /usr/lib/postgresql/17/bin).
   На этом Mac нет ни initdb/postgres/psql/pg_ctl, ни docker, ни brew. Скрипт под Mac годится с `PGBIN=...`; для `DB_NOW`
   (ночные часы) нужен ещё GNU `date -d` и libfaketime — на Mac не заработает, это только CI.
4. Сборка сайта (`expo export --platform web`) проходит.

## Что требует установки программ (решает основатель)
Postgres 17, один из способов:
- Postgres.app (postgresapp.com): ставится в /Applications/Postgres.app, бинарники в .../Versions/17/bin; `PGBIN` туда. Проще всего, без brew.
- Homebrew `postgresql@17`: нужен сам Homebrew (его на Mac нет); бинарники в /opt/homebrew/opt/postgresql@17/bin.
- Docker (Desktop или Colima): образ postgres:17, но run.sh ждёт initdb на хосте — пришлось бы переписывать скрипт; самый дорогой путь.
Рекомендация: Postgres.app. Ночной прогон (DB_NOW) локально не нужен, его делает CI.
