# 03 · Конструктор: шаблоны экранов как компоненты

Ревью 21.11.2026 · инженер-конструктор RN/Expo. Сверено: `wireframes.html`, `SCREENS.md`, `LAYOUT-RULES.md` ↔ `apps/mobile/src/ui`, `src/nav`, `packages/design-tokens`, CLAUDE.md правила 1, 27, 29.
**Итог:** 70 % кирпичей уже есть (`Screen`, `ActionBar`, `ViewTabs`, `SwipeRow`, `ButtonPair/FieldRow`, `Segmented`, `IconButton`, `StatusChip`, `MetaLine`, `FilterBar`, `Sheet/Menu`). Не хватает **уровня шаблона**: сейчас `Screen` принимает 20 свободных пропсов, и раскладку каждый экран собирает сам — поэтому правила П1–П7 держатся на совести. Предложение: 5 тонких обёрток над `Screen` с **типизированными слотами**, где правило выражено типом, а не текстом.

## 1. API шаблонов (`src/ui/templates/*.tsx`)
Общее для всех: слот главной кнопки — **одно значение типа `MainAction`** (`{label; onPress; reason?; testID}`), не `ReactNode`. Второй акцентной кнопки положить некуда — П2 гарантирован типом. Вторичные — только `IconAction[]` (`{icon; a11y; onPress}`; `a11y` обязателен — П6/VoiceOver). Опасное — только в `more: MenuItem[]` с `danger`, а `Menu` сам спрашивает подтверждение.

| Шаблон | Пропсы / слоты | Гарантирует |
|---|---|---|
| `OverviewScreen` | `title`, `date`, `next: {card: ReactNode; main: MainAction; more?: string}`, `attention: Row[]` (≤ 3, остальное → `allHref`), `summary: SummaryItem[]` (одна строка), `details?: ReactNode` (свёрнуто), `fab="home"` | главная кнопка — первая под шапкой (есть панель вкладок); «Требует действия» обрезается до 3; «Подробнее» закрыт по умолчанию; «＋» тональный |

**Что уже есть и становится частью шаблонов:** `Screen` (каркас, отступы, `footer`, `tabs/below/tabsMini`, `fab`), `ActionBar`, `ViewTabs`, `SwipeRow`+`swipeRowLogic`, `ButtonPair`, `FieldRow`, `FieldGroup`, `ListCard`, `FilterBar`, `Segmented`, `IconButton`, `StatusChip`, `StatusNote`, `MetaLine`, `Steps`, `Menu`, `Sheet`.
**Новое в `src/ui` (с записью в DS + витрина, правило 1/29):**
- `ObjectHeader` — имя (1 раз), строка «статус · сумма» через `MetaLine`, адрес мелко → маршрут, ссылка-связь «Клиент ›». Сейчас каждая карточка (`ClientCard`, `InvoiceCard`, job, visit) рисует шапку сама — источник дублей П7.
- `IconRow` — ряд `IconButton` 44 с обязательной `a11y`; заменяет `features/ActionTile` (плитки со словом).
- `MainStep` — главная кнопка + причина под ней (`MainAction.reason`).
- `DayPill` / `DayStrip` — **перенести** из `features/PlanParts.tsx` (`DayStrip`, `WeekStrip` там уже есть) в `src/ui`, добавить «точку загрузки» токеном.
- `SummaryLine` — «Получено $1,020 · Ждёт $2,800 · Просрочено 1», каждый пункт — ссылка; на 390 — перенос запрещён, хвост в «…».
- `StatTile` — только для «Подробнее»/820+, не на первом экране телефона.
- `Collapsible` («Подробнее ˅», «Готово · 2 ˅», «Итого ˅») — одна сущность вместо трёх самописных.
- Токены: `component.dayPill {w,h,dot}`, `component.iconRow {gap}`, `component.mainStep {reasonGap}` — в `packages/design-tokens` + `naryad-ds` (иначе красный `mirror.test.ts`).

## 2. Что в каркасах дорого или ломает правила — и как проще
1. **«＋» перевёрнут относительно решения основателя.** С2/§8 SCREENS: плавающий акцентный «＋» на списках, тональный на Главной. Код (`nav/sections.ts LIST_FABS`, #1395 вариант А, слово основателя 14.11): у списков «＋ объект» — **в шапке**, плавающий жёлтый — **только у Главной**. Каркасы противоречат действующему решению — до вёрстки нужен явный выбор основателя, иначе две волны правок `Screen`/`Fab`. Проще: оставить #1395 (уже сделано, тесты есть), каркасы поправить.
2. **Закреплённая кнопка + панель вкладок (Выезд).** `Screen` сейчас **выключает** `footer` там, где есть панель (`footerOn = … && !showsTabBar(route)`), а `visit/[id]` в `WITH_TAB_BAR`. Два пути: (а) перенести `visit/[id]` в `NO_TAB_BAR` как смета/счёт — 1 строка, без новой геометрии; (б) «полоса над вкладками» — новый режим `ActionBar`, пересчёт `useNavInsets`, тоста (`footerInset`), клавиатуры, «＋», жеста «назад» — ~8 ч и риск на iPhone. Рекомендую (а): на выезде вкладки не нужны, поле — одна рука.
3. **Жесты по строке (План, Клиенты, Задачи).** `SwipeRow` на вебе ничего не делает (честно). Значит П8 — не пожелание, а условие: каждое действие жеста обязано быть в карточке или «⋯», иначе на вебе/820 его нет. По правилу 27 каждый новый жест — тесты математики + строка «Натив:». Не делать «Перенести ←» в Плане через жест на первом шаге — открывать шторку переноса (меньше состояния). Перетаскивание по мастерам — только 820/1280 мышью, на телефоне не делать.
4. **Липкая полоса разделов + закреплённый низ + клавиатура** в одном экране (Смета, Счёт) — `Screen` уже умеет (`tabs/tabsMini/footer`, скрытие при клавиатуре). Не изобретать второй механизм в шаблоне — только прокидывать.
5. **Полоса разделов «вбок» с 8 пунктами.** `ViewTabs` уже со скроллом, затуханием и «подталкиванием». Риск — производительность: `onLayout` у каждой пилюли и `setBoxes` → лишние перерисовки при числах-счётчиках. Мемоизировать `items` в шаблоне.
6. **Чипы «одной полосой».** Сейчас `ChoiceChips/MultiChips` переносятся строками (`flexWrap`). Шаблон списка должен звать горизонтальный вариант; добавить `ChoiceChips layout="strip"`, а не новый компонент.
7. **Значки вместо слов.** Набор `icons` неполный для «ссылка», «напомнить», «маршрут» — проверить `primitives.icons`; новые значки — через DS, не SVG в экране.
8. **Ряд пары «Сумма · Номер» на 390 с крупным шрифтом (Dynamic Type).** `FieldRow` должен сам падать в столбик по `pairLayout.ts` — проверить, что шаблон не форсирует ряд.
10. **Размер кнопки.** П4/§4 «кнопка 40» и токен `component.button.phone: 40` расходятся с CLAUDE.md правило 3 («телефон 36»); ActionBar 44 — исключение правила 3. До вёрстки свести в одно (правило 3 или токен), иначе сторож и витрина спорят.
9. **Скриншоты каркасов 390×844 «влезают» потому что текст обрезан эллипсисом.** На живых данных (длинные имена, испанский позже) первый экран будет длиннее — сторож §4 мерить на реальных фикстурах.

## 4. Сторож компактности (автоматически)
**Уровень А — статический (vitest, быстро, в CI всегда):** экраны, перечисленные в карте `SCREEN_TEMPLATE` (`test/screenTemplates.test.ts`: маршрут → шаблон), обязаны рендерить свой шаблон, а не голый `Screen`; новый маршрут без записи — красный (как `tabBarRule.test.ts`). Плюс по исходникам: в `app/` нет `<Button variant="primary">` вне слота `main` шаблона; нет `flexWrap` у чипов; нет `ActionTile`.
**Уровень Б — рендер (vitest + @testing-library/react-native, на фикстурах демо-данных):** шаблон в `__DEV__`/тесте публикует метрики через `testID` и счётчики:
- **главных кнопок = 1** (`testID` `main-*` считается по дереву; акцентные `Button` вне слота — ошибка);
- **рядов чипов = 1** (все `ChipItem` внутри одного `ScrollView horizontal`);
- **слов в кнопке:** главная ≤ 3 слов (без суммы; исключение — шторка оплаты, П7), вторичные — 0 слов (только значок + `accessibilityLabel`);
- **дубли (П7):** собрать все `T` первого экрана, нормализовать, ключевые значения (имя, телефон, адрес, сумма `$…`, статус) не встречаются дважды; исключения — список в тесте, только сокращается;
- **«Требует действия» ≤ 3, значков в `IconRow` ≤ 5, разделов в полосе без счётчика-нуля.**
**Уровень В — геометрия первого экрана (Playwright, веб 390×844 + ручная проверка на iPhone по правилу 27):** на фикстуре считать блоки, верх которых < `844 − tabBar − safe`: ≤ 6 для Объекта/Обзора; **главная кнопка и полоса разделов обязаны быть видны без прокрутки**; у Редактора `ActionBar` виден при любой длине формы. Снимки 390/820/1280 в обеих темах — в артефакт PR. Веб-зелёное не доказывает натив (правило 27): высоты шапки/безопасных зон на iPhone другие — порог считать от `useNavInsets`, а не числом.
**Список исключений** — одна таблица в `LAYOUT-RULES.md` §7 + зеркальный массив в тесте (как `designSystem.test.ts`): экран, правило, чьё слово; может только сокращаться.
