## 2. Текущий вид «Наряд» (то, что в приложении сейчас)

Источник: DS `design/naryad-ds/DESIGN-SYSTEM.md` §1–§8, `packages/design-tokens/src/index.ts` (истина по числам). Формула DS §1 п.3: **«вид — Наряд, поведение — iOS»**.

### 2.1 Цвет
- **Тёмная тема** (графитовая): фон страницы `#181A1E`, приложения `#24272D`, текст `#F2F3F5`, второй текст `#CDD1DA`. Карточка — белый 7 %, поле — белый 5 %, рамка — белый 14 %, рамка поля — белый 38 %.
- **Светлая тема** (тёплая): страница `#DDD9D2`, фон `#EFEBE5`, текст `#15161A`, второй текст `#575C68`; карточка — белый 62 %.
- **Акцент `acc` = `#FBFF00` (лимонно-жёлтый)** в обеих темах, текст на нём `#0B0C0F`. Только главное действие экрана/листа, жёлтый «＋» на «Главной», тумблер «вкл», выбранное на графиках, рамка поднятой строки.
- **Статусы** (значок + слово): ok `#7CE08A`, info `#8FA2FF`, warn `#FF8A3D`, bad `#FF6B6B`, neutral — серый. Цветная кромка карточки (3 pt) только у warn и bad.
- Фон под всем: три размытых цветных пятна (`glow`: зелёное, оранжевое, синее) — разные в двух темах.
- Исключения из «цвет только для статуса» (их ровно три, все Gutters): этажи на холсте, плашка рулетки, образец цвета материала.
- Контраст проверяется тестом (`contrast.test.ts`): текст ≥ 4,5, крупный текст и значки ≥ 3, обе темы.

### 2.2 Шрифт
- **Onest** 400/500/600/700 (`@expo-google-fonts/onest`). Роли: display 28/700, title 22/600, heading 17/600, body 15, input 17, button 15/600, caption 13, micro 11 (только подписи вкладок). Минимум текста 11.
- Крупный системный шрифт: растёт до 200 %, потолок в кнопках/вкладках `maxScale` 1,6; высоты кнопок — `minHeight`. Цифры — одной ширины.

### 2.3 Стекло и поверхности
- Слои: L0 страница, L1 карточка (`surf`, **не размывает**), L2 вложенное (`in`), L3 нейтральные чипы (`surf2`), стекло, затемнение.
- Правило DS §6.3: стекло только у плавающего слоя управления (нижняя панель, закреплённая панель действия, меню, тост, шторка, окно, полоса шапки); у содержимого стекла нет. Не больше 3 размытых слоёв на экране.
- iOS 26+: нижняя панель вкладок — родное Liquid Glass (`expo-glass-effect`, `GlassView regular`). Остальное — «стекло Наряда» на `expo-blur` (`Glass`), на вебе `backdrop-filter`. Шторка и окно — стекло Наряда на всех платформах (много текста и полей).
- «Понижение прозрачности»: правило есть, код — не везде (⬜ Н-05, Н-72, задача #959).
- Тень у карточки: чёрная 0,3 / тёплая 0,12.

### 2.4 Форма, плотность, размеры
- Радиусы: карточка **24**, вложенное 18, поле 12, шторка 24, чип — пилюля.
- Отступы: шаг 4 (4/8/12/16/20/24/32).

## 3. «Графит»

### 3.1 Что это и откуда
- **Факт.** Новый вид, пакет «чата дизайна» (handoff v2.1, 19.11.2026; ссылки на пакет и прототип — только артефакты claude.ai, **в репозиторий не скопированы**). DS §25: «пилот, не правило», записан как **«выбор основателя 19.11»**.
- Что выбирал основатель (DS §25): шрифт Jost 300/400/500, фон «Светлее» в обеих темах, стекло «Матовое», нижняя панель «Прожектор» с жёлтым лучом, жёлтый только у главного действия и «＋». То есть **выбор шёл по прототипу и регуляторам внутри «Графита»**, а не между разными направлениями.
- **Мнение главного дизайнера (комментарий в #2344, 20.11 11:04, «со слов, по документам»):**
  - «разбора с несколькими дизайнерами и дебатами до выбора «Графита» не было»;
  - выбирали «сравнивая варианты внутри «Графита», а не разные направления. Критик тоже проверял пакет только внутри «Графита»»;
  - «Единственное сравнение направлений — исследование 20.11 (родной iPhone / своя система / готовая библиотека). По нему аудит выбрал «родной iPhone + один акцент». На этом выборе построены §1а (#2338) и спека 64»;
  - «Сверку с HIG «Графит» как вид проходит плохо: свой шрифт, своё стекло, луч на вкладках, жёлтый цвет режет глаз»;
  - «правила поведения §1а подходят любому направлению».
- Параллельное противоречие в самом репозитории: DS §1а (PR #2338) называет направление **«родной iPhone + один акцент»** (iOS — системный шрифт, вкладки, шапки, листы, меню, SF Symbols), а эпик #2294 и спека 63 ведут **весь** редизайн в «Графит». Два курса одновременно; основатель их ещё не сводил.

### 3.2 Что в «Графите» (токены `packages/design-tokens/src/graphite.ts`, зеркало `design/naryad-ds/tokens/graphite.css`)

- **К4** — замер главного пути скриптом (нажатия/вводы/экраны; сейчас 18 / 11 / 5·3) — после не хуже, цель меньше.
- **К5** — проход основателя на iPhone на улице, одной рукой, большим пальцем, не перехватывая телефон, по чек-листу (12 строк, спека 63 §5.5): светлая тема на солнце; полоска разделов; нажатие каждой кнопки; загрузка/выключено; круглая кнопка; «＋» и возврат; «Основа»; крупный текст на максимум; «Уменьшить движение» и «Понижение прозрачности»; вибрация; экран клиента — одно главное действие внизу, опасное отдельно; назвать номер варианта вслух.
- **К6** — независимая оценка по 10 эвристикам «до» и «после» по «стене экранов» (десять пунктов «что болит» — §2.7).
- Порядок: Ш0 стена + К4 + К6 → Ш1 листы → Ш2 переключатель цветов → Ш3 экран клиента + К5 → Ш4 главный путь → Ш5 сверка К1–К6 → только потом запуск.
- Приёмка каждого раздела листа: проверка крупного шрифта и контраста в обеих темах; кадры стенда; снимки «до/после» этапа III без отличий.

### 6.2 Принципы «Графита» (спека 63 §7, приняты аудитом 20.11; в DS правилами — позже, через двух design-reviewer)
1. **Одно главное действие на экран** — внизу, под большим пальцем; опасное отдельно, с подтверждением или «Вернуть» (ответ 61-А).
2. **Одно действие — одно поведение:** один компонент на токенах для «Создать», «Добавить», выбора, подписи поля, «Назад».
3. **Читается и нажимается всегда:** контраст по тестам, текст ≥ 12, подпись переносится, а не режется; цель ≥ 44.
4. **Экран показывает главное, остальное — по требованию:** служебное, «Демо», подсказки, пустые тупики не занимают рабочий экран; карточка ≤ 3–4 строк.
5. **Состояние не врёт:** цвет только за статус (значок + слово); статус вычисляется по данным; активное место меню — там, где человек.

Принципы закрывают все 10 пунктов К6. Они пишутся **от болей**, а не от вида: пригодны любому направлению.

### 6.3 Правила проверки поведения (DS §1а.10)
Сторожа модульные + e2e на шести видах + кадры со стенда (iPhone-симулятор, правило 27) + проход основателя + независимый критик (`design-reviewer`). Новые правила DS — два независимых ревьюера (в PR #2338 ревьюер нашёл 6 блокирующих, все исправлены).

### 6.4 Что ещё потребует #2344 (не согласовано, предлагаю как вход)
- Порядок, заданный основателем: бриф → исследование (лучшие CRM/FSM и лучшие приложения вообще, Apple HIG, правило 28) → брейншторм нескольких независимых дизайнеров → дебаты → общее решение с обоснованием; основатель утверждает готовое.
- Структура приложения (вкладки, где сметы и счета, главное действие, возможности лидеров рынка, перетаскивание) входит в тот же разбор (#2348).
- Предлагаю добавить в критерии: сверка с HIG по пунктам §3.4 (не «окей/не окей», а таблицей), и «проходит ли вид на трёх ширинах и в веб-версии без отдельной кодовой базы».
