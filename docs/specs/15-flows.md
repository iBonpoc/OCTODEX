# 15. Сквозные сценарии и связи

> v1, 06.11.2026. Парный документ к `docs/specs/13-app-structure.md` (дальше «13»). Не путать с картой пути `docs/15-story-map.md` (дальше «карта»): карта задаёт порядок, стыки и статусы, а здесь — как человек проходит путь по экранам приложения без обрывов.
> **Решение основателя 05.11 и 06.11:** устройство экранов как у Workiz и как принято на рынке, вид — «Наряд». Ничего нового не изобретаем.
> Источники: три сверки 06.11 (документы против 13; 12 сценариев «без обрывов», обрывы Б1–Б27; сущности и связи против кода и базы), разборы Workiz, Jobber, Housecall Pro, ServiceTitan, аудит сборки 109.
> Gutters и другие модули не участвуют.
>
> Правила `CLAUDE.md` действуют на каждом шаге: только токены; цвет только для статуса (значок + слово); офлайн с очередью; необратимое — подтверждение или «Отменить» 5 с; i18n RU/EN/ES; всё, что уходит клиенту, — на языке клиента (`tFor(docLanguageFor(…))`); деньги — только `@octo/estimating-engine`, целые центы; списки — карточками; на каждый стык — тест.

Как читать таблицы сценариев:
- **Кто:** Вл — владелец, Ад — админ, Оф — офис, Пр — продажи, М — мастер, Суб — субподрядчик, К — клиент, С — система.
- **Где:** вкладка (Главная, План, Сообщения, Звонки, Клиенты), ☰ (меню), «＋» (плавающая кнопка экрана), кнопка на экране.
- **Стык** — ID из карты §4. S18–S22 — новые, предложены в 13 §5; руководитель вносит их в карту.
- **Выход** — куда человек попадает и что делает дальше.

### 3.2 «Искать везде»

Одна чистая функция `features/search.ts` — `searchAll(db, q, role)`. Ею же пользуются поиск клиентов (`matchClient`) и поиск лидов, правила не дублируются. Работает по локальной базе, без сети.

| Что | Правило |
|---|---|
| Номер | точное начало: `EST-12`; просто `12` — по всем префиксам |
| Телефон | по цифрам, от 3 знаков, у всех людей клиента и лида |
| Имя, адрес, email | вхождение, без учёта регистра |
| Свои поля | только с признаком «искать по полю» |
| Закрытые лиды, архив клиентов | ищутся, показываются ниже с пометкой |
| Права | как в ☰ (13 §4): мастер — только своё, без счетов и оплат |

**Экран результатов:** группы Клиенты · Лиды · Объекты · Работы · Сметы · Счета · Оплаты, по 3 в группе и «Показать все»; в карточке — почему найдено («телефон Mary»). Объект открывает объект. Пусто — «Ничего не нашлось по «…»». Место: Главная и списки на телефоне; шапка над списком и клавиша `/` на 820 и 1280.

**Поиск в списках** (Работы, Сметы, Счета, Оплаты, План) — то же поле, отфильтрованное по своей группе.

Тесты: unit на каждый префикс, телефон, email, людей, свои поля, права мастера; e2e «Искать везде → JOB-0001 → работа» на 6 видах.

Пункты «Требует внимания» (S15) разных волн идут в `attention.ts` по очереди через руководителя.
- **Экраны-списки** (клиенты, сметы, счета, работы, каталог, лиды) сейчас переводит чат карточек, по одному PR. Пока список у него, другие чаты этот экран не трогают.
- **Каждая волна** начинается с короткого этапа 0 (полстраницы: какие сценарии §1 и клетки §2 она закрывает) и кончается зелёными `npm run check` и `npm run check:e2e -- --all-layouts <свои спеки>`; `BUILD` = номер PR.
- **Длинные чаты архивируются:** исполнитель берёт 2–3 волны одного направления, пишет памятку-передачу, руководитель открывает новый чат (`docs/ai/WORKER.md`).
