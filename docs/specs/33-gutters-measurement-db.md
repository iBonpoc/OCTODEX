## П19.3 Что сделано
- `gutter_measurements`: объект?, лид?, подпись ≤ 120, `draft` / `ready`, номер последней ревизии, служебные поля, `deleted_at`, `unique (id, company_id)`.
- `gutter_measurement_elements`: вид (`run`, `downspout`, `chain`, `wye`, `corner`, `point`), `geom` (объект ≤ 2 КБ, целые дюймы), `attrs` (объект ≤ 8 КБ — вход движка), уверенность `auto` / `drawn` / `taped`; ссылка `(measurement_id, company_id)` — элемент не может оказаться под замером другой компании.
- `gutter_measurement_revisions`: номер (один раз на замер), снимок элементов (массив), детали движка (массив, без цен), версия движка; всё ≤ 512 КБ; не меняется.
- Пределы на замер: ≤ 1000 элементов, ≤ 100 ревизий (триггер `app.tg_gutter_limits`).
- Чужой человек получает один ответ «not allowed» при любых id объекта и лида — по ошибке нельзя узнать, чей объект.
- Индексы на всех внешних ключах (сторож базы) и для синхронизации (`company_id, updated_at`).
- Функции: `app.gutter_sees` (кто видит замер), `app.gutter_sees_measurement` (элементы и ревизии — по своему замеру) — для RLS, authenticated; `app.tg_gutter_measurement_refs` (ссылки своей компании; мастер — только свои лид и объект), `app.tg_gutter_revision_frozen` — триггеры, никому.

## П19.4 Тесты
T92: модуль выключен — не сохраняется; владелец, продавец, офис видят и пишут все; мастер не видит чужой замер на не своём лиде и не рисует на нём, мерит своё, не привязывает к чужому лиду, другой мастер его замер не видит, после назначения лида — видит и рисует; автор не подделывается; повторная запись элемента = обновление, версия + 1; чужие объект и лид отклоняются (и при правке); формы и размеры; нет DELETE; `deleted_at`; `company_id` не меняется; чужая компания ничего не видит и не пишет; субподрядчик ничего; права anon / authenticated; RLS включена и принудительна.
T93: ревизия и «готов»; номер ревизии один раз; снимок — массив ≤ 1 МБ; ревизию не меняет ни приложение, ни сервер; после пробного периода чтение есть, запись нет (новый замер, правка, ревизия); после оплаты запись снова есть.

## П19.5 Проверка безопасности (security-check 07.11): исправлено и принятые риски
Исправлено в этом PR: утечка «чей объект / лид» через текст ошибки (первая проверка триггера — член ли компании); нет предела строк (пределы выше, снимок ≤ 512 КБ). Видимость мастера сужена до его замеров, лидов и выездов (по слову руководителя).
Второй круг (по новой видимости мастера): один текст отказа «this lead or property cannot be linked» и внутри компании (мастер не узнаёт, есть ли лид или объект); тесты на объект выезда, на чужой объект при вставке и смене, на правку замера на своём лиде при чужом объекте, на ревизии невидимого замера, на снятый лид, на полную перезапись из очереди (`insert … on conflict do update` — триггер сравнивает ссылки с переписываемой строкой); быстрый путь `is_staff` в правилах элементов и ревизий.
Принятые риски (записаны, закрываются в своих PR):
- Внутри компании мастер по ошибке upsert узнаёт, что замер с таким id есть (как во всех таблицах ядра). Видя замер через свой лид, мастер видит его `property_id` и `label`: в `label` и `attrs` не кладём персональные данные клиента.
- Офлайн: если офис сменил лид замера, полная перезапись с телефона мастера со старым лидом отклоняется (или отвязывает лид) — обработчик M5 и К9 учитывают.
- **Удаление данных клиента (CCPA):** при настоящем удалении объекта или лида замер остаётся (`on delete set null`). Задача удаления данных клиента должна удалять и замеры по `property_id` / `lead_id` — в её спеке (ядро).
- **После пробного периода** черновик нельзя и удалить (`deleted_at` — тоже запись; О2). M5: очередь показывает «модуль не активен» и не повторяет отправку без конца.
- **Номер ревизии и «готов»** ставит приложение; сервер не сверяет их с ревизиями — можно занять номер заранее (внутри компании, не утечка). Выдача номера сервером — вместе с M8 (замер → смета).
- Замер можно привязать к объекту или лиду с `deleted_at` (внутри компании).
- **Ядро:** `app.tg_service_fields` берёт `created_at` от клиента — строка «в прошлом» может пропасть из синхронизации по `updated_at` на других телефонах. Касается всех таблиц — отдельная задача ядра (руководителю).
