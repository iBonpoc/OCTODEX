## П19.1 Брейншторм: как писать
| Вариант | Плюсы | Минусы |
|---|---|---|
| **А. Прямой upsert под RLS** (как остальные таблицы ядра) | очередь пишет элемент целиком одним upsert (идемпотентно, П15 «полная запись»); меньше кода; права — в политиках | проверку версии (К9) не сделать без триггера |
| Б. Свои функции `gutter_save_element(…, base_row_version)` | проверка версии и всех правил в одном месте | больше функций (правило 18, T52), обработчик очереди сложнее; К9 — этап 4 |
**Выбор: А.** К9 (этап 4) добавится триггером на `row_version`, без смены схемы.

## П19.3 Что сделано
- `gutter_measurements`: объект?, лид?, подпись ≤ 120, `draft` / `ready`, номер последней ревизии, служебные поля, `deleted_at`, `unique (id, company_id)`.
- `gutter_measurement_elements`: вид (`run`, `downspout`, `chain`, `wye`, `corner`, `point`), `geom` (объект ≤ 2 КБ, целые дюймы), `attrs` (объект ≤ 8 КБ — вход движка), уверенность `auto` / `drawn` / `taped`; ссылка `(measurement_id, company_id)` — элемент не может оказаться под замером другой компании.
- `gutter_measurement_revisions`: номер (один раз на замер), снимок элементов (массив), детали движка (массив, без цен), версия движка; всё ≤ 1 МБ; не меняется.
- Индексы на всех внешних ключах (сторож базы) и для синхронизации (`company_id, updated_at`).
- Функции: `app.gutter_measurer` (роль, для RLS; authenticated), `app.tg_gutter_measurement_refs`, `app.tg_gutter_revision_frozen` (триггеры; никому).

## П19.4 Тесты
T92: модуль выключен — не сохраняется; владелец, мастер, продавец, офис пишут; автор не подделывается; повторная запись элемента = обновление, версия + 1; чужие объект и лид отклоняются (и при правке); формы и размеры; нет DELETE; `deleted_at`; `company_id` не меняется; чужая компания ничего не видит и не пишет; субподрядчик ничего; права anon / authenticated; RLS включена и принудительна.
T93: ревизия и «готов»; номер ревизии один раз; снимок — массив ≤ 1 МБ; ревизию не меняет ни приложение, ни сервер; после пробного периода чтение есть, запись нет (новый замер, правка, ревизия); после оплаты запись снова есть.
