## 1. Что сказал основатель
1. На каждом водостоке всегда должен быть даунспот: нарисовал желоб — даунспот появляется сразу, у края, слева или справа, **1 фут от края** (стандарт, настройка).
2. Редкие случаи: заглушек нет и вода уходит на соседнюю крышу → даунспота нет. Иногда ставят **выпуск (outlet)** без даунспота (вода перетекает в другой желоб) или с цепочкой (цепь висит на выпуске).
3. Удаление даунспота спрашивает: «удалить вместе с выпуском?» (галочка). Можно оставить выпуск.
4. Угол из двух линий = **один** даунспот на две линии. Две отдельные линии — по даунспоту; соединили в угол — один даунспот исчезает. Вручную добавить можно всегда.
5. Выпуски подбираются под даунспот: круглый / 2×3 / 3×4. Прямой и ребристый даунспот — один и тот же выпуск; круглый простой и ребристый — один и тот же.
6. В заказ поставщику идут выпуски, заглушки, и **винты: 15 на даунспот** (число — настройка).
7. Заказ поставщику выглядит и редактируется **как смета** (те же блоки позиций), позиции можно удалять и уменьшать; учитывается склад: «нужно 10, на складе 7 → заказать 3», показывать остаток («может, возьмёте со склада?»).
8. Склад (в перспективе): резерв под работу, пока работа не закончена; списание — по завершении.
9. На желобах — **защита (gutter guard)** разных видов, выбор вида.
10. У одной позиции **несколько поставщиков**, в строке сметы/заказа селектор поставщика (если поставщик один — селектора нет); у поставщиков артикул/название могут отличаться. Без «миллиона настроек».

## 7. Полная спека реализации (А1–А6, В1)
**Данные (геометрия, `geom jsonb`, без миграции — правило 16).** `DrawnDownspout.auto?: boolean`; `DrawnRun.dsAutoOff?: boolean` (на любой линии цепи, пересчёт смотрит на цепь целиком); `DrawnOutlet {id, runId, atIn, kind: "ds"|"chain"|"overflow", dsId?}` — **новое**: выпуск отдельный объект, `dsId` пуст, если даунспота нет. Настройки компании модуля: `dsAutoSpacingFt` (35), `dsEdgeOffsetIn` (12), `dsAutoSide` ("free-end" по умолчанию). Старые чертежи без `outlets` читаются: выпуск выводится из даунспота (миграция «лениво» при открытии, без записи в базу).
**Функции (`canvas/edit.ts`, чистые).** `autoDownspouts(drawing, settings) → Drawing` — пересчёт после каждой фиксации линии и после слияния/разъединения цепи: для каждой цепи считает нужное число (⌈длина цепи ÷ порог⌉), снимает лишние авто, ставит недостающие по правилу стороны; ручные (`auto` не true) не трогает; цепь с `dsAutoOff` — только ручные. `removeDownspout(drawing, id, {withOutlet})` — для диалога. Движок: выпуск по `(форма, размер желоба, форма и размер даунспота)`, не по `dsStyle`; выпуски считаются из `outlets`, а не из числа даунспотов; расходник `ds_screws` = `dsScrews (15) × число даунспотов`.
**Экран.** Диалог удаления даунспота с выпуском: чекбокс «Удалить также выпуск» (вкл.), «Отменить» 5 с (правило 5). Подпись «авто» на даунспоте в атрибутах. Настройки — в «Настройки модуля Gutters» (рядом с запасом и высотой этажа).
**Тесты.** Модуль: 1 линия = 1; 2 линии цепью = 1; две отдельные = 2; цепь 40 ft = 2; соединил → один исчезает; разъединил → второй возвращается; ручной остаётся; удалил авто → не вернулся; сторона: свободный конец, оба свободны — конец, которым закончили; отступ 12″. Движок: выпуск прямой = ребристый; 15 винтов × N; выпуск без даунспота; цепь на выпуске (rainchain) не даёт даунспота. База/данные: чертёж со старым геом читается. E2E (блок 296–299): нарисовал линию → даунспот на 12″ у свободного конца; угол из двух → один; удаление с выпуском/без. `chipsLabel`, niche guard (слово «gutter» только в модуле).
**Карта пути.** Стык S11g: `purchaseLines` отдаёт выпуски, винты, как позиции. Новых статусов нет. Вносит руководитель в `docs/15-story-map.md` §4.
