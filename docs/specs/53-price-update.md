## 0. Коротко (для основателя)

- **Откуда цены сейчас.** Смета берёт цену позиции каталога компании. Гаттерный модуль находит позицию по свойствам детали (профиль, размер, металл, цвет). Если позиции нет, «Создать позиции сразу» делает её с **тестовой** ценой.
- **Что сделаем.** На экране «Цены» модуля и в «Каталоге» появится кнопка **«Обновить прайс»**. Вы выбираете файл прайса (таблица CSV или Excel; позже — фото или PDF). Приложение находит свои позиции и показывает экран **«было → стало»**: старая и новая закупочная цена, процент, новая цена клиенту. Вы отмечаете строки галочками и нажимаете «Применить». Загрузку целиком можно отменить в течение 30 дней.
- **Одну цену вручную** — два нажатия: нажали на позицию на «Ценах» → ввели цену → «Сохранить».
- **Что не меняется.** Отправленные и подписанные сметы — никогда (у них снимок цены). Черновики — только по вашей кнопке «Пересчитать».
- **Следующий месяц быстрее первого.** В первый раз приложение сопоставляет строки прайса по названию и свойствам, и «похожие» вы подтверждаете сами. После «Применить» артикул поставщика запоминается в позиции, и в следующий раз все такие строки совпадут сами.
- **Вопросы к вам** — §15.1. Главный (деньги): у позиций с тестовой ценой наценка 0 %. Если подставить реальную закупку, цена клиенту станет равна закупке. Какую наценку ставить?

## 4. Брейншторм и решение

### 4.1. Что нужно подрядчику с телефона
Поставщик раз в месяц присылает прайс. ABC Supply, по словам аудита, пересматривает цену рулона ежемесячно. Подрядчику нужно: (1) за пару минут обновить закупку тех 20–80 позиций, которыми он реально пользуется, и не набирать цены руками; (2) увидеть, что подорожало и насколько, и не пропустить опечатку; (3) знать, что подписанные сметы не поменяются; (4) иногда поправить одну цену прямо на объекте.

### 4.2. Варианты

| Вариант | Что | Плюсы | Минусы |
|---|---|---|---|
| А. Как Jobber | выгрузить каталог в CSV, поправить в Excel, загрузить с «Update existing» | просто | Excel на телефоне неудобен; формат свой, а не поставщика; превью нет — перезаписывает сразу; цены нужно переводить в свои единицы руками |
| **Б. Прайс поставщика → «было → стало» (рекомендация)** | любой файл поставщика (CSV/XLSX, позже фото/PDF) → разбор и сопоставление на телефоне → проверка с галочками → одна серверная функция → отмена загрузки | формат поставщика как есть; видно каждое изменение; опечатку ловит порог ±25 %; следующий месяц совпадает сам (артикул запоминается); один экран для файла, фото и будущей команды помощника | сопоставление в первый раз требует подтверждения «похожих» |
| В. Только быстрая правка | шторка цены, без загрузки | ноль новых таблиц | 50 позиций — 100 нажатий каждый месяц; просьбу основателя «загрузить фото или PDF» не закрывает |

**Решение — Б, а быстрая правка (В) идёт первой волной:** она маленькая и закрывает «как менять цену вручную» уже сейчас.

### 4.3. Разбор файла (телефон, без ИИ, чистые функции)
- **CSV**: UTF-8 / UTF-8 BOM / Windows-1252, разделитель `,` `;` Tab — угадывается. Разбор — общий с импортом клиентов (`csvImport.ts`: `importCell`, предел ячейки 200 символов), вынести в `features/import/csv.ts` без изменения поведения клиентов (их тесты остаются зелёными).
- **XLSX**: первый лист (или выбор листа); строка заголовков — первая непустая строка, где угадана колонка цены. Читаем только сохранённые значения ячеек, формулы не вычисляем. Нужна зависимость для распаковки ZIP — проверка по правилу 17 (`fflate`: без зависимостей, без скриптов установки; альтернатива — `jszip`). Пределы — §10.
- **Колонки угадываются по заголовкам** EN/RU/ES: артикул (`sku`, `item #`, `part number`, `артикул`), название (`description`, `name`), цена (`price`, `cost`, `net`, `unit price`), единица (`uom`, `unit`), фасовка (`pack`, `qty/pack`, `per`). Угадано не всё → шаг «Какая колонка — цена?» (выбор из заголовков). Последний выбор для поставщика помнится на телефоне.
- **Деньги — строкой через движок**: `parseMoneyToCents` (принимает `$1,234.50`). Формат `1.234,50` распознаётся заранее по файлу и приводится к `1234.50` чистой функцией (тест). Пусто, ноль, минус или не число → строка «нет цены», её нельзя отметить.
- **Фасовка из текста**: «50 ft roll», «box of 50», «10' stick», «/50» → число и единица (чистая функция ядра, без нишевых слов). Не нашли и единица прайса ≠ единице позиции → «Сколько {ft} в упаковке?», пока не ответят — строку нельзя отметить.

### 4.4. Сопоставление (телефон, чистая функция `priceMatch`)
Только позиции `kind = material`, не удалённые. Для каждой строки:
1. **Артикул поставщика**: позиция с тем же `supplier_id` и `supplier_sku` (сравнение без регистра и пробелов) → «совпало».
2. **Свой код**: `sku` или `barcode` позиции равен артикулу строки → «совпало».
3. **Свойства от модуля** (слот S0e): модуль, если включён, возвращает свойства строки → `catalogMatch` ядра с той же единицей → «похоже».
4. **Название**: нормализованные слова (нижний регистр, без знаков, `"` → `in`), доля общих слов ≥ 0.6 → «похоже», до трёх кандидатов.
5. Иначе — «нет в каталоге».

Одна позиция — не больше одной строки: если две строки указывают на одну позицию, обе получают «две строки на одну позицию» и без галочки. Точное совпадение по артикулу важнее «похожего». «Похоже» отмечается только после выбора позиции человеком (шторка с кандидатами).

Позиция с другим основным поставщиком (не тем, чей прайс): строка показывает «Поставщик сменится: Home Depot → ABC Supply» и стоит без галочки (спека 36: у позиции один основной поставщик).

«Нет в каталоге» — в 53-2 только показываются: «Добавить в каталог» — вопрос основателю №4 (по умолчанию нет: каталог не засоряется сотнями чужих позиций).

### 4.5. Что меняет «Применить» (одна строка)
| Поле позиции | Значение |
|---|---|
| `catalog_item_costs.unit_cost_cents` | новая закупка за единицу каталога без налога (`costPerUnit`, при «цены с налогом» — после `netOfTax`) |
| `catalog_items.unit_price_cents` | `catalogPrice(cost, vendor_tax_bps, markup_bps)` — то же, что считает телефон |
| `markup_bps` | не меняется; **только** у позиции с тестовой ценой и наценкой 0 — значение поля «Наценка для тестовых» (§7.4), если человек его задал |
| `vendor_tax_bps` | не меняется; при смене поставщика — по правилу S0c (копия ставки поставщика, если она задана) |
| `supplier_id`, `supplier_sku`, `vendor` | поставщик загрузки и артикул строки (`vendor` — имя поставщика для старых телефонов, правило 16) |
| `pack_size`, `purchase_unit` | из строки, если человек их подтвердил |
| `is_placeholder_price` | `false` — цена больше не тестовая (правило 9) |

## 5. Данные (миграция `2026111x…_price_imports.sql`; правило 16 — шаг 1, только добавление)

### 5.1. `public.price_imports` — загрузка прайса
`id uuid pk` (создаёт телефон: повтор — та же загрузка), `company_id`, `supplier_id uuid not null` (FK `(company_id, supplier_id)` → `suppliers`), `source_kind text check in ('csv','xlsx','photo','pdf')`, `file_name text 1..200`, `file_sha256 text ^[0-9a-f]{64}$`, `price_date date` (дата прайса; пусто — дата загрузки), `prices_include_tax boolean not null default false`, `test_markup_bps int null check 0..100000` (наценка для тестовых, §7.4), `status text check in ('applied','undone')`, `counts jsonb` (`applied`, `skipped_changed`, `skipped_gone`, `undone`, `kept`), `applied_at`, `applied_by`, `undo_until` (= `applied_at + 30 days`), `undone_at`, `undone_by`, `created_at`, `created_by`; `unique (company_id, id)`; индексы `(company_id, created_at desc)`, `(company_id, file_sha256)`, FK-индексы; `t11_company_id_immutable`.

### 5.2. `public.price_import_rows` — строка (для отмены и истории)
`company_id`, `import_id`, `line int 1..1000`, `item_id uuid not null` (FK `(company_id, item_id)` → `catalog_items`), `raw_name text ≤ 200`, `supplier_sku text ≤ 64` (белый список символов, как `barcode`), `pack_price_cents bigint ≥ 0`, `pack_size numeric(12,3) > 0`, `purchase_unit text ≤ 20`, `unit_cost_cents bigint ≥ 0` (стало), и «было» для отмены: `prev_unit_cost_cents`, `prev_unit_price_cents`, `prev_markup_bps`, `prev_supplier_id`, `prev_supplier_sku`, `prev_vendor`, `prev_pack_size`, `prev_purchase_unit`, `prev_placeholder boolean`; `result text check in ('applied','skipped_changed','skipped_gone')`, `undone boolean default false`; `primary key (import_id, line)`, `unique (import_id, item_id)` (одна позиция — одна строка).

Права обеих таблиц: `revoke all … from anon, authenticated`; `grant select … to authenticated`; политика чтения `app.can_view_costs(company_id) and app.is_staff(company_id)`; записи нет ни у кого — только функции ниже. Мастер и продажник без права себестоимости строк не видят (в них закупка).

### 5.3. Функции (правило 18: `revoke all … from public, anon`, `grant execute … to authenticated`)
**`public.apply_price_import(p_import jsonb, p_rows jsonb) returns jsonb`** — `security definer`, `search_path = ''`.
- Кто: `auth.uid()` есть; `app.is_staff(company)` и `app.can_view_costs(company)`; иначе `42501`. Компания берётся из `p_import.company_id` и проверяется для поставщика и **каждой** позиции (позиция чужой компании, удалённая или не `material` → `skipped_gone`; чужого id не раскрываем — IDOR).
- Повтор: загрузка с этим `id` уже есть → вернуть сохранённый итог, ничего не писать (тот же `created_by`, иначе `42501`).
- Пределы: строк 1..1000; цена за упаковку 0..`100 000 000` ¢; фасовка `> 0` и `≤ 1 000 000`; тексты — пределы §5.2; иначе `P0001 price_import_bad` с номером строки.
- По каждой строке — «было» прислал телефон (то, что человек видел). Сервер сравнивает со своим: себестоимость или поставщик изменились после того, как телефон их прочитал → строка `skipped_changed`, позиция не трогается (другой человек успел поправить). Совпало → пишет поля §4.5, «было» — в строку загрузки.
- Цена за единицу и цена клиенту **считаются на сервере** из `pack_price_cents`, `pack_size`, ставки и наценки (тем же правилом, что движок: round half up), а не берутся с телефона. Значения телефона сверяются: расхождение → `skipped_changed` (тест T296 держит одинаковость).
- `set_config('app.cost_source', case source_kind when 'photo' then 'ai_scan' when 'pdf' then 'ai_scan' else 'import_file' end, true)` — журналы пишут правильный источник.
- Одна активная запись на позицию: блокировка строк позиций `for update` в порядке `id`.
- Итог: `{status, counts, rows:[{line, result}]}`.

**`public.undo_price_import(p_import uuid) returns jsonb`** — `security definer`.
- Кто: те же права; загрузку другого человека — только owner/admin.
- `undone` → тот же итог (повтор). Позже `undo_until` → `P0001 price_import_undo_expired`.
- По строке `applied`: позиция не менялась после загрузки (себестоимость, поставщик, артикул, фасовка равны «стало») → вернуть «было» всех полей, включая `is_placeholder_price` и наценку; иначе строка остаётся (`kept`), в итоге — «Оставлено как есть: N, их меняли после загрузки». `app.cost_source = 'import_file'`.
- Сметы не трогаются: у них снимок (PRD 04 §11 «Отмена импорта после того, как по новым ценам отправлены сметы»).

### 5.4. Стор и очередь (зона (а); общие файлы `store.tsx`, `types.ts`, `ops.ts`, `repo.ts` — отдельным PR с сообщением руководителю)
- Новые типы `PriceImport`, `PriceImportRow`; операции очереди `priceImport.apply` (вся загрузка одной операцией, ключ — `id` загрузки) и `priceImport.undo`.
- «Применить» меняет себестоимость позиций **на телефоне сразу** (правило 6) и ставит операцию. Ответ сервера: строки `skipped_*` → вернуть у себя «было» и показать «Обновлено 21 из 23. Две цены поменяли до вас — проверьте» (голос DS §4.4а).
- История загрузок (последние 30 дней) читается с сервера при сети; без сети — то, что сделано на этом телефоне.

После сохранения пометка снимется» и поле наценки, если она 0 %.
Нажатий: карточка (1) → ввод → «Сохранить» (2). Сейчас: 4 и больше.

### 6.4. Слот модуля S0e (реестр `modules/registry.ts` — общий файл, отдельным PR)
`ModuleDef.priceLineAttrs?(line: {name: string; unit?: string; sku?: string}) => Record<string, string> | null` — чистая функция модуля: свойства детали по тексту строки прайса. Ядро не знает слов модуля, модуль не знает о загрузке. Модуль выключен → слота нет, работают шаги 1, 2, 4 §4.4.

## 7. Экран «было → стало» (прототип `docs/prototypes/price-update.html`, снимки `docs/prototypes/img/53-*.png`)

Порядок сверху вниз (390): шапка «Обновить прайс» → карточка источника (поставщик · файл · дата прайса, «Изменить») → строка итога-фильтра (сегменты DS А1: «Изменились 18 · Похоже 4 · Без изменений 9 · Нет в каталоге 31»; по умолчанию «Изменились») → при тестовых позициях — баннер `warn` с полем наценки (§7.4) → список карточек строк → закреплённая панель (DS §8.9).

### 7.1. Карточка строки (ListCard, правило 12)
- Слева флажок (DS А4, зона 44, подпись «Применить строку {название}»).
- Заголовок — название **нашей** позиции; подзаголовок — строка прайса как в файле и артикул: «ABC #GUT5KW · 5" K-Style White 50' roll — $105.00».
- Значение справа: «$2.10 → $2.31 / ft» и чип процента: рост — `warn` со значком `arrowUp` и «+10.0%»; снижение — `ok` со значком `arrowDown` и «−4.2%»; ±25 % и больше — `bad` со значком `alert` и «Проверьте: +38.0%» (без галочки). Цвет — только статус, всегда значок и слово (правило 2).
- Вторая строка деталей: «Клиенту: $3.00 → $3.30 · наценка 30%» (видна тому, кто видит себестоимость, — все на этом экране).
- «Похоже» — чип `info` «Похоже — выберите» и строка «Это „Гаттер 5″ K белый“?»; нажатие → шторка с кандидатами (строки ListRow) и «Нет такой позиции».
- «Нужна фасовка» — чип `warn` «Укажите фасовку»; нажатие → поле «Сколько ft в упаковке?».
- Округление (> 1 %) — подпись `caption` «Цена за штуку округлена: $0.074 → $0.07».

### 7.2. Закреплённая панель
Строка итога — «Отмечено 18 из 22» (сумму закупок не показываем: у строк разные единицы, их сумма ничего не говорит). Кнопка `primary` «Применить 18» на всю ширину. Нажатие при 0 отмеченных — подсказка «Отметьте строки, которые хотите обновить» (кнопка всегда активна, DS §11 п.3). На 820 и 1280 — та же кнопка в правой колонке (DS §8.9).

### 7.3. Пороги
Галочка по умолчанию: «совпало» и изменение по модулю < 25 % — да; ≥ 25 %, «похоже» до выбора, смена поставщика, две строки на одну позицию — нет; «нужна фасовка», «нет цены» — нельзя отметить. Порог 25 % — константа ядра (вопрос основателю №2).

### 7.4. Тестовые цены (деньги)
Если среди отмеченных есть позиции с тестовой ценой и наценкой 0 %: баннер `warn` «У 12 позиций тестовая цена и наценка 0 %. Без наценки цена клиенту будет равна закупке» + поле «Наценка для них, %» (DS А6). Пусто — строки этих позиций несут пометку «Клиенту по закупке» (`warn`), применить можно (решает человек). Заданное значение уходит в `test_markup_bps` и применяется только к этим позициям. Значение по умолчанию — вопрос основателю №1.

### 7.5. Ширины и темы
390 — одна колонка карточек; 820 — карточки сеткой по две (`CardGrid`), панель — колонкой справа не помещается → кнопка в конце списка и закреплённая сверху строка итога; 1280 — строки `ListCard density="row"` с заголовком колонок «Позиция · Было · Стало · %», справа колонка источника и «Применить». Обе темы — токены «Наряда».

### 7.6. Пустые и особые состояния
- В файле не нашли цен: «В файле нет колонки с ценами. Выберите её вручную» + выбор колонки.
- Ничего не совпало: «Ни одна строка не совпала с вашим каталогом. Проверьте поставщика или выберите позиции для похожих строк».
- Тот же файл уже загружали (SHA-256 и поставщик): «Этот прайс уже загружен 03.11 в 14:20 (обновлено 23 цены). Открыть ту загрузку или загрузить снова» — снова = всё «без изменений».
- Без сети: разбор и проверка работают; «Применить» — «Нет сети. Цены обновлены у вас и отправятся, когда сеть вернётся» (DS §4.4а).

## 8. Деньги (правило 8: только движок; правило 15: движок и база)

Новые функции движка (`packages/estimating-engine/src/custom.ts`, общая часть, не gutter):
- `costPerUnit(packCents: number, packSize: string): {cents: number; roundedPct: string}` — `round_half_up(packCents / packSize)`; `roundedPct` — отклонение округления в процентах (для пометки > 1 %). Пример: $105.00 за 50 ft → 210 ¢; $18.50 за 250 → 7 ¢, отклонение 5.41 %.
- `netOfTax(grossCents: number, taxBps: number): number` — `round_half_up(gross / (1 + r))`. Пример: $11.03 при 10.25 % → $10.00.
- `pctChangeBps(before: number, after: number): number | null` — изменение в сотых процента; `before = 0` → `null` (на экране «новая цена»).
- Цена клиенту — существующая `catalogPrice(cost, tax, markup)`.

Общий набор примеров `apps/mobile/test/fixtures/priceImport.json` (как `matchKeys.json` у клиентов): упаковка, фасовка, налог, наценка → ожидаемые центы. Его читают тест движка и тест базы T296 — сервер и телефон считают одинаково.

## 10. Безопасность приёма файла (для security-check)

- **Файл не уходит на сервер** (CSV/XLSX): на сервер — только выбранные строки, имя файла (≤ 200, без управляющих и невидимых символов — `importCell`) и SHA-256 (`expo-crypto`, уже стоит).
- **Пределы на телефоне**: файл ≤ 10 МБ; CSV ≤ 5 000 строк и ≤ 100 колонок; XLSX: распакованный размер ≤ 50 МБ, записей в архиве ≤ 1 000, читаем только `xl/workbook.xml`, `xl/sharedStrings.xml`, `xl/worksheets/sheetN.xml` (остальное не распаковываем — защита от ZIP-бомбы), строк общих строк ≤ 100 000; разбор XML без DTD и внешних сущностей (встретили `<!DOCTYPE` — файл не читаем, «Сохраните прайс как CSV и выберите снова»); формулы не вычисляются, берётся сохранённое значение.
- **Текст ячеек — только данные**: не HTML, не команды; выводится как текст. Для фото/PDF (53-5) — только поля строгой схемы, текст из прайса в разговор с помощником не попадает без пометки (спека 43 §8.3).
- **Сервер не доверяет телефону**: пересчитывает центы сам (§5.3), проверяет компанию каждой позиции и поставщика, пределы чисел и текстов, права; повтор по `id`; блокировки.
- **Себестоимость**: таблицы загрузки читают только `can_view_costs ∧ is_staff`; мастер получает обновлённую цену продажи (`unit_price_cents`), но не закупку.
- **Экспорт** (обратно в CSV) в эту спеку не входит; когда будет — экранирование `= + - @` (PRD 04 §7.7.5).
