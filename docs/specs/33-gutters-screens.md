## П21.1 Брейншторм
**Где замеры живут на телефоне.**
| Вариант | Плюсы | Минусы |
|---|---|---|
| **А. Срез модуля в общем `DB`: `DB.moduleData[key]`** (ядро — `unknown`, тип знает модуль); чтение — `ModuleDef.load(read)` из `repo.ts`; правки — `moduleOp(…, apply)` | офлайн, кэш, «Отменить», полная перечитка после отправки очереди — всё уже есть у стора; ядро не знает ниши | весь замер всех замеров компании читается при каждой перечитке (как строки смет) |
| Б. Своё хранилище модуля (AsyncStorage) + своя очередь | не трогает общие файлы | вторая очередь, второй кэш, разъезд с «Не отправлено» и чисткой при выходе — дублирование ядра |
| В. Читать элементы по открытию холста (онлайн) | мало данных | офлайн на объекте не откроется — нарушает правило 6 |
**Выбор: А.** Объём — риск П21.5.

**«Модуль не активен» в очереди.** Сейчас отказ RLS (42501) — «попытка»: до 5 попыток, каждая останавливает очередь на тик (1,5 с). 200 элементов рисунка после конца пробного = 1000 отказов ≈ 25 мин, когда другие правки (лиды, оплаты) стоят. Сервер не различает «модуль выключен» и «нет права» (оба 42501 из RLS).
| Вариант | Плюсы | Минусы |
|---|---|---|
| **А. После отказа обработчик ядра перечитывает строку `company_modules`** (RLS даёт читать); модуль не активен → отказ с `hint = module_inactive`; очередь сразу снимает **все** ждущие `module.op` этого модуля, одна надпись «Пробный период закончился — замер не сохранён», перечитка | одна проверка на пачку, без новой функции базы; не трогает чужие правки | лишний запрос только после отказа |
| Б. Проверять активность до отправки по локальной компании | ноль запросов | локальная компания может быть старой — ложное «не активен» или наоборот |

## П21.2 Оспаривание

## П21.5 Риски
- Чтение всех элементов всех живых замеров компании при каждой перечитке. 100 замеров × 60 элементов ≈ 6 000 строк — как строки смет. Если вырастет — читать элементы по `updated_at` или по открытию (этап 4, вместе с К9).
- Офлайн-правки, ушедшие после конца пробного, теряются (О2), об этом говорит надпись.
- Мастер со старой привязкой лида перезаписывает замер (П19.5) — `measurement.save` шлёт привязку, только если она изменилась на телефоне (иначе берёт ту, что пришла с сервера).
