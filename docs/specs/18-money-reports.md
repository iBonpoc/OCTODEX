## 3. Сущности и поля (общие файлы — отдельным небольшим PR после сообщения руководителю и «Общим полям»)
- `Payment.receivedBy?: ID` (из `payments.received_by`) — «по людям» в «Собрано».
- `Payment.refundedCents` и показ возврата: сейчас repo кладёт `amount − refunded`, полностью возвращённая оплата видна как $0. В v1: возвращённые полностью не показываем в «Оплатах», частичный возврат — тег «Возврат $N». Возврат как действие — «Запуск» (только владелец и админ, 13 §4).
- `Invoice.status` (`draft` / `sent`; `void` уже отброшен) и `Invoice.subtotalCents`, `Invoice.estimateId` — нужны для «Источник лида → выручка» (PRD 14 §7). Черновик не долг: `dueDate` без срока сейчас подставляется из `created_at` — черновик выглядит просроченным. Исправить в repo (с тестом, падавшим до).
- `Invoice.remindedAt?` — последнее напоминание (S20). В базе — событие в ленте (`activities`) или колонка `invoices.last_reminded_at` — решает «Общие поля» (миграция, тест T45).
- Ничего gutter-специфичного.

## 4. Статусы и переходы
- Счёт: `status` хранится (draft/sent/void), `payment_status` ведёт триггер, **«просрочен» — вычисляемый признак** (одно правило: `listSigns.invoiceSigns`, день компании). Новых статусов нет. Карта §5 — поправить строку Invoice (руководитель).
- Оплата: приложение показывает `succeeded`, `partially_refunded` (с тегом); `refunded`, `failed`, `voided` — нет.

## 5. Отчёты v1 (движок, `packages/estimating-engine/src/reports.ts`, новые функции)
1. **«Кто должен»** — по клиентам: остаток = Σ `clientMoney`, просрочено и сроки 0–30 / 31–60 / 61–90 / 90+ дн от `dueDate`. Только `sent`.
2. **«Собрано за период»** — Cash collected (PRD 14 §7): Σ оплат − возвраты по способам и по людям (`receivedBy`), по дате оплаты в поясе компании.
3. **«Продажи»** — сметы отправлено / подписано (`approvedAt`) / сумма Estimate value (то же, что `estimateListAmount`, как цифры Главной), конверсия %.
4. **«Источник лида → выручка»** — Revenue (Σ subtotal по `sent` счетам) по источнику: работа → смета → лид → источник, иначе источник клиента. Подпись «Выручка, без прибыли» (прибыль по PRD 14 — «Запуск»).
- Период — как у Главной (`metrics.periodRange`) + «свой». Деньги на карточках без копеек, в отчёте — с копейками.
- Движок получает уже разобранные числа и ключи дней (без дат и поясов); группировка дня — в приложении через `isoDayKey`.

## 7. Экраны (390 / 820 / 1280, обе темы, только токены)
- **Счета** `/invoice`: фильтры-чипы «Не оплачен · Просрочен · N» (по умолчанию) · «Оплачен» · «Все»; группы «Просрочено» (bad) → «Ждёт оплаты» (info) с суммой группы; карточка `InvoiceListCard`; `?f=owed&customer=<id>` — долги одного клиента (со «Должен»). ### 11.3 Что показываем
`/reports/categories?p=<today|week|month|all>` (по умолчанию месяц), пятая карточка на `/reports`: «По направлениям», цифра — выручка за месяц, подпись «Направлений: N».
По каждому направлению — карточка (`ListCard`): название; цифра — выручка; детали:
- **Лиды**: получено в периоде · из них выиграно · конверсия %;
- **Сметы**: отправлено · подписано в периоде · сумма подписанных (`estimateListAmount`, как «Продажи»);
- **Работы**: работ со счётом, отправленным в периоде;
- **Средний чек** = выручка / работы (до цента, половина вверх).
Сверху итог «Выручка (выставлено, без налога)» и подсказка «Выручка, а не прибыль». Порядок: по выручке, затем по лидам, «Без направления» — последней. Направление без единой цифры в периоде не показывается. CSV (владелец): направление, лиды, выиграно, %, сметы отправлено, подписано, сумма подписанных, работы, выручка, средний чек.
