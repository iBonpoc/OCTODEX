# 04. Клиенты и объекты — спецификация OCTODEX

> Черновик v1, 04.11.2026. Шаг хребта «Клиенты и объекты» (`docs/15-story-map.md` §6: после «Лиды» и «Осмотр и План», до «Сметы»).
> Источники: `docs/03-prd/03-customers-properties.md` (PRD 03), `docs/04-domain-model.md`, код сборки 39 (`app/client/*`, `(tabs)/clients.tsx`), база (`customers`, `contacts`, `properties`, `tasks`, `activities`, `notes`), решения основателя 03.11 и 04.11.
> Ядро не знает ниши: поля «тип крыши», «fire zone», «этажность» есть в базе, но показываются только модулями (Gutters, Roofing). В ядре — адрес, доступ, люди, история, документы.

## 1. Стыки

| Стык | Что приходит / уходит | Как у клиента |
|---|---|---|
| **S3** лид → потенциальный клиент | Из лида при записи на оценку или первой смете: люди (с телефонами и email), адрес → объект, источник, метки лида, заметки | Создаётся `Customer(status=prospect)` + люди + `Property`. Повтор не создаёт дубля (одна функция `lead_to_client`, владелец — шаг «Лиды»). Если найден существующий клиент по телефону/email — лид привязывается к нему, новый не создаётся |
| **S5** клиент → смета | «Новая смета» из клиента или объекта | Смета получает `customerId` + `propertyId` (объект выбирается явно, по умолчанию последний) |
| **S8 / S8a** подпись или ручная победа | лид `won` | Клиент `prospect → active` |
| Клиент → работа, визит | «Записать», «Запланировать» | Работа на конкретном объекте |
| Клиент → счёт, оплата | счета работ | Баланс и «Оплатил всего» (LTV) на карточке |
| Клиент → новый лид | повторная заявка того же человека | Новый лид привязан к клиенту, бейдж «Уже клиент» (шаг «Лиды») |
| Всё → история клиента | события лида, смет, работ, визитов, счетов, оплат, заметки, задачи | Лента «История» в карточке клиента и объекта |

## 2. Сравнение и решения

| Тема | У нас сейчас | Jobber / HCP / ServiceTitan | Решение |
|---|---|---|---|
| Клиент: человек или компания | только имя | все три: person / company | `kind` (уже в базе): человек или компания (управляющая компания, HOA, бизнес); у компании — имя компании + контактные люди |
| Люди у клиента | один телефон и email | несколько контактов с ролями | Блок «Контакты», как у лида: люди (основной, супруг(а), арендатор, управляющий, бухгалтер…), у каждого несколько телефонов и email, звёздочка = основной, язык EN/ES |
| Объекты | список адресов | Jobber: несколько properties; ST: locations | Несколько объектов **только внутри клиента** (и лида): вкладка «Объекты» + карточка объекта. Отдельного раздела «Объекты» в меню нет (решение основателя 04.11) |
| Метки | нет | теги в Jobber/HCP | Список меток компании (как источники: + новая, правка, скрыть); нейтральные плашки; на клиенте; лид клиента показывает метки клиента |
| Статус клиента | prospect / active | lead / active / archived | Хранится: `prospect`, `active`, `archived`, `do_not_service`. Показывается вычисляемый ярлык (§4) |
| История | только списки | лента активности | Одна лента клиента: все события его лидов, смет, работ, визитов, счетов, оплат, заметок, задач |
| Деньги на карточке | баланс | баланс + lifetime value | «Должен» (открытые счета) и «Оплатил всего» (оплаты − возвраты); только офис/директор |
| Задачи | у лида | у клиента | Общая сущность `Task` (уже есть), у клиента и объекта своя вкладка |
| Файлы | нет | фото, документы | Вкладка «Файлы»: фото с визитов, файлы от клиента, PDF смет и счетов |
| Доступ на объект | нет | gate code, заметки | Заметки доступа (собака, калитка, парковка) и код ворот; мастер видит код только в день визита и накануне |
| Дубли | предупреждение в лиде | слияние | MVP: предупреждение при создании; «Слить» — этап «Запуск» |
| Импорт | нет | CSV | CSV с предпросмотром и отменой — отдельная волна (C3) |

Не делаем в ядре: тип крыши, fire zone, этажность на экранах ядра (это модули); «оценку» клиента; цветные метки (цвет только для статусов).

## 3. Сущности и поля

### 3.1 `Customer` (✚ — новое в приложении; в базе почти всё есть)
| Группа | Поля |
|---|---|
| Кто | `kind` (person/business), `name` (display_name), ✚`companyName` |
| Люди | ✚`people[]` → `Contact` (см. 3.2); один основной |
| Адрес для счетов | ✚`billingAddress` (если отличается от объекта) |
| Источник | `sourceId` (первый источник, ставится при S3; меняет только директор) |
| Метки | ✚`tagIds[]` |
| Статус | `status`: prospect / active / archived / do_not_service (+ причина) |
| Деньги (вычисляется) | ✚`balanceCents` (открытые счета), ✚`lifetimeCents` (оплаты − возвраты) |
| Служебное | ✚`number` CLT-0001 (нумерация компании), `createdAt`, `lastActivityAt` |

### 3.2 `Contact` (человек) — та же форма, что у лида (шаг «Лиды» использует её же)
`name`, `role` (main / spouse / tenant / property_manager / assistant / accountant / other), `language` (en/es), `preferredContact` (call/sms/email), ✚`phones[]` {`number`, `label` mobile/home/work/other, `isPrimary`}, ✚`emails[]` {`address`, `isPrimary`}, `smsConsent` (позже, для автоматических SMS), `isActive`.
В базе: `contacts` (есть) + ✚`contact_phones`, ✚`contact_emails`.

### 3.3 `Property` (объект)
`label` (Дом, Сдаётся, Офис…), `kind` (single_family / multi_family / commercial / hoa_common), адрес (`line1`, ✚`unit`, `city`, `state`, `zip`), ✚`accessNotes`, ✚`gateCode` (отдельно, с ограниченным доступом), ✚`contacts` объекта (арендатор, управляющий — ссылки на `Contact`), `attributes` (поля модулей; ядро не читает).

### 3.4 Остальное
| Сущность | Что |
|---|---|
| ✚`Tag` | `id`, `name`, `isActive`, `position` — список компании |
| `Task` | уже есть; `subjectType` = customer / property добавляется |
| `Note` | уже есть (команда / только я, закрепление) |
| `File` | фото и документы; ✚`customerId`, `propertyId` |
| `Activity` | уже есть; лента собирает события из всех таблиц |

Не заводим: отдельную «историю клиента» как таблицу — лента собирается из событий; «оценку» клиента.

## 4. Статусы

Хранится (как в `docs/15-story-map.md` §5): `prospect`, `active`, `archived`, `do_not_service`.

| Переход | Как |
|---|---|
| — → `prospect` | авто S3 (лид → клиент при оценке или смете) |
| `prospect` → `active` | авто S8 (подпись / депозит), S8a (ручная победа), или первая оплата |
| ручное создание клиента | сразу `active` (сборка 28) |
| `active` → `archived` | вручную директор; нельзя при открытом балансе («должен $850») |
| любой → `do_not_service` | вручную директор, обязательная причина; новые лиды с тем же телефоном получают красный бейдж |

**Ярлык в списке (вычисляется, не хранится):**
| Ярлык | Когда | Цвет (токены статусов) |
|---|---|---|
| Новый | `prospect`, есть открытый лид / смета не подписана | info |
| Отказался | `prospect`, все его лиды `lost` | neutral |
| Мы отказались | `prospect`, все его лиды `declined` | neutral |
| В работе | `active` + есть открытая работа, визит или смета | info |
| Должен | открытый баланс > 0 | warn (bad, если есть просроченный счёт) |
| Клиент | `active`, ничего открытого | ok |
| Архив / Не обслуживаем | по статусу | neutral / bad |

## 5. Как приходит / уходит

Приходит: из лида (S3), вручную «+ Клиент» (сборка 28), импорт CSV (волна C3).
Уходит: в смету, работу, визит, счёт (через кнопки карточки); в новый лид (повторная заявка); в архив.

## 7. Экраны

### 7.1 Список «Клиенты»
- Каждый клиент — карточка: имя (или компания), ярлык статуса, метки, основной телефон, первый объект, «Должен $…» если есть.
- Поиск: имя, любой телефон любого человека, email, адрес любого объекта, номер CLT-/LEA-/EST-/INV-/JOB-/RCT-.
- Фильтры: ярлык статуса, метки (несколько), источник, «Должен». Сортировка: недавние / имя / оплатил всего.
- «+ Клиент» (как сейчас) + предупреждение о дубле по телефону/email.

### 7.2 Карточка клиента
Шапка (как у лида): `‹ Клиенты`, имя, номер CLT-0012 · источник · с какого числа, ярлык статуса (нажатием — шторка статуса: в архив, не обслуживаем), метки (нажать — выбор), кнопки связи иконками (позвонить, SMS, email, маршрут к основному объекту), «⋯» (изменить, слить дубль — позже, архив).
Для директора/офиса: «Должен» и «Оплатил всего».

Вкладки (строка вкладок прилипает при прокрутке; меняется только содержимое под ней):
| Вкладка | Содержимое | Пустое состояние |
|---|---|---|
| **Обзор** | закреплённые заметки, ближайшее (визит, задача, неоплаченный счёт), контакты (люди с телефонами), объекты кратко, последние 3 события | — |
| **Объекты** | карточка на каждый объект: адрес, ярлык, открытые сметы и работы, следующий визит; «+ Объект» | «Объектов нет — + Объект» |
| **История** | лента: лиды, сметы (отправлена / открыл / подписал), работы, визиты, счета, оплаты, заметки, задачи, смены статуса; фильтр «Всё / Общение / Документы / Деньги» | «Пока ничего не было» |
| **Документы** | сметы, счета, квитанции карточками со статусами | «Смет и счетов нет — + Смета» |
| **Задачи** | открытые и выполненные; «Напомнить» с быстрыми сроками | «Задач нет — Напомнить» |
| **Файлы** | фото с визитов и от клиента, PDF; «+ Фото / файл» (камера, галерея, файлы) | «Файлов нет — + Фото / файл» |

Все правки — шторками iOS (смахивание, вопрос «Сохранить изменения?»).

### 7.3 Объекты клиента и карточка объекта
- Где: только внутри клиента (вкладка «Объекты») и лида. Отдельного раздела в меню нет. Найти объект по адресу — общий поиск клиентов (ищет по адресам всех объектов).
- Список: адрес, клиент, ярлык, открытые сметы/работы, следующий визит; поиск по адресу.
- Карточка объекта: `‹ <Клиент>`, адрес, ярлык, тип, кнопки маршрут/позвонить контакту объекта; «Сейчас на объекте» (все открытые сметы и работы); доступ (заметки, код ворот — по правам); люди объекта (арендатор, управляющий); вкладки История · Документы · Файлы · Задачи.

### 7.4 Ширины и темы
390: одна колонка, вкладки сверху. 820: шапка + вкладки, объекты в 2 колонки. 1280: слева шапка и контакты, справа вкладки. Обе темы, только токены «Наряда».

## 8. Права, офлайн, уведомления

| Кто | Видит |
|---|---|
| Директор | всё |
| Диспетчер / офис | всё, кроме изменения источника клиента |
| Мастер | только клиентов и объекты своих визитов (сегодня, будущие, последние 14 дней по календарю компании; не считаются отменённые визиты, неявки, визиты отменённой или закрытой работы; визит без даты считается по последнему дню гибкой недели, а без неё — по дню создания); заметки — свои и командные заметки того, что он видит (свой лид, объект, работа, клиент, смета); без денег («Должен», «Оплатил всего»), без источника; код ворот — только в день визита и накануне |
| Субподрядчик | только адрес, заметки доступа и контакт объекта по своему наряду |

Код ворот и пароли — только в поле «Доступ» объекта (мастер видит его в день визита и накануне). Заметки объекта мастер видит при любом визите в окне, поэтому в форме заметки объекта, работы и клиента стоит подсказка: «Код ворот и пароли пишите в поле „Доступ“ — мастер увидит их только в день визита». Отдельного типа заметки нет (решение руководителя 05.11).

Офлайн: просмотр, поиск, правка клиента/людей/объектов/меток, заметки, задачи — в очередь. Слияние, архив с проверкой баланса, импорт — только онлайн.
Уведомления: срок задачи → пуш исполнителю и в «Сегодня».

## 10. Волны и вопросы основателю

| Волна | Что |
|---|---|
| **C1** | Люди у клиента (несколько телефонов/email), метки, ярлык статуса, номер CLT-, новая шапка, вкладки Обзор · История · Документы · Задачи · Файлы с пустыми состояниями, «Должен / Оплатил всего», права мастера |
| **C2** | Вкладка «Объекты» у клиента и лида, карточка объекта, доступ и код ворот, люди объекта, «Сейчас на объекте». ✅ у клиента (e2e 27, T20); вкладки объекта «История · Документы · Файлы · Задачи» — следующим шагом; у лида объект один (адрес) и переходит клиенту при S3 |

**C2 — проверка безопасности (#62).** Сделано: мастер не меняет время, работу, лид и удаление визита (`app.tg_visit_tech_guard`). Отменённая или закрытая работа, а также завершённый визит и «клиент не пришёл» кода не открывают. В приложении код ворот хранится только в памяти и на телефон не записывается. Правило в приложении берёт часовой пояс компании. Роль sales входит в офис (`app.is_staff`) и видит код, как диспетчер.
**Потом:** проверять триггером, что `contact_ids` ссылаются на людей этого клиента; проверять, что `companies.timezone` — настоящий часовой пояс.
| **C3** | Импорт клиентов CSV (предпросмотр, дубли, отмена), слияние дублей, архив / не обслуживаем |

Ответы основателя (04.11.2026):
1. Отдельного меню «Объекты» нет — объекты живут только внутри клиента и лида.
2. Метки по умолчанию: VIP, Постоянный, Избранный, «Не звонить после 18:00» — да.
3. Код ворот мастеру — только в день визита и накануне (по умолчанию, основатель не возражал).
4. «Принёс всего» → **«Оплатил всего»**; видят директор и офис, мастер — нет.
5. Номер клиента — да, 3 буквы: **CLT-0001** (как LEA, EST, INV, RCT, JOB). Миграция пересоздаёт ограничение `doc_type` со всеми значениями (estimate, job, invoice, receipt, purchase_order, change_order, lead, customer) — общий файл, согласуется с чатом лидов.

## 12. Волна 4b «Не обслуживаем» и импорт CSV (06.11.2026, «Лиды и клиенты» №6) — этап 0 принят руководителем 06.11

Источник: §4 (переход в `do_not_service`), §10 (C3), `docs/specs/13-app-structure.md` §3.3, §3.16; `docs/specs/15-flows.md` §1.13; PRD CUST-US-13; `docs/market/others.md` п. 89 («клиенту нельзя будет назначить работу или смету»); `docs/08-security.md` (отзыв ссылки при `do_not_service`). Код — после влития #169 и 4a-2.

### 12.1 Что нужно подрядчику
Пометил клиента «Не обслуживаем» — и больше случайно не поставит ему работу, смету или выезд: ни с телефона, ни из очереди без сети, ни со второго телефона. Новый лид с тем же телефоном сразу видно — красная метка «Не обслуживаем».

### 12.2 Варианты и решения
| Что | Варианты | Решение (рекомендация) |
|---|---|---|
| Где запрет | только экран · только база · оба | **оба**: экран прячет кнопки (`canServe`), база отказывает триггером (очередь без сети, старая сборка, второй телефон) |
| Что запрещает база | insert в jobs, estimates, visits · + смена `customer_id` на такого клиента · + отправка старого черновика сметы | **insert + update `customer_id`** (jobs, estimates); visits — insert и смена job/lead/property; клиента выезда берём job → lead → объект. Отправку черновика (`draft → sent`) — **тоже запрещаем** (решено 06.11, тест) |
| Открытое | отменять · оставить | **оставить** как есть (работы, выезды, счета, оплаты идут; квитанции и письма по открытому — уходят, CUST-US-13) |
