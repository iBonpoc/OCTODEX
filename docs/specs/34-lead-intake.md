## 3. Устройство
```
браузер /f/<token>  ──POST──►  Edge Function lead-intake (verify_jwt=off)
Zapier ──POST Bearer key──►      │ размер ≤ 16 КБ, поля и длины, honeypot, время заполнения ≥ 3 с,
                                 │ Turnstile (форма), ключ sha256 (вебхук), лимиты
                                 ▼ service_role
                     app.intake_lead(endpoint, event_key, ip_hash, payload)  security definer
                       1 IntakeEvent (повтор event_key = прежний результат)
                       2 нормализация (телефон E.164, email lower, ZIP, язык en/es/ru)
                       3 дубль: открытый лид ≤30 дн по телефону/email → событие в ленту старого, без нового лида
                         совпал клиент → новый лид с customer_id (отметка «уже клиент»)
                       4 источник = источник точки приёма; цена: только от провайдера (целые центы ≤ $500), иначе нет
                       5 назначение: companies.lead_default_assignee_id (если участник в работе) → владелец
                       6 insert leads (status new) → t90 пуш, «Требует внимания»
```
- **Таблицы** (миграция `20261108210000`). `intake_endpoints` (kind form|webhook, `token_hash` для поиска, `public_token` только у формы, `token_hint`, source_id, service_category_id?, enabled, captcha_required, sms_consent_enabled, daily_limit, rotated_at). `intake_events` (endpoint_id, event_key, payload_hash, ip_hash, status accepted|merged|held|rejected|invalid, reason, lead_id, payload, sms_consent, consent_text_version, decided_by/at). Повтор события не пишется отдельной строкой — возвращается прежний статус. Уникальность (endpoint_id, event_key). `leads` + `intake_event_id`, `provider`, `provider_ref` (уникально в компании, где не null), `parse_status`.
- **Права.** anon — ничего в базе (только Edge Function). `app.intake_lead` — только service_role (правило 18, T52). Точки приёма создаёт/выключает/меняет ключ owner/admin через RPC; читать журнал — owner/admin/office. Ключ вебхука показывается один раз, хранится хэшем.
- **Лимиты** (в базе, под замком компании): с одного ip_hash 5/час на компанию → `held`; на точку приёма `daily_limit`/сутки (по умолчанию 100) → `held`; больше 10×лимита за сутки → `rejected/flood` без полей. Форма без IP → `rejected/no_ip`. Капча обязательна только при `captcha_required`. IP — только HMAC-хэш с секретом функции, сырой IP не храним.
- **Чужая компания.** Компания определяется только токеном точки приёма; из тела запроса `company_id` не читается. Токен формы публичен по смыслу (он на сайте) — защищает не тайна, а лимиты и капча; «Сменить ссылку» отключает старый. Ключ вебхука — тайна; в браузерную форму не попадает.
- **Содержимое — только данные** (14 §4 п.6): текст обрезается, хранится как текст, в приложении — `<Text>`, в письмах/PDF экранируется. Ссылки в сообщении не кликабельны.
- **Язык клиента.** Страница: `?lang=` → язык браузера → `Company.docLanguage`; переключатель EN/ES/RU. Выбранный язык → `leads.language` → `docLanguageFor` (дальше всё клиенту на нём).
- **Согласие на SMS (TCPA).** Необязательная, не отмеченная галочка «Согласен получать SMS от <Компания> по моей заявке. Отказ — STOP» отдельной строкой; запись {at, source: web_form, версия текста, ip_hash}. Автоматически ничего не шлём (01 §4.1); запись — задел под A2P 10DLC (там нужен скрин формы согласия).
- **Подтверждение клиенту.** На странице, на языке клиента: «Заявка отправлена, <Компания> свяжется с вами». Письмо — после П1b (домен).
- **Офлайн / старые версии.** Лид создаёт сервер, телефон его просто получает. Новые поля приложение старой версии не знает и не пишет; `lead.save` новые колонки не трогает (правило 16, шаг 1).

## 3а. Правки после security-check (08.11, 5 блокеров учтены)
1. **event_key** — для формы строит сервер: sha256(endpoint ‖ тело ‖ токен Turnstile); у вебхука — из тела (обязателен, иначе хэш тела) + `payload_hash`. Тот же ключ с другим телом → `invalid`. Вставка `on conflict do nothing`, строки не обновляются. Наружу всегда только `{ok}` — без id и статуса.
2. **Лимит компании не теряет заявки**: сверх лимита — статус `held` (payload сохранён, «Принять» в журнале), лимит считается по подозрительным/без капчи.
3. **IP** — только из одного доверенного заголовка шлюза (какой именно — проверить на Supabase перед PR 2), не первый XFF; нет заголовка → `rejected`. Тест «подделанный XFF не меняет ip_hash».
4. **Iframe**: встраивание разрешено только `/f/*`, остальным путям `frame-ancestors 'none'`. Если хостинг Expo не даёт заголовки по путям — форма на отдельном адресе без сессии (вопрос В4).
5. **Компанию находит база**: `app.intake_lead` получает хэш токена/ключа, сама ищет точку и проверяет `enabled` в той же транзакции; `set search_path=''`, revoke от public/anon/authenticated, execute только service_role.
6. Составные FK `(company_id, source_id)`, `(company_id, service_category_id)` в `intake_endpoints`; поиск клиента и назначенного только в своей компании (сторожа t06/t16 при `auth.uid() is null` пропускают) — T119.
7. Лимиты под `pg_advisory_xact_lock(company)`; T116 — параллельные вставки.
8. Дубль: ≤3 события `intake_repeat` на лид в сутки, контакт/цена/статус не меняются, пометка «не подтверждено».
9. Одинаковый ответ и минимальная задержка ~300 мс для accepted/merged/held.
10. GET той же функции отдаёт странице только имя, логотип, языки; неизвестный и выключенный токен — одинаковый ответ; лимит по IP.
11. Turnstile — siteverify (success, hostname, action, remoteip). Ключ вебхука ≥256 бит с префиксом, только в `Authorization`.
12. Хранение: отклонённые 30 дн, payload принятых 90 дн, согласие — бессрочно; `intake_events` в удаление аккаунта и выгрузку CCPA; в Privacy — Turnstile/Cloudflare.
13. Цена провайдера — целые центы, ≤ $500, иначе 0 и `parse_status=needs_review`.
14. CORS: POST формы только с адреса страницы; вебхук без CORS; ошибки `{ok:false, code}`; в логах нет IP и payload.
15. Триггер t85 знает только en/es — `ru` добавить (общая миграция). «Уже клиент»: новые телефон/email из заявки — в описание лида и событие, не в карточку клиента.
16. Текст заявки — только данные и для ИИ; CSV-выгрузка экранирует формулы; тест «имя клиента не попадает в пуш».
17. Индекс `provider_ref` — пометка rule16 или concurrently отдельным файлом; `created_by` null, в журнале actor `system`.

## 3в. PR 2: функция и страница (как сделано)
- `supabase/functions/lead-intake` (verify_jwt = false). GET `?t=` — что показать странице; POST от страницы — только с `https://octodex(--…)?.expo.app`, ответ всегда `{ok:true}` не раньше чем через 300 мс; POST с `Authorization: Bearer gxk_…` — вебхук: без CORS, из браузера (с Origin) — 403. Обёртки в базе: `public.intake_submit`, `public.intake_form` (только service_role, T120).
- Ключ события строит функция: `f:` + sha256(хэш полей | nonce страницы). Повтор той же отправки (тот же nonce) — одна заявка; поле `event_key` из тела не читается. Вебхук: `e:<event_id>` или `h:<хэш полей>`.
- IP: `cf-connecting-ip`, иначе последний адрес `x-forwarded-for` (первый подделывается); хранится только HMAC с секретом `INTAKE_IP_SECRET`. Без секрета IP нет — база отклоняет заявки формы (`no_ip`): секрет нужен до включения формы.
- Бот: скрытое поле заполнено, или от открытия до отправки < 3 с, или нет времени открытия. Капча: siteverify (success, hostname, action = lead); виджет на странице — после ответа основателя В3 (сейчас переключатель выкл, капча `none`).
- Страница `/f/<token>`: без меню приложения (`isAppPath`, `NO_TAB_BAR`), язык `?lang=` → браузер → компании, чипы EN/ES/RU; текст согласия на SMS виден рядом с переключателем (выкл по умолчанию) и только если компания включила; уведомление «Заявку получает <компания>, обрабатывает OCTODEX». e2e 178.
- **Встраивание (iframe) не делаем**: сайт отдаётся как `web.output: single`, заголовки по путям (`pageHeaders`) там не работают, а встраивать всё приложение — clickjacking. Код для сайта (PR 3) — ссылка/кнопка в новой вкладке и QR. Iframe — на отдельном адресе формы без сессии, со слова основателя.
- Секреты функции (заводит основатель, не в чат): `INTAKE_IP_SECRET`, `TURNSTILE_SECRET`. Без `INTAKE_IP_SECRET` функция отвечает странице «busy» (503) и пишет строку в лог, а не «отправлено»; `GET ?status=1` отдаёт `{ipSecret, captchaSecret}` — экран «Приём заявок» (PR 3) показывает понятную строку и не даёт включить форму.
- После ревью: время заполнения меряет сама страница (`filled_ms`, монотонные часы устройства) — неверное время телефона не делает человека ботом; IPv6 считается по сети /64; капча — только с hostname наших адресов и action = lead; ответ странице не раньше 800 мс; `event_id` вебхука ≤ 198 знаков; referrer — без query; форма с обязательной капчей показывается «недоступной», пока нет виджета (В3); двойное нажатие — одна отправка.
- Принятые риски: Origin вне браузера подделывается — защищают лимиты базы и капча, не регулярка; тело читается целиком до проверки размера в байтах (Supabase сам режет большие тела). После выкладки — один раз проверить в логах функции, что приходит `cf-connecting-ip` (иначе все посетители с одним IP прокси уйдут в `held` по лимиту IP).
