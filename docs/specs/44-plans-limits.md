## 3. Сущности и поля

**`public.company_plans`** (одна строка на компанию):

| Поле | Тип | Смысл |
|---|---|---|
| `company_id` | uuid PK → companies | |
| `plan_key` | text check in (`start`,`solo`,`crew`,`company`) | во время пробного — `crew` |
| `status` | text check in (`trialing`,`active`,`past_due`,`read_only`) | §4 |
| `trial_ends_at` | timestamptz null | ставится один раз |
| `trial_extended` | boolean default false | «+7 дней» (если срок 7) |
| `paid_until` | timestamptz null | конец оплаченного периода |
| `grace_until` | timestamptz null | конец льготы |
| `source` | text check in (`web`,`apple`,`manual`) null | `manual` — админ-панель, бета, старые компании |
| `external_id` | text null, unique | Stripe subscription id или Apple `originalTransactionId` |
| `conflict` | boolean default false | двойная подписка (§5) |
| `updated_at`, `row_version` | | |

**`users.trial_used_at timestamptz`** — ставит сервер при первом пробном. Пробный — один на человека; вторая своя компания (S32 спеки 42) пробного не получает. Обход через удаление учётной записи (строка `users` обезличивается, та же почта — новая строка) **не закрываем** — рекомендация (в) исследования §8, вопрос 11.

**`app.plan_limits(plan_key)`** → `{members, modules, ai_budget_cents_month, ai_cents_day_per_member, storage_bytes}`; пробный — запас ИИ 150 центов. Значения — вопрос 2. ИИ — учёт ходов и лимиты с резервом **спеки 43** (§8.5, §11.1); эта спека даёт только потолки; `ai_usage` — вид над учётом ходов.

**Люди тарифа** — активные члены любой роли, **включая субподрядчика**: по README §4.3 п.5 и спеке 42 субподрядчик — роль внутри компании-заказчика, иначе Solo обходится ролью (вопрос 12). Отключённые и удалённые не считаются.

**Модуль, входящий в тариф** — первый включённый владельцем; смена — раз в период.

**Не заводим:** счётчик документов, плату за место, пакеты ИИ (после беты), отдельный пробный модуля (срок модуля = срок компании).

**Существующие компании (замечание аудита №2, п.2).** Миграция заполняет `company_plans` для **всех** существующих компаний: `status = active`, `source = manual`, `paid_until = null` («бессрочно до решения оператора»), и `app.company_writable` считает `manual` без `paid_until` записываемой. Триггер `after insert on companies` создаёт строку для новых. Бета-компании переводятся на тариф вручную из админ-панели.

## 4. Статусы и переходы (внести в §5 карты)

| Из | В | Кто / когда |
|---|---|---|
| — | `trialing` или `read_only` | триггер при создании компании (S90) |
| `trialing` | `trialing` (+7) | владелец, один раз, если срок 7 |
| `trialing` | `active` | вебхук оплаты; остаток пробного **не** добавляется, `paid_until` — от Stripe / Apple |
| `trialing` | `read_only` | `trial_ends_at` прошёл |
| `active` | `past_due` | оплата периода не прошла; возврат Apple (`REFUND`) или отзыв (`REVOKE`) → `grace_until = now() + 7 дней` |
| `past_due` | `active` | оплата прошла |
| `past_due` | `read_only` | `grace_until` прошёл |
| `read_only` | `active` | оплата |
| `active` | `active` (другой `plan_key`) | смена тарифа; понижение — с конца периода; при людях сверх предела — отказ с причиной |
| `read_only` 12 месяцев | закрытие компании | письмо и сообщение → 30 дней на выгрузку → удаление **по схеме #1176** (решение 12.11; `app.retention_years() = 7` меняет #1176); срок 12 — вопрос 6 |
| любой | удаление | владелец, спека 38 (Apple 5.1.1(v)) |

**`app.company_writable(company_id)`** = `trialing` с `trial_ends_at > now()`, или `active` (с `paid_until > now()` или `source = manual` без `paid_until`), или `past_due` с `grace_until > now()`. Вызывается в RLS на `insert/update/delete` таблиц компании. **Не вызывается** в функциях S93: страница `/p/`, вебхуки Stripe, `refund_record` и `stripe-refund`, запись оплаты по существующему счёту, `lead-intake`, выгрузка, удаление.

**Правило 16 — два шага.** Шаг 1 (одна миграция): таблица, триггер, заполнение существующих, функции; `company_writable` **ещё не** в RLS. Приложение с экраном «Тариф» и общим отказом «не сохранено: срок оплаты вышел» выходит в магазин. Шаг 2 (отдельный PR, после того как старые версии не пишут — механизма минимальной версии сейчас **нет** [код: поиска `min_app_version` нет], завести его — задача этого шага или общая): `company_writable` подключается к RLS. До шага 2 неоплаченных компаний нет — продажи не открыты. Изменение `app.module_active()` (S96) — пометка `-- rule16: step 1 (module_active: tariff module, old paid_until still read)`.

## 5. Как приходит / как уходит

- **Сайт:** Stripe Checkout + Billing; вебхуки `customer.subscription.*`, `invoice.payment_failed` → `billing-webhook` (Edge, подпись Stripe проверяется). **Идемпотентность:** таблица обработанных `event.id`, повтор — без изменений.
- **Apple:** StoreKit 2; группа подписок Start/Solo/Crew/Company × месяц/год, **без** пробного периода Apple; App Store Server Notifications V2 → `apple-notifications`, подпись JWS проверяется; `appAccountToken` = id компании; идемпотентность по `notificationUUID`. Новая зависимость — правило 17, `docs/ai/CHECKS.md` §4.
- **Двойная подписка и гонка:** оформление разрешено, только если у компании нет действующей подписки другого источника — проверка на сервере под `select … for update` строки `company_plans`; при гонке второе событие ставит `conflict = true`: веб-подписка отменяется с возвратом через Stripe автоматически; если вторая — Apple, владелец получает сообщение «отмените в Apple», случай виден в админ-панели.
- **Кнопка «Оформить на сайте»** — только в витрине США (3.1.1(a)).
- **Уведомления владельцу:** за 2 дня до конца пробного, в последний день, при неудаче оплаты, при переходе в `read_only`, при `conflict` — пуш (`send-push` есть) + баннер; письмо — когда появится отправитель писем (сейчас `email_outbox` без отправителя), **своим видом вне** предела 20 писем в сутки (он для писем клиентам). Язык — **язык интерфейса владельца** (это не клиент; правило 7 о языке клиента сюда не относится); тексты — ключи RU/EN/ES.
- **Выгрузка** (CSV + PDF) — направление Д; **условие** включения шага 2 правила 16.

## 7. Экраны

«Тариф» (Настройки, владелец; остальным — строка статуса):
1. Состояние: тариф, статус значком + словом (правило 2: `info` — пробный «осталось N дней», `ok` — оплачено до, `warn` — оплата не прошла, `bad` — только чтение).
2. Использование: люди X из N, ИИ — полоса в %, память X из N GB.
3. Тарифы карточками `ListCard` (правило 12), одна главная кнопка `acc`.
4. Где управлять подпиской (Apple или сайт).
5. «Выгрузить данные» — всегда.

Баннер на главной: последние 2 дня пробного, `past_due`, `read_only`. В `read_only` кнопки создания и правки неактивны с подписью «Только чтение — оформите тариф»; кнопки S93 (запись оплаты, возврат) активны. Новый вид (баннер срока, полосы использования) — сначала в `DESIGN-SYSTEM.md` §2.3 и витрину. 390 / 820 / 1280 × 2 темы; экран — в `SCREENS` спеки `08-layouts`.

## 8. Права, офлайн, уведомления

- **Правило 18:** `revoke all … from public, anon, authenticated` на `company_plans` и всех новых функциях; затем: `grant select on company_plans to authenticated` (политика `app.is_member`); `grant execute on app.company_writable, app.plan_limits to authenticated` (их зовут RLS и приложение); функции вебхуков, триггер заполнения, смена тарифа, `conflict` — только `service_role`; «+7 дней» — `security definer`, проверка владельца. Тест T52 (никто не исполняет по умолчанию) — дополнить.
- Тариф видят все члены, меняет и платит владелец.
- **Офлайн (правило 6):** изменения без сети после срока сервер отклонит; очередь показывает «не сохранено: срок оплаты вышел» с кнопкой тарифа, на телефоне ничего не теряется. Сейчас такой отказ есть только у модуля (`modules/registry.ts:208` `rejectedKey`); общий механизм затрагивает **общие файлы** `src/cloud/ops.ts`, `src/data/store.tsx` — отдельным небольшим PR после сообщения руководителю (CLAUDE.md «Общие файлы»).
- Удаление учётной записи с подпиской Apple — предупреждение «отмените подписку в Apple» (5.1.1(v)).
