## 3. Сущности и поля

**`public.company_plans`** (одна строка на компанию):

| Поле | Тип | Смысл |
|---|---|---|
| `company_id` | uuid PK → companies | |
| `plan_key` | text check in (`start`,`solo`,`crew`,`company`) | во время пробного — `crew` |
| `status` | text check in (`trialing`,`active`,`past_due`,`read_only`) | §8 |
| `trial_ends_at` | timestamptz null | ставится один раз: `now() + 14 дней` |
| `paid_until` | timestamptz null | конец оплаченного периода |
| `grace_until` | timestamptz null | конец льготы |
| `read_only_since` | timestamptz null | момент перехода в `read_only`; от него считается 1 день ссылок (§7.2); очищается при оплате |
| `source` | text check in (`web`,`apple`,`manual`) null | `manual` — админ-панель, бета, старые компании |
| `external_id` | text null, unique | Stripe subscription id или Apple `originalTransactionId` |
| `conflict` | boolean default false | двойная подписка (§9) |
| `updated_at`, `row_version` | | |

**`users.trial_used_at timestamptz`** — ставит сервер при первом пробном. Пробный — один на человека; вторая своя компания (S32 спеки 42) пробного не получает. **Обход через удаление учётной записи** (строка `users` обезличивается, та же почта — новая строка) **признаём потерей** — решение по умолчанию (§12 п.8, вариант (в) исследования §8): цена одного обхода ≈ $1–2 (запас ИИ $1,50 [исследование]); новая компания начинается пустой. Админ-панель (спека 45) показывает повторные пробные **по установке (`install_id`); IP не хранится и не добавляется** (решение аудита №2 15.11, #1556); если обход станет заметным — варианты проверки телефона и хеша: §14 (рекомендация: сначала А, затем Б). **Задача спеке 45** (не моя зона): вид «повторные пробные».

**`app.plan_limits(plan_key)`** → `{members, subcontractors, ai, module_quota, storage_bytes}`; значения — §4. `ai` — `{budget_cents_month, cents_day_per_member, requests_day, requests_month, turn_cap_cents}`; для Start заполнены оба вида пределов (штуки и деньги), для остальных — только деньги. `module_quota` — `jsonb` `{<module_key>: {unit, per_month}}`; ядро ничего не знает про «замер» (правило планирования CLAUDE.md). ИИ — учёт ходов и резерв спеки 43 (§8.5, §11.1); эта спека даёт потолки; `ai_usage` — вид над учётом ходов.

**Люди тарифа** — активные члены любой роли, **кроме `subcontractor`** (§6). Отключённые и удалённые не считаются.

**Модуль, входящий в тариф** — первый включённый владельцем; смена — раз в период.

**Не заводим:** счётчик документов, плату за место, пакеты ИИ (после беты), отдельный пробный модуля (срок модуля = срок компании), Apple introductory offer.

**Существующие компании.** Миграция заполняет `company_plans` для **всех** существующих компаний: `status = active`, `source = manual`, `paid_until = null` («бессрочно до решения оператора»), и `app.company_writable` считает `manual` без `paid_until` записываемой. Триггер `after insert on companies` создаёт строку для новых. Бета-компании переводятся на тариф вручную из админ-панели.

### 4.2. ИИ на Start — «чисто как реклама» (§12 п.2)

**Обращение** = один ход помощника спеки 43 (вопрос или команда пользователя; несколько шагов внутри хода — одно обращение). Навигация и словарь команд на устройстве без модели — **вне счёта**, работают всегда.

| Предел | Значение | Зачем |
|---|---|---|
| В сутки | 3 | не даёт съесть месяц за день; человек пробует помощника «на вкус» |
| В месяц | 20 | видимый счётчик «осталось N из 20» |
| Денежный запас в месяц | **$1,00** (≈ 33 обычных хода) | **настоящая защита себестоимости** — штуки маржу не держат: цена хода колеблется в 8 раз ($0,03–0,25) [исследование §8] |
| Предел одного хода | $0,085 (тяжёлый ход, 5 шагов) | резерв до вызова (спека 43 §8.5): ход дороже предела не стартует |

Расчёт себестоимости [расчёт] по ценам Claude [проверено 15.11: platform.claude.com/docs/en/about-claude/pricing — Sonnet 5.5: ввод $2, запись кэша $2,50, чтение кэша $0,10, вывод $10 за 1M токенов; Haiku 5.5 (промпт ≤100 000): $0,10 / $0,125 / $0,01 / $0,50] и по оценке токенов спеки 43 §12 (шаг ≈ $0,010; обычный ход, 3 шага, ≈ $0,03; тяжёлый ход, 5 шагов, ≈ $0,085; допущение, заменит учёт ходов этапа И1):

| Сценарий | Расчёт | Итого в месяц |
|---|---|---|
| Ожидаемо (15 обращений из 20 обычные) | 15 × $0,03 | **$0,45** |
| Все 20 обращений обычные | 20 × $0,03 | $0,60 |
| Все 20 обращений тяжёлые | 20 × $0,085 = $1,70 → обрезается запасом | **$1,00** (потолок) |
| Цены ИИ выросли вдвое | 20 × $0,06 = $1,20 → запас | $1,00 (потолок) |

Худший случай не выше $1,00 при любой цене хода: держит денежный запас, а не штуки. Тексты (правило голоса; в строках RU/EN/ES): «Осталось 17 из 20 обращений в этом месяце»; на пределе — «Обращения этого месяца использованы. Новые — 1 декабря. В тарифе Solo помощник работает в течение всего дня». Без «ошибка / не удалось».

### 4.3. Gutters на Start — 15 новых замеров в месяц (§12 п.2, п.4)

**Что считается.** Создание нового замера (запись `gutter_measurements`). Считается в момент создания, включая черновик; удаление замера счётчик не возвращает. **Не считается и не ограничено:** открыть, смотреть («Просмотр замера»), править, дублировать, экспортировать, делать смету и счёт по уже созданному замеру, любое число старых замеров. Месяц — календарный, по часовому поясу компании (правило 7 о датах США). Квота действует только на `plan_key = start`; на пробном (`crew`) и тарифах Solo и выше — нет.

**Почему 15 [расчёт и допущение, подтвердить на бете]:**
1. **Себестоимость замера — доли цента.** Три снимка со спутника по $2 за 1 000 и один геокодинг по $5 за 1 000 [исследование §3: developers.google.com/maps/billing-and-pricing/pricing, 10 000 запросов в месяц каждого вида бесплатно] ≈ $0,011 за замер без бесплатной части; 15 замеров ≈ $0,17 в месяц. Предел — не про себестоимость, а про рычаг тарифа: Start $19 «пробует» модуль, Solo $39 — работает с ним.
2. Обычная компания делает ~40 смет со снимком в месяц, лёгкая — 10 [исследование §4.1, допущение]. 15 покрывает лёгкую целиком и больше трети обычной: одиночка вида «пара замеров в неделю» остаётся на Start, ежедневный пользователь упирается и покупает Solo.
3. Рядом: Roofr продаёт отчёт замера за $13–19 [исследование §2, roofr.com/pricing]; 15 бесплатных замеров в месяц — заметная ценность за $19 (как «адекватный лимит» по словам основателя).

Значение 15 — рабочее; на бете (этап 1–4, замер объёмов) проверить, какую долю компаний оно режет, и сдвинуть 10 / 20 без смены схемы (`module_quota` — данные). Вопрос основателю — §10.

**Где живёт.** Счётчик — в модуле Gutters; `app.plan_limits.module_quota` хранит число и единицу, ядро только отдаёт его модулю (S97). Ничего gutter-специфичного в ядре: ни экранов, ни текстов ядра.

**Офлайн (правило 6).** Замер на телефоне создаётся сразу, без сети. Проверка квоты — на устройстве по последнему известному счётчику; сервер **принимает** замеры сверх квоты, созданные без сети (запись не отклоняется, ничего не теряется), и показывает «использовано 17 из 15»: кнопка «Новый замер» закрыта до следующего месяца или тарифа выше. Тексты: «В этом месяце создано 15 из 15 замеров. Новые откроются 1 декабря; прежние замеры открыты как всегда. В тарифе Solo — без ограничения».

## 6. Субподрядчики и места тарифа (§12 п.9)

**Правило.** Субподрядчики (`memberships.role = 'subcontractor'`, спека 42) **не занимают мест тарифа**, пока их число не выше предела: Start 2, Solo 2, Crew 5, Company 15. Больше — предложение тарифа выше. Места (`members`) считают всех остальных активных членов (owner, admin, office, sales, tech).

**Проверка: Solo не обходится ролью** [код + спека 42]:

| Что | Член тарифа с местом (`tech`, ближайшая по правам роль) | Субподрядчик |
|---|---|---|
| Клиенты, объекты, работы | видит назначенных [код: `core.sql:1587-1631`, `is_customer_assignee`, `is_visit_assignee`] | **нет ни одной политики** для `subcontractor` в таблицах клиентов, работ, смет, счетов, оплат (поиск по `supabase/migrations`, 15.11) — при спеке 42 только функции `sub_visits()`, `respond_visit()`, `sub_visit_step()` (спека 42 §8.1) |
| Создать черновик сметы | да [код: `core.sql:1657`, `status = 'draft'`] | нет |
| Цены, оплаты, счета, лиды, каталог | нет (кроме своих работ) | **никогда** (спека 42 §8.1, T257 (был T218, перенумерован картой 15.11, #1556): 0 строк, в том числе по своему выезду) |
| Адрес и телефон клиента | по своим работам | только после «принять» (спека 42 §2.3) |
| ИИ-помощник, замеры Gutters, расписание офиса | по роли | нет |
| Фото выезда | да | только своё окно: `accepted` и 7 суток после (спека 42) |

То есть роль субподрядчика **уже и тесней**, чем `tech`: офисную работу (клиенты, сметы, счета, приём оплат), ради которой платят за место, он делать не может. Одиночка на Solo может назвать двух полевых помощников субподрядчиками — это и есть замысел роли (чужая компания, получает выезды «предложением»), и результат дешевле для нас, чем место `tech`, потому что у субподрядчика нет ИИ и офиса.

**Что всё же закрыть (S98), чтобы это не стало обходом:**
1. Смена роли `subcontractor` → любая другая роль считается как приглашение на место: при людях сверх предела — отказ с предложением тарифа выше (триггер на `memberships`).
2. Приглашение субподрядчика сверх предела (3-го на Solo, 6-го на Crew) — отказ с предложением тарифа выше.
3. Субподрядчик, отключённый или удалённый, число не занимает.
4. Общий вход на двоих — вне нашего контроля, ловится Условиями (общая учётная запись).
5. Зависимость: спека 42 **ещё не собрана** (в миграциях нет политик субподрядчика); вывод выше верен для замысла спеки 42 и для кода на 15.11 (доступа нет). **T257 спеки 42 («субподрядчик: `select` из клиентов, объектов, работ, выездов, смет, счетов, оплат, лидов, каталога, `member_documents` чужих — 0 строк, в том числе по своему выезду») — обязательный тест спеки 42 и условие сборки S98;** без него вывод «Solo не обходится» не держится.

- Удаление учётной записи с подпиской Apple — предупреждение «Отмените подписку в Apple: она продолжит списываться после удаления учётной записи» (5.1.1(v)).

## 14. Повторные пробные сроки (слова основателя 15.11, README исследований §13.6)

Слова основателя: «на одной почте нельзя регистрироваться дважды, на одном номере телефона тоже… а может, и нет, не знаю — надо обдумать». Решения нет — это разбор и рекомендация для обдумывания. Метки: **[код]** — прочитано в коде и миграциях `main`; **[цитата]** — страница открыта 15.11.2026; **[вывод]** — рассуждение автора; **[не проверено]**.

### 14.1. Что уже обеспечено
- **Почта уникальна, пока учётная запись жива.** Вход — Supabase Auth: повторная регистрация той же почтой новую запись не создаёт [вывод из устройства Supabase Auth; тест T231 спеки 50 фиксирует поведение]. Это уже закрывает «на одной почте нельзя дважды».
- **Пробный — один на человека, а не на компанию.** `users.trial_used_at` ставит сервер при первом пробном; вторая своя компания (S32 спеки 42) пробного не получает, начинается `read_only` до оплаты (S90, §3, §12 тесты). Несколько компаний у одного человека обхода не дают.
- **Пробный не складывается с Apple:** introductory offer не заводим (§3 «Не заводим»).
- **Что не закрыто:** (1) новая почта — новая учётная запись, пробный снова (бесплатные адреса создаются за секунды); (2) удаление учётной записи и регистрация заново: строка `users` обезличивается (`trial_used_at` остаётся на ней, спека 50 §3.2), а новая запись получает свой пробный; (3) номера телефона у входа сейчас нет — учётная запись держится на почте.

### 14.2. Что даёт проверка телефона и сколько стоит
Идея: при создании **первой** компании владельца просим код по SMS на его номер; номер уникален среди живых учётных записей.

- **Что закрывает:** «вторая почта на тот же номер» — пока первая учётная запись жива. Не закрывает: второй номер у человека (вторая SIM, eSIM, интернет-номера), номер, освободившийся после удаления учётной записи, и учётные записи, которые человек сам удалил.
- **Цена за проверку** (Twilio Verify, [страница тарифов Twilio](https://twilio.com/verify/pricing); сторонние обзоры совпадают, [Prelude](https://prelude.so/blog/sms-api-pricing)): **$0,05 за успешную проверку + $0,0083 за SMS в США** (на испанской странице Twilio — $0,0079; число плавает) ≈ **$0,058 за регистрацию владельца**. SMS-попытки оплачиваются и когда не доставлены [цитата Twilio]. Скидки за объём — «по запросу». Своей цены SMS у Supabase нет: он подключает Twilio, MessageBird или Vonage, и сам советует настроить лимиты и CAPTCHA, потому что вход по SMS «может стать дорогим» [цитата, [Supabase: Phone sign-in](https://supabase.com/docs/guides/auth/auth-twilio)]; цены MessageBird и Vonage **[не проверено]**.
- **Сравнение с потерей.** Один обход пробного стоит нам ≈ **$1–2** (запас ИИ на пробный $1,50, §3). Проверка телефона обходится в $0,058 на **каждого** честного владельца: на 1000 регистраций ≈ $58; окупается, если она отсекает больше 3–6% обходов. Подсчитать долю обходов сейчас нечем — админ-панель (спека 45, «повторные пробные») ещё не построена.
- **Побочные риски** [вывод]: накрутка SMS-кодов ботами (расход без регистрации) — нужны CAPTCHA и лимиты запросов; один рабочий телефон на двух партнёров или на семью даёт ложный отказ честному человеку; интернет-номера и Google Voice проверка не отличит без платной проверки типа линии (стоимость **[не проверено]**); лишний шаг при регистрации — падение конверсии (README §3: у Jobber жалоба на «слишком много шагов»).
- **Многокомпанийность:** номер привязан к человеку (его учётной записи), а не к компании: человек с тремя компаниями проходит проверку один раз. Сотрудники и субподрядчики по приглашению номера не дают: проверяется только создание первой компании.

### 14.3. Как это уживается с полным удалением учётной записи (Apple)
Apple: удаление «removes the account from the developer's records, along with any data associated with the account that the developer isn't legally required to maintain»; о том, что остаётся, нужно сказать человеку [цитата, [Apple: Offering account deletion](https://developer.apple.com/support/offering-account-deletion-in-your-app/)]. Из этого:
- хранить номер или почту удалённого человека «на случай нового пробного» — **не обязанность по закону**, и текстом Apple это не оправдано; риск отказа в ревью [вывод];
- хеш номера (HMAC с серверным ключом, не раскрываемый обратно) без связи с учётной записью, на ограниченный срок, — **осторожный вариант**: данных человека в обычном смысле нет, но хеш номера всё равно идентификатор. Допустимость по праву США (цель — предотвращение мошенничества, CCPA допускает хранение для безопасности и целостности, §1798.105(d)) **[не проверено по тексту статьи]**; Apple такой путь прямо не разрешает и не запрещает **[не проверено]**. Нужны: заключение юриста США, строка на экране удаления «что остаётся» (спека 50 §3.1), срок в таблице сроков (спека 50 §6) и абзац в политике конфиденциальности (спека 48).
- Текущая запись `users.trial_used_at` на обезличенной строке уже сегодня хранит факт «пробный использован» без почты и номера — на новую почту она не действует (спека 50 §3.2).

### 14.5. Рекомендация
1. **Беты и первый выпуск — вариант А** (без изменений). Потеря на обходе ≈ $1–2 мала; админ-панель считает повторные пробные (задача спеке 45).
2. **Перед публичным запуском — вариант Б**, если админ-панель покажет, что обходов заметно больше нескольких процентов регистраций (порог — при цифрах основателя: $0,058 за регистрацию против $1–2 за обход). Сделать выключаемой настройкой платформы, не жёстким правилом: спека 45 уже даёт панель.
3. **Вариант В — не делать сейчас.** Хеш номера после удаления конфликтует с обещанием «удалено» и требует юриста США и текста Apple; вернуться, только если Б не помогает. До этого — `trial_used_at` на обезличенной строке.
4. Основателю — когда будут цифры панели; решение по продукту и праву, не по технике.
