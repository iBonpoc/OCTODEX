# Ожидаемый разбор синтетического подтверждения заказа (спека 53 §8а.10)

**Всё выдумано** (правило 9): поставщик, люди, адреса, номера, цены. Источник — `order-ack.synthetic.txt`. Образец станет фикстурой модульного теста распознавателя и теста движка (налог). Деньги записаны десятичной строкой, как в документе; центы считает только движок.

## Тип
`order_ack` — подтверждение заказа. Действие по умолчанию — **закупка** (заказ поставщику / приход), а не цены каталога. Предложение «обновить цену по последней закупке» — только с подтверждением человека.

## Налог (К1, тест движка)
Ставки в документе нет, только сумма. Движок ищет ставку в bps, при которой налог сходится с документом:
- **по строкам** (налог каждой строки округляется до цента, затем суммируется): 825 bps → 16.09 + 12.38 + 30.69 + 3.55 + 7.18 = **69.89** = документу;
- **от subtotal** (одно округление): 847.00 × 8.25 % = 69.8775 → **69.88**, на 1 ¢ меньше документа.

Итог: «Налог 8.25 % — **вычислен**, сошёлся по строкам (от подытога разница 1 ¢). Подтвердите». Ставка поставщика не меняется без подтверждения.

### Freight: облагается или нет — по документу (зависит от штата)
Движок проверяет обе базы и предлагает ту, с которой сошлось. Подтверждает человек. Два случая (тест движка):

| Случай | Tax в документе | Без Freight (847.00) | С Freight (882.00) | Предложение |
|---|---|---|---|---|
| А — образец как есть | 69.89 | по строкам 69.89 ✓, от подытога 69.88 | от подытога 72.765 → 72.77, по строкам 69.89 + 2.89 = 72.78 | «8.25 %, сошёлся **без доставки**, по строкам» |
| Б — тот же документ, Tax 72.77, Total 954.77 | 72.77 | 69.89 / 69.88 | от подытога **72.77** ✓, по строкам 72.78 | «8.25 %, сошёлся **с доставкой**, от подытога» |

Если сумма сходится с обеими базами или ни с одной, выводится «Проверьте налог» без предложения.
