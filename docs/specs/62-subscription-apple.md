## 0. Что нужно пользователю

Подрядчик с телефона: «попробовал 7 дней → понравилось → платит без сайта, карты и переписки → не думает о подписке, пока она работает». ### 5.4. Поток покупки

1. Владелец (или админ — вопрос В3) открывает «Компания → Модули → Gutters» или нажимает на закрытую функцию модуля.
2. Экран подписки (§7): что даёт, цена за месяц, шкала пробного, автопродление, ссылки.
3. «Попробовать 7 дней бесплатно» (если Apple ID имеет право на пробный — `isEligibleForIntroOffer`; иначе «Оформить за $X в месяц»).
4. `requestPurchase({ sku, appAccountToken })`. `appAccountToken` — UUID, который выдал сервер (`iap_purchase_intent`, §6.2) для пары «компания + человек».
5. Окно Apple с Face ID.
6. Приложение получает подписанную транзакцию (JWS) и отправляет её на сервер `iap-verify`. Сервер проверяет подпись, `bundleId`, `appAccountToken` и пишет статус.
7. **Только после ответа сервера** — `finishTransaction`. Нет сети — транзакция не завершается, StoreKit отдаст её снова при следующем запуске (`Transaction.updates`). Это и есть очередь правила 6 для покупки; своя очередь не нужна.
8. Экран: «Gutters подключён. Пробный до 25 ноября, потом $X в месяц. Отменить можно в любой момент».

Состояния ответа: успех, отмена пользователем (тихо, без тоста), `pending` (одобрение «Ask to Buy» или банка — «Ждём подтверждения от Apple»), ошибка сети («Покупка прошла, подключим, как появится сеть»).

## 6. Сервер: проверка покупок и статус компании

### 6.1. Источники правды

| Канал | Что | Когда |
|---|---|---|
| Приложение → `iap-verify` (Edge Function, JWT пользователя) | подписанная транзакция после покупки и при «Восстановить» | сразу |
| App Store Server Notifications V2 → `apple-notifications` (Edge Function, публичная, без JWT) | `SUBSCRIBED`, `DID_RENEW`, `DID_FAIL_TO_RENEW` (с подтипом `GRACE_PERIOD`), `GRACE_PERIOD_EXPIRED`, `EXPIRED`, `DID_CHANGE_RENEWAL_STATUS`, `REFUND`, `REVOKE`, `TEST` и др. | от Apple, с повторами |
| App Store Server API (JWT из ключа In-App Purchase, ES256, `.p8` — секрет Supabase) | `Get All Subscription Statuses`, `Get Transaction Info`, `Get Notification History` | сверка раз в сутки и при сомнении |

Сервер никогда не верит приложению на слово: доступ даёт только подпись Apple, проверенная на сервере.

### 6.2. Проверка

- Подпись JWS: цепочка `x5c` (лист → промежуточный → корневой) до корневых сертификатов Apple (Apple Root CA G3 и остальные со страницы Apple PKI — Apple советует принимать список, а не один), затем подпись листовым ключом, алгоритм из заголовка [проверено 18.11: форумы Apple и WWDC22 «Explore in-app purchase integration and migration»].
- Библиотека проверки: официальная `@apple/app-store-server-library` 3.1.0 (Apple, MIT, обновлена 05.2026) через `npm:` в Deno. Работает ли она в среде Edge Functions — проверить в PR-2 первым делом [не проверено]. Запас — `jose` + своя проверка цепочки по образцу Apple, с тестами на поддельную цепочку.
- Проверяются: `bundleId`, `appAppleId` (в продакшне), `environment`, `productId` из нашего списка, `appAccountToken`.
- `appAccountToken`: сервер сам выдаёт UUID (`iap_purchase_intent(company_id)` → строка в `apple_account_tokens(token, company_id, user_id, created_at)`). Так токен из чужой компании или выдуманный не привяжет покупку. Проверка: токен есть, его компания совпадает, человек — владелец (или админ, В3).
- У транзакций Family Sharing `appAccountToken` нет [проверено 18.11] → такие транзакции компанию не открывают. В App Store Connect Family Sharing для подписки **выключен** (B2B, доступ у компании, не у семьи).
- Если `appAccountToken` потерян (Apple: новый `originalTransactionId` после переноса Apple ID [проверено 18.11, сообщение на форуме]) — сервер ставит токен заново через «Set App Account Token» (App Store Server API, WWDC25) по запросу «Восстановить» от владельца [не проверено: условия вызова].
- Идемпотентность: журнал `app.apple_notifications_seen(notification_uuid primary key)`. Повтор — 200 без изменений. Старое событие не перетирает новое: сравнение `signedDate` с последним сохранённым.
- Ответ Apple: 200 только после записи. Ошибка — 500, Apple повторит.

### 6.3. Сущности (шаг 1 правила 16, одна миграция, PR-2)

**`public.apple_subscriptions`** (одна строка на `originalTransactionId`):

| Поле | Тип | Смысл |
|---|---|---|
| `original_transaction_id` | text PK | ключ подписки у Apple |
| `company_id` | uuid → companies, not null | чья подписка; не меняется (триггер как T59) |
| `purchased_by` | uuid → users | кто купил (владелец) |
| `product_id` | text check in (список продуктов) | `gutters.monthly` (б) или продукты тарифов (а) |
| `environment` | text check in (`Production`, `Sandbox`) | |
| `status` | text check in (`trial`, `active`, `grace`, `billing_retry`, `expired`, `revoked`) | из `Get All Subscription Statuses` + тип предложения |
| `expires_at` | timestamptz | конец оплаченного (или пробного) периода |
| `grace_until` | timestamptz null | конец льготы Apple (`gracePeriodExpiresDate`) |
| `auto_renew` | boolean | выключил ли автопродление (для «Подписка закончится 25 ноября») |
| `last_signed_at` | timestamptz | `signedDate` последнего применённого события |
| `updated_at` | timestamptz | |

Права: `revoke all … from anon, authenticated`; пишет только `service_role` (Edge Functions). Член компании читает **только** `company_id`, `product_id`, `status`, `expires_at`, `auto_renew` своей компании через функцию `app.subscription_status(company_id)` (security definer, правило 18). `purchased_by` видят владелец и админ. Почта, Apple ID и суммы не хранятся.

**`app.apple_notifications_seen`**, **`public.apple_account_tokens`** — служебные, только `service_role`; токены старше 30 дней без покупки стираются.

### 6.4. Как статус доходит до доступа

| Вариант | Запись | Старые версии приложения |
|---|---|---|
| (б) | `company_modules.paid_until = coalesce(grace_until, expires_at)` для `gutters`; `enabled = true`. При `expired`/`revoked` — `paid_until = expires_at` (в прошлом) | **работают без правки**: `app.module_active` уже читает `paid_until` [код] |
| (а) | `company_plans` (спека 44): `status`, `paid_until`, `source = 'apple'`, `external_id = original_transaction_id`; Gutters открывается через S96 | по спеке 44 §8 (шаг 1 / шаг 2) |

Запись `paid_until` — **из транзакции**, а не «месяц от сегодня»: продление, возврат и отзыв дают точную дату.

### 6.5. Правило 16

- `company_modules`, `trial_ends_at`, `paid_until`, `module_enable`, `app.module_active` — **не удаляются и не меняют смысл**.
- Новое: `apple_subscriptions`, журнал, токены, `app.subscription_status`, `public.module_switch_on(company, module)` — включает модуль **без** своего пробного (для новой версии). `module_enable` остаётся для старых версий; удалить его — отдельным PR шага 2, когда ни одна версия его не зовёт.
- Новая миграция: `revoke all … from anon, authenticated` (и `from public, anon` для функций), потом минимальные `grant` (правило 18, T52).

### 6.6. Песочница и продакшн

Проверяющий Apple покупает в **песочнице**, но в сборке, которая пойдёт в продакшн. Значит, продакшн-сервер обязан принимать `environment = Sandbox` [Apple требует это для ревью; не проверено 18.11 дословно для JWS]. Риск: бесплатная «покупка» в песочнице открыла бы модуль бесплатно. Защита: песочницу дают только сборки TestFlight, разработки и ревью (сборка из App Store всегда в продакшне); подписка песочницы живёт ускоренно (месяц ≈ 5 минут, до 12 продлений [не проверено 18.11]); в базе `environment` виден, админ-панель (спека 45) показывает песочные подписки отдельно. Уведомления: два URL в App Store Connect (продакшн и песочница), одна функция, `environment` из подписанных данных, а не из URL. Вывод — для `security-check`.

## 7. Экран подписки (3.1.1, 3.1.2, Schedule 2 §3.8(b))

Собирается только из `src/ui` и токенов (правило 29). Вид — `design-reviewer` до сдачи PR-1 (два независимых, правило DS). Строки — i18n RU/EN/ES. Цена — **из StoreKit** (`displayPrice`, локализованная Apple), в коде цены нет.

Обязательно на экране до кнопки [проверено 18.11: 3.1.2(c) «clearly describe what the user will get for the price»; 3.1.2(a) — срок подписки не меньше 7 дней; Schedule 2 §3.8(b) — название, срок, цена]:

1. Название подписки и что она даёт (3–5 пунктов: чертёж, расчёт, каталог, сметы по замерам).
2. Цена за период: «$X в месяц» (из StoreKit).
3. Пробный: «7 дней бесплатно, потом $X в месяц» + шкала «Сегодня → за 2 дня напомним → день 8 — первое списание».
4. «Подписка продлевается автоматически, пока вы её не отмените. Отменить можно в Настройках Apple ID не позже чем за 24 часа до конца периода».
5. Ссылки «Условия использования» (наши или стандартный EULA Apple) и «Политика конфиденциальности» — рабочие публичные страницы (16-appstore §2 п.17).
6. «Восстановить покупки».
7. Главная кнопка — одна (`acc`, правило 2).

Владельцу с подпиской: статус («Пробный до 25 ноября» / «Оплачено до…» / «Подписка закончится 25 ноября»), «Управлять подпиской» (`showManageSubscriptions`). Мастеру и офису: «Подписку оформляет владелец компании» — без цены и без кнопки покупки (вопрос В3 об админе).

## 8. Сценарии и крайние случаи

### 8.1. Что закрывается без подписки
(б): по О2 — модуль недоступен на сервере: новые замеры, правка чертежа, настройки модуля — отказ `module_inactive`; старые сметы и PDF читаются; ядро работает полностью. (а): спека 44 §7–§8а.

### 8.2. Восстановление и смена устройства
Статус у компании на сервере: новый телефон после входа видит его сразу, без StoreKit. «Восстановить покупки» (`getAvailablePurchases` / `AppStore.sync`) нужна, когда владелец сменил Apple ID или токен потерян: приложение шлёт транзакции на `iap-verify`, сервер привязывает их к компании, только если `original_transaction_id` ещё ни к кому не привязан или привязан к этой же компании.

### 8.3. Несколько людей и компаний
- Платит **владелец**. Покупка привязана к компании, а не к человеку.
- Одна подписка Apple — одна компания (`original_transaction_id` — PK). Две компании одного владельца — две подписки. В одной группе подписок Apple одновременно действует только одна подписка на Apple ID [не проверено для двух покупок одного продукта]. Поэтому вторая компания одного Apple ID — вопрос В4: отдельная группа подписок или «одна подписка — одна компания, вторая платит с другого Apple ID».
- Уже есть подписка у компании, и второй человек пытается купить → сервер отказывает **до** покупки (`iap_purchase_intent` возвращает `already_subscribed`) — двойного списания нет.
- Смена владельца (спека 50): подписка остаётся на Apple ID прежнего владельца и держит компанию до конца оплаченного; новый владелец видит «Оплачено прежним владельцем до…» и оформляет свою после. Прежний владелец получает напоминание отменить свою.

### 8.4. Удаление учётной записи при подписке (5.1.1(v))
На экране удаления, если у человека есть действующая подписка Apple: «Подписка Apple продолжит списываться после удаления. Отмените её в Настройках Apple ID» + кнопка «Управлять подпиской» (тем же окном Apple). Удаление этим не блокируется (Apple не разрешает делать удаление сложным). Строка `apple_subscriptions` остаётся, пока жива компания (деньги и налоги), `purchased_by` обезличивается. Владелец компании проходит путь спеки 50 (передать или закрыть).

### 8.5. Возврат, отзыв, неоплата
`REFUND` / `REVOKE` → `status = revoked`, `paid_until = now()`; данные не удаляются (О2). `DID_FAIL_TO_RENEW` с `GRACE_PERIOD` → доступ до `grace_until`, баннер владельцу «Apple не смог списать оплату — проверьте способ оплаты». Льгота Apple (Billing Grace Period) **включается** в App Store Connect; срок 3 / 16 / 28 дней [не проверено] — рекомендация 16, согласовать с 7 днями спеки 44 (вопрос В5).

### 8.6. Веб и Android
Веб (сайт приложения): покупки нет, экран показывает статус и «Оформить можно в приложении GoRix на iPhone». Android: Play Billing через тот же `expo-iap` — отдельная задача после первой сборки Android; сервер готов к второму источнику (`source`).

### 8.7. Без сети
Статус подписки кэшируется в сторе вместе с модулями. Без сети модуль открыт до `paid_until` из кэша. Покупка без сети невозможна (окно Apple само скажет). Незавершённая транзакция дойдёт при сети (§5.4 п.7).

## 14. Риски

1. Один сопровождающий `expo-iap` — запас `react-native-iap` (тот же API) или своя тонкая обёртка StoreKit 2.
