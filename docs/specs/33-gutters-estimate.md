## П23.1 Брейншторм
**Что нужно подрядчику.** Нарисовал на крыше → «Смета» → готовые строки по разделам из его прайса, работа отдельными строками (О4), правит руками как любую смету, отправляет. Перерисовал — «Обновить смету»: пересчитались только строки замера; его ручные цены, количества и свои строки остались.

**Где хранить «эта строка — из замера».**
| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Колонки `estimate_line_items` (C4a: `source`, `source_key`, `section_key`) + приложение пишет (C4b) | видно в базе, отчёты по строкам | миграция + два шага (правило 16); строки переписываются из `calc_inputs` при каждом сохранении — колонки лишь копия; ядро смет менять в двух местах |
| **Б. Поля строки в документе** (`CustomLine.source = { module, key, section, calcQty }`, `CustomLine.override`), они уже доходят до базы в `calc_inputs` | без миграции; одна правда (документ); старые версии приложения просто не знают поле (терпят — строка как ручная) | в `estimate_line_items` метки нет (отчёты по модулям — позже, тогда C4a как копия) |
**Выбор: Б** (C4a/C4b переносятся «когда понадобится отчёт по строкам модуля»).

**Как обновлять.** Ключ строки = `matchKey` детали (то же, что ищет позицию прайса). «Обновить смету»: строка с ключом — новое количество (`calcQty`), если её `quantity` не правили руками (`override` нет); цена — из прайса, если не правили; строка, которой больше нет в замере, — убирается, если не тронута, иначе остаётся с пометкой «нет в замере»; свои строки не трогаются; новые — в конец своего раздела.

**Разделы.** Ядро не знает разделов; строки идут в порядке разделов движка (`section`: gutter, corners_caps, fasteners, downspouts, adapters, ds_bottom, guards, consumables, labor) — работа последней. **Решено (мелкое решение, вид): порядком, без подзаголовков** — подзаголовки потребовали бы правки экрана и PDF сметы ядра; снимки «было/стало» — в M8b, основатель может попросить подзаголовки.

**Цена не найдена.** Строка с ценой 0 и пометкой «нет цены» (не $0 молча) — отправить нельзя, пока не поставили (C5: проверка перед отправкой — общий механизм ядра «чего не хватает», модуль даёт свои причины).

## П23.5 Старые версии приложения (условие руководителя)
Проверено: документ сметы хранится целиком (`saveEstimate` пишет `op.doc` в `calc_inputs`, `repo.ts withCosts` и `clientDoc` раскрывают строку `{...l}`), `normalize.ts` строк не трогает, экран строки (`LineSheet`) правит копию `{...draft}` — **незнакомые поля строки доживают** при правке и пересохранении старой версией. «Выбрать позицию из прайса» строку не заменяет, а добавляет новую (`linesFromCatalog` → новый id, `saveLines` дописывает) — новая строка без `source`, она своя.
Поэтому ручная правка определяется **не флагом `override`**, а сравнением строки с её `source` (что модуль записал: количество, цена, имя): старая версия, поменявшая количество, всё равно видна как «правлено руками». Строка без `source` — своя: не меняется, не удаляется; деталь, чью позицию прайса уже взяла своя строка, не добавляется второй раз. C4 (флаг `override` в ядре) поэтому не нужен для правил. **C4 обязателен до M8b:** (1) `source` не уходит клиенту (`/p/`, PDF, письма) — в нём цена и имя, которые записал модуль (ревью M8a №12); как именно — П23.7 (отдельной «клиентской копии» `calc_inputs` нет); (2) пометки на строке: «из замера», «нет цены», «тестовая цена», «нет в замере»; (3) C5 — проверка перед отправкой: `noPriceLines`, `testPriceLines`, `goneLines` (пропавшая правленая строка — двойной счёт).

## П23.7 C4 — `source` строки в ядре смет (08.11.2026, чат «Модуль Gutters» №9)
**Проверка (этап 0).** В `calc_inputs` приложение пишет `clientDoc(doc)` (`store.tsx`, `estimate.save`) — одна копия на всех. Если `clientDoc` снимает `source`, он не доходит до базы: после перечитки и на другом телефоне «Обновить смету» видит все строки своими. Страница `/p/` при этом отдаёт **не** `calc_inputs` как есть, а `app.client_doc(calc_inputs)` — белый список полей строки (`id, name, description, group, quantity, unit, unitPriceCents, optional, selected`; миграция 20261106180000, T60).

**Где читают `calc_inputs` на сервере** (последние версии функций): `app.portal_estimate_base` — через `app.client_doc`; `public.portal_accept`, `public.sign_estimate_on_site` — только sha256 текста версии в отпечатке подписи (наружу не уходит; версия после отправки заперта, `source` в ней уже не меняется). Edge functions (`send-push`, `delete-account`) `calc_inputs` не читают. Письмо клиенту (`estimateMessage`) несёт компанию, имя, сумму и ссылку — строк нет.

**Решение (без миграции, правило 16 не задето; вариант «колонка `line_sources`» снят, т.к. сервер уже режет):**
| Что | Где |
|---|---|
| тип `LineSource` ядра `{module, key, priceCents?, noPrice?, testPrice?, gone?, …}`, `CustomLine.source?`; модуль сужает его своим `LineSource` | `packages/estimating-engine/src/custom.ts`, `modules/gutters/estimate.ts` |
| `storedDoc(doc)` — для `calc_inputs`: без себестоимости, **с** `source` | `features/estimateDoc.ts`, `store.tsx` |
| `clientDoc(doc)` — всё, что уходит клиенту из приложения (демо-`/p/`, PDF): без себестоимости и без `source` | `features/estimateDoc.ts` |
| пометки строки `lineMarks`: «Из замера» (нейтр.), «Нет цены» (цена 0), «Тестовая цена» (цена = записанной модулем), «Нет в замере» — значок + слово | `features/LineMarks.tsx`, `app/estimate/new.tsx`, `features/LineSheet.tsx` (+ подсказка: «Обновить смету» пересчитает, пока вы не измените) |
| ручная правка | как была: шторка строки правит копию, `source` доживает; правка видна сравнением с `source` (П23.5) |

**Кто видит `source`.** Те же, кто видит смету (`can_read_estimate`: офис; мастер — свои черновики и сметы на своих объектах). В `source` только слова модуля и **цена продажи** за единицу (`catalogUnitPrice`, как у строки) — себестоимости, наценки, поставщика нет (T97 проверяет набор ключей). Себестоимость по-прежнему в `estimate_line_costs` и скрыта от мастера.

**Старые версии приложения.** Пишут `clientDoc` старого вида (снимает только себестоимость) — `source` сохраняется. Строка без `source` (своя или пере-выбранная из прайса старой версией) — своя: «Обновить смету» её не удаляет и не дублирует, если её позиция прайса совпадает (П23.5); строка «нет цены» без позиции — принятый риск (дубль при обновлении), приложение ещё не у клиентов.

**Тесты.** unit `estimateLineSources.test.ts` (10): `clientDoc` без `source`/себестоимости; `storedDoc` с `source` без себестоимости; круг через JSON → «Обновить смету» видит ручную цену; битый `source` без пометок; демо-`/p/`, PDF (`estimateHtml`), письмо — без имени модуля и пометок; `lineMarks` (своя, из замера, нет цены → цена поставлена, тестовая → правлена, нет в замере). База T97: строка с `source` в `calc_inputs` → `portal_estimate` (anon) без `source`/`testPrice`/`noPrice`/`gone`/слов модуля, цена строки та, что у строки; офис и мастер (свой черновик) читают `source`; в `source` только слова модуля. e2e пометок — в M8b (154): строки модуля появляются только кнопкой «Смета»; там же снимки «было/стало».

## П23.12 Смета не помечается, когда меняется расчёт движка (#1165, найдено на ревью #1161, 12.11.2026)
`ENGINE_VERSION` уходил в ревизию, но смета со старой деталью (например, колена круглого водостока до #871) оставалась без пометки: «Обновить» исправит, но никто не подскажет. **Решение:** строка сметы, которую пишет «Смета» / «Обновить», несёт `source.engineVersion` (версия движка, посчитавшего количество); если она **меньше** текущей (сравнение числами 0.1.3 < 0.1.10 < 0.2.0), замер помечается **«Расчёт изменился — обновите»** (значок «внимание», как у «Чертёж изменён»): на карточке в списке замеров, в шапке «Просмотра замера» (`view-engine-changed`) и заметкой на странице сметы (`module-gutters-engine` с «Обновить из замера»). Кнопка сметы в просмотре — «Обновить», хотя чертёж не менялся. **Подписанная смета:** только подсказка «Расчёт изменился после подписи» — кнопки «Обновить» нет, смета не меняется (П23.8, В4). Строка без версии (составлена до этой правки) не помечается: версия неизвестна, ничего не говорим. «Обновить» записывает текущую версию во все строки, и руками правленные, но уже не считаемые тоже. Тесты: `gutterEngineChanged.test.ts` (сравнение версий, состояние замера, подписанная, чужой замер, «Обновить»), e2e 293.
