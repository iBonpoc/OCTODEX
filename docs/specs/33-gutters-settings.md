## П22.1 Брейншторм
**Что нужно подрядчику.** Хозяин один раз говорит приложению «что я ставлю и как считаю» — и каждый замер сразу предлагает его профиль, его цвета поставщика, его крепление и его цены. Мастеру на крыше — короче список (только то, что компания ставит).

**Где хранить цены работы.**
| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Ставки работы в `settings` (центы) | всё в одном месте | две правды о ценах (прайс и настройки); смета M8 читает цены из двух мест; деньги вне `catalog_items` (себестоимость, налог, история) |
| **Б. Работа — позиции прайса** (`catalog_items`, `kind = labor`, свойства `work` / `story` — ровно те, что движок кладёт в `PartQty.attrs`). В настройках — раздел «Цены работы»: строки этих позиций с ценой, «нет цены — поставить», «создать позиции сразу» | одна правда (прайс); M8 ищет цену одной функцией для всех деталей; права прайса уже есть (staff) | раздел настроек пишет в прайс, а не в `settings` |
**Выбор: Б.**

**Как привязать деталь к позиции прайса.**
| Вариант | Плюсы | Минусы |
|---|---|---|
| А. Таблица «ключ детали → id позиции» в `settings` | явно | ключей сотни (профиль × размер × материал × цвет); 32 KB кончатся; удалил позицию — висячий id |
| **Б. Свойства позиции = привязка.** Позиция с `attributes` `{part, profile, size, …}` находится `catalogMatch` по свойствам детали; модуль решает, какие свойства важны для вида детали (у крепления — без цвета, у желоба — с цветом). «Привязать» = записать нужные свойства в позицию; «создать позиции сразу» = позиции для выбора компании по умолчанию | живёт в прайсе, переживает переименование; размер настроек не растёт | правило «какие свойства важны» — данные модуля, нужен тест |
**Выбор: Б** (П14.2 e3: явная привязка сильнее подсказки — явная здесь и есть свойства позиции).

**Как сохранять экран.**
| Вариант | Плюсы | Минусы |
|---|---|---|
| **А. Каждая смена — сразу запись** (`saveModuleSettings`, тост «Отменить» 5 с — правило 5; числа — по уходу из поля) | как холст и остальные настройки приложения; офлайн через очередь | много маленьких записей (каждая — весь объект ≤ 32 KB) |
| Б. Черновик и «Сохранить» | одна запись | ушёл с экрана — потерял; второй вид сохранения в приложении |
**Выбор: А.** Чужая правка в это же время → сервер отвечает `row_version_conflict`, очередь роняет запись и перечитывает (C2c) — карточка «не сохранено» ядра; принятый риск: двое админов одновременно редко.

**Что лежит в `settings`** (версия 1, `v: 1`; всё необязательное — пусто = умолчание модуля):
- `offer` — что ставим: `profiles[]`, `sizes{profile: []}`, `materials[]`, `gauges{material: []}`, `palette[]` (имена цветов компании — слова, не образцы, правило 2), `hangers[]` (id наборов), `guards[]`, `ds{shape: sizes[]}`, `dsStyles[]`, `bottoms[]`, `wallKits{shape: {wall: []}}`;
- `defaults` — по умолчанию: профиль, размер, материал, толщина по (материал, профиль, размер), покрытие, цвет; крепление по (профиль, край) — `hangerByMount`; край крыши; даунспот по размеру желоба (форма, размер, стиль: K5 → 2×3, K6 → 3×4); колена; низ; стена; набор к стене по (форма, стена); метод угла;
- `rules` — правила П4 (`GutterRulesOverride`, только поля из белого списка): высота этажа, шаг креплений по набору, крюк по краям (да/нет), запас, вырезанный угол, длина на даунспот, компенсатор (совет / деталь), основа дождя (SMACNA 5 мин / код 60 мин), кусок даунспота, раскрой обрезков, удлинение, бесшовный/секционный;
- `use` — расход «проверить»: заклёпки и точки герметика по виду соединения, точек на тубу, припой (точек на lb, какие металлы паяются), краска, соединение даунспота заклёпками/винтами, длина куска сетки и винты на кусок.
Сторона приложения (`settings.ts`, чистый): `readGutterSettings(raw)` — терпит мусор (не тот тип, лишние ключи, чужие id → отбрасывает поле, не падает; данные пишет любой админ и старая версия), `toRulesOverride(s)`, `choicesFor(s)` (наборы шторки), `sizeOk(s)` (< 32 KB до записи — понятное сообщение вместо отказа сервера).

### П22.9а M7c — правки по независимому ревью (08.11.2026)
- Таблица наборов к стене компании в движок не уходит: даунспот сам хранит набор компании, если он не модульный (`wallValue`), поэтому шторка и движок считают одно, а смена таблицы не меняет старые рисунки (№1).
- «Переход» — только в меньший размер своей формы (`smallerSizes`); больший и чужой снимаются (№3).
- Свой метод угла считается, только если его держат обе линии угла: удалили линию и нарисовали новую от того же конца — снова метод компании (№4). Три линии в одной точке делят конец — принятый риск (редко).
- В «Углы этой линии» первым стоит «Как у компании (…)»: угол возвращается к методу компании и следует за его сменой (№5).
- Смещения создаёт только число; длина выбирается, когда смещения есть (№6).
- e2e 151: угол после перезагрузки, выбор по месту чипа, а не по словам.
- **Не сделано в M7c (в M7d или по запросу основателя):** шаг креплений по каждому набору (сейчас один шаг на все), какие металлы паяются (`solderedMaterials`, сейчас медь), винты на кусок сетки, колена по умолчанию, даунспот по размеру желоба (K5 → 2×3). Проверка «$ меняется от правил» на холсте — модульными тестами (движок + `toRulesOverride`), e2e проверяет запись и угол.
