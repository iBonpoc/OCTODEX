# 70. Gutters: замер → смета сама, одна смета на весь объём (этап 0, К1)

Статус: **код на стенде** (задача #3027, из замечаний основателя #3021; ответы #3047 А, #3048 А, решение #3054). Класс К1 (данные и деньги). Как сделано — спека 33 П23.13. Исполнитель — Gutters (зона в); правка карты §4/§5 — руководитель (общий файл). Отличие от §4.1: сохранение отправленной сметы ядро делает её новой версией-черновиком (как ручную правку) — отдельного состояния «Изменена после отправки» у ядра нет (вопрос руководителю).

## 1. Слова основателя (26.11.2026, ~20:00 LA, дословно)
> Кнопка сделать смету. Я думаю, если замер уже есть, то смета уже должна быть автоматически сделана. То есть надо продумать еще механику, как это работает. Если, допустим, я сделал чертеж, у меня создалась смета и она появилась автоматически у клиента, да, например, или у лида. Это смета. Это нужно сделать. Потом, если я внесу правки, то, ну и добавляю, допустим, в смету еще там ремонт розетки, да? То есть у меня есть, у меня идет эта смета, в ней gutters и отдельно потом там типа ремонт розетки или что-то там замена плитки на крыше какая-нибудь вот так. Как это будет отображаться в, ну, во-первых, в замерах, да, когда я открываю какой-то замер? И как это будет отображаться в смете у клиента? То есть это должна быть, ну допустим, одна смета будет на весь объем работы.

Четыре вопроса: (1) смета появляется сама после чертежа, у клиента или лида; (2) одна смета на весь объём — Gutters и другие работы; (3) что со сметой, когда замер правят после ручных строк; (4) как это видно в замере и в смете.

## 2. Как есть (код стенда, проверено картой пути и map-keeper 27.11)
- **Смета делается только по кнопке** «Сделать смету» (S5g: «система модуля по кнопке человека», `docs/15-story-map.md:120`; решение #2004 от 17.11: «вопрос, запись только по нажатию» — `33-gutters-workflow.md:188, :277`, `33-gutters-estimate.md:93`).
- `makeEstimate` (`estimateLink.ts`) пишет только в смету **этого замера**; если у лида уже есть другая смета (без строк замера), она лишь показывается («Уже есть смета EST-… — без этого чертежа», #2990), а кнопка делает **вторую** смету — две цены одному клиенту (находка crm-reviewer, блокирует).
- **Одна смета на несколько работ уже умеет почти всё:** строки модуля с `source{module, measurementId, key, …}`, «Обновить из замера» (`resyncLines`) не трогает ручные строки, ручные правки количества и строки другого замера (П23.8); варианты и группы строк; страница чертежа на замер (S6g).
- **Статус замера** `draft` / `ready` = «до / после „Сделать смету“» (`§5`, база `check (status in ('draft','ready'))`).
- **Смета без клиента невозможна:** `customer_id`, `property_id` обязательны. Черновик замера без лида и адреса остаётся «Привязать…».
- Смету лида ядро делает через `leadEstimateTarget` (клиент-prospect из лида, S3).

## 3. Как делают лучшие сегодня (правило 28)
- **Hover, RoofSnap, EagleView + Xactimate:** по готовому замеру смета (или «предварительная смета») считается сразу и лежит у проекта; подрядчик её проверяет и отправляет. Ручные позиции добавляются в ту же смету.
- **Jobber, Housecall Pro:** одна смета на запрос (request / job), в ней «line items» разных работ, разделы; по замеру/осмотру позиции добавляются в открытую смету, отправленная меняется только через «изменения» и повторную отправку.
- **magicplan:** план → смета сама из шаблона, пересчитывается при правке плана; ручные позиции живут отдельно.
- **Чем мы лучше измеримо:** сейчас 3 нажатия после чертежа («Готово» → «Сделать смету» → подтвердить) и риск второй сметы; станет 0–1 нажатия («Готово» — смета уже у лида/клиента) и одна смета на объём.

## 4. Варианты

### 4.1. Когда появляется смета
- **А (совет): сама, черновиком, по «Готово» на холсте** (и при привязке черновика к лиду/клиенту — тот же шаг). Пока смета — черновик, правки чертежа переносятся в неё **сами** (при «Готово»). Отправленная и подписанная — **никогда сами**: карточка показывает «Перенести изменения в смету» (отправленная → «Отправить изменения», #2637) или «изменился после подписи» → «Доп. смета» (#2728).
- **Б: по кнопке, но в одну смету.** Как сейчас, кнопка «Сделать смету», но она добавляет замер в открытую смету лида/клиента («Добавить в EST-0006»), а не создаёт вторую.

### 4.2. Какая смета — «одна на весь объём»
Правило выбора (для А и Б одно):
1. Есть смета **этого замера** — она.
2. Иначе у того же лида / объекта клиента есть **открытый черновик** — замер добавляется в него (новая группа «Gutters», см. 4.3).
3. Иначе есть **отправленная** смета без ответа — **вопрос основателю §7 В2**: добавить в неё (станет «Изменена после отправки» → «Отправить изменения») или сделать новую.
4. Иначе — новая смета (черновик).
Подписанная смета не трогается никогда (её дополняет «Доп. смета», #2728).

### 4.3. Как это выглядит в смете клиента
Одна смета, разделы:
- **Gutters** — строки из замера (желоба, downspout, переходники, работа), подпись раздела «по замеру 11/26» и чертёж-вложение (S6g);
- **Другие работы** — ручные строки: «Ремонт розетки», «Замена плитки на крыше» — как любая позиция каталога или своя строка.
Итог один на всю смету. Клиент на `/p/` и в PDF видит один документ, чертёж — страницей к нему.

### 4.4. Правка замера после ручных строк
- Перенос правок трогает **только строки этого замера** (`resyncLines`, П23.8): ручные строки («Ремонт розетки») и ручные правки количества (`is_override`) остаются; строку замера, которую удалили руками, перенос не возвращает, если ей поставили количество 0 (как сейчас).
- Черновик — переносится сам при «Готово» (А) или по кнопке «Обновить смету» (Б).
- Отправленная — только по кнопке, новой версией («было → стало», «Отправить изменения»).
- Подписанная — не трогается; «Доп. смета».

### 4.5. Как это видно в карточке замера
- Шаг «Сейчас» по состоянию (одна кнопка, текст — из `estimateAction`, работает при А и Б):
  черновик без клиента → «Привязать к лиду или клиенту»; смета-черновик есть → «Проверить и отправить»; есть чужая открытая смета (Б) → «Добавить в EST-…»; отправлена → «Открыть смету» / «Напомнить про смету»; изменена после отправки → «Отправить изменения»; подписана → «Заказать материалы».
- Вкладка «Сметы» (спека 67 §8.9): строка сметы «EST-0011 · $2,113.67 · Черновик ›», под ней «Прикреплено: Чертёж, Заказ материалов»; если в смете есть и другие работы — строка «В смете ещё: Ремонт розетки, Замена плитки» (видно, что смета общая).
- В смете у клиента/лида: раздел «Gutters» со ссылкой «Замер ›».

## 5. Риски и как закрыты
| Риск | Решение |
|---|---|
| Черновик без лида и адреса | смета не создаётся (нет клиента), шаг «Привязать…»; при привязке — тот же автошаг |
| Офлайн, много правок | автошаг только по «Готово» (выход с холста), не на каждое движение; одна ревизия на «Готово» |
| Две сметы (два телефона, двойное «Готово») | правило 4.2 + идемпотентность: id новой сметы — от замера (`uuid5(measurementId)`) |
| Отправленная тихо меняется | никогда сама; только «Перенести изменения» → «Отправить изменения» |
| Подписанная | не трогается; «изменился после подписи», «Доп. смета» |
| Мастер без объекта (RLS `estimates_insert`) | автошаг молча пропускается (без ложного тоста); смета появится, когда офис привяжет / назначит |
| Лид без клиента | как сейчас: `leadEstimateTarget` создаёт клиента-prospect; «Вернуть» снимает и его |
| Нет цен | смета создаётся, в ней «⚠ Нет цен · N», шаг «Указать цены» |
| Правило 16 (база) | новых колонок не нужно; меняется смысл статуса замера (`ready` = «смета есть»), строка §5 |

- **В1. Смета сама или по кнопке?** А — сама, черновиком, по «Готово» (совет); Б — по кнопке, но в одну смету. По умолчанию, если ответа нет: А.

## 8. Тесты (когда дойдёт до кода)
- unit: авто без клиента — не создаётся; повтор «Готово» — не вторая смета (идемпотентность); выбор сметы по 4.2 (свой, черновик лида, отправленная, подписанная); ручная строка жива после переноса; отправленная и подписанная не меняются сами; мастер без объекта — молча.
- db: `estimates_insert` мастера без объекта (как T-тесты RLS), uuid5 id сметы — повтор не даёт дубля.
- e2e: чертёж у лида → «Готово» → смета у лида на вкладке «Сметы»; добавить «Ремонт розетки» → правка чертежа → ручная строка на месте; отправить → правка → «Отправить изменения».
