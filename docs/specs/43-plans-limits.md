| S96 | Тариф ↔ модуль | `app.module_active()` учитывает модуль, входящий в тариф (вместо отдельного `paid_until` модуля) |

## 3. Сущности и поля

**Новая таблица `public.company_plans`** (одна строка на компанию; миграция по правилам 16 и 18):

| Поле | Тип | Смысл |
|---|---|---|
| `company_id` | uuid PK → companies | |
| `plan_key` | text check in (`solo`,`crew`,`company`) | тариф; во время пробного — `crew` (всё открыто) |
| `status` | text check in (`trialing`,`active`,`past_due`,`read_only`) | §4 |
| `trial_ends_at` | timestamptz null | ставится один раз при создании компании, если создатель ещё не получал пробного |
| `trial_extended` | boolean default false | «+7 дней» использовано |
| `paid_until` | timestamptz null | конец оплаченного периода |
| `grace_until` | timestamptz null | конец льготы при неудачной оплате |
| `source` | text check in (`web`,`apple`,`manual`) null | кто списывает; `manual` — админ-панель |
| `external_id` | text null | Stripe subscription id или Apple `originalTransactionId` |
| `updated_at`, `row_version` | | как в других таблицах |

Пишет только сервер: функции с `security definer` (вебхук Stripe, уведомления App Store, админ-панель). Приложение — только `select` своей компании.

**Пределы тарифа — константы в одной функции** `app.plan_limits(plan_key)` → `{members, modules, ai_month, ai_complex_month, ai_day, storage_bytes}`; для `trialing` — отдельные пределы ИИ (50 / 15 сложных) (как `email_company_daily_limit` [код]). Значения — §10 вопрос 2.

**Пробный — один на человека:** новое поле `users.trial_used_at timestamptz` (ставит сервер при первом пробном; защищает от бесконечного пробного через новые компании — до 5 на человека, спека 42 S32).

**Счётчики:** `public.ai_usage(company_id, day, count, complex_count)` — сложные (Sonnet, сканы чужих смет) считаются отдельно со своим пределом (этап 5, спека направления В) и байты файлов компании — сумма по `storage.objects` бакета `files` с префиксом компании (без новой таблицы, если запрос укладывается во время — проверить на объёме).

**Модули:** `company_modules.paid_until` остаётся (правило 16, шаг 1). `app.module_active()` получает второе условие: модуль включён и входит в действующий тариф компании (до N модулей по `plan_limits`). Старое условие `trial_ends_at / paid_until` модуля продолжает работать для уже включённых.

**Не заводим:** счётчик документов; плату за место; пакеты ИИ (после беты).

## 4. Статусы и переходы (внести в §5 карты)

| Из | В | Кто / когда |
|---|---|---|
| — | `trialing` | сервер при создании компании |
| `trialing` | `trialing` (+7 дней) | владелец, кнопка «Продлить на 7 дней», один раз (`trial_extended`) |
| `trialing` | `active` | вебхук оплаты; оставшиеся дни пробного **не** добавляются, `paid_until` — от Stripe / Apple |
| `trialing` | `read_only` | `trial_ends_at` прошёл без оплаты (проверка по времени в `app.company_writable()`, плюс ночная задача для уведомлений) |
| `active` | `past_due` | оплата периода не прошла → `grace_until = now() + 7 дней` |
| `past_due` | `active` | оплата прошла |
| `past_due` | `read_only` | `grace_until` прошёл |
| `read_only` | `active` | оплата |
| `active` | `active` (другой `plan_key`) | смена тарифа; понижение — с конца периода; если людей больше предела — понижение запрещено с объяснением |
| любой | удаление | владелец, `docs/specs/38-deletion.md` (Apple 5.1.1(v)) |

Запреты: `read_only` никогда не удаляет и не скрывает данные; переход не стирает приглашения и роли.

**Проверка на сервере:** `app.company_writable(company_id)` = статус `trialing` с `trial_ends_at > now()`, или `active`, или `past_due` с `grace_until > now()`. Вызывается в RLS на `insert/update/delete` всех таблиц компании (как `app.module_active` в таблицах модуля [код]). Исключения: функции страницы клиента `/p/` (подпись, оплата), вебхуки Stripe, удаление учётной записи, выгрузка.

Офлайн (правило 6): изменения, сделанные без сети после окончания срока, сервер отклонит — очередь показывает их как «не сохранено: срок оплаты вышел» (так же, как отказ модуля, `registry.ts:207` [код]), с кнопкой тарифа; ничего не теряется на телефоне до решения пользователя.

## 5. Как приходит / как уходит

- **Оплата на сайте:** Stripe Checkout + Billing (подписка на компанию), вебхук `customer.subscription.*`, `invoice.payment_failed` → `company_plans`. Новая функция `billing-webhook` (Edge), подпись Stripe проверяется.
- **Через Apple:** StoreKit 2 в приложении; подписка — группа из трёх продуктов (Solo/Crew/Company, месяц и год), **без** пробного периода Apple (пробный один — серверный, S90; иначе сроки сложатся); App Store Server Notifications V2 → функция `apple-notifications` → `company_plans`; привязка к компании через `appAccountToken` = id компании. Новая зависимость (StoreKit-обёртка или RevenueCat) — по правилу 17 и `docs/ai/CHECKS.md` §4.
- **Кнопка «Оформить на сайте»** — в приложении для витрины США (3.1.1(a)); вне США не показывать (последнее предложение 3.1.1(a)).
- **Двойная оплата:** если `source = apple`, сайт не продаёт подписку этой компании и наоборот; экран тарифа показывает, где управлять.
- **Уведомления:** за 2 дня до конца пробного, в последний день, при неудаче оплаты, при переходе в `read_only` — пуш (есть, `send-push`) + баннер; письмо владельцу — после появления отправителя писем (сейчас `email_outbox` без отправителя, `not_configured`, и предел 20 в сутки рассчитан на письма клиентам — письма о тарифе должны идти своим видом вне этого предела).
- **В `read_only` продолжают работать:** приём лидов (`lead-intake` — данные владельца, терять их нельзя), пуши, страница клиента `/p/`, вебхуки Stripe по уже выставленным счетам.
- **Выгрузка:** CSV всех сущностей + PDF документов — направление Д (админ-панель и выгрузка), доступна в любом статусе.

## 6. Настройки

| Настройка | Где | Кто | По умолчанию |
|---|---|---|---|
| Тариф, способ оплаты | Настройки → «Тариф» | владелец | пробный `crew` |
| «Продлить пробный на 7 дней» | там же, пока `trialing` и `trial_extended = false` | владелец | — |
| Продление, ручной тариф (`source = manual`) | админ-панель (направление Д) | создатель продукта, с записью в журнал | — |

Пределы — не настройка компании, а свойство тарифа.

**Кого считать «людьми» тарифа:** активные члены компании любой роли (owner, admin, office, tech); **не** считаются субподрядчики (люди другой компании, спека 42) и отключённые. **Какой модуль «входит»:** первый включённый владельцем; смена — раз в период. **Компании беты и прошлые договорённости:** до запуска оплаты никто не платит (`paid_until` модуля ставит только оператор [код]); бета-компаниям — `source = manual` через админ-панель.

## 7. Экраны

Экран «Тариф» (Настройки, владелец; остальным — только строка статуса):
1. Карточка состояния: тариф, статус значком + словом (правило 2: `info` — пробный «осталось N дней», `ok` — оплачено до даты, `warn` — оплата не прошла, `bad` — только чтение).
2. Использование: люди X из N, ИИ X из N в этом месяце, память X GB из N — полосы.
3. Три тарифа карточками `ListCard` (правило 12), одна главная кнопка `acc`.
4. «Где управлять подпиской» — Apple или сайт.
5. «Выгрузить данные» — всегда.

Баннер на главной: в последние 2 дня пробного и в `past_due` / `read_only`. В `read_only` кнопки создания и изменения скрыты или неактивны с подписью «Только чтение — оформите тариф» (не ошибкой после нажатия).

Новое правило вида (баннер срока, полосы использования) — сначала в `design/naryad-ds/DESIGN-SYSTEM.md` §2.3 и витрину. Проверка 390 / 820 / 1280 × 2 темы. Новый экран — в `SCREENS` спеки `08-layouts`.

## 8. Права, офлайн, уведомления

- `company_plans`: `select` — члены компании (`app.is_member`); запись — только `security definer`-функции; `revoke all … from anon, authenticated` сначала (CLAUDE.md, правило 18).
- Тариф видят все члены (строка статуса), меняет и платит только владелец.
- Офлайн — §4. Пробный срок считается по времени сервера; телефон показывает последнее известное значение с датой проверки.
- Учётная запись с подпиской Apple при удалении: предупреждение «отмените подписку в Apple» (5.1.1(v)).

## 10. Волны и вопросы основателю

**Волны** (этапы README аудита §2; выгрузка данных — **условие волны 3**: без неё «только чтение» = «заложники»): (1) этап 1–4 — счётчик байтов файлов, замер объёмов на бете; (2) этап 5 — `ai_usage` и потолки до открытия ИИ; (3) этап 6 — `company_plans`, `company_writable` в RLS, экран «Тариф», сайт + Stripe Billing; (4) этап 6 — StoreKit и уведомления Apple, кнопка на сайт; (5) модуль в тарифе (S96).

**Вопросы основателю** (каждый — задача с меткой `вопрос`, правило 21; списком в исследовании §9):
1. Модель: А (7 дней, потом платно, «без заложников») / Б (бесплатный с пределами) / В (низкая подписка + доля с платежей). Рекомендация — А.
2. Цены и пределы: Solo $39 (1 человек, 300 ИИ, 25 GB) / Crew $89 (до 5, 1 000 ИИ, 100 GB) / Company $179 (до 15, 3 000 ИИ, 250 GB); год — «2 месяца в подарок».
3. Модуль ниши входит в тариф (1 / 1 / 2) вместо надстройки $30 — меняет решение О1 от 07.11.
4. «+7 дней» по кнопке один раз — да / нет.
5. Цена через Apple — та же, что на сайте (рекомендация) или выше на комиссию.
6. Неоплаченные компании старше 24 месяцев — хранить или удалять с предупреждением.
7. Доля с платежей — не брать до 100 платящих (рекомендация).
8. Автоматические SMS через Twilio — платной функцией по себестоимости или не делать до выпуска.
9. Вторая своя компания: полный тариф или скидка.
10. Покупка через Apple с первого выпуска (рекомендация) или сначала только сайт (дешевле, риск отказа Apple по 3.1.3(b)).
