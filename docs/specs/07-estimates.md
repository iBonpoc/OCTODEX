# 07. Сметы: PDF подрядчика, подпись подрядчика, шаблоны — спецификация OCTODEX

> Черновик v1, 05.11.2026. Шаг хребта 4–5 «Смета → Согласие» (`docs/15-story-map.md` §3, строки 4–5; `10-build-plan.md` §0 п. 19). Шаблон — §7 карты, образец — `14-leads-spec.md`.
> Источники: код сборки 52 (`app/estimate/*`, `features/estimatePdf.ts`, `docPdf.ts`, `SignBlock.tsx`, `store.tsx` `approveEstimate`/`sendEstimate`, `app/p/[token].tsx`), база (`estimates`, `estimate_versions`, `estimate_approvals`, `memberships.can_sign_contracts`, `portal_accept`), PRD `03-prd/05-estimates.md` (EST-US-02, 13, 16, 26–31), `legal/legal-research.md` §1.6 (LEG-03).
> Estixa (`estixa_1`) только прочитана: миграция `0056_company_signers.sql`, `docs/ENTITIES.md` (раздел «Сметы, договоры и документы»), `test/e2e/estimate-templates-and-ai.spec.ts`. Что взяли и почему — §2, колонка «Почему».
> Это не юридическая консультация. Тексты договора и согласий уходят клиентам только после адвоката (`legal/README.md` п. 5); здесь — механика.

Что входит: **(1) PDF подрядчика** — один документ сметы/договора с шапкой компании, обеими подписями и журналом подписи, на языке клиента; **(2) подпись подрядчика** (countersign) — договор исполнен, только когда подписали обе стороны; **(3) шаблоны смет** — собрать смету за минуту из сохранённой.
Что не входит (свои шаги): срок отказа и Notice of Cancellation (LEG-04, нужен адвокат), change orders (шаг 7), версии смет на экране (база уже хранит), Stripe (шаг 20), модуль Gutters (после ядра, свой документ).

### 2.1 Язык приложения и язык клиента (правило основателя 05.11.2026)

Два разных языка, они никогда не смешиваются:

| | Что это | Где задаётся | На что влияет |
|---|---|---|---|
| **Язык приложения** | язык того, кто работает в OCTODEX (директор, офис, мастер) | «Мои настройки → Язык», у каждого свой: RU / EN / ES | только экраны приложения |
| **Язык клиента** (документов) | язык, на котором человек **получает** всё от компании | у клиента, у лида, у каждого человека клиента; позже — у поставщика и субподрядчика | всё, что уходит наружу: PDF сметы, договора, счёта, квитанции; страница клиента `/p/<token>`; готовые тексты SMS и писем; Notice of Cancellation |

Правила:
1. **Что бы ни делал подрядчик и на каком бы языке ни был его интерфейс, клиент получает документ на своём языке.** Директор с русским интерфейсом отправляет смету клиенту с языком EN → PDF, страница и текст SMS на английском.
2. Язык по умолчанию для клиентов — **язык страны компании** (`companies.address_country`): США → английский. ✚ Настройка компании «Язык документов по умолчанию» (меняет директор), заполняется сама по стране.
3. У каждого клиента и лида можно выставить свой язык (✚ поле у клиента; у лида и людей клиента поле уже есть). Порядок выбора — одна функция `clientLang(...)`: человек, которому отправляем → клиент → лид → язык компании по умолчанию → `en`.
4. Лид → клиент (S3): язык лида переходит к клиенту.
5. Стандартные надписи документов (заголовки, «Итого», «Депозит», условия, согласия) — через i18n на всех языках клиента; ключи одинаковые, проверяет TypeScript. Текст, который подрядчик написал сам (название строки, заметка), уходит как написан — вопрос В10.
6. Сейчас (сборка 52) это **не сделано**: язык у лида и людей хранится, но PDF, страница клиента и текст SMS берут язык интерфейса. Исправляется в волне E1 для смет и в той же волне — для счетов и квитанций (общий макет).

Как печатается: функции документов (`estimateHtml`, `invoiceHtml`, `receiptHtml`, текст SMS) получают **свой** переводчик `tFor(clientLang)`, а не `t` экрана. Тест-сторож: ни одна функция документа не принимает `t` интерфейса (проверка типов + модульный тест).

## 3. Сущности и поля (✚ — новое)

### 3.1 `Estimate` (приложение `types.ts`, база `estimates`)
- `status` — ✚ `awaiting_countersign` в приложении (в базе уже есть).
- ✚ `countersign?: EstimateCountersign` — подпись подрядчика (см. ниже).
- ✚ `executedAt?` — обе подписи есть (= `countersign.at`).
- ✚ `executedCopyAt?`, `executedCopyVia?: "portal" | "share" | "paper"` — когда клиент получил исполненную копию (первый подтверждённый способ). Нужен будущему сроку отказа (LEG-04); считать срок здесь не будем.
- ✚ `templateId?` — из какого шаблона (для отчёта «какие шаблоны продают»).

### 3.2 ✚ `EstimateCountersign` (база: строка `estimate_approvals` с `party = 'contractor'`)
`userId`, `signerName`, `signerTitle`, `signatureId` (версия сохранённой подписи), `method: "saved" | "drawn" | "auto"`, `channel: "on_site" | "app" | "auto"`, `at`, `documentHash` (отпечаток подписанной версии).
База: `estimate_approvals` + ✚ `party text not null default 'customer' check (party in ('customer','contractor'))`, ✚ `signer_user_id`, ✚ `member_signature_id`, ✚ `method`, ✚ `document_hash`. Таблица уже «только добавление» (`tg_append_only`).

### 3.3 ✚ `MemberSignature` (база ✚ `member_signatures`)
`id`, `companyId`, `userId`, `svg` (путь подписи, как у клиента), `name`, `title`, `createdAt`, `revokedAt?`. Новая подпись = новая строка, у прежней ставится `revokedAt`. Удалить нельзя. Сохранить может только сам человек.

### 3.4 ✚ `Company.contract`
`countersign: "manual" | "auto"` (по умолчанию `manual`), `autoSignerUserId?` (чья подпись ставится автоматически; только человек с правом), `showUnitPrices: boolean` (по умолчанию `true`). База: ✚ `companies.contract_settings jsonb`.

### 3.5 ✚ `EstimateTemplate` (база ✚ `estimate_templates`)
`id`, `companyId`, `name`, `doc: EstimateDoc` (варианты, строки, add-ons, скидка, налог, депозит, заметка — **без** клиента, объекта, лида), `module?: "gutters" | …` (стартовый шаблон модуля; null — свой), `showUnitPrices?`, `usedCount`, `lastUsedAt?`, `archivedAt?`, служебные поля.
Строка шаблона: как `CustomLine` + ✚ `catalogItemId?` (ссылка на позицию каталога; есть в базе у `estimate_line_items`).
Себестоимость строк в шаблоне хранится (нужна марже), видна только тем, кому видна себестоимость (`app.can_view_costs`).

### Не заводим
- Отдельную сущность `Contract` — договор = смета с подписями (§2).
- Стили и версии шаблонов документов, «чья подпись на каком документе» (Estixa) — один макет, одна настройка.
- Подпись на счетах и квитанциях.
- Папки и теги шаблонов — до 30 шаблонов хватает поиска по имени (вопрос В7).

## 4. Статусы и переходы

Сверка с §5 карты. ✚ В строку `Estimate` колонки «Приложение» добавляется `` `awaiting_countersign` `` (через чат «Leads tab implementation»: §5 карты, `statusMap.ts` — `awaiting_countersign` перестаёт сворачиваться в `sent`, `types.ts`, i18n).

| Из | В | Кто / когда | Что ещё происходит |
|---|---|---|---|
| `sent` | `awaiting_countersign` | клиент подписал на `/p/`, настройка `manual` | лид `won (approval)`, клиент `active`; уведомление и пункт «Подпишите договор» в «Требует внимания»; работы и счёта **нет** |
| `sent` | `approved` | клиент подписал на `/p/`, настройка `auto` | сервер сразу ставит подпись `autoSignerUserId` (`method=auto`) → всё из S8b |
| `sent` / `draft` | `approved` | подпись на месте: клиент + «Подписать за компанию» на том же экране | всё из S8 и S8b одной функцией |
| `awaiting_countersign` | `approved` | Д или человек с правом нажал «Подписать договор» | S8b: работа `unscheduled`, счёт на депозит, исполненная копия, уведомление клиенту на странице |
| `awaiting_countersign` | `draft` (новая версия) | Д: «Не подписывать — изменить смету» с причиной | подпись клиента остаётся в ленте и в базе, старая версия не меняется; клиент видит «Смета обновлена, подпишите снова»; лид остаётся `won`? — вопрос В3 |

Запреты:
- Менять строки и цены в `awaiting_countersign` и `approved` нельзя (версия заблокирована, база уже проверяет `tg_estimate_version_lock`).
- Подписать за компанию может только человек с `can_sign_contracts` (база: проверка в функции, тест T17). Сам себе право не выдаёт (только `owner`).
- Подпись подрядчика без подписи клиента нельзя (кроме «на месте», где они в одной функции, клиентская первой).
- Работа и счёт на депозит не создаются до `approved` (тест T18).
- Повторное нажатие «Подписать» ничего не дублирует (одна функция, идемпотентна).

Одна функция на стык (правило §4 карты): `countersignEstimate(id, by)` в сторе и `public.countersign_estimate(p_estimate_id, p_signature_id)` в базе; `portal_accept` при `auto` вызывает ту же внутреннюю функцию `app.execute_estimate()`.

## 5. Как приходит / как уходит

**Шаблон приходит:** «Сохранить как шаблон» в меню сметы (любой статус); из модуля (стартовые, ставятся при включении модуля, с пометкой «тестовые цены»); копия существующего шаблона.
**Смета из шаблона:** «Новая смета» → первая шторка «С чего начать?»: **Пустая** / список шаблонов (последние использованные сверху, поиск). Клиент, объект, лид — как сейчас (S5).
**PDF уходит:** кнопка «PDF» на смете (телефон — файл и «Поделиться», веб — печать), на странице клиента «Скачать PDF»; после S8b — «Скачать подписанный договор». Имя файла: `<номер> <фамилия клиента>.pdf`.
**Исполненная копия уходит:** страница клиента (отметка `executedCopyAt`, `via=portal` при первом открытии/скачивании); «Поделиться» с телефона (`via=share`); «Отдал на бумаге» (`via=paper`). Письмом — позже.

## 6. Настройки

«Настройки компании → Сметы и счета» (`docs/specs/05` §4.2, раздел «Сметы и счета»; меняет директор; остальные видят и знают, кого просить):

| Настройка | По умолчанию | Кто |
|---|---|---|
| Подпись за компанию: вручную / автоматически | вручную (одним нажатием сохранённой подписью) | директор (`owner`) |
| Чья подпись ставится автоматически | директор | директор; только человек с правом |
| Кто может подписывать договоры | только директор | директор (в «Команда → человек») |
| Показывать клиенту цену за единицу | да | директор; шаблон может переопределить |
| Шаблоны смет | пусто + стартовые модулей | директор, офис; мастер — только использует |

Автоматическая подпись включается с подтверждением: «Ставить мою подпись на все договоры, которые подпишет клиент» → запись в журнале (`audit_log`). Плашка «ждёт подтверждения юриста», пока адвокат не ответит (PRD §11.1 п. 3).

Личные («Настройки → Профиль → Моя подпись»): нарисовать пальцем, имя, должность; показать текущую; «Нарисовать заново» (старая остаётся в истории).

Экраны шаблонов и «Моя подпись» живут в моих файлах (`app/estimate/templates.tsx`, `app/estimate/signature.tsx`); строки-ссылки на них в «Настройках» добавляет чат «Leads tab implementation» (файлы меню и настроек — его).

## 7. Экраны

### 7.1 Смета (`/estimate/[id]`) — порядок блоков сверху вниз
1. Номер, название, сумма, статус (значок + слово; `awaiting_countersign` — **warn** «Ждёт вашей подписи»).
2. ✚ Если `awaiting_countersign` и у меня есть право: карточка «Клиент подписал {дата}. Подпишите договор» + кнопка-акцент **«Подписать договор»**. Нет права — «Ждёт подписи: {имя}».
3. Действия: Изменить · Отправить · Открыть как клиент · PDF · ✚ меню «…»: «Сохранить как шаблон».
4. Строки сметы (как сейчас).
5. Подписи: клиент (имя, дата, канал) и ✚ подрядчик (имя, должность, дата, «автоматически» / «на месте»).
6. Депозит, работа «назначить дату» — как сейчас, но только после `approved`.

### 7.2 Шторка «Подписать договор»
Сводка: клиент, вариант, итог, депозит; «Открыть PDF» (проверить перед подписью). Сохранённая подпись крупно + **«Подписать»** (одно нажатие). «Нарисовать другую» — `SignaturePad`. Подписи нет — сразу `SignaturePad` + «Сохранить как мою подпись» (по умолчанию вкл.). После подписи — тост «Договор подписан. Работа ждёт даты» + «Отменить» 5 секунд (отмена до синхронизации; после — только «Не подписывать» не применяется к исполненному).

### 7.3 Подпись на месте (`est.signOnSite`)
После подписи клиента в том же блоке: «Теперь подпишите за компанию» (если у мастера есть право) или «Договор подпишет {директор}; клиент получит копию на странице» (если нет).

### 7.4 «С чего начать?» (новая смета) и «Шаблоны смет» (`/estimate/templates`)
- Шторка: «Пустая смета» строкой, затем шаблоны строками (меню выбора — строками, правило 12): имя, число вариантов, «от $X» (итог рекомендованного варианта по текущему каталогу).
- Экран «Шаблоны смет»: список карточками (`CardList` + `ItemCard`): имя, варианты, использован N раз, метка модуля. Карточка → шаблон в том же конструкторе (`/estimate/new?template=<id>`), без клиента. Архив вместо удаления (+ «Отменить»).
- Пусто: «Сохраните любую смету как шаблон — меню «…» на смете».

### 7.5 PDF (печатный макет, токены `print`)
Шапка компании (логотип, имя, адрес, контакты, лицензии) | справа «Estimate / Contract EST-0012», дата, «Valid until». Клиент: имя, телефон, email, адрес объекта. Варианты (до подписи — все; после — выбранный с add-ons). Итоги. Заметка, условия компании, обязательные блоки (по типу договора, когда будут от юриста). Подписи: две колонки «Customer» / «Contractor» (линия, имя, дата; пустая линия до подписи). Последняя страница — «Signature record»: кто, когда (время с зоной), канал, отпечаток документа. Подвал: «EST-0012 · Page 1 of 2».

### 7.6 Страница клиента `/p/<token>`
После подписи клиента при `manual`: «Вы подписали. Договор подпишет {компания}; копия появится здесь». Депозит — после `approved`. После `approved`: «Договор подписан обеими сторонами» + «Скачать подписанный договор».

Ширины: 390 — один столбец, шторки снизу; 820 / 1280 — смета слева, подписи и действия справа (как сейчас). Цвета только статусов: warn «ждёт подписи», ok «подписан обеими сторонами».

## 8. Права, офлайн, уведомления

| Действие | Директор | Офис (`dispatcher`) | Мастер | Клиент |

| Настройки подписи компании | ✓ | видит | — | — |
| Своя подпись | ✓ | ✓ | ✓ | — |
| Шаблоны: создать, изменить, архив | ✓ | ✓ | — | — |
| Шаблоны: использовать | ✓ | ✓ | ✓ | — |
| Себестоимость в шаблоне | ✓ | по `can_view_costs` | — | — |

База: RLS на `member_signatures` (читать — своя компания; добавить — только своя строка; изменить — только `revoked_at` своей), `estimate_templates` (компания; писать — `owner/admin/office`), `countersign_estimate` — `security definer` с проверкой `can_sign_contracts`. Новая миграция начинает с `revoke all … from anon, authenticated`.

Офлайн: подпись за компанию работает без сети (сохранённая подпись на телефоне, очередь); на сервере применяется, если версия не менялась (тот же `document_hash`), иначе — конфликт директору. Шаблоны и PDF — офлайн (PDF строится на телефоне той же функцией). Подпись клиента на `/p/` и автоподпись — только при сети.

Уведомления: «{Клиент} подписал EST-0012 — подпишите договор» (пуш людям с правом; повтор через 24 ч и пункт в «Требует внимания» — правило attention, файл общий → через чат «Leads tab implementation»). «Договор EST-0012 исполнен» — в ленте сметы и клиента.
