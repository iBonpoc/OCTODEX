## 2. Брейншторм: что нужно подрядчику с телефона

Вечер после замера: смета клиенту ушла (или подписана). Подрядчик хочет **одной кнопкой** из сметы получить заказы по поставщикам (рулон и крепёж — у одного, водостоки и колена — у другого), поправить количество, **одним нажатием** разослать всем менеджерам поставщиков, себе — копию, бригаде — свой лист без цен, клиенту — чертёж.

| Вопрос | Варианты | Решение |
|---|---|---|
| Откуда заказ | А. только из работы (как сейчас); Б. **из сметы любого статуса**, из работы — как раньше; В. отдельный «конструктор» заказа без сметы | **Б**: слова основателя «из любой сметы»; у неподписанной — предупреждение (PRD 11, 03.11). «Новый заказ» на склад остаётся (37 §6) |
| Как Gutters попадает в заказ | А. свой лист MO-1 (как сейчас); Б. **слот `purchaseLines`**: модуль отдаёт строки, заказ — ядра; В. модуль пишет заказы сам | **Б**: «редактируется там же, где остальные заказы»; MO-1 и заказ считаются одной функцией модуля → не разойдутся |
| Чем «разослать всем» | А. «Поделиться» PDF по одному (как сейчас: N заказов = N раз выбрать почту и адрес); Б. на телефоне — черновики писем `mailto:` по очереди; В. **сервер шлёт письма** (очередь в базе → функция почты), с телефона одна кнопка | **В**: единственный способ «одним нажатием» и без сети (очередь). Пока нет почты площадки (#637 домен) — честный запасной путь Б с подсказкой «Почта ещё не подключена: письма откроются по одному» (§4.5) |
| PDF во вложении | А. сервер собирает PDF (нет браузера в Deno — 07-email §2); Б. телефон кладёт PDF в хранилище; В. **заказ таблицей в теле письма** (HTML + текст) | **В** сейчас: сервер строит письмо из строк базы, ничего не берёт из запроса; вложение PDF — позже вместе с П2 почты (07-email §2 вариант Б/В) |
| Несколько почт | А. текст через запятую; Б. **список адресов** (до 5) с подписью «Mike — sales»; В. контакты поставщика (люди с телефонами) | **Б**: «отдельными полями»; контакты-люди — позже |

## 4. Решение (только недостающее)

### 4.1. Заказ из любой сметы (ядро; стык S11b — расширение)
- **Где кнопка:** экран сметы (`app/estimate/[id]`), меню «⋯» и блок «Заказы поставщикам» (тот же `JobOrdersBlock`, обобщённый до «источника»: смета или работа). Видят owner, admin, office (`canEditOrders`); мастер и sales — нет.
- **Шторка «Заказ поставщикам»** (новая, одна): вариант сметы (чипы, если их больше одного; по умолчанию — утверждённый, иначе рекомендованный, иначе первый), «С дополнениями» (только у неподписанной; у подписанной — выбранные клиентом), затем по поставщику строка «ABC Supply — 6 позиций», ниже предупреждения:
  - смета не подписана: «Смета не подписана — материалы останутся за вами» (`warn` + слово; PRD 11, 03.11);
  - «3 позиции без поставщика» → «Назначить» (шторка выбора позиции → карточка позиции, S0c; после возврата шторка пересчитывается) — в заказ **не** идут (оспаривание №5);
  - позиция без упаковки — как сейчас «проверьте упаковку».
  Кнопка `acc` «Создать N заказов» → черновики (или открыть существующий черновик этого поставщика по этой смете). Одна кнопка — одно создание (защита от двойного нажатия, как `sending` в `purchase-order/[id].tsx:91`). «Отменить» 5 с (правило 5).
- **Строки:** материалы выбранного варианта (как `jobMaterialNeeds`, но из `estimateId` + `optionId`) + строки модулей через слот (§6). Деньги и количества — только движок (`sumQty`, `purchasePacks`).
- **Смета ↔ работа:** заказ помнит `estimate_id` и `estimate_option_id`. Когда смета становится работой (подпись), сервер дописывает `job_id` заказам этой сметы (§5) — мастер видит их в работе (T155 не меняется).
- **Смета изменилась после заказа** (новая версия, другой вариант подписан): на карточке заказа и в блоке — «Смета изменилась после заказа» (`warn` + слово), кнопка «Пересчитать черновик» только у `draft`; отправленный не трогаем (снова «Отправить» = новая ревизия, как сейчас). Признак — вычисляемый: версия сметы новее `created_at` заказа или подписан другой вариант.

### 4.2. Несколько почт у поставщика (ядро; стык S0c — расширение)
- Карточка поставщика `/suppliers/[id]`: блок «Почта для заказов» — до **5** строк «адрес + подпись (необязательно: Mike — sales)», «＋ Добавить почту», удалить строку — с «Отменить». Первая строка = прежнее поле `email` (старые телефоны видят и правят его).
- Проверка адреса — та же `emailBad` (`features/suppliers.ts`), повтор адреса — ошибка поля.
- На карточке заказа под поставщиком — «Кому: 3 адреса» (раскрывается списком).

### 4.3. Gutters в заказе ядра (модуль; стык S11g — реализация)
- `purchaseLines` модуля = **та же функция**, что строки MO-1 (`orderRows`, `view/shop/schedules.ts:109`): детали движка с `use ≠ estimate` (рулон или секции, трубы, заклёпки, крепёж, герметик) с позицией каталога; деталь без позиции — в заказ не идёт, в шторке строкой «Нет в прайсе: 2 детали → Цены и прайс» (модуль отдаёт её как `missing`, §6).
- Строка модуля **заменяет** строку ядра той же позиции (как сейчас, `purchaseOrders.ts:79`), а готовые длины сметы (жёлоб в футах, сделанный из рулона, — `use = estimate`) модуль **гасит**: отдаёт `{ catalogItemId, qty: "0", replace: true }` — чтобы подрядчик не заказал «120 ft K-style» вместо рулона (§6).
- Какой чертёж: замеры из строк выбранного варианта (`source.measurementId`). Подписанная смета — ревизия, на которую ссылаются строки (`source.revisionId`): телефон читает `parts` только этих ревизий (П25.5 H4, `data.ts`); ревизии нет на телефоне — текущий чертёж и пометка строки «проверьте по чертежу».
- «Документы» замера: строка MO-1 → строка **«Заказы поставщикам»**: нет заказов — «Создать из сметы EST-12» (шторка §4.1), есть — «Заказы: 2 · отправлен, черновик» → блок заказов сметы. Нет сметы — строка серая «Сначала смета».
- Лист заказа MO-1 как отдельный документ больше не выдаётся (единый заказ — ядра). Ведомости G-листов не меняются.

### 4.4. Сводный документ «для себя» (ядро)
- В блоке заказов сметы или работы: «Сводный PDF» — все заказы источника, по поставщикам: поставщик, адреса, № заказа, статус, строки (SKU, позиция, кол-во, ед.); цены — только у `costsVisible` и переключателем «С ценами» (по умолчанию выкл.).
- Язык — приложения (документ для себя и своих); переключатель «На английском» — если отдают кому-то вне компании. Печать/«Поделиться» — как PDF сметы (`saveEstimatePdf`).

### 4.5. Отправка: всем, одному, себе (ядро; новый стык S11c)
- **«Отправить всем»** (блок заказов источника): заказы `draft`/`sent`-с-изменениями, у которых есть поставщик, строки и хотя бы одна почта; шторка-подтверждение: «Отправить 3 заказа: ABC Supply (2 адреса), Beacon (1), Gutter Supply (3)? · Копию мне ☐» → одно нажатие. Без почты у поставщика — строка «нет почты → Добавить» и такой заказ не идёт (остальные идут).
- **Одному:** на карточке заказа «Отправить» → то же окно для одного: адреса поставщика (галочки, по умолчанию все), «Копию мне», «Поделиться PDF» (как сейчас) — второй строкой.
- **Себе:** «Копию мне» — на почту **учётной записи отправителя** (сервер берёт её сам, адреса из запроса нет); и «Сводный PDF мне на почту» (§4.4) тем же путём.
- **Как уходит:** приложение отмечает заказы отправленными (`po.send`, как сейчас: снимок поставщика, ревизия + 1) и ставит в очередь `po.email` (`public.po_email_send(po_ids, self)`). Сервер кладёт по строке на заказ в `po_emails` (§5), адреса — из **снимка** заказа. Письмо: тема «PO-0012 from Acme Gutters», тело — таблица строк (как PDF), без цен при `print_prices = false`, `Reply-To` — почта компании и отправителя; язык — английский.
- **Без почты площадки** (нет домена, #637; статус строки `not_configured`): приложение говорит «Почта ещё не подключена — письма откроются по одному» и открывает `mailto:` с адресами поставщика и текстом заказа по очереди («Письмо 1 из 3 → Дальше»). Заказ отмечен отправленным в обоих случаях. После подключения почты запасной путь исчезает сам.
- **Без сети:** «Отправить всем» — заказы и `po.email` в очередь; «В очереди: 3 письма» на блоке; уйдут, когда операции дойдут до сервера (номер заказа сервер даёт раньше — строка вставки идёт первой в очереди).
- **Статус письма** на карточке заказа: «Отправлено 3 адресам · 15.11 7:40» / «В очереди» / «Не отправлено: адрес отклонён» (`bad` + слово) с «Отправить ещё раз».

### 4.6. Чертёж в смете и отдельно (ядро + модуль; стык S6g — расширение)
- Редактор сметы: блок «Страницы» (если у сметы есть страницы-вложения) — строка на страницу «Чертёж замера · 1 стр.» с переключателем «В смете» (по умолчанию вкл.). Выкл. — страница не идёт в PDF, на `/p/` и в отпечаток подписи; «Обновить смету» её не возвращает. Это поле ядра (`EstimateDoc.pagesOff?: string[]`), модуль о нём не знает: `withMeasurementPage` смотрит `pagesOff` (§6).
- «Документы» замера, строка «Клиенту» при готовой смете: кроме «Открыть смету» — вторая кнопка «Только чертёж» (PDF без цен, язык клиента — `pdf("client")`, как без сметы).
- Экран сметы, меню «⋯»: «Страницы отдельно» — ядро печатает **только страницы-вложения** сметы (`pagesHtml(doc.pages)`, без строк и цен) отдельным PDF на языке документа сметы. Модуль не нужен, нового слота нет.

### 4.7. PDF исполнителю (модуль; стык S10b — расширение)
- «PDF бригаде» (`drawingPdf.ts`) получает **ведомость водостоков**: D1… — на каком желобе (№) и на каком расстоянии от ближнего конца, выпуск (outlet: размер и форма), переходник, колена по видам, отступы, высота (чего нет в замере — «TBD», как shop-drawings §4) — и **концы желобов**: №, начинается / кончается (заглушка левая/правая, угол, водосток в конце). Источник — `view/shop/model.ts` (то же, что G-листы), чтобы документы не расходились.
- Открыть из **работы** (S10b): блок «Документы» работы Gutters — «Для бригады» (ревизия подписанной версии, П25.5) — через слот модуля для работы (§6). Язык — приложения отправителя; меню «Язык документа: EN / ES / RU» (бригада и субподрядчик часто говорят на другом языке). Без цен — всегда.
