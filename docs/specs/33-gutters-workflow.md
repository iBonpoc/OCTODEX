## П24.1 Как делают другие (ресёрч, 09.11; источники — help-центры)
- Визит висит на заявке до клиента; при переводе в клиента всё идёт за ним (Jobber request → assessment → convert). У нас: замер на лиде, при конверсии — за ним (П24.3 Б4).
- Черновик заводится сразу, привязывается потом (Hover: draft job при приглашении).
- Один замер — несколько документов: предложение, заказ материала, наряд бригаде (Roofr); количества живые при рисовании (ArcSite).
- Разной аудитории — разное: домовладельцу без размеров/цен (Hover), цены и количества — настройкой (Jobber), материал — с ценами или без (Hover).
- Заказ поставщику из списка материалов: строка → артикул → заказ → подтверждение поставщика (Hover + ABC Supply).
- Подписанная смета не правится — изменение отдельным change order на разницу (ServiceTitan).
- Смета ссылается на версию чертежа, у чертежа история версий (ArcSite).
- Запись с документами не удаляется жёстко — сначала архив (Roofr).
- **Чего не повторять:** вложения не попадают в PDF (Housecall Pro, ServiceTitan — клиент, распечатавший смету, чертежа не видит) → у нас чертёж — страницей внутри PDF сметы; фото теряются при конверсии (Jobber) → у нас замер и фото идут за лидом; правка подписанной сметы снимает подпись (Jobber) → у нас подписанная не правится; желоба как «данные крыши» (Hover, EagleView: только карниз) → у нас желоба, углы, водостоки — свои данные.

## П24.2 Оспаривание (PLANNING)
1. «Кнопку замера перенести только в смету» (основатель 09.11) — **оспорено**: замер чаще делают до сметы (выезд по лиду), один замер даёт несколько смет; вход из сметы — **добавляется**, входы из лида, клиента, адреса, выезда остаются.
2. «Себестоимость — документ модуля» — **опровергнуто**: себестоимость и маржа — правило ядра (`costsVisible`, мастер не видит); модуль только кладёт цену закупки в строки. Отдельного PDF себестоимости у модуля нет.
3. «Заказ поставщику — документ модуля» — **опровергнуто**: заказ — сущность ядра (спека 36); модуль даёт строки через `purchaseLines`.
4. «Хранить готовые PDF» — **опровергнуто**: PDF строится по запросу из текущих данных; при отправке клиенту ядро сохраняет отправленное (как сейчас со сметой). Для сметы фиксируется **снимок чертежа** (ревизия) — смета всегда показывает тот чертёж, по которому считана.
5. «Черновик без клиента не нужен» — **подтверждено, что нужен**: на улице до знакомства с хозяином, основатель пользуется (П20.22).

**Д. Отправка.** Смета уходит как сейчас (SMS / письмо, язык клиента); в PDF сметы и на `/p/` — чертёж её ревизии. `/p/` читает документ через белый список `app.client_doc` (спека 33-estimate :66), `source` клиенту срезается, у anon нет доступа к таблицам модуля — поэтому **общее поле ядра в версии сметы** «страницы-вложения» (SVG без цен, на языке клиента; модуль кладёт туда снимок при «Сделать смету» / «Перенести изменения»), поле добавляется в `client_doc` + тест T; ядро не называет модуль. **Е. Хранение и офлайн.** Замер живёт на телефоне (`moduleData.gutters`), каждая правка — `module.op` в очередь, на сервере — таблицы модуля под RLS; черновик без лида и адреса виден офису компании, **мастеру — только свои черновики** (`gutter_sees`); автосохранение (П20.21, #694). **CCPA (#533):** функции удаления клиента в ядре пока нет (S22, 7а-3). Когда будет — **своя миграция модуля**: триггер на удаление `properties` / `leads` мягко удаляет их замеры (без SQL ядра с таблицами gutter); смена `on delete set null` — правилом 16 (новое ограничение `not valid` + `validate`, старое снять отдельным шагом).

**Ж. Модуль выключен / пробный срок кончился (S0b).** Входы А1–А7 скрыты; открытые замеры — только просмотр; правки, привязка, удаление отвергаются сервером (`module_active`) и в приложении не предлагаются; PDF и `/p/` смет, уже отправленных, показывают сохранённый снимок. Тест: e2e (входы скрыты, просмотр есть) + тест базы (правка отвергнута).

| **Б (выбрано)** | **примитивы**: плоские объекты только из скаляров (линия, круг, ромб, подложка, текст), цвета — имена печатных токенов | безопасно по устройству (нет разметки — нечего внедрять); белый список сервера проверяет типы; рисует ядро и в PDF (HTML с `esc`), и на `/p/` (react-native-svg); ядро не знает модуль | чуть больше кода в ядре |

**Решение:** необязательное поле ядра `EstimateDoc.pages?: DocAttachPage[]` («страницы-вложения»): `{ id, title, note?, w, h, items: Prim[], head?: string[], rows?: string[][] }`. Модуль кладёт свою страницу (id `gutters:<measurementId>`) при «Сделать смету» / «Перенести изменения» — заменяет только свою; текст — на языке клиента (`docLanguageFor`), это снимок: смена языка клиента позже его не меняет, «Перенести изменения» перерисует. Страница входит в `calc_inputs` → в отпечаток подписи (клиент подписывает то, что видел). Ядро рисует страницу после строк сметы в PDF (`estimatePdf.ts`) и на `/p/` (`EstimateView`/`[token].tsx`); старые версии без `pages` — как раньше.

**security-check (этап 0, 10.11) — обязательно, вошло в план:**
1. Тип по ключу: свой помощник `app.doc_prim(jsonb)` — числа только `number`, строки только `string`, `ink` ∈ (ink, mut), `fill` ∈ (paper, ink); незнакомый `t` или не тот тип — примитив выброшен целиком. В приложении цвет — словарь имя→токен с запасным.
2. Пределы чисел: |x| ≤ 1e5; `r`, `sw`, `fs` > 0 и с потолком; в JS — `Number.isFinite`, иначе пропуск.
3. Нагрузка: при чтении — `ordinality ≤ N` до `jsonb_agg` (страниц ≤ 4, примитивов ≤ 3000 на страницу, строк таблицы ≤ 200, столбцов ≤ 12), `left(s, 200)` — страховка; **при записи — отказ**: триггер на `estimate_versions` (размер `pages` ≤ 512 КБ и те же пределы) + та же проверка в приложении перед сохранением.
4. Длинная строка при записи **отклоняется**, а не обрезается: клиент подписывает полный `calc_inputs`.
5. JS-двойник очистки `clientPages` (в `clientDoc`, в нормализации при чтении) с общими примерами для vitest и теста базы — как `zeroQty`.
6. PDF: `esc()` на все строки, числа — только через формат конечного числа; `/p/` — текст только детьми `<Text>`, без `<image>`/`href`.
7. Модуль собирает таблицу из фиксированных столбцов (№, длина, этаж, профиль, цвет), без заметок и денег — тест модуля.
8. T: anon через `portal_estimate` получает очищенные страницы (вложенный объект, строка вместо числа, `<script>` в `ink`, незнакомый `t`, сверх пределов); отправка с `pages` проходит `lock_lines_match`; у помощника нет execute у public/anon/authenticated. Порядок — `with ordinality … order by`; `id` страницы ≤ 64, уникален. Правило 16: старые сборки, теряющие `pages` при правке, — модуль кладёт страницу заново при «Перенести изменения».
