## П24.1 Как делают другие (ресёрч, 09.11; источники — help-центры)
- Визит висит на заявке до клиента; при переводе в клиента всё идёт за ним (Jobber request → assessment → convert). У нас: замер на лиде, при конверсии — за ним (П24.3 Б4).
- Черновик заводится сразу, привязывается потом (Hover: draft job при приглашении).
- Один замер — несколько документов: предложение, заказ материала, наряд бригаде (Roofr); количества живые при рисовании (ArcSite).
- Разной аудитории — разное: домовладельцу без размеров/цен (Hover), цены и количества — настройкой (Jobber), материал — с ценами или без (Hover).
- Заказ поставщику из списка материалов: строка → артикул → заказ → подтверждение поставщика (Hover + ABC Supply).
- Подписанная смета не правится — изменение отдельным change order на разницу (ServiceTitan).
- Смета ссылается на версию чертежа, у чертежа история версий (ArcSite).
- Запись с документами не удаляется жёстко — сначала архив (Roofr).
- **Чего не повторять:** вложения не попадают в PDF (Housecall Pro, ServiceTitan — клиент, распечатавший смету, чертежа не видит) → у нас чертёж — страницей внутри PDF сметы; фото теряются при конверсии (Jobber) → у нас замер и фото идут за лидом; правка подписанной сметы снимает подпись (Jobber) → у нас подписанная не правится; желоба как «данные крыши» (Hover, EagleView: только карниз) → у нас желоба, углы, водостоки — свои данные.

## П24.2 Оспаривание (PLANNING)
1. «Кнопку замера перенести только в смету» (основатель 09.11) — **оспорено**: замер чаще делают до сметы (выезд по лиду), один замер даёт несколько смет; вход из сметы — **добавляется**, входы из лида, клиента, адреса, выезда остаются.
2. «Себестоимость — документ модуля» — **опровергнуто**: себестоимость и маржа — правило ядра (`costsVisible`, мастер не видит); модуль только кладёт цену закупки в строки. Отдельного PDF себестоимости у модуля нет.
3. «Заказ поставщику — документ модуля» — **опровергнуто**: заказ — сущность ядра (спека 36); модуль даёт строки через `purchaseLines`.
4. «Хранить готовые PDF» — **опровергнуто**: PDF строится по запросу из текущих данных; при отправке клиенту ядро сохраняет отправленное (как сейчас со сметой). Для сметы фиксируется **снимок чертежа** (ревизия) — смета всегда показывает тот чертёж, по которому считана.
5. «Черновик без клиента не нужен» — **подтверждено, что нужен**: на улице до знакомства с хозяином, основатель пользуется (П20.22).

**Д. Отправка.** Смета уходит как сейчас (SMS / письмо, язык клиента); в PDF сметы и на `/p/` — чертёж её ревизии. `/p/` читает документ через белый список `app.client_doc` (спека 33-estimate :66), `source` клиенту срезается, у anon нет доступа к таблицам модуля — поэтому **общее поле ядра в версии сметы** «страницы-вложения» (SVG без цен, на языке клиента; модуль кладёт туда снимок при «Сделать смету» / «Перенести изменения»), поле добавляется в `client_doc` + тест T; ядро не называет модуль. **Е. Хранение и офлайн.** Замер живёт на телефоне (`moduleData.gutters`), каждая правка — `module.op` в очередь, на сервере — таблицы модуля под RLS; черновик без лида и адреса виден офису компании, **мастеру — только свои черновики** (`gutter_sees`); автосохранение (П20.21, #694). **CCPA (#533):** функции удаления клиента в ядре пока нет (S22, 7а-3). Когда будет — **своя миграция модуля**: триггер на удаление `properties` / `leads` мягко удаляет их замеры (без SQL ядра с таблицами gutter); смена `on delete set null` — правилом 16 (новое ограничение `not valid` + `validate`, старое снять отдельным шагом).

**Ж. Модуль выключен / пробный срок кончился (S0b).** Входы А1–А7 скрыты; открытые замеры — только просмотр; правки, привязка, удаление отвергаются сервером (`module_active`) и в приложении не предлагаются; PDF и `/p/` смет, уже отправленных, показывают сохранённый снимок. **security-check (этап 0, 10.11) — обязательно, вошло в план:**
1. Тип по ключу: свой помощник `app.doc_prim(jsonb)` — числа только `number`, строки только `string`, `ink` ∈ (ink, mut), `fill` ∈ (paper, ink); незнакомый `t` или не тот тип — примитив выброшен целиком. В приложении цвет — словарь имя→токен с запасным.

5. JS-двойник очистки `clientPages` (в `clientDoc`, в нормализации при чтении) с общими примерами для vitest и теста базы — как `zeroQty`.

### П25.3 Решение: экраны
**А. Дом модуля — «Замеры»** (`/module/gutters/list`; вкладка, «＋ → Замеры», карточка модуля).
- Шапка: «Замеры», справа главная кнопка **«Новый замер»** (`acc`, единственная на экране) → холст нового черновика.
- Поиск (`FilterBar` ядра): по имени лида/клиента, адресу, телефону. Фильтры-чипы с числом: **Все · Черновики · Без сметы · Со сметой · Подписаны** (П25.4). Выбранный фильтр и поиск помнятся на телефоне (как в других списках, `filterBar`).
- Карточка замера (`ListCard`, правило 12; рецепт — новый `measurement` в `06-list-cards.md`, согласовать с чатом «Карточки списков»): заголовок — кто (имя клиента, «Лид: имя», иначе «Без клиента»); значок состояния и слово (П25.4); факты — адрес, «N желобов · M фт · K водостоков»; дата правки; метка «примерно» не нужна на карточке (она — на листе).
- Пусто: «Замеров пока нет» + «Новый замер». Фильтр пуст: «В этом фильтре пусто» + «Показать все».
- Нажатие → карточка замера. **1280:** список слева, карточка справа в `ListPanel` ядра (как другие списки, спека 06 «Панель 1280»; карточка в списке выбрана `selected`, «⤢ Открыть» — отдельной страницей); **390 и 820** — переход на `/module/gutters/view?m=` (как у других списков на 820).
- Удаление (спека 38 PR-G): смахивание влево на 390 → «Удалить»; «Выбрать» в шапке (Д/Дп) → «Выбрано N» → «Удалить N»; замер с подписанной сметой — пропуск с общей причиной ядра `trash.why.signed` (спека 38 §4.1). До PR-G спеки 38 — «Удалить» только в «⋯» карточки (мягко, «Отменить» 5 с).

**Б. Карточка замера** (`/module/gutters/view?m=` — развитие «Просмотра замера», П25.2 №3). Сверху вниз:
1. **Шапка:** кто (клиент / «Лид: имя» / «Без клиента») и адрес; значок состояния (П25.4); пометка «Примерно» или «Рулетка». Нажатие на «кто» → «Привязать к другому» / «Отвязать (в черновики)» (те же функции, что в «⋯» холста; `LinkSheet`). Черновик: вместо «кто» — кнопка «Привязать к клиенту или лиду». «⋯» справа: **«Точность замера»**, **«Дублировать»**, **«Удалить»** (тон `bad`; при подписанной смете — пункт виден, нажатие объясняет запрет).
2. **Лист** «как на бумаге» (П24.8), нажатие — во весь экран (масштаб пальцами). Пусто — «Нарисуйте желоба» и «Править чертёж».
3. **Одна главная кнопка** по состоянию (как сейчас, `estimateAction`): «Привязать к клиенту или лиду» → «Сделать смету» → «Открыть смету» / «Перенести изменения в смету» (с пояснением) → подписана: «Открыть смету». Рядом вторичная «Править чертёж».

Язык — клиента (`clientLangOf`, правило 7).

| `unlinked` | нет лида и адреса | Черновики | `neutral` «Черновик» |

| `estimate` | есть смета, ни одна не подписана | Со сметой | статус самой новой сметы ядра (слова и тон `statusMap` ядра: «Черновик сметы», «Отправлена», «Открыта клиентом»…); чертёж правили после неё — `warn` «Чертёж изменён» (тот же признак, что `staleMeasurements`) |
| `signed` | есть смета по замеру в `awaiting_countersign` или `approved` (`SIGNED`, `estimateLink.ts:24` — тот же набор, что запрет удаления) | Подписаны | `ok` «Подписан»; правили после подписи — второй меткой `warn` «Изменён после подписи» (признак §5 карты, В4 П24.3) |
«Все» — все неудалённые. Смета «по замеру» — строки `origin = module` с `source.measurementId` (`ofMeasurement`, как «сметы по замеру» сейчас). Счётчики фильтров считаются той же функцией.

### П25.5 «Для поставщика»: список деталей, цены, заказ (#515)
- **Один источник:** чистая функция модуля `supplierList(drawing, settings, prices)` → строки `{ catalogItemId?, name, sku?, qty, unit, note }` (`catalogItemId` нет — деталь «Нет в прайсе»: в документе есть, в слот не идёт — `ModulePurchaseLine.catalogItemId` обязателен, `features/purchaseOrders.ts:9`) (материалы движка + детали «только для закупки»: заклёпки, крепёж, герметик — `use = purchase` спеки 33-parts; упаковки — `purchaseQty`). Её же зовёт слот **`purchaseLines(job, db, data)`** (#515): по работе берётся замер из строк одобренной версии сметы (`source.measurementId`, ревизия `source.revisionId` — тот чертёж, что подписан) → строки заказа ядра. Так документ и заказ совпадают (unit-тест сравнивает строки **с позицией каталога**). Для этого телефону нужны ревизии: `loadGutters` сейчас читает только замеры и элементы (`data.ts:195`) — H4 добавляет чтение `gutter_measurement_revisions` (id, замер, `elements`, `parts`) **только для ревизий, на которые ссылаются утверждённые сметы** (немного строк); без ревизии на телефоне — слот берёт текущий чертёж и ставит `note` «проверьте по чертежу».
- **Экран «Для поставщика»** (из «Открыть»): строки-детали (одна карточка, `ListRow`), количество и единица; **owner, admin, office** (`costsVisible` и не мастер) — ещё столбец «Себестоимость» (цена закупки из прайса модуля × кол-во) и итог «Материалы по себестоимости» (деньги — движком, центы, правило 8); **мастер** — без цен; тестовые цены — с пометкой «тестовые» (правило 9). Деталь без позиции каталога — пометка «Нет в прайсе» (`warn`) и ссылка «Цены и прайс».
- **Копия поставщику** («Отправить»): PDF «MATERIAL LIST» на английском (спека 37 №13), компания, адрес объекта без имени клиента (спека 37 №14), строки (SKU, описание, кол-во, ед.), **без цен — всегда** (не переключатель), «Not a purchase order». До подписи это просьба о цене/наличии, не заказ.
- **«Заказ поставщику»:** работа появляется только при `approved` (`features/estimateSign.ts:81,98`), а заказ ядра — из работы. Поэтому:
  - смета не подписана — кнопка серая, подсказка «Появится, когда клиент подпишет смету»;
  - клиент подписал, компания ещё нет (`awaiting_countersign`) — серая, подсказка «Клиент подписал — подпишите смету от компании» и ссылка на смету (подпись подрядчика, S8b);
  - утверждена (`Job.estimateId` есть) — активна: **переход на работу** `/job/[id]` к блоку «Заказы поставщикам» (`features/JobOrdersBlock.tsx`), где ядро делает черновики по поставщикам (`makeJobOrders`, `data/store.tsx:2207`) со строками модуля через слот. Так ядро не меняется: у `ModuleStore` (`registry.ts:64`) вызова заказа нет и в П25 не добавляется;
  - заказы уже есть — «Заказы: N» и статусы ядра значком и словом (по одному на поставщика), нажатие — та же работа.
  Кнопку видят те, кому ядро даёт писать заказы (`canEditOrders`: владелец, админ, офис); мастер и продажи — нет.

**Таблица** (шаг 1 правила 16 — только новое): `id`, `company_id`, `measurement_id` (FK, `on delete cascade`), `revision_id` (ревизия чертежа на момент отправки — замороженная `gutter_measurement_revisions`; нет свежей — создаётся при отправке), `audience` (`client` / `crew` / `supplier`), `channel` (`share` / `sms` / `email` / `download`), `to_label` (кому — имя или «Поделиться», ≤ 120), `lang` (`en` / `es` / `ru`), `pages jsonb` (копия: те же примитивы, что «страницы-вложения» П24.7, проверка `app.doc_pages_problem` при записи, ≤ 512 КБ), `sent_by`, `sent_at`, `created_at`.
- Только добавление: `update` и `delete` запрещены (страж модуля, как `t01_frozen`); мягкое удаление замера прячет и его отправки — **своим условием в политике** `select` (`exists` замера с `deleted_at is null`), потому что `gutter_sees_measurement` удалённые не отсекает (`20261107180000_gutter_measurements.sql:180`).
- RLS + FORCE, `revoke all … from anon, authenticated`, затем `grant select, insert`: видит тот, кто видит замер (`gutter_sees`); пишет сотрудник, кто видит замер, при `module_active`; `sent_by = auth.uid()`; `company_id` — из замера (триггер), не от клиента. Проверка `pages` — триггер модуля `security definer` (`set search_path = ''`): `app.doc_pages_problem` отозван у authenticated (`20261111010000_doc_pages.sql:115`); правило 18 для новых функций. Миграция — на чистой и текущей базе (правило 15).
- **Цены в копии:** копия клиенту и поставщику строится аудиторией без цен (функции модуля не принимают цены для этих аудиторий — unit); копия бригаде — без цен. Себестоимость в таблицу не попадает никогда. Тест базы — запись с `audience = supplier` не содержит ключей денег (проверка `pages` на сервере: те же примитивы, денег там нет по устройству).
- Когда пишется: после того как PDF передан в «Поделиться» телефона (`expo-sharing` не говорит, выбрал ли человек получателя, поэтому канал так и называется — `share`, «Передано в „Поделиться“»; веб — после окна печати, `download`). SMS и письмо самим приложением (`sms` / `email`) — когда ядро даст отправку документа модуля (сейчас только смета). Отправку сметы ядра модуль не пишет (у сметы своя история). Без сети — запись в очередь (`module.op` `send.add`), PDF собирается на телефоне (правило 6).
- Поставщику уходит копия, а в истории видна «что получил поставщик»; клиенту без сметы — лист его языка.
