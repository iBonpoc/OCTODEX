## 1. Проблема
Скрин основателя («Лиды», 390): над списком **шесть рядов** — переключатель «Лиды · Сметы · Счета», поиск, три ряда чипов статуса (из них три с нулём), два ряда источников. Первая карточка начинается на **415 pt из 844** — на середине экрана (`img/31-before-leads-390.png`). На 1280 то же самое: четыре ряда над строками.

Причина в коде одна: `ChoiceChips` переносит чипы на новые строки (`src/ui/controls.tsx:542`, `flexWrap: "wrap"`), а каждый экран ставит свой набор рядов сам.

## 5. Варианты
**А. FilterBar везде, как есть** (поиск отдельным рядом, ниже лента статусов, «Фильтры» в конце ленты). Плюс: готово, один компонент. Минус: на «Лидах» всё равно три ряда (переключатель, поиск, лента); кнопка «Фильтры» уезжает за край ленты и её не видно — не понятно, что источники есть.

**Б. Ряд поиска + лента статусов** (рекомендую). Ряд 1 — поиск и справа кнопка «Фильтр» со значком и числом выбранного. Ряд 2 — одна лента статусов с числами, без переноса, нули скрыты. Всё прочее (источник, ответственный, мастер, метки, способ, даты, сортировка) — в шторке «Фильтр» группами. Выбранное из шторки — строкой «Google ✕ · Мои ✕ · Сбросить» под лентой, только когда выбрано. Над списком всегда **не больше двух рядов**; третий — только строка выбранного.

**В. Всё в одну кнопку** (как iOS Mail): поиск и «Фильтр», статус тоже в шторке. Плюс: один ряд. Минус: статус — главное, что подрядчик меняет 10 раз в день; два нажатия вместо одного; не видно чисел «Без ответа · 2».

**Переключатель «Лиды · Сметы · Счета»** — убирается совсем (решение основателя 07.11): это три раздела, каждый своим экраном (§7а).

## 6. Правило (вариант Б)
1. **Сверху вниз:** шапка экрана → **ряд 1: поиск + «Фильтр»** → **ряд 2: лента статусов** → (строка выбранного) → «Без сети · N» → список.
2. **Поиск есть на каждом списке, где больше 10 объектов бывает в жизни** (лиды, сметы, счета, работы, клиенты, задачи, каталог, оплаты, расходы). Ищет по имени, телефону, адресу, номеру (LEA, EST, INV, JOB, RCT, CLT) — 06 §6 п.3. Поиск идёт **поверх** выбранного статуса; если по статусу ничего, а во «Все» есть — в пустом состоянии «Найдено во „Все“ · N → Показать».
3. **Кнопка «Фильтр»** — справа в ряду поиска, всегда видна: значок `sliders`, слово только на 1280; при выбранном — рамка `ink` и число («Фильтр · 2»). Нет доп. фильтров у списка — кнопки нет, поиск на всю ширину.
4. **Лента статусов:** одна строка без переноса, прокрутка вбок (колесо мыши и клавиши на вебе — как в FilterBar). Первый — широкий охват по умолчанию («В работе», «Открытые», «Должны», «Активные»), затем остальные **по ходу работы** (как статусы в карте §5), «Все» — последним. Число — у каждого. **Чип с нулём скрыт**, кроме выбранного (иначе человек теряет, где он). Не больше ~6 чипов: остальное — в шторку.
5. **Шторка «Фильтр»:** группы с заголовком (Источник, Ответственный, Мастер, Метки, Способ оплаты, Период, Сортировка). Внутри — строки (`FilterRow`, правило 12), у строки число; строка с нулём показана `mut` с «0», её можно выбрать (чтобы не прыгал список при смене статуса). Внизу «Сбросить» (если есть выбранное) и «Готово». Сортировка — одиночный выбор, по умолчанию «как сейчас».
6. **Строка выбранного:** только если в шторке что-то выбрано: «Google ✕ · Alex ✕ · Сбросить». Каждая ✕ — своя цель 44. Пустой список при выбранном — «Ничего по фильтру» + «Сбросить фильтры» (06 §6 п.7).
7. **Что помнится:** статус, доп. фильтры и сортировка — на этом устройстве, для каждого списка отдельно (`usePersistentState`, ключ `octo.filter.<list>.v1`), до «Сбросить». Поиск не помнится. Переход по ссылке с фильтром (`?f=owed` с «Ждёт оплаты» на Главной, из «Требует внимания», со «Должен» у клиента) ставит фильтр **на этот заход** и сохранённый не трогает.
8. **Цвет:** чипы и кнопка без цвета статуса (выбранный — рамка `ink` на `surf2`, 06 решение 1); жёлтый на экране один — «＋» (правило 2). Цвет статуса — только на карточках.
9. **Ширины.**
   - 390: два ряда; лента прокручивается; шторка снизу.
   - 820: то же; лента обычно помещается без прокрутки.
   - 1280: **один ряд**: поиск (ширина `panel-w` 360) · лента статусов целиком · справа кнопки доп. фильтров прямо в ряду («Источник ▾», «Ответственный ▾» — выпадающее меню строками, то же содержимое, что в шторке) · выбранное — строкой с ✕ под рядом, как на телефоне (так ряд не переносится при длинных метках). Сортировка — по подписям колонок `ListCardHeader`.
10. **Доступность:** лента — `radiogroup`, чип — `radio` с `checked`; «Фильтр» — кнопка «Фильтры, выбрано N»; строка шторки — `checkbox`; ✕ — «Убрать фильтр: Google». Зона нажатия 44 (Android 48), видимые 28/32/36 (правило 3). Текст масштабируется, лента не обрезает слова.
11. **Обе темы:** только токены, контраст рамки `ink` и `mut`-текста ≥ 4.5:1 — как у FilterBar.

## 8. Компонент
Развить `FilterBar` (не новый, PR 1): `search` — ряд 1; `groups` (`FilterGroup`: заголовок, строки с числом и `on`, `onToggle`) — шторка группами, на 1280 — кнопка на группу («Метки ▾») с шторкой этой группы; `onReset`; строка выбранного считается из групп (`chosenFilters`); кнопка «Фильтр» — в ряду поиска (`testID filter-button`), число на ней — `activeFilterCount`.
