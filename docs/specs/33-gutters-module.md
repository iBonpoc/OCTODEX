## 2. Брейншторм: что нужно подрядчику с телефона

Путь основателя сегодня: на бумажке — стороны дома, длины, этаж, углы, водостоки, guards; дома считает. Нужно: **на объекте за 3–5 минут получить цену трёх пакетов и отправить смету**, а бригаде — что нарезать и что взять.

### 2.1 Как замерять (главный вопрос)
| Вариант | Плюсы | Минусы |
|---|---|---|
| А. **По сторонам дома** (карточка на сторону: длина, этаж, водостоки, снять старые, сетка; углы на весь дом) | Как на бумажке; 1 сторона = 1 бесшовный кусок → нарезка без геометрии; работает в перчатках, без сети, без фото; мало нажатий | Нет картинки для клиента; углы считаются «на глаз» |
| Б. Чертёж по своему фото (масштаб по известной длине, линии, водостоки) | Наглядно, картинка в смету/бригаде; код уже есть | Дольше, калибровка ошибается, фото 1 стороны за раз |
| В. Спутник по адресу | «Вау», замер до выезда | **Запрещено** условиями Google и Mapbox (ADR-004) |
| Г. Импорт отчёта EagleView/Hover | Лицензия у подрядчика | Платно, не мгновенно, партнёрские заявки — позже |
| Д. Одной формой (LF по этажам, PRD GUT-US-14) | Быстрее всего | Нет кусков для нарезки, нет «какая сторона» |

**Рекомендация: А как главный, Б как дополнительный** (фото даёт те же стороны). В и Г — нет в MVP (ADR-004). Д поглощается А (одна сторона = «весь дом»).

### 2.2 Как модуль встраивается в ядро
| Вариант | Плюсы | Минусы |
|---|---|---|
| А. **Слоты ядра**: ядро показывает карточки модуля в «Осмотре», «Объекте», «Смете» (кнопка «Из замера»), «Работе»; модуль заполняет строки обычной сметы | Смета, подпись, задаток, работа — одни на всех; модуль маленький | Нужен общий механизм слотов (общие файлы) |
| Б. Своя «смета гаттеров» модуля (как старая быстрая смета) | Быстро | Две сметы, дубль денег и подписи — против решения 04.11 |
**Рекомендация: А.**

### 2.3 BOM (материалы) в смете
PRD 06 кладёт материалы в смету скрытыми строками с ценой 0. В универсальной смете скрытых строк нет, и это правильно: клиенту и PDF они не нужны. **Рекомендация:** материалы — данные замера модуля (по выбранному пакету), себестоимость материалов входит в `unitCostCents` видимой строки (маржа считается как сейчас).

## 4. Решение (рекомендация, ждёт ответов основателя)
1. **Включение**: «Ещё → Настройки → Направления и модули → Модули → Gutters» (владелец, админ). Выключен — в приложении нет экранов и слов модуля.
2. **Осмотр** (экран ядра `visit/[id]`): карточка модуля «Замер гаттеров» → «Замерить по сторонам» (акцент) или «По своему фото».
3. **Замер по сторонам**: итоги сверху (LF, LF 2+ эт., водостоки, углы), карточка на сторону, шторка стороны (длина ft-in, этаж 1/2/3/4+, водостоки, снять старые, сетка), углы на весь дом. Дисклеймер точности.
4. **По фото**: своё фото, масштаб по известной длине, линии (этаж — стиль линии и подпись), водостоки; каждая линия → сторона.
5. **Пакеты**: Good / Better ★ / Best с итогами и составом; материалы — панель (только директор и офис видят себестоимость).
6. **Смета**: «Создать смету с тремя пакетами» → обычная смета ядра (черновик), строки с меткой «из замера»; задаток, налог, подпись, отправка — ядро. Тестовые цены — предупреждение.
7. **Работа** (экран ядра): карточки модуля «Нарезка» (кусок на сторону, coil по цвету с запасом) и «Материалы» (без цен); чек-лист «Перед монтажом» — стартовый шаблон модуля в механизме спеки 08.
8. **Настройки модуля**: высоты этажей, крепления, колена, запас coil, удлинение водостока, пакеты.

## 5. Данные (черновик для PR кода)
### 5.1 Ядро: общее место для модулей (без слова gutter)
- `Company.modules?: Record<ModuleId, { on: boolean; settings?: unknown }>`; `ModuleId = "gutters"` — строка-ключ в реестре модулей (`src/modules/index.ts`), ядро знает только реестр.
- Слоты: `ModuleSlot = "visit.card" | "property.card" | "estimate.fromModule" | "job.card" | "settings.module"`; реестр отдаёт компоненты по слоту, если модуль включён. Ядро рендерит `<ModuleSlots slot=… ctx=…/>`.
- База: `companies.modules jsonb not null default '{}'` (правило 16 — только добавление), меняют owner/admin (RLS, тест базы).
### 5.2 Модуль
- `GutterMeasure` (таблица модуля `gutter_measures`): `id, companyId, propertyId, visitId?, sides: Side[], outsideCorners, insideCorners, photo?: {fileId, calibration, lines[]}, constantsOverride?, updatedAt, updatedBy`. `Side = {id, name, ft (decimal str), story, downspouts, tearOff, guards, heightOverrideFt?}`.
- Движок: `measureToGutterInput(measure)` → `GutterInput` (каждая сторона — run со своим этажом, свободные концы по углам); `buildGutterOptions(input, map, presets)` → `CustomOption[]` для `EstimateDoc` (новое, рядом с `buildGbbOptions`); `cutList(measure)`, `materials(input, preset)`.
### 5.3 Каталог
