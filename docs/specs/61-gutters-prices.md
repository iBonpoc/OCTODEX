- «Когда открываю позицию, к примеру downspout extension, должна быть возможность выбрать единицу измерения, потому что downspout extension должен считаться в футах».
- «Это у меня будет огромнейший каталог… Сверху должен быть переключатель, что я хочу настроить: тип (форма) gutter, размер gutter, downspout, размер и форма downspout… материал. Типа фильтров… Подумай, как сделать это удобно».

## 2. Как устроено сейчас (разбор `main`, только чтение)
1. «Детали» на экране — детали **одной** образцовой работы по настройкам компании по умолчанию (`prices.ts` `sampleJob` → `materialRows`) и цвета замеров без позиции (#2000). Другие системы, которые компания ставит («Что ставим», `Offer`), на экране не видны: цену 6″ Fascia не задать, пока она не станет «по умолчанию» или не появится в замере.
2. Работа (`laborRows`) — один список на всё.
3. Единица детали задана в движке у каждой детали (`gutterParts.ts`, `acc.add`): extension — `ea` (стр. ~898), flex / drain — `ft`. Цена находится только при той же единице (`findItem`, `groupSource`: `it.unit === p.unit`, `prices.ts:54,79`). Позиция extension, переведённая в `ft` в общем каталоге, перестаёт находиться — деталь становится «нет в прайсе».
4. Чего нет в движке по стендам `docs/prototypes/gutters-ref` — не эта задача (правило 28д), заведено по семьям: outlets oval / square — #2135; guards Hinged / Drop-In и коробки — #2136; крепёж стендов — #2137; заготовки coil 7″ / 8″ / Half Round, Box / Euro — #2138; признаки цены splash_pan / rain_chain / outlet_screen / wye — #2139.

## 4. Решение

### 4.1. «Система» вверху — три поля прямо на экране
- Под шапкой, до списков: карточка «Система» (`Card`, `testID` `gpr-system`) с тремя строками `SelectField` (спека 56 стр. 4, значение формы), каждая — меню у строки:
  - **Желоб** — форма и размер одним значением («5″ K-Style», «6″ Fascia», «5″ Half Round»): только пары из «Что ставим» (`Offer.profiles` × `Offer.sizes`);
  - **Водосток** — форма и размер («2×3», «3×4», «3″ Round»): из `Offer.dsSizes`;
  - **Материал** — из `Offer.materials` (толщина — по умолчанию материала, `GAUGES_BY_MATERIAL` / настройки).
  Выбор применяется сразу, список под карточкой обновляется. Шторки нет (design-reviewer 18.11: шторка с тремя полями, закрывающаяся после первого, — 9 нажатий на смену системы; меню вылезало за шторку на 390). Цвет в систему не входит: цена одна на все цвета (`33-gutters-price-key.md` §4); подпись карточки — «Цена одна на все цвета».
- **По умолчанию** — система последнего изменённого замера компании (первый участок и первый водосток), нет замеров — настройки по умолчанию (`newRunAttrs` / `newDsAttrs`). Выбранная система помнится на устройстве (`octo.filter.gutters-prices.v1`), как фильтр списка (DS §5.5); значение, которого больше нет в «Что ставим», — сброс на умолчание.
- «Все системы» одним списком — нет (решение руководителя 18.11 до ответа основателя): одна система и поиск.

### 4.2. Список деталей выбранной системы
- «Детали» строятся той же функцией, что сейчас (`materialRows`), но по образцу работы **выбранной** системы: `sampleJob(raw, system)`. Цвета замеров без позиции (#2000) — только той же системы.
- Под баннером, над списками — один `FilterBar` (DS §5.5): поиск лупой (по названию, регистр не важен; ищет и в деталях, и в работе) и лента из 6: «Без цены · Желоб · Водосток · Guards · Расходники · Все». «Без цены» — строки без позиции (первым — то, ради чего экран открывают; design-reviewer 18.11 №5, ServiceTitan); «Желоб» — разделы сметы gutter, corners_caps, fasteners; «Водосток» — downspouts, adapters, ds_bottom; «Guards» — guards; «Расходники» — consumables. «Все» — по умолчанию и последним; когда выбрано «Все», лента стоит в начале (видны «Без цены», «Желоб», «Водосток»; design-reviewer №3). Нулевые скрыты (кроме выбранного), нули считаются с учётом поиска. Одна строка с прокруткой. Внутри «Все», «Без цены», «Желоб», «Водосток» — подзаголовки разделов сметы (`SECTION_ORDER`, те же подписи). Лента помнится, поиск — нет.
- Порядок: **сначала «Детали» выбранной системы, «Работа» — последним разделом** (design-reviewer №4: сменил систему — меняется то, что видно сразу). Работа без системы (у работы нет формы и размера); видна под «Все» и «Без цены», под разделами деталей — нет.
- Поиск ищет только в выбранной системе; под «Найдено: N» — строка «В других системах: M ›» (`ListRow`), если там есть совпадения: нажатие ставит систему первой найденной детали (design-reviewer №7).
- Карточки — `ListCard`, как сейчас (правило 12); у карточки с ценой — цена без чипа «В прайсе» (design-reviewer №6: стена одинаковых чипов, DS Б9; баннер уже считает строки без цены); у детали без позиции — «— / ea».
- Вводный абзац экрана — под «?» у заголовка (DS Б7, §12.2), подзаголовок «Gutters» под заголовком убрать (есть в «‹ Gutters»).
- Карточки — `ListCard`, как сейчас (правило 12); «— / ea» у детали без позиции.

### 4.3. Баннер и «Создать позиции сразу»
- «Нет цены: N» (DS Б9, один баннер) считает строки **выбранной системы** и работы; «Создать позиции сразу» создаёт их же (позиции образца, правило 9, `stableItemId` — те же id, что у этой детали в любой системе).
- Заголовок баннера — «Нет цены: 7» (Б9: называет состояние), пояснение — «в этой системе и в работе; добавит позиции с примерными ценами» (design-reviewer №8: систему не повторять трижды).

### 4.4. Единица extension (#2140, К1, отдельный PR после 4.1–4.3)
- Настройка модуля `extUnit: "ea" | "ft"` и длина вывода `extLengthIn` (по умолчанию 48 = 4 ft) — одна на компанию (решение руководителя 18.11; правка у водостока на холсте — позже, отдельной задачей).
- Движок: при `ft` деталь `bottom.extension` идёт в `ft`, количество = длина вывода × водостоки с выводом; при `ea` — как сейчас.
- Экран: у строки extension — `SelectField` «Единица ⌄» (шт / фут) и при «фут» — поле длины (суффикс ft, DS А6.2; компонент поля длины модуля). Одна запись меняет настройку модуля и единицу найденной позиции; тост «Отменить» 5 с (правило 5).
- Другая единица — только у extension (решение руководителя 18.11).
- **Правило 16:** старая сборка считает extension в `ea` и не найдёт позицию в `ft` → строка «нет в прайсе», сумма не врёт (принято руководителем 18.11). Позиции в `ea` не удаляются.
- `GUTTER_PARTS_VERSION` — следующая.

### 4.5. Чего не меняем
Ядро, база, RLS, группы цены и переход «Одна цена на все цвета» (`33-gutters-price-key.md` §4), права (правит персонал с себестоимостью; монтажник — только чтение; модуль выключен — экрана нет), вход «⋯» (#2128).

## 5. Оспаривание
- *Система — `FilterBar` целиком (группы «Желоб / Водосток / Материал» в шторке «Фильтр»)?* Нет: в шторке фильтра значения сбрасываются «Сбросить» и могут быть пустыми, а система — всегда ровно одно значение каждого поля; основатель сказал «сверху переключатель» — строка видна, а не спрятана за «Фильтр».
- *Три меню в ряд вверху?* Нет: на 390 три подписи не помещаются в одну строку (правило DS «ряд в две строки — нет»). Три строки `SelectField` одна под другой — да (≈ 3 × 44, «переключатель сверху» виден без нажатия).
- *Строка-итог «Система ›» и шторка?* Было в первом прототипе; design-reviewer 18.11: смена всей системы — 9 нажатий, меню вылезает за шторку на 390. Отказались.
- *Список по всем системам сразу?* Сотни строк, «нет цены: 412» не помогает; основатель: «огромнейший каталог». Поиск закрывает «найти одну позицию».
- *Система замера по умолчанию — какая, если в замере две системы?* Первый участок и первый водосток; остальные — выбором (1 нажатие).

## 6. Приёмка (сценарии; у теста тот же номер)
- **С1.** ДАНО в «Что ставим» 5″ K и 6″ Fascia, по умолчанию 5″ K, замеров нет. КОГДА офис открывает «Цены и прайс». ТОГДА поля «Система»: Желоб 5″ K-Style, водосток и материал по умолчанию; детали — 5″ K, «Работа» — после них.
- **С2.** ДАНО как С1. КОГДА поле «Желоб» → «6″ Fascia». ТОГДА детали — 6″ Fascia (гаттер, заглушки L/R, углы, крепёж Fascia), без 5″ K.
- **С3.** ДАНО последний изменённый замер — 6″ Fascia, 3×4, Copper. КОГДА экран открыт впервые на устройстве. ТОГДА система — 6″ Fascia · 3×4 · Copper.
- **С4.** ДАНО выбрана 6″ Fascia. КОГДА экран закрыт и открыт снова. ТОГДА 6″ Fascia (помнится); после удаления 6″ Fascia из «Что ставим» — система по умолчанию.
- **С5.** ДАНО у 6″ Fascia нет позиций у 7 деталей. КОГДА экран. ТОГДА баннер «Нет цены: 7»; лента «Без цены» — 7 строк; «Создать позиции сразу» создаёт 7 позиций, повторное нажатие — ничего.
- **С6.** ДАНО позиция «6″ Fascia End Cap – Left» создана при системе 6″ Fascia. КОГДА система 5″ K. ТОГДА её нет в списке; заглушки 5″ K — свои строки.
- **С7.** ДАНО система 5″ K. КОГДА поиск «cap». ТОГДА только строки с «cap» в названии (детали и работа); есть «6″ Fascia End Cap» — строка «В других системах: 1 ›», нажатие ставит 6″ Fascia; очистка поиска — весь список.
- **С8.** ДАНО система 5″ K. КОГДА лента «Guards». ТОГДА только детали раздела guards, «Работа» скрыта; разделов без строк в ленте нет.
- **С9.** ДАНО монтажник. КОГДА экран. ТОГДА поля «Система» и поиск работают, цены — только чтение, баннер «спросите офис».
- **С10.** ДАНО (PR #2140) extension «ft», длина 4 ft, два водостока с выводом. КОГДА смета. ТОГДА строка extension 8 ft по цене позиции в ft; при «ea» — 2 шт, как до PR.
- **С11.** ДАНО (PR #2140) позиция extension в ea, сумма сметы S. КОГДА «Единица» → фут. ТОГДА позиция в ft, настройка `extUnit = ft`; «Отменить» возвращает обе.
- **С12.** ДАНО (PR #2140) старая сборка, настройка `ft`, позиция в ft. КОГДА смета на старой сборке. ТОГДА extension «нет в прайсе», остальная сумма та же (правило 16).

Тесты: модульные — `sampleJob` по системе, система по умолчанию из замера, отбор по разделу и поиску (`gutterPricesSystem.test.ts`, С1–С8); e2e **507** — С1, С2, С5, С7, С9, 6 видов. PR #2140: тесты движка (С10, С12), модульные (С11), e2e — номер у руководителя. Натив: не касается (меню, поиск — компоненты `src/ui`).
