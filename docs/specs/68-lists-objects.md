## 2. Главный вывод

Находки делятся на две кучи:

- **(А) Долг: код не делает того, что уже решено** в DS и правилах. Выбор основателя не нужен — волны кода; где DS сам противоречив или правила нет — сначала правка DS отдельным PR (§2.3), потом код.
- **(Б) Вопрос основателю** — только то, что DS не решил или где два решения основателя расходятся (§6). Каждый — на веб-странице «как есть | как будет» (#2750) двумя снимками и советом.

Проверка трёх помощников показала: **большая часть первоначальных «предложений» уже решена в DS** (место главной кнопки, вторая кнопка — в «⋯», шапка списков, поиск, плитки не в слотах списка) — они перенесены в А. **Логика главного шага в коде продумана** (лид — `leadTurn`/`LeadStep`, клиент — `clientNextStep`, счёт — `invoiceNext`, выезд — шаги `app/visit/[id].tsx`); меняем только конкретные случаи, где она спорит со статусом или с решением основателя.

Самое важное для «простого пользователя» (#2754, #2757, #2758):
1. Лид, заведённый после разговора, просит «Ответить» («Клиент ждёт 0 мин») — сметы на экране нет (вопрос В4).
2. Одобренная смета предлагает «Выставить остаток $3,078.00» до начала работ (вопрос В3, деньги).
3. Одно и то же — по-разному: главная кнопка карточки в шести местах; создание — пятью способами; шапка — трёх видов; фильтры — пяти; одно дело — разными словами.
4. Лишние переходы: «＋» с меню из одного пункта; работы и задачи — 3–4 нажатия через «Ещё»; плитки опускают список до середины экрана.

**Предложение по В8** (согласовано crm-reviewer и design-reviewer 26.11; картинка — на странице): срок — та же настройка компании (`leadSettings.remindDays`, по умолчанию 3), в Настройках называется общо — «Напомнить клиенту через N дн.»; новой настройки нет. Срок считается от отправки или последнего напоминания; **сбрасывают** подпись, отказ, ответ клиента (SMS, письмо, звонок в журнале) и новое напоминание; **просмотр не сбрасывает** («смотрел, но не подписал» — лучший повод напомнить), просмотры показываются в строке. Пока срок не прошёл: «Отправлена 2 ч назад · не подписана», «Напомнить» — `secondary` (не жёлтая), видна всегда, не в «⋯». Срок прошёл: плашка статуса warn «Без ответа · N дн» (значок `alert` + слово), «Напомнить» — `primary`, пункт в «Требует внимания» — один на смету; после «Напомнить» пункт уходит до следующего срока; после `lostOrWaitDays` (14) — вопрос «Потеряна или ждём?», а не новое напоминание; больше трёх — группой «Сметы без ответа · N».

**Предложение по В7** (согласовано, картинка — на странице): на сегментах «Счета / Сметы / Оплаты» те же суммы — три плитки в одну строку («Ждёт оплаты», «Просрочено», «Получено»), четвёртая («Ещё выставить») — строкой под ними со «›»; цифра плитки — уменьшенным кеглем (токен, до кода — правка DS §12.12), без обрезки на 390; выбранная плитка — по §9 (заливка + `CheckMark`), не жёлтая (долг П9). Экран «Деньги» без сегментов — не трогаем. Отдельными задачами (не в этой паре): плитки «про оплату» на сегменте «Сметы» (нужны «Ждут ответа · Одобрены · Ещё выставить»); «Сегодня» на «Деньгах» повторяет «Оплачены сегодня».

- **С8.** ДАНО смета отправлена 2 часа назад, срок компании «Напомнить через 3 дн.». КОГДА директор открывает смету. ТОГДА под заголовком «Отправлена 2 ч назад · не открыта», кнопка «Напомнить» видна на экране (контурная), признака «Без ответа» нет.
