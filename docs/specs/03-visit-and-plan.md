>     **Решения П3c:**
>     1. **Одно правило** `visitLate(v, now, lateAfterMin = SCHEDULE_DEFAULTS.lateAfterMin)` в `features/schedule.ts`: выезд открыт (`isOpenVisit`), на нём есть люди (`assigneesOf` не пуст — без людей это «Не назначено», а не «опаздывает»), шаг `scheduled` или `en_route`, ни один пункт чек-листа не отмечен, и `now ≥ начало + 15 мин`. В `начало + 15:00` — уже опаздывает, в `начало + 14:59` — ещё нет. Снимают **только** «на месте» и любой шаг дальше (`on_site`, `working`, `signed`, `paid`, `done`), закрытый выезд (`closed`) или первый отмеченный пункт чек-листа; «в пути» не снимает (решение основателя 05.11). Порог — `SCHEDULE_DEFAULTS.lateAfterMin = 15`, настройка компании — П4 (§6.1). Осмотр и работа опаздывают одинаково.
>     2. `lateKind(v, now)` → `"en_route" | "not_left" | null` — для подписи: **«Опаздывает · в пути»** (шаг `en_route`) и **«Опаздывает · не выехал»** (шаг `scheduled`). `attention.ts`, `visits.tsx` и `listSigns.ts` вызывают только её и сами ничего не проверяют. `listSigns.ts` — файл чата карточек: он переводит `visitSigns` на `lateKind` сам (ключи подписей отдаём ему); мы правим `attention.ts` и `visits.tsx`.
>     3. **Время «выехал»**: `Visit.enRouteAt` в приложении, `visits.en_route_at` в базе (миграция `20261105360000_visit_en_route.sql`, номер выдал руководитель 05.11). Ставит стор в момент «в пути» по часам телефона и передаёт в операции очереди (`ops.ts`, шаг выезда), `repo.ts` читает обратно — чтобы офлайн-очередь не сдвинула время на момент синхронизации. Охрана мастера (`20261105170000`) дописывается: `en_route_at` ставится только вместе с переходом в `en_route`, после — не меняется; время, которому сервер не может верить (позже `now() + 5 мин`, раньше создания выезда или старше 3 дней), заменяется на `now()` — не отказ, чтобы не застряла офлайн-очередь (security-check П3c); поменять или стереть поставленное — отказ. Старые выезды без времени — подпись без «с HH:MM».

### 2.3 Решения и почему

| Тема | Решение | Почему |
|---|---|---|
| Осмотр — работа или выезд? | Выезд вида «осмотр», привязан к лиду (или к клиенту) и объекту; **работы нет** | Работа — это «что продали». Осмотр до продажи как работа плодит пустые работы и лишние статусы `lead` / `estimate` (`15` §9). У Jobber так же: осмотр — часть заявки. В базе это уже разрешено (`visits.lead_id`) |
| Одна форма выезда | Осмотр, работа, перенос — одна и та же шторка | Меньше учить, меньше кода, один тест на правила |
| Дата и время | Чипы «Сегодня / Завтра / ближайшие дни» + «Другая дата» (календарь месяца); время — свободные слоты выбранного мастера по рабочим часам + «другое время» | Чипы на 21 день (сейчас) не дают записать через месяц; слоты сразу показывают, где окно |
| Мастер по умолчанию | Тот, кто ведёт лид, если он выезжает; иначе «назначит диспетчер» | В компании основателя директор и ведёт лид, и едет на осмотр — ноль лишних нажатий |
| Несколько мастеров | Можно выбрать нескольких; выезд виден в колонке каждого | Монтаж часто вдвоём; база уже хранит список |
| Накладки | Предупреждение по пересечению времени, сохранить можно | Владелец знает лучше (короткий осмотр по пути); у HCP и в PRD 07 — так же |
| Перенос | Кнопка «Перенести» везде; перетаскивание — дополнительно | Перетаскивание на телефоне неточное и недоступно для части людей; кнопка проверяется тестом |
| Отмена | Всегда с причиной; выезд остаётся в ленте лида / работы; тост «Отменить» 5 с | Правило 5 и «ничего не удаляется на стыке» |

| Подтверждение клиенту | MVP — готовый текст со своего телефона; «Запуск» — автописьмо и напоминание за 24 ч | SMS с номера компании без согласия нарушает TCPA (`14` §1) |

## 4. Статусы и переходы

### 4.1 Выезд
```
scheduled ──► en_route ──► on_site ──► working ──► signed ──► paid      (выезд работы, шаг 7)
scheduled ──► en_route ──► on_site ──► done                          (осмотр; или работа без оплаты на месте)
scheduled / en_route ──► cancelled (с причиной)
```
| Переход | Кто | Как |
|---|---|---|
| создан → `scheduled` | Д, Дп | «Записать осмотр» / «Запланировать» — только с датой и временем |
| перенос (время, день, длительность, мастера) | Д, Дп | статус не меняется; запись в ленте «было → стало» |
| → `cancelled` | Д, Дп | причина обязательна: клиент отменил · клиента не было дома · перенесём, дату не знаем · мы отменили · другое (текст). «Клиента не было дома» в базе хранится как `no_show` |
| `scheduled` → `en_route` → `on_site` → … | М | шаг 7; «в пути» можно пропустить |
| → `done` | М, Д | осмотр: «Готово» на объекте |
| вернуть отменённый | Д, Дп | только через тост «Отменить» (5 с); потом — новый выезд |

Запреты: нельзя перенести или отменить выезд в `on_site` и дальше (мастер уже на месте — только через «Работы», шаг 7). Нельзя создать выезд в прошлом (кроме сегодняшнего прошедшего часа — запись задним числом «уже съездил», с пометкой в ленте).

### 4.2 Лид (сверено с `15` §5 и `14` §3.1)
| Событие | Было → стало |
|---|---|
| Записан осмотр | `new` / `replied` → `booked`. Из `new` дополнительно ставится `firstResponseAt` (записать на осмотр — это ответ) |
| Осмотр перенесён | `booked` остаётся |
| Отменён **последний** открытый осмотр | `booked` → `replied` (авто, событие в ленте, «Чей ход» = «⚠ нет шага» → шторка «Что дальше?») |
| Осмотр `done` | `booked` остаётся; «Чей ход» = «Шаг: сделать смету» |
| Записать осмотр у `estimate_sent` (второй выезд) | статус не меняется |
| Записать осмотр у `won` / `lost` / `declined` | нельзя: сначала «Открыть снова» (для `won` осмотр записывается на клиента) |

### 4.3 Работа
| Событие | Было → стало |
|---|---|
| Подпись (S8) | — → `unscheduled` (уже есть) |
| Первый выезд с датой | `unscheduled` → `scheduled` (уже есть) |
| Отменён последний открытый выезд | `scheduled` → `unscheduled` (снова «Ждёт даты», снова пункт в «Разборе») |
| Перенос | статус не меняется |
| Первый выезд `on_site` и дальше | шаг 7 |

## 7. Экраны

Общее: карточки — `CardList` + `ItemCard` / `VisitCard`; меню выбора в шторках (мастер, клиент) — строками; цвета только статусные и всегда со словом; одна кнопка акцента на экране; обе темы, ширины 390 / 820 / 1280.

Цвета выезда (уже так, кроме новых): назначен — neutral; без мастера — warn «Не назначено»; в пути / на месте / работа — info; ждёт оплаты — warn; оплачен / готово — ok; ✚опаздывает — warn «Опаздывает»; ✚накладка — warn «Накладка»; ✚отменён — neutral «Отменён» (только в ленте). «Ждёт даты» — warn.

### 7.1 Шторка «Форма выезда» (одна на «Записать осмотр», «Запланировать работу», «Перенести»)
Сверху вниз:
1. **Шапка**: «Осмотр · Linda Alvarez» / «Работа · Замена ограждения» / «Перенести выезд»; адрес строкой (нажать — поправить адрес объекта). Для работы — сумма и «уже выездов: N».
2. **Дата**: чипы «Сегодня · Завтра · Ср 6 · Чт 7 · Пт 8 · Сб 9 · Пн 11» + «Другая дата» (календарь месяца). Дни вне рабочих — бледнее, но выбрать можно.
3. **Мастер**: строки с аватаром, именем и занятостью на выбранный день («свободен» / «2 выезда, 10:00–12:00, 14:00–15:00»); можно отметить нескольких; первая строка — «Назначит диспетчер».
4. **Время**: чипы свободных слотов выбранного мастера в рабочих часах шагом из настроек; «Другое время» (−/+ как сейчас). Без мастера — все слоты рабочего дня.
5. **Длительность**: степпер, значение по умолчанию из настроек / модуля / работы.
6. **Заметка мастеру** (необязательно, одна строка, раскрывается).
7. **Предупреждения** (warn, со словом): «Иван занят 10:00–12:00», «Вне рабочих часов», «Прошедшее время». Сохранить можно.
8. **Итог строкой**: «Ср, Nov 6 · 10:00–10:45 · Иван. Клиент увидит окно 10:00–12:00».
9. Кнопка «Записать» / «Запланировать» / «Перенести» (акцент).

После сохранения: тост «Записано: ср 10:00 · Отменить» (5 с) и шторка «Сообщить клиенту?» — готовый текст на языке клиента: SMS · Email · Скопировать · «Не сейчас». Отправка отмечает `customerNotifiedAt`.
Обычная запись: ≤ 3 нажатия (дата → время → «Записать»), если мастер подставился сам.

Ширины: 390 — шторка снизу на весь экран; 820 и 1280 — шторка справа шириной формы, «План» под ней остаётся виден.

### 7.2 Вкладка «План»
Сверху вниз (390):
1. **Шапка**: «План», переключатель День · Неделя · Месяц, кнопка «+» (для Д, Дп).
2. **Навигация**: ‹ дата / диапазон › и «Сегодня» (если не сегодня) — уже есть.
3. **Чей план**: чипы «Все · Я · Иван · Мигель…» (Д, Дп; у мастера ряда нет — только свои).
4. **Ждут даты · N** (Д, Дп; warn): карточки работ без даты — клиент, работа, сумма, «подписал 2 дня назад» → «Запланировать». Свёрнуто до 2 карточек, «Показать все».
5. **Режим «День»**: ряд дней недели с числом выездов (есть) → «Не назначено · N» (warn, карточки + «Назначить», перетаскивание на человека — есть) → колонка на каждого человека: аватар, имя, «Выездов: N» / «Свободен», карточки выездов по времени.
6. **Режим «Неделя»**: 7 дней, у каждого заголовок с числом и карточки (время · клиент · мастер) — есть; ✚«+» у дня.
7. **Режим «Месяц»**: сетка с числом выездов; жёлтое число — есть без мастера — есть.
8. **Пусто**: «Выездов нет» + «Записать осмотр» / «Запланировать работу» (если есть ждущие даты).

**Карточка выезда в «Плане»** (`VisitCard`, уже есть) + ✚значок вида («Осмотр» / «Работа»), ✚чип «Опаздывает» / «Накладка», ✚аватары всех назначенных. Нажатие — карточка выезда.

**Ширины.**
- 390 — одна колонка, люди друг под другом.
- 820 — люди по двое в ряд (сетка, как сейчас); «Ждут даты» — горизонтальная лента карточек.
- 1280 — слева лоток «Ждут даты» + «Не назначено», в центре люди колонками рядом по шкале времени дня, справа карточка выбранного выезда. Этап «Запуск»: перетаскивание по шкале времени (меняет начало) и в «Неделе» на другой день; кнопка «Перенести» остаётся.

### 7.3 Карточка выезда (`/visit/[id]`) — что добавляется для офиса
Сверху вниз (для Д, Дп):
1. Шапка и статус — есть.
2. ✚**Когда и кто**: дата, время – конец, окно для клиента, мастера; кнопки «Перенести» · «Назначить» · «Отменить выезд» (вторичные). «Подтверждение отправлено 4 нояб» или «Сообщить клиенту».
3. ✚**Заметка мастеру**.
4. Объём работ, чек-лист, фото, шаги — как сейчас (шаг 7).
5. ✚Ссылки «Лид» / «Работа» / «Клиент».

Мастер видит то же без блока кнопок 2 (только дату, время и заметку).

### 7.5 Что видит мастер
- **«Визиты»** (уже есть): прогресс дня, «Сейчас / Следующий», остальные сегодня, ✚«Завтра» отдельно, потом «Позже».
- **«План»**: только свои выезды, без «Ждут даты», «Не назначено» и чипов людей; кнопки «+» нет.
- **Карточка выезда**: адрес, время, заметка, объём, баланс к оплате; без цены лида, источника, себестоимости.
- **Пуш**: «Вам назначен выезд: ср 10:00, Linda Alvarez», «Перенесено: …», «Отменено: …».

### 7.6 Где ещё видно
| Где | Что |
|---|---|
| «Разбор» (Дп) и «Требует внимания» (Д) | «Ждёт даты» (есть); «Не назначено» — ✚на сегодня **и завтра**; ✚«Опаздывает» (вычисляется); ✚«Осмотр прошёл — сметы нет» |
| «Сегодня» → «Бригада» (есть) | кто где сейчас по статусам выездов |
| Карточка лида | блок хода «Шаг: осмотр ср 10:00 · Иван»; вкладка «Шаги» — выезды-осмотры (`14` §7.2) |
| Карточка клиента, работы | выезды по времени, отменённые — свёрнуто с причиной |

## 8. Права, офлайн, уведомления

### 8.1 Права
| | Директор | Диспетчер | Мастер |
|---|---|---|---|
| Видит в «Плане» | все выезды | все выезды | только свои |
| Записать осмотр, запланировать работу | да | да | нет (вопрос В3) |
| Перенести, назначить, отменить | да | да | нет |
| Шаги на объекте | да | да | свои |
| «Ждут даты», «Не назначено» | да | да | нет |
| Цена лида, источник, себестоимость в выезде | да | да | нет; баланс к оплате клиента — да |
| Настройки расписания | меняет | видит | видит |

На сервере то же: выезды создают и меняют только `owner/admin/office` (уже так, T3); ✚мастер в своём выезде может менять только шаги, чек-лист, фото, подпись — время, людей и отмену нет (новый триггер базы, §2.1 п. 11). Те же правила в приложении — одна функция `canEditVisitSchedule(role)`.

### 8.2 Офлайн
- Записать, запланировать, перенести, назначить, отменить — сразу на телефоне, в очередь (`useStore().queue`); номера id выдаёт телефон, поэтому повтор из очереди безвреден (сервер узнаёт выезд по id).
- Запись осмотра офлайн создаёт клиента той же функцией, что и смета из лида; повтор не создаёт второго.
- Накладки офлайн считаются по данным на телефоне, с подписью «проверено без сети».
- Два переноса одного выезда (офис офлайн и телефон директора) — побеждает позднее изменение на сервере; автор проигравшего получает уведомление «Выезд перенёс Иван на 14:00 — вернуть ваше время?» (PRD 07 §11). Оба события — в ленте.
- Сообщение клиенту — только своим SMS / email (их телефон сам отправит при сети).
- Мастер видит свои выезды на 14 дней вперёд без сети (PRD 07 §9).
- П3a (решение руководителя 05.11): старые сборки в Expo Go назначали «удалить всех + вставить одного»; охрана `visit_assignees` такой `delete` отклоняет, поэтому на старой сборке назначение не проходит, пока не придёт обновление после выпуска (release публикует его, основатель получает при следующем открытии) — это допустимо.
- `public.assign_visit`: повтор того же списка людей возвращает успех («ничего не изменилось») и после «на месте» — ради офлайн-очереди (повтор операции после сбоя следующего шага). Другой список после «на месте» — отказ.
- Роль sales в приложении (решение руководителя 05.11): работает с лидами, сметами и клиентами, «План» только смотрит; «Перенести», «Назначить», «Отменить выезд» не видит; осмотр записывает без людей («Назначит диспетчер») — назначает офис. Сервер отказывает так же (T34, T35); e2e 47, `unit:roles`.

### 10.2 Решения, которые рекомендую
| # | Решение | Почему |
|---|---|---|
| Р1 | Осмотр — выезд у лида и объекта, без работы; статусы работы `lead` / `estimate` убрать | Работа = проданное; так у Jobber; меньше статусов и путаницы |
| Р2 | Одна форма выезда на запись, планирование и перенос | Одно поведение, один набор тестов |
| Р3 | Мастер по умолчанию = кто ведёт лид (если он выезжает), иначе «назначит диспетчер» | Директор основателя сам и ведёт, и едет |
| Р4 | Несколько мастеров на выезд с первого дня; бригады — позже | База уже умеет, монтаж часто вдвоём |
| Р5 | Накладки — предупреждение, не запрет | Короткий осмотр по пути — нормально |
| Р6 | Отмена — всегда с причиной, выезд остаётся в ленте; отмена последнего откатывает лид в «в контакте», работу — в «ждёт даты» | Правило «ничего не теряем» и честный «Чей ход» |
| Р7 | Мастер не создаёт и не переносит выезды (и в базе тоже) | Расписание держит один человек; иначе накладки |
| Р8 | Время по поясу компании; клиенту — окно 2 ч | Как у HCP и ServiceTitan: команде точное время, клиенту окно |
| Р9 | Подтверждение клиенту в MVP — готовый текст со своего телефона; автописьма — «Запуск» | Без ключей площадки и без нарушения TCPA |
| Р10 | «Не назначено» в «Разборе» — сегодня и завтра; «Осмотр прошёл — сметы нет» через 1 рабочий день | Ошибку видно заранее, осмотр не теряется до сметы |
