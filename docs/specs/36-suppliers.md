## 1в. Как приходит / как уходит
Приходит: ручной ввод (SUP1), перенос из `vendor` (миграция), импорт прайса (SUP3, `source = import_file`), AI-скан (шаг «ИИ», `ai_scan`), модуль при «создать позиции» (`module`). Уходит: ставка — в позицию и новые строки смет; имя — в карточку каталога и `vendor` (старые телефоны); SUP2 — PDF заказа (en), «Поделиться».

## 1г. Настройки
Ставка налога поставщика `purchase_tax_bps` — owner, admin, office на карточке поставщика. Пусто — ставка позиции не трогается при выборе (компанийской ставки при покупке в коде нет; `Company.tax_settings.default_purchase_tax_rate_id` модели — со шагом налогов). Личных настроек нет.

## 2. Брейншторм: что нужно подрядчику с телефона
Подрядчик покупает у 2–5 мест (магазин, оптовик, свой склад). Сегодня ему нужно: (1) **записная книжка** поставщика — кому звонить, номер аккаунта, условия, адрес самовывоза; (2) у каждой позиции — **у кого и почём** берёт (себестоимость уже есть, не хватает «у кого» как ссылки); (3) **видеть, что подорожало** — история закупочной цены; (4) потом — **отправить заказ** одним нажатием.

|---|---|---|---|

## 5. Сущности и поля (SUP1)
**`public.suppliers`** (новая): `id`, `company_id`, `name` (1–80, обязательно), `contact_name`, `phone`, `email` (для заказов), `account_number` (≤ 40), `address` (≤ 200), `payment_terms` (`cod`, `prepaid`, `net_15`, `net_30`, `net_60`, `custom`, null), `terms_note` (≤ 80, для custom), `purchase_tax_bps` (0–10000, null = не задана), `notes` (≤ 500), `is_active`, стандартные колонки (`created_*`, `updated_*`, `row_version`, `deleted_at`), `unique (company_id, id)`. Текст чистится от управляющих символов (как `catalogExtras.ts`).

**`public.catalog_items`** (+2 колонки, добавлением): `supplier_id uuid` → `(company_id, supplier_id)` на `suppliers (company_id, id)` (поставщик своей компании, T144), `supplier_sku text` (≤ 60). `vendor` остаётся, приложение пишет туда имя поставщика.

**`public.catalog_cost_history`** (новая, только чтение): `id`, `company_id`, `item_id`, `supplier_id` (на момент), `unit_cost_cents`, `vendor_tax_bps`, `source` (`manual`; дальше `import_file`, `ai_scan`, `shelf_tag`, `module`), `at`, `by`. Пишет триггер `AFTER INSERT OR UPDATE` на `catalog_item_costs` (ловит все пути: экран пишет туда напрямую, старые телефоны — через `t30_costs_move` `catalog_items`), если цена или ставка изменились (`is distinct from`). Поставщик и цена в одном сохранении: себестоимость переносится в BEFORE UPDATE позиции, когда `supplier_id` строки ещё старый (`20261108130000_tech_no_costs.sql:99–119`) — поэтому `AFTER UPDATE OF supplier_id` на `catalog_items` переписывает `supplier_id` у записи журнала этой же транзакции (`at = now()`, одинаково в транзакции). `source` — настройка транзакции `set_config('app.cost_source', …, true)` (импорт, модуль), по умолчанию `manual`. Прямой записи нет ни у кого.

**Перенос данных (правило 16, шаг 1):** в той же миграции — для каждой компании различные непустые `catalog_items.vendor` → строки `suppliers` (имя как есть, ставка — самая частая `vendor_tax_bps` его позиций), `supplier_id` проставлен. Демо-сид приложения — так же (поставщики из `seed.ts`, цены тестовые).

Не заводим: `supplier_items`, `TaxRate`, `branches`, `ImportJob` (SUP3), `purchase_orders` (SUP2).

## 7. Экраны (телефон 390 / планшет 820 / десктоп 1280, обе темы)
- **Меню «Ещё» → «Поставщики»** (группа «Документы», под «Каталогом»; роли owner, admin, office = director, dispatcher). `/suppliers`: поиск, «Активные / Архив», `ListCard` в `CardGrid`: имя; детали — контакт · телефон, условия, «N позиций»; пусто — «Добавьте поставщика: телефон, аккаунт, условия» + кнопка. Кнопка `acc` «Новый поставщик».
- **`/suppliers/[id]`** (форма, без нижней панели — `tabBarRule`): имя, контакт, телефон, email, аккаунт, адрес, условия (чипы), налог при покупке (`PctField`), заметки; «Позвонить» / «Написать» (как у клиента); «Сохранить»; «Архивировать» / «Вернуть из архива» (тост «Отменить»). Ниже — «Позиции» (`ListCard density="compact"`: имя, SKU, себестоимость/ед.) и «История цен» (последние 10 по его позициям). Смена ставки при сохранении, если у поставщика есть позиции с другой ставкой → шторка «Применить 10.25% к 12 позициям?» «Применить / Не сейчас».
- **Карточка позиции (`catalog/[id]`, материал)**: вместо текстового поля — строка «Поставщик: ABC Supply ›» (шторка выбора `ListRow`: активные поставщики, «＋ Новый поставщик», «Без поставщика»); поле «SKU поставщика». Выбор подставляет его ставку налога в поле «Налог поставщика» (видно сразу). Под расчётом — «История цен» (последние 5: дата, цена, поставщик) для `costsVisible`. Без поставщика и со старым текстом — текст показан подписью «Продавец: HD (не из списка)» и предложение выбрать. Sales без себестоимости — строка поставщика только чтением (имя из `vendor`).
- **Каталог (список)**: деталь «supplier» карточки берёт имя поставщика (сейчас `vendor`); вид не меняется.
- **Новый расход**: чипы продавца — активные поставщики компании, затем прежний список.
Цвет — только статус (архив = `neutral` + слово «Архив»), один `acc` на экране.

## 8. Права, офлайн, уведомления
- RLS `suppliers`: select/insert/update — `app.has_role(company, owner/admin/office)`; delete — не выдаём. `catalog_cost_history`: select — `app.can_view_costs`; insert/update/delete — никому (триггер `security definer`). Функции триггеров — `revoke … from public, anon, authenticated` (правило 18).
- Мастер и sales: меню «Поставщики» не видят (`sections.ts`), `suppliers` не читают (база), историю не читают (база, даже мастер с view_costs). Имя поставщика им видно, как и раньше, через `catalog_items.vendor` (приложение пишет туда имя; при переименовании — у всех его позиций); номер аккаунта, налог поставщика и история — нет.
- Поставщика позиции меняют только owner/admin/office: триггер `t20_supplier_guard` у остальных (sales правит каталог) игнорирует `supplier_id`, `supplier_sku`, а у привязанной позиции и `vendor` (security-check SUP1 №2, T144). На экране у sales имя привязанного продавца — только чтение.
- Позже: журнал цены растёт без предела (очистка или лимит — вместе с импортом прайса SUP3); `catalog_cost_history.supplier_id` без FK (исторический id; поставщики не удаляются).
- Офлайн: `db.suppliers` в сторе; мутации `supplier.save`, `supplier.archive` (с `undo`), `catalog.save` + `supplierId`, `supplierSku`; без сети — в очередь. История — только с сервера (снимок для `costsVisible`), без сети — последняя загруженная. Старый сервер без таблицы — `orNoTable`, поставщики не пишутся (как C3).
- Уведомлений нет (напоминание 180 дней — позже).
