## 2. Сравнение и решение

- **Jobber / HCP.** Задачи — список с фильтром «мои / все», «Mark complete» прямо в карточке. Журнал звонков и «Inbox» — по человеку, тред. Берём то же.
- **Estixa** — не копируем; ничего оттуда не нужно.
- Решения:
  - Задачи — один экран `/tasks` + одна форма (шторка) для всех мест, где сейчас две разные (`LeadParts.TaskSheet` и строка в `ClientSections`).
  - Звонки — существующий экран `(tabs)/calls` расширяется: карточка звонка, «Записать звонок» (шторка), фильтр по итогу.
  - Сообщения — **по людям**: одна карточка на человека (или на лид / клиента, если человек не известен), внутри тред его sms и писем.

## 3. Сущности и поля

- Новых таблиц **нет**. Новых колонок **нет** (вариант А, §10 в2).
- `Activity.meta.outcome` (`answered` / `no_answer` / `voicemail`) — **обязателен** у звонка, записанного вручную: база считает звонок без итога дозвоном (`coalesce(meta->>'outcome','answered')`) и сама переводит лид в `replied`.
- `Activity.meta.duration_min` — длительность звонка в минутах (строка-число, необязательна; `meta` — `jsonb` строк). Колонку не заводим: не считаем и не фильтруем по ней.
- `Activity.contactId` — человек звонка / сообщения. Сейчас `lead.touch` его не передаёт; добавляем в операцию.
- `Task` — без изменений (`startsAt/endsAt/allDay/description` уже есть, П-2b).
- Чего не заводим: `MessageThread`, `CallLog`, входящие, непрочитанные, запись звонков (13 §2.1.1, закон CIPA §632).

## 4. Статусы и переходы (сверка с §5)

- Задача: **открыта** → **выполнена** (`doneAt`) → «Вернуть» (снова открыта); всё с «Отменить» 5 с. Вычисляемый признак **просрочена** (`isOverdueTask`: открыта и срок прошёл) — уже в коде, **внести в §5** (руководитель).
- Итог звонка `CallOutcome` — не статус сущности, а признак события; **внести в §5** как «признак события ленты» и в `statusMap` (подпись + тон): дозвонился — ok, не ответил — warn, голосовая почта — warn.
- S2: «Дозвонился» на лиде `new` → `replied` (сервер); «не ответил ×N» — как сейчас `callAttempts`.

## 5. Как приходит / как уходит

- **Звонок.** Кнопка «Позвонить» у клиента, человека клиента, лида, работы → `tel:` и сразу шторка «Чем кончился?» при возврате в приложение (как `callResult` у лида), запись события с человеком. «Записать звонок» в «＋» Звонков, клиента, лида: к кому (лид / клиент; мастер — работа), человек, итог (обязателен), длительность, заметка.
- **Сообщение.** «Новое сообщение» в «＋» Сообщений и «SMS» у человека: выбрать человека → готовые тексты **на языке клиента** (`tFor(docLanguageFor(db, {personId}))`, правило 7) → SMS телефона (`sms:`) или письмо (`mailto:`) с текстом → событие `sms` / `email` с `contactId`. До своего номера — **вручную с телефона подрядчика**: журнал согласий не нужен (13 §2.1.1 «Закон»).
- **Готовые тексты** (v1, по одному на язык en / es / ru): «Еду к вам», «Напоминание о визите», «Смета отправлена», «Спасибо за оплату», «Свой текст». Дальше — настройка компании (позже).
- **Письма из `email_outbox`** (копия подписанной сметы, S8b) **не читаем напрямую**: у таблицы нет человека и клиента, читать её может только офис. Вместо этого то место, что ставит письмо в очередь, пишет событие `email` в ленту сметы (§10 в3 — чей файл).

## 6-3 Сообщения — этап 0 (06.11.2026, согласовано руководителем: вариант Б; i18n-блок своего направления, «Отменить» 5 с, без сети — очередь, суммы и даты в формате США)

**Что нужно подрядчику.** Видеть, что он писал каждому человеку (SMS и письма из OCTODEX), и быстро написать готовым текстом на языке клиента. Своего номера нет: сообщение уходит из приложения телефона (`sms:` / `mailto:`), OCTODEX не знает, отправил ли его человек.

**Варианты.** (А) список событий, как сейчас (по одному на сообщение); (Б) **по людям**: карточка на человека, внутри переписка; (В) по клиентам и лидам. Решение — Б (13 §2.1.1 «по людям»): человек — `contactId`; без человека — лид / клиент события (работа → её клиент).

**Как устроено.**
- Ключ переписки: `p-<contactId>` (настоящий человек) или `l-<leadId>` / `c-<customerId>`; экран `/messages/[key]` — события `sms` / `email` по времени, сверху человек и «Открыть клиента ›» / «Открыть лид ›», снизу «Написать».
- Под каждым исходящим — **«Открыто в приложении телефона · время»**, без «доставлено» (условие руководителя).
- «Новое сообщение» («＋» Сообщений, «Написать» в переписке, «SMS» у человека клиента): человек → SMS / письмо (что есть у человека) → готовый текст → можно поправить → «Отправить»: открывается приложение телефона с текстом, и **в этот момент** пишется событие.
- Готовые тексты — на языке клиента: `tFor(docLanguageFor(db, { personId, customerId | leadId }))` (правило 7), не на языке приложения. Стартовый набор (en / es / ru, основатель поправит): «Еду к вам», «Напоминание о визите {дата} {время}», «Смета {номер} отправлена», «Спасибо за оплату», «Свой текст» (пусто). Подставляются имя клиента и название компании.
