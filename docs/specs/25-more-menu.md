# 25. Меню «Ещё»: сгруппированный список строк со счётчиками

Статус: решено 07.11.2026 (основатель: «пусть дизайнер решает»; руководитель №4 принял этап 0). Чат правок основателя.
Основание: скрины «Ещё» (BUILD 238) — «Очень некрасивое меню».

## 1. Критика (что сейчас не так)
1. **Плитки там, где нужен список.** 13 пунктов-переходов показаны плитками ≈95pt (`size.rowMax` + `dockBtn` 36 + текст + `space[3]`×2). Глаз читает каждое слово отдельно, по колонкам, а не одним столбцом. В итоге меню на 2,5 экрана. В прототипе «Наряда» «Ещё» сделано строками, и правило 12 тоже говорит: меню выбора — строками.
2. **Дыры в сетке.** В группах из 3 пунктов («Документы», «Деньги») справа остаётся пустая клетка. Число пунктов зависит от роли, поэтому дыры есть почти у всех ролей.
3. **Нет иерархии.** Все плитки одинаковые: «Лиды», которые открывают каждый день, весят столько же, сколько «Помощь». Последняя группа без заголовка выглядит как остаток.
4. **Зелёный чип «Онлайн · всё сохранено» горит постоянно.** Это самое яркое пятно экрана, а действия за ним нет. Правило 2 разрешает цвет только для статуса, который что-то требует. Обычное состояние должно быть тихим, цвет нужен только для «без сети / N в очереди» (`SyncBadge`).
5. **Счётчиков нет.** Спека 13 §2.3 требует «плитки со счётчиком и статусом», это долг из BOARD. Сейчас «Ещё» не говорит, куда пора зайти.
6. **Лишний шум в шапке.** Подзаголовок «Все разделы приложения» повторяет смысл слова «Ещё» и занимает строку. Круг `surf2` вокруг каждой иконки тоже шумит: 13 одинаковых серых кругов.
7. **Расходится с меню слева на 820/1280.** Там те же разделы показаны строками (`MenuRow`, иконка + слово). На `/more` на широких экранах те же разделы идут плитками в 4 колонки, и выходит два разных языка для одного списка.

## 2. Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| **А. Сгруппированный список строк (как «Настройки» iOS)**: группы в карточках, строка = иконка · слово · справа счётчик · шеврон | Совпадает с прототипом «Наряда», с правилом 12 и с меню слева. Меню на 1–1,3 экрана. Счётчик стоит справа на понятном месте. Дыр нет при любой роли | Выглядит «обычно» и не продаёт продукт (для служебного меню это нормально) |
| **Б. Компактная сетка 3–4 колонки** (иконка над словом, ~72pt) | Плотно, всё видно сразу | Дыры остаются (3 пункта на 4 колонки). Слова «Настройки компании» и «Помощь и поддержка» не помещаются в 1/4 ширины 390. Счётчику некуда встать, кроме точки на иконке, а точка противоречит правилу «значок + слово». Спорит с меню слева |
| **В. Гибрид: 4 частых плитки + списки** | Сверху яркие «быстрые» входы | Частое у ролей разное (у мастера нет Лидов), значит плитки скачут по ролям. Два вида на одном экране. Частое и так есть во вкладках и в «＋». Получается дублирование |

## 3. РЕШЕНИЕ: вариант А, сгруппированный список строк
**Почему:** список одинаково читается при любой роли, его делает прототип «Наряда», на 820/1280 он выглядит так же, как меню слева, и только в нём счётчик встаёт как «значок/число + слово».

**Порядок (390, директор).** Источник — `menuGroups(role, false)`. Порядок внутри групп из `sections.ts` не меняем: он общий с меню слева.
1. **Профиль** — карточка. Строка: `Avatar` md 36 · имя (`body` semibold) · «Роль · Компания» (`caption`, `mut`) · шеврон. Ведёт в Мои настройки, как сейчас.
   Ниже строка связи. В обычном состоянии: `Icon check` `iconSm` цвета `c.mut` + `caption` `mut` «Онлайн · всё сохранено», **без цвета** (текст и `testID more-sync` остаются). Без сети или с очередью вместо неё `SyncBadge` (warn/info, значок + слово). Цвет появляется только тогда, когда есть что сказать.
2. **Работа:** Лиды · Работы · Звонки · Задачи.
3. **Документы:** Сметы · Счета · Каталог.
4. **Деньги:** Оплаты · Отчёты · Расходы.
5. **Компания** (новый заголовок `nav.group.company`, только директор): Команда · Настройки компании. Группу «bottom» в `more.tsx` делим на две карточки по `id`, `sections.ts` не трогаем.
6. **Без заголовка:** Мои настройки · Помощь и поддержка. Позже сюда же «О приложении · Что нового · Выйти» (13 §2.3).

**Размеры, только токены:**
- Строка `minHeight: size.rowMin` (44; DS: строки списков 44–52, это не кнопки). Зона нажатия = вся строка, `Press visibleHeight={size.rowMin}`.
- Слева иконка `size.iconMd` цвета `c.ink`, **без круга**, в колонке шириной `component.avatar.sm` (28), чтобы слова стояли ровно. Отступы `paddingHorizontal: space[4]`, `gap: space[3]`.
- Внутри карточки разделитель `Divider` (hairline) с отступом слева до начала слова: `space[4] + avatar.sm + space[3]`.
- Карточка `Card` (`radius.card`, стекло), отступ внутри по вертикали `space[1]`. Между группами `space[4]`.
- Заголовок группы — как в меню слева: `T v="caption" w="semibold" tone="mut"`, `paddingHorizontal: space[4]`, `accessibilityRole="header"` (вместо `SectionTitle` heading).
- Шапка: `Screen title="Ещё"` **без** subtitle (ключ `nav.more.hint` не удалять, просто не передавать).
- Итог: директор — 14 строк ≈ 1,3 экрана, мастер — 7 строк, один экран.

**820 / 1280.** Разделы уже есть в меню слева, `/more` открывают только по адресу. Там тот же список в одну колонку, `maxWidth` = **новый токен** `component.menuListMax: 560` (в блоке app-only; равен `paletteW`) и прижат влево, как остальные экраны. Строки те же 44: на широком экране они не становятся «кнопками 28/32», потому что это строки списка. Плиток на 4 колонки больше нет.

**Счётчики.** Одна чистая функция `moreCounts(db, role, now)` в новом файле `src/features/moreCounts.ts`, с unit-тестом. Она считает **из `buildAttention(db, role)`**, поэтому числа совпадают с «Требует внимания» на Главной, а права роли уже учтены. `attention.ts` (общий файл) не трогаем.
| Строка | Что считаем | Текст справа | Тон |
|---|---|---|---|
| Лиды | kind `lead`, `leadBack`, `leadNoStep`, `leadIdle`, `leadOrphan` (наш ход) | «3 ждут» | нейтральный |
| Задачи | мои: просроченные + на сегодня (`taskCounts(tasksOf(db,"mine"))`) | «2 сегодня» | нейтральный |
| Работы | `schedule` + `jobDone` (планировщики) | «1 к плану» | нейтральный |
| Сметы | `estimateSign` (ждут вашей подписи) | «1 на подпись» | нейтральный |
| Счета | `overdue` | `StatusChip soft status="bad"` «2 просрочено» | **bad**, значок + слово: единственный цвет на экране |
- Нейтральный счётчик — `T caption tone="mut"`, число со словом (просто «3» не пишем).
- 0 — справа ничего. Звонки без счётчика: своего номера нет и «пропущенных» тоже нет, 13 §3.12. У Каталога, Оплат, Отчётов, Расходов и Компании счётчиков нет.
- Новые строки i18n — блоком `more.count.*` (RU/EN/ES), с плюрализацией.
- Акцент `acc` на экране не используется: главного действия здесь нет, «＋» — плавающая кнопка.

**Роли** — через `menuGroups` и `routeRoles`, как сейчас.
- Мастер: Работы · Звонки · Задачи / Сметы · Каталог / Мои настройки · Помощь.
- Продажи: без Денег и Компании.
- Офис: без Компании.
- Пустая группа не рисуется, вместе с заголовком.
- Расхождение для руководителя: по 13 §4 мастеру видны свои Лиды, а в `sections.ts` у `leads` `roles: OFFICE`. Сейчас решение не меняем, только отмечаем.

**a11y:**
- Строка: `accessibilityRole="button"`, `accessibilityLabel` = **ровно слово** («Лиды»). На этом держатся e2e `getByRole("button",{name,exact})`.
- Счётчик — `accessibilityHint` («3 ждут ответа»). Если RN-web hint не отдаёт, проверить на этапе кода; запасной путь — `aria-description`.
- Порядок фокуса сверху вниз, заголовки групп — `header`.
- Контраст `mut` по CONTRAST.md ≥ 4.5. Dynamic Type: строка растёт по высоте, слово в одну строку с `numberOfLines={1}`.

## 4. Движение
Своей анимации нет. Нажатие — стандартное у `Press` (`motion.pressScale` 0.95, `durFast`), при «уменьшить движение» его нет. Экран не «въезжает», счётчики меняются без анимации. Это служебное меню, движение здесь только мешает.
