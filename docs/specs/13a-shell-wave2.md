## 1. Что нужно пользователю
Подрядчик с телефона за одно касание попадает в 5 мест, которые нужны каждый день: Главная, План, Сообщения, Звонки, Клиенты. Всё остальное лежит в ☰. «＋» создаёт то, что нужно на этом экране. На планшете и компьютере меню стоит слева, как у Workiz.

## 2. Варианты маршрутов
| | A. Оставить today / triage / visits, «Главная» = дом роли | B. Один маршрут `home`, внутри экран по роли |
|---|---|---|
| Плюсы | Охрана маршрутов (`routeRoles`) как есть. Около 25 e2e работают по старым адресам | Один адрес «Главной» |
| Минусы | У «Главной» три адреса | Переписать около 25 e2e. Охрана уходит внутрь компонента и слабеет. Файлы экранов всё равно остаются разными |

**Решение: A.** Позже `/home` можно добавить перенаправлением на дом роли.

- `(tabs)/inbox.tsx` («Продажи») переименовываем через `git mv` в `(tabs)/leads.tsx`, `?tab=leads|estimates|invoices` остаётся.
  - Экран остаётся внутри `(tabs)`, но кнопки на панели вкладок у него нет (так уже живут triage, today, visits).
  - В ☰ пункты «Лиды», «Сметы», «Счета» ведут на `/leads?tab=…`. «Сметы» у мастера ведут на `/estimates`, как сейчас.
- **Новые экраны:** `(tabs)/messages.tsx`, `(tabs)/calls.tsx`, стек-экран `search.tsx`.
- **Перенаправления:**
  - `/inbox?tab=X` → `/leads?tab=X`;
  - `/more` → дом роли с открытым ☰.
  - Оба — в `NOT_A_SCREEN` в `screens.test.ts`.
- **`routeRoles`:** `leads: OFFICE`, `inbox: OFFICE` (перенаправление). `messages` и `calls` открыты всем: мастер видит только своё.

## 3. Устройство
- **`src/nav/sections.ts`** — единственный список разделов, без React.
  - `Section { id, route, label (nav.*), icon, group: top|work|docs|money|bottom, placement: tab|menu|both, roles, match? }`.
  - У «Главной» `route` = `roleHome[role]`, `match` = today, triage, visits.
  - Функции: `tabs(role)` (всегда 5), `menuGroups(role)` (по ролям и `canOpen`; пустые группы не показываются), `activeSection(path, …)` (вместо `sectionTab`).
  - `roleNav` и `TabRoute` удаляются.
  - **Только готовое:** Задачи, Оплаты, Отчёты, Карта, Телефон, Модули в список не вносим, пока у них нет экрана. Это проверяет unit-тест: у каждого пункта есть файл маршрута.
- **Меню ☰.** Один `NavMenu` на три места: шторка на телефоне, `SideNav` на 820 и 1280, перенаправление с `/more`.
  - Новый `src/nav/Drawer.tsx` — шторка слева: Modal и reanimated, `Glass`, затемнение `z.scrim`, `aria-modal`, фокус заперт внутри и возвращается на ☰.
  - В группе «Низ» — профиль, «Сменить роль» (при нескольких ролях), Мои настройки.
- **Оболочка.** `NavShellProvider` в `_layout.tsx` хранит: меню открыто, закреплено, ширину содержимого.
  - Закрепление хранится на устройстве для каждого человека (`octo.nav.pinned.<me>`). По умолчанию меню свёрнуто (13 §5а).
- **`SideNav`** рисуется один раз в корневом `_layout` рядом со Stack. Так меню есть и на внутренних экранах, а `StackNavPill` (верхняя пилюля) удаляется.
- **Нижние вкладки** — только на телефоне: 5 вкладок, центральной «＋» больше нет.
- **«＋»** — справочник `src/nav/fab.ts`.
  - Наборы для экранов: home, plan, clients, client, job, visit.
  - `FabItem { id, label, icon, roles, href(ctx) }`, функция `fabItems(set, role, ctx)`.
  - Экран объявляет свой набор пропом: `<Screen fab="client" fabCtx={{ customerId }}>`. Чужим экранам (client, job, visit) — одна строка, их чатам заранее `send_message`.
  - Пункты без готового экрана (Задача, Событие, Выходной, Заметка, Файл) не показываем. Они появятся с волнами 3, 5 и 6.
  - «Фото» переезжает в «＋» выезда.
- **Шапка.** На корнях вкладок и меню: ☰ слева (только телефон, видимая 36, зона нажатия 44) · название · справа действия экрана. На Главной справа «Сообщения» и профиль.
  - Строка «Искать везде» стоит на Главной и в списках и ведёт на `/search`.
- **Поиск** — `searchAll(db, q, role)` в `src/nav/search.ts`. Ищет по имени, телефону, адресу и номерам, которые уже есть (CLT, EST, INV, RCT; JOB и LEA — когда появятся). Мастер ищет только по своему.
- **Звонки и Сообщения в волне 2.** Это честные списки событий `activities` (`call`; `sms`, `email`), которые уже пишут кнопки «позвонить» и «SMS». Каждое событие — карточка `ItemCard`, значка числа нет.
  - Пустое состояние: «Звонков пока нет. Звонки из приложения появятся здесь».
  - У мастера — только по его выездам.
  - Полные экраны — волна 6.
- **Ширина.** Новые токены: `component.navRail` (72) и `component.navMenu` (≈ 232).
  - `useNavInsets` на широком экране: сверху без пилюли, слева — ширина меню, снизу — запас под «＋».
  - **1280:** свёрнутое меню оставляет строкам ≈ 1280 − 72 − 360 − поля ≈ 816. Открытое по ☰ меню лежит поверх содержимого. Закреплённое сдвигает содержимое; если для панели не хватает места (`panelW + 700`), панель открывается поверх.
  - **820:** полоса значков с подписями; по нажатию — полное меню поверх. Панель всегда поверх.
- **Цепочка (`hierarchy.ts`).**
  - «Продажи» → «Лиды» (`/leads?tab=…`).
  - У корней меню (Работы, Деньги, Каталог, Компания, Команда, Настройки) нет «вверх», слева ☰.
  - Подпись домашней крошки — `nav.home`.
  - **Ошибка от руководителя:** в разделах компании последнее звено «Настройки компании» вместо имени раздела. Исправление: `kind = stepTitle(id)` для `SETUP_STEPS` + тест в `breadcrumbs.test`.
