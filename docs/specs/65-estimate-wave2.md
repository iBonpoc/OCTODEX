## 0. Итог одним экраном

1. **Жизнь сметы без новых статусов.** «Удалить» — только черновик, который ни разу не уходил клиенту (Корзина сервера уже это умеет, `trash_items`). «Отозвать смету» — `sent/viewed` → `draft` + признак «Отозвана {дата}», ссылка закрывается. «В архив» — признак `archived_at`, не статус. «Клиент отказался» — `sent/viewed` → `declined` с причиной (ход в базе есть). «Вернуть в черновик» из отказа — новый ход `declined → draft` (слово основателя C5). «Дублировать», «Переименовать» — без базы (дубль — обычная новая смета). Статус `voided` спеки 38 **не вводим** (решение совета C4, принято основателем 23.11) — спека 38 и карта §5 правятся этим PR.
2. **Правка отправленной (C11, §12–§13 карты).** Сейчас «Готово» у отправленной делает её черновиком (`store.saveEstimate` ставит `status: "draft"`, облако — `update estimates set status='draft'`), клиент видит старую версию и подписать не может, пока офис не отправит снова. Станет: статус остаётся `sent`/`viewed`; пока редактор открыт — у клиента «Смета обновляется», подпись закрыта; «Готово» = **публикация**: новая версия запирается и сразу видна клиенту. Нужны: «замок правки» на сервере (кто и с какого времени правит, со сроком), функция публикации и проверка версии при подписи клиента.
3. **Найдена опасная ошибка в нынешнем коде (до волны):** облачное сохранение сметы (`cloud/ops.ts` `saveEstimate`) при статусе сервера `awaiting_countersign` **само вызывает `reopen_estimate`** — правка, сделанная без сети до того, как клиент подписал, после синхронизации **молча снимает подпись клиента**. Чинится первым PR волны (65-1), тест красный до.
4. **Гонка подписи:** клиент открыл страницу, офис в это время опубликовал новую версию — клиент подпишет версию, которую не видел (`app.estimate_client_accept` подписывает `sent_version_id` на момент нажатия). Сейчас её нет только потому, что правка уводит смету в черновик. С C11 она появляется — подпись получает «ожидаемую версию» (§3.3).
5. **Наценка и налог.** Себестоимость в строке сметы **уже одно число** (`CustomLine.unitCostCents` «incl. supplier tax», `custom.ts`); поля «налог поставщика» в строке нет — убирать нечего, налог поставщика остаётся только в каталоге. Новое: наценка компании по умолчанию (одно число, 20 %, спрашивается при создании компании) в отдельной таблице, которую видят только те, кто видит себестоимость; цена новой позиции = себестоимость × (1 + наценка); «прибыль $ · %» в свёрнутой позиции; «Облагается налогом» на позиции (умолчание: материалы — да, работа — нет); налог суммой «$» в движке и на сервере.
6. **Лицензии уже печатаются** на PDF и `/p/` (`company_licenses.on_documents`, `docPdf.ts:82`, `portal_estimate_base`); **страховка заполняется, но нигде не печатается** (`contract_settings.insurance`). #2440 сводится к печати страховки; юридические формулировки не выдумываем — только поля с подписями (вопрос В4).
7. **Шаблоны (#2420):** шаблоны смет есть (`/estimate/templates`); шаблонов текстов «Примечания» и «Условия» нет — новая таблица и страница «Шаблоны» с сегментами. «Договоры» — сегмент со ссылкой на текущие условия компании; свои шаблоны договоров — позже.
8. **#2428 и #2430 — не К1:** цвет слова тоста — правило DS (design-reviewer), «Назад» по стеку — правка общей навигации (К2 с общими файлами → ревью как К1). Здесь только инспекция и границы.

### 3.3 Правка отправленной — «Готово» публикует (C11)

Поток (сервер), одна транзакция `publish_estimate_version`:
1. `select … from estimates where id = p_id for update` (порядок замков как у `send_estimate` и `save_estimate_version`: смета → версия).
2. Статус должен быть `sent/viewed/expired`, `p_version_id = current_version_id`, версия **не заперта** и это не `sent_version_id`. Иначе: уже опубликовано (повтор очереди) — тихо `return`; подписана (`awaiting_countersign/approved`) — отказ `22023` с подсказкой `estimate_signed_meanwhile` (§3.5).
3. Запереть версию (`locked_at`, `sent_at`), `sent_version_id := p_version_id`, статус **не трогать**, `editing_*` := null, активность `published` (для истории «Изменена 23.11»). Срок «действует до» не меняется (продление — отдельное действие карты §3, не в этой волне) [вывод].
4. Когда будет спека 49 (снимок издателя, `content_hash`) — она пишется **здесь же**: публикация — та же отправка новой версии. Одна точка, а не две [вывод].

Приложение:
- `store.saveEstimate` для `sent` **больше не ставит `draft` и не сбрасывает `sentAt`**; новая операция очереди `estimate.publish { id, versionId }` идёт **после** `estimate.save` той же версии (зависимость очереди — `data/outboxDeps.ts`).
- Облако `saveEstimate`: для `sent/viewed/expired` — без `update status='draft'`; создаёт новую версию, как сейчас; затем `publish_estimate_version`. Для `awaiting_countersign` — **только если операция несёт `fromStatus: "awaiting_countersign"`** (телефон правил подписанную через «Не подписывать — изменить»); иначе — отказ `estimate_signed_meanwhile`, правки остаются на телефоне (§3.5). Это и есть починка §0 п.3.
- Подпись клиента получает ожидаемую версию: `portal_accept(…, p_version_id uuid default null)` и `accept_on_site(…, p_version_id default null)`; `app.estimate_client_accept` при `p_version_id is not null and p_version_id <> sent_version_id` — отказ `22023` hint `estimate_version_changed`; страница перечитывает смету и говорит «Смета обновилась — проверьте и подпишите» (RU/EN/ES на языке клиента). `null` (старая страница из кэша, старый телефон) — как сейчас (правило 16).
- Карточка отправленной после публикации: главная «Отправить клиенту» (та же шторка), подпись над кнопкой «Изменена {дата} — по ссылке клиент уже видит новую версию» [карта §13 п.2]. «Отправить изменения», «Изменения не отправлены», «Сообщить клиенту» — не делаем [карта §12 п.1, §13 п.2].

### 3.4 «Смета обновляется» — замок правки и офлайн (правило 6)

- Открыл редактор отправленной сметы → в очередь `estimate.editBegin { id }` → `estimate_edit_begin` ставит `editing_since = now()`, `editing_by = auth.uid()`, `editing_until = now() + 30 мин`. Пока редактор открыт и есть сеть, автосохранение на телефоне раз в ≤5 мин продлевает замок (тот же вызов). «Готово» → публикация снимает замок; «Отменить» → `estimate.editEnd` снимает.
- **Срок замка обязателен:** приложение закрыли, телефон сел, человек ушёл — без срока клиент навсегда видит «обновляется» и не может подписать. 30 минут — решение руководителя (технический параметр, не продукт), константа в одном месте; через 30 минут без продления страница снова показывает опубликованную версию и даёт подписать [вывод].
- Сервер: `app.estimate_editing(e) = e.editing_until > now()`. `portal_estimate_base`: если `estimate_editing(e)` — `{"status":"updating", company{name}}` без документа и без «Позвонить» [карта §12 п.1]; `estimate_client_accept` — отказ `estimate_updating`.
- **Без сети:** замок не дошёл → клиент видит прежнюю опубликованную версию и **может её подписать**. Это неизбежно при правиле 6 (вопрос В3 — вариант по умолчанию): при синхронизации сохранение встречает `awaiting_countersign` → отказ `estimate_signed_meanwhile` → на телефоне то же окно, что #2381 даёт для подписанной: «Клиент подписал версию от {дата}. Ваши правки: сделать копией · сбросить» (копия = «Дублировать» с правками). Подпись клиента **никогда** не снимается молча.
- Два телефона правят одну отправленную: замок держит последний `editing_by`; публикация второго после первого — версия уже не текущая → правило конфликта #2381 («дать выбрать», слово 21.11) — без изменений.
- Старые телефоны (правило 16): не зовут `edit_begin` (клиент не видит «обновляется» — как сейчас) и по-старому делают `sent → draft` при «Готово». Ход остаётся разрешён; новые телефоны показывают такую смету черновиком «изменена после отправки» до новой отправки. Признака «отозвана» у неё нет — `withdrawn_at` ставит только `withdraw_estimate`.

## 4. #2437 — наценка компании, себестоимость одним числом, «прибыль · %»

### 4.1 Что сейчас в коде

- Строка сметы: `unitPriceCents`, `unitCostCents` («incl. supplier tax») — одно число; на сервере себестоимость строки — в `estimate_line_costs` (только `can_view_costs`, `20261108130000_tech_no_costs.sql`), с 17.11 — в миллицентах (`20261117640000`).
- Каталог: `catalogPrice(cost, vendorTaxBps, markupBps) = round(cost × (1+tax) × (1+markup))` (`custom.ts:262`), `catalogMarkupFor` (обратная наценка, предел 1000 %); `catalog_item_costs.markup_bps` у позиции каталога.
- Компания: наценки нет; создаётся `insert into companies(name)` (`cloud/auth.tsx:482`, экран `app/auth/company.tsx` — одно поле). `companies.estimate_settings` (jsonb) читают все члены компании, мастер тоже [вывод по RLS `companies_select`; сверить в PR].
- Маржа сметы — `MarginView`/`TotalsBreakdown` (только `seeCosts`).

### 4.2 Решение

- **Где хранить наценку компании:** не в `companies.estimate_settings` — их читает мастер, а наценка + цена = себестоимость (спека 55 §8: наценку видят только `can_view_costs`). Отдельная таблица, имя из спеки 55, одна колонка вместо трёх:

```sql
-- 2026112503xxxx_company_markup.sql (PR 65-6)
create table public.company_cost_settings (
  company_id  uuid primary key references public.companies (id),
  markup_bps  int not null default 2000 check (markup_bps between 0 and 100000),   -- 20 %; предел как у catalog_item_costs
  created_at timestamptz not null default now(), created_by uuid,
  updated_at timestamptz not null default now(), updated_by uuid,
  row_version bigint not null default 1
);
-- select: app.can_view_costs(company_id); insert/update: owner, admin (+ office? — как у catalog_item_costs: is_staff and can_view_costs)
```

  Существующие компании — строка с 20 % одним разом в той же миграции (вопрос В2: 20 % или 10 % из слова 16.11; по умолчанию 20 %).
- **Создание компании:** второе поле на экране создания «Наценка по умолчанию, %» со значением 20 и «?» [карта §14]; после `insert into companies` — `insert into company_cost_settings` (создатель — owner). Без сети компания не создаётся и сейчас — офлайн-очередь не нужна.
- **Настройки:** «Компания → Цены и наценка → Наценка, %» (одно поле; «?»: «Наценка — сколько процентов вы добавляете к себестоимости, чтобы получить цену. По умолчанию для новых позиций.» + «Изменить в настройках ›» в «?» редактора) [карта §14].
- **Новая позиция:** человек ввёл себестоимость, а цену — нет → цена = `priceFromCost(cost, markupBps)` (движок). Цену переписал → наценка позиции пересчитывается (`markupOf(cost, price)`) и видна в «прибыль $ · %». Смена наценки компании **не меняет** ни одну существующую строку, ни каталог (каталог — своя наценка позиции, спека 55 остаётся для каталога позже). Позиция из каталога берёт цену каталога, как сейчас.
- **Свёрнутая позиция** (только `seeCosts`): под суммой мелко «прибыль $90 · 150 %» — без слова «наценка» [карта §13 п.3]; «?» строки: «прибыль и наценка позиции». Себестоимость в итогах раскрывается по разделам [карта §13 п.5] — уже частично есть в `TotalsBreakdown`, сверить в PR 65-7.
- **Налог поставщика в строке сметы — нет и не будет** (себестоимость одним числом, слово 23.11). В каталоге остаётся «цена поставщика + налог %» → себестоимость.

### 4.3 Движок (правило 8)

- `priceFromCost(costMillicents | cents, markupBps): cents` = `round(cost × (1 + markup))` — один раз half up (= `catalogPrice(cost, 0, markup)`).
- `lineProfit(line): { profitCents, markupBps | null }` — `profit = round(qty × (price − cost))` той же формулой, что маржа сметы (`computeCustomOption`), `markupBps = null` при себестоимости 0 (деление на ноль — «—»).
- Тесты движка: 20 % от $10.00 = $12.00; от $13.23 = $15.88 (half up); цена $25 при себестоимости $10 → 150 %; себестоимость 0 → `null`; количество дробное (1.5 × …) — один раунд на строку; отрицательная прибыль (цена ниже себестоимости) — показывается с минусом и `bad`.

### 4.4 Офлайн, права, тесты

- Офлайн: наценка компании кэшируется на телефоне у тех, кто видит себестоимость; правка наценки — операция очереди `company.markup { bps }` (`upsert`); без сети — новое значение сразу на телефоне.
- Права: `select` — `app.can_view_costs`; `tech`/`subcontractor` строку не получают вовсе (тест: `select` под мастером — 0 строк; приложение у мастера наценку не показывает и цену от себестоимости не считает — себестоимости у него нет).
- **С15.** ДАНО новая компания, на экране создания наценка 20. КОГДА создаёт. ТОГДА `company_cost_settings.markup_bps = 2000`. (db, e2e 533)

## 5. #2429 — «Облагается налогом» на позиции

### 5.1 Сейчас

### 5.2 Решение

- Переключатель «Облагается налогом» в раскрытой позиции виден, когда налог сметы включён; «?»: «Входит ли позиция в строку „Налог“ внизу сметы» [карта §12 п.5]. Итог: «Налог 8.25 % с $4,200 облагаемых».

## 6. #2404 — налог суммой «$»

### 6.1 Сейчас

`TaxSettings { enabled, rateBps, ratePpm?, groups }`; `TAX_MODES = ["pct","off"]`; сервер: `estimate_versions.tax_enabled, tax_rate_bps, tax_rate_ppm, tax_mode='added_on_top'`, `app.estimate_option_totals` — налог ставкой от облагаемой суммы после скидки.

### 6.2 Решение

- Движок: `TaxSettings.kind?: "rate" | "fixed"`, `fixedCents?: number`; нет `kind` — ставка (старые). `fixed`: налог = `max(0, fixedCents)`, не делится скидкой, не зависит от облагаемости строк; итог = сумма − скидка + налог. Эффективная ставка для подписи «≈ 9,5 %» = `tax / (taxable − taxDiscount)`, округление до 0,1 % только для показа (не деньги) [решение 7, decisions.md].
- Варианты и допы: одна сумма на смету — каждый вариант получает ту же сумму; допы на выбор клиента налог не меняют; в редакторе предупреждение «Налог суммой не меняется от выбора клиента» (решение автора, см. конец §15).
- Сервер, шаг 1: `alter table estimate_versions add column tax_fixed_cents bigint check (tax_fixed_cents is null or tax_fixed_cents between 0 and 100000000)`; `app.estimate_option_totals`: `if v.tax_fixed_cents is not null then tx := v.tax_fixed_cents`. Старый телефон пишет `tax_fixed_cents`? Нет — `save_estimate_version` его не знает → колонка остаётся от прошлого сохранения нового телефона, а старый телефон считает ставкой → расхождение. Защита та же: `requires: ["taxFixed"]` + отказ старому `engine_version` (PR 65-5); `save_estimate_version` нового телефона пишет `tax_fixed_cents` явно (null, когда ставка).
- Приложение: `TAX_MODES = MONEY_MODES`; «$» в строке налога, под строкой «≈ 9,5 %»; предупреждение CA остаётся.
- **С22.** ДАНО сумма $1,000, скидка 10 %, налог «$» $95. ТОГДА итог $995, «≈ 10,6 %»; на сервере тот же итог. (engine, db «телефон = сервер»)
- **С23.** ДАНО два варианта $1,000 и $2,000, налог «$» $50. ТОГДА у обоих налог $50. (engine)
- **С24.** ДАНО налог «$» отрицательный или больше $1 000 000. ТОГДА поле не принимает; сервер — check. (engine, db)
- **Класс: К1** — движок и база (деньги); экран — К2 вместе с PR 65-7.

## 15. Вопросы основателю (только продукт, деньги, право)

Каждый — с вариантом по умолчанию; работа идёт по нему. Сверено с журналом `founder-answers-1.md` (21–23.11), памяткой №24 §9–§10: прямого ответа нет ни на один.

- **В1 (право).** Подписанную смету убрали в архив. Клиент по ссылке видит подписанный договор и может оплатить счёт — или «Смета больше не действует»? **По умолчанию: договор и счета остаются видны**, архив подписанной — только у вас в списке. (В журнале: «в архиве — больше не действует» без случая подписанной — ответа на него нет.)
- **В2 (деньги).** Наценка по умолчанию у уже работающих компаний (ваша и демо): 20 %, как у новых, или 10 % (ваше слово 16.11 «поставь 10 %» — было для материалов в прежней схеме из трёх наценок)? **По умолчанию: 20 %**; цены старых позиций, каталога и документов не меняются — наценка действует только на новые позиции. (Ответа на этот случай после 23.11 нет.)
- **В3 (право/деньги).** Вы правите отправленную смету **без сети**; клиент в это время подписал прежнюю версию (телефон не мог сказать сайту «обновляется»). **По умолчанию: подпись клиента остаётся, ваши правки становятся копией-черновиком**, вам окно «Клиент подписал версию от {дата}». Другой вариант — отправленную без сети не править вовсе. (В журнале: «подписывать старую версию нельзя» — случай без сети не обсуждался.)
- **В4 (право).** Страховка на смете и счёте: печатаем только факты — страховщик и номер полиса (и «освобождены» по компенсации работникам). Нужны ли обязательные фразы закона штата (например, для CA)? **По умолчанию: только факты**, юридический текст — когда даст юрист. (Ответ «печатать, если указано» — да; текст — нет.)

Налог суммой при вариантах и допах (одна сумма на каждый вариант, допы её не меняют, предупреждение) — решено автором по смыслу «$ — это сумма», не вопрос; если основатель скажет иначе — правка движка одним PR.
