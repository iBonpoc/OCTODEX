# 07-email. Почта П1 — копия подписанного договора клиенту

Шаблон — `docs/15-story-map.md` §7. Этап 0 (05.11.2026, чат «Сметы и модуль Gutters»). Код — после «да» руководителя, новый чат смет.

## 1. Что и зачем

Решение основателя (05.11): когда договор подписан **обеими сторонами** и у клиента есть email, ему **автоматически** уходит письмо с подписанной копией, **на языке клиента**. Сейчас в коде заглушка `sendSignedCopy(estimateId)` (`apps/mobile/src/features/sendEstimate.ts`) — она честно отвечает «почта ещё не подключена» и наружу ничего не шлёт.

Зачем:
- ESIGN Act: потребитель должен получить копию, которую сможет хранить;
- спор «я этого не подписывал»: письмо с копией — второе подтверждение;
- подрядчику не нужно ничего делать руками.

Клетка карты: стык **S8b** (`docs/15-story-map.md` §4) — «копия на почту — шаг «Почта П1»». Новый стык: **S8c «Копия договора клиенту»** (S8b → письмо). Новых статусов сметы нет.

## 2. Брейншторм

**Что в письме.**
- **А. Ссылка на страницу клиента `/p/<token>`** (там уже есть «Скачать подписанный PDF»). Плюсы: PDF собирать не нужно — тот же документ, что на странице. Ссылка подписанного договора не отзывается и не истекает (`revoke_estimate_link` отказывает подписанной смете, `linkOpen`). Минусы: копия «по ссылке», а не во вложении.
- **Б. PDF во вложении.** Плюсы: копия у клиента навсегда, даже без нашей страницы. Минусы: PDF сейчас собирает телефон (`expo-print`); на сервере (Deno, edge function) HTML → PDF без браузера не собрать, а браузер на бесплатном тарифе не запустить.
- **В. Телефон собирает PDF и кладёт его в хранилище, функция прикладывает.** Минусы: подпись на одном телефоне, письмо зависит от того, что этот телефон в сети и дошёл до загрузки. Новый бакет и новые права.

**Рекомендация: А в П1, Б или В — шагом П2.** В письме короткий текст на языке клиента: «Договор EST-0012 с {компания} подписан обеими сторонами», итог, депозит, кнопка «Открыть и скачать договор (PDF)», контакты компании. Копия всегда доступна по ссылке, PDF скачивается с той же страницы. Вопрос основателю — В1 ниже.

**Кто запускает отправку.**
- **1. Телефон после подписи** вызывает функцию. Минус: без сети отправка ждёт, подпись с сайта и с телефона идут разными путями.
- **2. База сама:** `app.execute_estimate` (S8b) кладёт строку в очередь писем `email_outbox`. Database Webhook Supabase (бесплатно) вызывает edge function `send-email` на каждую новую строку.
- **Рекомендация: 2.** Сервер — источник правды: письмо уходит ровно один раз на договор, при любом способе подписи, даже если телефон офлайн. Повтор подписи («approved» второй раз) строку не дублирует: уникальность `(estimate_id, kind)`.

## 3. Как устроено

```
countersign_estimate → app.execute_estimate → insert email_outbox (kind 'signed_copy', status 'queued')
   → Database Webhook → edge function send-email
        → нет ключа площадки            → status 'not_configured' (письма нет, в приложении «почта ещё не подключена»)
        → у клиента нет email           → status 'skipped_no_email'
        → компания выключила автокопию  → status 'skipped_off'
        → Resend 2xx                    → status 'sent', provider_id
        → ошибка                        → status 'failed', error (коротко, без адреса и ключа); до 3 повторов
```

**Сервис за интерфейсом.** `supabase/functions/_shared/mailer.ts`: `send({to, subject, html, text, replyTo})`. Внутри Resend (REST, `fetch`). Смена сервиса = новый файл, вызовы не меняются.

**Ключ площадки** — секрет функции `RESEND_API_KEY`. Его один раз ставит оператор OCTODEX; компания ключ не видит и не вводит. Отправитель — адрес домена площадки (`no-reply@<домен>`). `Reply-To` — email компании (если он есть и проходит `cleanEmail`), чтобы ответ клиента ушёл подрядчику. Инструкция оператору — `docs/runbooks/email-resend.md`: домен, DNS SPF/DKIM/DMARC, где положить ключ, как проверить тестовым письмом.

**Язык письма = язык клиента.**
- Язык берём на сервере из `portal_estimate.doc_language`, тот же порядок, что `docLanguageFor` в приложении.
- Тексты письма en/es/ru лежат в `supabase/functions/_shared/emailText.ts` (Deno не импортирует `src/i18n`).
- Модульный тест сверяет: ключи в трёх языках совпадают, а все подстановки `{…}` есть в каждом языке.
- Деньги — `$`, en-US; даты — по часовому поясу компании.

**Адрес клиента.** Только email из карточки клиента (основной человек), через `cleanEmail` (как в `contactLinks.ts`, своей копией в `_shared`). Никаких адресов из запроса. Функция принимает только `outbox_id` из вебхука (с секретом вебхука в заголовке) и сама читает всё из базы ключом сервиса.

**Настройка компании.** `companies.estimate_settings.autoSendSignedCopy` (по умолчанию **выкл**, решение основателя §10). Переключатель в настройках смет (экран чата «Лиды и клиенты» или свой, согласовать), с понятным текстом. Без ключа площадки рядом стоит статус «OCTODEX ещё не подключила почту».

**В приложении.**
- `sendSignedCopy` больше ничего не шлёт: отправку делает сервер. Функция становится чтением статуса из журнала (`email_log`).
- Карточка подписанной сметы: «Копия отправлена на {email} · {дата}», или «Не отправлена: нет email у клиента», или «Почта ещё не подключена».
- Кнопка «Отправить ещё раз» — директор и офис. Это `resend_signed_copy(estimate_id)`: новая строка очереди, не чаще раза в 10 минут.
- Без email у клиента «Требует внимания» ничего не добавляет: «Поделиться» и страница клиента остаются.

## 4. Данные (миграция `2026110x…_email_outbox.sql`, своя)

`email_outbox` (она же журнал), поля:
- `id`, `company_id`, `estimate_id`, `kind` (`signed_copy`);
- `to_email` — заполняется функцией в момент отправки;
- `lang`, `status` (`queued` | `sent` | `failed` | `skipped_no_email` | `skipped_off` | `not_configured`);
- `attempts`, `provider_id`, `error`, `created_at`, `sent_at`, `requested_by` (для повторов).

Ограничения:
- уникальность `(estimate_id, kind)` — только для строк, созданных автоматически (`requested_by is null`);
- повтор вручную — отдельная строка.

Права:
- `revoke all … from anon, authenticated`;
- `select` — члены компании с ролью owner, admin, office (`app.has_role`); техник видит статус только через саму смету;
- вставки и правки от клиентов нет: пишут только `app.execute_estimate` (security definer) и функция ключом сервиса;
- `resend_signed_copy` — security definer: проверяет роль и что смета `approved`, ограничивает частоту.

## 6. Тесты

- **База, новый T:**
  - подпись обеих сторон → ровно одна строка `queued`; повтор `countersign` — без новой строки;
  - клиенту и anon строки не видны;
  - техник не видит; owner, admin, office видят;
  - чужая компания не видит;
  - `resend_signed_copy`: техник — отказ; не `approved` — отказ; чаще 10 минут — отказ.
- **Функция (Deno test, с подменой `fetch`):**
  - нет ключа → `not_configured`, запроса наружу нет;
  - нет email → `skipped_no_email`;
  - выключено → `skipped_off`;
  - адрес вида `a@b.com?cc=…` → не отправляется;
  - ответ 500 → `failed`, затем повтор;
  - вебхук без секрета → 401;
  - письмо на es и ru для клиента с таким языком.
- **Модульные:** паритет текстов `emailText` (ключи и подстановки); статус в карточке сметы по строкам журнала.
- **e2e** (новая спека или дописать 35, на 6 видах): подписан обеими → в карточке «Почта ещё не подключена» (в демо и в CI ключа нет); «Отправить ещё раз» видят директор и офис, техник не видит.
- **security-check** — обязательно: приём вебхука, секреты, адреса.

## 9. Аудит security-check (05.11) — поправки, обязательны для кода

Ниже по каждой находке — что меняется в разделах 3–7.

**Блокирующие:**
1. **Лимиты против спама.** Повторов на смету — не больше 3 за всё время. На компанию — не больше 20 писем в сутки. Общий суточный лимит площадки ниже лимита Resend. Превышение → статус `rate_limited`. На каждый лимит — тест базы.
2. **Одно письмо при повторе вебхука.**
   - Строку функция забирает атомарно: `update … set status='sending', attempts=attempts+1 where id=$1 and status in ('queued','failed') and attempts<3 returning *`.
   - Если строка не вернулась — ответ 200 и ничего не делаем.
   - В Resend уходит заголовок `Idempotency-Key = outbox_id`.
   - Новый статус `sending`.
3. **Очередь не ломает подпись.** В `execute_estimate` вставка идёт как `on conflict do nothing`, с `requested_by = null` явно. Тест: повторный `execute` не падает, подпись не откатывается.

**Важные:**
4. **Вебхук.** Вместо вебхука из панели — триггер `after insert` через `pg_net`, он лежит в миграции и проверяется на чистой базе. Секрет — в Vault, не в тексте миграции. Функция сравнивает его за постоянное время и берёт из тела только `outbox_id` (uuid). Ключ `service_role` в заголовках не передаётся.
5. **Повторы.** `pg_cron` раз в 10 минут берёт строки `failed` с `attempts<3`. После 4xx от Resend повтора нет. Последний `failed` — статус конечный.
6. **Старые строки не досылаются.** `not_configured` — статус конечный. Строку старше 24 часов функция не отправляет (`expired`), поэтому после подключения ключа не уйдёт пачка писем по старым договорам.
7. **Ссылка ушла не на тот адрес.**
   - В журнале — адрес и кто последним менял email клиента.
   - Директор может «выпустить новую ссылку» для подписанной сметы: новый токен, старый уходит в `revoked_link_tokens`. Это стык с `/p/` и меняет правило «подписанная смета хранит ссылку» — отдельный пункт П1a, тест базы.
8. **Resend.** Отслеживание кликов и открытий выключено: токен не должен ходить через их переадресацию. В runbook — кто имеет доступ к панели. Вопрос основателю В4 (данные клиента у стороннего сервиса).
9. **Шаблон письма фиксированный.**
   - Свободного текста нет; все поля экранируются, длина ограничена, переводы строк в теме убираются.
   - Отправитель — «{компания} via OCTODEX».
   - Ссылка в письме одна — на `/p/<token>`.
   - Deno-тест: `<script>` и `\r\n` в названии компании.
10. **Проверка адресов.** Длина ≤ 254, только ASCII, один адрес. То же для `Reply-To`. Тест: `\r\n`, `,`, `;`.
11. **`resend_signed_copy`.** Смета блокируется (`select … for update`), `requested_by := auth.uid()` берётся внутри функции. Проверки: `deleted_at is null` и у клиента есть email.

**Мелочи:**
12. В `error` — только код ответа. В логах функции нет адреса, токена и ссылки. Срок хранения `to_email` — 2 года. Техник журнал не видит.
13. Отказы и жалобы (bounce, complaint) — П2: подписанный вебхук Resend (Svix) и список адресов, на которые больше не шлём.
14. Язык письма функция берёт из таблиц через `app.`-функцию, без токена.
15. Тесты дополнить:
    - повтор того же `outbox_id` → одно письмо;
    - лимит компании;
    - подпись не откатывается;
    - миграция проходит на чистой и текущей базе, `pg_net` и Vault есть локально.

**Вопрос основателю В4.** Resend хранит адрес и текст письма со ссылкой на договор у себя, в США. Это допустимо (`docs/security/…` п. 5)? Если нет — нужен другой путь отправки.

## 10. Решения основателя (05.11.2026)

- **В2. Домена ещё нет.** Покупка домена площадки и настройка DNS (SPF, DKIM, DMARC) — отдельный шаг плана **до** П1b. Без домена Resend шлёт только на адрес владельца аккаунта, поэтому П1a (база) можно делать сразу, а П1b (отправка) включается после домена. Шаг записан в `docs/10-build-plan.md`.
- **В3. Копию по умолчанию НЕ отправлять.** `autoSendSignedCopy` по умолчанию **выкл**; компания включает в настройках. Без включения строка очереди получает `skipped_off`. Тест: новая компания — `skipped_off`.
- **В4. Resend (данные в США) — согласен.**
- **В1** (ссылка или вложение PDF) — ждёт ответа; по умолчанию план — ссылка в П1, вложение в П2.
