## 2. Цель

Один путь: **почта → 6 цифр из письма от GoRix → внутри.** Первый код создаёт аккаунт и подтверждает почту — отдельной
регистрации и отдельного подтверждения нет. Письмо приходит на любой адрес за секунды, от «GoRix», не в спам. Каждая
неудача — понятными словами и с тем, что делать.

## 3. Как это делают другие (исследование 16.11, источники — в задаче #1756)

- Отраслевые FSM (Jobber, Housecall Pro, ServiceTitan) до сих пор на пароле; SMS-код у них — второй шаг (2FA).
  Housecall Pro добавил «Continue with Apple / Google».
- Современные продукты (Slack, Notion, Linear): один экран «Продолжить с email» → код, плюс Apple/Google и passkey.
  Отдельной формы регистрации нет. Linear кладёт в письмо и ссылку, и код; Slack и Notion — код.
- **Код лучше ссылки:** почтовые сканеры сами открывают ссылки и «сжигают» их; ссылка из почты открывается во встроенном
  браузере, а не в приложении (наш случай 2). С iOS 17 код из письма в Mail подставляется над клавиатурой, как из SMS
  (поле `oneTimeCode` у нас уже есть — `ui/fieldTypes.ts:43`).
- Apple 4.8: если есть вход через Google или другой сторонний — нужен и Sign in with Apple. **Только код на почту — Apple не
  обязателен.** Apple 5.1.1(v): удаление аккаунта в приложении — у нас есть (спека 50).
- Supabase: со своей почтой (SMTP) по умолчанию 30 писем в час на проект — поднять до запуска; отдельный поддомен для
  писем входа; письмо без ссылок, картинок и трекинга.

## 4. Решения

| # | Решение | Почему |
|---|---|---|
| Р1 | Только код, **никаких ссылок** в письмах входа | §1 п.2, §3 |
| Р2 | Вход = регистрация (`signInWithOtp`, `shouldCreateUser: true`); ответ одинаков для нового и известного адреса | просто; не выдаёт, есть ли аккаунт |
| Р3 | Код 6 цифр, срок **10 минут** (было 1 час), повтор — через 60 с | меньше шанс подобрать (security-check Ж1); 60 с — минимум Supabase |
| Р4 | «Confirm email» в Supabase **остаётся включённым** | `accept_invitation` доверяет `email_confirmed_at` (спека 19); введённый код и есть подтверждение |
| Р5 | Регистрации по паролю на экране нет. Вход по паролю — маленькая ссылка, только для аккаунтов с пометкой `password_ok` (проверяющий Apple, #913) | второй путь ломал вход (§1 п.4); пароль — дыра §7 Б1 |

## 5. Экран (`auth/sign-in.tsx`)

**Шаг 1 — почта.** Заголовок «Вход в GoRix». Поле почты (email-клавиатура, без автокапса, `autoComplete=email`).
Галочка согласия (7а-1, как было). Кнопка «Получить код». Под ней мелко: «Регистрация не нужна — аккаунт создастся сам».
- Подсказка опечатки до отправки: `gmial.com`, `gmal.com`, `yahooo.com`, `icloud.co`, `hotmial.com` … → «Может, gmail.com?»
  (нажатие правит адрес). Локальный список, без сети. Модульный тест.
- Без сети — кнопка неактивна, «Нужна сеть, чтобы получить код» (правило 6: вошедший работает офлайн, но код без сети не придёт).

**Шаг 2 — код.**
- «Код отправлен на **адрес** · Изменить почту».
- Одно поле на 6 цифр (`oneTimeCode`: iOS подставит код из Mail). **Вход сам, когда введена шестая цифра** (кнопка «Войти»
  остаётся для тех, кто вставил код с пробелом).
- «Отправить ещё раз через 42 с» → «Отправить ещё раз». Новый код очищает поле и пишет «Новый код отправлен… прежний больше
  не действует».
- «Не пришло письмо?» → шторка: проверьте «Спам» и «Промоакции»; проверьте адрес (Изменить); отправить ещё раз; после
  двух повторов — «Написать в поддержку» (адрес из `config/support.ts`, #836).
- Пауза 60 с не сбрасывается сменой почты (иначе её обходят — ревью №4).

**После кода.** Новый человек → «Создать компанию» (как было, S0) → спросить имя (e2e 417). Есть приглашение → `/auth/invite`
(как было, 7-2).

**Тексты отказов** (RU/EN/ES; без «ошибка / не удалось / сбой» — руководитель 16.11). Ключи `auth.err.*`, разбор —
`features/signIn.ts` (чистая функция, тест `test/signIn.test.ts`):

| Ответ Supabase | Текст |
|---|---|
| `otp_expired` («Token has expired or is invalid») — неверный **и** устаревший код одинаково | «Код неверный или устарел — проверьте цифры или отправьте новый» |
| `over_email_send_rate_limit` «…after N seconds» | «Новый код можно запросить через N с» + таймер на кнопке |
| `over_email_send_rate_limit` (часовой) | «Сейчас уходит слишком много писем — запросите код через несколько минут» |
| `over_request_rate_limit` | «Слишком много попыток — подождите минуту и повторите» |
| `email_address_not_authorized`, «Signups not allowed» | «На этот адрес письма пока не уходят — напишите в поддержку» |
| `email_address_invalid` | «Проверьте адрес почты» |
| `invalid_credentials` (пароль) | «Неверная почта или пароль — проверьте или войдите по коду из письма» |
| нет сети | «Нет связи с сервером — проверьте интернет и повторите» |
| прочее | «Сервер не ответил — повторите через минуту» |

## 6. Письмо

- Тема: **`{{ .Token }} — your GoRix sign-in code`** (код первым — его видно в уведомлении, не открывая письмо).
- Отправитель: «GoRix» `<login@auth.gorix.app>`.
- Тело: «Your GoRix sign-in code», код крупно, «Enter it in the GoRix app. It works once and expires in 10 minutes.»,
  «If you didn't ask for it, ignore this email.» Без ссылок, картинок, трекинга, без слов «Supabase» и «OCTODEX».
- Одинаковый текст в **Confirm signup** и **Magic Link**. Остальные шаблоны (Invite, Change email, Reset password,
  Reauthentication) приложение не использует — не трогаем.
- В репозитории: `supabase/templates/confirmation.html`, `magic-link.html`, темы в `supabase/config.toml`. Сторож
  `test/authEmails.test.ts`: оба шаблона с `{{ .Token }}`, без ссылок (`href`, `ConfirmationURL`, `TokenHash`, `SiteURL`),
  без «Supabase»/«OCTODEX»; срок в тексте = `otp_expiry` в `config.toml`; «Confirm email» включён.
- Облако берёт тексты **руками** (`release.yml` делает `db push`, не `config push`) — поэтому §8 и строка в PR.

## 7. Безопасность

- **Б1. Захват через заранее созданный пароль** (security-check 16.11). `POST /auth/v1/signup` с публичным ключом работает
  и без кнопки на экране: злоумышленник регистрирует чужую почту со своим паролем → владелец потом входит по коду и
  подтверждает почту → пароль злоумышленника продолжает работать → он видит аккаунт и принимает приглашения владельца.
  Решение (зона (б), миграция, тест базы **T290**): триггер на `auth.users` — когда `email_confirmed_at` ставится
  впервые, `encrypted_password` обнуляется, если у аккаунта нет пометки `raw_app_meta_data.password_ok = true` (ставит
  только `service_role`). Плюс облачный тест: `signUp(pw)` → код → `signInWithPassword(pw)` отклонён. Миграция — по
  правилам 16 и 18 (revoke/grant, `security definer` с `search_path`). **До закрытия Б1 регистрацию всем не открывать
  (Resend можно подключить, но публично ссылку на приложение не давать).**
- **Ж1. Подбор кода:** срок 10 мин (Р3); лимит проверок кода 30 за 5 мин с IP.
- **Ж2. Чужие письма и порча домена:** лимиты (§8), чистка неподтверждённых `auth.users` старше 7 дней (отдельная задача;
  она же минимизация данных CCPA), дневной лимит и оповещение в Resend.
- **Ж3. Капча:** только в порядке «сборка с `captchaToken` разошлась → включить в облаке» (иначе вход сломается у старых
  сборок, дух правила 16). В v1 на телефоне не ставим; отдельная задача.
- **Ж4.** Регистрацию в облаке не выключать: иначе ответ для нового адреса отличается и выдаёт, есть ли аккаунт.
- **Ж5.** Resend — обработчик персональных данных: вписать в Политику конфиденциальности (задача правовому направлению);
  хранение писем в Resend — минимум.
- Перебор адресов: ответы на код одинаковы для нового и известного адреса; «Invalid login credentials» общий.

## 8. Облако — что делает основатель (пошагово, ≈20 мин; ключи и пароли в чат не пишем)

**Этап A — сразу (вход заработает у основателя в сборке 1731, приложение менять не надо):**
1. Supabase → OCTODEX-APP → Authentication → Emails → **Confirm signup** и **Magic Link**: тема и текст из §6
   (файлы `supabase/templates/*.html`).
2. Authentication → Providers → Email: «Confirm email» — **вкл.**; Email OTP Expiration — **600**; Email OTP Length — **6**.

**Этап B — своя почта (письма всем):**
1. resend.com → аккаунт (бесплатный) → Domains → Add `auth.gorix.app`.
2. У регистратора gorix.app — DNS-записи, которые покажет Resend (SPF `TXT`, DKIM — 3 записи, `MX` для bounce) и DMARC
   `_dmarc.auth.gorix.app TXT "v=DMARC1; p=none; rua=mailto:…"` (через 2–4 недели — `p=quarantine`). Дождаться «Verified».
3. Resend → API Keys → ключ «Sending access» только для домена `auth.gorix.app`. Click/open tracking — **выкл.**
4. Supabase → Authentication → SMTP Settings → Enable custom SMTP: host `smtp.resend.com`, port `465`, user `resend`,
   password — ключ из п.3 (вставить только в панель), sender email `login@auth.gorix.app`, sender name `GoRix`.
5. Authentication → Rate Limits: emails per hour **100** (бесплатный Resend — 100/день; при Pro — 300), sign-ups and
   sign-ins **30 / 5 мин / IP**, token verifications **30 / 5 мин / IP**.
6. Проверка: вход с адреса, которого нет в команде Supabase (например, второй ящик) → письмо от «GoRix» с кодом во
   «Входящих», не в спаме.

## 9. Старые сборки и порядок выкладки

- Этап A облака помогает и старым сборкам (они тоже просят код). Ничего не ломает: ссылкой из письма никто не пользуется.
- Новая сборка не зависит от этапа B (работает и со встроенной почтой — для команды).
- Миграция Б1 не мешает старым сборкам: они входят по коду; вход по паролю у них есть, но аккаунтов с паролем, кроме
  проверяющего (с пометкой), не будет.
- Порядок: облако A → PR-1 (экран, шаблоны, сторож — ветка `claude/exciting-johnson-7z6wrp`) → PR-2 (миграция Б1, T290,
  облачный тест, убрать `signUpPassword` из `auth.tsx`) → облако B → открыть вход всем.
