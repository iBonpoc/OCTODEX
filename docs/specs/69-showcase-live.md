## 2. Как делают лучшие сегодня (правило 28)

| Что | Как у лучших | Источник |

| Устройство | «Основы → Стили → Детали»; токены — по смыслу, а не по коду | Material 3, Polaris, GitLab |
| Цвет | образец + текст на этом фоне + контраст числом; роль словами («фон экрана», «текст на главной кнопке») | GitLab, Polaris |
| Шрифт | «specimen»: фраза каждым размером и весом, рядом — роль («заголовок экрана») | Storybook (Swatchbook, design-token tables) |
| Движение | «площадка»: выбрать длительность и кривую → «Проиграть»; показ замедлен, чтобы видеть форму; при «Уменьшить движение» — без движения | GoCardless, Atlassian, Telerik, JM Family |
| Где применять | «так / не так» картинками рядом | Storybook, Figma guidelines |
| Поиск | строка поиска по всем токенам и деталям | Material 3, Polaris |

**Чем мы лучше (измеримо):** образцы — те же детали приложения (не копия в другой библиотеке, как в Storybook), обе темы на одном устройстве (поле «Тема ⌄»); «где видно» — **собирается из кода скриптом**, а не пишется руками (не устаревает: сторож); путь до любой строки — 1 нажатие от первого экрана витрины (группы — заголовками на одном экране, как Настройки iOS) или поиск; от вкладки «Ещё» — 4 нажатия: Ещё → Настройки → Дизайн-система → строка.

## 4. Живой образец — по виду значения (подгруппа)

У каждого листа: **образец** · **имя по-русски** · **где видно** · ключ (`caption` 13, `tone="mut"`) · значение. Тип образца задаётся **на подгруппе / по виду значения**, не на группе.

| Вид значения | Живой образец | Подгруппы |
|---|---|---|
| Цвет-текст / цвет-фон | плашка + «Аа 123» этим цветом или на нём; оценка словами «читается хорошо / плохо читается» (значок + слово, правило 2), число контраста мелко; для рамок — норма 3:1, для `glow`, градиента — заливка области | `themes.*` (по ролям: Главная кнопка · Фон и карточки · Текст · Статусы · Модуль — «Главная кнопка» первой), `accents` |
| Статус | плашка `StatusChip` (значок + слово) | `statusIcon`, `timing` (через N дн → warn/bad) |
| Размер шрифта, вес, межстрочный | фраза этим размером/весом («Bathroom remodel · $3,420.00»); межстрочный — абзац | `font.size`, `font.weight`, `font.lineHeight`, `font.tracking` |
| Множитель шрифта | та же фраза при множителе | `font.labelMaxScale`, `font.fitMinScale` |
| Отступ | полоска между двумя плашками | `space`, `spaceHalf`, `rhythm` |
| Размер | рамка этого размера; у кнопки — видимые 40 + зона 44 пунктиром | `size`, `component.*` (на экране детали) |
| Угол | прямоугольник с этим углом | `radius` |
| Слой | стопка карточек | `z` |
| Длительность + кривая | **один проигрыватель вверху экрана**: выбрал строку → «Проиграть» (одна кнопка); рядом с квадратом — настоящая мини-деталь (шторка, тост); «Медленно ×4» — токеном `motion.showcaseSlow` (только витрина, только по кнопке, исключение из потолка §14.4 — запись в §21.0); кривая — графиком | `motion.dur*`, `motion.ease*`, `motion.spring` |

| Удержание, задержка | «нажми и держи» с кольцом | `motion.longPressMs`, `spinnerDelayMs`, `toastUndoMs`, `gesture.dragHoldMs` |

| Печать | кусок PDF сметы/счёта в pt | `print` |
| Модуль | кусок холста / ленты / рабочего чертежа | `drawing`, `drawingPrint`, `shopSheet`, `themes.*.tape`, `component.select.swatch*` (правило 2 искл. 3 называет `materialSwatch.*`, такого имени в токенах нет — руководитель правит CLAUDE.md в PR #2811) |

**«Уменьшить движение» включено** — проигрыватель показывает то, что видит человек (DS §14.5: шторка, окно, тост, меню — растворением `durFast`; масштаб, пружина, сдвиг — мгновенно) с подписью «у вас уменьшено движение — так это выглядит у вас» и кнопкой «Показать как без уменьшения».

**Крупный шрифт** — переключатель 1 / 1,5 / 2 только в витрине: контекст масштаба в `src/ui/primitives` (правило 29 — сначала `src/ui` + DS §21.0 + витрина); на ×2 подписи кнопок переносятся, а не режутся (DS §4.3).

**Подписи.** «Имя по-русски»: на каждый лист — для `themes` (≈ 53), `font.size` (10), длительностей `motion`; на подгруппу — для `component` и печати; ≈ 150 ключей i18n своим блоком `ds.tok.*` (общий файл — по сообщению руководителю); появляются в волнах Ж2 (цвет, текст), Ж3 (отступы, углы, ширины), Ж4 (движение, жесты); названия групп и строк `ds.grp.*` — в Ж1. Лист без подписи по месту называется по месту из «где видно» («между строками»), а не по значению.

**«Где видно».** Файл **коммитится** и проверяется сторожем на свежесть — как `mirror.test.ts` сверяет токены с CSS. Так он есть на чистом клоне и во всех четырёх путях сборки: `tsc --noEmit`, vitest, `npx expo export` (`checks.yml`, `release.yml`), `eas update` и облачная сборка EAS — ничего не нужно запускать до них.
- **Файл:** `apps/mobile/src/features/showcase/tokenUsage.gen.ts` — `export const TOKEN_USAGE = { "motion.durBase": ["/estimates/[id]", "/leads"], … } as const`. Коммитится, поэтому есть на чистом клоне и в `tsc`/vitest. Детерминированный: ключи отсортированы, одна строка на лист, маршруты в строке отсортированы; только маршруты `src/app/**`, без заголовков (заголовок — из i18n при показе).
- **Сборщик:** `node scripts/tokenUsage.cjs` — пишет файл целиком; `--keys` — только добавляет новые листы (`[]`) и убирает исчезнувшие, маршруты не трогает. Путь к файлу → экран по маршруту `src/app/**`; деталь из `features`/`ui` — к экранам, которые её подключают; лист без места — `[]` («не используется»). Как узнаёт лист в коде: (1) `const { c } = useTheme()` → `c.X` = `themes.*.X`; (2) псевдоним импорта (`drawing as dt`, `size as sizes`) → исходное имя группы; (3) обращение по ключу (`c[tone]`, `space[n]`) → весь набор этой подгруппы с пометкой «по ключу» (не считается «не используется»). Тест сборщика `tokenUsage.test.ts` проверяет все три случая на маленьких образцах.
- **Сторож — только набор ключей и формат, не маршруты:** `apps/mobile/test/tokenUsage.test.ts` проверяет, что в файле есть каждый лист `tokens` и нет лишних, ключи отсортированы, значения — списки маршрутов. Маршруты в PR **не сверяются и не пересобираются**: экранный PR файл не трогает, поэтому конфликтов и красного `main` от него нет. Файл меняется только в PR, который добавляет или убирает лист токена (`--keys`; это редко и уже общий файл токенов, правило 1).
- **Свежие маршруты в сборке:** шаг `node scripts/tokenUsage.cjs` стоит в `checks.yml` и `release.yml` перед `npx expo export` и `eas update` (и в `preview:web`): в сайт предпросмотра, обновление по воздуху и TestFlight маршруты попадают свежими, в репозитории могут отставать — красного от этого нет. Конфликт файла при `git merge origin/main` (два PR с новыми листами) — взять любую сторону и `node scripts/tokenUsage.cjs --keys`; строка в `docs/ai/CHECKS.md` §9 тем же PR Ж2 (правило 30в). Правка `checks.yml`/`release.yml` — общий файл, по сообщению руководителю, в волне Ж2.
- **Показ:** строками со «›», не больше 3 и «и ещё N»; нажатие открывает настоящий экран (объекта — первый объект компании или демо; нечего открыть — серая подпись «откройте любую смету»), «Назад» — в витрину на то же место.

**Связь в обе стороны.** На детали — «Проиграть открытие» и строка «Движение › durBase»; у токена — «Окна и шторки ›».

**Тема.** Поле «Тема ⌄» на первом экране, кнопка в шапке раздела — тот же сохранённый выбор, что Настройки → «Оформление» (шаг 1, #2748): меняется тема всего приложения — так и подписано. Одно место на экран.

## 6. Правила витрины (DS §21.0 — отдельным PR до кода, §2.3)

1. Витрина — только «как есть» (#2750).
2. Любой PR, меняющий вид, тем же PR обновляет витрину и пишет «Проверить в витрине: раздел — что сделать, что увидеть».
3. Тип образца — на подгруппе / по виду значения (§4); у каждого листа — имя, «где видно», ключ, значение. Сторож — на этом уровне.
4. Подписи — простыми словами (#2757); коды DS — серой строкой внизу.
5. Одно слово — одна вещь (#2758): название строки = заголовок экрана; «Ввод» / «Выбор» — по признаку.
6. «Медленно ×4» — `motion.showcaseSlow`, только витрина, только по кнопке; пропуск витрины в сторожах (`scripts/codemod/motionLiterals.cjs`, `SKIP = showcase`) снимается — кроме этого исключения.
7. Группа «Модули» видна всегда; строка модуля открывается, только если модуль включён (`moduleActive`), иначе — серая подпись «Выключен в настройках компании».
8. Предложения вида — только на веб-странице «Как есть | Как будет» (§9), по её порядку.

**Пункт страницы** (один вопрос — один пункт):

**Снимки.** «Как есть» — `node scripts/shots.cjs <dist> <папка> 390 dark` и `… 390 light` из сборки сайта (`npm run preview:web`), экраны из `SCREENS` спеки `08-layouts`, уменьшенное движение, часы на полдень дня компании (правило 19); для экрана вне `SCREENS` — снимок e2e-спеки через `h.layout`. «Как будет» — прототип открывается в тех же 390 и обеих темах.
