# 38. Удаление во всём приложении: по одной и массово

> Этап 0, 11.11.2026, чат «Удаление и списки» №1. Задача #747 (основатель 11.11). Решения основателя — план руководителя (артефакт `6cA5TRxx…`) и комментарий в #747. Связано: #628 (срок хранения), #710 (удаление замера только из чертежа), #613, правила 5, 12, 16, 18 `CLAUDE.md`, спека `06-list-cards.md` §6 п.1 и п.8, `docs/08-security.md` §5.2.
> Код — только после «да» руководителя. Карту пути (`15-story-map.md` §4–§5) правит руководитель: здесь — предложение (§9).

## 0. Слова основателя (11.11)
«Продумать, как удалять: я не понимаю, как удалять черновики, как удалять сметы и тому подобное. Массовое удаление, отдельное удаление — всё это сделать. И вообще во всём приложении придумать, как удалять карточки по отдельности или все вместе».

Принято основателем 11.11:
1. **Три слова.** «Удалить» — в Корзину, «Отменить» 5 с, вернуть 30 дней. «В архив» — вернуть в любой момент. «Аннулировать» — деньги и подписанное; вернуть нельзя, только новый документ.
2. **Корзина 30 дней**: «Настройки → Корзина», кнопка «Вернуть»; потом скрыто насовсем, а в базе хранится по сроку хранения (#628; 7 лет не подтверждено — значение в одной функции `app.retention_years()`).
3. **Кто**: каждый — свои черновики; чужое и массовое — владелец, админ, офис.
4. **По одной**: «⋯» в карточке объекта → «Удалить»; в списке на телефоне — смахнуть влево (открывается кнопка, удаление только по нажатию + «Отменить»); на компьютере — значок при наведении.
5. **Массово**: «Выбрать» в шапке списка или долгое нажатие → галочки на `ListCard` → полоса «Выбрано N» (Удалить / В архив / Выбрать все); что нельзя — пропускается с объяснением («Удалено 4. 1 нельзя: смета подписана»); «Отменить» 5 с на всю пачку.
6. Причины «нельзя» — простыми словами на языке приложения.

## 3. Брейншторм

### 3.1 Где хранить «что лежит в Корзине»
| Вариант | Плюсы | Минусы |
|---|---|---|
| **А. Только `deleted_at` в каждой таблице**, Корзина читает таблицы по очереди | ничего нового в схеме | 8+ запросов; мастер не видит свои удалённые строки (политики прячут `deleted_at`); нет «кто удалил»; модульные таблицы ядро должно знать по имени |
| **Б. Запись Корзины `trash_entries`** (одна строка на удаление) + `deleted_at` в таблице как сейчас | один список, одна политика доступа, «кто и когда удалил», пачка (`batch_id`), модуль добавляет свой вид строкой реестра; старые телефоны, пишущие `deleted_at`, попадают в Корзину через триггер | новая таблица, триггер на каждой таблице Корзины |
| В. Перенос строки в отдельную таблицу-архив | чистые рабочие таблицы | ломает внешние ключи, ленты, отчёты, старые телефоны; против правила 16 |

**Решение: Б.** `deleted_at` в таблице остаётся единственным признаком «удалено» для всех чтений (старые версии приложения продолжают его понимать); `trash_entries` — журнал для Корзины и прав на «Вернуть».

### 3.2 Как удаляет приложение
| Вариант | Плюсы | Минусы |
|---|---|---|
| Прямой `update … set deleted_at` из приложения (как сейчас у каталога, фото) | просто | права «свои черновики» и причины «нельзя» придётся дублировать в политиках каждой таблицы; пачка — N запросов |
| **Одна функция `public.trash_items(kind, ids[])`** → ответ по каждой строке `{id, ok, reason}` | одна проверка прав и причин на сервере; пачка одним вызовом; повтор без вреда; тот же ответ «Удалено 4. 1 нельзя: …» и от сервера | новая функция с `security definer` — тщательный тест прав |

**Решение: функция.** Старые прямые записи `deleted_at` (каталог, фото, замер, контакты) продолжают работать (правило 16): триггер всё равно кладёт строку в Корзину. Перевод старых операций на функцию — по объекту, отдельными PR.

### 3.3 «Выбрать» в списке
| Вариант | Плюсы | Минусы |
|---|---|---|
| **Режим выбора у `ListCard`** (новый проп `picked`, галочка слева, нажатие = отметить) + общая полоса `SelectBar` + хук `useListSelection` | одно правило на все списки; правило 12 соблюдено | правка общего компонента карточек (держит чат «Дизайн системы карточек списков», согласовать) |
| Отдельный экран «Выбрать из списка» | не трогает карточку | ещё один экран, другие фильтры — против «одно правило» |

**Решение: режим у `ListCard`.**

### 3.4 Смахивание на телефоне
| Вариант | Плюсы | Минусы |
|---|---|---|
| **Смахнуть влево → открывается кнопка «Удалить»/«В архив», действие только по нажатию** (как решил основатель) | нет случайных удалений; «Отменить» 5 с | два движения |
| Полное смахивание удаляет сразу (iOS Mail) | быстро | случайные удаления в машине, в перчатках; основатель выбрал первое |

На 820 и 1280 смахивания нет: значок «Удалить» в карточке при наведении (мышь) и в «⋯» карточки; на планшете без мыши — долгое нажатие → «Выбрать».

## 4. Решение: одно правило на все объекты

### 4.1 Слово по объекту

Обозначения ролей: **Д** — owner, admin; **Оф** — office; **П** — sales; **М** — tech; **С** — subcontractor. «Свои» — `created_by = я`.

| Объект | Слово | Кто | Что блокирует (причина «нельзя», ключ i18n `trash.why.*`) | Что в базе | Тест |
|---|---|---|---|---|---|
| Смета-черновик (`draft`, ни одной отправки) | **Удалить** | свои — все, кто может её видеть; чужие — Д/Оф | — | `estimates.deleted_at` + `trash_entries` | db, e2e список смет |
| Смета отправлена, не подписана (`sent`, `viewed`) | **Аннулировать** (с причиной) — PR-O5, после «да» по статусу | Д/Оф | подписана — `signed` | новый статус `voided` (§9.2); ссылка `/p/` показывает «Смета отозвана», подпись не принимает | db, e2e `/p/` |
| Смета подписана (`awaiting_countersign`, `approved`) | **нельзя**; путь — «Отменить работу» | — | `signed`: «Смета подписана клиентом — её можно только хранить» | — | db (отказ) |
| Смета отклонена / просрочена | **В архив** | Д/Оф | — | `estimates.archived_at` (новое поле) | db, e2e |
| Замер (модуль) черновик или готовый без подписанной сметы | **Удалить** | свои — М/П/С; чужие — Д/Оф | `signed` (триггер модуля уже есть) | `gutter_measurements.deleted_at` + `trash_entries` (вид `gutters.measurement` — строка реестра из миграции модуля) | db (модуль), e2e «Замеры» |
| Задача | **Удалить** | свои и назначенные мне — все; чужие — Д/Оф | — | `tasks.deleted_at` | db, e2e «Задачи» |
| Расход | **Удалить** | свои — все; чужие — Д/Оф | расход в закрытом периоде — **нет такого понятия сейчас**, не блокирует | `expenses.deleted_at` | db, e2e «Расходы» |
| Позиция каталога | **Удалить** (как сейчас) | Д/Оф | — (в сметах строки — копии, позиция не нужна) | `catalog_items.deleted_at` + `is_active=false` | e2e каталог |
| Клиент **без документов** (нет смет кроме удалённых, работ, счетов, оплат) | **Удалить** (создан по ошибке, дубль) | свои — П; любые — Д/Оф | `hasDocs`: «У клиента есть сметы или работы — его можно только в архив» | `customers.deleted_at`, вместе — его объекты и люди (одна пачка `batch_id`) | db, e2e клиенты |
| Клиент с документами | **В архив** (как сейчас) | Д/Оф | — | `status archived` | есть |
| Лид без сметы и осмотра | **Удалить** (спам, дубль) | свои — все; чужие — Д/Оф | `hasDocs`: «По лиду есть смета или осмотр — его можно только в архив» | `leads.deleted_at` | db, e2e лиды |
| Лид закрытый (`won`/`lost`/`declined`) | **В архив** | Д/Оф | — | `leads.archived_at` → статус в приложении «архив» уже предусмотрен (`archivedAt`) | e2e |
| Работа | **Аннулировать = «Отменить работу»** (причина) | Д/Оф | `done`: «Работа выполнена»; `paid`: «По работе есть оплата — сначала сделайте возврат» | `jobs.status cancelled` + `cancel_reason`; открытые выезды отменяются той же функцией (`cancel_visit` внутри); неоплаченный счёт-аванс аннулируется | db, e2e работа |
| Счёт | **Аннулировать** (причина) | **Д** (база уже так требует; step-up `aal2` — когда будет MFA) | `paid`: «По счёту есть оплата — сначала сделайте возврат» | `status void` + `void_reason` (есть) | db (есть T на триггер — сверить), e2e счёт |
| Оплата наличными / чеком / другое | **Аннулировать** (причина) | **Д** | карта/ACH: «Оплату картой можно только вернуть» | `status voided` + `void_reason` (есть) | db, e2e оплаты |
| Выезд | «Отменить выезд» (есть) | Д/Оф | — | `cancel_visit` | есть |
| Заказ поставщику | «Отменить» (есть) | Д/Оф | — | `cancelled` | есть |
| Шаблоны, поля, направления, типы работ, поставщики | **В архив** (есть) | Д/Оф | — | `archived_at` / `is_active` | есть |
| Фото, заметки, контакты, лицензии | «Удалить» внутри объекта (есть) | как сейчас | — | `deleted_at`; **в Корзину не идут в первой версии** (объекты внутри объекта, своё «Отменить») | — |
| Уведомления | не удаляются (прочитано / не прочитано) | — | — | — | — |

Слово «Аннулировать» в интерфейсе — у счёта и оплаты; у работы — «Отменить работу» (так говорят подрядчики), у сметы — «Отозвать смету»; в коде и ключах это один вид действия `void`.

### 4.2 Правило «кто» одной функцией
`canTrash(role, me, obj)` (чистая, `src/features/trash.ts`, модульный тест) и то же на сервере (`app.can_trash`):
- Д/Оф — любой объект, для которого слово «Удалить» или «В архив» разрешено;
- П/М/С — только **свои черновики** (`created_by = я` и объект в состоянии «черновик» по таблице §4.1; для задачи — ещё назначенные мне);
- «Выбрать» и действия над пачкой видны только Д/Оф (решение основателя: «массовое — владелец, админ, офис»);
- «Аннулировать» — по таблице (счёт и оплата — только Д, как уже требует база).

### 4.3 Причины «нельзя»
Одна чистая функция `trashBlock(db, kind, id) → reason | null` в приложении и `app.trash_block(kind, id)` на сервере, коды одинаковые: `signed`, `paid`, `hasDocs`, `done`, `notYours`, `expired` (в Корзине больше 30 дней), `parentDeleted` («Сначала верните клиента»), `noRight`. Тексты — `trash.why.<код>` в RU/EN/ES простыми словами. Приложение проверяет первым (офлайн), сервер — всегда (старые версии и чужие очереди).

## 5. Экраны (в рамках «Наряда»)

Все размеры, цвета, длительности — токены (`packages/design-tokens`); нового цвета нет. Удаление — не статус: кнопка «Удалить» в полосе и в смахивании — тон `bad` со значком корзины и словом (правило 2: цвет + значок + слово). Главная кнопка `acc` на экране не меняется.

### 5.1 Шапка списка: «Выбрать»
- Кнопка «Выбрать» — обычная `surf2` рядом с «?» (спека 06 §6 п.1), видна только Д/Оф и только в списках, где у объектов есть «Удалить» или «В архив».
- В режиме выбора шапка: «Выбрано N» слева, «Готово» справа; фильтры и поиск работают (выбираешь по отбору); «＋» прячется.
- Долгое нажатие на карточку (≥ `motion.longPressMs`, новый токен, если нет) — входит в режим и отмечает эту карточку. На карточке с кнопками связи долгое нажатие на кнопку связи — своя подсказка (06 №12), не выбор.

### 5.2 Карточка в режиме выбора (`ListCard picked`)
- Новый проп `picked?: boolean` и `onPick` (проп `selected` — «открытая строка 1280» — не трогаем).
- Галочка слева (квадрат `component.checkbox`, зона нажатия 44/48), нажатие на всю карточку = отметить/снять, кнопки связи скрыты, чип статуса не нажимается.
- Отмеченная — рамка `ink` и галочка; цветом ничего не красим.
- 390: галочка слева, карточка сдвигается; 820 (сетка): галочка в левом верхнем углу; 1280 (строка-карточка): первая колонка — галочка; панель открытой карточки закрывается при входе в режим.

### 5.3 Полоса «Выбрано N» (`SelectBar`, новый компонент `src/ui`)
- Прилипает снизу над нижней панелью (390) / внизу колонки списка (820, 1280), с учётом безопасных зон (спека 32).
- Слева «Выбрано N», справа кнопки: «Удалить» (тон `bad`), «В архив», «Выбрать все (M)». Кнопки, которые ни к одному выбранному не применимы, не показываются; применимые к части — показываются с числом: «Удалить 4».
- После действия: тост «Удалено 4. 1 нельзя: смета подписана» + «Отменить» 5 с на всю пачку; режим выбора закрывается. Если «нельзя» больше одной причины — «Удалено 4. 2 нельзя» + «Почему?» → шторка со строками `ListRow` (имя → причина).
- Удаление пачки больше 20 штук — сначала подтверждение «Удалить 34 сметы?» (правило 5: необратимое для глаза — список сразу пустеет).

### 5.4 Смахивание (только 390, только телефон)
- Смахнуть карточку влево на ширину кнопки → открывается одна кнопка справа: «Удалить» (тон `bad`) или «В архив», по таблице §4.1; ничего не удаляется без нажатия. Смахнуть обратно или нажать мимо — закрывается.
- Если у объекта нет разрешённого слова для меня — смахивание не открывается (нет пустой кнопки).
- Одновременно открыта одна карточка. С «Уменьшить движение» — без анимации, сразу.
- Для экранного диктора — `accessibilityActions: delete / archive` у карточки (06 №9).
- Аннулирование смахиванием **не** делается (нужна причина) — только «⋯» на экране объекта.

### 5.6 «⋯» на экране объекта

### 5.7 «Настройки → Корзина»

- На карточке — кнопка «Вернуть»; режим «Выбрать» → «Вернуть все». После «Вернуть» — тост «Возвращено» и ссылка «Открыть».

## 6. База

### 6.1 Новое (шаг 1 правила 16 — только добавление)
- Таблица `public.trash_entries`: `id`, `company_id`, `kind` (`estimate`, `task`, `expense`, `catalog_item`, `customer`, `lead`, модульные — `gutters.measurement`), `object_id`, `batch_id` (пачка и дети: клиент → его объекты и люди), `deleted_by`, `deleted_at`, `restored_by`, `restored_at`. RLS + FORCE; `select`: Д/Оф — вся компания, остальные — `deleted_by = я`; `insert/update/delete` — никому напрямую (только функции и триггер). Индекс `(company_id, deleted_at desc)`.
- Реестр видов `app.trash_kinds(kind, table regclass, owner_col, draft_check regproc, block_check regproc)` — ядро заполняет свои виды; модуль Gutters — своей миграцией (ядро не знает имени таблицы модуля). Функции идут только по реестру (`format('%I')` из `regclass`, без текста от клиента).
- Триггер `app.tg_trash_stamp` (after update of `deleted_at`) на каждой таблице реестра: `null → время` — вставить запись Корзины (если её ещё нет для этого `object_id` и `deleted_at`), `deleted_by = auth.uid()`; `время → null` — отметить `restored_at`. Так в Корзину попадают и старые телефоны, пишущие `deleted_at` напрямую.
- `public.trash_items(p_kind text, p_ids uuid[], p_batch uuid default null) returns table(id uuid, ok bool, reason text)` — `security definer`, `set search_path = ''`, `auth.uid()` и роль внутри, повтор без вреда (уже удалённое → `ok`), по каждой строке `app.can_trash` и `app.trash_block`.
- `public.trash_restore(p_entry_ids uuid[]) returns table(id uuid, ok bool, reason text)` — те же проверки + `expired` (старше 30 дней, `app.trash_days()` = 30), `parentDeleted`; возвращает всю пачку `batch_id`.
- `public.trash_list(p_company uuid, p_kind text default null)` — записи ≤ 30 дней с именем объекта (имя читается из таблицы в момент запроса, в Корзине не копируется — нет второй копии личных данных для CCPA).
- `public.archive_items(p_kind, p_ids[])` / `unarchive_items` — для смет и лидов (новое поле `archived_at` у `estimates`, `leads` — у лидов архив есть статусом; сверить в PR-O, не дублировать).
- `public.void_invoice(id, reason)`, `public.void_payment(id, reason)`, `public.cancel_job(id, reason)`, `public.withdraw_estimate(id, reason)` — обёртки над уже существующими правилами триггеров (void, voided) и новым ходом `jobs → cancelled`; одна функция на стык.
- Правило 18: каждая новая функция — `revoke all … from public, anon`, `grant execute … to authenticated`. Новая таблица — `revoke all … from anon, authenticated`, затем `grant select` (только чтение через политику).

### 6.2 Права (сервер — главный)
- Д/Оф — любой объект реестра; П/М/С — только свои черновики; мастер не может удалить то, чего не видит (`select`-политика таблицы проверяется внутри функции тем же предикатом).
- Восстановить может тот, кто мог удалить; М/П/С — только записи `deleted_by = я`.
- Чужая компания — ничего (`company_id` записи и объекта совпадают, составная проверка).
- Счёт и оплата: `DELETE` по-прежнему запрещён `tg_forbid_delete`; в Корзину не попадают никогда.

### 6.3 Офлайн и очередь
- Удаление: стор сразу ставит `deletedAt` у объекта (объект исчезает из списков), кладёт операцию `trash.items {kind, ids, batchId}` в очередь; «Отменить» в 5 с вынимает её (как сейчас). Ответ сервера с `ok=false` по строке — объект возвращается в список, тост «1 нельзя: …» (не «Ошибка синхронизации»).
- Восстановление: операция `trash.restore {entryIds}`; объект возвращается локально сразу, если он есть в сторе, иначе — после ответа и подтягивания строки.
- Повтор операции без вреда (тот же `batchId`).
- Старые телефоны: читают `deleted_at is null` — восстановленный объект у них появляется при следующем обновлении, удалённый — пропадает. Новых операций они не шлют. Колонки не переименовываются и не удаляются.

### 6.4 Срок хранения
- 30 дней — `app.trash_days()` (одна функция, как `retention_years`).
- После 30 дней — только скрыто; стирание строк по `app.retention_years()` — задача 7а-3 / #628, **не в этой спеке** (нужно слово юриста о сроке).
