# 28. Нижняя панель на всех экранах телефона; «Звонки» с «‹ Ещё»

«Каркас приложения» №8, 07.11.2026. Жалоба основателя (телефон): нижняя панель пропадает на Работах, Задачах, Звонках, Счетах, Каталоге, Команде, Настройках компании, Моих настройках и на карточках; в «Звонках» нет «Назад» и не работает жест назад. Аудит — чат правок основателя; решение руководителя №4 — правило А.

## 1. Причина
- Панель была `tabBar` навигатора вкладок (`app/(tabs)/_layout.tsx`): видна только на экранах из папки `(tabs)`. Всё остальное открывается в корневом стеке (`app/_layout.tsx`) поверх вкладок и закрывает её. Правило выходило «по папке файла», а не по виду экрана: список «Клиенты» с панелью, карточка клиента — без.
- «Звонки» лежали в `(tabs)`: плитка «Ещё» (`router.navigate`) переключала вкладку без истории — назад некуда; у `calls` не было раздела в `nav/hierarchy.ts`, и «‹ Ещё» не рисовался.

## 2. Варианты
| | Плюсы | Минусы |
|---|---|---|
| **А. Панель на телефоне везде, кроме форм и полноэкранных** (выбрано) | как iOS HIG, Jobber, HCP; одна точка правды | список «без панели» нужно вести |
| Б. Только 5 вкладок с панелью, остальное без | ничего не менять | основатель жалуется именно на это |
| В. Свой стек у каждой вкладки | «родная» модель | большая перестройка навигации |

## 3. Решение
- `nav/tabBarRule.ts`: `showsTabBar(route)` и два явных списка — `NO_TAB_BAR` (формы создания и правки, подпись, вход, `/p/`, юр. тексты, удаление аккаунта, импорт) и `WITH_TAB_BAR` (всё остальное). Каждый маршрут `src/app` — ровно в одном списке, иначе падает `test/tabBarRule.test.ts`.
- Панель рисует каркас (`app/_layout.tsx`, над стеком, рядом с `SideNav`); у навигатора вкладок `tabBar={() => null}`. `TabBar` без `BottomTabBarProps`: переход — `router.canDismiss() ? router.dismissTo(href) : router.navigate(href)`. Только `dismissTo` снимает карточки над вкладками: `navigate` в expo-router возвращается к экрану, только если он на вершине стека, иначе кладёт новую копию вкладок — история росла, «назад» с вкладки вело в закрытую карточку (ревью #274). 820/1280 — без изменений (панели нет, `SideNav`). При клавиатуре — скрыта, как раньше.
- «Звонки»: `app/(tabs)/calls.tsx` → `app/calls.tsx` (адрес тот же), убраны из `TAB_SCREENS` и `Tabs.Screen`; в `hierarchy.ts` — корень «Ещё» (как Работы, Команда): «‹ Ещё», жест и системное «назад» ведут на «Ещё».
- Отступ «＋» (`ui/surfaces.tsx`, файл «Лидов», одна строка) — по `showsTabBar`, а не по `isTabScreen`: «＋» над панелью на любом экране с панелью.
- Место под панель внизу экрана уже было на каждом экране телефона (`useNavInsets().bottom`); тост «Отменить» и раньше стоял выше места панели — проверено e2e.

- **Сверка с обходом чата правок** (Playwright, 390, директор и мастер, 07.11): список «без панели» совпал; `+not-found` — без панели (по обходу). Спорные решены, как рекомендовано: `estimate/new` — без, `visit/[id]` — с панелью (главный экран мастера; последняя кнопка шага при прокрутке поднимается над панелью — место внизу уже есть), `company` — с, `company/[section]`, `company/schedule` — без. Тост «Отменить» стоит на высоте над местом панели на всех экранах (`overlays.tsx`, не меняется): на экранах без панели он немного выше, чем нужно, — не мешает; чат правок отступ тоста не меняет.
- **Ревью #274, второй круг:** `catalog/[id]` — форма (новая позиция / правка, «Сохранить»), без панели: вкладка молча сбросила бы несохранённое. **Подпись на месте** (смета, выезд): пока на экране `SignaturePad`, панель скрыта (`nav/tabBarHide.ts`: `useHideTabBar()` на время фокуса экрана, `useTabBarHidden()` в `TabBar`). **Помощь и документы до согласия** (сессия есть, `legal` = first/changed — ворота «Условий» открыты поверх): без панели; в демо и после согласия — с панелью. `routeKey` → `tabRouteKey` (не путать с `roles.ts`).
- **Ревью #274, третий круг:**
  - **Вкладка над несохранённой формой** (правило 5): если в стеке приложения над вкладками лежит форма (`formsAbove` по `NO_TAB_BAR`; пример — новый лид → «Этот номер уже есть» → карточка → «Главная»), панель сначала спрашивает «Выйти без сохранения?»: «Остаться» — ничего не меняется, форма цела; «Выйти без сохранения» — `dismissTo` на вкладку. Стек берётся из `useRootNavigationState` (под обёрткой expo-router `__root` — стек, в котором есть `(tabs)`).
  - **Подпись:** панель прячется только пока подпись рисуется — с первого штриха до «Подписать», «Очистить» или ухода с экрана (`useHideTabBar(!!d)` в `SignaturePad`); до первого штриха панель на месте. «＋» в это время опускается на место панели.
  - **«Условия», открытые до входа** (вход, регистрация, ворота согласия, приглашение): без «‹ Помощь» — кнопка шапки ведёт назад, на экран входа (`navContext(..., { appOpen })`, `appOpen` = сессия и согласие дано). В демо — то же «назад» (на «Помощь», откуда открыли).
  - **Известное:** глубокая ссылка без `(tabs)` в стеке (открыли карточку по ссылке, приложение не было запущено): `dismissTo` на вкладку кладёт вкладки под карточку, «назад» с вкладки на Android выйдет из приложения, а не вернёт в карточку — как у обычной вкладки.
- Проверка тоста в e2e 123 до этого PR не падала бы (на `/tasks` панели не было): это сторож нового сочетания «экран вне вкладок + панель + тост», а не тест исправленной ошибки.

- **Иерархия (аудит руководителя, `docs/ai/LOG.md` п.15–17):** `/estimate/signature` — под «Мои настройки», не смета с id «signature»; `/messages/[key]` — под «Сообщения» (назад и после перезагрузки); «Задачи» и «Помощь» — корни «Ещё» («‹ Ещё» и панель — /tasks больше не тупик); `/settings/delete-account` — под «Мои настройки»; `/legal/[doc]` — под «Помощь».

**«Лиды» из «Ещё» (решение руководителя 07.11, отдельный PR):** «Лиды» остаются вкладкой — это главная роли «Продажи». Для офиса плитка «Ещё» открывает раздел на вкладочном экране с пометкой `from=more` (`moreHref` в `nav/sections.ts`: Лиды, Сметы офиса на `/leads`; у главной роли пометки нет). На таком экране вверху «‹ Ещё» (`surfaces.tsx`, условие кнопки), у вкладок `backBehavior="history"` — системное «назад» (Android, браузер) возвращает на «Ещё», а не на первую вкладку. ~~Смахивание назад на iOS у вкладок не работает (так устроены вкладки); там — «‹ Ещё» и «назад».~~ Опровергнуто основателем 08.11 («с вкладки Лиды я не могу смахнуть назад») — см. §3б.

## 3б. Жест «назад» на вкладочном экране (основатель 08.11)
Жалоба: «С вкладки Лиды я не могу смахнуть назад». Жест от края есть только у экранов корневого Stack; у навигатора вкладок его нет. Вкладочный экран, открытый не с нижней панели, — «Лиды» из «Ещё» (`from=more`, «‹ Ещё»), «чужая главная» (Разбор/Выезды у директора, «‹ Главная»), — имел кнопку «назад», но не жест.
| | Плюсы | Минусы |
|---|---|---|
| **а. Свой жест от края на таком экране** (выбрано) | тот же обработчик, что у кнопки; адреса, история вкладок, веб не меняются | жест рисуем сами |
| б. Открывать такие разделы в корневом Stack | родной жест | `/leads` — и главная продаж (вкладка), и раздел; два маршрута одного экрана; ломает историю вкладок и e2e 07/123/134 |
- Правило — `nav/backSwipe.ts` `tabBackSwipe`: вкладочный экран (`isTabScreen`) **и** телефон **и** не Android **и** в шапке есть «назад» (`hasUp` или «‹ Ещё») **и** клавиатура спрятана. Экран корневого Stack — нет (там родной жест, два сработали бы). Вкладка нижней панели и главная продаж — нет («назад» некуда). 820/1280 — нет (боковое меню). Android — нет: системное «назад» уже идёт по истории вкладок (§3).
- Жест (`nav/BackSwipe.tsx`, обёртка в `Screen`): начинается только в левом поле экрана (`navInsets.left`, 16 или вырез) — там нет содержимого, лента фильтров (с 16) прокручивается сама. Экран едет за пальцем; отпустил дальше 35 % ширины или быстрее 500 pt/с — то же действие, что кнопка шапки (`goUp` / «‹ Ещё»), иначе пружина `motion.spring`. «Уменьшить движение» — экран не едет, решение то же. Экран не в фокусе (переход идёт) — жест выключен; шторка — `Modal` поверх экрана, касание забирает она.
- **«‹ Лиды» с карточки лида** терял `from=more` (`dismissTo('/leads?tab=leads')` заменял параметры вкладки): «Лиды» из «Ещё» возвращались без «‹ Ещё» и без жеста — вероятно, путь основателя. Теперь, если вкладка прямо под карточками — тот же экран и адрес не просит других параметров, `goTo` снимает карточки (`router.dismiss(n)`, `popsToTab` в `nav/tabBarRule.ts`), вкладка сохраняет параметры.
- Тесты: unit `test/backSwipe.test.ts` (когда жест есть/нет, порог, край = поле экрана, Screen передаёт обработчик кнопки, `popsToTab`); e2e **153** (6 видов): «Ещё» → «Лиды» → короткий рывок — остаёмся, рывок по ленте фильтров — остаёмся, смахивание от края → «Ещё»; «Лиды» → лид → «‹ Лиды» → «‹ Ещё» на месте, смахивание → «Ещё»; Разбор у директора → смахивание → Главная; План и главная продаж — жеста нет; 820/1280 — жеста нет.

## 3а. Переходы: смена раздела и переход вглубь (основатель 07.11)
Основатель: «Главная, План, Сообщения открываются без анимации, а Работы, Задачи, Сметы… выезжают сбоку». Правило одно:
**смена раздела — мягкое появление, переход вглубь — выезд сбоку.**
- Раздел нижней панели (вкладка навигатора Tabs) — короткое проявление `fade` за `motion.durFast` (`src/nav/tabTransition.ts`); при «Уменьшить движение» — без анимации.
- Экран вглубь (раздел из «Ещё», карточка, форма) — как было: выезд сбоку корневого Stack и жест «назад».
- Тест: unit `test/tabTransition.test.ts` (fade + токен, reduced motion — none, навигатор вкладок его использует).
