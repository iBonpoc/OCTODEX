# 15. Карта пути OCTODEX (story map) и стыки

> v1, 04.11.2026. Главный документ порядка сборки: всё остальное (`03-prd/*`, `04`, `05`, `10`, `13`, `14`) уточняет его клетки.
> Метод — user story mapping (Jeff Patton): слева направо — **хребет** (что делает подрядчик по порядку), сверху вниз — **детали** шага, горизонтальные полосы — **этапы выпуска**. Плюс то, чего у Паттона нет, но что нужно нам: **стыки** (что передаётся между шагами) и **тест на каждый стык**.

---

## 0. Как пользоваться

1. **Карта** (§3) показывает весь путь на одной странице. Новая функция сначала находит свою клетку здесь. Если клетки нет — сначала правим карту.
2. **Стыки** (§4) — договорённости между шагами. Меняется стык — меняются обе стороны и его тест в одном PR.
3. **Статусы** (§5) — единственный список статусов всех сущностей. Код, база, PRD сверяются с ним.
4. **Углубление вкладки** (§7) — один шаблон из 10 разделов. Первый образец — `14-leads-spec.md`.
5. **Тесты** (§8) — у каждого стыка, перехода статуса и денежного расчёта есть свой тест. Без теста клетка не «готова».

Цикл для каждого шага хребта:
```
карта (клетка и стыки) → спецификация шага по шаблону §7 → вопросы основателю → волна сборки → тесты стыков зелёные → отметка в §3
```

## 2. Как устроен путь у Jobber, Housecall Pro, ServiceTitan

> По открытым описаниям продуктов (центры помощи, демо). Перед углублением каждого шага сверить с их текущей справкой.

| Шаг | Jobber | Housecall Pro | ServiceTitan | OCTODEX |
|---|---|---|---|---|
| Заявка | Request (форма, онлайн-запись) | Lead / Online booking | Call / Booking (колл-центр, CSR) | Лид (☰ Работа → Лиды) |
| Осмотр | Assessment у Request | Estimate visit | Job типа «estimate» | Визит-осмотр (`Job kind=estimate`) |
| Смета | Quote (варианты, подпись, депозит) | Estimate (варианты) | Estimate на выезде, варианты | Смета (модуль или универсальная) |
| Согласие | Quote approved → **Job создаётся** | Estimate approved → Job | Estimate sold → работа продана | Подпись + депозит → клиент активен, работа «назначить дату» |
| Работа | Job → Visits (повторяющиеся) | Job → Schedule, dispatch | Dispatch board, техник | Работа → Визиты → План |
| Выполнение | Чек-листы, фото, время | Чек-листы, фото | Формы, фото, допродажи на месте | Шаги визита (в пути → на месте → работа → подпись) |
| Счёт | Invoice из Job (напоминания) | Invoice из Job | Invoice в конце визита | Счета по договору: депозит → этапы → остаток |
| Оплата | Card/ACH, клиентский портал | Card/ACH, финансирование | Card, финансирование | Квитанция на каждую оплату; Stripe позже |
| После | Запрос отзыва, повтор | Отзывы, абонементы | Memberships, повторные продажи | Отзыв, повторная чистка (модуль), гарантия |
| Отчёты | По источнику, по работе | По источнику, маркетинг | Глубокая аналитика по каналам | Источник → прибыль (PRD 14) |

Что берём из общего: **(1)** у всех один хребет «заявка → осмотр → смета → работа → счёт → оплата»; **(2)** работа создаётся из подписанной сметы, а не вручную; **(3)** счёт создаётся из работы или договора, а не с нуля; **(4)** клиент существует до сделки как «потенциальный»; **(5)** визит — отдельная от работы сущность (у работы может быть много визитов).
Чем отличаемся: телефон первым; модули по trade; честная цена лида до прибыли; офлайн.

## 4. Стыки

У каждого стыка: **кто запускает**, **что меняется с обеих сторон**, **что передаётся**, **тест**.
Колонка «Тест» читается машиной (`apps/mobile/test/storyMap.test.ts`): `e2e:<файл>` — `apps/mobile/e2e/specs/<файл>.cjs`, `unit:<файл>` — `apps/mobile/test/<файл>.test.ts`, `db:T<n>` — тест в `supabase/tests/core_rls.sql`, `engine:<файл>` — `packages/estimating-engine/test/<файл>.test.ts`. Каждая ссылка обязана существовать.
Колонка «Покрытие»: **✅** — обе стороны стыка проверены; **◐** — частично (чего нет — в «Пробел»); **✚** — теста нет. Сверка 04.11 — `docs/16-audit-2026-11-04.md`.

## 7. Шаблон углубления шага (спецификация вкладки)

Каждый шаг хребта получает документ `docs/specs/<шаг>.md` (первый — `14-leads-spec.md`) из 10 разделов:

1. **Стыки** — какие из §4 касаются шага; что приходит, что уходит.
2. **Сравнение** — что есть у нас, у Estixa, у Jobber / HCP / ServiceTitan; решение по каждому пункту.
3. **Сущности и поля** — новые и изменённые; чего не заводим.
4. **Статусы и переходы** — сверка с §5; авто и ручные; запреты.
5. **Как приходит / как уходит** — все каналы входа и выхода.
6. **Настройки** — компании и личные; значения по умолчанию; кто меняет.
7. **Экраны** — порядок блоков сверху вниз; вкладки до конца; шторки; 390 / 820 / 1280; пустые состояния; цвета статусов (только токены).
8. **Права, офлайн, уведомления.**
9. **Тесты** — список тестов на каждый стык, переход, расчёт, правило доступа (§8).
10. **Волны и вопросы основателю.**

Шаг «готов», когда: спецификация согласована → волна собрана → все тесты из раздела 9 есть и зелёные (`npm run check` и `npm run check:e2e`) → в §3 и §4 отметка обновлена.
