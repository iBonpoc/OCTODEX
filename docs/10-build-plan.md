# 10. План сборки приложения (брейншторм и проверка перед стартом)

> 03.11.2026. Основатель передал дизайн-систему «Наряд» (`design/naryad-ds/`): токены, компоненты, правила, чек-лист, контраст. Прототипы в ней тестовые, берём токены, компоненты, правила и сценарии, а не экраны.
> Главное требование: **рабочий процесс строится вокруг телефона**. Планшет и десктоп есть, но работа идёт с iPhone. Роли: **мастер (техник)**, **диспетчер**, **директор (владелец)**.

## 2. Роли и их главный экран на телефоне

| Роль | Главный экран | Что делает за день |
|---|---|---|
| **Мастер (техник)** | «Мои выезды» на сегодня | Шаги выезда: **Я в пути → На месте → Работа (фото до/после, чек-лист, замер, доп. работы) → Подпись → Оплата**. Работа без сети, очередь действий видна |
| **Диспетчер** | «Разбор дел» и «Входящие» | Лиды из почты и площадок с таймером ответа, запись на осмотр, расписание с перетаскиванием на мастера или субподрядчика, напоминания клиентам |
| **Директор (владелец)** | «Сегодня» | Деньги (подписано, получено, ждёт оплаты), «Требует внимания» (просрочки, неотвеченные сметы, лиды без ответа), быстрые сметы, отчёты и окупаемость источников |
| Субподрядчик | Ссылка на наряд (без приложения) | Принять, «готово», фото |

Один человек может совмещать роли (основатель и директор, и диспетчер, и мастер). Переключатель роли в профиле, главный экран меняется.

## 3. Навигация на телефоне (нижняя плавающая пилюля, 5 пунктов)
- **Мастер:** Выезды · План · **＋** · Клиенты · Ещё
- **Диспетчер:** Разбор · Входящие · **＋** · План · Ещё
- **Директор:** Сегодня · Входящие · **＋** · Клиенты · Ещё

**＋** (по центру) открывает быстрые действия: голосовая заметка, лид, смета, фото, расход по чеку.
Планшет и десктоп: верхняя пилюля-навигация и сетка 2 и 3 колонки (по токенам дизайн-системы).

## 5. Правила, которые соблюдаем в коде (из дизайн-системы «Наряд»)
- Все значения только из токенов. Новое значение сначала токен, потом использование.
- Кнопки видимые 28/32 (планшет и десктоп) и 36 (телефон), зона нажатия 44.
- Цвет только для статуса, всегда значок и слово.
- Необратимые действия: подтверждение или тост «Отменить» на 5 секунд.
- «?» у каждого раздела, подсказка при первом заходе.
- Каждый экран проверяем по `design/naryad-ds/CHECKLIST.md`: 3 размера (390 / 820 / 1280), 2 темы, контраст ≥ 4.5:1.
- `prefers-reduced-motion` отключает анимации.

## 7b. Универсальная смета (сделано 04.11.2026)
- Конструктор `/estimate/new`: строки вручную или из каталога (комплект раскрывается в строки), группы «Услуги / Работа / Материалы», 1 вариант по умолчанию + до двух (Good/Better/Best, «Рекомендуем»), доп. опции (клиент выбирает), скидка %/$, налог с продаж выключен по умолчанию и включается по группам (отдельной строкой), депозит % (1–100) или $ — лимит CA только предупреждением.
- Каталог `/catalog`: материал = закупка + налог продавца + надбавка ($10 + 10.25% = $11.03; +10% = $12.13), тестовые позиции нескольких ниш с пометкой «тестовая цена».
- Отправка: SMS / email с телефона со ссылкой, копирование; страница клиента `/p/<token>` в браузере без приложения: выбор варианта и доп. опций, подпись (E-SIGN), депозит (в демо — тестовая оплата; в облаке — после Stripe), PDF. Подрядчику — уведомление «назначьте дату»; работа получает статус «Ждёт даты» и в «План» попадает только после того, как подрядчик выберет дату, время, длительность и мастера (`/job/schedule`, решение основателя 04.11). «План» — лента на 14 дней.
- Подпись на месте — тот же экран клиента на телефоне подрядчика. PDF — `expo-print` (телефон) / печать браузера (веб).
- Конструктор как в Jobber / Housecall Pro: одна лента позиций; «Добавить позицию» = поиск по каталогу или своя позиция; под позициями — итоги, скидка, налог, депозит (по нажатию). Тип позиции (услуга / работа / материал) нужен только для налога.
- **Модули отключены** (решение основателя 04.11): код Gutters (быстрая смета, чертёж) вынесен в `apps/mobile/src/modules/gutters/` без маршрутов и кнопок; тестовые данные — разные направления (хендимен, сантехника, электрика, покраска, уборка); у компании больше нет направления `gutters` по умолчанию.

## 7a. Принцип: ядро CRM + модули (решение основателя, 03.11.2026)
OCTODEX — CRM для любых подрядчиков, **не только гаттеры**. Ядро: клиенты, объекты, лиды, сметы из позиций, счета, оплаты, расходы, расписание, роли. Gutters — **модуль** (чертёж по фото, калькулятор длин/углов/водостоков, gutter-каталог, чек-лист монтажа). Ближайшие задачи из этого:
1. Универсальная смета: позиции из каталога / вручную, количество × цена, варианты Good/Better/Best, налог, депозит — без привязки к гаттерам; «Быстрая смета гаттеров» и «Чертёж» — кнопки модуля Gutters.
2. Каталог услуг и материалов компании (своё, импорт), тестовые позиции по нишам.
3. Настройка компании: направление(я) работ и включённые модули; чек-листы и шаблоны — из модуля или свои.
4. Тексты интерфейса без «гаттер» вне модуля.

## 8. Решения, принятые без основателя (можно пересмотреть)
1. **Одно приложение Expo Router на все устройства** (поправка в ADR-001). Next.js — только публичный портал/SEO.
2. **Название продукта: OCTODEX** (решение основателя 03.11.2026). «Наряд» — имя дизайн-системы. Bundle id `com.octodex.app`.
3. **Язык по умолчанию — язык телефона** (английский для США; русский, если телефон на русском). Переключатель в «Ещё».
4. **Тестовые данные каждый новый день создаются заново** (даты «сегодня» относительные), пока нет сервера. Кнопка «Сбросить тестовые данные» с отменой.
5. **Статусы выезда:** запланирован — нейтральный, в пути/на месте/работа — синий, подписан и ждёт оплаты — оранжевый, оплачен — зелёный, без мастера и опаздывает — оранжевый.
6. **Срочность лида:** до 5 мин синий, 5–15 мин оранжевый, от 15 мин красный (токены `timing`). Смета без ответа 2–4 дня оранжевая, от 5 дней красная (из HANDOFF).
7. **Шаг «Работа» нельзя начать без фото «до»**, подпись — без закрытого чек-листа (защита от споров с клиентом).
8. **Депозит в быстрой смете 10% с лимитом CA** (меньшее из 10% и $1,000), налог «включён в цену» (подрядчик в CA).
9. **Запись на осмотр ставит выезд на завтра 10:00 без мастера**, диспетчер назначает в «Плане».
10. Добавлены иконки, которых нет в дизайн-системе (`packages/design-tokens/src/extraIcons.ts`: маршрут, фото, подпись, чек-лист, доллар, тема, линейка, синхронизация, минус и др.) — в том же стиле; стоит внести в DS.
11. Добавлен токен размера шрифта кнопки 12.5 (в DS он есть в компоненте Button, но не в foundation).
