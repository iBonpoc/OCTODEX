## 4. PDF
- Делается HTML-строкой (features/docPdf.ts docPage + estimatePdf.estimateHtml, invoiceHtml, receiptHtml; Gutters — gutterDrawingPdf, poPdf отдельно). Телефон: expo-print printToFileAsync({html}) и expo-sharing (saveEstimatePdf, features/estimatePdf.ts:~150). Веб: скрытый iframe и window.print() — «Сохранить как PDF» в диалоге браузера; файл не создаётся приложением. Подпись клиента рисуется inline-SVG (маленькая).
- Одинаков ли результат: НЕ гарантирован. Шрифт — системный стек (-apple-system, Helvetica Neue, Arial): на iOS/Android/веб будут разные гарнитуры и переносы. Размер бумаги нигде не задан: у printToFileAsync размер по умолчанию библиотеки (US Letter 612x792 pt, по документации expo-print — на устройстве не мерили); на вебе бумагу выбирает диалог браузера (в США Letter, в других странах A4). Поля @page margin задаются, но iOS-движок expo-print их, как известно, игнорирует (не проверял). Проход «PDF на iPhone» — в плане выпуска (F-21, шаг 6.9) ещё не пройден.
- Логотип: квадратный PNG, ужат до component.logoPx и хранится в профиле компании как data:image/png;base64 (app/company/[section].tsx:431-437); вставляется в каждый PDF. Вес файла определяют: логотип, шрифты не встраиваются (системные -> файл мал), число строк, SVG подписей и схем (Gutters: чертёж — SVG), фото в PDF не кладутся. Размера не мерили — типичная смета без фото по устройству вероятно десятки KB; это оценка, не замер.
- Где хранится: нигде. Файл — временный в кэше телефона, дальше «Поделиться»; в облако не кладётся, колонка estimate_versions.pdf_file_id есть (core.sql:635), но не используется ни в приложении, ни в функциях. Перегенерируется каждый раз из текущих данных. Следствие: «неизменяемой копии подписанного договора» нет: строки сметы заперты триггером (estimate version locked, core.sql:749), но шапка (название, адрес, телефон, лицензии, логотип, условия) берётся живая, т.е. через месяц PDF подписанной сметы выйдет с новой шапкой. content_hash в версии есть, в PDF и в проверке не используется. Спека 07 §2 «Вид документов… отправленный PDF не меняется, вид фиксируется в версии» — не реализована совсем: три вида (classic/modern/compact) и «показывать цену за единицу» есть в docPdf/estimatePdf и в unit-тестах, но ни один экран настроек их не включает: опции нигде не передаются (поиск по src: 'modern' и showUnitPrices только внутри estimatePdf/docPdf) — все PDF всегда «classic» с ценой за единицу. Теста «отправленный PDF не меняется после смены вида» нет (в спеке заявлен как unit:estimatePdf, в файле его нет).
- Варианты проще/надёжнее (без кода): (а) оставить как есть (HTML->PDF на устройстве): плюсы — офлайн, бесплатно, готово; минусы — шрифты и поля различаются, нет архива. (б) Один раз при подписи собрать PDF на сервере (edge-функция + headless-рендер или pdf-lib) и положить в Storage по pdf_file_id как неизменяемую копию: плюсы — одинаково везде, юридически «то, что подписали», можно слать ссылкой; минусы — нужен сервер и хранилище, работа M-L, нужна сеть, расходы. (в) Встроить свой шрифт в HTML (data:font) и явно задать width/height Letter в printToFileAsync: плюсы — дешёвая правка, одинаковый вид; минусы — вес файла растёт на размер шрифта, на вебе всё равно печать браузера. (г) Хранить «снимок шапки» (JSON компании) в подписанной версии и рисовать PDF из него: плюсы — неизменяемость без серверного рендера; минусы — нужна миграция по правилу 16. (д) Вместо PDF-вложения слать только ссылку на /p/ (там версия подписана и заперта): плюсы — ничего не весит; минусы — клиенту нужен интернет, архив у клиента не лежит.
