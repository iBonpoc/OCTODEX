## 1. Общий элемент: карточка → заголовок экрана

Нужно: имя и сумма с карточки списка «перелетают» в заголовок экрана объекта, а при смахивании назад летят обратно за пальцем.

### Варианты
**А. Reanimated Shared Element Transitions (SET), версия 4.8.0.**
- Источник — релиз 4.8.0 (github.com/software-mansion/react-native-reanimated/releases/tag/4.8.0): «They are now on by default». Документ «Shared element transitions → Overview»: «Available from 4.8.0». В 4.2–4.7 была «experimental version» за флагом `ENABLE_SHARED_ELEMENT_TRANSITIONS`.
- Проверено в пакете: в 4.7.1 `staticFlags.json` → `ENABLE_SHARED_ELEMENT_TRANSITIONS: false`, в 4.8.0 → `true`.
- Платформы: iOS и Android — да. Веб — нет: там вид «show in their places without a transition», то есть обычный переход, без поломки.
- Навигация: нужен родной стек (`@react-navigation/native-stack`). `Stack` expo-router именно такой. Каждый экран оборачивается в `SharedTransitionBoundary` — у нас для этого есть `screenLayout` в корневом `Stack`.
- Смахивание назад на iOS: «It follows the progress of the swipe, from 0 to 1». Отменённое смахивание возвращает вид на место. На Android переход за жестом назад не идёт, там работает анимация по времени.
- Ограничения (страница limitations):
  - один и тот же тег на двух видах одного родного типа;
  - вид не в родной шапке (у нас шапка своя — подходит);
  - между `UIWindow` переходить нельзя: из экрана в отдельное окно-шторку не полетит;
  - React-правки стиля применяются только по концу перехода;
  - `Pressable` с прозрачностью даёт двойное затемнение. Для карточки нужно нажатие через масштаб — у нас так и есть: `pressScale`, §14.2.
- При «уменьшить движение» переход пропускается сам, по записи релиза 4.8.
- Требует Worklets 0.14 и RN 0.87–0.89 (у нас 0.88.1 — подходит). Expo: «development build rebuild».

**Б. `Link.AppleZoom` из expo-router** — это не перелёт текста, а увеличение всей карточки. Разбор — в п.2.

**В. Свой «перелёт» поверх экранов** (снимок рамки, копия в слое над стеком, `measure` + `withTiming`). Так делали до SET.
- Минусы: своя математика жеста назад, рывки на медленных телефонах, нарушает правило 29.
- Не рекомендуется.

### Рекомендация
Вариант А — **Reanimated 4.8 SET**. Это единственное стабильное решение, и сделано оно авторами Reanimated, который у нас уже стоит.

Срок — со следующей сборкой в магазин. Лучше всего — вместе с переходом на Expo SDK, в котором 4.8 станет штатной версией. Если сборка нужна раньше, можно поставить 4.8 + Worklets 0.14 поверх SDK 58. Это отступление от набора SDK: `npx expo install --check` его покажет, и нужна полная проверка сборки.

Защита:
- **флаг компании / сборки `motion.sharedElement`**: выключен → обычный системный переход;
- на вебе и при «уменьшить движение» — обычный переход;
- старая сборка без 4.8 → флаг выключен сам: проверка `ENABLE_SHARED_ELEMENT_TRANSITIONS` во время работы, по образцу `tabGlass.ts`.

Где включать: карточка списка (`ListCard`) → заголовок экрана объекта. Летят только имя (заголовок) и, если есть, сумма. Карточки целиком не летят — для этого есть п.2.

### Риски
- Версия вне набора SDK 58. Пока Expo не поднимет пин, остаётся риск несовместимости других модулей.
- Обновление по воздуху (OTA) с тегами придёт и на старую сборку. Без флага там будет обычный переход — тоже безопасно, потому что 4.7.1 с флагом `false` теги не исполняет. Это нужно проверить тестом.
- Правило 27: проверка только на iPhone. Зелёный e2e в браузере перелёт не доказывает.
- Список прокручивается, и при возврате карточка может уйти из видимой части. Тогда перелёт не случится: «Both views must be mounted». Это допустимо, будет обычный возврат.

### Объём
3–4 дня:
- граница в `screenLayout`;
- проп `sharedTag` у `ListCard` и у заголовка экрана;
- флаг;
- модульный тест «флаг выключен → тегов нет»;
- образец в витрине «Движение».

Новая сборка: **да**.

## 2. Увеличение из карточки (zoom, iOS 18)

### Варианты
**А. `Link.AppleZoom` + `Link.AppleZoomTarget` (expo-router).**
- Документ «Zoom transition» (docs.expo.dev/router/advanced/zoom-transition/): «Zoom transition is an **alpha** API available on iOS only in Expo SDK 55 and later. The API is subject to breaking changes.»
- Нужна iOS 18+. На старых iOS, на Android и в вебе — «render normally without the zoom animation effect».
- Ограничения:
  - только в `Stack` роутера;
  - с родной шапкой не советуют (у нас шапка своя — подходит);
  - вместе с `Link.Preview` цель должна быть `fullScreenModal`;
  - `usePreventZoomTransitionDismissal` не работает в модальных экранах;
  - ребёнок один.
- Родной код уже в пакете expo-router 58 (`LinkZoomTransition.swift`). Новая сборка не нужна, если сборка TestFlight собрана с expo-router 58.x.

**Б. Reanimated SET (п.1)** — перелёт отдельных видов, карточку целиком не увеличивает. Стабильно с 4.8.

**В. Свой переход `animation: "fade"` + масштаб содержимого экрана** — подделка, не родное поведение iOS. Не рекомендуется.

### Рекомендация

Где пригодится потом: сетка карточек на планшете, фото замера → экран фото.

### Риски

- конфликт со своим `BackSwipe`, его надо проверить.

## 3. Лист поверх, экран сзади уходит вглубь (page sheet / form sheet)

### Варианты
**А. Родное представление экрана в `Stack` expo-router: `presentation: "modal"` (на iOS это page sheet), `"formSheet"` с `sheetAllowedDetents`.**
- Опора — react-native-screens 4.30: `"formSheet"` = `UIModalPresentationFormSheet`, на Android — Material BottomSheetBehavior. Документы expo-router «Modals» и «Stack».
- iOS сам уводит экран сзади вглубь: уменьшает и скругляет. Это и есть «стопка карточек».
- Ограничения:
  - на Android в formSheet нет вложенного стека и родной шапки;
  - Android — не больше 3 детентов;
  - в вебе «the modal is presented as a separate route, and the dismiss behavior has to be provided manually».
- Стабильно, родной код уже в сборке.

**Б. Наша `Sheet` (`src/ui/overlays.tsx`)** — как сейчас, для быстрых задач. Экран сзади вглубь не уходит, и это не маршрут: нет ссылки, нет «назад».

**В. `@expo/ui` `BottomSheet` (SwiftUI) / `ModalBottomSheet` (Compose)** — новая зависимость первой стороны Expo, новая сборка. На вебе ничего нет. Не нужна: А закрывает задачу.

### Рекомендация
Вариант А для экранов создания:
- новая смета;
- новый клиент;
- новый лид;
- форма поверх списка.

На телефоне iOS — `presentation: "modal"` (page sheet во весь рост, экран сзади вглубь). На Android — тот же `"modal"`: системный выезд снизу. formSheet на Android не брать из-за ограничений.

От 820 и на вебе — наша `Sheet` / окно 444 по центру (DS §10). Это одна обёртка `SheetScreen` в `src/ui`, правило 29.

Наша `Sheet` остаётся для быстрых задач на одном экране.

Несохранённое: смахивание листа вниз перехватывается так же, как сейчас (`dirtySheets.ts`). Для родного листа — `usePreventRemove` из навигации + диалог «Выйти без сохранения?».

### Риски
- Смахивание вниз закрывает лист системно, поэтому защиту несохранённого нужно проверить на iPhone (правило 27).
- Наш `GuardedScreen` в `screenLayout` должен правильно работать внутри модального экрана.
- В e2e лист — отдельный маршрут, спеки по URL могут поменяться (CHECKS §9).

### Объём
2 дня: обёртка, первая форма, e2e на 6 видах, строка DS §10.

Новая сборка: нет.

## 5. «ИИ думает» (shimmer, этапы) и тост с прогрессом

## 9. Жидкое стекло iOS 26 и запасное матовое

### Что показал пилот «Графит» (нижняя панель вкладок, `src/nav/tabGlass.ts`, `TabBar.tsx`)
- `GlassView glassEffectStyle="regular"` без своего оттенка: стекло само следует теме.
- Решение «жидкое или матовое» принимается **один раз на запуск**: iOS + `isGlassEffectAPIAvailable()` + `isLiquidGlassAvailable()`.
- `expo-glass-effect` грузится лениво через `require` в `try`. Обновление по воздуху на старой сборке без модуля не падает, а показывает прежнюю панель `Glass` (`--ov` + `expo-blur`).
- Android, веб и старый iOS — матовая панель без изменений.

### Варианты
**А. `expo-glass-effect` (Expo, первая сторона, уже стоит).**
- Документ: «GlassView is only available on iOS 26 and above. It will fallback to regular View on unsupported platforms».
- `isGlassEffectAPIAvailable` нужен, потому что «some iOS 26 beta versions do not have this API available, which can lead to crashes».
- Важно: «Apple does not recommend opacity values below 1 on GlassView». Появление делается прозрачностью обёртки или `glassEffectStyle={{ style, animate: true, animationDuration }}` (то же в DS §14.3 п.12).
- `GlassContainer` со `spacing` сливает соседние стеклянные кнопки — так это выглядит в системе.

**Б. `@callstack/liquid-glass` 0.8.2** (Callstack, живой, 16.11.2026) — то же, но 0.x, своя родная часть и новая сборка. Ничего сверх А не даёт.

**В. `NativeTabs` expo-router** (`expo-router/native-tabs`) — системная панель вкладок с жидким стеклом целиком. Но:
- вид и поведение панели становятся системными: «Наряд», «жидкая» подложка `liquidStretch` и наш `TabBar` уйдут;
- на вебе её нет.
- Это решение «Графита», а не техники. Отметить как вариант для чата дизайна.

### Рекомендация
А — общий `GlassSurface` в `src/ui` по образцу `tabGlass.ts`, для всех стеклянных поверхностей «Графита»: панель, плавающие кнопки, шапка при прокрутке.

Добавить:
1. `GlassContainer` для групп кнопок.
2. Проверку `AccessibilityInfo.isReduceTransparencyEnabled()` с подпиской. Документ предупреждает: `isLiquidGlassAvailable` бывает `true`, даже когда доступность ограничивает эффект. При «Понижении прозрачности» — матовая плотная поверхность `surf`.

## 10. Переходы и «уменьшить движение» — как у лучших

### Как делают лучшие
Apple HIG «Motion» и системные приложения iOS: при «Уменьшение движения» слайды, масштаб и перелёты заменяются растворением; растворения и смена цвета остаются; пружины и параллакс выключаются. Отдельная настройка iOS «Предпочитать переходы растворением» делает то же для системных переходов стека.

Наша DS §14.5 уже записана так же. Не сделано:
- З3 — шторка сейчас без анимации, а нужно растворение;
- витрина;
- сторож.

### Варианты
**А. Reanimated.**
- `ReduceMotion.System` по умолчанию у каждой анимации (документ «Accessibility»: «ReduceMotion.System — disabled when the device setting is on»).
- `useReducedMotion()`. **Но** он возвращает значение «when the app started» — смену настройки при открытом приложении не видит.
- `ReducedMotionConfig` у корня задаёт режим всем анимациям сразу.

**Б. `AccessibilityInfo.isReduceMotionEnabled()` + `addEventListener("reduceMotionChanged")` из ядра RN** — живая подписка. На вебе — `matchMedia("(prefers-reduced-motion: reduce)")`.

**В. Каждый компонент сам по себе** (как сейчас — около 25 вызовов `useReducedMotion`) — источник расхождений.

### Рекомендация
А + Б: один хук `useMotion()` в `src/ui`.
- Возвращает `reduce` из живой подписки Б.
- У корня ставит `<ReducedMotionConfig mode={reduce ? Always : Never}>`, так что анимации Reanimated и SET (п.1) берут одно значение.
- Отдаёт готовые варианты `enter` / `exit` по таблице §14.2: слайд → `FadeIn durFast`.

Все ~25 мест переводятся на него. Сторож запрещает прямой `useReducedMotion` вне `src/ui/motion` (правило 29). Системные переходы стека не трогаем — их меняет система.

### Риски
- e2e идут с `reducedMotion: "reduce"` (§14.4), то есть путь «с движением» в браузере не прогоняется. Нужна одна спека с движением (Н-75).
- Хук нельзя звать до первой отрисовки корня — начальное значение синхронно из `useReducedMotion`, потом подписка.

### Объём
1–2 дня + перевод мест — волной «Графита».

Новая сборка: нет.
