### #1100 Строка раскрывается в карточке; смахивание (К1 для «Скрыть»)
Слова: «Я не хочу, чтобы при нажатии на позицию открывалось новое модальное окно. Смахивание вправо: две кнопки — «удалить» и «заменить». «Заменить» — открывается каталог, я добавляю другую позицию, или просто очищается поле. Смахивание слева направо — строку можно скрыть. ### #1154 Аудит экранов: структура и единообразие (open; основатель, ядро, до-1.0) — шаг 5.0 эпика Э5

Порядок переделки: ошибки → правила и сторожа → компоненты (`ToggleRow`, `SelectField`, закреплённая панель) → настройки → формы → … → шторки.

## 3. Движок `packages/estimating-engine`

### 3.1 Что считает строку и смету
- `estimate.ts`: `Line` (`:9-23`: `sku, name, quantity, unitPriceCents, unitCostCents, unitMaterialCostCents, purchaseTaxBps, taxable, isOptional, selected, clientVisible`), `lineTotal(l) = roundCents(quantity × unitPriceCents)` (`:60`), `lineCost(l, includePurchaseTax)` = `round(qty × (unitCost + unitMaterialCost × purchaseTaxBps))` (`:62-69`), `computeOption(lines, tax, discount)` (`:77-112`).
- `computeOption` по шагам: (1) если `clientVisible === false` и цена ≠ 0 → `ValidationError «Скрытая строка… не может иметь цену»` (`:79-83`) — правило #1100 «скрыть можно только при нулевой продаже» УЖЕ есть в движке (на уровне `Line`), но `toLine` его не передаёт (`custom.ts:120-128` не ставит `clientVisible`); (2) `subtotal` = Σ `lineTotal` включённых строк (необязательная считается только если `selected`) (`:88`); (3) скидка: % — `round(subtotal × discountBps/10000)` (`discountBps` — целые bps, half up, `:75, :92`), фикс. — `min(cents, subtotal)` (`:93`); (4) `net = subtotal − discount`; (5) налоговая база: `taxableSub = Σ lineTotal(taxable)`; `taxableDisc = round(discount × taxableSub / subtotal)` (скидка пропорционально облагаемой части, `:96-97`); налог `= round((taxableSub − taxableDisc) × rate)` один раз на вариант (`:98-101`), режимы `added_on_top` и `tax_inclusive_display`; (6) `total`, `revenue = total − tax`; (7) `cost = Σ lineCost`, `margin = net − cost`, `marginPct = margin×100/net`, один знак после запятой, null при net=0 (`:105-107`). Возвращает также `lineTotals[]`, `lineCosts[]`, `warnings` («Итог $0»).
- `custom.ts`: `computeCustomOption(option, settings)` (`:133-148`): `activeLines` (отбрасывает пустые), `toLine` — `taxable = tax.enabled && tax.groups[l.group]` (налог по ГРУППЕ), `quantity` через `jobLineQty` (4 знака, half up, как сервер `numeric(14,4)`), считает через `computeOption` с `mode: "added_on_top"`, затем `groupSubtotals`, `deposit` (`depositAmount :89`, %/фикс), лимит CA `caDepositLimit :87` (меньшее из 10 % и $1000). `catalogCost/catalogPrice :154-159` (закупка × (1+налог поставщика) × (1+наценка), без промежуточного округления), `partsCost :184`, `marginPctOf(price, cost) :195` (одна цифра, может быть <0), парсеры `parseMoneyToCents/parsePctToBps/parseQty :162-178`.
- `jobLines.ts`: `jobLineQty`, `taxModeFor(taxExempt)`, `jobLinesTotals` — для работ без сметы (строки с `taxable` по строке).
- Откуда ставка налога: НИОТКУДА автоматически — вводится вручную в шторке «Налог» (`TaxSettings.rateBps`, по умолчанию 0); ставки компании/штата в коде нет. PRD `docs/03-prd/19-taxes.md` описывает профили (`TaxProfile`, `TaxRate`, пресеты-заглушки), в приложении не реализовано.
- Округление: round half up до цента (`roundCents`); налог — один раз на вариант; скидка в целых bps; количество — 4 знака. Налог закупки в себестоимости — внутри `lineCost` без промежуточного округления; в приложении вместо этого налог поставщика зашит в `unitCostCents` каталога (`catalogUnitCost`) — отличие от PRD 19 §7.6 (там снимки `unit_material_cost_cents` + `purchase_tax_bps` на строке, а цены поставщика хранятся без налога §7.10).
