# Аудит интерфейса по методике unslop (05.11.2026)

> Только отчёт, ничего в коде не менялось. Методика: скилл [unslop](https://github.com/heydamir/unslop) (раздел аудита «признаки слопа»), прочитан как текст из временной папки вне репозитория; его скрипты не запускались, в проект он не ставился, папка удалена.
> Снимки: 7 экранов × 390 / 820 / 1280 × тёмная / светлая (сборка BUILD 82, до перевода лидов — «Лиды» с тех пор на новых карточках, iBonpoc/OCTODEX#86). Экраны — то, что основатель видит каждый день: «Выезды» (мастер), «Сегодня», «Клиенты» (уже на новых карточках), «Лиды», карточка клиента, смета, страница клиента `/p/`.
> Каждое замечание сверено с «Нарядом» и правилами `CLAUDE.md`: если unslop советует противоположное нашим правилам — в разделе «Не применимо». Исправления — обычными PR владельцев экранов, только через токены.

## 1. Главные выводы

1. **Жёлтого слишком много.** На телефоне 3–6 жёлтых элементов на экране (активная вкладка панели, сегменты, «Новый лид», «Ответить» на каждой карточке, «Открыть выезд», «Продолжить настройку»). Правило 2: акцент один — главное действие. Исправлено пока только на «Клиентах» (PR iBonpoc/OCTODEX#82).
2. **Цвет статуса уходит не на статусы.** Синий у счётчика «Пунктов чек-листа осталось: 13», оранжевый у прогресса «5 из 8»; «Ждёт ответа N мин» нарисован вместо статуса лида (это вычисляемый признак, `15-story-map.md` §5).
3. **Один компонент — два вида.** Чип статуса где-то залитый, где-то контурный, без правила, когда какой.
4. **Ритм и раскладка на широких экранах.** В одной сетке разные ширины и высоты карточек («Выезды» 1280: блок на 1200 px рядом с колонками по 390 px; «Лиды» 820: ряды разной высоты), кнопки на всю ширину 1200 px, строки документа на 1200 px (смета, `/p/`, контакты клиента).
5. **Форматы.** Даты «чт, 5 нояб.» рядом с временем «8:30 AM» (правило 7: даты en-US), суммы то с центами, то без ($150 рядом с $145.56), троеточия («Лид без ответа 22 мин · An…», заголовок `/p/` «OCTODEX Demo Home S…»).

## 3. Не применимо (unslop советует, «Наряд» решил иначе)
- «Убрать стеклянные карточки с бликом, сделать плоско» — у нас стиль «Стекло».
- «Убрать радиальные пятна / блобы на фоне» — фон `--glow` — токен, на нём держится размытие. *Наблюдение для основателя:* в светлой теме пятна .2–.3 дают серое пятно в центре на 1280 — можно обсудить силу пятен, не их наличие.
- «Акцент из мира продукта, тёплые нейтралы» — акцент `#FBFF00`, графитовая и тёплая светлая темы зафиксированы.
- «Шрифт под характер продукта» — Onest и шкала 28 / 20 / 15 / 13 / 11.5 / 10.5.
- «Не всё пилюлями» — пилюли — стиль «Наряда»; кнопки ≤ 36, зона нажатия 44.
- «Номер версии в шапке — служебный шум» — правило 11 (основатель так видит, какая сборка открыта).
- «Цветная кромка слева лишняя» — кромка дублирует статус вместе со значком и словом; по 06 — только у warn / bad.
- «Подписи у фактов вместо значков» — решение основателя: значок без слова, подпись — в `accessibilityLabel`.

## 4. Что поменять в правилах и дизайн-системе, чтобы ошибки не повторялись

Ошибки выше — не случайные: у каждой группы есть общая причина. Предложения (решает руководитель / основатель; внедрение — отдельными PR):

| Группа ошибок | Причина | Предложение | Как проверять автоматически |
|---|---|---|---|
| Много жёлтого | `Button` по умолчанию `primary` (жёлтая); вкладки, сегменты, `MultiChips` выбранные — тоже `acc` | **Правило «один акцент»:** `Button` по умолчанию `secondary`; `primary` только у главного действия экрана (не больше одного на экран); выбранное состояние вкладок, сегментов, чипов — `surf2` + рамка `ink` (как уже сделано у `ChoiceChips` в #82) | e2e-сторож в `08-layouts`: на каждом экране не больше одного видимого элемента с фоном `acc` (кроме «＋» панели) |
| Цвет статуса на счётчиках и прогрессе | `StatusChip` берут для любого чипа | **Разделить компоненты:** `StatusChip` — только статусы и признаки из §5 (тип: ключ статуса, а не произвольный тон); для счётчиков и меток — серый `Tag`; прогресс — `stepBar` | модульный тест / сторож дизайна: `StatusChip` получает только ключ из списка §5 |
| Два вида чипа статуса | нет правила, когда контурный | **Правило:** залитый — статус; контурный — вычисляемый признак (как в `ListCard`) | сторож дизайна: `soft` только у признаков |
| Разные ширины и высоты в сетке, кнопки на 1200 px | у экранов свои `View` / `Grid` | **Правило раскладки:** сетка карточек — только `CardGrid`; кнопка не шире карточки; на 1280 у документов (смета, `/p/`, контакты) ширина колонки ≤ новый токен `layout.docMax` (≈ 720) | расширять `CARD_SCREENS` сторожа выравнивания; в `08-layouts` — ширина кнопок ≤ ширины родительской карточки |
| Даты по-русски, суммы с центами и без | форматирование по месту | **Одна функция даты en-US** для всех экранов (`i18n.day` в формате `Nov 5`) и **на документах всегда центы** | модульный тест форматтеров; e2e: на `/p/` и в смете все суммы вида `$X.XX` |
| Троеточия и обрезка заголовков | `numberOfLines` в старых экранах | **Правило 06 v2 на все экраны:** текст переносится, обрезка только по высоте без «…» | e2e-сторож в `08-layouts`: в видимом тексте нет «…» (как в спеке 29) |
| Неровный вертикальный ритм | отступы подбирали на глаз | **Шкала ритма:** внутри блока `space-2`, между элементами карточки `space-3`, между разделами `space-6` — в `HANDOFF.md` «Наряда» | визуально (снимки) — автоматикой не ловится |

Самое дешёвое и полезное сейчас: **сторож «один жёлтый на экран»** и **сторож «нет …»** в `08-layouts` — они сразу покажут все экраны с этими ошибками, а исправлять можно экран за экраном.
