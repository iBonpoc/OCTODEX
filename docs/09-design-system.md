# 09. Дизайн-система (бриф)

> Статус: направление выбрано по референсу основателя («Glassy SideBar»). Живой прототип: `design/copper-glass-direction.html` (опубликован как Artifact).

## Направление: Copper Glass
- **Стекло** (frosted glass, blur + saturate, светлая кромка сверху) поверх тёплой «сцены»: орех, медь, графит.
- **Акценты:** огненный оранжевый **Ember** только для главного действия и срочных отметок; **Copper** для выбранного и акцентов (отсылка к медным гаттерам).
- **Форма:** «пилюли» для меню, поиска, чипов и кнопок; карточки 20–22, панели 30–32.
- **Навигация на десктопе и планшете:** стеклянный сайдбар, который сворачивается в узкую панель с иконками, бейджами и подсказками.
- **Навигация на телефоне:** плавающий стеклянный таб-бар с центральной огненной кнопкой AI-помощника (голос).
- **Шрифты:** Barlow Condensed для сумм и заголовков; Geist для текста; Geist Mono для размеров (148′ 0″, 6″, .032).
- **Темы:** тёмная и светлая на равных.

## Правила (не нарушать)
1. Стекло только для навигации и инструментов. **Данные** (суммы, сметы, списки) лежат на плотных поверхностях с контрастом ≥ 4.5:1, потому что работа идёт на улице и под солнцем.
2. В режиме iOS «Reduce Transparency» стекло превращается в сплошную поверхность.
3. Минимальный размер тапа в поле 48 pt (работа в перчатках).
4. Огненный оранжевый — не больше одного главного действия на экране.
5. Семантические цвета (оплачено, ожидает, осмотр, срочно) отдельно от акцента.

## Анимации и движение (motion)
Принцип: движение объясняет, что произошло (откуда взялось, куда делось), а не украшает экран.

| Что | Как | Длительность / кривая |
|---|---|---|
| Нажатие кнопки | «Подпружиненное» сжатие до 92–96% и отскок | вниз 80 мс, возврат пружиной ~500 мс |
| Наведение на карточку (десктоп) | Подъём на 2–3 px, тень глубже | пружина ~550 мс |
| **Drag & drop** | Карточка **поднимается** (scale 1.05, наклон −2°, глубокая тень, обводка акцентом), на старом месте пунктирный «слот». Колонка под пальцем подсвечивается, соседние карточки **раздвигаются** (FLIP). При отпускании карточка **приземляется** пружиной в слот, расходится кольцо-вспышка | подъём 350 мс, следование 140 мс, приземление ~480 мс |
| Старт перетаскивания | Мышь: сдвиг на 5 px. Палец: долгое нажатие 230 мс (иначе это прокрутка) | — |
| Тактильный отклик (iOS/Android) | Лёгкий удар при подъёме, средний при приземлении (UIImpactFeedbackGenerator) | — |
| Перемещение кнопкой «Дальше» | Тот же FLIP-переезд и вспышка приземления | ~600 мс |
| Галочка задачи | «Поп» от 50% до 100% пружиной | ~500 мс |
| Смена экрана | Появление снизу на 12 px с проявлением | 550 мс, ease-out |
| Сворачивание меню | Плавное изменение ширины | 350 мс |

Пружина: `cubic-bezier(.34,1.56,.64,1)`, в браузерах с поддержкой `linear()` более точная кривая. В нативном iOS это `spring(response: 0.45, dampingFraction: 0.72)`.
**Reduce Motion:** при системной настройке «Уменьшить движение» все пружины и переезды отключаются, изменения применяются мгновенно.
Где ещё нужен drag & drop: канбан сделок, расписание (перенос работы на другой день или бригаду), порядок позиций в смете, точки на чертеже гаттеров, распределение работ по бригадам на карте.

## Библиотеки UI (решение на этапе разработки)
- **Веб (Next.js):** основа shadcn/ui + Tailwind + Motion. **KokonutUI** (https://kokonutui.com) и подобные shadcn-реестры берём **выборочно**: отдельные анимированные компоненты, перекрашенные под наши токены. Кандидаты: кнопки с эффектами, AI-поле ввода, карточки, переключатели. Целиком не ставим, лицензию проверяем перед использованием.
- **iOS/Android (React Native / Expo):** веб-компоненты здесь не работают. Анимации и drag & drop делаем через Reanimated + Gesture Handler (или Moti), стекло через нативный blur. Токены общие с вебом.


## Токены: всё через них (правило основателя)
Ни один экран не содержит «зашитых» значений цвета, размера, отступа, радиуса, шрифта или анимации. Всё берётся из токенов. Изменили токен — изменилось **везде**: в вебе, на iPhone, на Android, в портале и в PDF.

Три уровня токенов:
| Уровень | Пример | Кто использует |
|---|---|---|
| **1. Базовые (primitive)** | `color.copper.500 = #d0864c`, `space.4 = 16`, `radius.pill = 999`, `font.size.15 = 15` | Только токены уровня 2 |
| **2. Смысловые (semantic)** | `color.action.primary.bg`, `color.text.secondary`, `surface.glass`, `surface.solid`, `space.card.padding`, `motion.spring` | Компоненты |
| **3. Компонентные (component)** | `button.height.md = 40`, `button.radius`, `input.height = 42`, `input.border.focus`, `card.radius`, `tabbar.height`, `kanban.card.padding` | Конкретный компонент |

Примеры глобальных изменений:
- «Сделай все кнопки ниже» → меняем `button.height.*`.
- «Поменяй вид всех текстовых полей» → меняем токены `input.*`.
- «Другой акцент» → меняем `color.action.primary.*`.
- «Компакт» → набор токенов плотности `density.compact` переопределяет `space.*`, `button.height.*`, `input.height`, `font.size.*`.
- Тема (светлая/тёмная) и стиль (Copper, Daylight…) — это тоже наборы значений смысловых токенов.

Реализация: один источник правды `packages/design-tokens` (JSON в формате W3C Design Tokens) → генерация CSS-переменных и Tailwind-темы для веба и TypeScript-констант для React Native. Компоненты существуют в одном экземпляре (одна кнопка, одно поле) и используются на всех экранах. Style Lab уже построен так: все 5 стилей, темы и «Компакт» переключаются только заменой токенов.

## Темы (правило основателя)
Каждый стиль и каждый прототип обязательно имеет **светлую и тёмную тему** с переключателем; по умолчанию следует системной настройке телефона или компьютера. Обе темы задаются наборами смысловых токенов.

## Статусные цвета (решение основателя: стекло + разные цвета для статусов)
Цвет на экране всегда означает состояние, а не украшение. Один и тот же статус выглядит одинаково везде: в списках, календаре, таймлайне, на карте, в уведомлениях, в портале и PDF.

| Статус | Цвет | Где используется |
|---|---|---|
| Оплачено / Готово | зелёный | оплаченный инвойс, закрытая работа, подписанная смета |
| Просрочено / Ошибка | красный (коралловый) | просроченный счёт, пропущенный визит, ошибка синхронизации |
| Требует внимания / Скоро срок | янтарный | срок завтра, клиент открыл смету 3 раза, истекает страховка субподрядчика |
| В работе / Отправлено | синий (циан) | работа идёт, смета или счёт отправлены |
| Запланировано | фиолетовый | будущий визит, повторная чистка |
| Новый лид / Возможность | лайм | новый лид, upsell-подсказка |
| Черновик / Нейтрально | серый | черновики, архив |

Для каждого статуса токены: `status.<name>.fill`, `.on-fill` (текст на заливке), `.soft` (лёгкий тонированный фон или стекло), `.edge` (рамка и свечение), `.ink` (цвет текста статуса на обычном фоне), иконка. Значения задаются отдельно для светлой и тёмной темы с контрастом текста ≥ 4.5:1.
Правило доступности: статус никогда не передаётся только цветом. Всегда есть иконка и подпись.
На стекле карточка получает лёгкий оттенок и цветную кромку своего статуса (просроченный счёт светится красным краем, оплаченный — мягким зелёным).
