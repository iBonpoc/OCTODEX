## Как считаны нажатия
- Нажатие = тап, смахивание или выбор пункта. Ввод текста и цифр не считается (пишу «ввод: N полей»). Системное окно SMS/почты (отправить в нём) считаю отдельно как «+1 системное».
- «≈» — оценка по коду, на устройстве не мерил (жесты и клавиатуру в браузере не проверить, правило 27). Всё, что не видно из инвентаря, помечено «не проверено».
- Jobber / HCP: число шагов даю, только если справка его однозначно даёт; иначе «не подтверждено» и то, что справка говорит словами. Мобильная справка Jobber/HCP про смахивание и долгое нажатие молчит (`research §5`, п. 5).
- Пути в код — от `apps/mobile/src/`.

## 1. Смета на объекте с нуля
**Роль:** мастер или офис/продавец на объекте, телефон, одна рука. **Цель:** за 5–10 минут набрать смету (3 свои позиции, 2 из каталога, разделы «Материалы» и «Работа») и отправить клиенту, пока он рядом.

**Шаги сейчас (офис / продавец):**
1. Деньги → «Сметы» (1–2, зависит от того, откуда пришёл) → «＋» (1) → «Новая смета» (1) — `moneyTabs.tsx:41-53`. Или с карточки лида/клиента «Смета» (1).
2. Шторка «С чего начать?» (если есть шаблоны) → «Пустая смета» (1) — `new.tsx:1570`.
3. Шторка клиента открывается сама, если клиент не задан → выбрать клиента (1) — `new.tsx:192`.
4. 3 свои позиции: «＋ Позиция» (1) + поля «Кол-во» и «Цена» (по 1 нажатию, «Что делаем» уже в фокусе) = 3 на позицию → 9. Ввод: 3 названия, 3 кол-ва, 3 цены.
5. Раздел «Материалы/Работа»: отдельной кнопки раздела нет; разделы строятся сами **по полю «Вид»** строки (авто-группы, `new.tsx:277`). Нужно выставить «Вид» на строке (1 на строку, если по умолчанию не тот) → ≈ 3. Явно: «˅ → Добавить раздел» (2) и перетаскивание строк.
6. 2 из каталога: «˅» (1) → «Из каталога» (1) → отметить 2 позиции (2) → закрыть шторку (≈ 1, «набор — несколько») ≈ 5. Каталог пуст → тупик «Каталог пуст» (см. №12).
7. «Готово» (1) → карточка сметы. «Отправить клиенту» (1) → шторка «Отправить» (1) → 5-секундный отсчёт «Отменить · 5» → системное SMS (+1). Короче: круглая «Отправить» в шапке редактора (`est-send-top`, 1) сохраняет и сразу открывает шторку, дальше 1 + системное.
**Итого ≈ 24 нажатия + ввод 9 полей + 1 системное.** Считал без ошибок валидации.

**Мастер (`tech`):** шаги 1–6 те же (создавать можно только там, где у него выезд — `access.ts:63`), но отправить нельзя: вместо кнопки подсказка «Смету клиенту отправит офис» (`new.tsx:1375`, `EstimateCard.tsx:457`); `sendEstimate` для мастера — `noop` (`store.tsx:2404`). Функции «Передать офису / Уведомить офис» в инвентаре нет — **невозможно закончить цикл на объекте**; PDF мастер скачать может (`est-act-pdf`), показать на экране — нет («Как видит клиент» только офису).

**Jobber:** «Save and…» → Send as Email / Send as Text Message / Convert to Job / Mark as Awaiting Response (`research §3/§4`) — то есть сохранение и отправка в одном меню; число нажатий всего сценария не подтверждено. Позиции — из Products & Services или свои; разделы — только упомянуты в форуме. **HCP:** Send (самолёт), «Write it for me» (ИИ-описание), число шагов не подтверждено.

**Трение:**
- Нет «раздела» как прямого действия: «Материалы/Работа» — это «Вид» (поле строки) и «Разложить по видам» в «⋯»; три слова для одной идеи («Раздел», «Вид», «Позиция/Строка») — `inventory §3.4 п.8`.
- «Готово» — на деле «сохранить»; вместе с «Отправить» два пути в одно (шапка, «⋯», подвал, иконки SMS/Почта/Ссылка) — `inventory §3.1 п.1`.
- Мастер — тупик в конце (см. выше).
- Пять нажатий на «Из каталога» только ради двух позиций.

## 2. Правка после звонка: убрать позицию, скидка 5 %, отправить изменения
**Роль:** офис / продавец (мастер правит, но не отправляет). **Цель:** сменить уже отправленную смету и дать клиенту обновлённую, не потеряв ссылку.

**Шаги сейчас:**
1. Список → строка сметы (1) → «Изменить» (иконка, `est-act-edit`, 1) — `EstimateCard.tsx:392`.
2. Убрать позицию: корзина на свёрнутой строке (1; тост «Позиция удалена» + «Отменить»).
3. Скидка: прокрутка вниз → строка «Скидка» (1) → сегмент «%» (1) → ввод 5 → закрыть шторку (1; «применяется сразу», кнопки «Применить» нет) — `new.tsx:1463`.
4. Круглая «Отправить изменения» в шапке (`est-send-top`, 1) — сохраняет, возвращает смету в «Черновик» и открывает шторку «Отправить» (`?send=1`) → «Отправить» (1) → отсчёт 5 с → системное SMS (+1).
**Итого ≈ 8 + ввод 1 + 1 системное.** Если закрыть редактор «Готово» вместо отправки — смета остаётся «Черновик» (а клиент по ссылке видит «Смета обновляется. Подрядчик пришлёт её снова» — `p/[token].tsx:199`).

**Если клиент уже подписал (AC):** при «Готово» окно «Клиент уже подписал — правки снимут его подпись» (`k1-await-ask`) → «Сохранить и снять подпись» / «Сделать копию». Для подписанной (A): «Правки не сохранить, можно сделать копию» (`k1-signed-ask`).

**Jobber:** отправленную править можно без блокировки; «Save and Send…»; у одобренной — снимается подпись, галочка «I understand», прошлая версия остаётся PDF-заметкой (`research §4`). Шагов не подтверждено. **HCP:** правка отправленной не описана в справке; одобренную/отклонённую вернуть нельзя.

**Трение:**
- Правка тихо делает «Отправлена → Черновик»: до входа в редактор предупреждения нет, есть только подпись «изменена после отправки» уже внутри (`inventory §3.4 п.4`). Клиент на время теряет возможность подписать — а он, возможно, как раз сейчас открыл ссылку.
- Новые id строк при каждой версии (`store.tsx:2468`) — истории «что изменилось» клиенту и офису нет.
- Скидка: «%» не по умолчанию — нужно переключить сегмент; закрытие шторки без «Применить» легко принять за отмену.
- «Отменить» в трёх смыслах (тост «вернуть», кнопка «Отменить» в подвале = «Discard», «Отменить · 5») — `inventory §3.4 п.2`.

**Предложение:** _(пусто)_

## 3. Клиент хочет варианты (Good/Better/Best)
**Роль:** офис / продавец (мастер тоже может править). **Цель:** дать клиенту выбор из 2–3 пакетов в одной смете и пометить рекомендуемый.

**Шаги сейчас (уже набраны позиции «Good»):**
1. «˅» (1) → «Добавить вариант» (1) — или кнопка «Добавить вариант» в карточке вариантов (`est-var-add`, 1) — делается **копия текущего варианта** с именем из `nextOptionName`, тост «Вариант «…» — копия «…». Меняйте позиции в нём» — `new.tsx:592-606`. Переключение на копию происходит само (`setCur`).
2. Переименовать: «Ещё» (1) → «Переименовать» (1) → ввод имени → «Готово» (1) — `OptionsCard.tsx:51-69`.
3. Править позиции «Better»: поменять цену/кол-во/добавить позиции — в среднем 3–5 нажатий + ввод.
4. То же ещё для «Best»: 1+1+3 (+ правки 3–5).
5. Рекомендуемый: «Ещё» → «Рекомендовать «…»» (2) (или чекбокс «★ рекомендуем» — 1).
**Итого ≈ 9–12 нажатий на два варианта + ввод 3–6 полей** (зависит от того, насколько отличаются пакеты).

**Jobber:** Good/Better/Best как пакетов нет; есть опциональные позиции («Optional»): клиент ставит/снимает галочку, итог пересчитывается; при конвертации в job выбранные становятся обычными (`research §3`). Шагов не подтверждено. **HCP:** «+ New option» → «Option from scratch» / «Option from templates», у каждого варианта свои позиции и цены, режим Present показывает варианты рядом (`research §3`); число шагов не подтверждено.

**Трение:**
- Вариант = копия: нужно вручную переделать каждую позицию; шаблона пакетов «Good/Better/Best» нет.
- Две точки входа «добавить вариант» («˅» и карточка) и два способа переключения (сегмент и сумма под ним) — `inventory §3.1 п.6, 7`.
- «Вариант» — слово, которое на другом экране означает «шаблон с N вариантами» (`inventory §3.4 п.8`).
- Максимум три варианта; сообщение появляется только по нажатию на бледную кнопку.
- Подсказки «Как работают варианты» спрятаны за «?».

## 4. Смета не тому клиенту (черновик) — сменить клиента
**Роль:** офис / продавец / мастер. **Цель:** исправить клиента (и адрес) у черновика, не набирая смету заново.

**Шаги сейчас:**
1. Открыть черновик (из списка, 1) → «Изменить» (1, иконка `est-act-edit`).
2. Карточка клиента в редакторе (`est-client-card`, 1) → шторка «Для: …» → выбрать клиента (1) — `new.tsx:1166-1178, 1603-1621`.
3. «Готово» (1).
**Итого ≈ 4 (с учётом открытия сметы).** Подставляет клиента **и его адрес**; условия сметы (язык) следуют новому клиенту (`inventory §2.7`).

**Jobber:** «Change» в блоке клиента (`research §5`); число нажатий не подтверждено. **HCP:** не подтверждено.

**Трение:**
- Карточка клиента выглядит как информация (с «›»), а не как «сменить»; нигде не сказано, что можно.
- В выборе клиента нет поиска по телефону и нет «Новый клиент» (`estimatePickers.tsx:67-90`) — если нужного клиента ещё нет, придётся выйти (см. №12).

## 5. Отправил по ошибке — отозвать
**Роль:** директор / диспетчер (`canManageLink`); sales и мастер **не могут**. **Цель:** клиент не должен успеть подписать неверную смету.

**Шаги сейчас:**
1. Открыть смету (1) → «⋯» (1) → «Отозвать ссылку» (1, красная, последняя) — `EstimateCard.tsx:394-403, 113-129`. Сразу, без вопроса; тост «Ссылка отозвана. При новой отправке будет новая» + «Отменить».
**Итого 2–3.**

**Что получает клиент:** `/p/` — «Ссылка больше не действует. Попросите компанию прислать новую.» (`p/[token].tsx:89`).

**Jobber:** отзыв ссылки не подтверждён; статус назад из Awaiting Response в Draft нельзя; можно «Archive» (скрывает от клиента) (`research §2, §5`). **HCP:** «Cancel» с «Notify customer» (письмо/SMS) и подтверждением; запись остаётся (`research §5`).

**Трение:**
- Отзывается **ссылка**, а не смета: статус остаётся «Отправлена», в списке «Ждём клиента» и «Без ответа N дн»; обратного статуса нет (`inventory §0, §5`).
- Нет уведомления клиенту («мы ошиблись, пришлём новую»); клиент, открывший ссылку, увидит «недействительна» — без объяснения.
- Нет подтверждения при необратимом (правило 5 допускает тост «Отменить», он есть) — но у sales пункта нет вообще.
- Чтобы вернуть смету в работу — «Изменить → Готово» (≈ 3 нажатия), и только после этого она «Черновик».

**Предложение:** _(пусто)_

## 6. Клиент подписал → подпись компании → счёт/депозит → работа
**Роль:** сотрудник с правом подписи (`canSignContracts`), обычно директор/офис; затем планировщик. **Цель:** дойти от «клиент подписал» до запланированной работы и задатка.

**Шаги сейчас:**
1. Увидеть: «Требует внимания» — «{name}: клиент подписал — подпишите договор» (чип «Подпишите») или группа «Нужно действие» в списке (`attention.ts:319-346`, `listGroups.ts`). Открыть смету (1).
2. Главная кнопка «Подписать договор» (1): если есть сохранённая подпись — сразу (вибро, тост «Договор подписан. Работа ждёт даты» + «Отменить»). Если нет — вкладка «Подпись компании» → нарисовать подпись на холсте → «Подписать договор» (≈ 3–4) — `EstimateCard.tsx:354-366, 978-1053`.
3. Автоматически: создаётся работа, **счёт на задаток**, лид «выигран», клиент «активный» (`store.tsx:2526`).
4. «Запланировать работу» (1) → `/job/schedule` (дальше мимо сметы).
5. Задаток: клиент платит картой на `/p/` (Stripe или симулятор). **Если клиент платит наличными/чеком/Zelle**: главная кнопка «Взять задаток · $X» и шторка «Депозит к оплате» требуют `!job` — а работа создаётся при подписи всегда, значит ветка **мертва** (`EstimateCard.tsx:367-368, 343`, `inventory §2.2/§3.2`); путь через счёт (Деньги → Счета → счёт на задаток → записать оплату, ≈ 4–5, **не проверено**).
**Итого ≈ 3 (подпись сохранена: открыть, подписать, запланировать) + задаток отдельно ≈ 4–5.**

## 9. Себестоимость материала с налогом поставщика (чек: налог 10,25 %) и налог клиенту на позицию (#2429)
**Роль:** директор / офис (себестоимость и маржа видны только `seeCosts`, мастер их не видит). **Цель:** себестоимость материала = цена по чеку + 10,25 % налога, чтобы маржа была честной; клиенту налог — только там, где он положен.

**Налог поставщика — шаги сейчас:**
- **В каталоге:** карточка позиции → поле «Налог поставщика, %» (`catalog/[id].tsx:203`) → ввод 10,25; под ним показывается «Себестоимость с налогом» (211); цена продажи = `catalogPrice(cost, vendorTaxBps, markupBps)` (`estimateDoc.ts:210`). - **В строке сметы:** поле «Себестоимость за ед.» (`LineRow.tsx:381`) — **одна цифра**, поля «налог поставщика» нет. Если позиция не из каталога, нужно считать в уме (пример: 12,00 × 1,1025 = 13,23). **Налог клиенту на позицию (#2429):** в документе нет «налогооблагаемая/нет» на строке: шторка «Налог с продаж» — **один переключатель и одна ставка на всю смету** («Считать на всю сумму…» убирает старый режим «налог по видам»; `new.tsx:1487-1530`), плюс флаг клиента `taxExempt`. #2429 в коде/доках `origin/main` не нашёл (поиск по `#2429`, `taxable` — пусто, кроме облачных строк `cloud/estimateRows.ts:55`, где `taxable` приходит из группы). **Налог на материалы, но не на работу (раздельный договор): невозможно** кроме старых смет «по видам», которые редактор больше не создаёт.

**Трение:**
