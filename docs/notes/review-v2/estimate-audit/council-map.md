# Совет по смете — хранитель карты пути (23.11.2026)

Опора: `docs/15-story-map.md` §4 (S6, S7, S8, S37a), §5 (строка Estimate); `docs/specs/38-deletion.md` §4.1, §9.2; `statusMap.ts`; `types.ts:612`; миграции `core.sql:215-231` (таблица ходов), `estimate_decline.sql`, `trash.sql`.

## Схема статусов (предлагаю)
D -> S (viewed и expired остаются признаками) -> AC -> A; S -> X (клиент, `/p/`); AC -> X (компания, причина); S -> V (voided, отозвана, Д/Дп, причина); V и X -> архив (`archivedAt`, не статус); D без отправок -> корзина (`deletedAt`, 30 дн). Правка S = снова D только в базе (ход sent -> draft есть); в приложении S остаётся S + признак «изменения не отправлены». A -> `cancelled_by_customer` существует только в базе, из UI не используется.

## Что уже в базе
- Ходы: draft->sent, sent/viewed->declined/expired/awaiting_countersign/approved, expired->sent/viewed, approved->cancelled_by_customer, sent/viewed->draft, AC->declined (`decline_countersign`, нужна причина).
- Нет: `voided`, `estimates.archived_at` (в 38 §4.1 только планируется), хода declined->draft, вызова `withdraw_estimate`.
- Корзина: страж разрешает удалить только draft с `sent_version_id is null`; возврат 30 дней (`app.trash_days()`).
- Типы приложения: 5 статусов; `statusMap`: expired и viewed -> sent, cancelled_by_customer -> declined, `voided` нет.

## Новые статусы/переходы: нужно ли в §5
- `voided` — да, §5 + S37a + check + statusMap + types; тесты db, e2e `/p/`.
- `archived_at`, `deletedAt` — нет (поля); внести в строку «Вычисляемые признаки».
- «Изменения не отправлены» — признак (сравнение версии), не статус.
- declined->draft — только если основатель решит; тогда §5 и таблица ходов.

## 5 противоречий
1. Правка S: приложение -> draft (`sent->draft` в базе), а S6/лид `estimate_sent` и текст клиента «обновляется» — состояния лида и сметы расходятся.
2. `voided` в 38/§4/S37a описан, но в §5 «с волной», в `statusMap`, `types`, check отсутствует (статус не может существовать по правилу 14).
3. §5 «приложение»: 5 статусов, в базе `expired`, `viewed`, `cancelled_by_customer` схлопнуты; бриф говорит о «отказ клиента» как нет — а S->X и `decline` клиента есть в базе.
4. 38 §4.1 планирует `estimates.archived_at` и «В архив»; в миграциях её нет, X — тупик без архива.
5. Корзина (`trash.sql`) удаляет только draft без отправок; бриф (решение 11 «удалить» в конце пути) требует удалять и отправленные — несовместимо без `voided`/архива.
