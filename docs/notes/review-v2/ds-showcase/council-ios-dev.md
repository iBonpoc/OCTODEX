# Витрина «Дизайн-система» — взгляд iOS-разработчика (23.11.2026)

Смотрел: `registry.ts`, `[section].tsx`, опись, `research.md`, снимки `was/` (меню 390 тёмная; высоты экранов).
Факты: меню = 11 плоских строк + 3 скрытых экрана + «Графит» за тумблером. Длина экранов на 390 (px): Основа ≈ 9500 (~12 экранов телефона),
Прототип v2 ≈ 10500 (~13), Отступы ≈ 11800, Уведомления 4800, Строки 3700; остальные 1100–2500. Меню — 11 строк с подписями в 3–4 строки: без подзаголовков-групп и без поиска.

## 1. Как такая витрина устроена на iPhone

- **Форма = «Настройки» iOS**: большой заголовок, группы `insetGrouped` с подзаголовком группы (footer — одно предложение), строка = значок · имя · (одна строка подписи) · шеврон. Глубина **максимум 3**: группа → раздел → (якорь внутри раздела). Не 4: как в Apple HIG и Atlassian (research §4).
- **Поиск**: `.searchable` (тянущийся вниз на первом экране, скрыт под большим заголовком). Ищет по имени компонента, ключу токена и § DS — это главный сценарий разработчика («где ListGroup?»). Без поиска меню из 30+ строк непригодно. В RN: поле поиска как первая строка списка (наш `TextField`), а не нативный `UISearchController` (Expo Router `headerSearchBarOptions` есть, но живёт только на нативном стеке и не равен нашей шапке — не брать).
- **Назад-жест**: на iOS это уже даёт стек Expo Router; в коде сейчас `router.replace` на «назад» (кнопка) — это ломает свайп-назад/историю. Нужен `router.back()` с запасным `replace`, когда экран открыт по ссылке. Мелочь, но «телефон — не браузер».
- **Тема и ширина прямо в витрине**: закреплённая тонкая полоса-«панель инструментов» под шапкой раздела: сегмент `Тема: Авто | Светлая | Тёмная` и (на планшете/вебе) `Ширина: 390 | 820 | 1280` — переключатель эмулирует ширину рамкой образца, не окна. Сейчас «тема и ширина — как у экрана, меняйте в Настройках» — лишний переход туда-обратно; на каждом из шести видов проверки правила 4 это главный повторяющийся жест. Дёшево: локальный контекст темы вокруг `<View>` образцов (токены уже темизируются). Ширина — только как рамка для образцов шаблонов (§12.11), для остальных не нужна.
- **Dynamic Type**: в витрине — переключатель «Размер текста: 100 / 130 / 200 %» (тот же контекст, что даёт `fontScale.test.ts` в приложении). Правило 3 прямо привязано к масштабу шрифта — это проверка, которую разработчик иначе делает в системных настройках iPhone.
- **Большие заголовки**: `Screen` уже умеет; на разделе — большой заголовок + строка «§ DS · где в приложении» вторым цветом. Оставить как есть.

## 2. Длинные экраны (12–14 прокруток)

Не резать на «страницы» вкладками (потеряется общий вид); резать **якорями и сворачиванием**:
1. Раздел «Основа» (9500 px) разбить на **3 экрана-строки**: Цвет и статусы · Текст · Печать. Данные уже разделены на `tokens-color / tokens-text / tokens-print` — это только перекладка `screen`.
2. «Прототип v2» (10500) разбить на 3 экрана по `SECTIONS`: Шапка и объект · Списки и календарь · Фигуры v2 + шаблоны экранов. Секции уже имеют свой `id`.
3. Внутри экрана — **закреплённая «оглавление»-полоса** с чипсами якорей (прокрутка к блоку по `scrollTo` — уже есть контекст `ScreenScrollCtx`) и счётчик «3 из 7».
4. Блоки-таблицы токенов (hex, отступы) — по умолчанию **свёрнуты** (`Collapsible` из §12.12), раскрыть = смотреть значения. Образец сверху всегда виден: сначала «как выглядит», потом «значение».
5. Цель: **не больше 3–4 экранов телефона на раздел**; сторож длины — модульный тест не нужен, достаточно правила в DS.

## 3. Вибрация, жесты, анимации, стекло («телефон — не браузер»)

Витрина запускается и в вебе, но правда о них — только на устройстве. Каждый «нативный» образец получает **плашку-метку**:
- «Только на iPhone» (вибрация, жест смахивания, перетаскивание, натив-стекло, Face ID): на вебе вместо образца — статичная схема + строка «Проверить на телефоне». Сейчас это сделано выборочно (`Platform.OS === "web"` в Haptics, `SwipeRow` в UI_PENDING).
- **Вибрация**: кнопки «почувствовать» хорошо; добавить рядом **имя карты** (`haptics.*` → какой `UIImpactFeedbackGenerator`/`UINotificationFeedbackGenerator` стиль) и где она даётся в приложении (список «где» уже есть). Тумблер «вибрация вкл» — оставить.
- **Жесты**: образец-«песочница» с видимым результатом (счётчики «пройдено N pt», «скачок: нет») — это то, что просит правило 27(а). Для щипка/перетаскивания — отдельный раздел «Жесты» с тем же набором, что в приложении.
- **Анимации**: кнопка «Проиграть» + ползунок скорости ×0,25 / ×1 + переключатель «Уменьшить движение» (имитация системной настройки, проверка `reduceMotion`). Длительности — из токена (`timing`), показывать число рядом.
- **Стекло**: образец только на iOS 26 (`expo-glass-effect`), вне его — матовое запасное; метка «нативное / запасное» + «Уменьшить прозрачность» вкл. Пилот «Графит» уже умеет эту метку (§25 «Стекло»).
- Эти 4 группы свести в один раздел **«Поведение»** (не по компонентам, а по ощущению): Вибрация · Жесты · Анимации · Стекло. Apple Patterns так и делает (Playing haptics, Motion, Materials).

## 4. Что нужно разработчику на каждом образце

Сейчас есть: ключ токена, § DS, «где в приложении» (одна строка на экран). Не хватает **по компоненту**:
1. **Имя** (`ListGroup`) — копируемое (долгое нажатие = в буфер).
2. **Файл** (`src/ui/groupedList.tsx`) — строкой мелким моноширинным.
3. **Где используется** (N экранов; в описи уже есть грубый grep — перенести в данные `SECTIONS.components[]` → `{name, file, usedIn}` или считать скриптом сборки, чтобы не устарело).
4. **Токены**, которые образец рисует.
5. **Варианты/пропы** (`V2_VARIANTS` уже перечисляет — показать как чипсы «look=chips» под образцом).
Это один небольшой компонент `SpecLine` под образцом, а не переписывание образцов.

## 5. Предлагаемое дерево (3 уровня, ≤ 5 групп)

1. **Основа**: Цвет и статусы · Текст · Отступы, радиусы, слои · Иконки · Бренд · Печать
2. **Поведение** (нативное): Вибрация · Жесты · Анимации и время · Стекло
3. **Компоненты**: Кнопки и панель действия · Поля ввода · Выбор и селекторы · Окна: шторки и меню · Уведомления и состояния · Списки и строки · Фигуры v2 (числа, плашки, прогресс)
4. **Экраны (шаблоны)**: Шапка и объект · Список · Редактор/смета · Календарь
5. **Модули и пилоты** (метка статуса в строке): Gutters (рулетка, холст — когда появятся образцы) · «Графит» (архив, см. §7)

Сверху: поиск; под большим заголовком — полоса «Тема · Размер текста · (Ширина)». Подпись строки — одна строка («Кнопки · §7»), развёрнутая подсказка — внутри экрана (сейчас 3–4 строки подписи тянут меню вдвое).

## 6. Стоимость переделки

| Что | Оценка | Почему |
|---|---|---|
| Новые группы и порядок в меню (`index.tsx`), подзаголовки | **легко** | `SCREENS` — плоский массив; добавить поле `group` и рисовать `ListGroup` на группу. |
| Разбиение «Основа», «Прототип v2» на экраны | **легко–средне** | `SECTIONS[].screen` уже указывает на экран; нужны новые id в `SCREENS` + ветки в `[section].tsx`. Старые адреса `base`, `proto` оставить как **алиасы-редиректы** на первый из новых. |
| Поиск по меню | **средне** | Индекс из `SECTIONS.components` + токенов; без него — только меню. |
| Полоса темы/размера текста | **средне** | Локальный провайдер темы вокруг образцов; риск — компоненты с жёсткой привязкой к глобальной теме (стекло, статус-бар). |
| Метки «нативное», `SpecLine` с файлом/использованием | **средне** | Данные для каждого из ~120 компонентов; автоматизировать скриптом. |
| Новый раздел «Поведение» (жесты/анимации/стекло) | **тяжело** | Новые образцы с измерениями, правило 27 (тесты математики), натив-проверка. Делать отдельной волной после меню. |
| Сторож `designSystem.test.ts` | **не ломается**, если: id `SCREENS` и `SECTIONS[].screen` согласованы; новые экраны добавлены в `SCREENS`; § DS в `ds` существует; `UI_PENDING` только сокращается. Проверить блок «пилот открывается только витриной» (строки 336–344) — при удалении «Графита» его правят. |

**Адреса `/settings/design-system/<id>`**: ничего, кроме id, не меняется; ссылки в `docs/design/DS-V2-COMPLETENESS.md`, `review-2026-11-21/03-constructor.md`, DESIGN-SYSTEM.md. В e2e прямых ссылок на путь не нашёл (папка `apps/mobile/e2e`, grep по «settings/design-system» пуст). Правило: **id никогда не переименовывать**, только добавлять; переехавший — редирект (`Redirect` уже есть для неизвестного id; добавить карту `MOVED: {base: "base-color", proto: "proto-object"}`). Метки — по новым ключам `ds.*` в трёх языках (RU/EN/ES, правило 7).

Общая оценка реорганизации меню (группы + разбиение 2 длинных экранов + полоса темы): **средне** (1 PR зоны (г), около 1–2 дней; поиск и «Поведение» — отдельные волны).

## 7. Пилот «Графит»

Факты: `src/features/showcase/graphite/**` 4389 строк, свой набор токенов `graphite.ts/.css`, шрифт Jost, тумблер в AsyncStorage, сторож и тесты (`graphiteSheet.test.ts`, `graphiteBeam.test.ts`, e2e 510), раздел DS §25 + исключение §8.0. Основатель 21.11 выбрал «визуальный язык v2»; v2 уже в `src/ui` и в витрине.

**Мнение: в архив, не оставлять, не удалять сразу.**
- Не оставлять: это второй вид внутри каждой группы, свои компоненты вопреки правилу 29, свои токены в зеркале (`mirror.test.ts` и контраст держат их), и в меню появляется строка «пилот» — шум для разработчика. Держит ещё и исключения правила 3 (52 pt).
- Не удалять: живая математика (дентенты шторки, луч, стекло/Reduce Transparency, тост) — полезные находки для правила 27 и для «Поведения»; без памяти придётся изобретать заново.
- **Архив = ветка/тег `archive/graphite-pilot` + одна PR-строка «снято, откат: git revert»**; из `main` убрать: папку, `graphite.ts/.css`, тумблер, `pilot` в `registry.ts`, §25 (оставить 3 строки «снят 23.11, см. тег»), строки в сторожах. Сам откат описан в §25 («Откат: удалить папку пилота…») — значит, это делается за один PR зоны (г) + токены. Переносимое (математика жидкого стекла и «Reduce Transparency») — отдельной задачей в раздел «Стекло».
- До удаления — убедиться, что основатель не открывает «Графит» на телефоне (тумблер локальный).
