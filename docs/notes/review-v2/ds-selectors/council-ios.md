# Совет — iOS-разработчик (23.11)

## 1. Как делает iOS (числа «по памяти»)
- Pop-up button / Picker `.menu` (UIMenu): для выбора 1 из ~2–10 коротких значений. Меню открывается у кнопки, не закрывает экран, без заголовка, галочка слева у выбранного, ширина ~250–300pt (по памяти), строка ~44pt, радиус ~14pt, материал-блюр + тень. Тап вне закрывает; выбор закрывает сразу.
- `.navigationLink`: длинный список / длинные подписи / нужен подэкран — отдельный экран со строками и галочкой (Настройки → Рингтон). `.inline`: список прямо в форме, когда вариантов мало и они — суть экрана. `.palette`: ряд иконок/образцов в UIMenu (до ~5–6), без подписей.
- Sheet (`UISheetPresentationController`, detents medium/large): «задача внутри задачи» — выбор с поиском, фото, несколькими полями. Medium для короткого списка, large для поиска; шторка поверх, фон затемнён.
- UIColorWell: образец-кружок в строке; тап открывает системную палитру-шторку. Образец — всегда слева/справа от названия, не вместо него.
- Правило системы: по возрастанию «веса» — Segmented (2–4 коротких) → меню (3–10 коротких) → шторка/экран (длинные подписи, картинки, поиск, >~10–12). Меню не скроллится осмысленно и не показывает картинок.

## 2. Дерево
1. ≤4, подписи короткие, видны разом → Segmented.
2. 5–12, подпись ≤ ~20 знаков (влезает в ширину меню без обрезки), без картинок → Menu (у поля).
3. 2–6 образцов/иконок без текста → палитра-ряд (не у нас; цвет — отдельно).
4. Подпись длинная (>~24) ИЛИ нужна картинка/фото детали ИЛИ ≥13 ИЛИ поиск ИЛИ группы → PickerSheet (строки с картинкой слева, подзаголовок).
5. Цвет (до 24 образцов) → PickerSheet с образцом слева в строке (или сетка) — одна форма везде.
Критерий — самый «тяжёлый» признак, а не число вариантов: одна длинная подпись или картинка переводит весь список в шторку.

## 3. «Низ» vs «Крепление к стене»
Один механизм, два вида по правилу выше: «Низ» (5 коротких, без картинок) — Menu; «Крепление» (длинные, детали различаются видом, есть фото) — PickerSheet. Различие не вкусовое, а из содержимого: в меню картинку и 38 знаков не показать. Поле у обоих одинаковое (SelectField), различается только то, что открывается. Пользователь видит одинаковую «кнопку-значение» — это и есть единообразие.

## 4. Меню «Низ»
- А (компактное у поля) — ближе всего к iOS 26 pop-up; реализуемо на RN без нативных модулей (у вас уже Menu с измерением якоря). Б — шторка для 5 коротких слов: тяжело, закрывает форму, не по системе. В — раскрытие на месте (disclosure) — это `.inline`/accordion, двигает форму, на RN требует анимации высоты; не для pop-up.
- Поправить А: (а) якорь — край меню выровнять по правому краю поля (trailing), как iOS, ширина по содержимому, min = ширина значения поля, max 280; сейчас 240 справа норм, но не перекрывать соседнее поле «Верх» без необходимости — открывать ПОД полем, если места ≥ высоты меню, иначе НАД (флип); (б) не «поверх», а у кромки поля с зазором 4–6pt; (в) галочка слева, как в iOS, под неё резервировать место у всех строк (уже так); (г) разделитель только после «Ничего» — это iOS-приём (группа «пусто» отдельно), оставить; (д) анимация: масштаб 0.9→1 от точки якоря (transform-origin на углу у поля) + fade, 150–200 мс; reduce-motion — только fade; (е) лёгкая тактильная отдача на выбор. Блюр на RN без нативного — заменить плотной поверхностью `surface` + тень (как сейчас).

## 5. Метка рулетки
Жест — перемотка пальцем по самой рулетке; палец закрывает область под собой, поэтому важно, чтобы значение было видно НЕ под пальцем. Вариант B лучше: плашка вынесена под рулетку (палец её не закрывает), линия во всю высоту хорошо читается как «стрелка-указатель» при любой позиции пальца, соседние цифры не убраны (контекст остаётся, бледнеют). У A плашка на месте цифры — ровно там, куда ложится палец → закрыта, и убраны соседние цифры (теряется шкала). Рекомендую B; плашку можно увеличить для чтения при перемотке. Ограничение: красная — пятое исключение, только рулетка.

## 6. Общий компонент — набросок API
```
SelectField<K>: {
  label; value; items: {key, label, subtitle?, leading?: Leading}[];
  leading?: Leading          // слева в поле: значок | образец | картинка
  presentation?: "auto"|"menu"|"sheet"   // auto по дереву §2
  onChange; placeholder; error; disabled; labelAbove; testID; field
}
type Leading = {kind:"icon",name} | {kind:"swatch",color,ring?} | {kind:"image",uri,size?}
PickerSheet<K>: { items: {key,label,subtitle?,leading?:Leading,group?,disabled?}[]; searchable?: boolean (default items>12); height?: "medium"|"large"; rowHeight?: "option"|"media"; emptyOption?: {key,label} ("Ничего"/"Как у gutter") ; ... }
Menu: items тоже принимают leading (только icon/swatch 16–20, не фото).
```
Решение auto: `items.some(i=>i.leading?.kind==="image") || max(label.length)>24 || items.length>12 || searchable` → sheet, иначе menu. «Ничего/Как у gutter/Без покраски» — `emptyOption`, закреплён первым, отделён разделителем в обоих видах. Образец цвета — только Leading.swatch (исключение правила 2 остаётся в одном компоненте, названием цвета всегда рядом). Gutter и downspout тогда выглядят одинаково автоматически: один SelectField со swatch + один PickerSheet.
