# Совет по выбору значения — дизайнер дизайн-систем (систематизация)

## 1. Таксономия (минимум: 9 видов)
Значение: (1) `ToggleRow` да/нет; (2) `Segmented` — только вид экрана/шторки, 2–3; (3) `SelectField` — поле + **меню значения** (pop-up iOS) для 2–12 коротких; (4) `OptionList` — поле открывает шторку-список (строки `OptionRow`, значок/миниатюра/подзаголовок слева, галочка справа, поиск при >12); (5) `ColorField` — поле с образцом → шторка с сеткой образцов и названиями; (6) `Stepper` / `NumberField` / рулетка — числа; (7) `OptionTile` — оставить одно место (угол), не расширять; (8) `OptionRow multiple` — несколько. Меню: (9) `ActionMenu` «⋯» — действия, не значения.
Слить: `PickerSheet` + `OptionRow(s)` = один `OptionList` (поиск — флаг); `SelectField onOpen` = тот же `SelectField`, вид шторки выбирается правилом, не пропсом экрана; `Menu` делится на `ValueMenu` (галочка слева) и `ActionMenu`.
Убрать: `ChoiceChips` (52 места) и `MultiChips` (10), Gutters `Select`/`Pick`/`UnitPick`/`Switch` (свои, правило 29), `ViewTabs` как значение, `Segmented` как значение формы (PaySheet → меню), `PctUsdField` не внедрён — оставить как есть (исключение А1е). Лишних компонентов нет, лишние — места.

## 2. Дерево решения (по порядку, первое «да» выигрывает)
1. Да/нет → `ToggleRow`. 2. Число: 0–20 шагом → `Stepper`; иначе поле/рулетка. 3. Цвет-образец → `ColorField`. 4. Человек/объект, или у вариантов есть картинка/подзаголовок, или хотя бы один вариант длиннее **22 знаков**, или вариантов **>12** → строка-поле → шторка `OptionList` (поиск при >12; на 820+ поповер 360). 5. 2–12 коротких без картинок → меню значения у поля. 6. Меню в 4–12 пунктов, ≤6,5 строки видимо (остальное прокрутка). 7. >200 или нужны создание/правка → экран. Иерархия: встроенный (toggle/stepper/segmented-вид) → меню у поля → шторка → экран. Вложенность запрещена: меню внутри шторки допустимо (шторка свойств Gutters), шторка из шторки — нет, только страница `SheetPage`.
Порог 22: ширина меню 240 минус отступы ≈ 22 знака 17 pt; «Flex-A-Spout» (12) — меню, «Conductor Bracket Downspout Hanger» (34) — шторка.

## 3. Единый вид
- **Реестр «тип значения → компонент»** в DS (одна таблица): цвет → `ColorField` везде (gutter, downspout, настройки, бренд компании остаётся `ColorField` А15); единица длины, угол, вылет, размер, профиль, материал, этаж → `SelectField` (меню); крепление/верх/стена с длинными названиями → `SelectField` → шторка с миниатюрой. Новый тип значения без строки в реестре — сначала строка.
- **Один вид поля в окне.** Окно выбирает стиль целиком, поле не выбирает: по умолчанию «подпись слева, значение справа ⌄» (iOS Form); если в окне есть `FieldRow`-ряды или значения длиннее 14 знаков — **у всех полей окна подпись сверху**. Высота 44, рамка, радиус одни. Образец цвета слева от текста значения, всегда с названием.
- **Галочка: оставить как в iOS** — в меню слева (колонка 28 у всех пунктов, у невыбранных пусто), в списке справа. Причина: контейнер задаёт место, оба видны в одном окне и это нормально (iOS Настройки так же). Выравнивать = терять привычку.

## 4. «Низ» и «Крепление к стене»
Разные по данным, одинаковые по полю. Поле выглядит одинаково (подпись, значение, ⌄); раскрывается по-разному потому, что «Низ» — 5 коротких слов, ему хватает маленького списка у поля, а «Крепление» — длинные названия деталей, которые надо различать по фото, им нужен список на ширину экрана с картинками слева.
Формулировка основателю: «Вид у полей один. Короткие слова (Низ, Угол) открываются маленьким списком под полем. Длинные названия с фото (Крепление к стене, Верх) открываются большим списком снизу. Граница — 22 знака или есть фото».
Честно: в окне будет два способа открытия; это норма iOS (pop-up и лист), граница прописана числом, не на глаз.

## 5. Меню «Низ»: выбор А (с правками)
Б и В отвергнуть: Б дублирует лист поверх листа (шторка на шторке, нарушает Б1), прячет форму и кнопки; В сдвигает форму и ломает закреплённый низ. А — как pop-up iOS, форма на месте.
Правки А: ширина 240 (`menuW`), правый край = правый край поля, зазор до поля 6; радиус как у карточки (токен, не 20); поверхность светлее шторки на ступень (`surf` raised/стекло), тень elevation 2 токеном (в тёмной темы — рамка `bd` 1 px вместо тени); пункт 44, отступ слева 16, колонка галочки 28, справа 16; без заголовка (подпись поля видна над ним); «Ничего» — отдельная группа с разделителем (как сейчас, хорошо); разделители только между группами, не между строками; если снизу не хватает места — раскрывается вверх; сквозной фон-нажатие закрывает без выбора; выбранное — галочка + `ink` 600, невыбранное `ink` 400.

## 6. Метка рулетки: B
Красная линия во всю высоту с выемками сверху и снизу читается как курсор линейки («что под линией — то значение»), цифры не прячутся (A убирает соседние цифры — теряется сверка с делениями), плашка под рулеткой не закрывает шкалу. Правки: плашка вплотную к нижней выемке (сейчас парит), бледные цифры не бледнее контраста 3:1 (`mut`, не opacity 0,3), дублировать значение текстом у поля «Дробь». Пятое исключение правила 2 — красный только линия и выемки; плашка `acc`-жёлтая допустима только как токен `tape.markFill` (уже исключение 2) — не расширять.
