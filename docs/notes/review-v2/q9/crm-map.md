## 2. «Станет»

Принцип: **«˅» = как добавить позицию; ⋯ шапки = вся смета (вид, структура, варианты); ⋯ группы = этот раздел; ⋯ строки = эта строка, без того, что уже видно на строке.** Каждое действие — одно место; разный адрес (вся смета / этот раздел) — разные места.

## 3. Находки

### Блокирует
1. **Редактор, офис, подписанная смета (`approved` / `awaiting_countersign`), ⋯ шапки:** виден «Отправить изменения» (условие пункта — только `canSend`, без `!signed`; у круга `!signed` есть). Нажатие → `save(true)` → без правок `router.replace(/estimate/id?send=1)` → в `EstimateCard.useEstimateCore` шторка отправки открывается по `maySend` **без проверки статуса** (`useState(!!openSend && maySend)`, `SendSheet` рисуется при `universal && maySend`), хотя на самой карточке «Отправить» у подписанной нет (`canSend` требует draft/sent). Что сделает «Отправить» из этой шторки для подписанной (`store.sendEstimate` на `approved`) — проверить; в любом случае это действие, которого в этом статусе быть не должно. Чек-лист 2. → Прятать пункт при `signed` (С2) и не открывать шторку по `?send=1`, если `!canSend`.
2. **Редактор, офис, черновик/отправлена, шапка:** «Отправить» стоит дважды — круг ➤ и ⋯ «Сохранить и отправить». Чек-лист 9, слова основателя 22.11. → Убрать из ⋯ (С1).
3. **Редактор, ≥ 2 вариантов:** «Добавить вариант» (˅) и «Вариант — копия „A“» (карточка) — одно и то же `addOption`, разные слова в двух местах. Чек-лист 9 и 7. → С4.
4. **Строка, раскрыта:** «⋯ → Удалить» и 🗑 стоят вплотную (44 + 44), плюс «Удалить» в смахивании — три пути одного опасного действия; удаление в меню рядом с безопасными пунктами. Чек-лист 5 и 9 (тост «Вернуть» есть — данные не теряются, поэтому на грани «желательно»). → С9.

### Желательно
5. Круг ➤ у отправленной сметы без правок называется «Отправить изменения» (`existing.status !== "draft"`, не смотрит на `dirty`) — изменений нет. Чек-лист 7. → С3.
6. «˅» смешивает «как добавить позицию» со структурой документа (раздел, вариант). Пользователь Jobber/HCP ждёт под «+ ▾» только источники позиций. → С5, С6.
7. Меню строки 7 пунктов, из них 4 дублируют видимое (Выше, Ниже ↔ ⠿ и «Переместить»; Удалить ↔ 🗑; Скрыть ↔ переключатель). → С9.
8. «Экран для клиента» у мастера (и у всех без `seeCosts`) ничего не меняет на экране. Чек-лист 3. → С7.
9. «Экран для клиента» (редактор) и «Как видит клиент» (карточка) — похожие слова, разный смысл; при этом режим редактора показывает скрытые $0-строки, которых клиент не видит. → С13.
10. «★ рекомендуем» под суммой варианта — скрытая кнопка, которая молча снимает рекомендацию (без тоста «Вернуть»). → С11.
11. Пустая смета: «Из каталога» жёлтая внизу и «Каталог» в пустом состоянии на одном экране; плюс ⋯ шапки «Сохранить и отправить», хотя круга нет. → С12, С1.
12. «Удалить раздел» не говорит, что позиции остаются — пугает, человек не уберёт лишний раздел. → С8.
13. Добавить позицию из каталога при наличии позиций — 3 нажатия (˅ → Из каталога → позиция). Jobber/HCP: в поле имени новой позиции подсказки из прайса (2 нажатия + буквы, без выбора способа). Предлагаю отдельной задачей: подсказки каталога в поле «Название» новой строки — тогда «Из каталога» станет редким.
14. Карточка сметы: одно действие для `sent` — «Отправить ещё раз» (`EstimateCardBody`) и «Напомнить» (`EstimateObject`). Выбрать одно слово.

### Мелочь
15. Правка шаблона — шапка без ⋯: нет «Строки подробно» и «Разложить по видам». → С14.
16. `OptionsCard`: ветка «один вариант → Добавить вариант» никогда не рисуется (карточка только при ≥ 2) — мёртвый код, путает читающего.
17. Сумма варианта под сегментом — вторая цель для того же выбора варианта (две нажимаемые полосы одна под другой).
18. ⋯ шапки (снимок `3-more-menu`): «Сохранить и отправить», «Разложить по видам» переносятся на 2 строки — меню шире или слова короче («Разложить по видам» → «По видам»).
19. В ⋯ группы три пункта начинаются со слова «Добавить» и два с «+», один с лупой — слова и значки не различают «новая» и «из каталога» (у «˅» каталог — значок книги, у группы — лупа). Один значок каталога везде.
