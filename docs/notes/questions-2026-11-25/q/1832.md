# 1832 — Цена ниже минимальной наценки: запрещать или предупреждать

## Жив?
**ЖИВ — только В4** (минимальная наценка). Остальное отвечено. Комментарий в задаче от 25.11 это перечисляет, источники такие:
- В1 «моя цена — это цена в каталоге» — `artifact-answers/C-до-2026-11-16.md` Г3;
- В3 «себестоимость = цена поставщика уже с налогом» — `founder-answers-1.md:391`, `:400`;
- подсказки «?» — `founder-answers-1.md:416`.
По В4 ответа нет ни в журналах, ни в задачах `решение`.

**Важно:** спека 55 относит минимальную маржу к работам **после 1.0**. `docs/specs/55-company-markup.md:356`: «после 1.0 | … минимальная маржа …». В 1.0 (55-2) входит только предупреждение «ниже себестоимости» в строке сметы. Значит, вопрос «запрещать» про 1.0 не держит. Его нужно задать вместе с вопросом «нужен ли вообще порог минимальной наценки».

## Что решаем
Сотрудник ставит в смете цену ниже вашей минимальной наценки, например почти по себестоимости. Приложение только предупреждает или не даёт сохранить?

## Ресёрч
- **ServiceTitan Sales Margin Control** — лучший образец в FSM. Два порога. Ниже «порога предупреждения» — жёлтая плашка с недостающей суммой в $, работать можно. Ниже «минимума» — блок с той же суммой. Правила задаются по ролям: техник «без лимита», продавец — минимум 20 %. Самое точное правило побеждает. Менять пороги может только роль с правом «Edit Margin Thresholds». [help.servicetitan.com — Sales Margin Control](https://help.servicetitan.com/residential-s-r/docs/set-up-and-use-sales-margin-control), [Margin Enforcement](https://help.servicetitan.com/release-hub/docs/enforce-minimum-margins-margin-enforcement-feature-protect-profitability)
- ServiceTitan в 2026 добавил «Margin Granular Rules», которые блокируют сметы ниже цены. Тренд — защищать маржу правилами по ролям, а не одним общим запретом. [release-hub](https://help.servicetitan.com/release-hub/docs/protect-job-profitability-with-margin-granular-rules-block-underpriced-estimates)
- **Jobber / Housecall Pro**: показывают маржу в смете (Job costing), запрета по наценке в справке не нашёл (поиск 25.11).
- **У нас сейчас** (код): строка сметы с ценой ниже себестоимости показывает «в минус» со значком (`features/estimate/LineRow.tsx:390`, `est.row.loss`). Каталог показывает «В убытке» (`app/catalog/index.tsx:61`). Порога «минимальная наценка» нет ни в коде, ни в базе.
- Права: себестоимость видят owner, admin, office; sales — только с галочкой `view_costs`; tech и sub — никогда (`docs/specs/19-db-security.md` §9). Продавец без права себестоимости не может сам оценить, «в минусе» он или нет.

## Варианты
- **(а) Только предупреждать.** Строка помечена «Ниже наценки 20 %» (или «в минус» ниже себестоимости), сохранить и отправить можно. 0 лишних шагов, но скидку «в убыток» может дать любой.
- **(б) Предупреждать директора, останавливать сотрудника.** Владелец и админ видят пометку и сохраняют. Остальные (офис, продавец) ниже минимума отправить смету клиенту не могут: «Нужно согласие владельца» → владельцу уведомление → одно нажатие «Разрешить». Сотруднику +1 шаг и ожидание, только в редком случае.
- **(в) Запрещать всем.** Ниже минимума не сохраняется ни у кого. Директор теряет право сделать скидку ради заказа. Противоречит слову «правится по позиции» (23.11).

## Совет
**(б), но после 1.0.** Сотрудник не уйдёт в минус случайно, а вы сами решаете, когда скидка того стоит. В 1.0 оставить то, что уже есть: пометку «в минус» ниже себестоимости, без запрета. Отдельная настройка «минимальная наценка» и одобрение директором — после выпуска, как записано в спеке 55.

## По умолчанию
(а): в 1.0 только пометка «в минус» (ниже себестоимости), без запрета и без отдельного порога. Порог минимальной наценки и одобрение — задача «после-1.0».

## Мини-спека
- **1.0 (55-2, уже в плане).** Строка сметы: ниже себестоимости — `Icon alert` + `T tone="bad"` «в минус» (есть). Итог: «в минус $200 · 16.7 %» (`TotalsBreakdown.tsx`, есть). Добавить только тест: пометка видна тем, кто видит себестоимость, и не видна мастеру и клиенту (правило 19 §9, `can_view_costs`).
- **После 1.0 (если (б)):**
  - Настройка компании «Минимальная наценка, %» (по умолчанию пусто = выкл.) в «Настройки → Цены и наценка» (спека 55-1, `PctUsdField` / `NumberField`), подсказка «?» (`HelpButton`, слово основателя 23.11).
  - Расчёт — движок: `belowMinMarkup(line, minBps)`, сравнение в целых bps. Порог считается на себестоимость (как наценка).
  - Сервер: при отправке сметы `send_estimate` проверяет строки. Если роль не owner/admin и есть строка ниже минимума без одобрения — отказ `estimate_below_min_markup`. Одобрение — запись `approvals` (кто, когда, сумма недобора) в `audit_log`. RLS-тест: продавец не может обойти проверку прямым вызовом (правило 15).
  - Офлайн (правило 6): правка сохраняется локально всегда. Блок только на «Отправить», он и так требует сети.
  - Деньги — только центы и движок (правило 8). Сумма недобора в $ — как у ServiceTitan.
  - Продавец без права себестоимости видит «Ниже минимальной цены — нужно согласие владельца» без цифры себестоимости. Иначе через цифру он узнал бы закупку (спека 53 Б1).
- **Право.** Юрист не нужен.

## Вид
**Да, но только «как будет» после 1.0, если выберет (б).** Сейчас достаточно одной картинки «как сейчас», чтобы основатель увидел, что пометка уже есть.
- **Как сейчас.** Веб-сборка, демо, роль «директор». `/estimates` → любая смета-черновик → `/estimate/[id]` → раскрыть позицию → поставить цену ниже себестоимости (например, $1). Снять строку с «в минус» и итог «Прибыль: в минус $…».
- **Как будет (после 1.0, (б)), 390:**
  1. Та же строка сметы (DS §8.2а, §8.3): под суммой `StatusNote` tone `warn`, значок + «Ниже наценки 20 % · не хватает $42». Красный (`bad`) остаётся только для «в минус» — ниже себестоимости.
  2. Для сотрудника: `ActionBar` — главная кнопка «Отправить» заменена на `Button` «Попросить согласие» (`acc`), над ней `Banner` `warn` «Цена ниже минимальной — нужно согласие владельца».
  3. Для владельца: пункт в «Требует внимания» (`GroupRow`) «Смета EST-1042 · ниже наценки · Разрешить» → `ConfirmDialog` «Разрешить цену ниже наценки? Не хватает $42» → «Разрешить» / «Не разрешать».
- **Чего нет в ДС.** Правила «запрос согласия руководителя» (кто просит, где видит владелец, какие слова) в ДС нет — нужно дописать в DS §15 (обратная связь) и §8.2а. Различие `warn` «ниже наценки» и `bad` «в минус» — дописать в DS §3 (статусы).
