## Что решаем
По старой ссылке octodex.pages.dev до сих пор открывается старая версия с прошлым названием. Перенаправлять её на новый адрес GoRix и потом удалить — или пока ничего не трогать.

## Ресёрч
- **Cloudflare (официально)**: чтобы `*.pages.dev` вёл на свой адрес, делают «Bulk Redirects» — список: источник `<проект>.pages.dev`, цель — новый адрес, код 301, «сохранять параметры» и «подпути» включены; проверка — открыть старый адрес и увидеть переход. [Cloudflare — redirect to custom domain](https://developers.cloudflare.com/pages/how-to/redirect-to-custom-domain/)
- Тонкость Cloudflare: эта схема рассчитана на перенаправление на **свой домен, подключённый к тому же проекту Pages**; на чужой адрес (`gorix.expo.app`) люди на форуме получали ошибку «invalid target url» — проще целиться в `https://gorix.app` (наш домен в Cloudflare, он сам ведёт на `gorix.expo.app`). [обсуждение](https://www.answeroverflow.com/m/1190880760073298010)
- Другой простой путь (Cloudflare): заменить сборку в проекте Pages на страницу из одного файла `_redirects` со строкой `/* https://gorix.app/:splat 301`. [Cloudflare — redirects](https://developers.cloudflare.com/pages/configuration/redirects/)
- Общая практика при смене имени: постоянное перенаправление (301) держат долго (месяцы), чтобы закладки и поисковики перешли; удалять сразу — «мёртвые» ссылки.
- Риск удаления: освобождённое имя `octodex.pages.dev` может занять кто угодно и показать что угодно людям со старой ссылкой (то же уже сказано про `octodex.expo.app` в спеке 35). Значит, «удалить» хуже, чем «держать перенаправление».

## Варианты
- **(а) Перенаправить на gorix.app (301) и держать**; удалять проект не раньше выпуска и только если по старому адресу никто не ходит. 1 действие в Cloudflare, ~15 минут, обратимо.
- (б) Оставить как есть до выпуска. 0 действий; минус — старое приложение «OctoDex» видно по старой ссылке.
- (в) Удалить сразу. Кто сохранил ссылку — ошибка; имя освобождается и его может занять кто-то другой.

## Совет
**(а)**, но перенаправление держать, а не удалять через месяц. Старая версия по старой ссылке путает людей, а переход на gorix.app безопасен и обратим; удаление же отдаёт старое имя чужим. По вашему слову 09.11 — делает программист (или чат-мост на Mac под вашим присмотром), не исполнитель кода.

## По умолчанию

## Мини-спека
Не код приложения — настройки Cloudflare (вне `apps/mobile`):
1. Cloudflare → Workers & Pages → проект `octodex` (Pages): записать, что в нём (последний деплой, дата) — для отката.
2. Account → Bulk Redirects → список `old-octodex`: `octodex.pages.dev` → `https://gorix.app`, 301, Preserve query string ✅, Subpath matching ✅, Preserve path suffix ✅; правило включить. Если Cloudflare не примет цель — второй путь: новый деплой проекта из одного файла `_redirects` (`/* https://gorix.app/:splat 301`).
3. Проверка: `curl -I https://octodex.pages.dev/any?x=1` → `301`, `location: https://gorix.app/any?x=1` → дальше 302 на `gorix.expo.app`.
4. Старые Workers (если есть с именем octodex) — тот же порядок, по одному, после списка «что там».
5. `octodex.expo.app` — проверить владельца в Expo → Hosting; если не наш — записать в задачу и в `11-setup-guide.md` (люди со старой ссылкой попадают к чужому).
6. Записать в `docs/11-setup-guide.md` таблицу «Старые адреса → куда ведут».
