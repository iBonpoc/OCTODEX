E2E — `apps/mobile/e2e/specs/486-visit-no-show.cjs`.

## Что решаем
Мастер приехал, клиента нет, он отметил это в приложении. Писать ли клиенту «Мы приезжали, вас не было — давайте выберем новое время», и если да — само сразу или когда офис нажмёт кнопку.

## Ресёрч
- **ServiceTitan**: в списке статусов работы есть отдельный «Customer Not Home»; по нему компании настраивают сообщение клиенту (часто через внешнюю автоматизацию, не само из коробки). [гайд по автоматизации](https://ustechautomations.com/resources/blog/home-services-noshow-appointment-followup-automation-recipe-2026), [ServiceTitan — общение с клиентом](https://help.servicetitan.com/residential-s-r/docs/communicate-with-your-customers.md)
- Советы рынка по тексту: имя компании, дата, кто приезжал («our technician»), ясный путь «ответьте или выберите время», строка отказа от рассылок. [Service Fusion — шаблоны SMS](https://www.servicefusion.com/blog/blog-appointment-reminder-sms-templates), [Jobber — шаблоны напоминаний](https://getjobber.com/academy/appointment-reminder-templates/)
- Сообщение лучше уходит быстро (в первые минуты), пока клиент помнит про визит — это совет вендоров, не правило. [там же](https://ustechautomations.com/resources/blog/home-services-noshow-appointment-followup-automation-recipe-2026)
- Право (по памяти + `docs/legal/01-founder-protection.md`, FCC 15-72 TCPA): **автоматическое** SMS требует согласия клиента на сообщения; сообщение, которое человек отправляет сам со своего телефона, — обычная переписка. Это довод за «по кнопке».
- У нас уже есть способ «офис отправляет с телефона»: `smsHref()` в `src/features/contactLinks.ts:27` открывает приложение «Сообщения» с готовым текстом — без своего SMS-сервера.

## Варианты
- **(а) Ничего не отправлять само** (как сейчас). Офис видит пункт и сам звонит или пишет. 0 работы. Минус: офис набирает текст сам, на английском/испанском — ошибки и разнобой.
- **(б) Офис отправляет готовое сообщение одним нажатием** из пункта «Требует внимания». Кнопка «Написать клиенту» → открываются «Сообщения» телефона с текстом на языке клиента. +1 нажатие у офиса, ноль риска «ушло зря» (мастер мог уже дозвониться). ≈ 1 PR.
- (в) Само, сразу после отметки мастера. 0 нажатий. Минусы: нужен свой отправщик SMS (сервис, деньги, согласие по TCPA), сообщение уйдёт, даже если клиент через минуту открыл дверь; офлайн у мастера — уйдёт с опозданием.

## Совет
**(б).** Клиент получает понятное вежливое сообщение на своём языке, а офис сам решает, отправлять ли (вдруг мастер уже договорился). И это обычное сообщение с телефона офиса — не нужна рассылка и отдельное согласие клиента на автоматические SMS.

## По умолчанию
(а) — клиенту ничего не уходит, пункт офиса «перенести выезд» остаётся как есть.

## Мини-спека
Вариант (б), К2:
- Где: пункт `visitNoShow` в «Требует внимания» — `src/app/(tabs)/triage.tsx:73` и строка карточки `src/features/AttentionCards.tsx:55`. Сейчас одна кнопка «Назначить» (`sch.title`). Добавить вторую — `Button variant="secondary" icon="sms"` «Написать клиенту» (`testID="att-noshow-sms"`), только если у клиента есть телефон; нет телефона, есть почта — «Написать на почту» (`mailtoHref`).
- Текст: новые ключи i18n блоком `noShow.*` (правило 7): `noShow.msg` — на языке **клиента**: `tFor(docLanguageFor(db, { customerId, leadId }))` (`src/data/people`), не язык интерфейса. EN-образец: «Hi {first}, this is {company}. Our technician stopped by today at {time} but no one was home. Reply to this message or call {companyPhone} to pick a new time.» — дата/время по поясу компании, формат США; без имён сотрудников и без ссылок (ДС §19.4). RU/ES — те же смыслы.
- Отправка: `Linking.openURL(smsHref(phone, text, Platform.OS))` — открывает «Сообщения» телефона; мы ничего не шлём со своего сервера (правило 6: офлайн — просто открывается приложение).
- Отметка в ленте лида/работы: «Офис написал клиенту: нет дома» — после открытия «Сообщений» (не знаем, отправил ли; формулировка «Открыто сообщение клиенту»). Пункт «Требует внимания» не уходит, пока выезд не перенесён.
- Шторка мастера: текст `noShow.hint` «Клиенту ничего не отправится» → «Клиенту сами ничего не отправим — офис напишет ему» (EN/ES тоже).
- Тесты: e2e 486 дополнить С4 (кнопка есть при телефоне; ссылка `sms:` содержит текст на языке клиента — es-клиент → испанский); модульный тест сборки текста (язык, время в поясе компании). Правка надписи — найти старое слово в `e2e/specs` и `e2e/cloud` (правило 19).
- Компоненты — только `Button`, существующие строки «Требует внимания» (`GroupRow`), токены; ДС §19.4 (SMS), §4.4а (голос сообщений).

## Вид
Да. Снять «как сейчас»:
1. Шторка мастера: веб-сборка, роль `tech`, выезд в шаге `on_site` (как в e2e 486: в `localStorage` `octo.db.v5` визит `step: "on_site"`, `octo.role.v1 = "tech"`), открыть `/visit/<id>` → «⋯» → «Клиента нет дома» (`testID="visit-no-show"`) → шторка `testID="no-show-sheet"`. Ширина 390, обе темы.
2. Офис: роль `dispatcher`, `/triage` после отметки — строка «{имя}: клиента не было дома — перенести выезд» с кнопкой «Назначить».
Собрать «как будет» (только `src/ui`):
1. Та же шторка; меняется одна строка подсказки: «Клиенту сами ничего не отправим — офис напишет ему».
2. `/triage`: та же строка `GroupRow`, под ней две кнопки в ряд: `Button` «Назначить» (icon `calendar`, обычная) и `Button variant="secondary"` «Написать клиенту» (icon `sms`).
3. Третий кадр: «Сообщения» iPhone с готовым текстом (EN-клиент) — рисовать как простой блок текста с подписью «откроется приложение Сообщения», без своего пузыря (своих компонентов нет).
