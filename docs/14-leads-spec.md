## 0. Карта всего пути и стыки (сначала она, потом вкладки)

Порядок углубления: **Лиды → Клиенты и объекты → Сметы → Работы и визиты → Счета и оплаты → Отчёты**. Этот документ — шаг «Лиды», но стыки с соседями решены здесь, чтобы потом не возвращаться.

| Стык | Что происходит | Кто запускает | Что меняется у лида | Что появляется у соседа |
|---|---|---|---|---|
| Заявка → Лид | Звонок, форма, письмо, Thumbtack, монтажник на объекте | человек или приём лидов | `new`, таймер «ответить» | — |
| Лид → Клиент (потенциальный) | Первая запись на осмотр **или** первая смета из лида | система, по действию человека | `customerId`, `propertyId` | `Customer(status=prospect)`, `Property`, `Contact` |
| Лид → Визит-осмотр | «Записать осмотр» с выбором даты и мастера | человек | `booked` | `Job(kind=estimate)`, `Visit` |
| Лид → Смета | «Создать смету» | человек | — (`estimates.lead_id`) | `Estimate(draft, leadId)` |
| Смета отправлена | Ссылка ушла клиенту | человек | `estimate_sent`, `lastOutboundAt` | — |
| Смета подписана / депозит | Клиент на странице `/p/<token>` | клиент | `won`, `wonVia=approval|deposit` | `Customer.status=active`, работа к планированию, счёт на депозит |
| Ручная победа | «Сделать клиентом» с причиной (бумага, устно, уже оплатил) | человек | `won`, `wonVia=manual` | `Customer.status=active` |
| Закрытие | «Закрыть» с причиной | человек (система только предлагает) | `lost` / `declined` | клиент-«потенциальный» остаётся, но не в основном списке |

Правило стыков: **лид никогда не удаляется и не дублируется в клиента вручную** — переход делает одна серверная функция `lead_to_client` (идемпотентная по id лида; повтор возвращает того же клиента — в Estixa для этого был «claim token»).

## 1. Что взяли, что выбросили

| Тема | OCTODEX сейчас | Estixa | Решение |
|---|---|---|---|
| Статусы | 7: new, replied, booked, estimate_sent, won, lost, declined (в PRD другие имена) | 4 этапа, но в базе висят 6 старых | **Оставить 7 из кода Окто**, переписать PRD под них. Старых статусов в базе не держать |
| «Чей ход» | нет; таймер только до первого ответа | вычисляемое: ответить / шаг / нет шага / ждём клиента | **Взять из Estixa** — главное улучшение |
| Таймер ответа | от `receivedAt` до первого ответа | от **последнего** сообщения клиента, заново при каждом | Взять Estixa: `lastInboundAt` / `lastOutboundAt` |
| Рабочие часы | не учитываются | время видно всегда, цвет и тревоги ждут открытия дня | Взять Estixa, переключатель в настройках (по умолчанию вкл) |
| Пороги | зашиты в токены дизайна (5/15 мин) | в настройках компании | **В настройки компании**; в коде — только значения по умолчанию |
| Следующий шаг | `Task` + визит | два механизма (`follow_up_date` и `lead_task`) | **Один механизм — `Task`** (+ визит считается шагом) |
| Долгое молчание | 14 дн задача, 30 дн «закрыть?» | 2 дн «напомнить», 5 дн внимание, 14 дн «последнее напоминание», +7 дн «потерян или ждать?» | Взять Estixa (вопрос основателю В1) |
| Причины закрытия | два списка: lost (решил клиент) и declined (решили мы) | `lost_kind` из 3 + до 12 своих | **Оставить Окто** (два фиксированных списка + «другое» текстом) — отчёты сравнимы |
| Источники | свой список компании, 4 вида, «человек» как источник | фиксированный список + свои коды из сырого текста | **Окто** + модель денег из Estixa (за лид / за период / бесплатно) |
| Цена лида | `costCents` | цена + происхождение (площадка / вручную / ставка) + возвраты | Взять поля Estixa, ручную цену система не перезаписывает |
| Дубли | предупреждение | слияние в браузере **с удалением** дубля | Предупреждение + «Объединить» без удаления: дубль → `declined/duplicate`, `duplicateOfLeadId`, цена остаётся |
| Приём лидов | только вручную | одна точка приёма (форма, Zapier, Google, Angi), Thumbtack, CallRail, SMS; повторы по ключу события | **Архитектура Estixa**: одна функция приёма + журнал событий |
| Писать клиенту сама | автоответ в PRD | никогда, только готовит текст | **Estixa**: приложение готовит текст, отправляет человек (вопрос В4 про форму сайта) |
| Сводка по лидам | нет | личная: выкл / утром / вечером / оба | Взять, этап «Запуск» |
| Список | все лиды в памяти | все лиды в браузере, без страниц | Страницы с сервера по фильтру (ошибка Estixa на 1000+ компаний) |
| Канбан, массовые действия, теги, импорт CSV | нет | есть | Канбан и массовые — только 1280, этап «Запуск». Теги и «оценка лида» — **не делать** (в Estixa мёртвый код) |
| Логика в двух местах | только приложение | копия клиент/сервер + тест сверки | **Один пакет `@octo/lead-rules`** для приложения и серверных функций |

### Ошибки Estixa, которые не повторяем
1. Три системы «температуры» лида, две системы напоминаний, две тревоги скорости — **одна вычисляемая функция `leadTurn`**.
2. Мёртвые статусы в базе и диалог, который никогда не открывается — чистить в той же волне.
3. Слияние с удалением — нарушает «никогда не терять лид».
4. Коды источников из сырого текста (`yelp!`) — источник всегда запись в таблице.
5. Весь список в браузере — постранично.
6. Общие запасные ключи площадки для всех компаний — ключи только на компанию.

### Расхождения внутри OCTODEX, которые надо закрыть
- PRD: `contacted / qualified / inspection_scheduled`, код: `replied / booked`. Правда — код.
- PRD: роли owner/admin/tech, код: `director / dispatcher / tech`. Правда — код; в тексте «владелец/админ» = `director`, «офис» = `dispatcher`.
- PRD: «вручную won не ставится»; код: ручная победа с причиной. Решение: ручная можно, но `wonVia=manual` отдельно в отчётах.
- Новый лид требует телефон; PRD: телефон **или** email (Yelp часто без телефона). Исправить.
- «Записать осмотр» ставит визит на завтра 10:00 без выбора. Нужна шторка с датой, временем и мастером.
- Источник по умолчанию ищется по имени «Thumbtack» — заменить на «последний использованный».

## 3. Статусы и «чей ход»

### 3.1 Статус (хранится)
```
new ──► replied ──► booked ──► estimate_sent ──► won
  │        (в контакте) (осмотр)   (смета ушла)      (клиент)
  └──► lost (решил клиент) / declined (решили мы) — из любого открытого, всегда с причиной
       lost/declined ──► «Открыть снова» ──► replied
```
| Переход | Как |
|---|---|
| new → replied | Авто: первый исходящий (звонок, SMS, email, «ответил в Thumbtack», «Я ответил») |
| → booked | Авто: создан визит-осмотр |
| → estimate_sent | Авто: смета с `leadId` отправлена |
| → won | Авто: подпись или депозит; вручную — только с причиной (`wonVia=manual`) |
| → lost / declined | Только человек, обязательная причина; для «другое» — текст |
| Открыть снова | Причина очищается, событие в ленте |
| Архив | Не статус: `archivedAt` через 90 дней после won/lost/declined, лид скрыт из списка, в отчётах остаётся |

Статусы можно пропускать (смета без осмотра — нормально). Назад вручную — нельзя, кроме «Открыть снова».

**Причины.** lost: не отвечает, выбрал другого, дорого, не сейчас, другое. declined: невыгодно, не делаем такое, вне зоны, спам/фейк, дубль, другое.

### 3.2 «Чей ход» (вычисляется, не хранится) — `leadTurn(lead, tasks, settings, now)`
| Ход | Когда | Отсчёт | Цвет (по умолчанию) | Главная кнопка |
|---|---|---|---|---|
| **Ответить** | клиент написал последним или лид новый | `lastInboundAt ?? receivedAt` | info → warn 5 мин → bad 15 мин | «Ответить» |
| **Шаг** | есть открытая задача / визит | дата шага | будущее — neutral, сегодня — ok, просрочено — bad (с начала следующего рабочего дня) | действие задачи |
| **Нет шага** | открыт, не new, нет задачи и визита | последний контакт | warn 1 ч, bad 1 дн | «Добавить шаг» |
| **Ждём клиента** | мы писали последними, шага нет | `lastOutboundAt` | neutral; 2 дн — «Напомнить»; 5 дн — warn и в «Требует внимания»; 14 дн — «Последнее напоминание»; +7 дн — «Потерян или подождать?» | «Напомнить» |
| — | won / lost / declined | — | статус | «Открыть клиента» / «Открыть снова» |

Рабочие часы: время видно всегда; цвет и пуши «ответить» ночью ждут начала рабочего дня (настройка).

## 4. Как лид приходит

| Канал | Как | Источник | Этап |
|---|---|---|---|
| Вручную во время звонка | «+ Лид» | последний использованный | ✅ есть |
| Монтажник на объекте | «+ Лид от соседа» с визита | «Сарафан», `referredFromVisitId` | MVP |
| Форма сайта / портал клиента | код формы, защита от ботов (honeypot, Turnstile, лимит) | «Сайт» / «Портал» + utm | MVP |
| Пересылка писем площадок | адрес `leads-<slug>@in.octo.app`, шаблоны + ИИ; неуверенно → «Проверить» | по отправителю | MVP (ждёт образцы писем, Г3) |
| Thumbtack | подключение компании, события «новый лид / сообщение» | Thumbtack, цена из площадки | Запуск |
| Zapier / Make / Google lead forms / Angi | одна точка приёма с ключом компании | по каналу | Запуск |
| Входящий звонок (CallRail / свой номер) и SMS с неизвестного номера | новый номер → лид; известный открытый лид → в его ленту | по номеру | Позже |

**Единый конвейер приёма** (одна серверная функция для всех каналов):
1. Проверить ключ компании → записать `IntakeEvent` (повтор по ключу события = пропуск).
2. Привести данные к виду лида (телефон, email, адрес, услуга, ответы).
3. Найти дубль: открытый лид ≤ 30 дней по телефону/email → новое в ленту старого, своя цена остаётся отдельной строкой; совпал клиент → отметка «уже клиент».
4. Источник и цена (из площадки → ставка источника → 0).
5. Назначить (по умолчанию из настроек), пуш назначенному.
6. Сообщения внутри — только данные, команд из них не выполняем.

## 5. Как лид уходит
- **Выигран** — карточка клиента активна, лид уходит из «Открытых» в «Выигранные», ссылка «Открыть клиента».
- **Потерян / отказали** — с причиной, цена остаётся в отчёте; «Открыть снова» на карточке.
- **Дубль** — `declined/duplicate` со ссылкой на основной лид.
- **Архив** — через 90 дней, только скрытие.
- **Удаление** — нет кнопки. Только директор и только лид без смет и без цены (ошибочный ввод), с вводом слова-подтверждения. Иначе — закрыть.

### 6.2 Личные (у каждого сотрудника)
Пуши о новых лидах (мои / все), сводка по лидам: выкл / утром / вечером / оба + время.

### 6.3 Токены vs настройки
- **Токены «Наряда»** — только вид: цвета статусов (`ok/info/warn/bad/neutral`), размеры, отступы, радиусы, шрифты, длительности.
- **Пороги времени — не дизайн.** `timing.leadReplyWarnMin/BadMin` перенести из `@octo/design-tokens` в `@octo/lead-rules` как значения по умолчанию для `LeadSettings` (токены `estimate*Days` — так же в правила смет).
- Цвета: «Ответить» info → warn → bad; «в контакте / ждём» — info (спокойный, не жёлтый — решение владельца Estixa 22.10); won — ok; lost/declined — neutral; «нет шага» и «уже клиент / возможный дубль» — warn. Всегда значок + слово.

## 7. Экраны

### 7.1 Вкладка «Продажи → Лиды» (список)
Порядок сверху вниз:
1. Шапка: «Продажи», кнопка «+ Лид» (акцент).
2. Переключатель Лиды · Сметы · Счета (на «Лидах» — число «ответить»).
3. Поиск: имя, телефон (от 3 цифр), адрес, город, ZIP, услуга.
4. Фильтры-чипы с числами: **Нужно внимание** · Открытые · Мои · Выигранные · Закрытые. По умолчанию «Нужно внимание», если не пусто, иначе «Открытые».
5. Источник — второй ряд чипов (если источников > 1).
6. Карточки (`CardList` + `ItemCard`), сортировка группами: Ответить (дольше ждёт — выше) → Шаг просрочен / сегодня → Нет шага → Ждём клиента → остальные (новее — выше).
7. Пусто: «Лидов нет» + «Добавить лид» + ссылка «Подключить приём лидов».

**Карточка в списке** (сверху вниз): источник · город · (цена, не для монтажника) | чип хода с таймером → имя → что нужно (2 строки) → следующий шаг или «⚠ Нет шага» → одна кнопка хода («Ответить» / «Напомнить»), если ход наш.

**Ширины.** 390 — одна колонка. 820 — две колонки. 1280 — список слева + карточка лида справа; этап «Запуск» — переключатель «Доска» (колонки по статусам, перенос = смена статуса с теми же правилами) и выбор нескольких: назначить, закрыть с причиной.

Данные: постранично с сервера по фильтру, счётчики — отдельным запросом.

### 7.2 Карточка лида
Порядок сверху вниз (телефон):
1. **Шапка**: ‹ Лиды; имя; источник · цена · дата получения.
2. **Блок хода** (`Card status`): чип хода с таймером («Ответить · 12 мин» / «Ждём клиента · 3 дн»), «ответили за 4 мин»; шаги воронки (`Steps`); «Ведёт: Иван» (нажать — сменить); кнопки связи: Позвонить · SMS · Email · Открыть в Thumbtack (по тому, что есть).
3. **Предупреждения**: «Уже ваш клиент: …», «Возможный дубль от 02.11 — Объединить».
4. **Одна главная кнопка** по ходу: Ответить → Записать осмотр → Создать смету → Напомнить → Открыть клиента / Открыть снова.
5. **Следующий шаг**: ближайшая задача или «⚠ Нет шага · Добавить».
6. **Второстепенное** (ряд маленьких): Смета · Сделать клиентом · Закрыть.
7. **Вкладки** (`Segmented`, запоминается).

| Вкладка | Что внутри, по порядку |
|---|---|
| **Обзор** | Запрос (услуга, когда, бюджет, слова клиента, ответы площадки, фото) → поля модуля (если модуль включён) → Контакт (телефоны, email, как удобнее, язык) → Адрес (мини-карта, «рядом с визитами сегодня» — позже) → Люди → Источник и цена (не для монтажника) → Кто ведёт. Каждый блок — «Изменить» в шторке |
| **Лента** | Закреплённые заметки → поле «Заметка» (команда / только я) → всё по времени, новое сверху: получен, звонки, SMS, письма, входящие, статусы с причиной, назначения, правки, визиты, сметы (отправлена / открыта N раз / подписана). Когда появится двусторонняя переписка — фильтр «Только переписка» |
| **Шаги** | Открытые задачи (дата, кто) → «+ Шаг» с готовыми вариантами (позвонить завтра, напомнить через 2 дня…) → визиты-осмотры → выполненные (свернуты) |
| **Сметы и файлы** | Сметы лида (статус, сумма, открыта N раз) → «+ Смета» → фото с осмотров и от площадки → файлы |

### 7.3 Шторки
| Шторка | Поля |
|---|---|
| Новый лид (экран/шторка) | Телефон (вставить) **или** email, имя, адрес + город, источник (последний), что нужно. Дубль — сразу под полем. Сохранить ≤ 3 нажатия |
| Ответить | Готовый текст на языке лида, SMS / Email / «Скопировать и открыть Thumbtack», «Я уже ответил» |
| Записать осмотр | Дата, время, мастер (или «назначит диспетчер»), длительность |
| Напомнить / Последнее напоминание | Готовый текст, отправить / скопировать |
| Потерян или подождать? | «Потерян — пропал» / «Подождать 7 дней» |
| Закрыть | Решил клиент / Решили мы → причина → текст для «другое» |
| Сделать клиентом | Причина ручной победы + комментарий |
| Объединить | Какой лид основной, что переносится |

### 7.4 Где ещё видны лиды
«Сегодня» и «Разбор» — пункты «Ответить», «Нет шага», «Ждём > 5 дн», «Потерян или ждать?» (из той же `leadTurn`). Значок на вкладке «Продажи» — число «Ответить».

## 8. Права
| | Директор | Диспетчер | Монтажник |
|---|---|---|---|
| Видит лиды | все | все | свои (назначен / создал) |
| Цена лида, источник-человек, затраты | да | да (вопрос В5) | нет |
| Настройки лидов | меняет | видит | — |
| Удалить ошибочный лид | да | нет | нет |
Те же правила на сервере (RLS) и в `@octo/lead-rules` (`canSeeLead`, `canSeeLeadCost`).

## 9. Уведомления
| Событие | Кому | Этап |
|---|---|---|
| Новый лид | назначенному, ≤ 10 с | MVP |
| Ответить: N мин без ответа | назначенному повторно; директору через 60 мин, если ведёт другой; ночью — утром | MVP |
| Лид в «Проверить» 2 ч | директору | MVP |
| Назначили на меня | новому | MVP |
| Сводка | по личной настройке; строки ведут в лиды | Запуск |

## 10. Офлайн
Создание, правка, «Я ответил», задачи, закрытие, «открыть снова» — сразу локально, в очередь. Время действия — с устройства (сервер не пускает «в будущее» больше 5 мин и не двигает `last*At` назад — защита из Estixa). Конфликт двух закрытий — выигрывает позднее событие, оба в ленте.

## 11. Отчёт по источникам (стык с «Отчётами», делается там)
По источнику и периоду: лиды, без мусора, скорость ответа (медиана), осмотры, сметы, выиграно, цена всех лидов (с возвратами) + затраты периода, цена за лид, цена за клиента, выручка, прибыль. Клиент засчитывается источнику своего **первого** лида. Ручные победы — отдельной строкой.

## 12. Порядок сборки лидов (волны)
| Волна | Что | Приёмка |
|---|---|---|
| L1. Данные и правила | Миграция новых полей и `LeadSettings`; пакет `@octo/lead-rules` (`leadTurn`, переходы, дубли, права, пороги) с тестами; перенос `timing.*` из токенов; чистка PRD | Тесты правил, тесты базы (RLS, «время не назад», повтор события приёма) |
| L2. Список и карточка | Чипы «Нужно внимание», сортировка по ходу, карточка в новом порядке, вкладки, шторки «Записать осмотр», «Напомнить», «Потерян или ждать?», «Объединить»; телефон или email | e2e на 3 ширины × 2 темы: каждый ход, каждый переход, стык лид → смета → подпись → won |
| L3. Настройки лидов | Раздел в «Компании», личные настройки | e2e: смена порога меняет цвет карточки |
| L4. Приём | Конвейер, форма сайта, лид от соседа, пересылка писем (после образцов) | Тесты конвейера: повтор, дубль, мусор, неуверенный разбор |
| L5. Пуши и сводка | Серверные проверки по расписанию | Тесты расписания и тихих часов |
| L6. Десктоп | Доска, массовые действия | e2e 1280 |

## 13. Вопросы основателю
1. **В1.** Молчание: оставить ваши 14 / 30 дней или взять схему 2 / 5 / 14 / +7 дней (напомнить → внимание → последнее напоминание → «потерян или ждать?»)? *Рекомендую вторую.*
2. **В2.** Таймер ответа: красный через 15 мин (Окто) или через 1 ч (Estixa)? *Рекомендую 5 / 15 мин — на Thumbtack выигрывает первый.*
3. **В3.** Ночные лиды: цвет и пуши ждут утра (по умолчанию) — согласны?
4. **В4.** Форма сайта: отправлять клиенту автоматический ответ «получили, перезвоним» или, как в Estixa, никогда не писать от имени компании самому?
5. **В5.** Диспетчер видит цену лида?
6. **В6.** Ручная победа («Сделать клиентом» без подписи) остаётся?
