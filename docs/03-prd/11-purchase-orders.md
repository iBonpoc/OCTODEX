# 11. Заказы поставщикам (Purchase Orders)

> Статус: черновик v0.1, ноябрь 2026. Сущности: `PurchaseOrder`, `Supplier`, `SupplierItem`, `CatalogItem`, `EstimateLineItem` (BOM), `Job`, `Expense` (`../04-domain-model.md` §3, §6, §9). Связанные: `04-catalog-suppliers.md`, `05-estimates.md` §7.8, `06-gutters-module.md` §7.7–7.8, `10-expenses-job-costing.md` §7.
> MVP = **PDF и email поставщику**. API ABC Supply, SRS, Beacon закрытые и партнёрские (`01-competitor-analysis.md` §7), подключаются после первых клиентов.

## 1. Назначение
После подписи сметы одним нажатием отправить поставщику правильный заказ материалов: из BOM выбранного варианта, сгруппированный по поставщикам, в единицах поставщика, с адресом доставки. Затем отметить получение и увидеть материалы в себестоимости работы.

## 2. Как это приносит деньги подрядчику (`money_impact`)
| Механизм | Эффект |
|---|---|
| PO в день подписи, без перепечатки BOM | Материалы приходят раньше → монтаж раньше → финальный платёж раньше (кэшфлоу) |
| Количества из движка, округление до упаковок | Нет недостачи (повторная поездка ~$50–100 времени и топлива) и нет лишних упаковок/coil |
| Один PO на поставщика вместо звонков | Экономия 15–30 мин на работу у владельца без офиса |
| PO как «обязательства» в job costing (`10`) | Владелец видит маржу работы до прихода счёта поставщика |
| Сверка PO ↔ счёт поставщика | Ловит пересорт и завышенные цены поставщика (переплата за coil на 5–10% — частый случай) |

## 3. Пользователи и роли
| Роль | Возможности |
|---|---|
| owner, admin, office | Создают, правят, отправляют, отменяют PO; видят себестоимость |
| sales | Просмотр PO по своим сметам (себестоимость по `can_view_cost`) |
| tech | Видит PO своей работы **без цен**, отмечает получение (кол-во, фото накладной) |
| subcontractor | Нет доступа |
| Поставщик (не пользователь) | Получает email с PDF; ответ приходит на email компании (reply-to) |

| PO-US-02 | Как office, я хочу видеть количества уже в единицах поставщика (упаковки, рулоны, палки) с исходным количеством из BOM |

## 5. Критерии приёмки
**PO-US-01**
- Given смета одобрена, When выполняется конверсия в работу (`05` §7.8), Then для каждого поставщика из BOM-строк выбранного варианта (+ выбранные add-ons) создаётся ровно один PO `draft` с `job_id`, `estimate_version_id`; задача «Проверить и отправить PO» на office/owner.
- Given конверсия повторена, When тот же ключ `estimate_id + version_id`, Then новых PO нет (уникальность `job_id + supplier_id + source_version_id` для автосозданных).
- Given BOM-строка без `supplier_item_id` у позиции каталога, When создаются PO, Then строка попадает в блок «Без поставщика» (PO-US-11), а не теряется.
- Given видимые строки сметы (работа, fee, tear-off), When формируется PO, Then в PO идут только строки с `CatalogItem.kind = material` и строки с материалом в позиции поставщика; работа в PO не попадает.

**PO-US-02**
- Given BOM 65 hidden hangers, `pack_size = 50`, When строка PO, Then `qty = ceil(65 / 50) = 2` коробки, рядом «из BOM: 65 ea», себестоимость строки = 2 × цена коробки.
- Given coil 111 LF Musket Brown и 26 LF White (`06` §7.9 пример B), When PO поставщику coil, Then две строки по цветам; единица и пересчёт по `pack_size` позиции поставщика (если coil продаётся по LF — 111 и 26).
- Given одна позиция каталога в BOM двух вариантов, When строится PO, Then берётся только вариант, выбранный клиентом.

**PO-US-03**
- Given PO `draft`, When меняет поставщика строки, Then строка переезжает в PO нового поставщика (создаётся при отсутствии), цена берётся из его SupplierItem; если позиции у него нет — строка с ценой 0 и пометкой «нет в прайсе».
- Given доставка, When выбирает «на объект», Then `delivery_address` = адрес объекта работы, поле «заметка водителю» (gate code берётся только по явной галочке, потому что это внутренние данные).
- Given самовывоз, When выбирает филиал из `Supplier.branches`, Then в PDF «Will call: <филиал>, дата».

**PO-US-04**
- Given у поставщика есть `email_for_orders`, When «Отправить», Then письмо от имени компании (from: Octo-домен, reply-to: email компании, имя компании), тема `PO-0031 · <компания> · <job>`, PDF во вложении, копия отправителю; статус `sent`, `sent_at`, `sent_via = email`; всё с `idempotency_key`.
- Given двойное нажатие, When второй запрос, Then второго письма нет.
- Given нет сети, When «Отправить», Then действие в outbox, статус остаётся `draft` с пометкой «в очереди» до ответа сервера.
- Given «Только PDF», When пользователь скачивает или делится (share sheet), Then статус `sent`, `sent_via = pdf` только после явного «Отметить отправленным».
- Given строка с количеством 0 или ценой «нет в прайсе», When отправка, Then предупреждение; строки с qty 0 не попадают в PDF.

**PO-US-05**
- Given `sent`, When office отмечает «Подтверждён» и дату доставки, Then `confirmed`, `delivery_date`; дата видна в карточке работы и календаре (`07`) как метка «материалы».

**PO-US-06**
- Given `confirmed` или `sent`, When tech отмечает получение всех строк, Then `received`, фото накладной `File(kind=document)` на PO.
- Given пришло 1 коробка hangers из 2, When tech вводит `received_qty = 1`, Then статус `partially_received`, в работе предупреждение «не хватает: hangers 1 коробка»; задача office.
- Given tech, When открывает PO, Then цен нет (ни в UI, ни в API-ответе).

**PO-US-07**
- Given PO `sent/confirmed/partially_received/received`, When открыта вкладка «Деньги» работы, Then сумма PO в «обязательствах» (`committed_cost_cents`), не в факте (`10` §7).
- Given Expense со ссылкой `purchase_order_id`, When сохранён, Then PO уходит из обязательств, сумма Expense идёт в факт; показ разницы «PO $642.30 / счёт $671.10 (+4.5%)», при > 3% — подсветка.

**PO-US-08**
- Given «Новый PO» без работы, When сохранён, Then `job_id = null`, в обязательства работ не попадает, видно в общем списке PO.

**PO-US-09**
- Given PO `sent` или `confirmed`, When office меняет строки и «Отправить ревизию», Then `revision + 1`, PDF с пометкой «REVISED rev 2 — заменяет предыдущий», в письме diff строк (добавлено/изменено/удалено).
- Given «Отменить» на `sent`/`confirmed`, When подтверждает, Then `cancelled`, поставщику письмо об отмене (по галочке, по умолчанию вкл.), обязательства работы уменьшаются.
- Given `received`, When пытается отменить, Then запрещено (возврат товара оформляется как отрицательный Expense или кредит — позже).

**PO-US-10**
- Given одобрен change order с материальными строками, When одобрение, Then предложение «Создать PO на материалы CO-0004?» (не автоматически, чтобы не дублировать уже отправленный PO).

**PO-US-11**
- Given BOM-строки без поставщика, When открыт блок, Then для каждой: «Назначить поставщика» (запоминается в каталоге по галочке) или «Со склада» (строка исключается из PO, остаётся в плановой себестоимости).

## 7. Бизнес-правила и расчёты
### 7.1 Статусы
```
draft → sent → confirmed → partially_received → received
  ↘ cancelled (из draft / sent / confirmed / partially_received)
```
- `partially_received` — новое состояние (предложение в §14). Переход в `received`, когда по всем строкам `received_qty ≥ qty`.
- `sent → sent` (ревизия) не меняет статус, увеличивает `revision`. `confirmed` после ревизии возвращается в `sent`.
- Каждый переход → StatusEvent; правки строк после `sent` → AuditLog.

### 7.2 Из BOM в строки PO
```
bom_qty[item]      = Σ quantity BOM-строк выбранного варианта (+ выбранные add-ons) по catalog_item
supplier_item      = CatalogItem.supplier_item_id (текущая версия, valid_to IS NULL)
po_qty             = ceil(bom_qty / pack_size)                // pack_size = единиц каталога в ед. поставщика
po_line_cost       = round(po_qty × supplier_item.cost_cents)
po_total           = Σ po_line_cost
```
- Группировка: один PO на `(job, supplier)`. Один поставщик с разными филиалами — один PO, филиал выбирается.
- Строки агрегируются по `supplier_item` (например, end caps из двух runs → одна строка).
- Coil: отдельная строка на (ширина, gauge, цвет), атрибуты печатаются в описании.
- Цены поставщика в PO — информационные (что мы ожидаем заплатить). Истина — счёт поставщика (Expense).
- Если `pack_size` не задан → `pack_size = 1` с пометкой «проверьте упаковку».

### 7.3 Нумерация и идемпотентность
- `PO-NNNN` из счётчика компании (`Company.numbering`), номер выдаёт сервер; офлайн-черновик получает номер при синхронизации.
- Ключи: автосоздание `estimate_id:version_id:supplier_id`; отправка `po_id:revision`.

### 7.4 Job costing (согласовано с `10` §7)
- `committed_cost_cents` работы = Σ `po_total` PO в статусах `sent … received`, у которых нет связанного Expense.
- Факт = Expense. PO никогда не входит в факт напрямую (нет двойного счёта).
- PO `received` без Expense > 7 дней → задача «Внести счёт поставщика» (`10`).

### 7.5 Email
- Отправка через наш почтовый провайдер (SES) с домена Octo, `reply-to` = email компании, чтобы ответы поставщика шли подрядчику. Bounce → статус письма `failed`, PO остаётся `draft` с ошибкой «письмо не доставлено».
- Язык PDF и письма — английский (поставщики US).

## 9. Офлайн
- Просмотр и правка черновиков PO, отметка получения с фото — офлайн, синхронизация позже.
- Отправка email — только в сети (outbox). PDF генерируется на сервере; офлайн доступен последний сгенерированный PDF.
- Конфликт: получение, отмеченное офлайн, на PO, который в это время отменили → получение сохраняется как заметка, owner решает.

## 10. Уведомления и автоматизации
- Смета одобрена → задача «Проверить и отправить N PO» (owner/office).
- PO `sent` без подтверждения 24 ч → напоминание «Позвонить в ABC Supply по PO-0031».
- Дата доставки завтра → push исполнителю работы.
- `partially_received` → задача office «Досдача: hangers 1 коробка».
- Письмо поставщику не доставлено → push отправителю.

## 11. Ошибки и крайние случаи
| Случай | Поведение |
|---|---|
| Смета одобрена, а позиция поставщика архивирована | Строка с пометкой «позиция архивирована у поставщика», выбрать замену |
| Цена поставщика изменилась между сметой и PO | PO берёт текущую цену поставщика; показ «в смете себестоимость $X, сейчас $Y»; плановая себестоимость работы не меняется, разница видна в план/факт |
| Работа отменена при открытых PO | Предложение отменить `draft/sent/confirmed` PO с письмами поставщикам |
| Два PO одному поставщику на одну работу (ручной + авто) | Разрешено, предупреждение о возможном дубле |
| Поставщик без email | Только PDF / share |
| Нет прав (tech пытается отправить) | Кнопки нет; API 403 |
| Отрицательное или нецелое qty для `ea` | Валидация: qty ≥ 0, для `ea` целое |
| Очень большой PO (> 100 строк) | PDF на несколько страниц, тот же поток |

## 13. Метрики
- Доля одобренных смет Gutters, по которым PO отправлен в течение 24 ч (цель > 80%).
- Время от одобрения до отправки PO (baseline на бете).
- Доля PO, отправленных без правок количеств (качество BOM; цель > 70%).
- Недостача на объекте: доля работ с `partially_received` или внеплановым Expense на материалы того же поставщика.
- Средняя разница PO ↔ счёт поставщика, %.

## 15. Открытые вопросы
1. У каких поставщиков основатель реально берёт материалы (coil, hangers, downspouts) и как сейчас заказывает: звонок, SMS, email, приезд?
2. Нужен ли PO на coil, если основатель покупает coil рулонами на склад, а не под работу? Тогда coil = «со склада» по умолчанию до coil-склада.
3. Печатать ли имя клиента в PO (поставщику нужно только «job ref» и адрес)? Предложение: нет, только номер работы и улица.
4. Кто отмечает получение, если материалы забирает сам владелец (will call)? Предложение: при самовывозе кнопка «Забрал» сразу ставит `received`.

## Дополнение 03.11.2026: заказ и себестоимость из черновика сметы (решение основателя)

Основатель хочет видеть себестоимость материалов и готовить заказ **ещё до одобрения сметы**, прямо из черновика. Это заменяет правило «PO только из одобренной сметы».

### Что меняется
| Было | Стало |
|---|---|
| BOM и PO доступны только после `approved` | **«Материалы и себестоимость»** доступны в любой версии сметы, включая `draft` |
| PO создаётся автоматически при одобрении | PO можно создать **вручную из черновика**. При одобрении PO создаётся автоматически, как раньше, если черновых PO ещё нет |

### User stories
- **PO-US-20.** Как владелец, я хочу открыть в черновике сметы вкладку «Материалы», чтобы увидеть список материалов по поставщикам, количества с упаковками и **себестоимость каждого варианта G/B/B** до отправки клиенту.
  - Given черновик EST-0148 с вариантами Good/Better/Best, When я открываю «Материалы», Then вижу по каждому варианту: позиции BOM, поставщика, количество в упаковках, себестоимость материалов, цену клиенту и маржу (видно только ролям с доступом к себестоимости).
- **PO-US-21.** Как владелец, я хочу из черновика создать **предварительный заказ** поставщику для выбранного варианта.
  - Given черновик, When нажимаю «Создать заказ» и выбираю вариант Better, Then создаётся PO в статусе `draft` с пометкой **«Из неодобренной сметы»** и ссылкой на версию сметы.
- **PO-US-22.** Как владелец, я хочу отправить поставщику **запрос цены и наличия** (RFQ), ничего не заказывая.
  - Given предварительный PO, When нажимаю «Запросить цену», Then поставщику уходит письмо/PDF «Request for quote» без обязательства покупки, а PO получает статус `rfq_sent`. Ответ поставщика можно внести вручную, и тогда себестоимость в смете обновится.
- **PO-US-23.** Как владелец, я хочу при необходимости **отправить настоящий заказ до подписи клиента** (например, нужен редкий цвет coil).
  - Given предварительный PO, When нажимаю «Отправить заказ», Then показывается предупреждение «Смета не одобрена клиентом. Если клиент откажется, материалы останутся за вами» и требуется явное подтверждение. AI-помощник такой заказ отправить не может.
- **PO-US-24.** Как владелец, я хочу видеть, что заказ **устарел**, если смету изменили.
  - Given PO создан из версии v2, When создаётся версия v3 или меняется выбранный вариант, Then PO помечается «Устарел», показывается разница (было → стало по позициям и сумме) и кнопка «Обновить заказ». Уже отправленный поставщику PO не меняется сам: создаётся ревизия.
- **PO-US-25.** Если смета отклонена или истекла, черновые PO автоматически переходят в `cancelled`. Отправленные остаются, и владелец получает задачу «Отменить заказ у поставщика».

### Правила
- Себестоимость в черновике считается тем же движком, что и в одобренной смете, по текущим ценам поставщиков (`SupplierItem.cost_cents`). При одобрении цены фиксируются снимком.
- Предварительный PO **не попадает** в «обязательства» (committed cost) работы, пока смета не одобрена. Отправленный до одобрения PO попадает в отдельную строку отчёта «Заказано без подписи клиента».
- Пересчёт упаковок (например, downspout 10′ по 1 шт., hangers по 50 шт.) одинаковый для черновика и одобренной сметы.

### Изменения модели данных (внести в 04-domain-model)
- `PurchaseOrder.estimate_version_id`, `PurchaseOrder.option_id` — из какой версии и варианта.
- `PurchaseOrder.origin`: `draft_estimate` / `approved_estimate` / `manual`.
- `PurchaseOrder.status`: добавить `rfq_sent`, `outdated` (флаг `is_outdated`), `cancelled` уже есть.
- `PurchaseOrder.sent_before_approval bool`.

## Автоматический разбор ответа поставщика на RFQ (MVP, решение основателя 03.11.2026)

### Как ответ попадает в Octo
- Запрос уходит с адреса вида `rfq-<company>@in.octo.app`, в теме номер: `RFQ PO-0031 · Bonpoc Gutters`. Reply-To содержит уникальный адрес запроса `rfq+PO-0031.<token>@in.octo.app`, поэтому ответ поставщика автоматически привязывается к нужному заказу.
- Если поставщик ответил на старый адрес или из другого ящика, письмо попадает в общую очередь «Проверить», и Octo предлагает к какому RFQ его привязать (по номеру, поставщику, позициям).
- Владелец может переслать ответ вручную на тот же адрес или загрузить файл/фото в карточку заказа.
- Поддерживаемые форматы: текст письма, PDF (quote / invoice), Excel/CSV, фото или скан бумажной сметы поставщика.

### Что извлекается (AI + проверки)
| Поле | Пример |
|---|---|
| Позиция поставщика (SKU, название) | `K6-032-MB` 6″ K-Style .032 Musket Brown coil |
| Сопоставление с нашей строкой PO | по SKU, затем по названию и атрибутам (профиль, толщина, цвет), с оценкой уверенности |
| Цена за единицу и единица | $1.42 / LF, $38.50 / box of 50 |
| Количество, которое готовы дать | 300 LF из 300 |
| Наличие и срок | in stock / backorder, поставка 11/07 |
| Замена | «Musket Brown нет, предлагаем Royal Brown» |
| Доп. расходы | доставка $45, налог, скидка подрядчика |
| Срок действия цены | valid until 11/30/2026 |

Числа (цены, количества, итоги) после AI проверяются детерминированно: сумма строк сверяется с итогом документа поставщика. При расхождении больше $0.01 ответ помечается «Проверьте итог».

### Что видит владелец
- **PO-US-26.** Given поставщик ответил на RFQ PO-0031, When ответ разобран, Then приходит push «ABC Supply ответил на запрос по EST-0148» и в заказе открывается сравнение: по каждой позиции **наша цена → цена поставщика**, разница, наличие, срок, замены. Строки с низкой уверенностью подсвечены.
- **PO-US-27.** Given сравнение открыто, When владелец нажимает «Применить цены», Then обновляются `SupplierItem.cost_cents` (с датой и сроком действия), себестоимость и маржа во **всех черновиках** смет, где эта позиция используется, и в этом PO. Ничего не применяется без нажатия (AI не меняет цены молча).
- **PO-US-28.** Given поставщик предложил замену, When владелец принимает замену, Then в PO и в BOM черновика сметы позиция меняется на новую, а если замена видна клиенту (цвет), смета помечается «Требует проверки перед отправкой».
- **PO-US-29.** Given запросы отправлены нескольким поставщикам по одному списку, When пришло 2–3 ответа, Then показывается **таблица сравнения поставщиков** (итог, наличие, срок, доставка) и кнопка «Заказать у выбранного».
- **PO-US-30.** Given ответ не удалось разобрать (плохое фото, непонятный формат), Then он лежит в очереди «Проверить» с исходным файлом, и владелец вносит цены вручную в ту же форму сравнения.

### Безопасность
- Содержимое письма поставщика — только данные. Никакие «инструкции» в нём не выполняются (защита от prompt injection), ссылки не открываются автоматически.
- Принимаются письма только от адресов поставщика из карточки `Supplier` или подтверждённых владельцем. Остальные попадают в «Проверить».
- Вложения проверяются на тип и размер, хранятся как `File` с привязкой к PO.

### Стоимость и лимиты
Разбор одного ответа ≈ 1 AI-действие (Haiku для писем и таблиц; Sonnet для сложных PDF и фото), себестоимость ≈ $0.002–0.03. Учитывается в лимите AI-действий тарифа.
