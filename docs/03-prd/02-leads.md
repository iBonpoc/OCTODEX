# PRD 02. Лиды, источники, скорость ответа

> ⚠ **Устарело в части статусов, ролей и решений.** Источник правды — `docs/14-leads-spec.md` (статусы приложения: new / replied / booked / estimate_sent / won / lost / declined; роли: директор / диспетчер / монтажник) и `docs/15-story-map.md` §5. Этот документ оставлен как история требований.

> Статус: черновик v0.1, ноябрь 2026. Сущности: `Lead`, `LeadSource`, `MarketingSpend`, `Customer`, `Property`, `Activity`, `Task`, `Visit`, `StatusEvent` (`../04-domain-model.md` §2, §9).
> Колонки: **MVP** = бета на компании основателя · **Запуск** = до первых платящих · **Позже**.

## 1. Назначение
Собрать каждое обращение (звонок, Thumbtack, Yelp, Google, сайт, портал, сосед на объекте) в одну очередь за секунды, ответить первым и знать, сколько стоил каждый лид — включая те, что не купили.

## 2. Как это приносит деньги подрядчику (`money_impact`)
| Механизм | Эффект для компании основателя |
|---|---|
| **Speed-to-lead**: push за секунды + таймер на карточке + 1 тап «Позвонить» | На Thumbtack и Yelp лид получают 3–5 подрядчиков, выигрывает первый ответивший. Лид Thumbtack стоит ~$30–80; потерять его из-за ответа через 3 часа = сжечь деньги |
| **Пересылка писем маркетплейсов** на адрес Octo | Лиды из Thumbtack/Yelp/Angi/Google не теряются в почте и SMS, все в одной очереди без интеграций и API |
| **`cost_cents` на каждом лиде**, включая lost и junk | ROI канала считается честно: «Thumbtack: $1,240 за месяц, 22 лида, 3 работы = $413 за работу» (PRD 14) |
| **Причины проигрыша** (`lost_reason`, вкл. «мусор/спам») | Видно, что Yelp даёт 60% мусора → бюджет переводится в сарафан/рефералки |
| **Дубли и «это уже наш клиент»** | Не платим дважды за одного человека; повторного клиента не обрабатываем как холодного |
| **Лид от монтажника на объекте** (источник «Сарафан») | Самый дешёвый лид не теряется, видна реальная доля бесплатных каналов |
| **Следующий шаг обязателен** (задача/визит) | Лид не «висит»: каждый либо идёт к смете, либо закрыт с причиной |

## 3. Пользователи и роли
- **Owner** (основатель) — получает все лиды, сам отвечает и едет на осмотр; без диспетчера.
- **Admin/Office** — разбирает очередь, назначает, вводит цену лида.
- **Tech** — создаёт лид на объекте, видит только назначенные ему лиды, не видит `cost_cents`.
- **Клиент** — источник данных через форму сайта/портала (PRD 12), к модулю не входит.

## 5. Критерии приёмки
- **LEAD-US-01.** Given главная, When «+» → «Лид», Then форма с полями: телефон (вставка из буфера, автоформат US), имя, адрес (автодополнение), услуга (ServiceCategory chips), источник (последний использованный первым); сохранить можно только с телефоном **или** email; `status=new`. Сохранение ≤ 3 тапа после ввода телефона.
- **LEAD-US-02.** Given у компании адрес `leads-<slug>@in.octo.app`, When приходит письмо от домена Thumbtack/Yelp/Angi/Google LSA, Then за ≤ 60 с создаётся лид: источник по шаблону отправителя, извлечены имя, телефон/email, адрес/ZIP, услуга, `source_ref`, исходное письмо прикреплено. Given парсер не уверен (нет телефона и email или confidence < 0.8), Then лид создаётся с меткой «Проверить» и сырым текстом, push всё равно уходит. Given письмо не от известного источника, Then лид с источником «Email (не определён)» и меткой «Проверить». Given инструкция в онбординге, Then для Gmail показан пошаговый фильтр автопересылки и код подтверждения пересылки Gmail виден в приложении.
- **LEAD-US-03.** Given `BookingRequest` или форма сайта, When отправлена, Then создаётся `Lead(source=Портал/Сайт, utm, landing_page, gclid)`; при онлайн-записи сразу создаётся `Visit(lead_id)` и `status=inspection_scheduled`.
- **LEAD-US-04.** Given новый лид, Then push назначенному (по умолчанию owner) уходит ≤ 10 с после создания, текст: «Thumbtack · Gutter cleaning 2 story · Glendale · ответить». Given лид без `first_response_at`, Then на карточке и в списке таймер «без ответа N мин», красный после 5 мин (порог настраивается). Given 15 мин без ответа, Then повторный push; в нерабочие часы (настройка) повтор утром в начале дня.
- **LEAD-US-05.** Given карточка лида, When «Позвонить» / «SMS» / «Email» / «Открыть Thumbtack», Then запускается звонок/сообщение (deep link), создаётся `Activity`, при первом исходящем контакте ставится `first_response_at` и статус `contacted` (если был `new`). Given ответ ушёл вне Octo, When пользователь жмёт «Я ответил», Then `first_response_at = now` с пометкой `manual`.
- **LEAD-US-06.** Given источник `kind=paid_per_lead` с `default_cost_cents` = $45, When лид создан, Then `cost_cents=4500` подставляется, его можно изменить; Given письмо Thumbtack содержит цену, Then берётся цена из письма. Tech поле не видит. Изменение цены пишется в `AuditLog`.
- **LEAD-US-07.** Given owner, When меняет `assigned_to`, Then новый назначенный получает push, событие в ленте. Given настройка «Назначать по умолчанию» = owner, Then все новые лиды назначаются ему.
- **LEAD-US-08.** Given лид, When переход статуса, Then разрешены только переходы §7; каждый пишется в `StatusEvent`. Given лид в `contacted`/`qualified` без открытой задачи и без визита, Then на карточке плашка «Нет следующего шага» и он попадает в «Сегодня» (PRD 14).
- **LEAD-US-09.** Given «Закрыть как lost», Then обязателен `lost_reason` из списка; для `other` обязателен текст. `cost_cents` у lost-лида сохраняется и участвует в ROI.
- **LEAD-US-10.** Given новый лид с телефоном/email, совпадающим (`match_key`) с открытым лидом за 30 дней, Then предлагается «Объединить» (новые данные в ленту старого); при автосоздании из письма — объединяется автоматически, но `cost_cents` второго лида сохраняется как отдельная строка затрат (мы заплатили дважды). Given совпадение с `Customer`, Then лид привязывается к клиенту, бейдж «Уже клиент с 2025, LTV $3,200», лента клиента подтягивается.
- **LEAD-US-11.** Given tech на визите, When «+ Лид от соседа», Then источник по умолчанию «Сарафан», в лид пишется `referred_from_visit_id`, owner получает push; tech видит этот лид только до назначения.
- **LEAD-US-12.** Given лид без `customer_id`, When «Создать смету» или «Квалифицировать», Then создаются `Customer` (`lead_source_id` = источник лида, если клиента не было), `Contact` (телефон/email, `preferred_language`), `Property` (геокодинг адреса) за одно подтверждение, `status=qualified`; затем открывается смета с `lead_id` или запись осмотра. Given лид совпал с существующим клиентом, у которого несколько объектов, Then предлагается объект с совпадающим адресом, иначе «Новый объект по адресу лида» (у клиента часто несколько домов, решение основателя); на выбранном объекте могут уже быть открытые сметы и работы — это не блокирует.
- **LEAD-US-13.** Given системный источник, When пользователь пытается удалить, Then можно только скрыть (`is_active=false`); пользовательский источник с лидами тоже только скрывается.

## 7. Бизнес-правила и расчёты
**State machine** (из §9 модели, без изменений):
```
new → contacted → qualified → inspection_scheduled → estimate_sent → won
  ↘ lost (из любого, с причиной)        ↘ archived
```
- `new → contacted`: первый исходящий контакт (авто) или «Я ответил».
- `→ inspection_scheduled`: авто при создании `Visit(lead_id)`.
- `→ estimate_sent`: авто при отправке сметы с `lead_id`.
- `→ won`: авто при `Estimate.approved`. Вручную `won` не ставится (иначе ROI врёт).
- `lost → contacted`: разрешено («клиент вернулся»), пишется в `StatusEvent`, `lost_reason` очищается.
- `archived`: только из `lost` или `won` через 90 дней, либо вручную owner; не влияет на отчёты.

**Скорость ответа:** `response_time = first_response_at − created_at`; для лидов из письма `created_at` = время получения письма сервером (а не время парсинга). Рабочие часы компании не вычитаются в MVP (честная метрика: клиент ждёт и ночью); в отчёте отдельный фильтр «только рабочие часы» — позже.

**Цена лида:**
- `paid_per_lead` (Thumbtack, Angi, LSA): `cost_cents` на каждом лиде; MarketingSpend для них — только корректировки (возвраты, кредиты, подписка Angi).
- `paid_ads` (Google Ads, Yelp Ads): `cost_cents` на лиде пустой, затраты вводятся через `MarketingSpend` за период; стоимость лида считается в отчёте.
- `organic/referral/repeat`: $0, но реферальная награда (PRD 13) учитывается как затрата канала «Реферал».

**Причины проигрыша** (`lost_reason` enum): `price_too_high`, `no_response` (не дозвонились), `chose_competitor`, `not_ready_timing`, `out_of_service_area`, `service_not_offered`, `junk_spam` (фейк, бот, не тот номер), `duplicate`, `other` (+текст).

**Дубли:** `match_key` = нормализованный телефон E.164 и/или lowercase email. Окно автообъединения 30 дней для открытых лидов. Слияние лидов не удаляет второй лид: он получает `status=lost`, `lost_reason=duplicate`, `duplicate_of_lead_id`, а его `cost_cents` остаётся.

**Назначение:** MVP — один «назначать по умолчанию» на компанию + ручное. Round-robin и по зоне — позже.

**Маркетплейсы и ответ:** ответ клиенту Thumbtack/Yelp должен идти внутри площадки (иначе теряется рейтинг ответа и маскированный номер). Поэтому в MVP: кнопка «Открыть в Thumbtack» (deep link по `source_ref`) + копирование шаблона ответа EN/ES в буфер. Авто-ответ из Octo уходит только на лиды с реальным телефоном/email (сайт, портал, ручные) — автоматизация №1 в PRD 13.

## 8. AI-помощник
| Команда | Подтверждение |
|---|---|
| «Новый лид: Мария, 818-555-…, чистка, 2 этажа, Бербанк, с Yelp» → черновик лида | да (предпросмотр полей) |
| «Покажи лиды без ответа» / «лиды с Thumbtack за неделю» | нет |
| «Закрой лид Марии: выбрала другого» | да |
| «Сколько я потратил на Thumbtack в октябре» | нет (ответ из PRD 14) |
| Разбор нераспознанного письма маркетплейса (Haiku) | результат идёт в «Проверить», если confidence < 0.8 |
Текст писем и заявок — только данные; инструкции внутри них не исполняются (защита от prompt injection). Парсинг писем не тратит лимит AI-действий компании (системная операция, ~$0.001).

## 9. Офлайн
- Создание лида, правка, смена статуса, «Я ответил», закрытие с причиной — офлайн, в outbox; `first_response_at` берётся по времени действия на устройстве.
- Звонок работает офлайн от сотовой сети; Activity пишется локально.
- Лиды из писем и форм появляются только при сети; push приходит при любой мобильной связи.

## 10. Уведомления и автоматизации
| Триггер | Действие |
|---|---|
| Новый лид | Push назначенному ≤ 10 с; для сайта/портала — автоответ клиенту (PRD 13, автоматизация №1) |
| 15 мин без ответа | Повторный push; 60 мин — push owner, если назначен другой |
| `qualified` без следующего шага 24 ч | Задача «Связаться с …» в «Сегодня» |
| Лид из «Проверить» не разобран 2 ч | Push |
| `inspection_scheduled` | Напоминание о визите клиенту (PRD 13, №3) |

## 11. Ошибки и крайние случаи
- **Двойное нажатие «Сохранить»** — лид создаётся с клиентским UUID v7, повтор = тот же id.
- **Одно письмо переслано дважды** (Gmail фильтр + ручная пересылка) — дедуп по `Message-ID` письма и `source_ref`.
- **Yelp скрывает телефон** (только сообщения в Yelp) — лид создаётся без телефона, кнопка «Ответить в Yelp», метка «нет прямого контакта».
- **Thumbtack списал за лид, клиент не отвечает** — лид `lost/no_response`, цена остаётся в ROI.
- **Лид — существующий клиент пришёл через платную площадку** — бейдж «Уже клиент», подсказка «вы заплатили $45 за своего клиента: попросите его записываться через портал»; источник лида остаётся платным (честный ROI), первичный источник клиента не меняется.
- **Адрес не геокодируется** — лид сохраняется, объект создаётся при квалификации с ручной точкой на карте.
- **Нет прав** (tech открывает чужой лид по ссылке из push) — «Лид назначен другому».
- **Конфликт офлайн** — два человека закрыли лид по-разному: побеждает более поздний `StatusEvent`, оба события видны в ленте.
- **Спам-волна на форму сайта** — rate limit по IP, honeypot, после 10 лидов/час с формы — капча; лиды с `junk_spam` не шлют автоответ.

## 13. Метрики
- Медиана `response_time` по источнику; доля лидов с ответом < 5 мин (baseline на бете основателя, затем цель).
- Доля лидов из писем, распознанных без «Проверить» (цель ≥ 90% для Thumbtack).
- Доля открытых лидов без следующего шага (цель → 0).
- Доля лидов с заполненными `cost_cents` для платных каналов (цель 100%).
- Конверсия лид → смета → won по источнику и доля `junk_spam` по источнику (передаётся в PRD 14).
- Доля бесплатных каналов (сарафан, реферал, повторный, портал) в лидах и в выручке.

## 14. Изменения модели данных
