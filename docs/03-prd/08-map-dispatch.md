# 08. Карта со слоями и простая диспетчеризация

> Статус: черновик v0.1, ноябрь 2026. Сущности: `Lead`, `Customer`, `Property` (`geo`), `Visit`, `Job`, `Crew`, `Membership.color`, `Estimate`, `RecurringPlan`, `Company`, `CompanyGroup` (`../04-domain-model.md`).
> Связанные модули: `07-jobs-schedule.md` (визиты, порядок дня), `02-leads.md`, `03-customers-properties.md`, `05-estimates.md`, `16-offline-sync.md`.

## 1. Назначение
Одна карта, на которой владелец видит, где его деньги: лиды, клиенты, сегодняшние визиты и бригада, и прямо с пина звонит, едет, создаёт смету или визит. Плюс простой порядок объезда на день без «оптимизатора».

## 2. Как это приносит деньги подрядчику (`money_impact`)
| Механизм | Оценка |
|---|---|
| **«Пока ты рядом»**: открытые сметы, клиенты с подходящей чисткой и лиды в радиусе 1 мили от сегодняшних визитов | 1 дополнительный осмотр или дожим в неделю ≈ **$1–2k/мес** выручки при среднем чеке gutter-монтажа ~$2.5k и close rate 30–40% |
| **Порядок маршрута** вместо «зигзагов» по LA | 20–40 мин/день и ~10–20 миль меньше на бригаду ≈ **$300–600/мес** (топливо + время) |
| Фильтр «клиенты без guards / с винилом в fire zone» | Реактивация базы: upsell негорючих guards ($12–25/LF × 120 LF ≈ $1.5–3k за заказ) |
| Быстрый звонок/навигация с пина | Скорость ответа лиду (лид выигрывает первый ответивший) |
| Кластеры работ по районам | Меньше пустых переездов при раскладке сезонных чисток |

## 3. Пользователи и роли
| Роль | Видит на карте |
|---|---|
| owner / admin / office | Все слои своей компании (и группы в режиме «Все компании»), позицию бригад |
| sales | Лиды и клиенты (все или свои по настройке), свои визиты |
| tech | Только свои визиты на сегодня/завтра и свою позицию; без слоя лидов и без сумм |
| Каждый сотрудник | Управляет своим согласием на передачу геопозиции (iOS permission + переключатель в профиле) |

## 5. Критерии приёмки
- **MAP-US-01.** Given открыта карта, When выключен слой «Лиды», Then пины лидов исчезают без перезагрузки карты, состояние слоёв запоминается для пользователя на устройстве.
- **MAP-US-02.** Given фильтр «Лиды: new+contacted, источник Thumbtack», When применён, Then на карте только такие лиды, счётчик «12 лидов» совпадает со списком; кнопка «Списком» открывает тот же набор в списке.
- **MAP-US-03.** Given пин клиента, When тап, Then снизу карточка: имя, адрес, статус/последняя работа, баланс (если есть права), кнопки «Позвонить» (tel:), «Написать», «Маршрут» (Apple Maps / Google Maps / Waze по выбору пользователя), «Смета», «Визит»; «Смета» открывает создание сметы с уже выбранными клиентом и объектом.
- **MAP-US-04.** Given у tech 3 визита сегодня, When открыта карта, Then пины пронумерованы по `sequence_in_route` (иначе по `starts_at`), линия маршрута соединяет их, кнопка «Навигация к №2» ведёт к первому незавершённому.
- **MAP-US-05.** Given у Mike 5 визитов на день и задана стартовая точка (база/дом), When «Упорядочить маршрут», Then показывается предпросмотр: новый порядок, новые времена (длительности сохранены, переезды по оценке), «−18 мин дороги»; визиты с точным временем клиента (онлайн-запись, `exact` с уведомлением) не двигаются; применение только после «Применить»; затронутым клиентам предлагается уведомление.
- **MAP-US-06.** Given список маршрута дня, When карточка перетащена с 4-го места на 2-е, Then `sequence_in_route` пересчитан, времена сдвигаются по каскаду (опция «пересчитать время»), FLIP-анимация по дизайн-системе, undo 6 с.
- **MAP-US-07.** Given Luis дал согласие на геопозицию и приложение отправило координату 10:42, Then его аватар на карте с подписью «10:42 · 3 мин назад»; если последняя координата старше 30 мин — аватар серый «давно не обновлялось»; вне рабочих часов позиция не передаётся и не показывается.
- **MAP-US-08.** Given сегодня визиты у 3 объектов, When включён режим «Рядом», Then показываются только объекты/лиды в радиусе R (по умолчанию 1 миля) от этих визитов из набора: открытые сметы `sent/viewed`, клиенты с RecurringPlan, у которых следующее вхождение в ближайшие 30 дней без времени, лиды `new/contacted`; у каждого пометка «0.4 mi от визита Ким».
- **MAP-US-09.** Given режим «Все компании» (Roofing + Electrical), Then форма пина = слой (капля = лид, круг = клиент, квадрат = визит), цвет обводки/заливки = цвет компании из `Company.brand`; легенда показывает обе компании; фильтр «Компания» доступен; данные компании, где у пользователя нет прав, не видны.

## 6. Экраны
| Экран | Телефон | Планшет / веб |

| Маршрут дня | Список визитов 1…N с временем, перетаскивание, «Упорядочить», итог миль/минут, старт/финиш | Колонки по людям/бригадам, тот же список |
| Фильтры | Слои, статусы, источник, тип работы, дата (сегодня/завтра/неделя), человек/бригада, теги, «нет guards», fire zone, компания | Боковая панель |

## 7. Бизнес-правила и расчёты
**Источник координат.** `Property.geo` (геокодинг при создании адреса, один раз, ~$5/1000). Лид без Property геокодируется по `address_text` в новое поле `Lead.geo`; при квалификации координата переходит в Property. Адрес не распознан → лид в списке «Без координат», не на карте.

**Слои (MVP):**
| Слой | Что | Цвет/признак в одной компании |
|---|---|---|
| Лиды | Lead в статусах `new…estimate_sent` | по статусу; «горячие» (new < 1 ч) пульсируют |
| Клиенты | Property активных Customer (`active`) | серый; акцент для «есть открытая смета», «скоро чистка» |
| Визиты | Visit на выбранную дату (по умолчанию сегодня) | по статусу визита; номер в маршруте |
| Бригада | Последняя позиция каждого участника/бригады | `Membership.color` / `Crew.color` |

**Multi-company:** форма = слой, цвет = компания. Если компаний > 4 — цвет компании только на обводке, заливка по статусу. Совпадение клиента между компаниями (`match_key`) показывается одним пином с двумя бейджами.

**Простой порядок маршрута (MVP):**
1. Вход: визиты человека/бригады на дату, стартовая точка (`Membership` home base или `Company.address`), финиш (= старт по умолчанию).
2. Фиксированные: визиты с `exact` временем, о котором клиент уведомлён, и `en_route/on_site/completed`.
3. Алгоритм: nearest neighbor + 2-opt по матрице расстояний (Haversine × коэффициент 1.3 для городских дорог в MVP; реальная матрица времени через Directions API — опция при наличии сети, ≤ 10 точек).
4. Времена: `start_i = max(end_{i-1} + travel_i + buffer, окно_i.start)`; buffer по умолчанию 15 мин. Визит, выпадающий из своего окна прибытия, помечается красным, применять можно только с подтверждением.
5. Результат — предпросмотр (diff времён), применение = обновление `starts_at/ends_at/sequence_in_route` одной транзакцией + `AuditLog`.

**Геопозиция сотрудников (MVP «последняя известная»):** точка отправляется при смене статуса визита, при открытии приложения и каждые 5 мин в foreground во время рабочих часов (`scheduling_settings`). Фоновый трекинг — позже. Хранение точек 30 дней, видят только owner/admin/office. Сотрудник видит индикатор «геопозиция передаётся».

**Радиус «Рядом»:** R = 1 миля (настройка 0.5–5). Расчёт на сервере по PostGIS, офлайн — по кэшированным точкам.

**Права:** слой «Лиды» и суммы скрыты от tech; gate code показывается только назначенным на визит.

**Стоимость карт:** мобильные SDK практически бесплатны [проверить], веб-карта по загрузкам — на вебе карта грузится по требованию (не на дашборде), кластеризация на клиенте, пины ≤ 5,000 в одной выборке (дальше «уточните фильтр»).

## 9. Офлайн
Без сети: карта показывает кэшированные пины (визиты 14 дней, клиенты и объекты компании, лиды последних 30 дней); базовые тайлы — только те, что уже в кэше SDK; спутник для чертежей кэшируется отдельно (модуль 16). Ручной порядок маршрута — офлайн (outbox). «Упорядочить» — офлайн по Haversine. Позиция бригады — нет (показывается последняя загруженная с меткой времени). Навигация передаётся в Apple/Google Maps (их собственный офлайн).

## 10. Уведомления и автоматизации
- 7:00 сводка дня (модуль 07) содержит ссылку «Маршрут на сегодня» и «N возможностей рядом».
- После «Упорядочить» и применения: push затронутым сотрудникам «Порядок визитов изменён».
- Новый лид в радиусе 2 миль от текущего визита → push владельцу «Лид рядом с тобой (0.8 mi)» (настройка, по умолчанию вкл. для owner).

## 11. Ошибки и крайние случаи
- **Геокодинг неточный** (новостройка, горы) → ручная установка пина перетаскиванием, сохраняется в `Property.geo` с `geo_source=manual`.
- **Много пинов в одной точке** (кондоминиум, HOA) → один пин с числом, раскрытие списком.
- **Сотрудник отозвал разрешение** → аватар исчезает, owner видит «Luis не делится геопозицией», без давления.
- **Упорядочить при отсутствии сети и > 10 точек** → только Haversine, пометка «приблизительно».
- **Двойное «Применить»** → операция с `idempotency_key`, повтор не сдвигает времена второй раз.
- **Визит перенесли в календаре, пока открыт предпросмотр маршрута** → применение отклоняется (`row_version` изменился), предпросмотр пересчитывается.
- **Нет прав** на компанию в группе → её слои не загружаются вообще (фильтрация на сервере, не в UI).

## 12. MVP / позже
**MVP:** 4 слоя, базовые фильтры (статус, источник, тип, дата, человек/бригада, компания, теги), карточка пина с действиями, нумерованный маршрут дня, ручная перестановка, «Упорядочить» (NN + 2-opt, фиксированные визиты), последняя известная позиция сотрудника, режим «Рядом», раскраска по компаниям, кластеры.
**Позже:** live-трекинг в фоне и ETA клиенту по GPS, оптимизация мультибригадная с окнами (VRP через внешний сервис), drag & drop работ на бригады прямо на карте (веб), лассо → кампания, тепловая карта выручки по ZIP, слой fire zone (CAL FIRE) и границ service areas, сравнение пробега с TimeEntry travel.

## 13. Метрики
| Метрика | Цель |
|---|---|
| Доля активных компаний, открывающих карту ≥ 3 раз/нед | ≥ 50% |
| Использование «Упорядочить» на днях с ≥ 3 визитами | ≥ 30% |
| Средняя экономия мин/день по предпросмотру маршрута | ≥ 15 мин |
| Действий «Позвонить/Смета/Визит» с карты в неделю на компанию | baseline в бету |
| Сметы, созданные из режима «Рядом» → одобрены | отслеживаем $ (атрибуция `source=map_nearby`) |

## 15. Открытые вопросы
1. Провайдер карт: Google Maps SDK (единый с веб и спутником) или Apple MapKit на iOS + Mapbox на вебе? Влияет на цену веб-карты и офлайн-кэш (решение в ADR Фазы 3).
2. Нужно ли «последнюю известную позицию» сотрудника показывать в MVP с учётом согласия (CCPA: геоданные сотрудников — personal information; нужен notice at collection) — юридическая проверка.
3. Радиус «Рядом» по умолчанию 1 миля — проверить на данных основателя (LA: плотность выше, пробки важнее расстояния).
4. Показывать ли лиды конкурирующих каналов (Thumbtack) на одной карте с клиентами для tech — по умолчанию нет.
