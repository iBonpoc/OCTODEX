# 19. Налоги: профили, ставки, налог при покупке материалов

> Статус: черновик v0.1, ноябрь 2026 (решение основателя от 03.11.2026, второй пакет). Сущности: `TaxProfile` (новая), `TaxRate` (расширена), `Company.tax_settings`, `Supplier.purchase_tax_rate_id`, налоговые поля `EstimateVersion` / `EstimateOption` / `ChangeOrder` / `Invoice`, `EstimateLineItem.taxable`, `unit_material_cost_cents`, `purchase_tax_bps`, `Refund.allocation`, `Expense.tax_cents`, `PurchaseOrder.tax_cents` (`../04-domain-model.md` §3, §6, v0.3).
> Связанные модули: `04-catalog-suppliers.md` (цены без налога, ставка поставщика), `05-estimates.md` §7.2 (итоги), `09-invoices-payments.md` (налог на инвойсе, возвраты), `10-expenses-job-costing.md` (налог при покупке в себестоимости), `11-purchase-orders.md` (налог в PO), `18-money-test-cases.md` §K (проверочные примеры TX1–TX21).
> **Юридическая оговорка.** Octo не даёт налоговых и юридических советов. Пресеты ниже — это **шаблоны настроек**, а не вывод о том, как облагается ваша работа. Все ставки — **заглушки с пометкой «проверить»**. Исследование для юриста и CPA — `../legal/legal-research.md` §5 (v0.1, 03.11.2026); выводы о том, какой режим верен для калифорнийского подрядчика, подтверждает только ваш CPA.
> **v0.1.1 (03.11.2026, LEG-16):** по исследованию (CDTFA Reg. 1521, Publication 9) для типичного монтажа гаттеров в CA по lump-sum подрядчик — **потребитель** материалов: платит налог при покупке, клиенту налог не начисляет; отдельная строка «Sales tax» клиенту может стать **excess tax reimbursement** (Reg. 1700). Поэтому пресет CA по умолчанию — `included_in_price` с предупреждением при попытке начислить налог. Ставки LA с 01.10.2026 (CDTFA L-1037) внесены как **датированные заглушки**. Подтвердить у CPA (`../legal/legal-research.md` §11.2).

## 1. Назначение
Дать подрядчику настраиваемую схему налогов, которая работает в разных штатах и странах без переделки данных: налог клиенту (sales tax / IVA) по выбранному режиму и налог при покупке материалов, который правильно попадает в себестоимость и маржу. Налог по-прежнему **никогда не включается и не определяется автоматически** по адресу: режим, ставку и облагаемые строки выбирает человек.

## 2. Как это приносит деньги подрядчику (`money_impact`)
| Механизм | Эффект |
|---|---|
| Налог при покупке материалов входит в себестоимость сметы | Маржа не завышена. Пример A из `06` §7.9: себестоимость $859.30 → **$898.02** (+$38.72), маржа 61.2% → **59.5%**. Для компании с $100k закупок материалов в год при ставке 10.25% это ~$10k затрат, которые иначе «пропадают» из маржи |
| Правильный режим на документе | Нет лишней строки налога там, где подрядчик сам платит налог при покупке (иначе клиент переплачивает и смета проигрывает конкуренту), и нет пропущенного налога там, где его надо собирать (иначе налог платится из своей маржи) |
| Цены поставщиков хранятся без налога | Сравнение поставщиков и обновление цен честные: $10.00 у ABC и $10.00 у Home Depot — одна и та же цена, даже если налог у филиалов разный |
| Переключение режимов без потери данных | Компания, которая начала продавать материалы отдельно (или вышла в Texas / Mexico), меняет настройку, а не каталог и не историю |
| Возврат делится на налог и выручку по режиму | Нет ручных расчётов для CPA при каждом возврате |

## 3. Пользователи и роли
| Роль | Что делает |
|---|---|
| owner, admin | Профили, ставки, пресеты, ставки поставщиков, настройка «налог при покупке в себестоимости», отчёт по налогам для CPA |
| office | Выбирает профиль и ставку на документе, включает/выключает налог, меняет `taxable` на строках, вносит ставку поставщика (если включено `permissions_override.can_edit_supplier_tax`) |
| sales (позже), tech | На черновике видит профиль документа; менять профиль и налог не может (настройка: «tech может включать налог») |
| subcontractor | Нет доступа |
| Клиент | Видит строку налога в смете, инвойсе, портале и PDF по режиму документа (§7.5) |

## 5. Критерии приёмки
**TAX-US-01**
- Given новая компания в CA, When онбординг, шаг «Налоги», Then **рекомендован и выбран по умолчанию** пресет «California contractor (lump sum)» (`included_in_price`: подрядчик — потребитель материалов, налог при покупке в себестоимости, строки налога клиенту нет) с пометкой «Рекомендация по исследованию CDTFA Reg. 1521 — подтвердите с CPA» и ссылкой на памятку (`../legal/legal-research.md` §5); выбор любого пресета создаёт `TaxProfile` и нужные `TaxRate` с `is_placeholder = true`.
- Given в CA выбирается пресет с налогом клиенту («Retail materials sale»), Then предупреждение TAX-US-16 и attestation «мой CPA подтвердил модель retailer (seller's permit)» → AuditLog.
- Given пресет выбран, When мастер спрашивает «Включать налог на новых документах по умолчанию?», Then ответ пользователя пишется в `TaxProfile.default_enabled`; по умолчанию — «нет» (налог никогда не включается сам).
- Given пропуск шага, Then создаётся профиль «No tax» по умолчанию, в чек-листе «Настройка» пункт «Налоги не настроены».

**TAX-US-02**
- Given два профиля, When owner отмечает один «по умолчанию», Then у остальных `is_default = false` (ровно один по умолчанию на компанию).
- Given профиль используется в документах, When owner пытается удалить, Then только архив (`is_active = false`); документы живут на снимке.

**TAX-US-03**
- Given черновик сметы с профилем по умолчанию, When office выбирает другой профиль, Then режим, ставка по умолчанию, `include_purchase_tax_in_cost` и подсказки `taxable` берутся из нового профиля; итоги и себестоимость пересчитываются движком; показан diff итогов; в AuditLog запись.
- Given отправленная версия, When пытается сменить профиль, Then запрещено; только новая версия (`05` EST-US-17).
- Given инвойс из сметы, When создаётся, Then профиль и налог берутся из одобренной версии (снимок), а не из текущих настроек компании.

**TAX-US-04**
- Given ставка «LA County 9.50%» с `effective_to = 2026-03-31` и новая «9.75%» с `effective_from = 2026-04-01`, When черновик создан 25.03 и отправляется 02.04, Then предупреждение «ставка устарела: применить 9.75%?»; если пользователь оставляет 9.50%, выбор пишется в AuditLog, снимок 9.50% (TX8).
- Given `effective_from > effective_to`, When сохранение, Then ошибка у поля.
- Given ставка `is_placeholder = true`, When она выбрана на документе, Then на документе значок «тестовая ставка — проверить»; отправка не блокируется.

**TAX-US-05 / TAX-US-06**
- Given режим `added_on_top` и `tax_enabled = false`, When строки помечены `taxable`, Then налог $0.00 (TX6 = `05` T18).
- Given режим `included_in_price` или `exempt`, When открыт документ, Then переключателя налога и флажков `taxable` клиентской стороны нет (флажки сохраняются в данных и вернутся при смене профиля).
- Given любой режим, When меняется адрес объекта, Then ставка и режим не меняются (определения по адресу нет).

**TAX-US-07**
- Given новый поставщик, When создаётся, Then `purchase_tax_rate_id` = ставка компании по умолчанию для покупок (`Company.tax_settings.default_purchase_tax_rate_id`, заглушка «LA area 10.25% — проверить»); ставку можно сменить в карточке, а у филиала задать свою (например, Santa Monica).
- Given поставщик без ставки и у компании нет ставки по умолчанию, When считается себестоимость, Then налог при покупке 0 и предупреждение «у ABC Supply не задан налог при покупке».

**TAX-US-08**
- Given профиль «California contractor», `include_purchase_tax_in_cost = true`, When расчёт примера A (`06` §7.9), Then себестоимость **$898.02**, маржа **59.5%** (TX2); Given `false`, Then **$859.30**, **61.2%** (TX3).
- Given строка услуги без материальной части (`unit_material_cost_cents = 0`), Then налог при покупке к ней не добавляется.

**TAX-US-09**
- Given профиль «Mexico (IVA 16% incl.)», налог включён, When добавлена позиция каталога с ценой без налога $100.00, Then цена строки на документе $116.00 (с IVA); итоги: Total $1,660.00, «в т.ч. IVA 16%: $160.00», без IVA $1,500.00 (TX9).

**TAX-US-10**
- Given профиль `exempt`, When пользователь пытается включить налог (UI или API), Then отказ «профиль без налога»; налог $0.00 (TX12).

**TAX-US-11**
- Given компания меняет профиль по умолчанию «California contractor» → «Retail materials sale», When сохраняет, Then отправленные и одобренные документы не меняются (снимки); у черновиков баннер «Профиль компании изменён. Применить к этому черновику?» с diff; без нажатия черновик остаётся на старом профиле (TX20).
- Given смена профиля и обратно, Then флажки `taxable`, цены и себестоимость строк не теряются (режим только меняет расчёт).

**TAX-US-12** — см. TX13–TX16.
- Given возврат по документу `added_on_top`, When owner вводит $100.00, Then предложено распределение «налог $4.01 / выручка $95.99» (пропорционально); можно выбрать «по строке» или ввести вручную; сумма частей = сумме возврата.
- Given документ `included_in_price` или `exempt`, Then налоговая часть = $0.00, поле распределения не показывается.

**TAX-US-13**
- Given период «октябрь», When «Отчёт по налогам», Then две таблицы: (1) налог с клиентов по ставкам (база, налог, возвраты налога) из инвойсов `sent` не `void`; (2) налог при покупке из `Expense.tax_cents` и PO, по поставщикам; экспорт CSV/XLSX (`04` §7.7).

**TAX-US-14**
- Given есть `TaxRate.is_placeholder = true`, Then в «Настройка» пункт «Проверьте налоговые ставки: 3 тестовые»; пометка снимается кнопкой «Ставка проверена» (кто и когда — в AuditLog).

**TAX-US-16** (LEG-16)
- Given компания или объект в CA и тип договора `ca_home_improvement` / `ca_service_repair` (lump sum), When пользователь включает налог на документе (`tax_enabled = true`) или выбирает профиль `added_on_top` / `tax_inclusive_display`, Then inline-предупреждение: «Обычно подрядчик в CA платит налог при покупке материалов. Начисляйте налог клиенту, только если так сказал ваш бухгалтер. Если клиенту выставлен “sales tax”, а вы были потребителем материалов, собранная сумма — излишний налог: её нужно вернуть клиенту или заплатить в CDTFA (Reg. 1700)». Подтверждение — галочка «мой CPA подтвердил» (один раз на компанию, AuditLog), дальше — только inline-плашка на документе.
- Given change order в CA с отдельно указанной ценой материалов, Then подсказка «отдельно указанная цена материалов в change order может облагаться даже при lump-sum договоре (CDTFA Pub. 9) — уточните у CPA».
- Given шаблон услуги «Чистка гаттеров», Then подсказка `taxable = false` «чистка — услуга без передачи товара, в CA обычно не облагается [подтвердить у CPA]».
- Given первый вход в настройки налогов, Then плашка (один раз на компанию): «Ставки и облагаемость задаёте вы. Octo не определяет налог» (§9.4 исследования).

**TAX-US-15** — см. TX18, TX19 и `04` §7.6.
- Given прайс или чек, где налог указан одной строкой внизу, When распознан, Then цены строк сохраняются без налога, распознанная ставка (налог / подытог) показывается отдельно; если она отличается от ставки поставщика больше, чем на погрешность округления, Then предложение «обновить ставку поставщика до 10.25%?» (только по кнопке).

## 7. Бизнес-правила и расчёты
### 7.1 Два разных налога
| Налог | Кто платит | Где в Octo |
|---|---|---|
| **Налог клиенту** (sales tax, IVA) | Клиент подрядчику, подрядчик передаёт государству | Строка налога на смете, change order, инвойсе — по режиму профиля |
| **Налог при покупке** (purchase / use tax на материалы) | Подрядчик поставщику | Не виден клиенту; входит в себестоимость материалов, если включено `include_purchase_tax_in_cost` |
Все цены поставщиков и себестоимость каталога хранятся **без налога** (`04` §7.2). Цены продажи в каталоге тоже хранятся без налога; режим документа решает, как цена показывается клиенту.

### 7.2 TaxProfile и режимы
| Режим `mode` | Что видит клиент | Налог клиенту | Типичный случай (без юридического вывода) |
|---|---|---|---|
| `included_in_price` | Цены без отдельной строки налога | Нет (0) | Подрядчик как потребитель материалов, договор lump sum (часто в CA); налог при покупке — часть себестоимости |
| `added_on_top` | Строка «Sales tax (ставка)» сверху на облагаемые строки | `round(база × r)` | Продажа материалов (retail), другие штаты |
| `tax_inclusive_display` | Цены с налогом, внизу «в т.ч. налог» | Выделяется из цены: `round(gross × r / (1 + r))` | Mexico (IVA), страны с ценами «с налогом» |
| `exempt` | Без налога | Нет; включить нельзя | Освобождённые клиенты и сделки, тесты |

Поля профиля: `name`, `mode`, `default_sales_rate_id` (→ TaxRate, для `added_on_top` / `tax_inclusive_display`), `default_enabled` (вкл. налог на новых документах; по умолчанию false, меняет только пользователь), `default_taxable_scope` (`all` / `materials_only` / `none`), `deposit_tax_mode` (`in_final` / `proportional`), `include_purchase_tax_in_cost` (по умолчанию true), `is_default`, `is_active`, `preset_key`. В компании несколько профилей, ровно один по умолчанию.

### 7.3 Пресеты (все ставки — заглушки «проверить», см. `../legal/`)
| Пресет | `mode` | Ставка продаж (заглушка) | `default_taxable_scope` | `include_purchase_tax_in_cost` |
|---|---|---|---|---|
| **California contractor (lump sum)** — рекомендуется для CA (LEG-16) | `included_in_price` | — | `none` | вкл. |

### 7.4 TaxRate и регионы
- Поля: `name`, `rate_bps`, `kind` (`sales` / `purchase` / `both`), `country`, `state`, `county`, `city`, `district_note`, `effective_from`, `effective_to` (пусто = действует), `is_placeholder`, `source_note`, `is_active`.
- Ставка на документе выбирается человеком из таблицы; движок только проверяет, что выбранная ставка действует на дату документа (дата создания версии / инвойса). Если не действует — предупреждение (TAX-US-04), не автозамена.
- Таблица ставок — справочник компании; Octo не поставляет «официальные» ставки по адресам и не подбирает ставку по ZIP. Пресеты кладут несколько заглушек.
- Изменение ставки = новая запись с новой `effective_from` (старая закрывается `effective_to`), чтобы история не переписывалась. Пример: «County & City of LA 9.75%» с `effective_to = 2026-09-30` и «10.25%» с `effective_from = 2026-10-01`; черновик от 25.09.2026, отправленный 02.10.2026, получает предупреждение «ставка устарела» (как TX8).

### 7.5 Формулы налога на документе (на вариант; все суммы в центах, round half up, `r = tax_rate_bps / 10000`)
Общие величины (`05` §7.2): `subtotal`, `discount`, `net = subtotal − discount`, `taxable_sub = Σ line_total(included, taxable)`, `taxable_disc = subtotal = 0 ? 0 : round(discount × taxable_sub / subtotal)`.
```
included_in_price:      tax = 0;  total = net                          // taxable не действует
exempt:                 tax = 0;  total = net                          // включить налог нельзя
added_on_top:           tax = tax_enabled ? round((taxable_sub − taxable_disc) × r) : 0
                        total = net + tax
tax_inclusive_display:  цены строк — с налогом (gross)
                        total = net_gross = subtotal − discount          // клиент платит ровно это
                        tax = tax_enabled ? round((taxable_sub − taxable_disc) × r / (1 + r)) : 0
                        net_ex_tax = total − tax                          // «без налога», для выручки
```
- Округление налога — **один раз на документ (вариант)**, не по строкам (TX7).
- Выручка (`10` §7) всегда считается без налога: для `tax_inclusive_display` — `net_ex_tax`.
- `tax_inclusive_display`: при добавлении позиции каталога цена строки = `round(unit_price_cents × (1 + r))`; пользователь может ввести цену с налогом напрямую. Выключение налога на таком документе пересчитывает цены строк каталога обратно в цены без налога (из каталога), а ручные строки — `round(gross / (1 + r))`, с показом diff.
- Вариант может переопределить `tax_enabled` и ставку (как в v0.2); режим — общий для версии (из профиля).
- Скидка в MVP одна на вариант, до налога, распределяется на облагаемую часть пропорционально.

### 7.6 Налог при покупке в себестоимости
```
purchase_tax_bps  = ставка филиала поставщика (если выбран) ?? Supplier.purchase_tax_rate (на дату документа)
                    ?? Company.tax_settings.default_purchase_tax_rate ?? 0 (+ предупреждение)
effective_unit_cost = unit_cost_cents + (include_purchase_tax_in_cost ? unit_material_cost_cents × purchase_tax_bps / 10000 : 0)
line_cost         = round(quantity × effective_unit_cost)          // decimal без промежуточного округления
```
- `unit_cost_cents` — полная себестоимость единицы без налога; `unit_material_cost_cents` (≤ `unit_cost_cents`) — часть, купленная у поставщика, на которую идёт налог при покупке. По умолчанию: `kind = material` → вся себестоимость; `labor`, `fee` → 0; `service` → задаётся на позиции (стартовый price book задаёт материальную часть для miters, elbows, guards, extensions, fascia — `04` §7.5).
- Строка документа хранит снимок `unit_material_cost_cents` и `purchase_tax_bps`, поэтому смена ставки поставщика не меняет старые сметы.
- План/факт (`10` §7): план — по этой формуле; факт — `Expense.amount_cents` (с налогом чека). Если `include_purchase_tax_in_cost = false`, факт материалов = `amount − tax_cents`, а налог чека идёт в отдельную строку отчёта «налог при покупке» (не в себестоимость работы).
- PO (`11` §7.2): строки без налога, `PurchaseOrder.tax_cents = round(Σ po_line_cost × purchase_tax_bps)` (ожидаемый, правится по счёту поставщика); обязательства работы = `po_total + tax_cents + delivery_fee_cents`, если настройка включена.
- Налог при покупке не зависит от режима налога клиенту: в `added_on_top` подрядчик может и собирать налог с клиента, и платить его при покупке — это решает CPA, Octo только даёт переключатель.

### 7.7 Снимки и переключение без потери данных
- На версии сметы, CO и инвойсе хранятся снимки: `tax_profile_id`, `tax_mode`, `tax_enabled`, `tax_rate_id`, `tax_rate_bps`, `include_purchase_tax_in_cost`; на строках — `taxable`, `unit_material_cost_cents`, `purchase_tax_bps`.
- Смена профиля компании или правка профиля не меняет отправленные / одобренные документы и инвойсы с оплатами. Черновики — только по кнопке «Применить» с diff.
- Режим не удаляет данные: флажки `taxable` хранятся всегда, даже когда режим их не использует.
- Инвойс наследует снимок одобренной версии сметы; standalone и recurring — профиль компании по умолчанию.

### 7.8 Депозиты
- `added_on_top`, `deposit_tax_mode = in_final` (по умолчанию): депозитный инвойс без налога, весь налог в финальном (TX17).
- `proportional`: депозитный инвойс несёт долю налога `round(deposit × tax / total)`; финальный — остаток налога (TX17b).
- `tax_inclusive_display`: депозит берётся из total (с налогом); доля налога выделяется так же пропорционально.
- `included_in_price`, `exempt`: налога в депозите нет.

### 7.9 Возвраты (`Refund.allocation`)
| Режим | Распределение по умолчанию | Другие варианты |
|---|---|---|
| `added_on_top` | Пропорционально: `tax_part = round(refund × tax / total)`, остальное — выручка | «По строке»: возврат за строку + её налог по ставке документа; вручную (сумма частей = возврату) |
| `tax_inclusive_display` | Пропорционально (та же формула) | Вручную |
| `included_in_price` | Налоговая часть 0, весь возврат уменьшает выручку | — |
| `exempt` | Налоговая часть 0 | — |
Налог при покупке материалов при возврате денег клиенту не меняется (подрядчик его уже заплатил); возврат материалов в магазин — отрицательный Expense со своим налогом (`18` M23).

### 7.10 Цены поставщиков без налога
- `SupplierItem.cost_cents` и `CatalogItem.unit_cost_cents` — всегда без налога.
- Импорт и AI-скан (`04` §7.6–7.7): если налог указан только внизу документа, строки берутся как есть (без налога), ставка = `tax / taxable_subtotal` сравнивается со ставкой поставщика с допуском на округление (`|tax − round(subtotal × r_supplier)| ≤ 1¢`); расхождение → предложение обновить ставку поставщика (TX18).
- Если цены в файле или на ценнике с налогом (отметка в шаблоне сопоставления «цены включают налог» или распознано на ценнике), цена без налога = `round(gross / (1 + r_supplier))`, строка помечается «цена восстановлена из цены с налогом» (TX19).
- Скидка подрядчика и доставка из прайса / RFQ хранятся отдельно (`SupplierQuote.delivery_fee_cents`), в цену единицы не вмешиваются.

### 7.11 Округление
Одно правило — **round half up** до цента; налог — один раз на вариант / документ; налог при покупке — внутри `line_cost` без промежуточного округления цены единицы; возврат — на сумму возврата.

## 9. Офлайн
Профили, ставки и ставки поставщиков синхронизируются на устройство; переключение налога и профиля на черновике и расчёт итогов — офлайн тем же движком; сервер пересчитывает при синхронизации. Правка профилей и ставок — только в сети (owner/admin).

## 10. Уведомления и автоматизации
- Есть тестовые ставки → пункт чек-листа «Настройка» (TAX-US-14).
- Ставка с `effective_to` через 14 дней → задача owner «Ставка X заканчивается DATE: добавьте новую».
- Квартальное напоминание (за 14 дней до 1 января, 1 апреля, 1 июля, 1 октября) компаниям в CA с налоговыми ставками: «Ставки CDTFA меняются с начала квартала — проверьте свои ставки» (`../legal/README.md` п. 6).
- Распознанная в прайсе или чеке ставка ≠ ставке поставщика → предложение в итоге импорта (не автоматическое изменение).
- Смена профиля по умолчанию → баннер на черновиках.

## 11. Ошибки и крайние случаи
| Случай | Поведение |
|---|---|
| Профиль `exempt`, а строки помечены `taxable` | Флажки сохраняются, налог 0, подсказка «профиль без налога» |
| Два профиля «по умолчанию» (гонка двух админов) | Уникальный частичный индекс; второй получает ошибку и обновлённый список |
| Ставка удалена, а документ её использует | Удалить нельзя, только архив; документы живут на снимке `tax_rate_bps` |
| `unit_material_cost_cents > unit_cost_cents` | Ошибка валидации у поля |
| У поставщика ставка 0% (out of state, без налога) | Допустимо; значок «0% — проверить» |
| Возврат частями: сумма налоговых частей превысила налог документа | Последняя часть ограничивается остатком налога |
| Офлайн-смена профиля при параллельной смене профиля компании | Побеждает выбор на документе (он явный); баннер показывается при открытии |
| Инвойс с оплатой, налог неверный | Строки заблокированы (`09`); исправление — новый standalone-инвойс или void после refund |
