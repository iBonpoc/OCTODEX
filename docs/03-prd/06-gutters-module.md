# 06. Модуль Gutters: чертёж на спутнике → G/B/B → BOM → cut list

> Статус: черновик v0.1, ноябрь 2026. Флагманский модуль, срез 3 MVP. Сущности: `Property`, `Drawing`, `DrawingRun`, `DrawingPoint`, `Assembly`, `CatalogItem`, `EstimateVersion` (`../04-domain-model.md` §2–4). Связанные: `04-catalog-suppliers.md` (price book, формулы), `05-estimates.md` (итоги, версии), `11-purchase-orders.md` (PO из BOM).
> Важно: это **ручной чертёж поверх снимка с известным масштабом**, а не автоизмерение. Автоконтур (Google Solar, AI) — позже (`inputs/gpt-brief-review.md`).
> **Стандарты расчёта — решение основателя 03.11.2026 (второй пакет)**, все редактируются на уровне компании и на конкретной смете: отходы coil **5%** (можно любое значение, включая 0); hangers **каждые 2 ft**; **3 колена A** на один downspout; высоты этажей по умолчанию **1-й = 10 ft, 2-й = 20 ft, 3-й = 30 ft, 4-й = 40 ft** (таблица компании, переопределение на объекте, своя высота на каждом downspout для коммерческих и высоких зданий; этажи выше 4-го — через свою высоту). Длина downspout = высота + удлинение (настройка). Справочник колен (A/B, 2×3 / 3×4 / круглые) расширяемый: полный список основатель пришлёт позже (`04` §7.5).

## 1. Назначение
Подрядчик за 3–5 минут обводит пальцем линии гаттеров на спутниковом снимке дома, ставит downspouts, жмёт «Рассчитать» и получает смету Good/Better/Best, внутренний BOM, cut list для seamless-машины и расход coil по цветам. Это то, что основатель сейчас делает на бумажке: линейные футы, inside/outside углы, downspouts, этажность, guards отдельно.

## 2. Как это приносит деньги подрядчику (`money_impact`)
| Механизм | Эффект |
|---|---|
| Смета на месте или удалённо по адресу до выезда | Меньше выездов «просто померить» (~45–90 мин и ~$20–40 топлива каждый); для лидов с Thumbtack ответ с ценой в тот же час, первый ответивший выигрывает |
| G/B/B пакеты из одного чертежа | Upsell: в примере §7.9 Better +$399 к Good, Best +$2,212 к Good |
| Ничего не забыто (miters, end caps, elbows, hangers по шагу, tear-off, этажность) | Каждая забытая позиция — прямой минус маржи; надбавка за 2-й этаж в примере §7.9 = $316.50 |
| BOM и cut list | Нет повторной поездки к поставщику (~$50–100 времени) и лишнего coil; waste под контролем |
| Coil по цветам → PO | Заказ материалов в день подписи, работа раньше → деньги раньше |
| LA: tile roof и fire zone | Надбавка за tile не теряется ($1.50/LF); в fire zone предлагаются негорючие guards: +$1,813 на примере 129.5 LF |
| Чертёж хранится на объекте | Повторные продажи (чистка, guards) без нового замера |

## 3. Пользователи и роли
| Роль | Что делает |
|---|---|
| owner, sales | Рисует, считает, отправляет смету |
| tech | Рисует черновик (как в `05`: без отправки, без себестоимости), смотрит чертёж и cut list по своей работе |
| subcontractor | Смотрит чертёж, cut list и количества BOM в своём наряде (без цен и себестоимости), не рисует и не считает |
| office | Считает по готовому чертежу, правит атрибуты, отправляет |
| admin | + настройки модуля (константы, пресеты G/B/B) |

## 5. Критерии приёмки
**GUT-US-01**
- Given у объекта есть `geo`, When открывается «Чертёж», Then загружается снимок (zoom 20–21, north-up) за ≤ 3 с на LTE, `scale_ft_per_px` вычислен по формуле §7.1, показаны дата снимка и атрибуция провайдера.
- Given дом не помещается в кадр, When пользователь сдвигает карту, Then догружаются соседние тайлы и склеиваются, масштаб единый.
- Given снимок недоступен (нет покрытия, нет сети, деревья), When открывается, Then предложены: загрузить фото, быстрый ввод (GUT-US-14).

**GUT-US-02**
- Given загружен скриншот, When пользователь проводит линию по объекту и вводит «20 ft», Then `scale_ft_per_px = 20 / длина_px`, `image_source = upload`, калибровка сохранена и видна (линия с подписью).
- Given калибровочная линия < 40 px, When вводит длину, Then предупреждение «слишком короткая, точность низкая», сохранить можно.
- Given масштаб не задан, When пытается рисовать, Then длины не показываются, кнопка «Рассчитать» недоступна.

**GUT-US-03**
- Given режим «Run», When ведёт пальцем и отпускает в точке поворота, Then создаётся вершина; двойной тап или кнопка «Готово» завершает run; длина показывается живьём над сегментом в формате 48′ 6″.
- Given конец сегмента в пределах 1.5 ft от вершины или конца другого run, When отпускает, Then точка прилипает (snap), видна подсветка.
- Given угол сегмента в пределах 7° от 0/45/90° к соседнему, When рисует, Then направление прилипает (можно выключить удержанием).
- Given палец закрывает точку, When ведёт, Then показывается лупа с перекрестием.
- Given ошибка, When жмёт Undo/Redo, Then откат последнего действия (до 50 шагов на сессию).

**GUT-US-04**
- Given сегмент 48.3 ft по снимку, When вводит рулеткой 47′ 9″, Then `length_override_ft = 47.75`, на чертеже значок рулетки, расчёт использует override; расхождение > 10% → вопрос «уверены?».

**GUT-US-05**
- Given выбраны 3 run, When ставит «этаж 2», Then атрибут меняется у всех трёх, итоговая полоса (LF по этажам) обновляется.
- Given новый run, When создаётся, Then атрибуты копируются с предыдущего run (или из `Property.stories`, `roof_type` для первого).
- Given у run профиль half-round, When стоит «зафиксировать профиль», Then пресеты G/B/B его не меняют (`locked_attrs`).

**GUT-US-06**
- Given run с поворотом ≥ 20°, When вершина создана, Then ставится miter: outside, если поворот в сторону крыши, иначе inside (§7.3); значок угла на вершине.
- Given поворот < 20°, When создана вершина, Then miter не ставится (плавный изгиб), вершина отмечена серым.
- Given тап по значку угла, When тапает, Then цикл: outside → inside → нет угла; ручное значение помечается `user_overridden` и не пересчитывается при сдвиге точек.
- Given сторона крыши определена неверно для всего run, When тап «перевернуть сторону крыши», Then все автоматические углы run инвертируются.

**GUT-US-07**
- Given режим «Downspout», When тапает рядом с run (≤ 3 ft), Then точка прилипает к run, высота = высота этажа run по таблице (§7.6: объект → компания → 10/20/30/40 ft), длина = высота + `ds_extension_ft`, колена = `default_elbows` (3 × A размера downspout), размер из пресета варианта, outlet создаётся автоматически.
- Given у свободного конца run нет соседнего run, When run завершён, Then автоматически ставится end cap; у закрытого контура end caps нет.
- Given run без downspout, When «Рассчитать», Then предупреждение «R2 без водостока», расчёт не блокируется.
- Given на run больше 40 LF на один downspout, When «Рассчитать», Then совет «добавьте downspout (рекомендуется ≤ 40 LF на один)».

**GUT-US-18**
- Given настройки компании «Gutters → Высоты этажей», When owner меняет 2-й этаж с 20 на 22 ft, Then новые расчёты используют 22 ft, отправленные сметы не меняются (снимок констант в `calc_inputs`); значение вне 4–80 ft → ошибка с диапазоном.
- Given `ds_extension_ft = 1`, When downspout 2-го этажа, Then длина 20 + 1 = 21 ft.

**GUT-US-19**
- Given у объекта `story_heights_override_ft = {1: 12}`, When ставится downspout на run 1-го этажа, Then высота 12 ft (а не 10); в шапке чертежа «высоты этажей: свои для объекта»; 2-й этаж — из таблицы компании (20 ft).

**GUT-US-20**
- Given downspout, When sales включает «Своя высота» и вводит 46 ft, Then `height_mode = custom`, длина = 46 + `ds_extension_ft`; смена этажа run эту высоту не трогает; значок «своя высота» на точке.
- Given run с этажом 5+ (нет в таблице), When ставится downspout, Then запрашивается своя высота (без неё «Рассчитать» недоступен для этого downspout).

**GUT-US-21**
- Given downspout 3×4, When открыть «Колена», Then по умолчанию «3 × A 3×4»; можно изменить количество и добавить другие варианты из справочника, подходящие по `ds_size` (A, B, круглые для round); 0 колен допустимо.
- Given в каталоге нет колена нужного варианта (например, B для round 4″), When «Рассчитать», Then ошибка «нет позиции Elbow B round 4″» с кнопкой «создать позицию» (`04` §7.3).

**GUT-US-22**
- Given смета, When owner на вкладке «Расчёт» ставит отходы 0%, Then `calc_inputs.constants_override.coil_waste_pct = 0`, coil считается без запаса (пример D), настройки компании не меняются; значок «константы изменены для этой сметы».
- Given отходы > 20%, When сохраняет, Then предупреждение «необычно высокие отходы», сохранить можно (допустимо 0–100%).

**GUT-US-08**
- Given точка fascia repair, When вводит длину 12 ft, Then в смету добавляется строка fascia repair 12 LF во все варианты.

**GUT-US-09**
- Given `Property.roof_type` = `tile_clay` или `tile_concrete`, When создаются runs, Then `hanger_type = strap_tile` по умолчанию; в BOM strap hangers вместо hidden, в смете строка «Работа с tile roof» на LF этих runs.

**GUT-US-10**
- Given чертёж с масштабом и ≥ 1 run, When «Рассчитать», Then за ≤ 1 с (офлайн, на устройстве) создаётся черновик сметы (или новая версия текущей) с вариантами Good / Better (рекомендуем) / Best по пресетам §7.7, итоги по `05` §7.2.
- Given у компании выключены пресеты, When «Рассчитать», Then один вариант «как нарисовано».
- Given в каталоге нет позиции для атрибутов (например, K6 .032 цвета Sandstone нет, а цвет — атрибут coil), When расчёт, Then ошибка с указанием, какой позиции не хватает, и кнопкой «создать позицию» (цена вводится человеком).
- Given результат, When сохраняется, Then `EstimateVersion.calc_inputs` = нормализованные входы (§7.5), `drawing_id`, `drawing_version`, `engine_version`.

**GUT-US-11**
- Given расчёт, When открыть «BOM», Then список материалов по варианту с количеством и (по правам) себестоимостью; все строки `client_visible = false`, `unit_price = 0`.

**GUT-US-12**
- Given расчёт, When открыть «Cut list», Then куски сгруппированы по (профиль, gauge, цвет), у каждого: метка (R1-a), длина ft-in, этаж, концы (end cap / miter); итог coil по группе по §7.8.
- Given half-round, When cut list, Then вместо кусков — число секций по 10 ft (не seamless).

**GUT-US-13**
- Given `Property.fire_zone` ∈ {`high`, `very_high`}, When «Рассчитать», Then в Best только guards с `noncombustible = true`; в Good и Better добавлен optional add-on «негорючие guards» на весь LF; баннер с пояснением (CRC R337 / LA County).
- Given fire zone и выбранная горючая позиция (винил, пена) вручную, When сохраняет смету, Then предупреждение, отправка с подтверждением owner.
- Given `fire_zone` не задан, When открыт объект в MVP, Then поле заполняется вручную (выбор из 4 значений, подсказка со ссылкой на карту CAL FIRE).

**GUT-US-14**
- Given нет чертежа, When «Быстрый ввод», Then форма: LF по этажам (1/2/3/4+), outside / inside углы, число downspouts, число отдельных runs (для end caps, по умолчанию 2), профиль, цвет, guards (да / LF), tear-off; результат — те же сборки и G/B/B.
- Given быстрый ввод, When открыть cut list, Then доступен только итог coil, без кусков (нет геометрии).

**GUT-US-15**
- Given смета отправлена, When пользователь меняет чертёж и «Пересчитать», Then чертёж получает `version + 1`, создаётся версия сметы N+1 (draft) с diff строк и итогов; ручные правки строк версии N (override, добавленные строки) переносятся с пометкой «проверьте».

**GUT-US-16**
- Given tech назначен на работу, When открывает работу, Then видит чертёж утверждённой версии (только чтение), цвета, cut list, BOM без себестоимости; данные есть офлайн за 14 дней до визита.

**GUT-US-17**
- Given у объекта есть чертёж, When создаётся новая смета (например, чистка), Then предлагается использовать существующий чертёж; LF для чистки/guards берётся из него.

## 7. Бизнес-правила и расчёты
### 7.1 Снимок и масштаб
- Спутник: статические снимки провайдера (Google Static Maps или Mapbox, решение в архитектуре), north-up, zoom 20 (21, где есть), `scale = 2` (retina).
- Масштаб Web Mercator: `m_per_px = 156543.03392 × cos(lat) / 2^zoom / scale`; `ft_per_px = m_per_px × 3.28084`.
- Своё изображение: `scale_ft_per_px = known_ft / line_px` (одна калибровочная линия).
- Точность: цель ±2% к рулетке на чистом снимке (проверяем на 20 объектах основателя на бете). Тень, деревья, наклон снимка — причина для override рулеткой.
- Длина сегмента = евклидово расстояние вершин × `scale_ft_per_px`, хранится `numeric(10,3)`, показывается до 1″ (ft-in). Длина run = Σ сегментов (override сегмента побеждает).

### 7.2 Геометрия чертежа
- Run = ломаная по линии карниза (eave), где висит гаттер. Run на одном этаже; соединение runs разных этажей запрещено (предупреждение).
- Snap: вершины и концы ≤ 1.5 ft; направления 0/45/90° ± 7°.
- Концы двух runs одного этажа в пределах 1.5 ft = соединение (joint): угол на стыке, end caps там нет.
- Закрытый run (последняя точка = первая) — контур без end caps.

### 7.3 Углы (inside / outside)
- У каждого run есть `roof_side` (`left`/`right` от направления рисования): крыша всегда по одну сторону от карниза. Авто: по большинству сегментов — сторона, где лежит центр всех точек чертежа (пользователь может перетащить центр здания). Один тап переворачивает.
- В вершине: поворот `θ = угол между направлениями сегментов`. `θ < 20°` → без miter. Иначе: поворот **в сторону крыши** → `miter_outside`, от крыши → `miter_inside`.
- `θ` от 20° до 70° (bay-угол 135°) → miter с атрибутом `angle_deg` (bay miter, отдельная позиция каталога при наличии, иначе обычный miter с пометкой).
- Ручная правка (`user_overridden`) не пересчитывается при изменении геометрии.

### 7.4 End caps, outlets, downspouts
- `end_caps` = число свободных концов runs (не joint, не закрытый контур), по профилю.
- `outlets = downspouts` (размер outlet = размер downspout).
- Высота downspout (решение основателя): 
  ```
  story_height(s) = Property.story_heights_override_ft[s] ?? Company.gutter_settings.story_heights_ft[s] ?? модуль {1:10, 2:20, 3:30, 4:40}
  height_i        = height_mode_i = custom ? custom_height_ft_i : story_height(story_i)      // этажа нет в таблице (по умолчанию 5+) → только custom
  downspout_len_i = length_override_ft_i ?? height_i + ds_extension_ft
  ```
  Высота = расстояние от карниза данного этажа до земли (до точки слива). `length_override_ft` — значение рулетки, побеждает всё.
- Колена: `elbows_i` — список `{style, qty}` по умолчанию из `default_elbows` = `[{style: A, qty: 3}]` (2 сверху для отвода к стене, 1 внизу), правится на точке; размер колена = размер downspout. Позиция колена выбирается селектором `component = elbow, elbow_style, ds_size` (`04` §7.5).

### 7.5 Нормализованные входы сборки (`calc_inputs`)
```
runs[]:       id, label, story, profile, gauge, color, guards, tear_off, hanger_type,
              lf (после округления §7.6), segments_ft[], ends: [end_cap|joint|miter]
miters[]:     run_id, kind (in/out), angle_deg
downspouts[]: run_id, size (2x3/3x4/round_3/round_4), height_mode (story/custom), height_ft, length_ft,
              elbows: [{style, qty}], extension
fascia_lf, property: { stories, roof_type, fire_zone, story_heights_override_ft }
constants:    Assembly.constants → Company.gutter_settings → constants_override сметы (снимок итоговых значений)
```
Совпадает с `Assembly.inputs` модели (`gutter_lf_by_story`, `downspouts[]`, `miters_in`, `miters_out`, `end_caps`, `guards`, `tear_off`): агрегаты считаются из этого JSON. Быстрый ввод (GUT-US-14) создаёт тот же JSON без `segments_ft`.

### 7.6 Константы (по умолчанию, настраиваются компанией и на смете)
Порядок: значения модуля (`Assembly.constants`) → настройки компании (`Company.gutter_settings`) → переопределение на смете (`calc_inputs.constants_override`). В `calc_inputs` версии сохраняются итоговые значения, поэтому отправленная смета не меняется при правке настроек.
| Константа | По умолч. (решение основателя 03.11.2026) | Диапазон |
|---|---|---|
| `hanger_spacing_ft` | **2.0** (24″) | 1.0–4.0 |
| `story_heights_ft` | **{1: 10, 2: 20, 3: 30, 4: 40}** | каждое 4–80 ft, строго возрастают; можно добавить этажи 5+ в таблицу компании |
| `ds_extension_ft` (было `ds_extra_ft`) | 0 | 0–10 |
| `ds_stick_ft` | 10 | 10, 20 |
| `default_elbows` | **[{style: A, qty: 3}]** на downspout | qty 0–10 по каждому стилю |
| `coil_waste_pct` | **5%** | **0–100%** (0 допустим; > 20% — предупреждение) |
| `lf_rounding_ft` | 0.5 (вверх, на run) | 0, 0.5, 1 |
| `joints_per_sealant_tube` | 8 | 4–20 |
| `lf_per_screw_box` | 150 | 50–500 |
| `max_lf_per_ds` (совет) | 40 | 20–80 |
| `min_turn_deg` | 20 | 10–45 |
| `coil_width_in` | K5 → 11⅞″, K6 → 15″ | по профилю |
`Property.story_heights_override_ft` переопределяет отдельные этажи для объекта; `custom_height_ft` на downspout — для коммерческих и высоких зданий и для этажей вне таблицы.

### 7.7 Формулы сборок (на вариант)
```
run_lf_i        = ceil_to(lf_rounding_ft, Σ segments_i)            // 105.5 → 105.5; 148.625 → 149.0
gutter_lf[p,g]  = Σ run_lf_i по (profile, gauge)                     → видимая строка gut.<p>.<g>
story_fee_lf[s] = Σ run_lf_i где story = s (s ≥ 2)                    → fee.story2 / fee.story3 / fee.story4 (для 4 и выше)
miters_out/in   = count(miters по kind)                              → miter.out / miter.in
downspout_lf[z] = Σ downspout_len_i по size z (§7.4)                  → ds.<z>
elbows[st,z]    = Σ qty колен стиля st на downspouts размера z         → elbow.<st>.<z> (селектор по атрибутам)
tear_off_lf     = Σ run_lf_i где tear_off                             → rem.tearoff
guards_lf       = Σ run_lf_i где guards (в Best: все runs)            → guard.*
tile_lf         = Σ run_lf_i где hanger_type = strap_tile             → fee.tile
fascia_lf       = Σ длин точек fascia_repair                          → fascia.repair
— BOM (client_visible = false, price 0) —
hangers[type]   = Σ ceil(run_lf_i / hanger_spacing_ft)  (по каждому run, потом сумма)
end_caps[p]     = свободные концы по профилю
outlets[z]      = downspouts по size
ds_sticks       = Σ ceil(length_ft_i / ds_stick_ft)
sealant_tubes   = ceil((end_caps + miters_in + miters_out + outlets) / joints_per_sealant_tube)
screw_boxes     = ceil(Σ gutter_lf / lf_per_screw_box)
coil_lf[w,g,c]  = ceil(Σ cut_len_k × (1 + coil_waste_pct))  по (ширина, gauge, цвет), см. §7.8; при 0% = ceil(Σ cut_len_k)
hr_sections     = Σ ceil(run_lf_i / 10)  для half-round (вместо coil)
```
Пресеты G/B/B (системный `EstimateTemplate` модуля, правится admin):
| Вариант | Профиль / gauge | Downspout | Guards |
|---|---|---|---|
| Good | K5 .027 | 2×3 | нет (в fire zone — optional add-on негорючие) |
| Better (рекомендуем) | K6 .032 | 3×4 | нет (в fire zone — optional add-on) |
| Best | K6 .032 | 3×4 | micro-mesh на все runs (в fire zone только негорючие) |
Пресет меняет только профиль, gauge, размер downspout и guards; этаж, цвет, tear-off, hanger type и `locked_attrs` остаются как нарисовано.

### 7.8 Cut list и coil
- Кусок = прямой сегмент между концами и miters одного run. `cut_len = segment_ft + end_allowance × число концов` (по умолчанию 0″; настройка компании), округление вверх до ¼″.
- Метки: `R<номер run>-<буква сегмента>`, сортировка по группе (профиль, gauge, цвет), затем по убыванию длины.
- Coil считается по группе (ширина, gauge, цвет) с округлением вверх до целого фута **на группу**, поэтому сумма по цветам может быть больше, чем coil «в целом» (см. пример B).
- Учёт остатков coil на складе — позже.

### 7.10 Специфика Лос-Анджелеса
- **Tile roof:** strap hangers, надбавка за LF; tile — частый случай, поэтому `roof_type` спрашивается при первом чертеже, если не задан.
- **Fire zones (FHSZ/WUI):** по CRC R337 / CBC 705A и правилам LA County гаттеры и guards должны быть негорючими. В MVP `fire_zone` вводится вручную, автопроверка по данным CAL FIRE — позже. Позиции каталога несут атрибут `noncombustible`.
- **Сезон дождей (окт–ноя):** после монтажа предлагается RecurringPlan на чистку по LF из чертежа (`07`).

## 9. Офлайн

## 10. Уведомления и автоматизации
- Осмотр запланирован → снимок объекта кэшируется на устройство исполнителя накануне.
- Смета из чертежа одобрена → PO-черновики по coil и материалам (`11`), cut list прикрепляется к работе.
- Объект в fire zone без guards в одобренной смете → через 30 дней после работы задача «предложить негорючие guards» (не отправка, только задача).

## 11. Ошибки и крайние случаи
| Случай | Поведение |
|---|---|
| Снимок старый (дом перестроен) | Показ даты снимка; загрузка своего фото / быстрый ввод |
| Деревья закрывают карниз | Рисовать по видимой части + override рулеткой; предупреждение при > 10% override |
| Поворот телефона во время рисования | Состояние сохраняется, незавершённый run не теряется |
| Самопересекающийся run | Предупреждение, расчёт разрешён |
| Run длиной < 1 ft (случайный тап) | Удаляется автоматически с toast «Отменить» |
| Downspout без run рядом | Не ставится, подсказка «поставьте ближе к линии» |
| Нет позиции в каталоге для цвета/профиля | Ошибка с кнопкой создания позиции (`04` §7.3) |
| Двойное нажатие «Рассчитать» | Один черновик / одна новая версия (ключ: `drawing_id + drawing_version + preset_set`) |
| Чертёж изменён после одобрения сметы | Смета не меняется; изменения только через change order (`05`) |
| Дом > 300 ft по стороне | Склейка тайлов; при > 9 тайлах предложение загрузить фото |

## 13. Метрики
- Время чертёж → смета (baseline основателя на бумаге; цель < 5 мин на типовой дом).
- Точность: |чертёж − рулетка| / рулетка на 20 объектах (цель ≤ 2% медиана, ≤ 5% у 90%).
- Доля смет Gutters из чертежа vs быстрый ввод vs вручную.
- Доля override рулеткой (сигнал качества снимков).
- Нехватка материала на объекте (повторные поездки к поставщику на 10 работ; цель снизить вдвое к baseline).
- Доля одобрений Better/Best; доля принятых add-on guards в fire zone.
