# 12. Портал клиента, витрина, онлайн-запись, публичная SEO-страница

> Статус: черновик v0.1, ноябрь 2026. Сущности: `PortalAccess`, `PublicProfile`, `AvailabilityRule`, `BookingRequest`, `ReviewRequest`, `Referral`, `Estimate/EstimateVersion/EstimateOption/EstimateLineItem/EstimateApproval`, `Invoice`, `Payment`, `Job`, `Visit`, `RecurringPlan`, `Property`, `File`, `Lead`, `LeadSource`, `Activity`, `Contact.preferred_language` (`../04-domain-model.md` §7).
> Связанные модули: `05-estimates.md`, `09-invoices-payments.md`, `07-jobs-schedule.md`, `13-communications-automations.md` (отзывы, рефералки), `02-leads.md`. SEO-архитектура — `08a-seo.md` (Фаза 3).

## 1. Назначение
Клиент без установки приложения открывает защищённую ссылку и делает всё: смотрит смету G/B/B, подписывает, платит депозит и инвойсы, видит историю своего дома и записывается снова. Портал одновременно — **витрина подрядчика** (другие услуги, галерея, отзывы, рефералка). Плюс публичная SEO-страница компании с онлайн-записью на осмотр.

## 2. Как это приносит деньги подрядчику (`money_impact`)
| Механизм | Оценка |
|---|---|
| **Подпись + депозит в одной ссылке** | Same-day close вместо «подумаю»: +5–10 п.п. к close rate; при 20 сметах/мес × $2.5k ≈ **+$2.5–5k/мес** выручки |
| G/B/B с рекомендованным вариантом | Доля Better/Best ↑ → средний чек +10–20% |
| **Витрина: другие услуги** (guards, чистка, fascia) рядом со сметой/инвойсом | Cross-sell 5–10% клиентов × $1.5k guards |
| **«Book again» / следующая чистка** из истории дома | Повторная выручка без рекламы (см. RecurringPlan, модуль 07) |
| **Реферальная ссылка** | Самый дешёвый лид: $0–50 награды против $45–100 за лид Thumbtack |
| **Онлайн-запись на осмотр** 24/7 в реально свободные слоты | Ловит вечерние/выходные лиды, которые иначе уходят первому ответившему |
| SEO-страница + schema.org | Органические лиды вместо платных площадок; страница — бесплатный «сайт» для тех, у кого его нет |

## 5. Критерии приёмки
- **POR-US-01.** Given отправлена смета, When клиент открывает `octo.app/c/{token}`, Then без входа видна `sent_version` сметы, бренд компании, контакты; `PortalAccess.last_opened_at`, `Estimate.viewed_count` обновлены, Estimate `sent → viewed` при первом открытии, в ленту — Activity «Клиент открыл смету». Открытия сотрудниками компании (по их сессии) не считаются.
- **POR-US-02.** Given 3 варианта и `is_recommended` у Better, Then Better подсвечен «Рекомендуем»; When клиент отмечает optional «Guards 120 LF», Then итог варианта пересчитывается тем же детерминированным движком (центы, без float) и совпадает с серверным расчётом; клиент не видит BOM-строки и себестоимость.
- **POR-US-04.** Given выбран вариант, When клиент вводит имя, рисует подпись, ставит галочку согласия на электронную подпись (ESIGN/UETA) и нажимает «Подписать», Then создаётся `EstimateApproval` (signer_name, signature_file_id, signed_at, ip, user_agent, channel=portal), Estimate → `approved` идемпотентно, клиенту email с PDF подписанной версии; при `deposit_rule` экран сразу переходит к оплате депозита (модуль 09). Given смета `expired` или версия заменена, Then подпись недоступна, кнопка «Запросить актуальную смету».
- **POR-US-05.** Given у клиента 2 инвойса с балансом, Then список с суммами и сроками, ACH первым при балансе ≥ порога; оплата по правилам модуля 09 (idempotency, pending ACH); после оплаты — квитанция на экране и email.
- **POR-US-06.** Given по объекту закрыты 2 работы, Then «Мой дом»: адрес, список работ (дата, что сделано), фото с `client_visible=true` (до/после парами), гарантии (вид, срок, «до 11/2036»), «Следующая чистка: неделя 6–10 октября» (из RecurringPlan) или кнопка «Запланировать чистку».
- **POR-US-07.** Given в `PublicProfile.services` 5 услуг, Then в портале под документом блок «Мы также делаем» без услуг, которые уже есть в этой смете/работе; галерея ≤ 12 фото; отзывы (выбранные владельцем тексты + ссылка «Все отзывы на Google»); «Порекомендуйте нас» с персональной ссылкой `Referral.code`; клик по услуге создаёт BookingRequest/Lead с источником «Портал» и привязкой к клиенту.
- **POR-US-08.** Given AvailabilityRule (пн–сб 8–17, осмотр 45 мин, буфер 30 мин, ZIP-зоны, сотрудники Mike/Yuri), When посетитель вводит адрес и выбирает день, Then показываются только слоты, где хотя бы один разрешённый сотрудник свободен с учётом его визитов во всех компаниях пользователя, буфера и минимального уведомления (по умолчанию 12 ч); When слот выбран и подтверждён, Then слот резервируется атомарно, создаются BookingRequest, Lead (source Портал/Сайт), Visit `kind=inspection` с `lead_id`; при одновременной записи двух посетителей на один слот второй получает «Слот только что заняли» и ближайшие альтернативы. Адрес вне зон → «Оставьте заявку, мы перезвоним» (Lead без визита).
- **POR-US-09.** Given `PublicProfile` заполнен, When Googlebot запрашивает `octo.app/p/{public_slug}`, Then HTML отдаётся с сервера (SSR), есть `<title>`, meta description, canonical, `hreflang` en/es, JSON-LD `HomeAndConstructionBusiness` (name, address или areaServed, telephone, url, openingHours, aggregateRating только из реальных отзывов на странице), страница в sitemap компании; Lighthouse SEO ≥ 95, LCP < 2.5 с на 4G.
- **POR-US-10.** Given `Contact.preferred_language=es`, Then портал открывается на испанском (интерфейс + тексты документа, если есть ES-версия), переключатель EN/ES сверху; юридические тексты (terms, согласие на e-sign) — в утверждённых переводах.
- **POR-US-12.** Given токен истёк или отозван, When клиент открывает ссылку, Then экран «Ссылка устарела» с кнопкой «Прислать новую» → новая ссылка уходит только на email/телефон из карточки Contact (не на введённый), лимит 3 запроса/сутки.

## 7. Бизнес-правила и расчёты
**PortalAccess (безопасность).**
- Токен ≥ 128 бит случайный, в URL; в базе только `token_hash` (SHA-256). `scope`: `document` (одна смета/инвойс) или `customer` (все документы клиента, «Мой дом»). Ссылки из писем по документу — `document`; «Мой дом» — `customer`.
- Срок: по умолчанию 90 дней для смет (или до `expires_at` сметы), 180 дней для `customer`; отзыв (`revoked_at`) при смене владельца объекта, по кнопке владельца, при `Customer.status=do_not_service`.
- Ответы портала `noindex, nofollow`, `Referrer-Policy: no-referrer`, без PII в URL; rate limit по токену и IP; один токен — одна компания (multi-company: у каждой компании свой бренд и свой портал; клиент двух компаний группы получает две отдельные ссылки).
- Действия «подписать» и «оплатить» требуют свежего открытия (токен активен) и записываются в AuditLog с `actor_type=customer`. Для смет > $10k (настройка) — одноразовый код на email/телефон из карточки перед подписью (позже, по умолчанию выкл. в MVP).

**Электронная подпись:** согласие на электронные записи (ESIGN Act / UETA, CA Civil Code §1633), явное намерение (кнопка с текстом «Подписываю»), привязка к версии (`version_id` + хэш содержимого PDF), копия клиенту, хранение ≥ 4 лет (CSLB / договорные споры) [проверить у юриста]. Подписанная версия неизменяема.

**Финансирование в смете (позже):** «от $X/мес» — это trigger term по TILA/Reg Z; показываем только данные/виджет лендера (Wisetack) с обязательными раскрытиями (APR, срок). Своих расчётов ежемесячного платежа в MVP **не показываем**; `EstimateOption.financing_monthly_cents` заполняется только из ответа лендера.

**Слоты онлайн-записи:**
```
кандидаты = окна AvailabilityRule(день) для разрешённых сотрудников
          − [визиты сотрудника во всех компаниях (starts_at − buffer, ends_at + buffer)]
          − [слоты, держащиеся в hold < 10 мин]
          − [всё раньше now + min_notice]
слот виден, если ∃ сотрудник, у которого свободно [t, t + inspection_duration)
адрес ∈ service_zip_zones (иначе — заявка без слота)
```
- Резервирование: транзакция с блокировкой по (`company_id`, сотрудник, интервал) + exclusion constraint на пересечение визитов назначенного сотрудника; hold 10 мин на шаге «контакты».
- Подтверждение: `auto_confirm` (по умолчанию вкл.) → BookingRequest `confirmed` сразу; иначе `requested` → владелец подтверждает в 1 тап, клиенту уведомление.
- Только `inspection` в MVP. Монтаж и чистка — заявкой («Записаться снова» на чистку → BookingRequest `requested` с предпочтительной неделей, владелец ставит время).
- Защита от спама: Cloudflare Turnstile, лимит 3 записи/сутки на телефон и IP, подтверждение телефона SMS-кодом только при включённом пакете SMS (иначе email-подтверждение).

**Витрина:** услуги = `PublicProfile.services` (из ServiceCategory + цена «от» по желанию владельца); исключаем уже купленные/предложенные в этом документе. Отзывы MVP: тексты, которые владелец добавил вручную (с именем/инициалами и согласия клиента), плюс ссылка на Google-профиль; **без фильтра недовольных при запросе** (review gating запрещён, модуль 13), но отображение выбранных цитат на своей странице допустимо, aggregateRating в JSON-LD — только по отзывам, реально показанным на странице. Импорт отзывов из Google Business Profile — позже.

**Рефералка (MVP):** у каждого клиента с завершённой работой `Referral.code`; ссылка `octo.app/p/{slug}?ref={code}` ведёт на публичную страницу/запись → Lead `source=Реферал`, `Referral.new_lead_id`; награда фиксируется вручную владельцем (`reward`), автоматические выплаты — позже.

**Публичная SEO-страница (MVP):** одна страница на компанию `octo.app/p/{public_slug}` + ES-версия `/es`. Районы обслуживания — список городов/районов LA (Glendale, Burbank, Pasadena…) текстом и `areaServed`, **без** генерации отдельных страниц на каждый город (doorway pages — риск санкций Google). Адрес: если работает из дома — скрыть улицу (`service-area business`), показывать город. Лицензия CSLB со ссылкой на проверку. Sitemap и canonical; при подключении своего домена (позже) — 301 и canonical на свой домен.

**Переводы:** интерфейс портала — EN/ES из словаря продукта; тексты компании (about, услуги, scope сметы) — AI-перевод черновиком, владелец утверждает; неутверждённый перевод не публикуется (показывается EN).

## 11. Ошибки и крайние случаи
- **Двойное «Подписать»/«Оплатить»** → идемпотентно (approval по `version_id`, платежи — модуль 09).
- **Подрядчик выпустил новую версию, пока клиент смотрит старую** → при подписи сервер проверяет `sent_version_id`; несовпадение → «Смета обновлена, посмотрите новую версию».
- **Клиент переслал ссылку соседу** → scope `document` ограничивает ущерб; в «Мой дом» доступ только по `customer`-ссылке; владелец может отозвать.
- **Слот заняли параллельно** → атомарная проверка, альтернативы.
- **Сотрудник удалён из AvailabilityRule при существующих записях** → записи остаются, владельцу Task переназначить.
- **Stripe не подключён** → кнопки оплаты скрыты, текст «Оплата: свяжитесь с нами», подпись работает.
- **Фото с лицами/номерами домов в галерее** → по умолчанию в публичную галерею попадают только фото, явно отмеченные владельцем; предупреждение «проверьте, нет ли адреса/людей».
- **Испанский текст сметы отсутствует** → показываем EN с пометкой, интерфейс на ES.
- **Брутфорс токенов** → 128 бит + rate limit + алерт при всплеске 404.

## 12. MVP / позже
**MVP:** PortalAccess (document/customer), смета G/B/B с add-ons, e-sign, депозит, инвойсы и оплата (card/ACH), «Мой дом» (работы, фото до/после, гарантии, следующая чистка), блок витрины (услуги, галерея, отзывы вручную + ссылка Google, рефералка с ручной наградой, «Записаться снова» заявкой), онлайн-запись на inspection в реальные слоты, одна публичная SEO-страница EN/ES с JSON-LD, трекинг открытий, повторный запрос ссылки.
**Позже:** финансирование «от $X/мес» (Wisetack), membership с автосписанием, перенос визита клиентом, онлайн-запись на чистку/монтаж с длительностью по размеру дома, импорт отзывов GBP, страницы услуга × город и свой домен, instant quote по адресу, OTP перед подписью, cross-sell между компаниями группы, клиентский AI-чат.
