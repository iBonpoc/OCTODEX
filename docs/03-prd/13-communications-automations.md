# PRD 13. Коммуникации и автоматизации

> Статус: черновик v0.1, ноябрь 2026. Сущности: `MessageThread`, `Message`, `Contact` (согласия), `ReviewRequest`, `Referral`, `Task`, `Activity`, `Entitlement`/`UsageCounter` (`../04-domain-model.md` §2, §7, §8).
> Колонки: **MVP** = бета на компании основателя · **Запуск** = до первых платящих · **Позже**.
> Юридические пункты (TCPA, 10DLC, CAN-SPAM, FTC 16 CFR 465) перед запуском проверяет юрист.
> **v0.1.1 (03.11.2026):** внесены требования `../legal/legal-research.md` §3, §7 (LEG-10…LEG-14): журнал согласий `ConsentRecord`, тексты согласий EN/ES как шаблоны (черновики для адвоката), слова отзыва и срок исполнения ≤ 10 рабочих дней, quiet hours по часовому поясу **получателя**, импорт ≠ согласие, запрос отзыва и реферальное предложение — **разные** сообщения (транзакционное и маркетинговое).

## 1. Назначение
Автоматически сказать клиенту нужное в нужный момент — «получили заявку», «смета ждёт», «завтра приедем», «мы в пути», «счёт к оплате», «оставьте отзыв», «приведите соседа» — по SMS или email на его языке, законно и без ручной работы владельца. В MVP — 5 встроенных автоматизаций с настройками, без конструктора.

## 2. Как это приносит деньги подрядчику (`money_impact`)
| Автоматизация / функция | Эффект |
|---|---|
| №1 Мгновенный ответ на лид | Клиент с сайта/портала получает ответ за секунды, пока владелец на лестнице; выше шанс, что не позвонит следующему подрядчику |
| №2 Дожим сметы + сигнал «открыл 3 раза» | Возвращает часть зависших смет (рынок: 10–20%); владелец звонит в момент интереса, а не через неделю |
| №3 Напоминание о визите и «В пути» | Меньше no-show и «никого нет дома» = меньше холостых выездов бригады |
| №4 Напоминание об оплате | Деньги приходят раньше, меньше дебиторки 30+ дней без звонков «а вы заплатите?» |
| №5 Отзыв всем (транзакционное) + №5b реферальное предложение (маркетинг, отдельным сообщением) | Больше отзывов в Google → выше в local pack → бесплатные лиды вместо Thumbtack; рефералка = лид за цену награды; разделение сообщений убирает риск TCPA за маркетинг без письменного согласия |
| Сезонная кампания чистки (Запуск) | Прошлые клиенты в сентябре–октябре (перед дождями) = повторная выручка без рекламы |
| SMS «с моего телефона» на Starter | Бесплатная альтернатива платным SMS: шаблон открывается в Messages iPhone |
| Законность (opt-in, STOP, quiet hours, без review gating) | Нет штрафов TCPA ($500–1,500 за сообщение) и FTC (~$51k за нарушение) |

## 3. Пользователи и роли
- **Owner/Admin** — включают и настраивают автоматизации, шаблоны, SMS-номер, 10DLC, кампании.
- **Office** — переписка, ручные сообщения, запуск дожима.
- **Tech** — «В пути», сообщения клиенту по своим визитам (по шаблонам), видит переписку только по своим работам.
- **Клиент** — получает сообщения, отвечает, отписывается (STOP / unsubscribe).
- **Субподрядчик** — получает наряды по ссылке и напоминания (PRD 07), отвечает в переписку наряда; никогда не получает цены клиента.

## 5. Критерии приёмки
- **COMM-US-01.** Given клиент, Then вкладка «Переписка» показывает `MessageThread` по каналам SMS/email/portal с статусами `queued → sent → delivered / failed`; входящее SMS/email-ответ появляется ≤ 30 с и даёт push назначенному на клиента/лид (по умолчанию owner). Given входящее SMS с неизвестного номера, Then создаётся `Lead(status=new, parse_status=needs_review)` с текстом сообщения.
- **COMM-US-02.** Given Starter без SMS-пакета, When «SMS» в карточке, Then открывается системный композер iOS с номером контакта и текстом шаблона; в ленту пишется `Activity(kind=sms_external)` «отправлено с личного телефона (не подтверждено)». Автоматизации на Starter используют email; шаги «только SMS» пропускаются.
- **COMM-US-03.** Given Pro или SMS-пакет, When owner заполняет анкету (юр. имя, EIN или sole proprietor, адрес, сайт или `PublicProfile`, примеры сообщений), Then Octo регистрирует Brand и Campaign в TCR через Twilio (ISV), покупает номер в выбранном area code; статус виден («на проверке, обычно 1–4 недели»). Given статус не `approved`, Then отправка SMS недоступна, всё уходит email.
- **COMM-US-04.** (LEG-10) Given контакт, Then каждое согласие и каждый отзыв — запись `ConsentRecord` (§14; `../legal/legal-research.md` §3.5): номер E.164, канал, категория (`transactional` / `marketing`), статус, **точный текст согласия и его версия**, язык, источник (`web_form` / `portal` / `estimate_sign` / `verbal_recorded_by_user` / `customer_texted_first` / `paper_form_photo` / `attestation`), URL и скриншот формы (версия), IP, user agent, время UTC, кто записал (для устного и attestation), message SID подтверждающего SMS; отзыв — время, способ, исходный текст, когда исполнено. Флаги `Contact.sms_opt_in` / `sms_marketing_opt_in` — вычисляемые из последней записи по категории. Хранение — 5 лет после последнего сообщения или отзыва (LEG-21).
  - Given формы лида, портала и экран подписи сметы, Then **две отдельные галочки**, обе **не отмечены заранее**: служебные SMS (текст A) и маркетинг (текст B, COMM-US-16); согласие не спрятано в ToS; ссылки на SMS Terms и Privacy компании (`PublicProfile`, LEG-13).
  - Given получено согласие, Then сразу **одно** подтверждающее SMS (текст C, для маркетинга — D); его SID пишется в запись. Given устное согласие, Then сотрудник выбирает «клиент согласился устно» по скрипту G (attestation-галочка → AuditLog), Octo сразу отправляет C; устное согласие **никогда** не даёт маркетинга.
  - Given **импорт контактов** (CSV/XLSX, `04` §7.7), Then импорт **никогда не создаёт согласие**: статус SMS = `unknown`. Транзакционные SMS — только после согласия самого клиента (форма, портал, ответное SMS, подпись сметы) или отдельного attestation подрядчика по контакту/списку («у меня есть согласие этих клиентов на служебные SMS», источник `attestation`, AuditLog). Маркетинговые SMS импортированным номерам — **никогда** без нового письменного согласия.
  - Given входящее SMS с ключевым словом (без учёта регистра, всё сообщение или первое слово): **STOP, STOPALL, QUIT, END, REVOKE, OPT-OUT, OPTOUT, CANCEL, UNSUBSCRIBE**, ES: **ALTO, PARAR, CANCELAR, BAJA** [Проверить у адвоката и Twilio], Then отзыв **всех** категорий SMS на этот номер в этой компании: запись отзыва, **одно** подтверждение (текст F), дальше любые SMS этому номеру блокируются сервером **немедленно** (закон требует ≤ 10 рабочих дней, FCC 24-24; мы исполняем сразу).
  - Given входящее сообщение без ключевого слова, но со смыслом отзыва («please stop texting me», «no me manden mensajes») — «любой разумный способ», Then AI-классификатор или правило помечает «возможный отзыв», Task владельцу «Подтвердите отписку» с дедлайном **≤ 10 рабочих дней** от получения (по умолчанию — тот же день); до решения автоматические SMS на номер приостановлены. Отзыв по телефону или email — кнопка «Клиент отозвал согласие» (способ, текст) с тем же исполнением.
  - Given HELP / AYUDA, Then ответ E (имя компании, CSLB #, телефон, email). Given START / UNSTOP, Then восстанавливается **только транзакционное** согласие (новая запись, источник `customer_texted_first`), маркетинг — только новой письменной галочкой.
  - Given первое SMS на номер, Then в конце «Reply STOP to opt out» / «Responda STOP para cancelar».
  - Отзыв по категории (FCC R&O 09.2026, вступает через 30 дней после публикации [Проверить дату]): Given клиент отписался только от маркетинга (ссылка в маркетинговом SMS/email или кнопка в портале), Then транзакционные продолжаются; отзыв маркетинга прекращает **весь** маркетинг.
- **COMM-US-05.** Given шаблон с ключом (например `estimate.followup.1`), Then есть системные версии EN и ES; owner может править текст (переменные `{first_name}`, `{company_name}`, `{estimate_link}`, `{total}`, `{recommended_total}`, `{visit_date}`, `{arrival_window}`, `{eta_min}`, `{invoice_link}`, `{balance}`, `{review_link}`, `{referral_link}`, для нарядов: `{work_order_link}`, `{sub_first_name}`, `{job_address}`); язык = `Contact.preferred_language`, нет ES-версии → EN. Отправка с неразрешённой переменной блокируется с ошибкой в предпросмотре.
- **COMM-US-06.** (№1) Given лид с сайта/портала/ручной лид с отметкой «отправить приветствие», имеющий телефон с согласием или email, When лид создан, Then ≤ 60 с уходит «Thanks {first_name}, we got your request — {company_name} will call you within {N} min. Book an inspection now: {booking_link}» и создаётся задача «Перезвонить» (если нет `first_response_at` через N мин). Автоответ не считается `first_response_at`. Лиды из маркетплейсов (email-пересылка) не получают автоответ (ответ идёт в площадке, PRD 02).
- **COMM-US-07.** (№2) Given смета `sent`, Then расписание: +2 дн если не открыта — «Did you get your estimate?»; +3 дн после первого открытия без решения — сообщение + задача owner «Позвонить: открыл N раз»; +7 дн — напоминание с вариантами («Better option: {recommended_total}»; «от $X/мес» в MVP не используется — финансирование позже и только с раскрытиями лендера); за 2 дня до `expires_at` — «estimate expires on …». Максимум 4 сообщения. Цепочка останавливается при: `approved`, `declined`, `expired`, ответе клиента любым каналом, `Lead.lost`, ручной паузе на смете, новой версии (перезапуск от новой отправки). Каждый шаг виден на смете («следующее касание: чт 10:00 · пропустить · остановить»).
- **COMM-US-08.** Given смета, When `viewed_count` растёт до 3 за 24 ч или клиент открыл смету впервые после 5+ дней тишины, Then push владельцу сметы «Ана Лопес открыла смету EST-0148 ($3,400) 3 раза — позвонить?» с кнопкой звонка; не чаще 1 раза в 24 ч на смету. «Открытие» = загрузка страницы сметы в портале по `PortalAccess` (не email-пиксель; открытия самим подрядчиком не считаются).
- **COMM-US-09.** (№3) Given `Visit.scheduled` с началом > 24 ч, Then за 24 ч (не раньше 8:00 и не позже 21:00 местного времени) уходит напоминание с окном прибытия и ссылкой «перенести»; given визит создан < 24 ч до начала — одно подтверждение сразу. When tech ставит `en_route`, Then уходит «{tech_first_name} from {company_name} is on the way, ETA ~{eta_min} min» (ETA по маршруту; без сети — без ETA), `customer_notified_at` заполнен. Получатели — контакты объекта с флагом уведомлений, иначе primary контакт клиента.
- **COMM-US-10.** (№4) Given инвойс `sent`, `payment_status ∈ {unpaid, partially_paid}`, Then напоминания: в `due_date`, +3, +10 дней; затем задача owner «Позвонить по долгу $X». Не отправляется, если есть `Payment.pending` (ACH в пути) или инвойс `void`. Тон шаблонов вежливый, со ссылкой на оплату (card/ACH).
- **COMM-US-11.** (№5, LEG-12) Given инвойс по работе стал `paid` (или работа `completed` и оплачена на месте), Then через 2 ч (в разрешённые часы получателя) **каждому** клиенту уходит `ReviewRequest(platform=google)` со ссылкой на форму отзыва Google Business Profile компании; одно повторное напоминание через 3 дня, если `clicked_at` пуст. Сообщение — **только** просьба об отзыве: без реферального предложения, скидок, акций и наград (шаблон `review.request` проверяет отсутствие `{referral_link}` и денежных переменных при сохранении). Канал SMS — по транзакционному согласию; является ли запрос отзыва без промо информационным, подтверждает адвокат (§11.1 п. 9), до ответа SMS-вариант запроса отзыва — за настройкой `review_request_sms` (по умолчанию: email, SMS — после ответа юриста). Нет фильтра по оценке/NPS и нет экрана «довольны ли вы?» перед ссылкой; у owner нет настройки «отправлять только довольным». Исключения только: контакт отписан, нет канала, работа `warranty`/`cancelled`, клиенту уже отправляли запрос за 90 дней, **контакт — член команды или родственник** (фильтр: телефон/email совпадает с `User`/`Membership` компании или отметка «член команды» на контакте). Yelp не запрашиваем (правила Yelp запрещают просить отзывы). AI не пишет отзыв за клиента.
- **COMM-US-12.** (№5b, LEG-12) Given клиент, Then у него `Referral.code` и ссылка `octo.app/p/<slug>?ref=<code>` (в портале всегда; в сообщении — **отдельной** маркетинговой автоматизацией `referral_offer`: «Know a neighbor who needs gutters? They get $25 off, you get $50»). Отправка: SMS — только при `sms_marketing_opt_in` (письменное согласие) + проверка National DNC, в маркетинговом окне 9:00–20:00 получателя; email — с ссылкой отписки и физическим адресом (CAN-SPAM); не раньше чем через 3 дня после запроса отзыва и **не зависит** от того, оставил ли клиент отзыв (награда никогда не связана с отзывом, FTC 16 CFR 465). Без маркетингового согласия — только ссылка в портале. When по ссылке создаётся лид, Then `Lead.source=Реферал`, `Referral.new_lead_id`, push owner «Ана привела соседа»; When лид `won` и работа оплачена, Then `Referral.status=reward_due`, задача owner «выдать награду $50»; owner отмечает «выдано» (способ: скидка на следующую работу / gift card / наличные). Награда учитывается как затрата канала «Реферал» в ROI.
- **COMM-US-13.** (Запуск) Given owner, When «Кампания» → сегмент (работы `install`/`cleaning` за последние 6–24 мес., город/ZIP, тег; исключены: с активным `RecurringPlan`, `do_not_service`, без маркетингового согласия для SMS, номера из National DNC без маркетингового согласия, импортированные без нового согласия, члены команды, отписанные от email), Then чек-лист маркетинга с attestation (LEG-10), предпросмотр: число получателей по каналам, стоимость SMS-сегментов, текст EN/ES; отправка пачками в маркетинговом окне 9:00–20:00 по времени каждого получателя; первое SMS кампании содержит CSLB # компании (B&P §7030.5); лиды по ссылке записи получают источник «Повторный клиент» и `campaign_id`.
- **COMM-US-15.** Given наряд `offered` (PRD 07 JOB-US-18), Then ≤ 60 с субподрядчику уходит `work_order.offer` («{company_name}: new work order at {job_address}, {visit_date} {arrival_window}. Open: {work_order_link}») на `Subcontractor.preferred_language`; SMS — если есть номер компании и 10DLC `approved` (B2B-транзакционное сообщение по рабочему наряду; согласие фиксируется при заведении субподрядчика), иначе email. За 24 ч до визита — `work_order.reminder`; при переносе/отмене — `work_order.changed` / `work_order.cancelled`. Шаблоны с `audience = subcontractor` не допускают переменных с деньгами клиента (`{total}`, `{balance}`, `{invoice_link}`, `{estimate_link}`) — сохранение блокируется. Ответ субподрядчика попадает в переписку наряда, push owner. Принятие / отказ / «готово» → push owner. Квиет-часы те же (8:00–21:00 по часовому поясу получателя — по адресу объекта наряда), ручные сообщения сразу.
- **COMM-US-16.** (LEG-10, LEG-13) Given новая компания, Then системные шаблоны согласий и служебных ответов EN/ES из `../legal/legal-research.md` §3.6 созданы как `ConsentText` / `MessageTemplate` с версией и пометкой **«черновик — ждёт утверждения адвокатом»**: A — галочка служебных SMS, B — галочка маркетинга (до 4 сообщений в месяц), C — подтверждение служебных, D — подтверждение маркетинга, E — HELP (с CSLB #), F — STOP, G — скрипт устного согласия (для сотрудника, на языке интерфейса + EN/ES). Переменные `{Company}`, `{license}`, `{phone}`, `{email}`, ссылки `[Terms]`, `[Privacy]` подставляются из `Company` и `PublicProfile`.
  - Given owner правит текст A/B, Then создаётся новая версия; на формах используется новая; все прежние `ConsentRecord` хранят свою версию. Правка **не может** убрать обязательные элементы (имя компании, тип сообщений, частота, «Msg & data rates may apply», STOP/HELP, «Consent is not required to buy» / «not a condition of any purchase», ссылки) — проверка при сохранении.
  - Given текст не утверждён адвокатом (`ConsentText.attorney_approved_at` пусто), Then SMS-автоматизации для реальных клиентов работают только на бете компании основателя с баннером «тексты согласий ждут юриста» (Б3); для платящих клиентов — блок до утверждения.
  - Given `PublicProfile`, Then генерируется публичная страница опт-ина (форма с галочками A/B, SMS Terms, Privacy подрядчика с фразой «Mobile information will not be shared with third parties or affiliates for marketing/promotional purposes») — URL и скриншот идут в анкету 10DLC (LEG-13).
- **COMM-US-14.** Given редактор шаблона SMS, Then счётчик «символов / сегментов» в реальном времени; given текст содержит не-GSM символы (ñ, á, emoji), Then предупреждение «Unicode: 70 символов на сегмент, этот шаблон = 3 сегмента». Перед массовой отправкой — итог сегментов и остаток пакета; если не хватает, отправка email-частью и предложение пакета.

## 7. Бизнес-правила и расчёты
**Каналы и тарифы** (`02a`):
| | Starter | Pro |
|---|---|---|
| Email (SES, fair use) | ✅ все автоматизации | ✅ |
| SMS через Octo | ❌, только пакет $15/мес (номер + 10DLC + 300 сегм.) | ✅ 500 сегм./мес + номер |
| SMS «с моего телефона» | ✅ | ✅ |
| 5 встроенных автоматизаций | ✅ все | ✅ все |
Выбор канала в автоматизации: SMS, если есть номер компании + `approved` 10DLC + согласие контакта + остаток сегментов; иначе email; иначе шаг пропускается с записью в ленте «нет канала».

**Quiet hours (LEG-11):** время считается по **часовому поясу получателя**: (1) адрес объекта сообщения (`Property.address` → tz), (2) иначе адрес клиента, (3) иначе по коду номера телефона (area code → tz), (4) иначе `Company.timezone`. Окна: **8:00–21:00** — информационные автоматические сообщения; **9:00–20:00** — маркетинг (с запасом от §64.1200(c)(1)). Сообщение вне окна ставится на начало следующего окна получателя. Ручные сообщения и «В пути» отправляются сразу (инициирует человек), но вне 8:00–21:00 получателя — предупреждение «у клиента сейчас 21:40». Номер с area code другого штата и объект в CA — берётся tz объекта, но если они расходятся больше чем на 1 ч, применяется **пересечение** окон (самое строгое). Определённая tz пишется в `Message.recipient_timezone`.

**Согласия (по `../legal/legal-research.md` §3.4):**
| Сообщение | Категория | Нужное согласие |
|---|---|---|
| №1 «Получили заявку», смета, №3 напоминание о визите и «в пути», №4 инвойс, квитанция | Информационное | `sms_opt_in` (prior express consent) |
| Ответ на входящее SMS клиента | Conversational | Сам факт входящего |
| Наряд субподрядчику | Информационное (B2B) | Согласие субподрядчика в карточке / при принятии наряда (`ConsentRecord`) |
| №2 дожим неподписанной сметы | Серая зона [Проверить, §11.1 п. 10] | `sms_opt_in`; текст **без** скидок и акций (проверка шаблона при сохранении) |
| №5 запрос отзыва (без промо) | Серая зона [§11.1 п. 9] | `sms_opt_in`; SMS-канал — за настройкой до ответа адвоката, по умолчанию email |
| №5b реферальное предложение, кампании, реактивация, сезонные напоминания о чистке | **Маркетинг** | `sms_marketing_opt_in` (письменное, E-SIGN) + проверка National DNC |
Email: транзакционные всегда; маркетинговые — с ссылкой отписки и физическим адресом компании (CAN-SPAM), `email_unsubscribed_at` блокирует маркетинг. Включение любой маркетинговой автоматизации или кампании — модальное окно-чек-лист (маркетинговое согласие, DNC, часы, STOP) с attestation → AuditLog (§9.4 исследования). Чем больше Octo делает «по умолчанию», тем выше риск Octo как «initiator» по TCPA (§11.1 п. 11): маркетинговые автоматизации **выключены** по умолчанию.

**Email-адреса:** отправитель `"{Company} <{slug}@mail.octo.app>"` (SPF/DKIM/DMARC на нашем домене), `Reply-To: reply+{thread_token}@in.octo.app` → ответ попадает в переписку и копией на email компании. Свой домен отправителя — позже.

**Сегменты SMS:** GSM-7 — 160 символов (153 в составном), UCS-2 — 70 (67). `Message.segments` считаем до отправки; списываем по факту из `UsageCounter.sms_segments_used`. Пакет исчерпан → SMS-шаги автоматизаций переходят на email, ручная SMS блокируется (PRD 01).

**Запуск автоматизаций:** каждая автоматизация = набор `ScheduledMessage` с `automation_key`, `subject`, `step`, `scheduled_at`; при событии-стопе отменяются все будущие шаги по subject. Идемпотентность: ключ `automation_key + subject_id + step` — один шаг не уходит дважды (повтор события, ретрай воркера).

**Отзывы (FTC 16 CFR 465, правила Google):** запрос всем без отбора по удовлетворённости; нельзя предлагать награду за отзыв; реферальное предложение — **отдельное маркетинговое сообщение**, награда не связана с отзывом (LEG-12); запрос не отправляется членам команды и родственникам; ответы на негатив — вручную (AI-черновик позже).

**Реферал:** награда задаётся компанией (по умолчанию $50 рефереру / $25 скидка новому); статус `Referral`: `lead_created → reward_due → reward_paid` / `void` (лид lost/дубль/уже был клиентом); ссылка — `Customer.referral_code`.

## 9. Офлайн
- Ручные сообщения и «В пути» без сети ставятся в outbox (`queued`) и уходят при появлении сети; если «В пути» задержалось > 30 мин, при отправке спрашиваем «ещё актуально?».
- SMS «с моего телефона» работает без интернета (через сотовую сеть).
- Автоматизации работают на сервере и от сети телефона не зависят.
- Чтение переписки — из локального кэша (последние 100 сообщений на клиента).

## 11. Ошибки и крайние случаи
- **Двойное нажатие «Отправить»** — `idempotency_key` на сообщение; повтор не создаёт второе.
- **SMS `failed`** (номер стационарный/неверный) — пометка на контакте «SMS не доставляются», дальше автоматизации шлют email.
- **10DLC отклонён** — показываем причину TCR и что исправить; SMS не работают, email работает; повторная подача платная — предупреждаем.
- **Клиент ответил «STOP» на «В пути»** — отписка действует немедленно; бригаде в визите видно «клиент отписан от SMS».
- **«Не пишите мне больше» без ключевого слова** — пометка «возможный отзыв», SMS на номер на паузе, Task подтвердить ≤ 10 рабочих дней (по умолчанию сегодня).
- **Импортированный номер без согласия** — SMS-шаги автоматизаций пропускаются с записью «нет согласия», уходит email; в карточке кнопка «Запросить согласие» (email/портал-ссылка с галочкой A).
- **Часовой пояс получателя не определён** — берётся `Company.timezone`, в `Message.recipient_timezone` пометка `fallback`.
- **Номер стал чужим (reassigned)** — при ответе «wrong number» отзыв и пометка `sms_undeliverable` [проверка по Reassigned Numbers Database — позже].
- **Клиент отвечает на автоматическое сообщение вопросом** — цепочка дожима останавливается, push owner, Activity.
- **Смета переотправлена новой версией** — старая цепочка отменяется, новая стартует от новой отправки; счётчик касаний не превышает 4 за 14 дней.
- **Визит перенесён после отправки напоминания** — новое напоминание с пометкой «новое время», старое не повторяется.
- **Испанский шаблон отсутствует после правки EN** — ES остаётся прошлой версией; предупреждение «ES-версия не обновлена».
- **Два контакта с одним телефоном (муж/жена)** — одно сообщение на номер, не два.
- **Пауза аккаунта** (PRD 01) — все автоматизации остановлены, кроме №4 (напоминания по уже выставленным инвойсам — деньги подрядчика).
- **Нет прав** — tech не видит переписку по чужим работам и не может запустить кампанию.
