# PRD 13. Коммуникации и автоматизации

> Статус: черновик v0.1, ноябрь 2026. Сущности: `MessageThread`, `Message`, `Contact` (согласия), `ReviewRequest`, `Referral`, `Task`, `Activity`, `Entitlement`/`UsageCounter` (`../04-domain-model.md` §2, §7, §8).
> Колонки: **MVP** = бета на компании основателя · **Запуск** = до первых платящих · **Позже**.
> Юридические пункты (TCPA, 10DLC, CAN-SPAM, FTC 16 CFR 465) перед запуском проверяет юрист.

## 1. Назначение
Автоматически сказать клиенту нужное в нужный момент — «получили заявку», «смета ждёт», «завтра приедем», «мы в пути», «счёт к оплате», «оставьте отзыв», «приведите соседа» — по SMS или email на его языке, законно и без ручной работы владельца. В MVP — 5 встроенных автоматизаций с настройками, без конструктора.

## 2. Как это приносит деньги подрядчику (`money_impact`)
| Автоматизация / функция | Эффект |
|---|---|
| №1 Мгновенный ответ на лид | Клиент с сайта/портала получает ответ за секунды, пока владелец на лестнице; выше шанс, что не позвонит следующему подрядчику |
| №2 Дожим сметы + сигнал «открыл 3 раза» | Возвращает часть зависших смет (рынок: 10–20%); владелец звонит в момент интереса, а не через неделю |
| №3 Напоминание о визите и «В пути» | Меньше no-show и «никого нет дома» = меньше холостых выездов бригады |
| №4 Напоминание об оплате | Деньги приходят раньше, меньше дебиторки 30+ дней без звонков «а вы заплатите?» |
| №5 Отзыв всем + реферальная ссылка | Больше отзывов в Google → выше в local pack → бесплатные лиды вместо Thumbtack; рефералка = лид за цену награды |
| Сезонная кампания чистки (Запуск) | Прошлые клиенты в сентябре–октябре (перед дождями) = повторная выручка без рекламы |
| SMS «с моего телефона» на Starter | Бесплатная альтернатива платным SMS: шаблон открывается в Messages iPhone |
| Законность (opt-in, STOP, quiet hours, без review gating) | Нет штрафов TCPA ($500–1,500 за сообщение) и FTC (~$51k за нарушение) |

## 3. Пользователи и роли
- **Owner/Admin** — включают и настраивают автоматизации, шаблоны, SMS-номер, 10DLC, кампании.
- **Office** — переписка, ручные сообщения, запуск дожима.
- **Tech** — «В пути», сообщения клиенту по своим визитам (по шаблонам), видит переписку только по своим работам.
- **Клиент** — получает сообщения, отвечает, отписывается (STOP / unsubscribe).

## 4. User stories
| ID | Story |
|---|---|
| COMM-US-01 | Как владелец, я хочу переписку SMS и email с клиентом в одной ленте внутри карточки, чтобы не искать в личном телефоне |
| COMM-US-02 | Как владелец на Starter, я хочу отправить шаблон «через мой телефон» (Messages iPhone), чтобы общаться по SMS без платного пакета |
| COMM-US-03 | Как владелец на Pro, я хочу бизнес-номер с местным кодом (818/323/310/626) и пройти 10DLC за меня по анкете, чтобы SMS доставлялись |
| COMM-US-04 | Как владелец, я хочу фиксировать согласие клиента на SMS (источник, дата, текст), чтобы соблюдать TCPA |
| COMM-US-05 | Как владелец, я хочу шаблоны на английском и испанском, которые подставляются по языку контакта, чтобы клиент понимал сообщение |
| COMM-US-06 | Как владелец, я хочу, чтобы заявка с сайта/портала получала мгновенный ответ (№1), чтобы клиент не ушёл к другому |
| COMM-US-07 | Как владелец, я хочу автоматический дожим отправленной сметы (№2), который останавливается при ответе, одобрении или отказе |
| COMM-US-08 | Как владелец, я хочу push «клиент открыл смету 3 раза — позвони», чтобы звонить в момент интереса |
| COMM-US-09 | Как владелец, я хочу напоминание о визите за день и «В пути» с ETA по тапу монтажника (№3), чтобы клиент был дома |
| COMM-US-10 | Как владелец, я хочу автоматические напоминания о неоплаченном инвойсе (№4), чтобы не звонить самому |
| COMM-US-11 | Как владелец, я хочу автоматический запрос отзыва в Google **каждому** клиенту после оплаты (№5), чтобы расти в поиске законно |
| COMM-US-12 | Как владелец, я хочу дать клиенту личную реферальную ссылку и видеть, кого он привёл и какую награду я должен, чтобы получать дешёвые лиды |
| COMM-US-13 | Как владелец, я хочу в сентябре разослать прошлым клиентам предложение чистки перед дождями со ссылкой на запись, чтобы заполнить октябрь |
| COMM-US-14 | Как владелец, я хочу видеть, сколько SMS-сегментов стоит шаблон и сколько осталось в пакете, чтобы не удивляться |

## 5. Критерии приёмки
- **COMM-US-01.** Given клиент, Then вкладка «Переписка» показывает `MessageThread` по каналам SMS/email/portal с статусами `queued → sent → delivered / failed`; входящее SMS/email-ответ появляется ≤ 30 с и даёт push назначенному на клиента/лид (по умолчанию owner). Given входящее SMS с неизвестного номера, Then создаётся `Lead(status=new, parse_status=needs_review)` с текстом сообщения.
- **COMM-US-02.** Given Starter без SMS-пакета, When «SMS» в карточке, Then открывается системный композер iOS с номером контакта и текстом шаблона; в ленту пишется `Activity(kind=sms_external)` «отправлено с личного телефона (не подтверждено)». Автоматизации на Starter используют email; шаги «только SMS» пропускаются.
- **COMM-US-03.** Given Pro или SMS-пакет, When owner заполняет анкету (юр. имя, EIN или sole proprietor, адрес, сайт или `PublicProfile`, примеры сообщений), Then Octo регистрирует Brand и Campaign в TCR через Twilio (ISV), покупает номер в выбранном area code; статус виден («на проверке, обычно 1–4 недели»). Given статус не `approved`, Then отправка SMS недоступна, всё уходит email.
- **COMM-US-04.** Given контакт, Then у него `sms_opt_in` (транзакционные) и `sms_marketing_opt_in` (маркетинг) с датой, источником (`web_form`, `portal`, `verbal_recorded_by_user`, `customer_texted_first`, `import`) и версией текста согласия. Given чекбокс на форме сайта/портала, Then согласие пишется автоматически с IP. Given первое SMS на номер, Then в конце «Reply STOP to opt out» / «Responda STOP para cancelar». Given входящее STOP/UNSUBSCRIBE/CANCEL/END/QUIT/ALTO, Then оба флага `false`, `sms_opted_out_at`, одно подтверждение отписки, дальше любые SMS этому номеру блокируются на уровне сервера; START возвращает транзакционное согласие.
- **COMM-US-05.** Given шаблон с ключом (например `estimate.followup.1`), Then есть системные версии EN и ES; owner может править текст (переменные `{first_name}`, `{company_name}`, `{estimate_link}`, `{total}`, `{monthly}`, `{visit_date}`, `{arrival_window}`, `{eta_min}`, `{invoice_link}`, `{balance}`, `{review_link}`, `{referral_link}`); язык = `Contact.preferred_language`, нет ES-версии → EN. Отправка с неразрешённой переменной блокируется с ошибкой в предпросмотре.
- **COMM-US-06.** (№1) Given лид с сайта/портала/ручной лид с отметкой «отправить приветствие», имеющий телефон с согласием или email, When лид создан, Then ≤ 60 с уходит «Thanks {first_name}, we got your request — {company_name} will call you within {N} min. Book an inspection now: {booking_link}» и создаётся задача «Перезвонить» (если нет `first_response_at` через N мин). Автоответ не считается `first_response_at`. Лиды из маркетплейсов (email-пересылка) не получают автоответ (ответ идёт в площадке, PRD 02).
- **COMM-US-07.** (№2) Given смета `sent`, Then расписание: +2 дн если не открыта — «Did you get your estimate?»; +3 дн после первого открытия без решения — сообщение + задача owner «Позвонить: открыл N раз»; +7 дн — напоминание с вариантами («Better from {monthly}/mo»); за 2 дня до `expires_at` — «estimate expires on …». Максимум 4 сообщения. Цепочка останавливается при: `approved`, `declined`, `expired`, ответе клиента любым каналом, `Lead.lost`, ручной паузе на смете, новой версии (перезапуск от новой отправки). Каждый шаг виден на смете («следующее касание: чт 10:00 · пропустить · остановить»).
- **COMM-US-08.** Given смета, When `viewed_count` растёт до 3 за 24 ч или клиент открыл смету впервые после 5+ дней тишины, Then push владельцу сметы «Ана Лопес открыла смету EST-0148 ($3,400) 3 раза — позвонить?» с кнопкой звонка; не чаще 1 раза в 24 ч на смету. «Открытие» = загрузка страницы сметы в портале по `PortalAccess` (не email-пиксель; открытия самим подрядчиком не считаются).
- **COMM-US-09.** (№3) Given `Visit.scheduled` с началом > 24 ч, Then за 24 ч (не раньше 8:00 и не позже 21:00 местного времени) уходит напоминание с окном прибытия и ссылкой «перенести»; given визит создан < 24 ч до начала — одно подтверждение сразу. When tech ставит `en_route`, Then уходит «{tech_first_name} from {company_name} is on the way, ETA ~{eta_min} min» (ETA по маршруту; без сети — без ETA), `customer_notified_at` заполнен. Получатели — контакты объекта с флагом уведомлений, иначе primary контакт клиента.
- **COMM-US-10.** (№4) Given инвойс `sent`, `payment_status ∈ {unpaid, partially_paid}`, Then напоминания: в `due_date`, +3, +10 дней; затем задача owner «Позвонить по долгу $X». Не отправляется, если есть `Payment.pending` (ACH в пути) или инвойс `void`. Тон шаблонов вежливый, со ссылкой на оплату (card/ACH).
- **COMM-US-11.** (№5) Given инвойс по работе стал `paid` (или работа `completed` и оплачена на месте), Then через 2 ч (в разрешённые часы) **каждому** клиенту уходит `ReviewRequest(platform=google)` со ссылкой на форму отзыва Google Business Profile компании; одно повторное напоминание через 3 дня, если `clicked_at` пуст. Нет фильтра по оценке/NPS и нет экрана «довольны ли вы?» перед ссылкой; у owner нет настройки «отправлять только довольным». Исключения только: контакт отписан, нет канала, работа `warranty`/`cancelled`, клиенту уже отправляли запрос за 90 дней. Yelp не запрашиваем (правила Yelp запрещают просить отзывы).
- **COMM-US-12.** Given клиент, Then у него `Referral.code` и ссылка `octo.app/p/<slug>?ref=<code>` (в портале и в сообщении №5: «Know a neighbor who needs gutters? They get $25 off, you get $50»); When по ссылке создаётся лид, Then `Lead.source=Реферал`, `Referral.new_lead_id`, push owner «Ана привела соседа»; When лид `won` и работа оплачена, Then `Referral.status=reward_due`, задача owner «выдать награду $50»; owner отмечает «выдано» (способ: скидка на следующую работу / gift card / наличные). Награда учитывается как затрата канала «Реферал» в ROI.
- **COMM-US-13.** (Запуск) Given owner, When «Кампания» → сегмент (работы `install`/`cleaning` за последние 6–24 мес., город/ZIP, тег; исключены: с активным `RecurringPlan`, `do_not_service`, без маркетингового согласия для SMS, отписанные от email), Then предпросмотр: число получателей по каналам, стоимость SMS-сегментов, текст EN/ES; отправка пачками в разрешённые часы; лиды по ссылке записи получают источник «Повторный клиент» и `campaign_id`.
- **COMM-US-14.** Given редактор шаблона SMS, Then счётчик «символов / сегментов» в реальном времени; given текст содержит не-GSM символы (ñ, á, emoji), Then предупреждение «Unicode: 70 символов на сегмент, этот шаблон = 3 сегмента». Перед массовой отправкой — итог сегментов и остаток пакета; если не хватает, отправка email-частью и предложение пакета.

## 7. Бизнес-правила и расчёты
**Каналы и тарифы** (`02a`):
| | Starter | Pro |
|---|---|---|
| Email (SES, fair use) | ✅ все автоматизации | ✅ |
| SMS через Octo | ❌, только пакет $15/мес (номер + 10DLC + 300 сегм.) | ✅ 500 сегм./мес + номер |
| SMS «с моего телефона» | ✅ | ✅ |
| 5 встроенных автоматизаций | ✅ все | ✅ все |
Выбор канала в автоматизации: SMS, если есть номер компании + `approved` 10DLC + согласие контакта + остаток сегментов; иначе email; иначе шаг пропускается с записью в ленте «нет канала».

**Quiet hours:** автоматические сообщения только 8:00–21:00 по времени объекта (по умолчанию `Company.timezone`); иначе ставятся на 8:00. Ручные сообщения и «В пути» отправляются сразу (инициирует человек), но после 21:00 — предупреждение.

**Согласия:** транзакционные SMS (смета, визит, инвойс, «в пути», отзыв по своей работе) — по `sms_opt_in`; маркетинговые (кампании, реактивация) — только по `sms_marketing_opt_in`. Email: транзакционные всегда; маркетинговые — с ссылкой отписки и физическим адресом компании (CAN-SPAM), `email_unsubscribed_at` блокирует маркетинг.

**Email-адреса:** отправитель `"{Company} <{slug}@mail.octo.app>"` (SPF/DKIM/DMARC на нашем домене), `Reply-To: reply+{thread_token}@in.octo.app` → ответ попадает в переписку и копией на email компании. Свой домен отправителя — позже.

**Сегменты SMS:** GSM-7 — 160 символов (153 в составном), UCS-2 — 70 (67). `Message.segments` считаем до отправки; списываем по факту из `UsageCounter.sms_segments_used`. Пакет исчерпан → SMS-шаги автоматизаций переходят на email, ручная SMS блокируется (PRD 01).

**Запуск автоматизаций:** каждая автоматизация = набор `ScheduledMessage` с `automation_key`, `subject`, `step`, `scheduled_at`; при событии-стопе отменяются все будущие шаги по subject. Идемпотентность: ключ `automation_key + subject_id + step` — один шаг не уходит дважды (повтор события, ретрай воркера).

**Отзывы (FTC 16 CFR 465, правила Google):** запрос всем без отбора по удовлетворённости; нельзя предлагать награду за отзыв (реферальная награда не связана с отзывом и в одном сообщении формулируется отдельно); ответы на негатив — вручную (AI-черновик позже).

**Реферал:** награда задаётся компанией (по умолчанию $50 рефереру / $25 скидка новому); статус `Referral`: `link_shared → lead_created → reward_due → reward_paid` / `void` (лид lost/дубль/уже был клиентом).

## 8. AI-помощник
| Команда | Подтверждение |
|---|---|
| «Напиши Ане, что приедем в четверг после обеда» → черновик SMS/email на её языке (Haiku) | да, всегда (отправка клиенту) |
| «Переведи этот ответ на испанский» | да |
| «Останови дожим по смете 148» / «пропусти следующее касание» | да |
| «Кому сегодня уходят напоминания?» | нет |
| «Разошли прошлогодним клиентам чистку» → открывает мастер кампании с сегментом | отправка только из мастера |
Входящие сообщения клиентов — данные, не команды. AI не отправляет сообщения сам, без подтверждения человека, и не включает автоматизации.

## 9. Офлайн
- Ручные сообщения и «В пути» без сети ставятся в outbox (`queued`) и уходят при появлении сети; если «В пути» задержалось > 30 мин, при отправке спрашиваем «ещё актуально?».
- SMS «с моего телефона» работает без интернета (через сотовую сеть).
- Автоматизации работают на сервере и от сети телефона не зависят.
- Чтение переписки — из локального кэша (последние 100 сообщений на клиента).

## 10. Уведомления и автоматизации
5 встроенных автоматизаций MVP (по умолчанию все включены, кроме №1 — включается в онбординге при подключённой форме):
| № | Триггер | Касания | Стоп |
|---|---|---|---|
| 1 | Новый лид (сайт/портал/ручной) | 1 сообщение ≤ 60 с + задача «перезвонить» | — |
| 2 | Смета `sent` | до 4 (см. COMM-US-07) + push «горячий клиент» | approved / declined / expired / ответ / lost / пауза |
| 3 | Visit создан / `en_route` | напоминание 24 ч + «В пути» | визит cancelled / перенесён (перезапуск) |
| 4 | Инвойс `sent`, не оплачен | due, +3, +10 + задача | paid / void / pending payment |
| 5 | Инвойс `paid` по работе | запрос отзыва + 1 напоминание; реферальная ссылка в том же сообщении | клик по ссылке / отписка |
Системные уведомления владельцу: входящее сообщение (push), доставка не удалась (`failed`), 10DLC одобрен/отклонён, 80%/100% SMS (PRD 01).

## 11. Ошибки и крайние случаи
- **Двойное нажатие «Отправить»** — `idempotency_key` на сообщение; повтор не создаёт второе.
- **SMS `failed`** (номер стационарный/неверный) — пометка на контакте «SMS не доставляются», дальше автоматизации шлют email.
- **10DLC отклонён** — показываем причину TCR и что исправить; SMS не работают, email работает; повторная подача платная — предупреждаем.
- **Клиент ответил «STOP» на «В пути»** — отписка действует немедленно; бригаде в визите видно «клиент отписан от SMS».
- **Клиент отвечает на автоматическое сообщение вопросом** — цепочка дожима останавливается, push owner, Activity.
- **Смета переотправлена новой версией** — старая цепочка отменяется, новая стартует от новой отправки; счётчик касаний не превышает 4 за 14 дней.
- **Визит перенесён после отправки напоминания** — новое напоминание с пометкой «новое время», старое не повторяется.
- **Испанский шаблон отсутствует после правки EN** — ES остаётся прошлой версией; предупреждение «ES-версия не обновлена».
- **Два контакта с одним телефоном (муж/жена)** — одно сообщение на номер, не два.
- **Пауза аккаунта** (PRD 01) — все автоматизации остановлены, кроме №4 (напоминания по уже выставленным инвойсам — деньги подрядчика).
- **Нет прав** — tech не видит переписку по чужим работам и не может запустить кампанию.

## 14. Изменения модели данных
- Новая `MessageTemplate`: `company_id` (null = системный), `key`, `channel (sms/email)`, `locale (en/es)`, `subject`, `body`, `is_system`, `updated_by`.
- Новая `AutomationSetting`: `company_id`, `automation_key` (`lead_instant_reply`, `estimate_followup`, `visit_reminders`, `invoice_reminders`, `review_referral`), `enabled`, `params json` (тайминги, каналы, N минут).
- Новая `ScheduledMessage`: `company_id`, `automation_key`, `subject_type/id`, `step`, `scheduled_at`, `status (scheduled → sent / skipped / cancelled)`, `cancel_reason`, `message_id`, unique (`automation_key`, `subject_id`, `step`).
- Новая `Campaign` (Запуск): `company_id`, `name`, `segment json`, `channels`, `template_keys`, `status (draft → sending → sent)`, `recipients_count`, `sent_at`; `Lead.campaign_id`.
- `Contact`: + `sms_marketing_opt_in` (+дата), `consent_source`, `consent_text_version`, `consent_ip`, `sms_opted_out_at`, `email_unsubscribed_at`, `sms_undeliverable bool`.
- `Company`: + `sms_number`, `a2p_brand_status`, `a2p_campaign_status` (`not_started/pending/approved/rejected`), `google_review_url` (или GBP place id), `referral_reward json`.
- `Message`: + `segments`, `cost_cents`, `template_key`, `automation_key`, `idempotency_key`, `sent_via (octo/own_phone)`.
- `ReviewRequest`: + `invoice_id`, `reminder_sent_at`. `platform` в MVP только `google`.
- `Referral`: + `status` (§7), `reward_due_cents`, `reward_paid_at`, `reward_method`.

## 15. Открытые вопросы
1. Юрист: достаточно ли согласия «клиент дал номер для сервиса» для транзакционных SMS; формулировка чекбокса на форме; текущий статус правил FCC one-to-one consent.
2. 10DLC через ISV: кто платит регистрацию ($4 + $15 разово) — включаем в пакет или отдельной строкой; что делать с sole proprietor без EIN (лимиты Sole Prop brand).
3. Размер реферальной награды по умолчанию у основателя ($50/$25?) и допустим ли «кредит на следующую чистку» как основной способ.
4. Нужна ли автоматизация №1 для лидов маркетплейсов, если в письме есть реальный телефон (риск нарушить правила площадки)?
5. Отправлять ли запрос отзыва после оплаты или после `completed` (основатель часто получает оплату чеком через неделю)?
6. Pricing `02a` («Автоматизации: Starter 5, Pro без лимита») — убрать, пока нет конструктора (см. PRD 01 §15.6).
