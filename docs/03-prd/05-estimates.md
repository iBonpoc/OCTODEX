# 05. Сметы: версии, Good/Better/Best, одобрение, change orders

> Статус: черновик v0.1, ноябрь 2026. Сущности: `Estimate`, `EstimateVersion`, `EstimateOption`, `EstimateLineItem`, `EstimateApproval`, `ChangeOrder`, `PortalAccess`, `Job`, `Invoice` (`../04-domain-model.md` §4, §9). Связанные модули: `04-catalog-suppliers.md`, `06-gutters-module.md`, `09-invoices-payments.md`, `11-purchase-orders.md`, `12-portal-public-page.md`, `13-communications-automations.md`, `15-ai-assistant.md`, `19-taxes.md` (налоговые профили и налог при покупке, решение основателя 03.11.2026).
> **v0.1.1 (03.11.2026): внесены требования юридического исследования** `../legal/legal-research.md` (LEG-01…LEG-08, LEG-16): тип договора, CA-шаблон с заблокированными блоками, отдельное согласие E-SIGN, подпись подрядчика (countersign), доставка полностью подписанной копии, срок отказа как настраиваемые правила, бумажная Notice of Cancellation. Это **не юридическая консультация**: тексты шаблонов и согласий попадают к клиентам только после утверждения адвокатом CA (`../legal/README.md` п. 5).

## 1. Назначение
Превратить замер или параметры в профессиональную смету с вариантами, отправить её клиенту, получить подпись и депозит и без повторного ввода создать работу. Смета — главный документ денег: всё, что видит и подписывает клиент, фиксируется неизменяемой версией.

## 2. Как это приносит деньги подрядчику (`money_impact`)
| Механизм | Эффект (гипотеза, проверяем на бете) |
|---|---|
| Смета у клиента дома за < 5 мин вместо «пришлю вечером» | Выше close rate: подписи в тот же день (Leap SalesPro как ориентир) |
| Good/Better/Best с рекомендуемым вариантом | Средний чек выше: в примере `06` §7.9 Better $3,215.75 против Good $2,816.75 (+14%), Best $5,028.75 (+79%) |
| Optional add-ons (guards, extensions) отмечает сам клиент | Upsell без давления, +$X на смете одним тапом |
| Маржа по каждому варианту видна владельцу до отправки | Нет убыточных смет «на глаз» |
| Трекинг открытий + дожим (`13`) | Возврат 10–20% зависших смет |
| Депозит при подписи (в CA — не больше 10% или $1,000, что меньше; в Service & Repair — без депозита) + оплата по этапам | Кэшфлоу на материалы законным способом: «депозит до $1,000 + оплата после доставки материалов и после монтажа» (LEG-06) |
| Change orders с подписью | Доп. работы (fascia, лишний downspout) оплачиваются, а не «делаем бесплатно, чтобы не спорить» |
| Идемпотентная конверсия в работу | Нет двойных работ и двойных PO (дубль coil-заказа = замороженные $300–800) |

## 3. Пользователи и роли
| Роль | Возможности |
|---|---|
| owner, admin | Всё, включая маржу, настройки, переопределение порога маржи, продление срока; включение автоподписи компании (только owner) |
| Пользователь с правом `sign_contracts` | Подписывает договор от имени подрядчика (countersign, LEG-03). По умолчанию право есть у owner; owner выдаёт его admin/office точечно (`permissions_override`) |
| office | Создание, отправка, маржа, change orders |
| sales | Создание и отправка. Себестоимость и маржа по настройке (`can_view_cost`) |
| tech | Только черновик (без отправки), без себестоимости и маржи; видит BOM-количества для загрузки машины |
| subcontractor | Нет доступа |
| Клиент (не пользователь) | Портал: просмотр отправленной версии, выбор варианта и add-ons, подпись, депозит |

## 5. Критерии приёмки
**EST-US-01**
- Given выбран клиент без объекта, When создаётся смета, Then требуется выбрать или создать объект (`property_id` обязателен).
- Given добавлена позиция каталога, When цена каталога позже меняется, Then `unit_price_cents` строки не меняется.
- Given свободная строка без `catalog_item_id`, When сохраняется, Then обязательны name, quantity, unit, price; себестоимость по умолчанию 0 с пометкой «себестоимость не указана» в марже.
- Given создана смета, When сохранена, Then номер `EST-NNNN` из счётчика компании, статус `draft`, версия 1.
- Given на объекте уже есть открытая смета или работа, When создаётся новая смета на тот же объект, Then создание не блокируется; в шапке подсказка «На объекте ещё: EST-0140 (sent), JOB-0210 (in_progress)» со ссылками (у объекта может быть сколько угодно смет одновременно, решение основателя).

**EST-US-02**
- Given шаблон (`EstimateTemplate`) с 2 вариантами и текстами, When создаётся смета, Then копируются варианты, строки (цены из **текущего** каталога), intro/scope/terms/exclusions, правило депозита.

**EST-US-03** — см. `06-gutters-module.md` §5 (GUT-US-10..12). Здесь: Given расчёт из чертежа, When создана версия, Then в версии сохранены `drawing_id`, `drawing_version`, `calc_inputs`, `engine_version`.

**EST-US-04**
- Given копируется смета EST-0120, When выбран новый объект, Then количества и структура копируются, цены по умолчанию берутся из текущего каталога; показан diff «цены изменились: 4 строки, итого +$62.00»; переключатель «оставить старые цены».
- Given у исходной сметы был чертёж, When копируется на другой объект, Then чертёж не копируется (другой дом), строки остаются ручными.

**EST-US-06**
- Given 3 варианта, When один отмечен рекомендуемым, Then только один `is_recommended = true`.
- Given вариант без строк, When отправка, Then отправка заблокирована «вариант Best пуст».
- Given > 3 вариантов, When добавляет четвёртый, Then запрещено в MVP (максимум 3).

**EST-US-07**
- Given строка `is_optional = true`, When считаются итоги, Then она не входит в total варианта; клиент видит «+$2,100.00» и переключатель.
- Given клиент включил add-on и подписал, When создаётся `EstimateApproval`, Then `selected_optional_items` содержит id строки, итог одобрения включает её.

**EST-US-08**
- Given строка `client_visible = false`, When клиент открывает портал или PDF, Then строки нет ни в HTML, ни в API-ответе портала (фильтр на сервере).
- Given скрытая строка с `unit_price_cents > 0`, When сохраняется, Then ошибка: «скрытые строки не могут иметь цену» (правило честной цены).

**EST-US-09**
- Given роль tech, When открывает смету, Then полей cost/margin нет в ответе API.
- Given маржа варианта 28% при пороге 35%, When sales нажимает «Отправить», Then предупреждение; sales не может отправить без разрешения owner/admin (настройка `margin_override_role`), owner может с подтверждением, факт пишется в AuditLog.

**EST-US-10** — см. тест-кейсы T4, T5, T9, T12.
- Given скидка 10%, When клиент видит смету, Then строка «Скидка 10%: −$239.00» внизу варианта.

**EST-US-11** — см. T8, `18` §L (D1–D4).
- Given компания в CA и тип договора `ca_home_improvement`, When правило депозита 50%, Then депозит = min(50%, 10% и $1,000) и показано предупреждение о лимите. Лимит действует для **всех** жилых HIC в CA, а не только от $500 (LEG-06; применимость к договорам ≤ $500 — вопрос адвокату §11.1 п. 5). Owner может отключить лимит только attestation-галочкой «Подтверждаю, что у меня есть bond по B&P §7159.5(a)(8)» (тип bond, номер, файл → AuditLog).
- Given тип договора `ca_service_repair`, When задаётся правило депозита (в т.ч. из шаблона), Then депозит = $0, поле депозита недоступно с подсказкой «В Service & Repair оплата только после завершения работы (B&P §7159.10)»; депозитный и progress-инвойс по этой работе создать нельзя (`09`).
- Given CA HIC, Then в смете обязателен **график прогресс-платежей** (`payment_schedule`): каждая выплата в $ привязана к этапу работ («после доставки материалов», «после монтажа гаттеров», «после финальной приёмки»); сумма депозита + этапов = цена договора; график печатается в договоре (блок 8 §7.7.3).

**EST-US-13**
- Given смета в draft, When нажимается «Отправить», Then (1) текущая версия блокируется (`locked_at`), (2) `sent_version_id` = эта версия, (3) создаётся `PortalAccess` со scope одного документа, (4) генерируется PDF с хэшем, (5) статус `sent`, (6) сообщение уходит в очередь. Всё по `idempotency_key`.
- Given двойное нажатие, When второй запрос, Then второго сообщения и второй PortalAccess нет.
- Given нет сети, When «Отправить», Then действие в outbox «отправится при появлении сети», статус остаётся `draft` до подтверждения сервера.
- Given у контакта нет `sms_opt_in`, When выбран SMS, Then SMS недоступен, предлагается email или «показать QR / скопировать ссылку».
- Given в смете строки с тестовыми ценами (`is_placeholder_price`), When «Отправить», Then предупреждение «N строк с тестовыми ценами» (не блокирует, `04` CAT-US-22).

**EST-US-14**
- Given клиент открыл ссылку впервые, When страница загрузилась, Then статус `sent → viewed`, `viewed_count = 1`, Activity «открыл смету», push владельцу сметы.
- Given ссылку открыл участник компании, авторизованный в Octo, When открывает, Then просмотр не считается.
- Given 3-е открытие за 48 ч без подписи, When происходит, Then задача «Позвонить: Yuri открыл смету 3 раза» (`13`).

**EST-US-15**
- Given клиент в портале, When подписывает, Then обязательны: выбор варианта, имя, подпись и действующее согласие E-SIGN (EST-US-26). Для CA HIC на экране подписи ещё: вопрос «Есть ли среди собственников человек 65 лет и старше?» (Да / Нет / Не хочу отвечать) и инициалы у уведомления о праве отказа (блок 17 §7.7.3).
- Given подпись принята, When сохраняется, Then `EstimateApproval` содержит signer_name, signature_file_id, signed_at, ip, user_agent, `document_hash` версии, `esign_consent_id`, `owner_65_plus`; статус сметы `awaiting_countersign` (если для типа договора нужна подпись подрядчика и автоподпись выключена) или сразу `approved` после автоподписи (EST-US-27). Клиенту сразу уходит PDF **полностью подписанного** договора (EST-US-28); PDF только с подписью клиента клиенту как «договор» не отправляется.
- Given версия истекла (`expires_at` прошла), When клиент открывает, Then подписать нельзя, кнопка «Запросить обновлённую смету» создаёт задачу.
- Given после подписи есть правило депозита, договор исполнен (подписан обеими сторонами) и Stripe подключён, Then открывается оплата депозита (`09`); подпись действительна и без оплаты, депозит остаётся инвойсом `deposit`. Given ждём ручную подпись подрядчика, Then клиент видит «Договор подписан вами, ждёт подписи {company_name}; копию пришлём на email», оплата депозита — после countersign.

**EST-US-16**
- Given подпись на устройстве (in_person), Then экран согласия E-SIGN показывается клиенту так же, как в портале; email для доставки копии обязателен или выбирается «только бумага» (тогда печать договора и Notice of Cancellation — EST-US-29).
- Given iPad без сети, When клиент подписывает на устройстве, Then подпись и одобрение сохраняются локально (`channel = in_person`), статус `approved (ожидает синхронизации)`; на сервере применяется, только если версия на сервере не менялась (тот же `content_hash`), иначе конфликт показывается owner.
- Given офлайн-подпись, When сеть появилась, Then конверсия в работу выполняется сервером один раз.

**EST-US-17**
- Given статус `sent` или `viewed`, When owner нажимает «Изменить», Then создаётся версия N+1 (копия), статус `draft` (через `revised`), клиент продолжает видеть версию N, пока N+1 не отправлена.
- Given версия N+1 отправлена, When клиент открывает старую ссылку, Then видит N+1 и пометку «смета обновлена»; версию N подписать нельзя.
- Given смета `approved`, When owner пытается изменить, Then редактирование запрещено, предлагается change order (после создания работы).

**EST-US-18**
- Given `expires_at` прошла и статус `sent`/`viewed`, When ночная задача (timezone компании), Then статус `expired`, StatusEvent, задача владельцу «Смета истекла: продлить или обновить цены».
- Given истекшая смета, When owner продлевает срок, Then статус возвращается в `sent`/`viewed` (по `viewed_count`), новая версия не создаётся (меняется только контейнер, в аудит).

**EST-US-19**
- Given смета `approved` (договор исполнен: подпись клиента + countersign), When конверсия, Then в одной транзакции создаются: Job (`estimate_id`, `approved_version_id`, `option_id`), deposit Invoice (если правило и тип договора допускает депозит), PO-черновики из BOM выбранного варианта (`11`), Task «запланировать»; Lead → `won`.
- Given CA HIC и `rescission_ends_at` в будущем, Then Task называется «Запланировать после {дата/время окончания срока отказа}», а визит `install` нельзя поставить раньше этого момента (`07` JOB-US-03). ## 7. Бизнес-правила и расчёты
### 7.1 Статусы (из модели, §9)
```
draft → sent → viewed → [awaiting_countersign] → approved → [cancelled_by_customer]
          ↘ declined   ↘ expired
draft/sent/viewed → revised (новая версия, снова draft)
```
- `awaiting_countersign` (v0.3.1, LEG-03) — клиент подписал, ждём подпись подрядчика; при автоподписи шаг проходит мгновенно. `approved` = договор исполнен (обе подписи).
- `cancelled_by_customer` (v0.3.1, LEG-04) — клиент отказался в срок отказа (CA HIC) или до начала работ (S&R); после `rescission_ends_at` отказ оформляется как отмена работы по договору (`18` M6/M8).
- `revised` — событие, а не конечное состояние: StatusEvent `sent → revised`, затем текущая версия N+1 в `draft`.
- Отправка блокирует версию: `locked_at` ставится, правки запрещены на сервере (проверка в API и триггер БД).
- `approved`, `declined`, `expired` → правка только через новую смету / change order / продление.

### 7.2 Формулы итогов (на каждый вариант), всё в центах, round half up
```
line_total      = round(quantity × unit_price_cents)
line_cost       = round(quantity × (unit_cost_cents + (include_purchase_tax_in_cost ? unit_material_cost_cents × purchase_tax_bps / 10000 : 0)))   // `19` §7.6, без промежуточного округления
included_lines  = строки варианта, где is_optional = false, + выбранные optional
subtotal        = Σ line_total(included_lines)            // скрытые строки дают 0
discount        = pct: round(subtotal × pct)  |  fixed: min(value, subtotal)
net             = subtotal − discount
taxable_sub     = Σ line_total(included_lines, taxable = true)
taxable_disc    = (subtotal = 0) ? 0 : round(discount × taxable_sub / subtotal)
tax             = по режиму профиля версии (`19` §7.5):
                    added_on_top:          tax_enabled ? round((taxable_sub − taxable_disc) × tax_rate) : 0
                    tax_inclusive_display: tax_enabled ? round((taxable_sub − taxable_disc) × tax_rate / (1 + tax_rate)) : 0
                    included_in_price, exempt: 0
total           = net + tax   (tax_inclusive_display: total = net, налог уже в цене; выручка = net − tax)
cost            = Σ line_cost(included_lines, включая скрытые)
margin          = net − cost ;  margin_pct = margin / net (1 знак; при net = 0 не показывается)
deposit         = contract_type = ca_service_repair ? 0 :
                  (pct: round(total × pct) | fixed: min(value, total));
                  CA HIC (лимит вкл., нет bond-attestation): min(deposit, round(total × 10%), 100000)
payment_schedule (CA HIC): deposit + Σ milestones.amount = total; каждый этап привязан к объёму работ
```
- Скидка в MVP одна на вариант, применяется до налога, распределяется на облагаемую часть пропорционально.
- Налог **ручной и настраиваемый**, никогда не автоматический: профиль `tax_profile_id` (режим — снимок `tax_mode`), `tax_enabled` + `tax_rate_id` на версии (вариант может переопределить включение и ставку), снимок ставки `tax_rate_bps` в версии; значения по умолчанию — из профиля компании по умолчанию (налог выключен, пока пользователь не включит). Флажок `taxable` на строке (по умолчанию из каталога) решает, какие строки облагаются. Что облагать в CA для монтажа, решает подрядчик с CPA (исследование — `../legal/`); стартовый LA price book идёт с `taxable = false` (`04` §7.2a). Проверочные примеры по всем режимам — `18` §K (TX1–TX21).
- Себестоимость строки включает налог при покупке материалов по ставке поставщика (снимок `purchase_tax_bps`), если в профиле включено `include_purchase_tax_in_cost` (по умолчанию да).
- Итоги хранятся в `EstimateVersion.totals` и пересчитываются движком на сервере при сохранении; клиентский расчёт = тот же пакет. Расхождение сервера и клиента = ошибка, сервер побеждает и пишет событие в мониторинг.
- Смета без G/B/B = один вариант.

### 7.4 Версии
- Версия = полный снимок: варианты, строки, тексты, налог (`tax_enabled`, `tax_rate_id`, `tax_rate_bps`), правило депозита, `calc_inputs` (если из чертежа), `engine_version`, итоги.
- `content_hash` = SHA-256 канонического JSON видимой клиенту части + PDF; входит в EstimateApproval (доказательство, что подписано именно это).
- Сравнение версий: построчно (добавлено / удалено / изменено) и по итогам.

### 7.5 Срок действия
- По умолчанию `expires_at = sent_at + 30 дней` (настройка компании). Для смет с coil/материалами предлагается 14–30 дней из-за цен поставщиков.
- Проверка ежедневно в 00:05 по timezone компании.

### 7.6 Отправка и PDF
- Ссылка: `PortalAccess` (scope = смета), токен в базе только хэшем, срок жизни = срок сметы + 90 дней.
- PDF: бренд компании, лицензия CSLB, видимые строки, варианты, add-ons, тексты, подпись (если есть). Генерация на сервере.
- Сообщение из шаблона компании на языке контакта (`preferred_language` en/es).

### 7.7 Калифорнийские правила (по `../legal/legal-research.md` §1; требуют проверки адвокатом)
Принцип (§9.1–9.2 исследования): **безопасно по умолчанию, отклонение — явным действием с записью в AuditLog**. Дисклеймер в ToS не снимает с подрядчика обязанностей закона, поэтому правила ниже — в продукте, а не только в тексте.

#### 7.7.1 Тип договора (LEG-01)
| `contract_type` | Когда | Депозит | Срок отказа | Countersign | Шаблон |
|---|---|---|---|---|---|
| `ca_home_improvement` | Жилой дом, работы > $500 (полный B&P §7159); по умолчанию для всех жилых CA-смет, кроме чистки | ≤ min(10%, $1,000), обход только bond-attestation | 3 / 5 / 7 рабочих дней от доставки полностью подписанной копии | Обязателен | CA HIC (заблокированные блоки) |
| `ca_service_repair` | ≤ $750, клиент сам позвал, только позиции исходного запроса, **оплата только после завершения** (§7159.10) | **Запрещён** системой | Пока работа не начата; возврат ≤ 10 дней | Обязателен | CA Service & Repair (упрощённый) |
| `non_hic` | Чистка гаттеров (вероятно, не home improvement [Проверить]), коммерческий объект, работы вне CA | По настройкам компании | Нет | Настройка (по умолчанию авто) | Обычные terms компании |
Порог $750, сумма $500 и список условий — поля `ContractRuleSet`, не константы. Ремонт по вызову, где на месте продали сверх запроса («заодно guards»), перестаёт быть S&R → система предлагает HIC.

#### 7.7.2 Срок отказа (LEG-04)
```
start         = executed_copy_delivered_at (дата в tz объекта; день доставки не считается)
N             = max( owner_65_plus ∈ {yes, unknown} ? senior_days(5) : base_days(3),
                     disaster_emergency_repair ? emergency_days(7) : 0 )
business_day  = день ≠ воскресенье ∧ день ∉ holidays(year)       // суббота — рабочий день
rescission_ends_at = 23:59:59 N-го business_day после start (tz объекта)
```
- Источник чисел — `ContractRuleSet` (юрисдикция `US-CA`, версия, `effective_from`, `base_days = 3`, `senior_days = 5`, `emergency_days = 7`, `saturday_is_business_day = true`, `unknown_senior_policy = senior`, `holidays[]` на каждый год, `approved_by_attorney_at`). Новый год праздников загружается заранее; отсутствие списка на год → блок отправки CA-договоров с ошибкой в мониторинг.
- Отказ клиента от права отказа (срочный ремонт, Civ. §1689.15) в MVP **не строим**.
- До `rescission_ends_at` install-визиты не планируются (`07`), удержание за материалы невозможно (`18` M7/M8), возврат при отказе — ≤ 10 дней (`09` INV-US-20).

#### 7.7.3 Обязательные блоки CA HIC (заблокированы в шаблоне, порядок образца CSLB, LEG-02)
1. Заголовок **Home Improvement**; подрядчик, адрес, телефон, email, License No.; телефон помощи по Notice of Cancellation. 2. Продавец (HIS): имя и номер. 3. Approximate Start / Completion Date и что считается substantial commencement. 4. **Contract Price** (доллары и центы), **Finance Charge** («none» в MVP). 5. **Downpayment** + фраза 12 pt bold о лимите $1,000 / 10%. 6. Описание проекта и значимых материалов/оборудования. 7. Субподрядчики: да/нет (список с лицензиями по запросу). 8. **Schedule of Progress Payments** + фраза о запрете брать оплату за невыполненную работу и недоставленные материалы. 9. Note about Extra Work and Change Orders. 10. Lien release после каждой оплаты. 11. Список документов, входящих в договор. 12. Уведомления CGL и Workers' Compensation (галочки вариантов). 13. **MECHANICS LIEN WARNING**. 14. Information about CSLB (12 pt). 15. Фраза 12 pt bold о праве на полностью заполненную копию, подписанную обеими сторонами, до начала работ. 16. Право потребовать performance and payment bond. 17. Инициалы владельца: получено уведомление о 3-, 5- или 7-дневном праве отказа. 18. Подписи Owner, Second Owner, **Contractor**, Registered Salesperson + номер. 19. Three/Five/Seven-Day Right to Cancel (12 pt bold, рядом с подписью) + отрывная **Notice of Cancellation** с датой сделки и крайним сроком.
- Подпись клиент ставит **на фиксированной PDF-вёрстке**, а не только на адаптивном HTML (шрифты 10/12 pt); на телефоне — масштабируемый PDF с обязательной прокруткой до блока подписи.
- Испанский договор — полный перевод, **включая все статутные уведомления** (Civ. §1689.7; для S&R §7159.10(d)); язык договора = язык переговоров (`Contact.preferred_language`), до утверждения перевода адвокатом (Б6) ES-шаблон недоступен.
- Change order в CA HIC — письменно и с подписью клиента **до** начала этих работ (EST-US-20), с теми же правилами countersign.

### 7.8 Конверсия в работу
- Ключ идемпотентности: `estimate_id + approved_version_id`. Уникальный индекс `Job.estimate_id`.
- Создаётся: Job (`type = install` по умолчанию, из шаблона), `planned_cost_cents` = cost выбранного варианта + выбранные add-ons, deposit Invoice (`kind = deposit`, сумма из 7.2), PO-черновики, Task «Запланировать монтаж» на owner сметы.

### 7.9 Change order
- Те же формулы 7.2. Статусы `draft → sent → approved / declined`.
- Одобренный CO: `amount_cents` → строки финального инвойса; cost → `planned_cost_cents` работы; при материалах → предложить PO.
- CO с отрицательной суммой (убрали downspout) допустим, тоже требует подписи.

| «Добавь guards в Best» | Позиция из каталога, цена каталога | предпросмотр |

## 9. Офлайн
- Создание и правка черновиков, расчёт итогов, шаблоны, копирование, предпросмотр, подпись на устройстве (`in_person`) — офлайн.

## 10. Уведомления и автоматизации
- Push владельцу сметы: открыта (первый раз), подписана, отклонена, истекает через 3 дня, истекла.
- Дожим неподписанных (`13`): по умолчанию через 2 и 5 дней после отправки, если не `approved`/`declined`; останавливается при подписи.
- Подписана клиентом → пользователям с `sign_contracts` push «Подпишите договор» (если нет автоподписи).
- Договор исполнен → клиенту email с PDF **полностью подписанного** договора (+ ссылка в портале, журнал подписи) и, после оплаты, квитанция депозита; команде задача «запланировать после {rescission_ends_at}»; при бумажной форме отказа — задача «вручить 2 экземпляра Notice of Cancellation».
- Срок отказа истёк без отказа → Activity «Срок отказа истёк», задача «запланировать» становится активной, предупреждения по PO снимаются.
- Клиент отказался → push owner, Task «Вернуть $X до {дата + 10 дней}» (`09` INV-US-20).

## 11. Ошибки и крайние случаи
| Случай | Поведение |
|---|---|
| Двойная подпись (два устройства) | Первая побеждает; вторая получает «смета уже подписана» |
| Клиент подписывает старую версию по старой вкладке | Сервер проверяет `sent_version_id`; отказ «смета обновлена», показывается новая |
| Подпись офлайн, а на сервере за это время отправили новую версию | Конфликт к owner: принять подпись старой версии (и отозвать новую) или запросить повторную подпись |
| Каталожная позиция удалена/архивирована | Строки старых смет живут на снимке |
| Total = 0 или отрицательный | Отправка с предупреждением; отрицательный total запрещён (кроме CO) |
| Клиент без email и телефона | Отправка только PDF / QR / подпись на устройстве |
| Портал-ссылка переслана третьему лицу | Подпись требует ввода имени и подтверждения; ссылку можно отозвать (`revoked_at`) |
| Нет прав (tech жмёт «Отправить») | Кнопки нет; API возвращает 403; запрос «попросить owner отправить» → задача |
| Смена клиента у отправленной сметы | Запрещено, только новая смета |
| Налоговая ставка поменялась после отправки | Отправленная версия не меняется; новая версия берёт новую ставку |
| Stripe не подключён | Подпись работает, депозит выставляется инвойсом для оплаты наличными/чеком |
| Клиент подписал, подрядчик не подписал 24 ч+ | Повторный push + Task owner; работа не планируется, депозит не выставляется, срок отказа не идёт |
| Клиент отказался от E-SIGN | Только бумажный договор (печать), смета `viewed`, Task |
| Копия договора не доставлена (bounce) | `executed_copy_delivered_at` пусто, срок отказа не начинается, Task «вручить на бумаге / исправить email» |
| S&R: сумма выросла > $750 или добавлена позиция сверх запроса | Отправка как S&R заблокирована, предложение «Переоформить как Home Improvement» |
| Нет праздников на следующий год в `ContractRuleSet` | Блок отправки CA-договоров с понятной ошибкой, алерт команде Octo |
| Клиент отказался до конца срока, а PO уже отправлен | Task «отменить заказ у поставщика»; удержание с клиента недоступно (`18` M8) |

## 13. Метрики
- Время от открытия объекта до отправленной сметы (baseline основателя «на бумажке», цель < 5 мин для gutters).
- Close rate смет (approved / sent) по источникам лидов; доля одобрений в тот же день.
- Распределение выбора G/B/B (цель: Better+Best > 50%) и доля смет с принятым add-on.
- Средний чек и средняя маржа одобренных смет.
- Доля отправленных смет, которые открыты в течение 24 ч; среднее время открытие → подпись.
- Ошибки: расхождения клиент/сервер расчёта (цель 0), дубли Job (цель 0).
