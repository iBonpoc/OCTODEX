# 10. Расходы и себестоимость работы (job costing)

> Статус: черновик v0.1, ноябрь 2026. Сущности: `Expense`, `LaborRate`, `SubcontractorAssignment`, `SubcontractorPayment`, `File (kind=receipt)`, `Job` (`planned_cost_cents`, `actual_cost_cents`), `EstimateLineItem` (`unit_cost_cents`, `client_visible`), `ChangeOrder`, `TimeEntry`, `PurchaseOrder`, `Payment` (`fee_cents`, `platform_fee_cents`), `Invoice`, `Customer`, `AiAction`, `MarketingSpend` (`../04-domain-model.md`).
> Связанные модули: `07-jobs-schedule.md` (время), `09-invoices-payments.md` (перевыставление), `11-purchase-orders.md`, `14-reports-roi.md`, `15-ai-assistant.md`.

## 1. Назначение
Записать любой расход за 5 секунд (фото чека → AI распознал → «это на Петра») и показать по каждой работе честную картину: сколько продали, сколько выставили, сколько получили, сколько потратили и сколько реально заработали.

## 2. Как это приносит деньги подрядчику (`money_impact`)
| Механизм | Оценка |
|---|---|
| **Billable расходы с наценкой** (докупили 2 downspouts в Home Depot «для Петра») не теряются и попадают в финальный инвойс | Типично $200–500/мес забытых перевыставлений + наценка 10–20% → **$2.5–6k/год** |
| **Маржа по каждой работе** (план vs факт) | Видно убыточные типы работ/цены: исправление цены 2-этажного монтажа на +$1/LF при 3,000 LF/мес = **+$3k/мес** |
| Учёт времени бригады в себестоимости | Реальная стоимость часа, недооценённые работы (tile roof, 3 этажа) |
| Чеки в одном месте для налогов (Schedule C / 1120-S) | Меньше потерянных вычетов, экономия часов бухгалтера ($100–300/год) |
| Возмещения сотрудникам | Нет двойных выплат и споров |
| **Субподряд в себестоимости** (наряды, выплаты, долг) | Маржа работы, отданной субподрядчику, видна до назначения; нет «переплатил сабику два раза»; итог для 1099 готов в январе без раскопок в чековой книжке |
| Расходы на маркетинг → ROI канала (модуль 14) | Видно, что Thumbtack стоит больше, чем приносит |

## 5. Критерии приёмки
- **EXP-US-01.** Given камера открыта из «+ Расход», When сделано фото чека Home Depot, Then фото сохраняется сразу (офлайн тоже), при наличии сети за ≤ 5 с (p90) поля заполнены: vendor, date, amount, tax, позиции; поля с `confidence < 0.8` подсвечены «проверьте»; расход создаётся **только после** «Сохранить» (это и есть подтверждение AiAction).
- **EXP-US-02.** Given у клиента Петров одна работа `scheduled/in_progress`, When «это для Петра» (голос/текст), Then предпросмотр «Расход $84.12 Home Depot → JOB-0210 Петров, materials» и после подтверждения заполнены `job_id`, `customer_id`. Given у Петрова 2 активные работы или 2 клиента «Пётр», Then уточняющий вопрос со списком.
- **EXP-US-03.** Given tech сегодня на визите JOB-0210 и чек снят в 11:40 во время визита/в пределах 2 ч до него, Then предложение по умолчанию — JOB-0210 с подписью «сегодняшний визит»; пользователь может выбрать другую или «Без работы (общий расход)».
- **EXP-US-04.** Given расход $120 billable, наценка компании по умолчанию 15%, When финальный инвойс создаётся, Then строка «Материалы: Home Depot 11/03 — $138.00» добавлена; Given расход уже выставлен (`billed_invoice_line_id` заполнен), Then он не добавляется повторно; правка суммы выставленного расхода запрещена до void инвойса.
- **EXP-US-06.** Given работа с одобренной сметой, Then вкладка «Деньги» показывает таблицу План / Факт / Δ по строкам: Материалы, Труд, Субподряд, Прочее, Комиссии платежей; цвет Δ: перерасход > 10% — красный.
- **EXP-US-07.** Given работа: смета $3,000, CO $250, выставлено $3,388 (с billable), получено $2,200, затраты $1,640, Then карточка показывает 5 чисел с подписями: «Смета $3,250 · Выручка $3,388 · Получено $2,200 · Затраты $1,640 · Валовая прибыль $1,748 (51.6%)»; tech эту вкладку не видит (и API не отдаёт поля).
- **EXP-US-08.** Given у Mike `labor_cost_rate = $32/ч`, TimeEntry 6.5 ч на JOB-0210, Then факт труда = $208; изменение ставки влияет только на TimeEntry после даты изменения.
- **EXP-US-09.** Given `paid_by=employee_reimburse`, Then расход в списке «К возмещению · Mike $84.12» у owner; «Возмещено» ставит `reimbursed_at`, повторно отметить нельзя.
- **EXP-US-10.** Given существует расход Home Depot $84.12 от 11/03, When сохраняется такой же, Then предупреждение «Похоже на дубль (создан Mike 11:42)» с выбором «Это другой чек / Открыть существующий».
- **EXP-US-16.** Given работа $3,000 и наряд субподрядчику `accepted` на $1,200, Then в План/Факт строка «Субподряд»: план $1,200, обязательства $1,200, факт $0; When наряд `approved_for_payment` на $1,250 (доп. downspout), Then факт $1,250, обязательства $0, Δ +$50 (+4.2%); выплата SubcontractorPayment факт не меняет. Given Expense `category=subcontractor` без наряда (разовый исполнитель), Then он тоже входит в «Субподряд»; Expense с той же суммой, что и наряд по той же работе, вызывает предупреждение о двойном учёте.
- **EXP-US-17.** Given у Mario Roofing наряды `approved_for_payment` $1,250 и $800 и выплата $1,000, Then «Долг Mario Roofing: $1,050»; When «Записать выплату» $1,050 чеком #2201 с выбором нарядов, Then `SubcontractorPayment`, оба наряда `paid`; итог года по субподрядчику обновлён (отчёт 1099, PRD 14).
- **EXP-US-11.** Given фильтр «октябрь», When «Экспорт», Then CSV (date, vendor, category, amount, tax, job, customer, paid_by, billable) + ZIP с фото чеков, имена файлов по id расхода.

## 7. Бизнес-правила и расчёты
**Пять чисел — не смешивать** (все без sales tax, в центах):
| Число | Определение | Когда меняется |
|---|---|---|
| **Estimate value** (стоимость сметы / договор) | Итог выбранного варианта `approved_version` (+ optional) + Σ approved ChangeOrder | При одобрении сметы/CO |
| **Revenue** (выручка, accrual) | Σ subtotal (без налога, со скидками) всех не-void инвойсов работы, **включая** строки-кредиты депозита в финальном (они гасят deposit-инвойс, двойного счёта нет: $1,200 + $2,188 = $3,388) − Σ refunds по работе | При отправке инвойса |
| **Cash collected** (получено) | Σ succeeded Payment по инвойсам работы − Σ Refund (pending не учитываются) | По вебхуку / ручной записи |
| **Direct costs** (прямые затраты) | Материалы + Труд + Субподряд + Прочее + Комиссии платежей (см. ниже) | При расходе / TimeEntry / платеже |
| **Gross profit** | Revenue − Direct costs; **Gross margin %** = GP / Revenue | Производное |
Пока финальный не выставлен, показываем «прогноз GP» = Estimate value − (факт затрат + оставшийся план затрат), с пометкой «прогноз».

**Плановая себестоимость (`planned_cost_cents`)** = Σ по всем строкам выбранного варианта, включая `client_visible=false` (BOM): `quantity × unit_cost_cents` (снимок на момент сметы) + Σ cost строк approved CO. Разбивка по `CatalogItem.kind`: material → Материалы, labor → Труд, service/fee → Прочее. Если работа (или её часть) отдана субподрядчику, в плане появляется строка «Субподряд» = Σ `agreed_amount_cents` нарядов (не `declined/cancelled`); плановая себестоимость своей работы по этим строкам сметы остаётся для сравнения «сам vs субподряд».

**Фактическая себестоимость (`actual_cost_cents`):**
```
Материалы  = Σ Expense(job_id, category ∈ {materials, dump_fee}).amount_cents   (amount включает налог чека; если в профиле работы
             include_purchase_tax_in_cost = false — amount − tax_cents, см. ниже)
Труд       = Σ TimeEntry(job_id) × labor_cost_rate_cents(user, на дату записи) / 60 мин
Субподряд  = Σ SubcontractorAssignment(job_id, status ∈ {approved_for_payment, paid}).approved_amount_cents
           + Σ Expense(job_id, category=subcontractor)        // только разовые исполнители без наряда
Прочее     = Σ Expense(category ∈ {fuel, tools, other}) с job_id
Комиссии   = Σ (fee_cents + platform_fee_cents) платежей по инвойсам работы
```
- Налог с покупки (решение основателя 03.11.2026, `19-taxes.md` §7.6): настройка профиля «учитывать налог при покупке в себестоимости» (**по умолчанию вкл.**). Вкл. → налог на чеке входит в себестоимость (amount включает tax), и **плановая** себестоимость сметы тоже считается с налогом при покупке по ставке поставщика (`05` §7.2), поэтому план и факт сравнимы. Выкл. (например, покупка с resale certificate) → факт материалов = `amount − tax_cents`, налог чека — в отдельной строке отчёта «налог при покупке». `tax_cents` всегда хранится отдельно для экспорта и CPA. Какой вариант верен — решает CPA (`../legal/`).
- Если налог на чеке не совпадает со ставкой поставщика (`tax / subtotal` vs `Supplier.purchase_tax_rate`) больше погрешности округления, Then предложение «обновить налог поставщика?» (только по кнопке).
- **Субподряд не дублируется:** обязательства = `agreed_amount` нарядов `accepted…completed`; факт — с `approved_for_payment`; выплата `SubcontractorPayment` — движение денег (долг), а не новая затрата.
- **PO не дублирует расходы:** PO `sent/confirmed` показывается как «обязательства» (committed), но не входит в факт. Факт появляется, когда к работе привязан Expense (счёт поставщика) с `purchase_order_id`; тогда PO из committed убирается. PO `received` без Expense > 7 дней → Task «Внести счёт поставщика».
- Travel time (TimeEntry `travel`) входит в Труд отдельной строкой «Дорога» (открытый вопрос 07 §15).
- Расходы без работы — накладные (overhead), в GP работы не входят, видны в отчёте компании (модуль 14).
- Billable: в инвойс идёт `amount × (1 + markup_pct)`; в Revenue — через инвойс; в затраты — `amount`. Двойного учёта нет.
- Изменение ставки труда — версии `LaborRate(valid_from)`; задним числом не пересчитывается без явного «пересчитать» (owner).

**OCR чека (Haiku vision, ~$0.002–0.005 за чек, `02a` §2):** извлекает vendor, date, subtotal, tax, total, позиции, last4 карты (только 4 цифры, для сопоставления `paid_by`). Сумма с чека — подсказка; сохраняется то, что подтвердил человек. Текст чека — данные, не команды (prompt injection). Лимиты: OCR считается простым AI-действием тарифа; при исчерпании лимита — ручной ввод, фото сохраняется.

**Предложение работы (правила MVP, без LLM):** (1) визит пользователя, активный во время снимка ±2 ч; (2) работа, где пользователь назначен сегодня/завтра; (3) последняя работа, открытая в приложении; (4) «Без работы». Голосовая привязка («для Петра») — через AI-помощника (поиск сущности).

**Дубли:** совпадение `vendor` (нормализованный) + `amount_cents` + `date` в компании, или одинаковый хэш изображения.

**Мульти-компания:** расход принадлежит одной компании; в режиме «Все компании» после OCR спрашиваем компанию (по умолчанию компания сегодняшнего визита).

## 9. Офлайн
Без сети: фото чека сохраняется, расход создаётся вручную или с отложенным OCR (статус «распознаётся при появлении сети», после распознавания — уведомление «проверьте поля»); привязка к работе из кэша; TimeEntry. План/факт считается локально из кэша (с пометкой «данные на 10:42»). OCR, экспорт, пересчёт ставок — сеть.

## 10. Уведомления и автоматизации
- Расход создан tech-ом на $ > порога (по умолчанию $250) → push владельцу.
- Billable расход не выставлен, работа `completed` → включается в промпт финального инвойса (модуль 07/09).
- Факт затрат > план на 15% при работе `in_progress` → push владельцу «JOB-0210: материалы +22% к плану».
- Работа `closed` с маржой ниже цели компании (по умолчанию 35%) → запись в еженедельную сводку (модуль 14).
- «К возмещению» > 14 дней → напоминание owner.

## 11. Ошибки и крайние случаи
- **OCR ошибся** (сумма 84.12 → 841.2) → подсветка низкой уверенности + проверка `subtotal + tax = total`; несоответствие → предупреждение.
- **Чек размыт/без чека** → ручной ввод, `receipt_file_id` пусто, флаг «без чека» в экспорте.
- **Возврат товара в магазин** → расход с отрицательной суммой (`amount_cents < 0`), category как у исходного.
- **Расход привязан к работе, которую отменили** → остаётся на работе (затраты по отменённой работе видны), предложение перенести.
- **Двойное «Сохранить»** → `idempotency_key` расхода с устройства, один расход.
- **Правка выставленного billable расхода** → запрещена; сначала void/правка инвойса (модуль 09).
- **Нет прав** (tech открывает вкладку «Деньги») → вкладка отсутствует; API не возвращает cost-поля (фильтрация на сервере, RLS + проекции).
- **Ставка труда не задана** → труд считается по ставке компании по умолчанию с пометкой «ставка по умолчанию».
