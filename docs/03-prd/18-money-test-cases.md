# 18. Проверочные примеры: деньги, отмены, аннулирования, возвраты

> Дополнение к `05-estimates.md` (T1–T18), `09-invoices-payments.md`, `10-expenses-job-costing.md`, `19-taxes.md` (§K: налоги по режимам, TX1–TX21).
> Запрос основателя (03.11.2026): в проверочные примеры движка добавить отмены и аннулирования счетов, чеков, предоплат и депозитов.
> Каждый пример — это будущий автотест: при этих входных данных система обязана дать ровно эти цифры и статусы.
> Цифры комиссий примерные: Stripe карта 2.9% + $0.30; ACH 0.8%, не больше $5; наша комиссия 0.5% (для ACH не больше $5). **Перед запуском сверить с действующими тарифами.**

## 0. Термины и правила, на которых построены примеры

| Термин | Что это |
|---|---|
| **Void (аннулирование)** | Документ отменён и не считается нигде (выручка, долг клиента). Номер не переиспользуется. Нужна причина |
| **Refund (возврат)** | Деньги возвращаются клиенту. Платёж остаётся в истории со статусом `partially_refunded` / `refunded` |
| **Returned / bounced** | Банк вернул ACH-платёж или чек не прошёл. Долг клиента восстанавливается |
| **Deposit (предоплата)** | Отдельный депозитный инвойс. В финальном инвойсе зачитывается строкой «Депозит» с минусом |
| **Customer credit (кредит клиента)** | Переплата, которая хранится на клиенте и зачитывается в следующий инвойс или возвращается |
| **5 чисел работы** | Сумма сметы · Выручка (без налога, за вычетом возвратов) · Получено денег (нетто) · Прямые затраты · Валовая прибыль |

**Инварианты (проверяются в каждом тесте):**
1. `balance = total − paid_net − credits_applied`, где `paid_net = payments_succeeded − refunds − returned`.
2. Инвойс можно аннулировать, только если `paid_net = 0`. Иначе сначала возврат или перенос оплаты в кредит клиента.
3. Возврат не больше, чем `paid_net` по этому платежу.
4. Зачёт депозита в финальный инвойс не больше фактически оплаченного (нетто) депозита.
5. Номер документа никогда не переиспользуется, даже после void.
6. Налог не является выручкой. Возврат по облагаемому инвойсу делится на налог и сумму без налога по режиму документа (`19` §7.9): пропорционально по умолчанию для `added_on_top` и `tax_inclusive_display`; для `included_in_price` и `exempt` налоговая часть 0 (§K5).
7. Комиссию процессора (Stripe) при возврате не возвращают. Это прямые затраты работы.
8. Каждый void, refund, returned и перенос в кредит пишется в AuditLog и StatusEvent с причиной и автором.
9. Void и refund делают только owner/admin. AI-помощник не может их выполнять.

**Базовая смета для примеров:** EST-0148, Yuri Petrov, вариант Better **$3,400.00**, налог выключен (если не сказано иное).
**Депозит по правилу CA:** меньшее из 10% и $1,000 → **$340.00**.

## A. Депозиты и предоплаты

### M1. Депозит, затем финальный инвойс (нормальный сценарий)
| Шаг | Действие | Ожидаемо |
|---|---|---|
| 1 | Смета одобрена | Создан INV-0101 (kind `deposit`) на $340.00 |
| 2 | Оплата картой $340.00 | INV-0101 `paid`. Комиссия Stripe $10.16, наша $1.70 |
| 3 | Работа завершена, финальный INV-0102 | Строки $3,400.00, строка «Депозит INV-0101» −$340.00, **balance $3,060.00** |
| 4 | Оплата ACH $3,060.00 | INV-0102 `paid`. Stripe ACH $5.00 (потолок), наша $5.00 (потолок) |

**5 чисел:** смета $3,400.00 · выручка $3,400.00 · получено $3,400.00 · прямые затраты (только комиссии) $21.86 · валовая прибыль считается с учётом материалов и труда (здесь не заданы).

### M2. Смета пересмотрена в меньшую сторону после депозита
| Шаг | Действие | Ожидаемо |
|---|---|---|
| 1 | Депозит $340.00 по версии v2 (Better $3,400) оплачен | |
| 2 | Клиент выбирает Good $2,850.00, создаётся v3 | Новый лимит депозита $285.00. **Предупреждение:** «Депозит $340.00 превышает лимит CA $285.00. Вернуть $55.00?» |
| 3 | Владелец подтверждает возврат $55.00 | Refund $55.00, депозит нетто $285.00 |
| 4 | Финальный инвойс | $2,850.00 − $285.00 = **$2,565.00** |

### M3. Смета увеличилась после депозита
v2 Better $3,400 (депозит $340.00 оплачен) → v3 Best $5,100.00. Новый лимит $510.00. Система **может** предложить доплату депозита $170.00 (не обязательно). Если доплачен: финальный $5,100.00 − $510.00 = **$4,590.00**.

### M4. Доп. работы (change order) после депозита
Депозит $340.00 оплачен, CO-001 +$420.00 одобрен. Финальный: $3,400.00 + $420.00 − $340.00 = **$3,480.00**.

### M5. Два депозита по двум работам одного клиента на одном доме
Работа A (гаттеры, депозит $340.00), работа B (fascia, депозит $120.00). Финальный инвойс по A зачитывает **только** депозит A. Попытка зачесть депозит B в инвойс A → ошибка «Депозит принадлежит другой работе». Перенос возможен только явным действием owner/admin с записью в аудит.

## B. Отмена работы клиентом

### M6. Отмена с полным возвратом депозита
Депозит $340.00 оплачен картой. Клиент отменяет до начала работ.
| | Ожидаемо |
|---|---|
| Refund | $340.00, платёж `refunded`, INV-0101 `payment_status = refunded`, затем void разрешён (paid_net = 0) |
| Job | `cancelled`, причина обязательна |
| Комиссия Stripe $10.16 | не возвращается → прямые затраты |
| Наша комиссия $1.70 | **рекомендация:** возвращаем пропорционально возврату (здесь полностью) |
| **5 чисел** | смета $3,400.00 · выручка $0.00 · получено $0.00 · затраты $10.16 · прибыль **−$10.16** |

### M7. Отмена в течение 3 дней (право на отказ в CA)
То же, что M6, но возврат **обязателен**. В карточке сметы виден дедлайн отказа (из `EstimateApproval`). Если отказ пришёл до дедлайна, кнопка «Удержать часть» недоступна. **Проверить с юристом.**

### M8. Отмена после изготовления материалов: частичный возврат
Депозит $340.00 (карта). Coil уже нарезан, себестоимость материалов $96.50. Договорились удержать $180.00.
| | Ожидаемо |
|---|---|
| Refund | $160.00 → платёж `partially_refunded`, нетто $180.00 |
| Документ | Инвойс отмены INV-0103 «Материалы, изготовленные по заказу» $180.00, зачтён из депозита, balance $0.00 |
| Наша комиссия | возвращаем пропорционально: $1.70 × 160 / 340 = $0.80, остаётся $0.90 |
| **5 чисел** | смета $3,400.00 · выручка $180.00 · получено $180.00 · затраты $96.50 + $10.16 + $0.90 = $107.56 · прибыль **$72.44** |

## C. Аннулирование инвойсов

### M9. Void неоплаченного инвойса
INV-0094 $1,200.00 отправлен, оплат нет. Void с причиной «ошибка в объёме». Ожидаемо: статус `void`, долг клиента −$1,200.00, в отчёте дебиторки его нет, номер INV-0094 больше не выдаётся. Ссылка в портале показывает «Счёт аннулирован».

### M10. Попытка void инвойса с оплатой
INV-0095 $500.00, получено $200.00 наличными. Void → **отказ**: «По счёту получено $200.00. Сначала верните деньги или перенесите их в кредит клиента». После переноса $200.00 в кредит клиента void разрешён, кредит клиента = $200.00.

### M11. Void после частичного возврата
INV-0096 $800.00, оплачено $800.00 картой, возврат $800.00 → paid_net = 0 → void разрешён. Комиссия Stripe $23.50 остаётся затратами.

### M12. Void инвойса с перевыставленным расходом
Расход Home Depot $212.40 с наценкой 15% выставлен строкой $244.26 в INV-0097. INV-0097 аннулирован (не оплачен). Ожидаемо: расход снова «не выставлен» и может попасть в новый инвойс. Выставить его в два действующих инвойса одновременно нельзя.

## D. Возвраты

### M13. Частичный возврат за претензию
Финальный $3,400.00 оплачен ACH. Возврат $150.00 «за задержку». Ожидаемо: платёж `partially_refunded`, balance $0.00 (возврат не создаёт новый долг), выручка **$3,250.00**, получено **$3,250.00**, комиссия ACH не возвращается.

### M14. Возврат по облагаемому инвойсу
Режим `added_on_top` (`19-taxes.md`). Налог включён вручную, ставка 9.5% только на материалы $1,200.00 → налог $114.00, итого $3,514.00, оплачено полностью. Возврат 10% = $351.40. Распределение по умолчанию пропорционально: налог $11.40, без налога $340.00. Ожидаемо: выручка $3,060.00, налог к учёту $102.60. Пользователь может изменить распределение вручную.

### M15. Возврат больше оплаченного
Попытка вернуть $400.00 по платежу $340.00 → отказ «Можно вернуть не больше $340.00».

## E. Банк вернул платёж, чеки

### M16. Чек не прошёл (bounced)
Депозит $340.00 записан как чек (`succeeded`, ручной). Через 3 дня отметка «Чек вернулся».
| | Ожидаемо |
|---|---|
| Платёж | `returned`, причина «NSF» |
| INV-0101 | снова `unpaid`, balance $340.00, напоминания возобновляются |
| Банк списал комиссию $15.00 | расход «Bank fee» на работу |
| Плата клиенту за возврат чека | опциональная строка в инвойсе, по умолчанию $25.00 (CA Civil Code §1719, **проверить с юристом**) |

### M17. ACH возвращён банком (R01, недостаточно средств)
Финальный $3,060.00 оплачен ACH, через 4 дня возврат. Ожидаемо: платёж `returned`, INV-0102 balance $3,060.00, работа остаётся `completed`, но не `closed`. Комиссия Stripe за возврат ACH (ориентир $4.00, **проверить**) → прямые затраты. Push владельцу.

### M18. Записанный офлайн платёж по уже аннулированному инвойсу
Техник офлайн записал наличные $340.00 по INV-0101, офис в это время аннулировал INV-0101. При синхронизации сервер платёж **не отклоняет молча**: статус `needs_review`, владельцу предлагается «Перенести в кредит клиента» или «Вернуть наличные». Деньги не теряются.

## F. Переплата и двойная оплата

### M19. Переплата чеком
Счёт $3,060.00, клиент дал чек на $3,100.00. Ожидаемо: инвойс `paid`, **кредит клиента $40.00**. Следующий инвойс за чистку $289.00 → зачёт $40.00 → balance $249.00. Либо возврат $40.00 по кнопке.

### M20. Двойное нажатие «Оплатить»
Клиент дважды нажал «Оплатить $3,060.00» в портале. Ожидаемо: **одно** списание (тот же `idempotency_key` и PaymentIntent). Второй запрос возвращает результат первого.

### M21. Оплата двумя способами
Клиент оплатил $3,060.00 в портале и одновременно отдал чек технику на $3,060.00. Ожидаемо: второй платёж записывается, инвойс показывает переплату $3,060.00, статус `needs_review`. Владелец выбирает: вернуть чек (void ручного платежа, разрешено, пока чек не обналичен) или оставить кредит.

## G. Чеки расходов (receipts) и расходы

### M22. Дубль чека
Фото того же чека Home Depot $212.40 загружено дважды. Ожидаемо: второй помечен «возможный дубль» (совпал `image_hash` или магазин+дата+сумма), сохранить можно только после подтверждения. При удалении дубля себестоимость работы уменьшается на $212.40.

### M23. Возврат товара в магазин
Возвращены лишние элбоу на $64.10. Расход с отрицательной суммой −$64.10 на ту же работу. Материалы нетто = $212.40 − $64.10 = $148.30.

### M24. Расход перенесён на другую работу
Расход $212.40 записан на Petrov, на самом деле Kim. Перенос → у Petrov затраты −$212.40, у Kim +$212.40. Если расход уже выставлен Petrov в оплаченном инвойсе, перенос запрещён до корректировки инвойса.

## I. Изменения модели данных (внести в 04-domain-model v0.3)
✅ Внесено в 04-domain-model v0.2 (досрочно). `needs_review` внесён как флаг Payment (PRD 09), а не как статус; `returned` — статус Payment.
- `CustomerCredit`: `customer_id`, `amount_cents`, `source (overpayment / void_transfer / refund_alternative)`, `source_payment_id`, `status (open / applied / refunded)`.
- `CreditApplication`: `credit_id`, `invoice_id`, `amount_cents`, `applied_at`.
- `Payment.status`: добавить `returned`, `needs_review`; поле `return_reason`.
- `Invoice`: `void_reason`, `voided_by`, `voided_at`; правило «void только при paid_net = 0».
- `Refund`: `allocation` (налог / без налога), `platform_fee_refunded_cents`.
- `Job`: `cancel_reason`, `cancelled_at`.
- `Expense`: разрешена отрицательная сумма, `transferred_from_job_id`.

## J. Вопросы
1. Возвращаем ли нашу комиссию при возврате? **Рекомендация:** да, пропорционально. Это честно и соответствует позиционированию.
2. Плата за возвращённый чек $25: включать по умолчанию или нет? Нужна проверка юристом.
3. Отрицательный кредит клиента (долг) не допускаем: долг всегда живёт в инвойсе.
