# 04. Каталог, сборки, поставщики, импорт/экспорт, AI-скан прайсов

> Статус: черновик v0.1, ноябрь 2026. Сущности: `CatalogItem`, `Assembly`, `AssemblyComponent`, `Supplier`, `SupplierItem`, `ImportJob` (бывший `PriceListImport`), `ImportRow`, `ImportMapping`, `DataExport` (`../04-domain-model.md` §3, §8, v0.3). Связанные модули: `05-estimates.md`, `06-gutters-module.md`, `11-purchase-orders.md`, `15-ai-assistant.md`, `19-taxes.md`.
> **Решения основателя 03.11.2026 (второй пакет):** (1) стартовый price book поставляется с **тестовыми** редактируемыми ценами, реальные цены вручную основатель не вводит; (2) **массовый импорт/экспорт — MVP** (§7.7); (3) **AI-скан прайса и ценника возвращён в MVP** (§7.6), обновление цен — только через diff и кнопку; (4) все цены поставщиков и каталога хранятся **без налога**, у поставщика — своя ставка налога при покупке (`19-taxes.md`).

## 1. Назначение
Единый источник цен, себестоимости и правил расчёта (Estimating Engine, шаги 2–3). Сметы, BOM, PO и маржа берут цифры только отсюда. Модуль Gutters при включении ставит готовый LA price book и сборки, поэтому первая смета считается без настройки.

## 2. Как это приносит деньги подрядчику (`money_impact`)
| Механизм | Эффект |
|---|---|
| Себестоимость рядом с ценой, контроль минимальной маржи | Не продаёт ниже себестоимости. Цель: нет смет с маржой ниже порога компании без явного подтверждения владельца |
| Cost-plus позиции пересчитываются при росте закупочных цен | Рост цены coil у поставщика не съедает маржу молча. При марже 40% и росте материала на 10% без пересчёта теряется ~2–3 п.п. маржи по каждой работе |
| Готовый LA price book и сборки | Первая смета в день установки, а не через неделю настройки. Активация = выручка подрядчика с первой недели |
| Сборки вместо ручного перечня | Ничего не забыто (hangers, sealant, end caps, elbows). Забытые 12 elbows по $6 = −$72 на смете, плюс повторный выезд в магазин ~$50–100 времени |
| AI-скан прайса поставщика и ценника (MVP) | Обновление 200–300 строк прайса за 5–10 минут вместо часа-двух ручного ввода, актуальная себестоимость в job costing |
| Массовый импорт/экспорт с diff и отменой | Каталог и цены поставщиков обновляются файлом из Excel за минуты; ошибка импорта откатывается одной кнопкой, а не вручную по 300 строкам |
| Себестоимость с налогом при покупке (`19`) | Маржа в смете не завышена на 3–4 п.п. по материалам (пример A `06`: 61.2% → 59.5%) |

## 3. Пользователи и роли
| Роль | Что делает |
|---|---|
| owner, admin | Всё: позиции, цены, себестоимость, сборки, формулы, поставщики, импорт прайсов |
| office | Позиции и цены, поставщики, импорт прайсов и каталога, экспорт каталога (колонки себестоимости — по праву `can_view_cost`). Формулы сборок только просмотр (настраивается) |
| sales | Просмотр каталога и цен. Себестоимость по настройке `permissions_override.can_view_cost` |
| tech | Просмотр названий и единиц (для черновика сметы и BOM). **Без себестоимости и маржи** |
| subcontractor | Нет доступа |

| CAT-US-02 | Как owner, я хочу задать позицию как cost-plus (цена = себестоимость × наценка), чтобы цена клиенту следовала за закупочной |
| CAT-US-03 | Как owner, я хочу при включении модуля Gutters получить готовый LA price book с **тестовыми** ценами и сборки, чтобы сразу считать сметы и заменить цены импортом или сканом, а не вводом руками |

| CAT-US-05 | Как owner, я хочу менять константы сборок (шаг hangers, waste %, высота этажа), чтобы расчёт совпадал с моей практикой |

| CAT-US-09 | Как office, я хочу импортировать прайс поставщика из CSV, XLSX, XML или JSON с шагом сопоставления колонок, чтобы не вводить строки руками |
| CAT-US-10 | Как office, я хочу сфотографировать или загрузить PDF / скриншот прайса, чтобы AI распознал строки, а я проверил их diff перед применением (MVP) |
| CAT-US-11 | Как owner, я хочу видеть, какие позиции станут ниже минимальной маржи после обновления себестоимости, чтобы поднять цены |
| CAT-US-12 | Как tech, я хочу находить позицию по названию или SKU на телефоне, чтобы добавить её в черновик сметы |
| CAT-US-13 | Как owner с двумя компаниями, я хочу скопировать каталог и сборки из одной компании в другую |
| CAT-US-14 | Как owner, я хочу сфотографировать **один ценник на полке** (например, Home Depot), чтобы обновить цену одной позиции за 10 секунд |
| CAT-US-15 | Как office, я хочу сохранить шаблон сопоставления колонок для поставщика, чтобы следующий прайс ABC Supply загружался без настройки |
| CAT-US-16 | Как owner, я хочу видеть diff импорта по классам (новые / цена изменилась / без изменений / не сопоставлено / ошибка) и применять его одной кнопкой, в том числе для 300+ строк |
| CAT-US-17 | Как owner, я хочу **отменить весь импорт** одной кнопкой, если загрузил не тот файл |
| CAT-US-18 | Как owner, я хочу импортировать свой каталог (price book) и клиентов из файла, чтобы перейти в Octo без ручного ввода |
| CAT-US-19 | Как owner, я хочу импортировать строки сметы и архив старых смет из файла |
| CAT-US-20 | Как owner, я хочу экспортировать каталог, клиентов, сметы (строки), инвойсы и расходы в CSV/XLSX, а сметы, инвойсы и PO — в PDF, чтобы отдать бухгалтеру или поправить в Excel и загрузить обратно |
| CAT-US-21 | Как owner, я хочу, чтобы цены поставщика всегда хранились без налога, а ставка налога при покупке была в карточке поставщика (`19`) |
| CAT-US-22 | Как owner, я хочу видеть, какие цены ещё тестовые, и получать предупреждение при отправке сметы с тестовыми ценами |

## 5. Критерии приёмки
**CAT-US-01**
- Given owner в каталоге, When создаёт позицию без `name` или `unit`, Then сохранение заблокировано с подсказкой у поля.
- Given цена введена как `12.5`, When сохраняет, Then хранится `unit_price_cents = 1250` (целые центы).
- Given позиция уже использована в смете, When owner меняет её цену, Then строки существующих смет не меняются (снимок цены в `EstimateLineItem`).

**CAT-US-02**
- Given позиция cost-plus, себестоимость $4.10, наценка 150%, When сохраняется, Then цена = round_half_up(410 × 2.5) = 1025 центов ($10.25).
- Given позиция cost-plus, When пользователь пытается вручную ввести цену, Then поле цены только для чтения с пояснением «цена считается от себестоимости».

**CAT-US-03**
- Given компания включила модуль Gutters, When открывает каталог, Then есть ≥ 30 позиций с `module = gutters` и 4 сборки (§7.5), у всех позиций `is_placeholder_price = true` и бейдж «тестовая цена»; цены и себестоимость редактируются как обычно.
- Given позиция с тестовой ценой, When пользователь меняет цену или себестоимость (вручную, импортом, сканом) или нажимает «Цена проверена», Then `is_placeholder_price = false`.
- Given модуль включён повторно (выключили и включили), When сид выполняется, Then дублей нет (уникальность по `seed_key`).

**CAT-US-04**
- Given owner изменил цену сид-позиции, When выходит обновление price book модуля, Then его цена не меняется, а в позиции появляется пометка «доступно новое значение по умолчанию: $X» с кнопкой «Принять».
- Given owner не менял сид-позицию, When выходит обновление, Then показывается список изменений до применения, применение только по кнопке.

**CAT-US-05**
- Given константа `hanger_spacing_ft = 2`, When owner ставит 1.5, Then расчёт новых смет использует 1.5, старые сметы не пересчитываются.
- Given ввод константы вне допустимого диапазона (например, шаг 0 или > 4 ft), When сохраняет, Then ошибка с допустимым диапазоном.

**CAT-US-06**
- Given формула ссылается на неизвестную переменную, When admin сохраняет, Then ошибка «неизвестная переменная `gutter_lf2`», сохранение заблокировано.
- Given у сборки есть сохранённые тест-кейсы, When admin меняет формулу, Then все тест-кейсы прогоняются, расхождения показываются; сохранить можно только с явным «Принять новые ожидаемые значения».
- Given admin на телефоне, When открывает сборку, Then формулы только для просмотра (редактирование на вебе/iPad).

**CAT-US-07**
- Given поставщик без `email_for_orders`, When пользователь пытается отправить ему PO, Then отправка по email недоступна, доступен только PDF.

**CAT-US-08**
- Given позиция «Hidden hanger 6″» привязана к SupplierItem с `pack_size = 50`, When в BOM 65 hangers, Then в PO идёт ceil(65/50) = 2 упаковки (`11-purchase-orders.md`).

**CAT-US-09**
- Given CSV с колонками SKU, Name, Unit, Cost, When пользователь сопоставляет колонки, Then строки идут в тот же экран diff, что и AI-скан (CAT-US-10), без вызова AI.
- Given XLSX с несколькими листами, When загружен, Then предлагается выбрать лист и строку заголовков; Given XML/JSON, Then предлагается выбрать повторяющийся элемент / массив (например `items.item`), его поля становятся «колонками» для сопоставления (§7.7).
- Given в файле > 5,000 строк, When загрузка, Then отказ «до 5,000 строк в одном импорте, разделите файл» до разбора (§7.7.4).

**CAT-US-10**
- Given загружено фото, PDF или скриншот прайса, When распознавание завершено, Then `ImportJob.status = review`, каждая строка с confidence; строки с confidence < 0.8 или с непарсимой ценой подсвечены и по умолчанию не выбраны.
- Given налог указан только внизу прайса, When распознан, Then цены строк сохраняются без налога, ставка показывается отдельно и сравнивается со ставкой поставщика (`19` §7.10, `18` TX18).
- Given строка совпала с существующим SupplierItem по SKU, When показан результат, Then видно «было $X → стало $Y (+Z%)».
- Given пользователь не нажал «Применить», When закрывает экран, Then ни одна цена не изменилась (статус остаётся `review`).
- Given применение, When выбраны 40 строк, Then создаются новые записи SupplierItem с `valid_from = сегодня`, старые получают `valid_to`; в AuditLog одна запись на импорт со списком изменений; изменения записаны в `ImportRow.before/after` для отмены (CAT-US-17).

**CAT-US-11**
- Given минимальная маржа компании 35%, When применение импорта поднимает себестоимость fixed-позиции так, что маржа становится 28%, Then в итоге импорта эта позиция в списке «ниже порога» с действием «поднять цену».

**CAT-US-12**
- Given нет сети, When tech ищет «elbow», Then поиск работает по локальной копии каталога, без поля себестоимости.

**CAT-US-13**
- Given owner в двух компаниях, When копирует каталог из A в B, Then в B создаются новые записи (новые id, `company_id = B`), поставщики копируются без номеров аккаунтов, действие в AuditLog обеих компаний.

**CAT-US-14**
- Given камера «Ценник», When снят ценник «K-Style Gutter Elbow A 2×3 White — $11.03», Then AI возвращает 1 строку (название, SKU/Internet #, цена, единица, признак «цена с налогом»), сопоставление с каталогом и поставщиком «Home Depot» (по SKU, иначе по названию и атрибутам) и diff «было $X → стало $Y» за ≤ 5 с (p90) в сети.
- Given на ценнике цена без налога (как обычно в США), Then она сохраняется как есть; Given признак «с налогом» (например, Mexico), Then цена без налога вычисляется по ставке поставщика (`18` TX19).
- Given снято без сети, Then фото сохраняется, распознавание — при появлении сети, push «Ценник распознан, проверьте».

**CAT-US-15**
- Given сопоставление колонок при первом импорте от ABC Supply, When пользователь нажимает «Сохранить шаблон», Then создаётся `ImportMapping` (поставщик, формат, лист/путь, колонки → поля, единицы, «цены с налогом да/нет», разделитель десятичных); следующий файл с теми же заголовками сопоставляется автоматически, пользователь видит «Шаблон: ABC Supply (CSV)» и может поправить.
- Given заголовки файла изменились (новая колонка, переименование), Then шаблон предлагается, а несопоставленные колонки подсвечены.

**CAT-US-16**
- Given импорт 300 строк, When diff готов, Then вкладки-счётчики: «Новые 12 · Цена выросла 141 · Цена снизилась 37 · Без изменений 96 · Не сопоставлено 9 · Ошибки 5»; по умолчанию выбраны новые и изменённые с confidence ≥ 0.8 и изменением ≤ ±25%; групповые действия: «выбрать класс», «снять подозрительные (> ±25%)», фильтр по категории/поставщику, сортировка по % изменения; «Применить выбранные (178)» одной кнопкой.
- Given применение 300 строк, Then выполняется в одной транзакции за ≤ 10 с, итог: N обновлено, M новых, K позиций cost-plus меняют цену клиенту (список), L позиций ниже порога маржи.
- Given «Не сопоставлено», When пользователь выбирает позицию каталога вручную или «создать новую», Then строка переходит в класс «новая» / «цена изменилась»; ручное сопоставление запоминается в `ImportMapping.sku_aliases` для следующих импортов.

**CAT-US-17**
- Given импорт применён, When owner нажимает «Отменить импорт» (≤ 30 дней), Then все изменения импорта откатываются: новые SupplierItem/CatalogItem архивируются, закрытые `valid_to` возвращаются, цены cost-plus пересчитываются обратно, статус `undone`; сметы, PO и инвойсы, уже созданные по новым ценам, **не меняются** (снимки).
- Given после импорта пользователь вручную изменил 3 из затронутых записей, When «Отменить», Then предупреждение «3 записи изменены после импорта: оставить их как есть / откатить тоже»; по умолчанию оставить.

**CAT-US-18**
- Given файл каталога (name, kind, unit, price, cost, material cost, sku, category, taxable, attributes.*), When импорт в каталог, Then сопоставление с существующими позициями по `sku`, иначе по `seed_key`, иначе по нормализованному имени + unit; классы как в CAT-US-16; цены и себестоимость — без налога.
- Given файл клиентов (name, phone, email, address, tags, source), When импорт, Then дубли ищутся по `match_key` (телефон/email) и нормализованному адресу; классы: новый клиент / обновление / возможный дубль / ошибка; согласие на SMS из файла **не включает** `sms_opt_in` без колонки согласия и явного подтверждения owner (`consent_source = import`, TCPA, `00-decisions-for-founder.md` Б3).

**CAT-US-19**
- Given открытая черновая смета и CSV строк (option, group, name, qty, unit, price, cost, taxable, catalog sku), When «Импорт строк», Then строки добавляются в выбранный вариант черновика (`origin = manual` или `catalog` при совпадении SKU), итоги считает движок; отправленные версии не меняются.
- Given файл архива смет (номер, клиент, адрес, дата, статус, итог, строки), When импорт архива, Then создаются сметы `created_via = import` с одной заблокированной версией (только чтение, без портала и без отправки); они участвуют в истории объекта и в «похожих сметах» AI (`15` §7.3), но не в отчётах выручки.

**CAT-US-20**
- Given каталог 400 позиций, When «Экспорт XLSX», Then файл в том же формате, что принимает импорт (round-trip: выгрузил → поправил в Excel → загрузил → diff только по изменённым ячейкам); колонки себестоимости — только при праве `can_view_cost`.
- Given фильтр инвойсов «октябрь», When «Экспорт PDF», Then ZIP с PDF каждого документа (те же неизменяемые PDF, что видел клиент) + CSV-оглавление; Given > 500 документов или > 5,000 строк, Then фоновой задачей `DataExport`, ссылка на email (§7.7.6).

**CAT-US-21**
- Given поставщик создан, Then у него поле «Налог при покупке» (по умолчанию ставка компании, заглушка «LA area 10.25% — проверить»); все `SupplierItem.cost_cents` без налога (`19` §7.6, §7.10).

**CAT-US-22**
- Given смета содержит строки с `is_placeholder_price = true`, When «Отправить», Then предупреждение «В смете 6 строк с тестовыми ценами» с кнопками «Проверить» и «Отправить всё равно» (не блокирует); факт в AuditLog.

## 6. Экраны
| Экран | Телефон | Планшет / веб |
|---|---|---|
| Каталог (список) | Поиск, фильтр по kind/модулю, строка: имя, цена/ед., (себестоимость и маржа по правам) | Таблица с массовым редактированием цен (±%), сортировка по марже |
| Позиция | Имя, описание для клиента, kind, unit, цена, себестоимость, cost-plus, taxable (подпись «облагается, если налог включён на документе»), поставщик, атрибуты (профиль, gauge, цвет) | То же + история цен, где используется |
| Сборки | Список, просмотр компонентов и констант, правка констант | Редактор формул с подсветкой, тест-панель «входы → выходы», тест-кейсы |
| Поставщики | Карточка: email для заказов, телефон, аккаунт, филиалы | + список SupplierItem, история цен |
| Импорт (прайс, каталог, клиенты, сметы) | Камера (прайс / ценник) / файл → прогресс → diff карточками с групповыми действиями | Мастер: файл → лист/путь → сопоставление колонок (шаблон поставщика) → diff-таблица (класс, было/стало, %, confidence, сопоставление) → «Применить выбранные» → итог и «Отменить импорт» |
| Ценник | Камера с рамкой, результат одной карточкой «было → стало», «Применить» | — |
| История импортов | Список: что, когда, кто, сколько строк, статус, «Отменить» | То же + скачать исходный файл и отчёт ошибок CSV |
| Экспорт | Выбор сущности, формат (CSV / XLSX / PDF), фильтр | То же + история экспортов (`DataExport`) |
| Price book модуля | Баннер «тестовые цены: N позиций» с действиями «Загрузить прайс», «Сканировать прайс», и список изменений версии | То же + фильтр «только тестовые» |

## 7. Бизнес-правила и расчёты
### 7.1 Единицы
`LF`, `SF`, `SQ`, `ea`, `hr`, `day`, `flat` (из модели). Количество `numeric(10,3)`. `flat` всегда количество 1. Единица позиции каталога и единица поставщика разные: связь через `SupplierItem.pack_size` = сколько единиц каталога в одной единице поставщика (коробка 50 hangers → 50; coil: LF в одном рулоне/фунте, вводится пользователем).

### 7.2 Цена и себестоимость
- Все деньги в целых центах. Округление везде одно: **round half up** (0.5 цента → вверх).
- **Все цены и себестоимость в каталоге и у поставщиков хранятся без налога** (решение основателя). Налог клиенту добавляется или выделяется режимом документа, налог при покупке — по ставке поставщика (`19-taxes.md` §7.5–7.6).
- `unit_material_cost_cents` — часть себестоимости, купленная у поставщика (база налога при покупке): `material` — вся себестоимость, `labor`/`fee` — 0, `service` — задаётся на позиции (в стартовом price book — для позиций «материал + работа», §7.5).
- `fixed`: цену вводит пользователь.
- `cost_plus`: `unit_price_cents = round_half_up(unit_cost_cents × (1 + markup_bps / 10000))`. Наценка (markup) задаётся от себестоимости; на экране рядом показывается маржа: `margin = (price − cost) / price`.
- Маржа позиции = `(price − cost) / price`, показывается с 1 знаком. При `price = 0` (внутренние BOM-позиции) маржа не показывается.
- Минимальная маржа компании (`min_margin_bps`, по умолчанию 3500) — порог предупреждений в каталоге и сметах.
- Изменение каталога **никогда** не меняет существующие строки смет: строки хранят снимок цены и себестоимости.

### 7.2a Налог и флажок `taxable`
- Налог в Octo **никогда не считается автоматически** (решение основателя, `04-domain-model.md` §6, `19-taxes.md`). `CatalogItem.taxable` — только значение по умолчанию для флажка `taxable` строки документа; налог появляется, только если режим профиля документа его предусматривает (`added_on_top` / `tax_inclusive_display`) и пользователь включил его на смете / варианте / инвойсе / change order.
- Новая позиция получает `taxable` по `default_taxable_scope` профиля по умолчанию (`TaxProfile`): `all` → да; `materials_only` → да только для `kind = material`; `none` → нет. Пользователь меняет флажок на позиции и на строке документа.
- Стартовый LA price book (§7.5) поставляется с `taxable = false` для всех позиций: материалы в нём «зашиты» в видимые service-строки, а BOM-строки имеют цену 0, поэтому «только материалы» без отдельных видимых материальных строк ничего не обложит. Что облагать для монтажа в CA, решает подрядчик с бухгалтером (`00-decisions-for-founder.md`).

### 7.3 Сборки и формулы (детерминированный движок)
- Язык формул: числа, переменные входа и констант, `+ − × /`, скобки, `ceil`, `floor`, `round`, `min`, `max`, `if(cond, a, b)`, сравнения, `and/or/not`. Без циклов, без вызовов внешнего мира.
- Арифметика **decimal**, не float. Один и тот же движок (общий пакет TypeScript) работает на телефоне офлайн и на сервере; у движка есть `engine_version`, она пишется в версию сметы.
- Порядок: входы → константы (по умолчанию модуля, переопределения компании) → вычисляемые переменные в порядке зависимостей (цикл = ошибка сохранения) → `quantity_formula` каждого компонента → `condition` (если false, строки нет) → строки сметы.
- Выбор позиции компонента: фиксированный `catalog_item_id` **или** селектор по атрибутам (`kind = gutter, profile = $profile, gauge = $gauge`). Если селектор не нашёл позицию, расчёт останавливается с ошибкой «нет позиции K6 .032 в каталоге», а не подставляет что-то похожее.
- Количество меньше или равно 0 → строка не создаётся.
- Изменение формулы или констант действует только на новые расчёты. Пересчёт черновика сметы по новым правилам — явная кнопка с показом разницы.
- Каждая сборка хранит тест-кейсы (входы → ожидаемые количества). Сид-сборки поставляются с тест-кейсами из `06-gutters-module.md` §7.

### 7.4 Поставщики и позиции поставщика
> **Заменено спекой `docs/specs/36-suppliers.md` (08.11.2026, руководитель принял):** отдельной таблицы `SupplierItem` с версиями нет. Позиция ссылается на основного поставщика (`catalog_items.supplier_id`, `supplier_sku`); себестоимость — одна, в `catalog_item_costs` (#383); история цены — журнал `catalog_cost_history` (триггер); фасовка — `purchase_unit`, `pack_size` позиции (C3); ставка поставщика `suppliers.purchase_tax_bps` копируется в `vendor_tax_bps` позиции. Правила ниже читать через эту замену.
- SupplierItem версионируется: смена себестоимости = новая запись с `valid_from`, старая получает `valid_to`. Текущая = `valid_to IS NULL`.
- `CatalogItem.supplier_item_id` указывает основного поставщика. Смена основного поставщика не меняет `unit_cost_cents` позиции автоматически: показывается предложение «обновить себестоимость с $X до $Y».
- Обновление себестоимости позиции из SupplierItem: `unit_cost_cents = round_half_up(supplier_cost_cents / pack_size)`.
- `SupplierItem.cost_cents` — **всегда без налога**. У поставщика (и при необходимости у филиала) — ставка налога при покупке `purchase_tax_rate_id` (по умолчанию ставка компании, заглушка «LA area 10.25% — проверить»; в разных городах разная, например Santa Monica). Налог при покупке добавляется к себестоимости материалов в сметах и PO по настройке профиля (`19-taxes.md` §7.6), а не хранится в цене.

### 7.6 AI-скан прайса и ценника: конвейер (MVP)
```
upload (фото / PDF / скриншот / ценник / ответ RFQ) → parsing (AI) → matching (без AI) → review (diff, человек) → applying → applied → (undone)
                                                                                                    ↘ failed | cancelled
```
1. Файл сохраняется как `File(kind=document)`, создаётся `ImportJob(target = supplier_prices, source_kind = photo | pdf | screenshot | shelf_tag)`. CSV/XLSX/XML/JSON идут через сопоставление колонок без AI (§7.7).
2. AI возвращает строки строго по схеме: `supplier_sku, name, unit_text, pack_size, price, price_includes_tax, confidence по полям, page, bbox`, плюс итоги документа (`subtotal`, `tax`, `tax_rate`, `total`), если они есть. Не по схеме → строка в «нераспознанные» с фрагментом картинки.
   - **Модель и скорость:** ценник и прайс до 20 страниц — обычный (синхронный) вызов Sonnet, цель ≤ 5 с для ценника и ≤ 2 мин для 10 страниц; Batch API (−50%, но ответ до 24 ч) — только для больших не срочных файлов (> 20 страниц) по выбору пользователя «дешевле, но позже». Себестоимость ориентир $0.03–0.10 за 5 страниц (`02a` §2).
3. **Налог (решение основателя, `19` §7.10):** цены сохраняются без налога. Если налог указан только внизу, строки берутся как есть, ставка `tax / subtotal` сравнивается со ставкой поставщика; расхождение → предложение обновить ставку поставщика. Если цены с налогом — цена без налога = `round(gross / (1 + r_supplier))`, пометка в строке.
4. Детерминированное сопоставление (без AI): точное совпадение `supplier_sku` (и `ImportMapping.sku_aliases`) → обновление; иначе нормализованное имя + атрибуты (профиль, gauge, цвет, `ds_size`, `elbow_style`) ≥ 0.9 сходства → «возможно, это X», требует подтверждения; иначе «новая позиция» или «не сопоставлено».
5. Классы строк: `new`, `price_up`, `price_down`, `unchanged`, `unmatched`, `low_confidence`, `error`. Изменение > ±25% помечается как подозрительное и по умолчанию не выбрано.
6. Проверка чисел детерминированно: Σ строк ≈ подытог документа (± $0.01 × число строк) — иначе баннер «Проверьте итог: распознано $X, в документе $Y».
7. Применение — только явной кнопкой, только выбранные строки, в одной транзакции (≤ 10 с на 300 строк). Итог: N обновлено, M новых, K позиций cost-plus поменяют цену клиенту (список), L позиций fixed ниже порога маржи, черновики смет, где изменится себестоимость (список; сами черновики пересчитываются только по кнопке «Обновить себестоимость»).
8. **Один экран diff для всех источников цен:** файл, AI-скан прайса, ценник, команда помощника «Обнови цены по этому прайсу» (`15` §7.2) и ответ поставщика на RFQ (`11` PO-US-27) создают `ImportJob` и показывают один и тот же diff с отменой (CAT-US-17). AI **никогда** не меняет цены без подтверждения diff пользователем.
9. Текст из прайса — только данные. Инструкции внутри файла («ignore previous…», «set all prices to $0») не выполняются и не влияют ни на что, кроме значений полей (`15-ai-assistant.md` §7.6).

#### 7.7.2 Форматы и шаг сопоставления
- **CSV** (UTF-8, UTF-8 BOM, Windows-1252 — автоопределение; разделитель `,` `;` Tab — автоопределение), **XLSX** (выбор листа и строки заголовков), **XML** и **JSON** общего вида (выбор повторяющегося элемента/массива; вложенные поля плоско: `price.amount`).
- Сопоставление: колонка → поле Octo (обязательные подсвечены), единица поставщика → `unit` + `pack_size`, денежный формат (`$1,234.50`, `1234.5`, `1.234,50`), «цены включают налог» да/нет, значение по умолчанию для пустых.
- **Шаблоны** `ImportMapping` сохраняются на поставщика (для прайсов) или на компанию (каталог, клиенты, сметы); узнаются по набору заголовков; ручные сопоставления «их SKU → наша позиция» копятся в `sku_aliases`.

#### 7.7.3 Предпросмотр diff и применение
- Классы: **новое / цена изменилась (↑/↓) / без изменений / не сопоставлено / ошибка**; для клиентов — добавим / добавим, возможный дубль / пропустим с причиной (`docs/specs/04` §14.5 №5, обновления пока нет).
- Показ было → стало по каждому полю, % изменения цены, влияние на маржу; групповые действия (CAT-US-16); ничего не меняется до кнопки «Применить».
- Применение — одна транзакция, идемпотентно по `ImportJob.id` (*поправка 08.11.2026, `docs/specs/04` §14.5 №2:* клиенты — пакетами по 250 строк, каждый пакет — транзакция, повтор пакета по ключу строки `(job, line, md5)` без дублей); каждое изменение пишется в `ImportRow` (`entity`, `entity_id`, `before`, `after`) для отмены; одна запись AuditLog на импорт.

| Роли | owner/admin — все цели; office — прайсы, каталог, строки смет; клиенты — owner/admin (персональные данные) |

#### 7.7.5 Ошибки и идемпотентность
- Ошибки строк не останавливают импорт: строка с ошибкой в классе `error` с причиной (нет обязательного поля, цена не число, отрицательная цена, неизвестная единица, дубль SKU внутри файла, слишком длинное поле); «Скачать ошибки CSV» с исходной строкой и причиной.
- Ошибка файла (не читается, пустой, > лимитов, формулы-макросы) → `failed` с понятной причиной; AI-действие не списывается.
- Повторная загрузка того же файла (тот же SHA-256 + цель + поставщик) → «Этот файл уже импортирован 03.11 в 14:20 (применено 178 строк)», можно открыть прошлый импорт или загрузить заново (всё будет «без изменений»).
- Значения ячеек — только данные: формулы не вычисляются; CSV-инъекции (`=`, `+`, `-`, `@` в начале) экранируются при экспорте (`../08-security.md`).

#### 7.7.6 Экспорт
| Сущность | Форматы | Примечание |
|---|---|---|
| Каталог (price book) | CSV, XLSX | Формат = формат импорта (round-trip); себестоимость — по праву `can_view_cost` |
| Клиенты (с контактами и объектами) | CSV, XLSX | owner/admin; `gate_code` не выгружается по умолчанию (`03`) |
| Сметы (строки) | CSV, XLSX | По строке: смета, версия, вариант, группа, позиция, кол-во, цена, сумма, taxable; себестоимость — по праву |
| Инвойсы | CSV, XLSX | Итоги, налог (по режиму), оплаты, баланс |
| Расходы | CSV, XLSX (+ ZIP фото чеков, `10` EXP-US-11) | Сумма, налог чека отдельно |
| Сметы, инвойсы, PO | PDF (по одному или ZIP по фильтру) | Те же неизменяемые PDF, что видел клиент / поставщик |
- До 5,000 строк / 500 PDF — сразу; больше — фоновой задачей `DataExport` со ссылкой на email (7 дней). Полный экспорт компании — `01` ACC-US-10.

## 8. AI-помощник
| Команда | Поведение | Подтверждение |
|---|---|---|
| «Найди позицию elbow», «сколько стоит 6-дюймовый гаттер» | Поиск и ответ из каталога, цена из базы | нет |
| «Подними цены на guards на 10%» | Предпросмотр: список позиций было → стало | да (деньги) |
| «Вот прайс ABC Supply» + фото, «Обнови цены по этому прайсу» | `catalog.price_import`: запуск ImportJob, затем тот же экран diff (§7.6) | применение только кнопкой на diff (T2) |
| Фото ценника + «обнови цену» | ImportJob `shelf_tag`, одна строка diff | кнопка (T2) |
| «Поставь шаг hangers 18 дюймов» | Предпросмотр изменения константы и пример влияния на типовую смету 150 ft | да |
AI не создаёт цены из головы: если позиции нет, он предлагает создать её с пустой ценой, которую вводит человек (или цена приходит из распознанного прайса и видна в diff). MVP помощника: поиск по каталогу, «обнови цены по этому прайсу / ценнику» и «подними цены на X%» — все через diff с подтверждением (`15` §7.2).

## 9. Офлайн
- Весь каталог, сборки, константы и текущие SupplierItem хранятся на телефоне (движок смет считает офлайн).
- Себестоимость не загружается на устройства ролей без права её видеть (фильтр на уровне синхронизации, а не только UI).
- Правка позиций офлайн: owner/admin/office, слияние по полям; конфликт цены (две правки одной цены) → побеждает последняя по серверному времени, проигравшее значение в истории позиции.
- Импорт файлов, AI-скан и редактор формул требуют сети. Фото прайса или ценника без сети сохраняется и распознаётся при появлении сети (push «проверьте»).

## 10. Уведомления и автоматизации
- Импорт распознан → push «Прайс ABC Supply готов к проверке: 212 строк, 9 требуют внимания».
- После применения импорта: если есть позиции ниже минимальной маржи → задача owner «Проверить цены: 6 позиций ниже 35%».
- Новая версия price book модуля → баннер в каталоге (без авто-применения).
- Себестоимость SupplierItem не обновлялась > 180 дней → мягкое напоминание раз в месяц.

## 11. Ошибки и крайние случаи
| Случай | Поведение |
|---|---|
| Двойное нажатие «Применить» в импорте | Применение идемпотентно по `ImportJob.id`; второй вызов возвращает тот же результат |
| Удаление позиции, которая используется в сборке | Запрещено, показать сборки. Можно архивировать (`is_active = false`): не предлагается в новых сметах, старые не трогаются |
| Удаление поставщика с открытыми PO | Только архив |
| Формула делит на ноль (шаг = 0) | Ошибка валидации константы; в рантайме → расчёт остановлен с понятной ошибкой, смета не создаётся |
| Плохое фото прайса (размыто) | `failed` с причиной и советом переснять; AI-действие не списывается с лимита при ошибке на нашей стороне |
| PDF > 20 страниц | Обрабатывается частями, прогресс по страницам |
| Валюта не USD в прайсе | Строка `low_confidence`, не применяется по умолчанию |
| Нет прав на себестоимость | API не отдаёт поля cost (проверка на сервере и в RLS-представлении) |
| Позиция с одинаковым SKU у двух поставщиков | Допустимо: SKU уникален в рамках поставщика |
| Один SKU дважды в файле с разными ценами | Обе строки в `error` «дубль SKU в файле», остальной файл применяется |
| Отмена импорта после того, как по новым ценам отправлены сметы | Отменяются только каталог и SupplierItem; сметы остаются на снимке, в итоге отмены список «смет с ценами отменённого импорта» |
| Ценник с акционной ценой («Was $12.98 Now $9.98») | Берётся текущая цена, строка помечена «акция», по умолчанию не выбрана |
| Прайс с ценами за упаковку, а каталог в штуках | `pack_size` из шаблона или распознан («box of 50»); без него строка `low_confidence` |
| Ставка налога в прайсе не совпадает со ставкой поставщика | Предложение обновить ставку (`19` §7.10), без автоматической смены |

## 13. Метрики
- Время от включения модуля до первой посчитанной сметы (baseline на бете, цель < 30 мин).
- Доля смет, где все строки из каталога или сборки, а не свободные строки (цель > 80%).
- Доля смет ниже минимальной маржи, отправленных клиенту (цель < 5%).
- Импорт прайса: доля строк, принятых без ручной правки (цель > 90% после доводки), время на проверку 100 строк.
- Возраст себестоимости: доля позиций с SupplierItem моложе 90 дней.
- Доля позиций с тестовой ценой у активных компаний (цель → 0 к первой реальной смете).
- Импорт 300 строк: время от загрузки до применения (цель ≤ 10 мин), доля отменённых импортов.
- Ценник: время «фото → применено» (цель ≤ 20 с).
