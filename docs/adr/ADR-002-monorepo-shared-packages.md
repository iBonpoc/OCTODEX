# ADR-002. Монорепозиторий и общие пакеты

- **Статус:** Proposed — needs founder/tech review
- **Дата:** 03.11.2026
- **Связано:** `06-architecture.md` §3, ADR-001, ADR-005, ADR-008

## Контекст
Один и тот же код нужен в трёх средах исполнения: Hermes (iOS), браузер/Node (Next.js), Deno (Edge Functions). Критично общее: типы сущностей, state machines, права, деньги, движок смет, геометрия гаттеров, токены. Разработка вертикальными срезами «база → API → веб → iOS → тесты» (`00-roadmap.md` п. 4) требует видеть все слои в одном PR.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Один монорепозиторий: pnpm workspaces + Turborepo** | Атомарные PR через все слои; общие пакеты без публикации; кэш сборок; простой контекст для AI-ассистентов | Нужна дисциплина границ (eslint-правила импортов); настройка Metro/Expo для монорепо |
| B. Nx | Мощные генераторы и граф зависимостей | Тяжелее, больше «магии»; для 3 приложений избыточно |
| C. Несколько репозиториев + приватные npm-пакеты | Чёткие границы | Версионирование общих пакетов, рассинхрон движка смет между телефоном и сервером — прямой риск для денег |

## Решение
**Вариант A** [Совет]. Структура — `06-architecture.md` §3. Ключевые правила:
1. `packages/domain`, `estimating-engine`, `gutters`, `design-tokens` — **чистый TypeScript без зависимостей от платформы** (нет React, Supabase, `fetch`, `Date.now()` внутри расчётов). Проверяется eslint-правилом и тестом сборки под Deno и Hermes.
2. Типы сущностей **генерируются из схемы БД** (`supabase gen types`) и дополняются zod-схемами в `domain` — одна правда для API, форм, AI-инструментов и импорта.
3. State machines описаны данными (таблица переходов) в `domain`; из неё генерируется SQL-функция проверки переходов для миграций.
4. `packages/api` — модульный монолит (модули владеют своими таблицами, общаются через сервисы и доменные события). Тонкие входы в `supabase/functions/*` только импортируют его.
5. `packages/api-client` — типизированный клиент (Hono RPC или OpenAPI) с обязательным `idempotency_key` для команд.
6. UI: `ui-web` и `ui-native` — разные реализации одних компонентов, оба только на токенах (ADR-008).
7. Версия движка смет (`engine_version`) = версия пакета; телефон отправляет её с расчётом.

## Последствия
- ✅ Изменение формулы или правила денег — один PR, одни тесты для телефона и сервера.
- ✅ AI-инструменты строятся из тех же zod-схем, что и API (ADR-006).
- ⚠️ Metro + pnpm: нужна настройка (`node-linker=hoisted` или конфиг Metro под symlink) — задача Sprint 0.
- ⚠️ Мобильное приложение в сторах живёт дольше, чем сервер: API поддерживает операции от версий приложения ≥ 2 назад (`16` §11), а изменения общих пакетов, влияющие на протокол, — с версией протокола.
