# ADR-008. Конвейер дизайн-токенов

- **Статус:** Proposed — needs founder/tech review
- **Дата:** 03.11.2026
- **Связано:** `09-design-system.md` («Токены: всё через них»), ADR-002, Style Lab (`design/*.html`)

## Контекст
Правило основателя: ни одного «зашитого» цвета, размера, отступа, радиуса, шрифта, анимации; изменили токен — изменилось везде: веб, iPhone, Android, портал, PDF. Три уровня (primitive → semantic → component), темы (светлая/тёмная), стили (Copper Glass, Daylight…), плотность (`density.compact`), Reduce Motion / Reduce Transparency. Потребители: Next.js + Tailwind (веб, портал), React Native (Reanimated-пружины, blur), PDF смет/инвойсов/нарядов, email-шаблоны.

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. W3C DTCG JSON → Style Dictionary → платформенные выходы** | Стандартный формат; Style Dictionary поддерживает DTCG и свои трансформы; один источник | Нужно написать трансформы под RN (пружины, тени, blur) |
| B. Tokens Studio (Figma) как источник | Удобно дизайнеру | Источник правды вне git; у нас нет отдельного дизайнера в Figma |
| C. TS-объект как источник, CSS генерируем из него | Просто для разработчика | Не стандарт; сложнее инструментам дизайна и AI-генерации |

## Решение
**Вариант A** [Совет]:
1. **Источник:** `packages/design-tokens/tokens/**/*.json` в формате W3C Design Tokens (DTCG: `$value`, `$type`, ссылки `{color.copper.500}`). Наборы-переопределения: `themes/{light,dark}`, `styles/{copper-glass,daylight-glass,…}`, `density/compact`, `a11y/{reduce-motion,reduce-transparency}`.
2. **Сборка:** Style Dictionary (актуальная major-версия с поддержкой DTCG [Проверить номер на Фазу 4]) с нашими трансформами →
   - **веб/портал:** CSS-переменные (`:root`, `[data-theme=dark]`, `[data-style=…]`, `[data-density=compact]`) + Tailwind v4 `@theme` (CSS-first) — классы ссылаются на переменные, переключение темы без пересборки;
   - **React Native:** TS-модуль `theme.ts` (числа в pt, цвета, тени для iOS, параметры пружин `{response, dampingFraction}` для Reanimated, уровни blur) + типы;
   - **PDF/email:** тот же TS-модуль (бренд компании подставляется поверх `color.brand.*`).
3. **Компоненты** используют только semantic/component-токены; primitive — запрещены в коде (eslint-правило и stylelint: запрет hex/px-литералов в `apps/*` и `ui-*`).
4. **Бренд компании** (логотип, цвет для документов и портала) — runtime-переопределение `color.brand.*`, с автоматической проверкой контраста ≥ 4.5:1 (`09` правило 1); при провале — подбирается безопасный оттенок.
5. **Проверки в CI:** валидация схемы DTCG, контраст всех пар text/surface в обеих темах, снапшот-тесты компонентов в двух темах и в «Компакт».
6. **Style Lab** переводится на сгенерированные CSS-переменные — живая витрина токенов.

## Последствия
- ✅ «Сделай все кнопки ниже» = правка `button.height.*` в одном JSON (`09` примеры).
- ✅ Тёмная/светлая темы и стили — наборы значений, без форков компонентов.
- ⚠️ Стекло и blur на RN — нативные эффекты; токен задаёт параметры, а при Reduce Transparency компонент рисует сплошную поверхность (`09` правило 2).
- ⚠️ Нужен выбор стиля основателем (А1) до фиксации semantic-слоя; primitive-слой можно начинать сразу.
