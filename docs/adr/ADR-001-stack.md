# ADR-001. Стек: Expo React Native + Next.js + Supabase

- **Статус:** Proposed — needs founder/tech review
- **Дата:** 03.11.2026
- **Связано:** `06-architecture.md` §2, ADR-002, ADR-003

## Контекст
- Маленькая команда, разработка с AI-ассистентами; нужен один язык и максимум общего кода.
- Платформы: iOS первым (iPhone + iPad), веб для офиса/планшета, публичный портал и SEO-страницы, Android позже (`02` §10).
- Обязательны: офлайн в поле (`16`), один и тот же расчёт смет на телефоне и сервере (`05`, `06`), изоляция компаний в базе (RLS), деньги через Stripe.
- Бюджет инфраструктуры на старте — десятки долларов в месяц (`02a` §7).

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Expo RN + Next.js + Supabase (TS везде)** | Один язык; общие пакеты (domain, движок смет, токены); Android почти бесплатно; EAS Build/Update; Postgres + RLS + Auth + Storage «из коробки»; готовая интеграция PowerSync; дёшево на старте | Нативные эффекты (стекло, drag & drop) требуют аккуратности (Reanimated, нативный blur); зависимость от Supabase как платформы; Edge Functions имеют лимиты времени |
| B. Нативный Swift (iOS) + Next.js + Supabase | Лучший нативный UX и доступ к iOS API | Движок смет пришлось бы писать дважды (Swift и TS) или гонять через JS-движок; Android — третья кодовая база; меньше общего кода с вебом |
| C. Flutter + отдельный бэкенд | Один UI-код на iOS/Android | Веб/портал/SEO всё равно на другом стеке; Dart не делится с сервером; меньше готовых интеграций (Stripe Terminal, PowerSync есть, но экосистема веба отдельно) |
| D. Expo + Next.js + свой бэкенд (Node + managed Postgres, своя авторизация) | Полный контроль, нет лимитов Edge Functions | Больше работы на старте: auth, storage, бэкапы, RLS-обвязка — то, что Supabase даёт готовым |

## Решение
**Вариант A** [Совет]:
- **Мобильное:** Expo, актуальный SDK на старте Фазы 4 (сейчас SDK 55: RN 0.83, только New Architecture — [Факт] F8), Expo Router, EAS Build/Submit/Update, development build (не Expo Go — нужны op-sqlite/SQLCipher и Stripe Terminal).
- **Веб:** Next.js 16 (App Router, Turbopack, Cache Components — [Факт] F9), Tailwind v4, shadcn/ui; два приложения — `apps/web` (вошедшие пользователи) и `apps/portal` (публичное: SEO, портал клиента, наряд субподрядчика).
- **Бэкенд:** Supabase (Postgres, Auth: email OTP + Sign in with Apple, Storage, Edge Functions, Cron, Queues). Доменная логика — **модульный монолит** `packages/api` на Hono, который запускается в Edge Functions (Deno) и, без изменений, на Node (запасной путь, если упрёмся в лимиты).
- **Сборка и хостинг:** Vercel для `web` и `portal`; EAS для iOS.

## Последствия
- ✅ Движок смет, state machines и матрица прав пишутся один раз (ADR-002, ADR-005).
- ✅ Android в Фазе 8 — в основном работа над UI-полировкой, а не новая кодовая база.
- ⚠️ Нативные ощущения (стекло, пружины, тактильный отклик) требуют прототипа на реальном iPhone в Sprint 0 — проверка Шлюза 4.
- ⚠️ Привязка к Supabase смягчается: всё в стандартном Postgres + SQL-миграциях, API не зависит от Supabase-специфичных клиентов, кроме auth/storage-адаптеров. Выход — любой managed Postgres + Node.
- ⚠️ Лимиты Edge Functions [Проверить на дату реализации]: тяжёлые задачи (PDF, экспорт, пачки AI) планируем сразу как воркеры, которые можно перенести на Node-хостинг.
- Нужен `08-security.md`: хранение секретов, service role только на сервере.

## Поправка 04.11.2026: одно универсальное приложение
- **Статус поправки:** Accepted (решение принято при старте сборки, `docs/10-build-plan.md` §1; основатель может пересмотреть).
- Кабинет для вошедших пользователей (`apps/web` на Next.js) **не делаем отдельно**. Одно приложение `apps/mobile` на Expo Router работает на iPhone, iPad, Android и в браузере (react-native-web). Причина: основатель работает с телефона, планшет и десктоп нужны минимально; один код дешевле и не расходится.
- Next.js остаётся только для публичной части (`apps/portal`: SEO-страницы, портал клиента, наряд субподрядчика) — там нужен серверный рендер для поиска.
- Фактические версии на старте: Expo SDK 58, React Native 0.88, React 19.3, Expo Router 58, Reanimated 4.
- Пакеты из `packages/*` пишутся как ESM TypeScript с импортами `./x.js`; Metro сопоставляет их с `.ts` через `apps/mobile/metro.config.js`.
