# ADR-006. Архитектура AI-помощника на Claude

- **Статус:** Proposed — needs founder/tech review
- **Дата:** 03.11.2026
- **Связано:** PRD `15-ai-assistant.md`, `04-domain-model.md` §8 (AiAction), `02a` §2, §6, `06-architecture.md` §9, §10.5; будущий `07-ai-assistant.md`

## Контекст
- Помощник — **оператор**, а не чат: превращает голос/текст/фото в те же операции, что пользователь сделал бы руками, с его правами; предпросмотр (diff) → подтверждение → отмена (`02` §2 п. 4, `15`).
- Уровни T0/T1/T2, whitelist операций на intent, деньги/отправка/удаление — только кнопкой (`15` §7.2).
- Данные клиентов (SMS, письма, чеки, прайсы) не должны становиться командами (`15` §7.6).
- Себестоимость: типичная компания ~$4–5/мес, лимиты Starter 100 / Pro 1,000 действий (`02a`).
- [Факт] Цены: Sonnet 5.5 $2/$10 за 1M (кэш $0.20), Haiku 5.5 $0.10/$0.50 (≤100K), Batch −50%; на Sonnet 5.5 нельзя принудительный `tool_choice` (`any`/`tool`) — только `auto`; есть `strict: true` у инструментов и structured outputs (F17).

## Варианты
| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. Свой детерминированный конвейер на Claude API: модель планирует, сервер исполняет** | Полный контроль прав, предпросмотра, отмены, стоимости; модель не имеет доступа к базе | Больше своего кода (оркестрация, схемы) |
| B. Свободный агент с инструментами-CRUD (агентный цикл «пока есть tool_use») | Гибко, быстро в прототипе | Непредсказуемая цена и число шагов; трудно гарантировать «одна T2-операция», предпросмотр до записи; шире поверхность для injection |
| C. Managed Agents / хостинг-агент | Не пишем цикл | Наши инструменты всё равно у нас; лишняя инфраструктура и задержка для коротких команд |
| D. MCP-сервер над нашим API | Стандартный протокол, пригодится для внешних агентов | Для MVP — лишний слой; можно добавить позже поверх тех же операций |

## Решение
**Вариант A** [Совет]. Модуль `packages/api/ai`.

**Конвейер** (`15` §7.1):
1. **Устройство:** словарь навигации (`nav.open`, простые поиски) — без LLM, $0, офлайн.
2. **Router — Haiku 5.5**, structured output (`output_config.format`, JSON-схема `{intent, slots, confidence}`), вход — **только текст пользователя + контекст экрана** (тип/ID сущности). Данные из базы на этом шаге не передаются → intent нельзя «внушить» содержимым документов.
3. **Политика (код):** intent есть в каталоге и в MVP? разрешён роли (матрица `04` §1)? лимит `Entitlement`/`UsageCounter`, суточный потолок, анти-спам? Иначе — отказ с причиной.
4. **Разрешение сущностей — детерминированно** (SQL + trigram + фонетика, `15` §7.4), уточнение чипами.
5. **Planner — Sonnet 5.5** для `estimate.*`, Haiku 5.5 для остального. Инструменты = **операции whitelist'а этого intent'а** (например, для `estimate.update_lines`: `add_catalog_line`, `remove_line`, `set_quantity`, `move_line`), каждая со строгой схемой (`strict: true`, `additionalProperties: false`) из zod-схем `packages/domain`. `tool_choice: auto` + инструкция в системном промпте (принудительный выбор на Sonnet 5.5 недоступен, F17). Модель возвращает **план** — список вызовов; мы их **не исполняем на базе**, а собираем.
6. **Dry-run (код):** план исполняется доменными сервисами в транзакции с откатом + движок смет (ADR-005) → diff, итоги в центах, `assumptions` с источниками → `AiAction(proposed)`. Цены — только из каталога (ID позиций), числа пользователя сверяются с текстом ввода.
7. **Подтверждение:** T1 — «Применить» (голос «да» — только для черновиков, А28); T2 — отдельный диалог с суммой/получателем, только кнопка, одна T2-операция на действие.
8. **Apply:** повтор плана в транзакции с проверкой `entity_row_versions`; результат обязан совпасть с предпросмотром, иначе `failed`. `undo_payload` пишется сразу; AuditLog `actor_type=ai`, `on_behalf_of_user_id`.

**Границы prompt injection:**
- Внешние тексты (SMS, email, заметки, чеки, PDF, имена клиентов) передаются только в блоках-данных с меткой источника, после стабильного префикса; системное правило: инструкции из данных не исполняются.
- Intent фиксируется до загрузки данных; план с операциями вне whitelist отклоняется кодом.
- В MVP нет инструментов, которые выходят наружу (отправка SMS/email, URL); платежи, возвраты, void, роли, тарифы — инструментов нет вообще.
- Ответы модели валидируются схемой; всё вне схемы отбрасывается.
- Разбор писем лидов/RFQ (`06` §8) — отдельный вызов без инструментов, только structured output; применение — кнопкой человека.
- Red-team набор из `15` §7.6 — обязательный тест в CI (на записанных ответах) + ежемесячный прогон на живой модели.

**Маршрутизация и стоимость:**
| Задача | Модель | Режим |
|---|---|---|
| Router, `search`/`query.list`, `expense.attach`, `customer.create` | Haiku 5.5 | effort `low`, structured output |
| Чек → расход (vision) | Haiku 5.5 | structured output |
| `estimate.create/update_lines/set_option` | Sonnet 5.5 | effort `medium`, strict tools, ≤ 3 вызова на действие |
| Скан прайса (после MVP), черновики ответов поддержки | Sonnet 5.5 | Batch API (−50%) |
- **Prompt caching:** порядок `tools → system → сводка каталога компании` стабилен (отсортированный JSON, без времени в промпте); изменчивое — в конце. Проверяем `usage.cache_read_input_tokens` в метриках.
- **Учёт:** `tokens_in/out`, `cache_read`, `cost_cents`, `model` в каждом `AiAction` из `response.usage`; суточный бюджет на компанию и глобальный аварийный предел; алерт при превышении себестоимости.
- **Отказы модели** (`stop_reason: refusal`): серверный fallback Claude API (`fallbacks: "default"`) для Sonnet 5.5 [Проверить на дату реализации], иначе — понятная ошибка, лимит не списывается.
- **Данные:** в контекст не уходят `gate_code`, TIN/EIN, данные карт; себестоимость — только если роль её видит. Политика хранения у Anthropic и ZDR — вопрос для `08-security.md` и Б7.

## Последствия
- ✅ AI не может сделать то, чего не может пользователь; деньги и отправки — только кнопкой.
- ✅ Стоимость предсказуема: ≤ 3 вызова, фиксированный бюджет токенов, кэш.
- ⚠️ Каждый новый intent = whitelist операций + уровень T0/T1/T2 + тесты (в т.ч. red-team) — правило `15` §8.
- ⚠️ Голосовая навигация офлайн зависит от on-device распознавания iOS (`16` OFF-US-12).
- 🔁 MCP-сервер над теми же операциями — после MVP (интеграции с внешними агентами).
