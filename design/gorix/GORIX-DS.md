## 0. Как пользоваться

**Статус документа.** Черновик 2.0: вступает в силу, когда `CLAUDE.md` «Где что» укажет на этот файл. До этого действует Наряд (`design/naryad-ds/DESIGN-SYSTEM.md`), а этот документ — его перенос. После вступления по Наряду — только пункты, которые `MAP.md` помечает «остаётся в Наряде» (до их переноса).

**Один источник.** Правила вида и поведения — только в этом документе и в `CLAUDE.md` репозитория. Всё остальное о дизайне (`docs/design/*`, старые `design/naryad-ds/*.md`, разборы, спеки `docs/specs/*` в части вида) — материал, а не правило (Наряд §0, решение основателя #2878). Нашлось правило только там — сначала перенести сюда, потом делать.

**Что главнее, по порядку:**
1. Слова основателя — `CLAUDE.md` или задача GitHub с ярлыком `решение`. Расходится с документом — правится документ.
2. Этот документ — правила.
3. Код: числа — `packages/design-tokens/src/index.ts`, детали — `apps/mobile/src/ui`. Где документ и токен спорят о числе — прав токен (Наряд §0 п.2).
4. Спеки `docs/specs/*` — что делает экран и какие у него данные; вид и поведение берутся отсюда.

**Как предложить правку.** Один путь, одним PR (Наряд §2.3, CLAUDE.md «Где что»):
1. правило — в этот документ (номер версии и строка в `CHANGELOG.md`: исправление текста — третья цифра, новое правило — вторая, отмена — первая);
2. токен — источник значений `packages/design-tokens/src/index.ts`; `design/gorix/tokens.css` и `tokens.md` строит скрипт (`npm run gen -w @octo/design-tokens`), руками не правятся. CSS Наряда (`design/naryad-ds/tokens/*.css`) пока зеркалит `index.ts` (сверка `mirror.test.ts`) и уйдёт в архив вместе с Нарядом. Деталь — в `apps/mobile/src/ui`;
3. витрина — Настройки → Дизайн-система, только «как есть» (`features/showcase/registry.ts`; сторож `designSystem.test.ts`; #2744, #2750); в PR строка «Проверить в витрине: раздел — что сделать, что увидеть»;
4. снимки — пара «как есть | как будет» (390, обе темы) на веб-странице «Как есть | Как будет» (#2750, #2893 п.4), не в приложении;
5. экраны — переводятся тем же PR или волной своей зоны.

**Кто утверждает.**
- **Вид** меняется только через пару «как есть | как будет» на веб-странице. Пару до показа согласуют инженерия, design-reviewer и crm-reviewer (правило 31, #2673); в приложение — только после «да» основателя (#2916). Решение по слою — его; подготовку без смены вида чат дизайн-системы делает без остановки (#2905 п.2). Пока основатель недоступен — вопросы копятся, временное решение помечается и ждёт ответа (#2918).
- **Заморозка:** на время перестройки вид приложения меняет только чат дизайн-системы; остальные чаты чинят поведение и данные (#2893 п.3).
- **Витрина** в приложении — «как есть»; «как будет» — только на веб-странице (#2744, #2750).
- **Правила** — чат аудита; **вливает** — руководитель при зелёных проверках (Наряд §2.3).

**Пока переезд не закончен.** Ссылка «Было в Наряде» у карточки — откуда правило пришло. Сторожа и витрина пока ссылаются на заголовки Наряда (`designSystem.test.ts`, блок «the showcase covers everything») — их переводят отдельной задачей.

**Статус в тексте.** «есть» — код так делает; «⬜» — правило действует, код пока нет (задача — в Issues, правило 21); «будет» — деталь запланирована, правила для неё — пункт Наряда, который `MAP.md` помечает «остаётся в Наряде».

## 1. Принципы

1. **Телефон, одна рука.** Работа идёт с телефона; планшет и десктоп — то же приложение (CLAUDE.md). Главное действие — под большим пальцем; на объекте — под шапкой, в редакторе — внизу (Наряд §12.2).
2. **Цвет — только для статуса, всегда значок + слово; один акцент `acc` — главное действие экрана** (правило 2). Исключения — поимённо, §9.
3. **Только токены и детали `src/ui`** (правила 1 и 29). Своих чисел, кнопок, шторок, окон и стилей элемента на экране нет. Нет детали — сначала `src/ui`, документ и витрина.
4. **Вид «Наряда», поведение iOS.** Жесты, порядок кнопок, движение, вибрация, доступность — как у системного аналога iOS; сознательные отличия названы в §6 (Наряд §1 п.3, §16).
5. **Офлайн с первого дня.** Изменение сразу видно и записано на телефоне; без сети — ждёт отправки (правило 6).
6. **Обе темы и три ширины.** Каждый экран — тёмная и светлая, 390 / 820 / 1280 и малый телефон 375×667 (правило 4, Наряд §1 п.12).
7. **Язык клиента ≠ язык приложения.** Всё, что уходит клиенту, — на языке клиента; бригаде — на языке сотрудника; поставщику — en (правило 7).
8. **Деньги — с центами, везде** (правило 31, #2672), считаются только движком (правило 8). Необратимое — подтверждение или тост «Вернуть» на 5 секунд (правило 5).
9. **Основа — принципы ресёрча #2751** (основатель 25.11, #2754: «давай руководствоваться этими принципами, сценариями и инструментами»): одна главная кнопка под пальцем; следующий шаг виден; вкладки — только переходы; одинаковое на одном месте; сначала главное; меньше печатать; работа в поле; «Вернуть» вместо «Вы уверены?»; привычки iPhone.
10. **Новичок понимает сразу, меньше переходов** (основатель 25.11, #2757: «чтобы простой пользователь мог нормально пользоваться приложением, ему не пришлось разбираться, чтобы не было каких-то много пересылок»). Мера — нажатия, переходы и «места, где непонятно» по сценарию до/после.
11. **Меньше на экране: первый экран отвечает «что это и что дальше»** (основатель 25.11, #2758: «у него слишком много информации, он не понимает, куда ему переходить»). Остальное — по нажатию; мера — число блоков и кнопок на первом экране (390) до/после.
12. **Одно слово — одна вещь, везде** (#2758: «если это работа, то это работа везде»). Слова — из одного словаря (§7.1).
13. **Строки не полупустые** — *предложено, ждёт слова* (#2701 открыта; заметка основателя 20.11). Две кнопки или два поля в ряд, если помещаются, — уже решено (#2350, Д-пара-1).

## 3. Основа

Числа здесь не пишутся — только имена токенов и где их взять. Таблицы значений — `design/gorix/tokens.md` (строит скрипт `npm run gen -w @octo/design-tokens`); источник чисел — `packages/design-tokens/src/index.ts`; живые образцы — витрина «Цвета и шрифты», «Отступы, радиусы, размеры, слои», «Движение и время».

### 3.1. Цвет и статусы
*Было в Наряде: §3.1–§3.5, §12.12.*
- **Темы** — `themes.dark` и `themes.light`: фон `page`, `bg`, `ground` (фон экрана «Тёплый»); поверхности `surf` / `surfSolid` → `surf2` → `surf3`; поле `in`; текст `ink`, вторичный `mut`; линии `bd`, рамка поля `bdField`, дорожка `track`, выключенное `off`, пунктир `dash`; стекло `ov` / `ovSolid`; затемнение `scrim`; тост `toast` / `onToast` / `toastAction`; блик `hl`; тень `shadow`.
- **Правило 60/30/10:** фон 60, поверхности и текст 30, акцент 10; нигде чистого чёрного и белого (основатель 21.11, #2350; Наряд §1.1 П10).
- **Акцент** — `acc` + текст на нём `onAcc`; жёлтое слово на поверхности — `accText`; токен `accEdge` (кромка жёлтого в светлой теме) остался, но у жёлтой кнопки и плитки обводки нет: жёлтая заливка одна в обеих темах, кнопку узнают по слову (#2363 F36, F19); тон подсветки (выбранный день, ближайший интервал) — `tint` / `tint2`. **Одна жёлтая заливка на экран** — только главное действие (сторож `oneAccent.test.ts`). Выбранное — не жёлтое: «Заливка» `surf2` и галочка (`fillStyle`, `CheckMark`). Жёлтая кнопка — всегда сплошная.
- **Статусы** — `themes.*.status.{ok, info, warn, bad, neutral}.{fill, text}`; значок тона — `statusIcon` и `statusGlyph(status, draft)`: у серого два значка — `draft` (черновик) и `neutral` («нет», «отменён») (сторож `statusDraft.test.ts`). Смысл: ok — готово, оплачено; info — в работе, новое; warn — ждёт, опаздывает; bad — надо делать сейчас; neutral — черновик, архив.
- **Всегда значок + слово.** Текст в цвете статуса — только `StatusNote`; `<T tone>` без значка — ошибка (сторож `designSystem.test.ts`). Подпись тона `bad` — «Требует внимания», не «Ошибка».
- **Опасное** — заливка `status.bad.fill`, текст `status.bad.on` — только в окне подтверждения или на шаге подтверждения.
- **Кромка карточки** `component.statusEdge` — только warn и bad.
- **Графики:** акцент — выбранное и текущее, нейтральный — остальное, тон статуса — только если значение и есть статус; приглушённые — `component.chart.mutedOpacity`, ноль виден — `chart.barMin`.
- **Фирменный цвет компании** — только PDF и `/p/`, никогда в интерфейсе (§19 Наряда).
- **Пастели** `pastels.{lav, mint, butter, peach}` — только инициалы (`pastelOf` — `apps/mobile/src/ui/pastelOf.ts`) и плашки v2, не статус.
- **Контраст:** текст ≥ 4,5:1, крупный текст и значки ≥ 3:1, рамка поля и край вторичной кнопки ≥ 3:1 (WCAG 1.4.11), в обеих темах, на худшем фоне; текст на стекле — на самом светлом и тёмном под ним. Выключенное не обязано держать 4,5:1 — рядом объясняется, почему выключено; выключенный переключатель — порог `DISABLED_MIN` (константа в `packages/design-tokens/test/contrast.test.ts`). Сторож — `packages/design-tokens/test/contrast.test.ts`.
- **Сроки смет** — `timing.estimateWarnDays` (warn), `timing.estimateBadDays` (bad).
- **Повышение контраста** (слой «Основа», 27.11.2026, #2893/#2918; опись этапа 1 — работа на солнце) — `highContrast.{dark,light}` и `withHighContrast(c, name)`; в приложении — `useTheme().highContrast`. Включается само, когда в системе включено «Повышение контраста»: iOS — «Универсальный доступ → Дисплей и размер текста → Повышение контраста», Android — «Текст с высоким контрастом», веб — `prefers-contrast: more`. Меняются только серые слова `mut` и слова статусов (`status.*.text`, `on`) — тот же оттенок, только светлота: светлая тема ≥ 7:1 на `bg`, `surf`, `surf2`, `surf3` и на заливке статуса; тёмная ≥ 7:1 на `bg` и `surf`. Жёлтые слова `accText`, фон, акцент, `ink`, заливки и **красный кружок «Лиды»** (правило 2, искл. 4) не меняются; обычный вид не меняется. *Почему:* подрядчик работает на улице, 4,5:1 на солнце мало. *Проверяет:* `packages/design-tokens/test/contrast.test.ts` («high contrast»: ≥ 7:1, не слабее обычного, оттенки статусов различимы), `apps/mobile/test/highContrast.test.ts`.
- **Пунктир открытого пункта** `dash` — ≥ 3:1 и на выбранной ячейке `surf3` (слой «Основа», 27.11; было 2,94 и 2,77). *Проверяет:* `contrast.test.ts`.

### 3.2. Текст
*Было в Наряде: §4.1–§4.3, §4.5.*
- Шрифт — `font.families` (Manrope, основатель 21.11, #2350); цифры одной ширины везде.
- Роли — `font.size.{display, figure, title, figureSm, heading, input, body, button, caption, micro}`; трекинг `font.tracking`; межстрочный `font.line` (`tight` — заголовки, `snug` — строки, `body` — абзацы). На экране — не больше пяти размеров.
- Поле ввода — `font.size.input` (не меньше — иначе iOS Safari увеличивает страницу).
- Минимум — `font.minSize`; исключения поимённо — §9.4.
- Весь текст — через `T`; строки — через i18n (сторож `designSystem.test.ts`).
- Рост с системным шрифтом: подписи в фиксированной форме — не больше `font.labelMaxScale` (`T capped`); заголовок в одну строку ужимается не меньше `font.fitMinScale` (`FitTitle`). Высоты кнопок и строк — `minHeight`, текст переносится, не режется.
- Форматы — только США (правило 7): деньги `$` en-US **всегда с центами**; минус — знак «−»; дата в документах клиенту — MM/DD/YYYY; время — 12-часовое; день в строке — «сегодня / завтра / вчера» словом, иначе «пт, 19 нояб.» (`dayWord`, тест `dayWords.test.ts`); длительность точная — `duration`, ожидание — одной единицей (`waitShort`, `startsIn`); номера документов EST-, INV-, RCT-, PO-, JOB-.
- Множественное число — `Intl.PluralRules`, ключи `.one/.few/.many/.other`, в коде `tn(основа, n)`; «(s)» и «выезд(а)» не пишем.

### 3.3. Раскладка и ширины
*Было в Наряде: §5.1–§5.4, §12.9, §12.10.*
- Ширины — `breakpoint.tablet`, `breakpoint.desktop`: телефон < планшет < десктоп. Проверяются 390, 820, 1280 и 375×667.
- Отступы — `space[1…8]`, полушаги `spaceHalf.{hair, tight}`, ритм экрана `rhythm.{screen, cardGap, cardPad, rowGap, blockGap, headGap}`.
- Содержимое — не шире `layout.contentMax`; колонка формы — `layout.formMax`; колонок карточек — `layout.gridCols`.
- Правая колонка карточки и панель списка — `component.panelW`; окно вместо шторки от 820 — ширина `modalW` + 2 × `space[8]` (считает `Sheet`).
- Навигация: телефон — нижние вкладки `size.tabbarH`, всегда пять (Главная · План · Сообщения · Клиенты · Ещё; вкладка модуля встаёт на место «Плана» с именем модуля без перевода); планшет — полоса `navRail`; десктоп — меню `navMenu` или полоса. Подпись вкладки = пункт меню = заголовок экрана (тест `sections.test.ts`).
- Безопасные зоны — только из `useNavInsets()` / `navInsets()`; `size.statusbarH` и `size.safeBottom` — минимумы для расчётов, не отступы (сторож `shell.test.ts`). Телефон работает в портрете и пейзаже; у каждого `<Modal>` — все ориентации (сторож `modalOrientations.test.ts`).
- Фон и стекло — до края, содержимое — в безопасном прямоугольнике; системные жесты сверху и снизу не перехватываются.

### 3.4. Поверхности
*Было в Наряде: §6.1–§6.5.*
- Слои: страница (`page`, `ground`) → карточка (`surf`, `radius.card`, без размытия) → вложенное (`in`, `radius.inner`) → навигация и значки (`surf2`) → стекло (`ov` + `blurOverlay`, `Glass strong`) → затемнение (`scrim`).
- **Стекло — только у плавающего слоя управления:** нижняя панель, закреплённая панель действия, меню, тост, шторка и окно, полоса шапки при прокрутке. У содержимого (карточки, поля, строки, холст, PDF) — без стекла.
- Стекло на стекле не ставим; на экране не больше трёх размытых слоёв; размытие не анимируется.
- iOS 26: `GlassView regular` — нижняя панель (выбор — `nav/tabGlass.ts`, тест `tabGlass.test.ts`); шторка и окна — стекло «Наряда» `Glass strong` на всех платформах. Нижняя панель вне iOS 26 — сплошная `ovSolid`.
- «Понижение прозрачности» — все стеклянные поверхности сплошные `ovSolid` ⬜.
- Слои — только `z.{under, over, dragged, nav, lift, fab, scrim, sheet, modal, toast}`; своих чисел `zIndex` нет.
- Радиусы — `radius.{pill, chip, field, card, inner, sheet, tip}`.

### 3.5. Движение
*Было в Наряде: §1.4, §14.1–§14.5.*
- Шкала — `motion.durPress`, `durFast`, `durBase`, `durSlow`; `durSlow` — потолок переходов интерфейса. Исключения: `liquidStretch` + `liquidSettle` (сегменты, вкладки), `durChart` (графики), `durBrand*` (знак GoRix).
- Кривые — `motion.easeOut` (появление, сдвиги), `motion.spring` / `easeSpring` (после пальца), `easeLiquid` («жидкая» подложка). `ease-in` для интерфейса не применяется (Наряд §1.4 п.3).
- Анимируются только `transform` и `opacity`; старт не с нуля, а с малого масштаба и прозрачности.
- Анимировать ли — по частоте: то, что нажимают сотни раз в день, — без анимации. Анимацию не ждут: элемент нажимается сразу.
- Сразу, без анимации: деньги и числа, ошибки под полем, смена темы и языка, раскладка при повороте, кольцо фокуса, галочка выбора, список при поиске, счётчики, время.
- **Уменьшенное движение** (`useReducedMotion()`): сдвиг, масштаб, пружины — убрать; шторка, окно, меню, тост — растворение `durFast`; системные переходы стека — как делает система.
- Нажатие — масштаб `motion.pressScale` за `durPress`; строки списка — подложка `surf2`.
- Чувство движения проверяется на iPhone и медленном Android (правило 27).

### 4.0. Дерево выбора значения
*Было в Наряде: §9 (вводная), §9б.1, §20.* Первое «да» решает:
1. Действие, а не значение → кнопка или «⋯» (меню действий).
2. Да / нет → `ToggleRow`.
3. Число: целое в узком диапазоне → `Stepper`; деньги, проценты, количество → `NumberField`; длина → поле длины (модуль — рулетка); дата → `DateField`.
4. Цвет материала → `ColorField`.
5. Человек или объект → `PickerSheet`, всегда.
6. Больше `component.select.menuMaxItems`, или у варианта картинка / образец / подзаголовок → список (`SelectField` открывает `PickerSheet` сам, `opensList`).
7. 2–12 коротких слов, поле формы → `SelectField` с меню у поля.
8. Выбор — единственный вопрос шторки → `OptionRow`.
9. Вид экрана, 2–3 коротких, не сохраняется → `Segmented` (по списку мест).

**Запрещено** (основатель 16.11, #1869): чипы для выбора значения и любой ряд кнопок или чипов в две строки; квадратные флажки и роль `checkbox` (кроме `DoneCircle`); сегмент в поле формы, для да/нет, для единицы числа (кроме исключений §9.5). ## 6. Поведение «как в iOS»

### 6.1. Жесты
*Было в Наряде: §1.2, §14.6, §16.*
- **Жест — ускоритель, не единственный путь:** у каждого жеста есть кнопка, пункт «⋯» и действие для диктора (П8, HIG «Gestures»).
- Порог «жест взят» — `gesture.slop`.
- **Смахнуть шторку вниз** — по ручке сразу, по телу — только если список в начале; отпускание — Д-шторка-5.
- **Назад от края** — системный жест стека; во вкладках изнутри — свой `BackSwipe` (`nav/backSwipe.ts`, тест `backSwipe.test.ts`); выключен при клавиатуре, на широком, на Android, на холсте и в подписи.
- **Перетаскивание** — палец и перо после удержания `gesture.dragHoldMs` (строки сметы — `gesture.sortHoldMs`), мышь — после сдвига `gesture.dragStart`; в момент захвата — `light`, предмет поднят (`motion.liftScale`, `motion.liftTilt`), места, куда положить, подсвечены (основатель 12.11, #1272); бросок на новое место — `medium`. Только через `Draggable` (`features/dnd.tsx`) или `features/SortableList.tsx`.
- **Смахнуть строку** — Д-смахивание.
- **Долгое нажатие** — `motion.longPressMs` → контекстное меню (⬜); у строк сметы — перетаскивание.
- **Повторное нажатие вкладки** — к корню, затем к началу (⬜). **Потянуть, чтобы обновить** — системный `RefreshControl` (⬜).
- Системные жесты сверху и снизу не перехватываются; страница не масштабируется щипком (кроме просмотра фото).
- Жесты, клавиатура, вибрация, рисование на iPhone ведут себя не как в браузере: модульные тесты математики и строка «Натив:» в PR (правило 27).

### 6.2. Клавиатура
*Было в Наряде: §11 п.7, п.13, §16 7.7, §10 Б1, Б1а.*
- Тип клавиатуры — из `type` поля; Return — к следующему полю, на последнем — «Готово», форму не отправляет (как в iOS); веб: Enter — следующее поле, форму не отправляет. Карточка «Поле ввода» — Д-поле-8; сторож — ⬜.
- У цифровой клавиатуры iOS — панель «‹ › Готово» над клавиатурой: у самой цифровой клавиатуры «Готово» нет. Карточка «Число» — Д-число-4; проверка — строка «Натив:» в PR (правило 27).
- Шторка — над клавиатурой; прокрутка тела убирает клавиатуру (в `Screen` есть, в `Sheet` ⬜).
- Одно короткое значение с клавиатурой — окно ввода, которое клавиатура не двигает (будет `InputDialog`; основателю не нравится шторка над клавиатурой, #924).
- Цепочка полей: следующее поле берёт фокус сразу и выделяет текст (`focusNow`, `ui/fieldFocus.ts`, тест `fieldFocus.test.ts`).
- Веб: всё доступно с клавиатуры; Esc закрывает окна; `/` — поиск.

### 6.3. Сохранение, «Вернуть» и «Отменить»
*Было в Наряде: §1 п.8, §15.1, §15.2, Б1, Б3; CLAUDE.md правило 5.*
- **Обратимое** — сразу и тост «Вернуть» на `motion.toastUndoMs` (смена статуса, удаление позиции, архив без последствий, задача выполнена).
- **Необратимое и редкое** — окно подтверждения до действия (удаление навсегда, деньги, отзыв доступа).
- **Ни окна, ни тоста** — правка поля, переход.
- **«Вернуть»** — только тост после действия. **«Отменить»** — только откат правок в редакторе (внизу; у сметы, где внизу «Отправить», — пунктом «⋯», §9.6 п.5). Отсчёта и «Не отправлять» у отправки нет: «просто выбираешь и нажимаешь „Отправить“, и всё» (основатель 23.11; сделано #2637).
- **Закрыть = сохранить** у заметок сметы (Notes, Terms) и шторок итогов: «×», смахивание и фон сохраняют набранное.
- **Вопрос о несохранённом — одно правило** (основатель 24.11, #2485 п.3): шторка с правками спрашивает; заголовок «Сохранить изменения?» (EN «Save changes?», ES «¿Guardar cambios?»); три кнопки столбиком: «Сохранить» · «Не сохранять» (красное слово) · «Продолжить правку» (EN «Keep editing», ES «Seguir editando»). Слов «Отмена» и «Назад» нет. Esc, «Назад» Android и фон на вопросе = «Продолжить правку». Ключ — `sheet.keepEditing`, сторож — `unsavedQuestionWords.test.ts`. Исключение — §9.6. Другой вопрос, не путать: «Выйти без сохранения? / Остаться / Выйти» — форма-экран и там, где сохранить нельзя.
- Мутации стора возвращают `undo`; тост принимает только «Вернуть» стора (`GuardedUndo`, `src/data/undo.ts`).

### 6.4. Состояния экрана
Таблица — §5.0. Экран не блокируется при действии: кнопка в загрузке. Алерт при запуске не показывается; нет сети — сохранённые данные и метка (HIG «Alerts»).

### 6.5. Офлайн
*Было в Наряде: §1 п.11, §13, §15.1, §15.3б; CLAUDE.md правило 6.*
- Изменение сразу пишется на телефон; без сети — в очередь (`useStore().queue`).
- Видно всегда: строка очереди на телефоне, баннер на широких; слова — словаря состояния данных («Сохранено», «Ждёт отправки», «Нет сети», «Не отправлено», «Всё отправлено: N»).
- Ошибка сети при действии, которое пишется локально, — не ошибка: тоста нет, баннер «Нет сети · Ждёт отправки · N».
- Действие, которому нужна сеть (оплата картой, приглашение), — тост «Нужна сеть», `error`.
- Отказ сервера — «Не отправлено» (`bad`), нажатие — список неотправленного (`StuckOps`).
- Обновление приложения — только сообщает; перед перезапуском открытые шторки спрашивают о несохранённом, очередь записывается (Наряд §15.3а).

### 6.6. Сознательные отличия от iOS (одно место)
*Было в Наряде: §16, §16.1.*
- Главная кнопка шторки — снизу, «✕» справа (у iOS — «Отмена» слева, «Готово» справа).
- Вопрос о несохранённом: сверху «Сохранить», «Не сохранять» в середине (у HIG разрушающее — наверху).
- Свой календарь (выходные и день компании).
- Стекло «Наряда» на шторке и окне.
- «Вкл» переключателя — `acc` (основатель 16.11, В-08).
- Сегменты по ширине подписи; степпер с круглыми кнопками.
- Тост «Вернуть» (в iOS нет); «Удалить» строки сметы без подтверждения, но с «Вернуть».
- Ручка перетаскивания видна всегда, без режима правки.

## 7. Слова и тон
*Было в Наряде: §4.2, §4.4, §4.4а, §19.1; словарь — `docs/audit/2026-11-11-glossary-draft.md` (файл данных).*

### 7.1. Общие правила
1. Одно понятие — одно слово на языке, синонимов нет (словарь).
2. Кнопка — **глагол + объект** («Создать смету»); один глагол — только когда объект очевиден («Сохранить»).
3. Без «Упс», «Пожалуйста», восклицаний (кроме клиентского «Спасибо!»), без многоточия в кнопках (кроме тех, после которых нужен ввод: «Отправить копию…»).
4. Запрещённые слова — словарь §13 (синхронизация, очередь, шторка, пуш, сущность…).
5. ES — американский узус, «usted»; RU — «вы»; EN — «you», без «please».
6. Названия языков — на самом языке: «Русский · English · Español».

### 7.2. Голос сообщений (основатель 15.11, #1584)
- Сообщение говорит **что происходит** и **что сделать** (или что приложение сделает само), а не что «не получилось».
- Запрещены в строках для человека: RU «не удалось», «не получилось», «ошибка», «сбой», «что-то пошло не так»…; EN «couldn't», «failed», «error», «unable»…; ES «no se pudo», «error», «falló»… Полный список и исключения — в стороже `voice.test.ts` (исключения только сокращаются).
- Примеры: «Нет сети. Изменение сохранено и отправится, когда сеть вернётся.» · «Сервер занят. Повторим сами через 5 минут.» · «Укажите номер телефона или почту.» · «Это доступно владельцу. Попросите его.»
- Типовые фразы (пусто, не найдено, подтверждение, тост) на трёх языках — словарь §12 (выписка — Наряд §4.4а).

### 7.3. Соседние слова
| Пара | Правило |
|---|---|
| Создать / Добавить | «Создать» — новый объект с нуля; «Добавить» — элемент внутрь существующего; «Новый X» — только заголовок формы |
| Сохранить / Готово / Применить | «Сохранить» — записать форму; «Готово · N» — применить выбор нескольких («Показать N» — в фильтрах); «Применить» — параметры без записи в базу |
| Удалить / Убрать / В архив | запись пропадает / убрана из списка или связи / скрыта, можно вернуть |
| **Вернуть / Отменить** | **«Вернуть» — в тосте после действия. «Отменить» — только откат правок внизу редактора** (и статус «Отменён» у выезда, заказа) (правило 5) |
| Закрыть / Сбросить | окно без изменений / выбросить несохранённое или вернуть по умолчанию |
| Отправить / Отправить ещё раз / Повторить | любое исходящее клиенту / приглашение, письмо / когда отправка ждёт вашего шага |
| Назначить / Запланировать / Перенести | мастера на выезд / дату работы / дату того же выезда |
| Окно подтверждения | подтверждение повторяет глагол («Удалить клиента»), отмена — «Не удалять» / «Назад», не «Отмена» |

**Вопрос о несохранённом** — см. §6.3.

### 7.4. Язык клиента ≠ язык приложения (правило 7)
- Всё, что уходит клиенту (PDF сметы, счёта, квитанции, `/p/`, SMS, письма), — `tFor(docLanguageFor(db, {personId?, customerId?, leadId?}))`; порядок: человек → клиент → лид → компания (`Company.docLanguage`). Языки клиента — en, es, ru. Сторож — `docLanguage.test.ts`.
- Бригаде (раскрой, рабочие чертежи, задание) — язык интерфейса сотрудника-получателя, иначе язык документов компании; поставщику — всегда en. Переводятся только наши надписи; текст людей — как введён.
- Клиенту — только его слова: Estimate, Invoice, Payment, Deposit, Receipt, Visit; без «лид», «мастер» (→ «our technician»), «модуль», «синхронизация». Подпись — компания-подрядчик, не GoRix.
- Цены образца — без пометки «тестовая», «test», «sample» нигде (правило 9; сторож `noTestPriceWord.test.ts`). При первой отправке сметы клиенту — одно напоминание проверить цены каталога (правило 9).
- В пуше нет сумм, имён и адресов (App Store 4.5.4, спека 27).

## 8. Доступность
*Было в Наряде: §17, §3.5, §4.3, §7.1.*
1. **Контраст** — см. §3.1.
2. **Крупный шрифт:** текст растёт минимум до 200 % (HIG «Accessibility»); высоты — `minHeight`; имена клиентов переносятся, а не режутся; веб — масштаб 200 % без горизонтальной прокрутки. Каждый шаблон проверяется на самом крупном размере.
3. **VoiceOver:** у каждой кнопки-значка — подпись по смыслу с объектом («Позвонить, …»); статусы читаются словом; переключатель — с состоянием; заголовок экрана — `heading`, заголовки секций — `header` (⬜); строка списка — один элемент с `accessibilityActions`; окна — фокус на заголовок, содержимое под ними недоступно (`accessibilityViewIsModal`), после закрытия — на источник; тост — `announceForAccessibility` на iOS (⬜), `accessibilityLiveRegion` на Android; ошибка поля объявляется при показе.
4. **Зоны нажатия** ≥ `size.hitMin` (сторож `fontScale.test.ts`); соседние зоны не перекрываются (в ряду — только сверху и снизу, ⬜ `ButtonRow`); на вебе зона — настоящая коробка (`hitSlop` там не работает).
5. **Цвет не единственный признак:** значок + слово; график — подпись и таблица значений для диктора.
6. **Уменьшенное движение** — §3.5; **понижение прозрачности** — `ovSolid` (⬜); **повышенный контраст** — рамки толще, вторичный текст `ink` (⬜, после выпуска).
7. **Клавиатура на вебе** — всё с клавиатуры, кольцо фокуса (⬜ токен), Esc закрывает окна.
8. **Язык страницы** — по языку интерфейса; на `/p/` — по языку клиента.
9. Проверка на устройстве — список `design/naryad-ds/DEVICE_TESTING.md` (порядок; числа — из этого документа).
