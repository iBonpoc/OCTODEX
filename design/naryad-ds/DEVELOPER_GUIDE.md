# Наряд: руководство для разработчика

## Сначала прочитайте
Прототип «Наряд CRM» и страница «Наряд Design System» это тестовые экраны, на которых строилась дизайн-система. Это не готовое приложение. Берите из них токены, компоненты, правила и сценарии, а не экраны и вымышленные данные. Все значения должны быть глобальными токенами (`tokens/*.css`), без «своих» значений у компонентов. Недоделанное перечислено в разделе «Статус и что не сделано» дизайн-системы.

## Что вы получаете
| Файл | Для чего |
|------|----------|
| `Наряд Design System.dc.html` (и версия одним файлом `dist/`) | Дизайн-система: откройте в браузере, переключайте тему и стиль |
| `Наряд CRM.dc.html` (и `dist/`) | Интерактивный прототип: телефон, планшет, десктоп, роль «Мастер» |
| `tokens/theme.css`, `tokens/status.css`, `tokens/foundation.css`, `tokens/icons.json`, `styles.css` | Готовые токены для кода |
| `CLAUDE.md` | Правила проекта, подхватываются Claude Code автоматически |
| `HANDOFF.md` | Экраны, размеры, поведение, требования App Store |
| `CHECKLIST.md`, `CONTRAST.md` | Правила проверки и отчёт о контрасте |
| `RESEARCH.md`, `BACKLOG.md` | Исследование рынка и структура запросов |
| `components/core/` | Button, StatusChip, Card, Toggle в React |

## Как начать в Claude Code
1. Распакуйте архив в корень вашего репозитория (например `design/`) или откройте папку отдельно.
2. Файл `CLAUDE.md` должен лежать в корне репозитория (скопируйте или добавьте в него ссылку на `design/CLAUDE.md`).
3. Откройте Claude Code в репозитории и дайте задачу, например:

> Прочитай CLAUDE.md, HANDOFF.md и DEVELOPER_GUIDE.md. Открой design/Наряд Design System.dc.html и design/Наряд CRM.dc.html как спецификацию. Начни с токенов из design/tokens в виде нативного набора для iOS (SwiftUI), затем компоненты из раздела «Сводная таблица» и экран «Сегодня». Соблюдай CHECKLIST.md.

4. Для работы с HTML-файлами используйте версии из `dist/` (один файл, открываются без интернета) или откройте `.dc.html` в браузере проекта Claude Design.

## Рекомендуемый порядок разработки
1. Токены: цвета тем и стилей, статусы, размеры, радиусы, движение, иконки (замена на SF Symbols по таблице в разделе «Иконки»).
2. Базовые компоненты: кнопки, чипы, поля, переключатели, вкладки, нижняя панель.
3. Окна: шторка, диалог, тост с отменой, выпадающий список, поиск и палитра команд.
4. Экраны телефона: Сегодня, Разбор дел, Входящие, Клиенты и карточка, Календарь, Мастер.
5. Данные и офлайн: очередь действий, синхронизация, вложения.
6. Диспетчер: календарь с перетаскиванием, карта, команда, отчёты.
7. Платежи, подпись, камера, push.
8. Доступность, Dynamic Type, App Store.

## Тесты (обязательны)
Проверка на реальном телефоне: `DEVICE_TESTING.md`.

Перед каждой передачей и в CI на каждый pull request: `npm test` (контраст и токены), `npm run test:screens` (браузерные тесты, нужен `npm i`). Подробно в TESTING.md. Тест экранов ещё ни разу не запускался в этом проекте, первый запуск может найти настоящие замечания.

## Правила, о которых легко забыть
- Видимые кнопки на телефоне 36, зона нажатия 44.
- Цвет только для статуса, всегда со значком и словом.
- Окна полупрозрачные только в стиле «Стекло».
- Любое необратимое действие: подтверждение или отмена на 5 секунд.
- «?» и подсказка при первом заходе у каждого раздела.
- Любой новый экран проверять по `CHECKLIST.md`: 3 устройства, 2 темы, стиль «Стекло».
