# Наряд: комплект для разработчика

**Начать с DEVELOPER_SPEC.md** (одна страница: принципы, токены, компоненты, иконки, тесты, что не готово).

## Открыть сразу (один HTML, работает без интернета)
- dist/Naryad-Design-System.html: дизайн-система (цвет, шрифт, иконки, кнопки, поля, навигация, окна, пикеры, списки, жесты, графики, фото, форматы и роли, доступность, разметка, токены).
- dist/Naryad-CRM-prototype.html: интерактивный прототип. Это тестовые экраны для построения дизайн-системы, а не техзадание. Данные вымышлены.

## Источники правды для кода
- tokens/theme.css, status.css, foundation.css, icons.json, Tokens.swift (SwiftUI). Значение меняется в токене, а не в компоненте.
- CLAUDE.md (правила проекта, читается Claude Code автоматически), HANDOFF.md, DEVELOPER_GUIDE.md.
- CHECKLIST.md (проверка каждого экрана), CONTRAST.md (контраст), AUDIT.md (аудит и что не сделано), BACKLOG.md (запросы и статусы), RESEARCH.md (конкуренты и отзывы).

## Тесты
TESTING.md, tests/*.mjs, package.json. Обязательны перед передачей и в CI. Контраст и токены проверены (190 и 71 проверка без ошибок). Браузерный тест экранов (tests/screens.spec.mjs) написан, но не запускался.

## Что сознательно не входит
Настоящая авторизация, сервер, платежи, карты, камера, распознавание речи, push, офлайн-хранилище, Dynamic Type, VoiceOver в окнах. Перечень и причины в AUDIT.md и в разделе «Статус» дизайн-системы.

## Порядок
1. Прочитать CLAUDE.md и DEVELOPER_GUIDE.md. 2. Перенести токены (Tokens.swift или CSS). 3. Собрать компоненты по сводной таблице. 4. Экраны по HANDOFF.md. 5. Проверка по CHECKLIST.md в двух темах и на трёх устройствах.
