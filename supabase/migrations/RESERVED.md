**Миграции не бронируются вперёд** (18.11.2026): сторож `migrationGuard` (#759) требует, чтобы новая миграция ветки была позже последней на `main`, поэтому любое влитие большего номера сделало бы все меньшие брони красными. Номер миграции выдаёт руководитель **при сдаче PR** — выше последней на `main` и всех ожидающих; такие PR вливаются по возрастанию номера. В таблице — только уже выданные.

**e2e и T** бронируются вперёд (порядок им не важен).

Сторож `scripts/numbersGuard.cjs` (задача `numbers` в `checks.yml`): номер из таблицы, закреплённый за задачей, PR может взять, только если в его описании `Closes #N` / `Refs #N` этой задачи — для миграций это и есть «уникальность среди выданных»; строка без задачи («—») значит «выдано», за PR не закреплено.
